  1. 1

    Маршрутизатор: мекенжай - функция

    Бастайық. Веб-сервердің ең басты жұмысы - «мына мекенжай сұралды, қай функцияны шақыру керек?» деген сұраққа жауап беру. Мұны сөздік (dict) керемет шешеді: кілті - мекенжай, мәні - функция. Тек ROUTES["/"] = home деп қолмен жазу жалықтырады, сондықтан Flask-тағыдай декоратор (decorator) жасаймыз: функцияның үстіне @route("/") деп жазасыз да, ол өзі сөздікке тіркеледі.

    Декоратор - функцияны алып, жаңа функция қайтаратын функция. Ең қарапайым түрі мынау:

    def loud(func):
    def wrapper():
        return func().upper() + "!"
    return wrapper


@loud
def hello():
    return "сәлем"


print(hello())   # @loud жазу hello = loud(hello) дегенмен бірдей

    Біздің @route("/") жолында жақша бар, демек route өзі декоратор қайтарады: аты register болсын.

    app.py файлында жазыңыз:
    • ROUTES = {} - мекенжайлар кітабы;
    • route(path) - функцияны ROUTES[path]-ке тіркейтін декоратор; функцияның өзін қайтарады;
    • handle(path) - тіркелген функцияны шақырып, нәтижесін қайтарады; мекенжай жоқ болса "404 Not Found".
    Кеңес

    route(path) ішінде екі деңгей болады: сыртқысы path-ты алады, ішкісі register(func) функцияны алады. Сыртқысы ішкіні қайтарады. handle ішінде ROUTES[path]() деп жазыңыз: жақшаны ұмытпаңыз, себебі функцияны шақыру керек. Мекенжайдың бар-жоғын in арқылы тексеріңіз.

    Ойланып көріңіз: register функцияны қайтармаса не болады?

    Алдымен болжап көріңіз. Python @route("/") жазуын home = route("/")(home) деп орындайды, яғни home атына register-дің қайтарған мәні жазылады. return func болмаса, ол None болады да, кейін home() дегенде TypeError: 'NoneType' object is not callable шығады. Автотексеруші дәл осыны тексереді.

  2. 2

    Параметрлі мекенжайлар: /user/<name>

    Нағыз сайттарда мекенжай өзгеріп тұрады: /user/Aigerim, /user/Nurlan. Әр адамға бөлек route жазбаймыз ғой, сондықтан /user/<name> деген үлгі (pattern) жазамыз. Үлгі мен нақты мекенжайды бөліктерге бөліп салыстырсақ болғаны: <name> түріндегі бөлік - параметр, қалғандары дәл сәйкес келуі керек.

    pattern = "/user/<name>"
path = "/user/Aigerim"
print(pattern.strip("/").split("/"))
print(path.strip("/").split("/"))

    Екі тізімнің ұзындығы бірдей, әр орындағы бөліктерді жұптап салыстыруға болады. Ал ұзындығы басқа болса, мекенжай сәйкес келмейді.

    Қосыңыз және өзгертіңіз:
    • match(pattern, path) сәйкес келсе параметрлер сөздігін (мысалы {'name': 'Aigerim'}), әйтпесе None қайтарады. Параметрсіз дәл сәйкестік бос сөздік {} береді;
    • басындағы және соңындағы / ескерілмейді;
    • handle әр үлгіні match арқылы тексеріп, функцияны func(**params) түрінде шақырады; ешқайсысы сәйкес келмесе - "404 Not Found".
    Кеңес

    Бос сөздік {} жалған (falsy) мән! Сондықтан if params: емес, if params is not None: деп тексеріңіз, әйтпесе /about сияқты параметрсіз маршрут табылмай қалады. Бөліктерді жұптау үшін zip(p, q), ал ұзындықтарды алдын ала len арқылы салыстырыңыз: zip қысқасына дейін ғана жүреді, артық бөлікті үнсіз тастап кетеді.

    Ойланып көріңіз: /user/Aru мен /user/Aru/ бір бет болуы керек пе?

    Біз strip("/") қолданып, екеуін бірдей еттік. Нағыз серверлерде бұл жиі талас тудырады: Flask мұны strict_slashes баптауымен реттейді. Басты ой: мекенжайды салыстырмас бұрын қалыпқа келтіру (normalization) керек, әйтпесе бір бет екі мекенжайға бөлініп кетеді.

  3. 3

    Шаблон және қауіпсіздік

    Енді функциялар HTML қайтарсын. Бірақ HTML-ді f-жолмен қолмен жинау ыңғайсыз әрі қауіпті. Шаблон (template) - ішінде бос орындары бар дайын мәтін: Сәлем, {{ name }}!. render сол бос орындарды деректермен толтырады. Бұл Jinja2 мен Django шаблондарының ең қарапайым түрі.

    Ал қауіпті жері мынау: қолданушы атының орнына <script>...</script> жазып жіберсе ше? Егер оны өзгеріссіз қойсақ, браузер оны код ретінде орындайды. Бұл XSS шабуылы (Web курсының 8-аптасында көрдік). Сондықтан сырттан келген әр мәнді html.escape арқылы өткіземіз:

    import html
print(html.escape("<script>alert(1)</script>"))
print(html.escape('Ақ "тау" & көл'))
    render(template, **context):
    • {{ аты }} белгілерін context-тегі мәнмен ауыстырады (қос жақша ішіндегі бос орын болса да, болмаса да);
    • мән str болып, html.escape арқылы қорғалады;
    • context-те жоқ айнымалы бос жолға ауысады (қате шықпайды).
    Кеңес

    re.sub(өрнек, функция, мәтін): екінші аргумент функция болса, ол әр табылған жерге шақырылады, m.group(1) - жақшадағы бөлік. Өрнек: r"\{\{\s*(\w+)\s*\}\}"; { таңбасы өрнекте арнайы, сондықтан \{ деп жазамыз. Белгісіз айнымалы үшін context.get(аты, "") қолданыңыз.

    Ойланып көріңіз: escape-ті неге бүкіл шаблонға емес, әр мәнге бөлек қолданамыз?

    Шаблонның өзі - біздің сенімді HTML-іміз (<h1>, <p>). Оны да escape қылсақ, барлық тегтер мәтінге айналып, бет бұзылады. Қауіпті тек сырттан келген мәндер, сондықтан тек солар қорғалады.

  4. 4

    Шаблонға цикл және бүкіл қосымша

    Соңғы қадам - шаблонға тізім шығаруды үйрету. Мысалы, қолданушының тілдерін <li> ретінде тізу үшін {% for l in langs %}<li>{{ l }}</li>{% endfor %} деп жазамыз. Қарапайым көрінеді, бірақ мұнда бір қызық қақпан бар: циклдің нәтижесін шығарып алған соң бүкіл мәтінді тағы бір рет толтырсақ, деректің ішіндегі {{ ... }} шаблон болып орындалып кетеді! Сондықтан мәтінді бөліктерге бөліп, әр бөлікті бір-ақ рет толтырамыз.

    render енді мынаны да біледі:
    • {% for x in xs %}...{% endfor %} блогы context["xs"] тізімінің әр элементі үшін дене мәтінін қайталайды (цикл айнымалысы x және сыртқы айнымалылар қолжетімді);
    • тізім жоқ не бос болса, блок ештеңе бермейді; бірнеше блок және {%for x in xs%} сияқты бос орынсыз жазу да істейді;
    • деректің ішіндегі {{ secret }} сияқты мәтін шаблон ретінде орындалмайды, ол escape-пен өзгеріссіз шығады.
    Кеңес

    LOOP.finditer(template) әр блоктың орнын береді (m.start(), m.end()). Алдымен блоктан бұрынғы кесіндіні (template[pos:m.start()]) fill-мен толтырып қосыңыз, сосын әр элемент үшін fill(m.group(3), {**context, m.group(1): item}), ал соңында pos = m.end(). Барлық блоктан кейін қалған құйрықты (template[pos:]) ұмытпаңыз.

    Ойланып көріңіз: пікір қалдыратын адам {{ secret }} деп жазса не болады?

    Қарапайым «алдымен цикл, содан кейін бәрін толтыру» тәсілінде бұл мәтін шаблон ретінде танылып, secret айнымалысының мәні бетке шығып кетер еді. Мұны шаблон инъекциясы (template injection) дейді; нағыз Jinja2-де де render_template_string дұрыс қолданылмаса, осындай қауіп бар. Біздің шешімде деректер бір-ақ рет, толтыру кезінде ғана өтеді.

  1. 1

    HTML тегін жасайтын көмекші

    Бастау үшін кішкентай көмекші керек. <a href="/x">Сілтеме</a> деп жолдарды қолмен жапсырсақ, тырнақшаны не жабатын тегті ұмытып кету оңай. Сондықтан tag("a", "Сілтеме", href="/x") деп жазсақ та, дұрыс HTML қайтаратын функция жасаймыз. Python-да class тыйым салынған сөз, сол себепті class_="card" деп жазамыз да, функция оны class етіп береді.

    Кілттік аргументтердің барлығын бір сөздікке жинау үшін **attrs қолданылады:

    def show(**attrs):
    print(attrs)


show(href="/x", class_="card", data_id=7)
    site.py файлында tag(element, inner="", **attrs):
    • атрибуттарды аты="мәні" түрінде, жазылған ретпен шығарады; class_ → class, data_id → data-id;
    • мәнді html.escape(str(мән), quote=True) арқылы қорғайды;
    • br, img, meta сияқты жабылмайтын тегтерге (VOID жиыны) жабатын тег қоспайды.
    Кеңес

    attrs.items() бойынша жүріңіз. Python 3.7-ден бастап сөздік қосылу ретін сақтайды, сондықтан атрибуттар жазғаныңыз ретімен шығады. key.rstrip("_") соңындағы астын сызуды алып тастайды, ал .replace("_", "-") қалғанын сызықшаға айналдырады. Ашатын тегті жеке айнымалыға жинап алсаңыз, жабылмайтын тегтер үшін оны бірден қайтарасыз. Екінші параметрдің атын әдейі inner деп алдық: <meta content="..."> сияқты атрибуттың аты content болуы мүмкін және ол параметрмен шатаспауы керек.

    Ойланып көріңіз: атрибут мәнін неге quote=True деп қорғаймыз?

    Мәннің ішінде " болса, title="Ақ "тау"" деп жазылып, атрибут ерте жабылады да, қалғаны жаңа атрибут болып кетеді. Бұл да XSS-тің бір түрі. Тырнақшаны &quot; етсек, бұл жолды жабамыз.

    <header><h1>аты</h1><p class="role">рөлі</p></header>
<main>
  <h2>Дағдылар</h2>
  <ul class="skills"><li>...</li></ul>
  <h2>Жобалар</h2>
  <section class="cards">
    <article class="card"><h3><a href="url">атауы</a></h3><p>мәтіні</p></article>

    • жоғарыдағы құрылымды tag көмегімен жинап, жолды қайтарады;
    • аты, рөлі, дағдылар, жоба атаулары мен мәтіндері html.escape арқылы қорғалады (href мәнін tag өзі қорғайды);
    • жобалар немесе дағдылар тізімі бос болса да бет бұзылмайды.

    Ойланып көріңіз: skills бос тізім болса, бет «сынып» қала ма?

    Жоқ: <ul> бос болады, бет жұмыс істей береді. Деректері өзгеріп тұратын бағдарламада шеткі жағдайларды (бос тізім, өте ұзын мәтін, арнайы таңба) әрқашан тексеру керек. Автотексеруші де жобасы жоқ профильді, тіпті атына <script> жазылған профильді сынайды.

    Зертхана: құрылым (стильсіз)

    Дайын нұсқа. Профильге өз деректеріңізді жазып көріңіз. Бет әзірге стильсіз, түрі қарапайым, бірақ құрылымы дұрыс.

  3. 3

    CSS генераторы: түстер бір жерде

    Құрылым бар, енді көркем болсын. Бірақ түстерді бетте жиырма жерге қолмен жазбаймыз. CSS айнымалылары (custom properties) бар: :root { --accent: #0a7c6e; } деп бір рет жазамыз да, барлық жерде var(--accent) деп қолданамыз. Түсті өзгерткіңіз келсе, тек бір жолды өзгертесіз. Python-да екі кішкентай функция жазамыз: rule бір CSS ережесін жасайды, make_css тақырып сөздігінен :root ережесін шығарады.

    h1 {
  font-size: 2rem;
  border-radius: 12px;
}
    Қосыңыз (BASE_CSS қаңқада дайын):
    • rule(selector, props) - жоғарыдағыдай ереже жолын қайтарады: қасиет атындағы _ → - (border_radius → border-radius), әр қасиет жаңа жолда, 2 бос орын шегінісімен, соңында ;, жол \n-мен бітеді;
    • make_css(theme, base="") - rule(":root", ...) нәтижесіне base жолын қосып қайтарады; тақырыптағы әр кілт -- префиксімен айнымалы болады (accent → --accent, bg_soft → --bg-soft).
    Кеңес

    rule ішінде f-жол және .join жеткілікті: әр қасиет үшін f" {аты.replace('_', '-')}: {мәні};\n". Қос жақшаны f-жолда екі есе жазу керек: {{ мен }} - әріптік жақша. make_css ішінде rule(":root", {f"--{k}": v for k, v in theme.items()}) шақырсаңыз, _ → - ауыстыруын rule өзі жасайды.

    Ойланып көріңіз: айнымалыларды неге body емес, :root ішінде жариялаймыз?

    :root - құжаттың түбірі (<html>), ал body ішіндегі бәрі одан мұра алады, сонымен қатар html элементінің өзі де айнымалыны көреді. Қараңғы режим жасағыңыз келсе, тек :root-тағы мәндерді ауыстырасыз. Осы сайттың өзі де дәл солай жұмыс істейді.

    Зертхана: түстерді өзгертіп көріңіз

    theme ішіндегі түстерді өзгертіп, ▶ басыңыз: accent тақырып пен жиектерге, bg фонға, text мәтінге өтеді.

  4. 4

    Бәрін жинаймыз: толық сайт және файл

    Енді бәрін біріктіретін кез. Толық HTML-құжат жай <body> емес: оның басында <!DOCTYPE html>, ортасында <html lang="kk">, ал <head> ішінде charset, viewport, title және <style> болуы керек. Соңында нәтижені UTF-8 файлға жазамыз да, браузерде ашамыз.

    Қосыңыз:
    • page(title, body, css) - "<!DOCTYPE html>\n" жолымен басталатын құжат: <html lang="kk">, <head> ішінде реті бойынша <meta charset="utf-8">, viewport meta (name="viewport", content="width=device-width, initial-scale=1"), <title> (қорғалған), <style>; одан кейін <body>. Соңы \n;
    • generate(profile, theme) - page(...) шақырып, тақырып ретінде профиль атын, мазмұн ретінде build_body, CSS ретінде make_css(theme, BASE_CSS) береді;
    • save(path, text) - мәтінді UTF-8 файлға жазып, path қайтарады.
    Кеңес

    Бұрын жазған tag көмекшіңіз осында да көмектеседі: tag("meta", charset="utf-8"). Ішіндегі <head> мен <body> бөліктерін алдымен жеке жолға жинап, соңында tag("html", ..., lang="kk") ішіне салыңыз. Файлды with open(path, "w", encoding="utf-8") as f: деп ашыңыз: encoding болмаса, қазақ әріптері кейбір жүйелерде бұзылады.

    Ойланып көріңіз: viewport meta-ты алып тастасақ, телефонда не болады?

    Мобильді браузер бетті 980 пиксельдік «компьютер беті» деп есептеп, оны кішірейтіп көрсетеді де, мәтін ұсақ болып қалады. Viewport «құрылғының нақты енін қолдан» деп айтады (Web 0-аптадағы адаптивті дизайн). Бұл бір жол ғана, бірақ мобильді сайттың жартысы осыған байланысты.

    Файл қайда жазылады?

    Осы беттегі Python браузердің ішінде жұмыс істейді, сондықтан save жасаған файл «виртуалды» және компьютеріңізге түспейді. Өз компьютеріңізде python site.py істетсеңіз, my.html нағыз файл ретінде пайда болады да, оны екі рет басып ашасыз.

    Токенизация: мәтіннен сөздер

    Компьютер сөйлемді түсінбейді, оған жеке сөздер керек. Бірінші қадам - мәтінді токендерге (tokens) бөлу: бәрін кіші әріпке түсіреміз, тыныс белгілері мен сандарды тастаймыз. Қазақ әріптерін (ә, ғ, қ, ң, ө, ұ, ү, һ, і) жоғалтпау үшін \w емес, [^\W\d_] қолданамыз: «әріп (сөз таңбасы), бірақ цифр да, астын сызу да емес» дегенді білдіреді. Айырмашылықты өзіңіз көріңіз:

    import re

text = "Тамақ ӨТЕ дәмді! 10/10".lower()
print(re.findall(r"[^\W\d_]+", text))
print(re.findall(r"\w+", text))
    classifier.py файлында tokenize(text): мәтінді кіші әріпке айналдырып, тек әріптерден тұратын сөздердің тізімін қайтарады. Сандар, тыныс белгілері, дефис пен төменгі сызық бөлгіш болады; қайталанған сөздер сақталады.
    Кеңес

    Бір жол: re.findall(r"[^\W\d_]+", text.lower()). Тізім бос болса да ("!!! 123") қате шықпайды, бос тізім қайтады. Әр сөз тек бір рет емес, кездескен санына қарай тізімде қалады: оны келесі қадамда санау үшін қолданамыз.

    Ойланып көріңіз: \w+ неге жеткіліксіз?

    Жоғарыдағы шығысты салыстырыңыз: \w цифрларды да сөз таңбасы деп санайды, сондықтан «10» жеке «сөз» болып қалады. Модель үшін «10» мағынасыз шу. Сондай-ақ астын сызу _ да \w ішінде. Дұрыс таңдалған токенизация - модельдің сапасына тікелей әсер ететін алғашқы шешім.

  2. 2

    Оқыту: train

    Енді модельді оқытамыз. Аңғал Байес үшін оқыту - жай ғана санау: әр класта неше құжат бар, әр сөз әр класта неше рет кездесті. Бұл бір ғана for циклі! Ойымызша сөздердің реті маңызды емес, тек саны (сөздер қапшығы, bag of words). Санау үшін collections.Counter тамаша құрал:

    from collections import Counter

c = Counter()
c.update(["тамақ", "дәмді"])
c.update(["тамақ", "суық"])
print(c)
print(c["тамақ"], c["жоқ сөз"])

    Модельді қарапайым сөздік етіп сақтаймыз: кейін оны JSON-ға және JavaScript-ке көшіру оңай болады. Төрт пікірден тұратын шағын мысалда ол былай көрінеді:

    {"priors": {"pos": 0.5, "neg": 0.5},
 "counts": {"pos": {"тамақ": 1, "дәмді": 1, "қызмет": 1, "тамаша": 1},
            "neg": {"тамақ": 1, "суық": 2, "қызмет": 1, "баяу": 1}},
 "vocab": ["баяу", "дәмді", "суық", "тамаша", "тамақ", "қызмет"]}
    train(data), мұнда data = [("Тамақ дәмді", "pos"), ...], келесі сөздікті қайтарады:
    • "priors" - әр класс үшін үлесі: сол кластағы құжаттар саны / барлық құжат;
    • "counts" - әр класс үшін {сөз: неше рет} (тек кездескен сөздер; бір құжатта қайталанған сөз бірнеше рет саналады);
    • "vocab" - барлық кездескен әртүрлі сөздердің сұрыпталған тізімі.
    Кеңес

    Counter(label for _, label in data) әр класта неше құжат екенін береді, оны len(data)-ға бөлсеңіз priors шығады. Әр класқа Counter() жасап, counts[label].update(tokenize(text)) шақырыңыз. vocab үшін барлық сөздерді set-ке жинап, sorted тізімге айналдырыңыз. Қорытындыда Counter-ды dict(...) қылсаңыз, JSON-ға оңай өтеді.

    Ойланып көріңіз: біз сөздердің ретін тастадық. «Дәмді емес» мен «дәмді» үшін модель не дейді?

    Екеуіне де дерлік бірдей жауап береді: «емес» сөзі басқа сөздерден күштірек болмаса, ол жауапты өзгертпейді. Бұл сөздер қапшығының негізгі әлсіздігі - ол ретті де, терістеуді де түсінбейді. Сондықтан AI курсында одан әрі n-граммдар, нейрон желілер мен назар аудару (attention) келеді.

  3. 3

    Болжау: predict

    Ең қызық жері осында. Жаңа пікір келді: қай класқа жатады? Байес теоремасы бойынша әр класқа есептейміз: P(класс) · P(сөз₁ | класс) · P(сөз₂ | класс) ⋯, ең үлкені жеңеді. Үш ұсақ қақпан бар:

    • Нөл ықтималдық. Сөз бір класта мүлде кездеспесе, оның ықтималдығы 0 болып, бүкіл көбейтінді нөлге айналады. Сондықтан Лаплас тегістеуі (Laplace smoothing): санына 1 қосамыз, ал бөлгішке сөздік көлемін қосамыз: (count + 1) / (класстағы_сөздер_саны + len(vocab)).
    • Нөлге құлау. Ықтималдықтар кішкентай, ұзын мәтінде көбейтінді компьютер үшін 0-ге тең болып кетеді. Сондықтан көбейту орнына логарифмдерін қосамыз (math.log): ең үлкен мән сол күйінде жеңіп шығады.
    • Белгісіз сөз. vocab-та жоқ сөзді еленбейміз.
    predict(model, text): класс атауын (str) қайтарады. Кластарды әліпби ретімен (sorted(model["priors"])) қарап, score = log(prior) + Σ log(...) есептейді; ең үлкен score-лы класс жеңеді, тең болса әліпби бойынша бірінші.
    Кеңес

    Жақсы құрылым: known = set(model["vocab"]), words = [w for w in tokenize(text) if w in known]. Әр класс үшін counts = model["counts"][label], total = sum(counts.values()). Цикл ішінде counts.get(w, 0) қолданыңыз, себебі сөз осы класта кездеспеген болуы мүмкін (бірақ тегістеу арқасында ықтималдығы нөл емес). Ең жақсы класты if best_score is None or score > best_score арқылы таңдасаңыз, тең жағдайда бірінші қалады.

    Ойланып көріңіз: 0.001 санын 400 рет көбейтсек не шығады?

    Python 0.001 ** 400 деп есептесе, нәтиже 0.0 болады (float үшін ең кіші сан шамамен 10⁻³⁰⁸). Ал логарифмдерін қоссақ, 400 · log(0.001) ≈ -2763: бұл қалыпты сан. Екі класты салыстыру үшін логарифм жеткілікті, себебі log өспелі функция, үлкен мән үлкен күйінде қалады. Автотексеруші дәл осы «ұзын мәтін» жағдайын тексереді.

    Зертхана: модельдің ішіне үңілу

    Дайын нұсқа әр класстың score мәнін көрсетеді. Өз пікіріңізді жазып көріңіз: оң сөздер мен теріс сөздер қалай таластыратынын көресіз.

  4. 4

    Бағалау және экспорт

    Модель дұрыс жұмыс істей ме? «Сезім» бойынша емес, сан бойынша айтайық: дәлдік (accuracy) = дұрыс болжамдар саны / барлық болжамдар саны. Бір маңызды ереже: модельді оқу деректерінде бағалауға болмайды, себебі ол өзі көрген жауаптарды «жаттап алған» болуы мүмкін. Сондықтан сынау деректері (TEST) бөлек. Ал соңында модельді JSON жолына айналдырамыз: JavaScript бұл форматты өзінен-өзі оқиды, 4-жоба дәл осыны қолданады.

    Қосыңыз:
    • accuracy(model, data) - data = [(мәтін, дұрыс_класс), ...] үшін дұрыс болжамдар үлесі (0.0 - 1.0); бос data үшін 0.0;
    • export_model(model) - модельді JSON жолына айналдырады (json.dumps); қазақ әріптері \uXXXX болмай, өз күйінде қалуы керек (ensure_ascii=False).
    Кеңес

    sum(1 for text, label in data if predict(model, text) == label) / len(data) дәлдікті береді; бос тізімді алдын ала бөлек өңдеңіз, әйтпесе нөлге бөлу қатесі шығады. Экспортта json.dumps(model, ensure_ascii=False) жеткілікті.

    Ойланып көріңіз: сынау жиынында 100% дәлдік шықса, модель мінсіз бе?

    Жоқ. Біздің сынау жиынымыз небәрі 12 сөйлем және оқу жиынына ұқсас сөздерден тұрады. Нағыз өмірде жаңа сөздер, мысқыл, терістеу кездеседі: «суық емес, өте дәмді» деген сөйлемді төмендегі зертханада сынап көріңіз. Модель оқу деректерін шамадан тыс «жаттап алса», бұл артық үйрену (overfitting) деп аталады (AI 4-апта). Сондықтан нағыз жобаларда сынау деректері әлдеқайда көп және әртүрлі болады.

  1. 1

    JavaScript-те жіктеуші

    Python мен JavaScript-тің синтаксисі басқа, ал алгоритм бірдей. Сондықтан аудару - жеңіл жұмыс: Python-дағы for label in sorted(...) JavaScript-те for (const label of Object.keys(...).sort()) болады. Негізгі айырмашылықтар: math.log орнына Math.log, жиілігі жоқ сөз үшін counts.get(w, 0) орнына counts[w] || 0, ал [^\W\d_]+ орнына әріптерді табатын \p{L}+ (міндетті түрде u жалаушасымен).

    const text = "Тамақ ӨТЕ дәмді! 10/10";
console.log(text.toLowerCase().match(/\p{L}+/gu));
console.log("123".match(/\p{L}+/gu));   // сөз табылмаса null қайтады, бос массив емес
    model.js файлында:
    • tokenize(text) - кіші әріпке айналдырып, әріптерден тұратын сөздер массивін қайтарады (табылмаса бос массив);
    • predict(model, text) - Python-дағыдай: белгісіз сөздерді тастайды, Лаплас тегістеуімен log-ты қосады, кластарды әліпби ретімен қарайды, ең үлкен score-лы класты қайтарады (тең болса бірінші). model - 3-жоба экспорттаған нысан: {priors, counts, vocab}.
    Кеңес

    text.toLowerCase().match(/\p{L}+/gu) || []: match ештеңе таппаса null қайтарады, ал бізге бос массив керек. Класс бойынша жиынтық: Object.values(counts).reduce((a, b) => a + b, 0). Ең жақсы класты табу үшін let best = null, bestScore = -Infinity деп бастаңыз да, score > bestScore болғанда ғана жаңартыңыз (>= емес: тең жағдайда бірінші қалуы керек). Белгісіз сөздерді new Set(model.vocab) арқылы тез сүзуге болады.

    Ойланып көріңіз: сөз «constructor» болса, counts["constructor"] || 0 не береді?

    JavaScript нысандарында constructor, toString сияқты жасырын қасиеттер бар (Object.prototype арқылы), сондықтан counts["constructor"] 0 емес, функцияны қайтарады! Біздің жобада қауіп жоқ: біз тек vocab-тағы сөздерді іздейміз. Бірақ пайдаланушы мәтініндегі кез келген сөзбен жұмыс істесеңіз, Map не Object.hasOwn(counts, w) қолданыңыз. Python-да мұндай мәселе жоқ, JavaScript-ке аударғанда осындай «тілдің ерекшеліктері» шығады.

  2. 2

    Ықтималдықтар: softmax

    Тек «жағымды» деп айту аздау: пайдаланушы «қаншалықты сенімдісің?» деп сұрайды. Логарифмдік score-ларды (мысалы -23.1 және -25.7) пайызға айналдыру үшін softmax қолданамыз: escore алып, қосындыға бөлеміз. Бірақ -1500 сияқты score-дан Math.exp нөл береді! Сондықтан алдымен ең үлкен score-ды бәрінен азайтамыз: математикалық нәтиже өзгермейді, ал есеп тұрақты болады.

    const scores = [-23.1, -25.7];
const max = Math.max(...scores);
const exps = scores.map((s) => Math.exp(s - max));
const sum = exps.reduce((a, b) => a + b, 0);
console.log(exps.map((e) => Math.round((100 * e) / sum)));
console.log(Math.exp(-1500), Math.exp(-1500 - -1500));
    probabilities(model, text) (қаңқада tokenize, logScore, knownWords, predict дайын):
    • әр класс үшін пайызды (бүтін сан, Math.round) есептейді;
    • нәтиже - [класс, пайыз] жұптарының массиві: пайыз кему ретімен, тең болса класс әліпбиі бойынша. Мысалы [["pos", 87], ["neg", 13]].
    Кеңес

    Кластарды Object.keys(model.priors).sort() арқылы алыңыз, scores = labels.map((l) => logScore(model, l, words)). Кейін Math.max(...scores), exps, sum (жоғарыдағы мысалдай). Жұптар үшін labels.map((l, i) => [l, Math.round(...)]), ал сұрыптау: .sort((a, b) => b[1] - a[1] || (a[0] < b[0] ? -1 : 1)).

    Ойланып көріңіз: модель «97% жағымды» десе, 97% жағдайда дұрыс болады ма?

    Міндетті емес. Аңғал Байес сөздерді бір-біріне тәуелсіз деп есептейді («аңғал» болуы сондықтан), нәтижесінде пайыздар шектен тыс сенімді (overconfident) болып шығады. Пайыз - модельдің өз «сенімі», ал шындықтың ықтималдығы емес. Сондықтан кейде оны «сенім деңгейі» деп атаған дұрыс.

  3. 3

    Пішін: адамға көрсетеміз

    Енді модельді адамға көрсетеміз. Пішін (<form>) жіберілгенде браузер әдетте бетті қайта жүктейді. Біз submit оқиғасын ұстап, event.preventDefault() арқылы тоқтатамыз, пікірді оқимыз, probabilities шақырамыз да, нәтижені <p id="result"> ішіне жазамыз. Тапсырманы екіге бөлеміз: HTML бөлігін (форманың сыртқы түрі) төмендегі зертханада өзіңіз жазасыз, ал JavaScript бөлігін (тыңдаушы) автотексеруші тексереді.

    Зертхана: пішінді өзіңіз жазыңыз

    Бет дайын, тек форма жоқ. Комментарийді оқып, <form id="review-form">, ішінде <input id="review"> мен батырма, астында <p id="result"> жазыңыз да, ▶ басыңыз. Модель беттің ішінде тұр, пікір жазып сынаңыз.

    Модельдің нысаны (__MODEL__) қысқа болу үшін көрсетілмеген: іске қосқанда projects/model.js файлынан автоматты түрде қойылады.

    Автотексеруші үшін app.js: бет дайын (#review-form, #review, #result), MODEL мен алдыңғы функциялар қаңқада тұр. Тыңдаушыны жазыңыз:
    • submit кезінде бет қайта жүктелмейді (preventDefault);
    • мәтін бос (не тек бос орындар) болса: #result мәтіні "Алдымен пікір жазыңыз", класы бос;
    • әйтпесе: "Жағымды 😊: 97%" түріндегі мәтін (LABELS арқылы) және #result класы pos не neg (алдыңғы класс жиналып қалмайды).
    Кеңес

    form.addEventListener("submit", (event) => { event.preventDefault(); ... }). Мәтінді input.value.trim() деп алыңыз. probabilities(MODEL, text)[0] - ең ықтимал жұп, оны const [label, percent] = ... деп бөліп алыңыз. Нәтиже: result.textContent = `${LABELS[label]}: ${percent}%`, ал result.className = label (classList.add емес, себебі ол жиналып қалады).

    Ойланып көріңіз: нәтижені неге textContent арқылы қоямыз, innerHTML арқылы емес?

    Қазір біз тек өз жолымызды көрсетеміз, бірақ ертең нәтижеге пайдаланушы мәтінін де қоссақ (мысалы «Сіз жаздыңыз: ...»), innerHTML оны HTML ретінде орындар еді. Бұл - 1-жобадағы XSS-тің дәл өзі. textContent кез келген мәтінді тек мәтін ретінде қояды, сондықтан қауіпсіз әдет болып қалады.

  4. 4

    Жариялау алдындағы құпия іздегіш

    Сайт дайын. Бірақ GitHub Pages-ке қоятын нәрсе бүкіл әлемге ашық. Кодқа қойылған API кілті не құпия сөз бірнеше минутта боттарға табылады: оларды іздейтін құралдар тынбай жұмыс істейді. Web 8-аптада көргеніміздей, құпияның орны - орта айнымалылары, .gitignore-ға жазылған .env файлы не GitHub Secrets. Ал енді қарапайым құпия іздегішті өзіңіз жазасыз: ол кодты оқып, күдікті жолдарды табады. Бүгін модельде құпия жоқ, бірақ ертең бұл сайтқа сыртқы API қосқанда осы құрал өз пайдасын көрсетеді.

    const bad = 'const API_KEY = "sk-live-12345678";';
const good = "const key = process.env.API_KEY;";
const re = /api[_-]?key\w*\s*=\s*["'][^"']{8,}["']/i;
console.log(re.test(bad), re.test(good));
    publish.js файлында findSecrets(code) - code (көп жолды мәтін) ішінде күдікті жолдардың нөмірлерін (1-ден бастап) массив етіп қайтарады. Жол күдікті, егер:
    • онда api_key / apiKey / api-key / secret / token / password бар (регистр маңызды емес; атынан кейін әріптер мен JSON-дағыдай тырнақша болуы мүмкін);
    • артынан = не : және тырнақшадағы кемінде 8 таңбалы мән келсе ("sk-live-12345678").
    process.env.API_KEY сияқты орта айнымалысын оқу қауіпсіз, оны белгілемеңіз.
    Кеңес

    code.split("\n") жолдарға бөледі, forEach((line, i) => ...) ішінде жол нөмірі i + 1. Өрнек құрылымы: ат (api[_-]?key|secret|token|password) + \w* + міндетті емес тырнақша ["']? + \s*[:=]\s* + ["'][^"']{8,}["']. Регистрге қарамау үшін өрнек соңына i жалаушасын қосыңыз.

    Ойланып көріңіз: кілтті кодтан өшіріп тастасақ, ол GitHub-тан жоғала ма?

    Жоқ! Git тарихы бәрін есте сақтайды: кілт ескі коммитте қала береді. Кілтті жарияланып қойғаннан кейін өшірумен шектелмей, оны бірден жарамсыз етіп (revoke), жаңасын шығарыңыз. Сондықтан ереже қарапайым: құпия ешқашан репозиторийге түспеуі керек. Web 8-аптадағы «Қандай ақпаратты жария етеміз?» бөлімін қайта оқып шығыңыз.

  5. 5

    Жариялау тізімі

    Соңғы қадам - сайтты әлемге шығару. Жариялау - бір команда емес, шағын процесс: код GitHub-қа түседі, құпиялар сыртта қалады, сайт GitHub Pages арқылы қолжетімді болады. Бастаңыз:

    git init
git add .
git commit -m "Пікір талдаушы: бірінші нұсқа"
git branch -M main
git remote add origin https://github.com/<аты>/review-ai.git
git push -u origin main

    Содан кейін GitHub-та репозиторийде Settings → Pages → Build and deployment → Deploy from a branch таңдап, main және / (root) көрсетіңіз. Бір-екі минуттан соң сайт https://<аты>.github.io/review-ai/ мекенжайында ашылады. Құпиялар үшін .gitignore файлы:

    .env
node_modules/
*.key

    Docker - сайтты кез келген машинада бірдей іске қосудың тәсілі. Біздің сайт статикалық, сондықтан nginx суреті жеткілікті; Dockerfile бар болғаны үш жол:

    FROM nginx:alpine
COPY index.html /usr/share/nginx/html/index.html
EXPOSE 80
    docker build -t review-ai .
docker run -p 8080:80 review-ai    # http://localhost:8080

    Ұзағырақ жолмен кету үшін: GitHub Actions арқылы әр push кезінде автоматты тексеру не жариялау жасауға болады (Web 7: CI/CD).

    Жариялау тізімі

    • Код GitHub репозиторийінде: git push орындалды, index.html түбірде тұр.
    • Кодта API кілті, құпия сөз не токен жоқ: құпия іздегішім күдікті жол таппайды.
    • .gitignore ішінде .env жазылған; нақты құпиялар (болса) орта айнымалыларында не GitHub Secrets-те.
    • GitHub Pages қосылған (Settings → Pages → main / root), сілтеме ашылады.
    • Сайт телефонда да ашылады (viewport meta бар, мәтін оқылады) және пікір жібергенде нәтиже шығады.
    • Нәтиже textContent арқылы қойылады, innerHTML емес.
    • Dockerfile жазылды: nginx суретіне index.html көшіріледі (іске қосу міндетті емес).
