S05·09Compiler Construction

Код генерациясы: стек машинасы

  • күрделі
  • ≈ 55 мин
  • 3 мақсат
  • 5 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

AОқу мақсаттары

  • Ағаштан стек машинасының командаларын (PUSH, LOAD, ADD, …) кейінгі ретпен генерациялау.
  • Ең үлкен стек тереңдігі d(e) = max(d(a), d(b) + 1) екенін дәлелдеп, оны регистр санымен байланыстыру.
  • Коммутативті амалдарда операндтарды ауыстырып, стек тереңдігін азайту.

BАлғышарттар

  • Оңтайландыру

CҰғымға кіріспе

Конвейердің соңғы қадамы - код генерациясы: аралық көріністі мақсатты машинаның командаларына аудару. Ең қарапайым мақсатты машина - стек машинасы: операндтар стекке салынады, амал жоғарғы екеуін алып, нәтижені қайтадан салады. JVM, Python байткоды, WebAssembly - стек машиналары. Генерация бір жолда жазылады: сол бала, оң бала, амал.

Бірақ ресурс бар: стектің тереңдігі (нақты процессорда - регистрлер саны). ((a+b)+c)+d және a+(b+(c+d)) бірдей мән береді, бірақ біріншісі стекте ең көп 2 мән, екіншісі 4 мән ұстайды. Неге? Себебі оң жақ ішкі ағашты есептеу кезінде сол жақтың нәтижесі стекте «күтіп» тұрады. Бұл бақылау Сети-Ульман алгоритмінің негізі - регистрлерді үнемдейтін код генерациясы.

DАкадемиялық теория

Анықтама

Генерация және тереңдік

gen(сан) = PUSH; gen(айнымалы) = LOAD; gen((op, a, b)) = gen(a) ++ gen(b) ++ [OP]. d(e) - gen(e) орындалғанда (бос стектен бастап) стектің ең үлкен биіктігі.

Теорема

Тереңдік формуласы

(1) gen(e) бос стекте орындалса, соңында стекте дәл бір мән қалады - eval(e). (2) d(жапырақ) = 1, d((op, a, b)) = max(d(a), d(b) + 1).

Дәлелдеу

Дәлелдеу (құрылымдық индукция)

Күштірек тұжырым: биіктігі h стектен басталса, gen(e) стектің төменгі h мәнін қозғамайды, соңында биіктік h + 1 (үстінде eval(e)), ал ең үлкен биіктік h + d(e). Жапырақ: бір PUSH/LOAD - биіктік h + 1, d = 1. (op, a, b): gen(a) h-тен басталады, ең үлкені h + d(a), соңында h + 1 (eval(a) үстінде). gen(b) h + 1-ден басталады: ең үлкені h + 1 + d(b), соңында h + 2. OP екеуін алып, бір нәтиже салады: соңында h + 1, үстінде op(eval(a), eval(b)) = eval(e). Ең үлкен биіктік max(h + d(a), h + 1 + d(b)) = h + max(d(a), d(b) + 1). h = 0 қойсақ (1) және (2) шығады. ∎ Салдар: сол жаққа ұзын, оң жаққа қысқа ағаштар таяз. Коммутативті + мен * үшін тереңірек ішкі ағашты солға қою d-ны азайтады.

Ескерту

Регистрлер

Регистрлік машинада d(e) - стек «регистрлерге» сыйса, жадқа шығару (spill) керек емес. Сети-Ульман (1970): тереңірек ішкі ағашты бірінші есептеу регистрлер санын минималдайды. Бұл теореманың коммутативті емес амалдарға (a − b) кеңеюі - операндтарды кері ретпен есептеп, кейін «ауыстыру» командасымен.

EКөрнекі түсіндірме

Бір мән (10), екі түрлі ресурс: сол жақтан топтасқан ағашқа стек тереңдігі 2, оң жақтан топтасқанға 4. Формула симуляциямен дәл сәйкес келеді.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Ағашты кейінгі ретпен аралап, PUSH/LOAD және амал командаларын шығару.
  2. VM-де орындап, нәтижені ағаш интерпретаторымен салыстыру.
  3. Әр түйінге тереңдікті d(e) = max(d(a), d(b) + 1) бойынша есептеу.
  4. Коммутативті амалда d(b) > d(a) болса, балаларды ауыстыру.
  5. Тереңдікті машинаның регистр санымен салыстыру.

GЖұмыс мысалдары

HИнтерактивті эксперимент

Теңгерімді ағаш (a+b)+(c+d): тереңдік қанша? Формуламен есептеп, симуляциямен салыстырыңыз. n жапырақты ағаш үшін ең кіші және ең үлкен мүмкін тереңдік қандай?

IЖаттығулар

JМатематикалық пайымдау

Тереңдік теоремасы код генерациясының ресурс жағын ашады: бірдей мағыналы ағаштардың бағасы әртүрлі, ал күштірек индукция болжамы (кез келген h биіктіктен бастап) дәлелді таза етеді - m07-дегі «индукция болжамын күшейту» тәсілінің мысалы. Коммутативтілік оңтайландыруға мүмкіндік береді, бірақ тек мағына сақталатын жерде - 8-сабақтағы ереже қайта қолданылды.

KЖиі қателер

  • SUB-та операндтардың ретін шатастыру (b − a).
    Себебі: Стектің үстінде b тұр; a − b үшін алдымен b, сосын a алынады.
    Түзету: b, a = pop(), pop(); нәтиже a − b.
  • Коммутативті емес амалда балаларды ауыстыру.
    Себебі: Мағына өзгереді.
    Түзету: Тек + және * үшін (бүтін сандарда).

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.
