S05·06Compiler Construction

Семантикалық талдау

  • зерттеу
  • ≈ 60 мин
  • 3 мақсат
  • 5 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. Парсер 1 + true не if 5 then … сияқты сөйлемдерді қабылдайды - олар синтаксистік тұрғыдан дұрыс. Бірақ мағынасы жоқ. Семантикалық талдау - синтаксистен кейінгі тексеріс: әр атау анықталған ба, амалдар дұрыс типтерге қолданылған ба? Екі құрал.
  2. Жол. 1-қадам. Тілдің типтерін және әр құрылымның типтер ережесін жазу.
  3. Жол. 2-қадам. Ағашты аралап, әр түйінге ережелер бойынша тип беру.
  4. Жол. 3-қадам. Атауларды аймақтар кестесінен іздеу; let жаңа аймақ ашады.
  5. Жол. 4-қадам. Ереже бұзылса - қай түйінде, қандай тип күтілгенін айтатын қате.
  6. Жол. 5-қадам. Дұрыстық теоремасын индукциямен дәлелдеп, тип тексерушінің орнын түсіну.
  7. Тексер. Типтердің дұрыстығы теоремасы нені кепілдейді? Жауап: Типтері тексерілген бағдарлама орындалғанда тип қатесіне ұшырамайды.. Дұрыс.
  8. Түйін. Типтердің дұрыстығы. Γ ⊢ e : τ және орта ρ Γ-ге сай болса (әр x үшін ρ(x) мәні Γ(x) типіне жатады), онда eval(e, ρ) тип қатесіне ұшырамайды және τ типті мән қайтарады.
  9. Түйін. Жиі қате: Ортаны (env) орнында өзгерту: env[x] = t. Дұрысы: Жаңа сөздік не аймақтар стегі.

AОқу мақсаттары

  • Аймақтар (scope) кестесін құрып, атаулардың қай анықтамаға сілтейтінін шешу.
  • Шағын тілдің типтерін тексеретін функция жазып, түсінікті қате хабарын беру.
  • Типтері тексерілген бағдарлама орындалғанда тип қатесіне ұшырамайтынын (типтердің дұрыстығы) құрылымдық индукциямен дәлелдеу.

BАлғышарттар

  • Басымдық: Pratt парсері

CҰғымға кіріспе

Парсер 1 + true не if 5 then … сияқты сөйлемдерді қабылдайды - олар синтаксистік тұрғыдан дұрыс. Бірақ мағынасы жоқ. Семантикалық талдау - синтаксистен кейінгі тексеріс: әр атау анықталған ба, амалдар дұрыс типтерге қолданылған ба?

Екі құрал. Аймақтар кестесі: let x = … in … жаңа аймақ ашады, ішкі x сыртқысын жасырады, аймақ біткенде ескі мағына қайтады. Типтерді тексеру: әр түйінге тип береміз (int, bool) және ережелерді тексереміз. Мұның сыйы - Робин Милнердің әйгілі тұжырымы: «типтері дұрыс бағдарламалар қате кетпейді» (well-typed programs cannot go wrong). Біз оны өз тіліміз үшін дәлелдейміз.

DАкадемиялық теория

Анықтама

Типтер ережелері

Γ ⊢ e : τ - «Γ ортасында e өрнегінің типі τ». int n : int, bool b : bool; x : Γ(x); e₁, e₂ : int болса e₁ ∘ e₂ : int (∘ ∈ {+, −, *}), e₁ < e₂ : bool; e₁, e₂ : τ болса e₁ == e₂ : bool; c : bool, a : τ, b : τ болса if c then a else b : τ; e₁ : τ₁ және Γ[x ↦ τ₁] ⊢ e₂ : τ₂ болса let x = e₁ in e₂ : τ₂.

Теорема

Типтердің дұрыстығы

Γ ⊢ e : τ және орта ρ Γ-ге сай болса (әр x үшін ρ(x) мәні Γ(x) типіне жатады), онда eval(e, ρ) тип қатесіне ұшырамайды және τ типті мән қайтарады.

Дәлелдеу

Дәлелдеу (құрылымдық индукция)

e-нің құрылымы бойынша. Тұрақтылар: мәні өз типінде. Айнымалы x: ρ Γ-ге сай, сондықтан ρ(x) - Γ(x) типті. e₁ + e₂: ереже бойынша e₁ : int, e₂ : int; индукция бойынша eval(e₁), eval(e₂) - бүтін сандар, ал + бүтін сандарға анықталған, нәтиже int. < және == ұқсас (нәтиже bool). if c then a else b: c : bool, индукция бойынша eval(c) - логикалық мән, сондықтан тармақ таңдалады (тип қатесі жоқ); таңдалған тармақ индукция бойынша τ типті. let x = e₁ in e₂: eval(e₁) τ₁ типті, сондықтан ρ[x ↦ eval(e₁)] Γ[x ↦ τ₁]-ге сай; индукция бойынша eval(e₂) τ₂ типті. ∎ Тип тексеруші - бағдарламаны орындамай, оның мінез-құлқы туралы барлық кіріс үшін дұрыс тұжырым жасайтын дәлелдеуші.

Ескерту

Аймақтар

Ортаны өзгертпей, жаңа сөздік жасау ({**env, x: t}) аймақтың шекарасын автоматты сақтайды: let ішіндегі x сыртқа шықпайды. Ірі компиляторларда бұл - аймақтар стегі (кіргенде push, шыққанда pop).

EКөрнекі түсіндірме

Бес бағдарлама: екеуі тексеруден өтті, үшеуі орындалмай тұрып тоқтатылды - әрқайсысына себебі айтылды. Тип тексеруші бағдарламаны іске қоспайды, бірақ оның ешқашан «int-ке bool қосуға» тырыспайтынын кепілдейді.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Тілдің типтерін және әр құрылымның типтер ережесін жазу.
  2. Ағашты аралап, әр түйінге ережелер бойынша тип беру.
  3. Атауларды аймақтар кестесінен іздеу; let жаңа аймақ ашады.
  4. Ереже бұзылса - қай түйінде, қандай тип күтілгенін айтатын қате.
  5. Дұрыстық теоремасын индукциямен дәлелдеп, тип тексерушінің орнын түсіну.

GЖұмыс мысалдары

HИнтерактивті эксперимент

== үшін тип тексерісін алып тастадық. 1 == true қандай тип алады? Енді (1 == true) бағдарламасы орындалғанда тип қатесі бола ма? Дұрыстық теоремасының қай қадамы бұзылды - әлде бұл ереже қауіпсіз бе (Python-да 1 == True не береді)?

IЖаттығулар

JМатематикалық пайымдау

Тип тексеруші - бағдарламаның барлық мүмкін орындалуы туралы дәлелдеуші: дұрыстық теоремасы құрылымдық индукциямен әр ережені бір рет тексеріп, шексіз көп кіріс үшін кепілдік береді. Бұл m02-дегі индукцияның ең практикалық қолданыстарының бірі. Аймақтар кестесі мен тип ортасы бір құрылым - атаудан ақпаратқа бейнелеу, тек бірі мәнді, бірі типті сақтайды.

KЖиі қателер

  • Ортаны (env) орнында өзгерту: env[x] = t.
    Себебі: let-тен шыққанда сыртқы x-тің типі жоғалады.
    Түзету: Жаңа сөздік не аймақтар стегі.
  • Бірінші тип қатесінде тоқтап, түсініксіз хабар беру.
    Себебі: Пайдаланушы не дұрыс емес екенін білмейді.
    Түзету: Түйін, күтілген тип, келген тип - хабарда.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.
