S05·08Compiler Construction

Оңтайландыру

  • зерттеу
  • ≈ 60 мин
  • 3 мақсат
  • 5 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

AОқу мақсаттары

  • Тұрақтыларды бүктеуді (constant folding) және алгебралық жеңілдетулерді іске асыру.
  • Бүктеу мағынаны сақтайтынын (eval(fold(e)) = eval(e)) құрылымдық индукциямен дәлелдеу.
  • Тірі айнымалылар талдауымен өлі кодты (нәтижеге әсер етпейтін меншіктеулерді) жою.

BАлғышарттар

  • Аралық көрініс: үш адресті код

CҰғымға кіріспе

Компилятор кодты тек аудармайды - оны жақсартады. Бағдарламашы 2 * 60 * 60 деп оқылатындай жазады, ал компилятор оны бір рет, компиляция кезінде 7200-ге айналдырады. Бағдарламашы бір айнымалыны есептеп, кейін қолданбауы мүмкін - компилятор ол есептеуді алып тастайды. Бұл - оңтайландыру.

Оңтайландырудың алтын ережесі: мағынаны сақта. Жылдам, бірақ басқа нәтиже беретін код - қате код. Сондықтан әр түрлендіру дәлелденуі керек. Бұл сабақта екі классикалық түрлендіруді жасаймыз: тұрақтыларды бүктеу (ағашта) және өлі кодты жою (тірі айнымалылар талдауы арқылы, TAC тізбегінде) - және біріншісінің дұрыстығын дәлелдейміз.

DАкадемиялық теория

Анықтама

Бүктеу ережелері

fold(e): жапырақ - өзі. (op, a, b): a' = fold(a), b' = fold(b); екеуі де сан болса - op(a', b') саны; әйтпесе алгебралық ережелер: x * 0 → 0, 0 * x → 0, x + 0 → x, x * 1 → x; қалған жағдайда (op, a', b').

Теорема

Бүктеу мағынаны сақтайды

Бүтін сандар үстіндегі, жанама әсері жоқ өрнектер үшін: кез келген орта ρ-да eval(fold(e), ρ) = eval(e, ρ).

Дәлелдеу

Дәлелдеу (құрылымдық индукция)

Жапырақ: fold(e) = e. (op, a, b): индукция бойынша eval(a', ρ) = eval(a, ρ) = u және eval(b', ρ) = eval(b, ρ) = v. Онда eval((op, a', b'), ρ) = op(u, v) = eval(e, ρ). Енді әр нәтижелік түр сол мәнді береді: (і) a', b' сандар: op(a', b') = op(u, v). (іі) x * 0: v = 0, сондықтан op(u, v) = u·0 = 0 - кез келген u үшін (бүтін сандарда). (ііі) x + 0: u + 0 = u = eval(a', ρ). (іv) x * 1: u·1 = u. (v) өзгеріссіз (op, a', b') - жоғарыда көрсетілді. ∎ Шарттар маңызды: қалқымалы нүктеде x * 0 ≠ 0 болуы мүмкін (x = ∞ не NaN), ал x жанама әсері бар шақыру болса (f() * 0), оны жою бағдарламаның мінезін өзгертеді.

Ескерту

Тірі айнымалылар

Айнымалы x бағдарламаның бір нүктесінде тірі, егер оның мәні кейін (қайта меншіктелмей тұрып) оқылса. Кері бағытта аралау: live := live \ {dst} ∪ uses(e). Тірі емес айнымалыға меншіктеу (жанама әсерсіз) - өлі код, оны жою нәтижені өзгертпейді.

EКөрнекі түсіндірме

(2 + 3) * x → 5 * x; (y − y) * (0 + 0) → … * 0 → 0; соңында + 0 жойылды: бүкіл ағаш ('*', 5, 'x')-ке айналды. Өлі код: c ешқайда қолданылмайды, ал бірінші a кейін қайта меншіктелді, бірақ b арқылы тірі - сақталды.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Ағашты төменнен жоғары аралау: алдымен балаларды бүктеу.
  2. Екі баласы да сан болса - бірден есептеу.
  3. Алгебралық ережелерді қолдану, олардың шарттарын (бүтін сан, жанама әсерсіз) тексеру.
  4. TAC тізбегін кері аралап, тірі айнымалылар жиынын жүргізу.
  5. Тірі емес мақсатқа меншіктеулерді жою және дифференциалды тестпен мағынаның сақталғанын тексеру.

GЖұмыс мысалдары

HИнтерактивті эксперимент

Қате ереже қостық: x − 0 → 0. Бағдарлама қате бермейді. Мысал ағашта нәтиже өзгерді ме? Дифференциалды тест (жұмыс мысалындағы) бұл қатені қанша итерацияда табар еді? Дәлелдеудің қай жерінде бұл ереже құлайды?

IЖаттығулар

JМатематикалық пайымдау

Оңтайландырудың әр ережесі - кішкентай теорема, ал оның шарттары (бүтін сандар, жанама әсердің жоқтығы) - оның қолданылу шекарасы. Құрылымдық индукция бүктеудің дұрыстығын бір рет дәлелдейді; эксперимент көрсеткендей, бір қате ереже үнсіз бұзады, ал дифференциалды тест оны тез табады. Нақты компиляторлар (GCC, LLVM) жүздеген осындай ережені қолданады - және олардың әрқайсысының дұрыстығы дәл осылай негізделеді.

KЖиі қателер

  • Қалқымалы нүктелі сандарда x * 0 → 0 ережесін қолдану.
    Себебі: x = ∞ не NaN болса, нәтиже NaN, 0 емес.
    Түзету: Ережені тек бүтін сандарға (не -ffast-math баптауымен ғана).
  • Оңтайландыруды тексерусіз қосу.
    Себебі: Қате оңтайландыру бағдарламаның мағынасын үнсіз өзгертеді.
    Түзету: Әр ережеге дәлел не кемінде дифференциалды тест.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.

MРефлексия

NТереңірек

Honors

  • Тұрақтыларды тарату (constant propagation) мен бүктеуді TAC-та біріктіріп, бекітілген нүктеге (fixpoint) дейін қайталаңыз. Қанша итерация керек?

Research

  • Alive (Lopes et al., PLDI 2015): LLVM-нің peephole оңтайландыруларын SMT шешушімен автоматты дәлелдеу. Ол қанша қате тапты?

Дереккөз және лицензия

  • R. Nystrom, Crafting Interpreters - рекурсивті түсу және Pratt парсері (салыстыру үшін).
