11·04Memory & Pointers

Стек және шақырулар

  • күрделі
  • ≈ 50 мин
  • 3 мақсат
  • 6 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. Әр функция шақыруы стекке бір жақтау қосады: параметрлер, жергілікті айнымалылар және «қайда қайту керек» мекенжайы. Функция аяқталғанда жақтау алынады - оның жергілікті айнымалылары жойылады .
  2. Жол. 1-қадам. main шақырады f(3): стекке f-тің жақтауы (n = 3, қайту мекенжайы).
  3. Жол. 2-қадам. f(3) шақырады f(2): тағы бір жақтау үстіне.
  4. Жол. 3-қадам. f(0) қайтады: жақтау алынады, басқару f(1)-дегі сақталған қайту орнына.
  5. Жол. 4-қадам. Бәрі қайтқанда стек main-нің жақтауына қайта оралады.
  6. Тексер. int *f(void) { int x = 5; return &x; } - мәселе неде? Жауап: f біткенде x жойылады - қайтарылған көрсеткіш ілулі. Дұрыс: автоматты сақтау ұзақтығы.
  7. Түйін. Стек тереңдігі. Рекурсивті функция әр шақыруда кемінде F байттық жақтау қолданса, тереңдігі d рекурсия кемінде d · F байт стек жадын қажет етеді; стек өлшемі S болса, d > S / F…
  8. Түйін. Жиі қате: Жергілікті массивтің мекенжайын қайтару (char buf[64]; return buf;). Дұрысы: Шақырушының буферін параметр етіп алу не malloc.

AОқу мақсаттары

  • Шақыру стегін жақтаулар (frame) тізбегі ретінде модельдеу: параметрлер, жергілікті айнымалылар, қайту орны.
  • Жергілікті айнымалының өмір сүру уақытын және оның мекенжайын қайтарудың қаупін түсіндіру.
  • Рекурсия тереңдігі мен стек жадының байланысын (Stack overflow) көрсету.

BАлғышарттар

  • Көрсеткіш арифметикасы
  • Рекурсия мен итерация

CҰғымға кіріспе

Әр функция шақыруы стекке бір жақтау қосады: параметрлер, жергілікті айнымалылар және «қайда қайту керек» мекенжайы. Функция аяқталғанда жақтау алынады - оның жергілікті айнымалылары жойылады. m09 l06-да айқын стек жасағанымыз - компьютердің өзі осылай жұмыс істейді.

Салдар: жергілікті айнымалының мекенжайын қайтару - қате. int *f(void) { int x = 5; return &x; } - f біткенде x жоқ, көрсеткіш «ілулі» қалады. gcc мұны -Wreturn-local-addr ескертуімен ұстайды.

DАкадемиялық теория

Анықтама

Автоматты сақтау ұзақтығы

Функция ішінде (static-сіз) жарияланған айнымалы - автоматты: оның өмірі блокқа кіргенде басталып, блоктан шыққанда бітеді (C11 6.2.4). Жадының орны - әдетте стек.

Теорема

Стек тереңдігі

Рекурсивті функция әр шақыруда кемінде F байттық жақтау қолданса, тереңдігі d рекурсия кемінде d · F байт стек жадын қажет етеді; стек өлшемі S болса, d > S / F болғанда стек толады.

Дәлелдеу

Дәлелдеу

Тереңдігі d рекурсияда ең терең нүктеде d шақыру бір мезгілде белсенді: әрқайсысы әлі аяқталмаған (оның ішіндегі шақыру жалғасып жатыр), сондықтан олардың жақтаулары стекте қатар тұр (жақтау тек функция аяқталғанда алынады). Жақтаулар қиылыспайды, әрқайсысы ≥ F байт, барлығы ≥ d · F. Стек S байттан аспайды, демек d · F > S болса, сыймайды. ∎ Linux-та әдепкі стек ≈ 8 МБ; жақтауы 100 байт рекурсия ≈ 80 000 тереңдікте құлайды.

Ескерту

Стек төмен қарай өседі

x86-64-те стек жоғары мекенжайлардан төменге өседі: шақырылған функцияның жергілікті айнымалылары әдетте шақырушынікінен кіші мекенжайда. Бұл - іске асыру ерекшелігі, стандарт талабы емес.

EКөрнекі түсіндірме

Әр түйін - стектегі бір жақтау. Ең терең нүктеде 6 жақтау қатар тұр (n = 5..0); әрқайсысы өз n-ін сақтайды.

Интерактивті модель: өзің басқар

Шақыру стекке жақтау қосады, қайту - оны алады. Жақтаудағы a, b, t айнымалылары функциямен бірге жоғалатынын бақылаңыз.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. main шақырады f(3): стекке f-тің жақтауы (n = 3, қайту мекенжайы).
  2. f(3) шақырады f(2): тағы бір жақтау үстіне.
  3. f(0) қайтады: жақтау алынады, басқару f(1)-дегі сақталған қайту орнына.
  4. Бәрі қайтқанда стек main-нің жақтауына қайта оралады.

GЖұмыс мысалдары

HИнтерактивті эксперимент

static айнымалы стекте емес, бағдарлама бойы өмір сүреді - оның мекенжайын қайтару қауіпсіз. static-ті алып тастасаңыз, gcc «function returns address of local variable» деп ескертеді (бұл курс оны қате деп есептейді).

IЖаттығулар

JМатематикалық пайымдау

Стек - ең жылдам және ең қарапайым жад басқаруы: бөлу мен босату - бір регистрді жылжыту. Бірақ оның шегі бар: өлшемі шектеулі және нысан функциядан «аман шыға» алмайды. Функциядан ұзақ өмір сүруі керек деректер үшін - келесі сабақтағы үйме.

KЖиі қателер

  • Жергілікті массивтің мекенжайын қайтару (char buf[64]; return buf;).
    Себебі: Функциядан кейін buf жоқ.
    Түзету: Шақырушының буферін параметр етіп алу не malloc.
  • Стекте өте үлкен массив (int big[10000000];).
    Себебі: 40 МБ стекке сыймайды - құлау.
    Түзету: static не malloc (үйме).
  • printf("%d %d", f(), global) - f() global-ды өзгертеді деп күту.
    Себебі: Аргументтердің есептелу реті анықталмаған: gcc бұл модульді тексергенде global-ды f()-тен БҰРЫН оқыды.
    Түзету: Алдымен int r = f(); сосын printf.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.

MРефлексия

NТереңірек

Honors

  • ulimit -s командасымен стек өлшемін өзгертіп, рекурсия тереңдігінің шегі қалай өзгеретінін тексеріңіз.

Research

  • Стек буферінің толуы (stack smashing) және оған қарсы қорғаулар: canary, ASLR, NX бит. -fstack-protector не істейді?
