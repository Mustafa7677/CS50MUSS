11·10Memory & Pointers

Python-да жады қалай басқарылады

  • орта
  • ≈ 55 мин
  • 3 мақсат
  • 6 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. Python-да free жоқ - бірақ жад бәрібір босатылады. CPython-да әр нысанның сілтемелер санағышы бар: жаңа айнымалы не тізім элементі оған сілтесе +1, сілтеме жоғалса −1. Санағыш 0 болғанда нысан бірден жойылады (C-дағы free автоматты түрде шақырылады).
  2. Жол. 1-қадам. x = [1, 2, 3] - тізім нысаны, refcount = 1 (x).
  3. Жол. 2-қадам. y = x - refcount = 2 (бүркеншік ат, m08 l02).
  4. Жол. 3-қадам. del x - refcount = 1; тізім әлі тірі (y).
  5. Жол. 4-қадам. y = None - refcount = 0 - тізім бірден жойылады (C-да free(...)-ке тең).
  6. Тексер. a = [1]; b = [a]; a.append(b); del a, b - не болады? Жауап: Цикл: санағыштар 0-ге жетпейді, тізімдерді gc кейін жинайды. Дұрыс (теорема).
  7. Түйін. Санағыш циклды жоя алмайды. Нысандар циклы (әрқайсысына циклдағы басқасы сілтейді) сыртқы сілтемелер жойылғаннан кейін де тек санағыш арқылы жойылмайды.
  8. Түйін. Жиі қате: «Python-да жад туралы ойлаудың қажеті жоқ». Дұрысы: Қажет емес сілтемелерді жою, weakref, tracemalloc арқылы өлшеу.

AОқу мақсаттары

  • Python нысандарының сілтемелер санағышы (reference counting) арқылы жойылуын түсіндіру.
  • Циклдық сілтемелер мен қоқыс жинаушының (gc) рөлін көрсету.
  • C-ның қолмен басқаруы мен Python-ның автоматты басқаруын салыстыру; модуль жобасын (p11) жоспарлау.

BАлғышарттар

  • Динамикалық массив
  • Кортеждер және өзгермейтіндік

CҰғымға кіріспе

Python-да free жоқ - бірақ жад бәрібір босатылады. CPython-да әр нысанның сілтемелер санағышы бар: жаңа айнымалы не тізім элементі оған сілтесе +1, сілтеме жоғалса −1. Санағыш 0 болғанда нысан бірден жойылады (C-дағы free автоматты түрде шақырылады).

Бір мәселе: циклдар. a.next = b, b.next = a болса, сыртқы сілтемелер жоғалса да әрқайсысының санағышы 1 - олар ешқашан 0-ге жетпейді. Бұл үшін Python-да қосымша қоқыс жинаушы (gc модулі) бар: ол мезгіл-мезгіл жетуге болмайтын циклдарды тауып, жояды.

DАкадемиялық теория

Анықтама

Сілтемелер санағышы

refcount(x) = x-ке сілтейтін орындардың саны (айнымалылар, контейнер элементтері, атрибуттар, функция стегі). sys.getrefcount(x) - бұл сан + 1 (аргумент ретінде берілгені үшін).

Теорема

Санағыш циклды жоя алмайды

Нысандар циклы (әрқайсысына циклдағы басқасы сілтейді) сыртқы сілтемелер жойылғаннан кейін де тек санағыш арқылы жойылмайды.

Дәлелдеу

Дәлелдеу

Цикл x₁ → x₂ → ... → xₖ → x₁ болсын. Сыртқы сілтемелер жоқ болғанда әр xᵢ-ге циклдағы алдыңғы элемент сілтейді, демек refcount(xᵢ) ≥ 1 барлық i үшін. Санағыш әдісі нысанды тек refcount = 0 болғанда жояды. Бірде-бір xᵢ жойылмағандықтан, ешбір сілтеме жоғалмайды да, санағыштар азаймайды - ешбір xᵢ ешқашан 0-ге жетпейді. ∎ gc бұл жағдайды «қол жетімділік» арқылы шешеді: тамырлардан (айнымалылардан) жетуге болмайтын нысандар - қоқыс.

Ескерту

id() және мекенжай

CPython-да id(x) - нысанның жадтағы мекенжайы. Python айнымалысы - нысанға сілтеме (C көрсеткішіне ұқсас), бірақ көрсеткіш арифметикасы, NULL-ды ашу, use-after-free мүмкін емес.

EКөрнекі түсіндірме

A соңғы сілтеме (b) жойылғанда бірден жойылды. X↔Y циклы тек gc.collect() кезінде жойылды (теорема).

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. x = [1, 2, 3] - тізім нысаны, refcount = 1 (x).
  2. y = x - refcount = 2 (бүркеншік ат, m08 l02).
  3. del x - refcount = 1; тізім әлі тірі (y).
  4. y = None - refcount = 0 - тізім бірден жойылады (C-да free(...)-ке тең).

GЖұмыс мысалдары

HИнтерактивті эксперимент

gc өшірулі кезде әр Big нысаны (1 МБ) өзіне сілтегендіктен жойылмады - бұл Python-дағы «ағып кету». gc.collect() оларды тапты. self.me = self жолын алып тастап, қайта іске қосыңыз.

IЖаттығулар

JМатематикалық пайымдау

m11-нің қорытындысы: жадты басқару - әр тілдің негізгі дизайн шешімі. C жылдамдық пен бақылауды береді, бірақ қателерді бағдарламашыға жүктейді. Python қауіпсіздік береді, бірақ санағыш пен gc уақыты бар. Rust үшінші жолды ұсынады - компилятор иелікті тексереді. Бұларды салыстыра алу - жүйелік ойлаудың белгісі (m12).

KЖиі қателер

  • «Python-да жад туралы ойлаудың қажеті жоқ».
    Себебі: Үлкен кэш-сөздіктер, жабылмаған циклдар жадты толтыра береді.
    Түзету: Қажет емес сілтемелерді жою, weakref, tracemalloc арқылы өлшеу.
  • __del__-ге сүйеніп ресурстарды (файлды) жабу.
    Себебі: Цикл болса, __del__ кешігеді не шақырылмауы мүмкін.
    Түзету: with (m08 l06) - детерминистік жабу.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.

MРефлексия

NТереңірек

Honors

  • Модуль жобасы - Memory Address Explorer (тапсырма төменде): C-дағы жадты зерттейтін және Python моделімен салыстыратын құрал.

Research

  • CPython 3.12+ «immortal objects» (PEP 683): кейбір нысандардың санағышы неге өзгермейді? Бұл көп ағынды орындауға қалай көмектеседі?

Модуль жобасы: Memory Address Explorer

C бағдарламасының жадын зерттейтін құрал жасаңыз: айнымалылардың, массивтердің, құрылымдардың, стек жақтауларының және үйме блоктарының мекенжайлары мен өлшемдерін (салыстырмалы түрде) шығарып, нәтижені Python моделі болжамымен салыстырыңыз. Құрал динамикалық массив пен байланысқан тізімнің іске асыруын да қамтиды және AddressSanitizer-мен таза өтеді.

Функционалдық талаптар

  • C бөлігі: sizeof/offsetof кестесі (кемінде 5 құрылым), массив элементтерінің мекенжай айырмалары, стек тереңдігі мен бағыты (рекурсия), үйме блоктары (malloc ретімен).
  • Динамикалық массив (Vec) және байланысқан тізім: push, pop/remove, free; әрқайсысына тесттер.
  • Python бөлігі: құрылым өлшемін болжайтын модель (туралау ережесі) және C шығысымен автоматты салыстыру (C бағдарламасын subprocess арқылы іске қосу).
  • gcc -Wall -Wextra -Werror -fsanitize=address,undefined-пен таза; ағып кету жоқ.
  • README: little-endian, туралау, стек/үйме айырмасы, Python-дағы сілтемелер санағышымен салыстыру.

Кезеңдер

  • 1. sizeof/offsetof кестесі.
  • 2. Стек пен үйме зерттеуі.
  • 3. Vec және тізім + тесттер.
  • 4. Python моделі және салыстыру скрипті.
  • 5. Санитайзерлер, README.

Қабылдау тесттері

  • Python моделі барлық 5 құрылымның өлшемін gcc нәтижесімен дәл болжайды.
  • Vec-ке 10⁶ push: қайта бөлулер саны ⌈log₂ 10⁶⌉ + 1 = 21.
  • ASan/LSan бірде-бір қате таппайды.
  • README-де кемінде 3 эксперимент нәтижесі түсіндірілген.
