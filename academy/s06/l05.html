S06·05Web Security

XSS және контекстік экрандау

  • күрделі
  • ≈ 55 мин
  • 3 мақсат
  • 5 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. XSS (Cross-Site Scripting) - SQL инъекциясының браузердегі егізі. Пайдаланушы түсініктеме жазады: <img src=x onerror=…> .
  2. Жол. 1-қадам. Пайдаланушы деректері бетке шығатын барлық орынды табу.
  3. Жол. 2-қадам. Әр орынның контексін анықтау: мәтін, атрибут, URL, script, CSS.
  4. Жол. 3-қадам. Контекстке сай экрандау (шаблон қозғалтқышының автоматты экрандауы).
  5. Жол. 4-қадам. Шикі HTML керек жерде - allowlist санитайзері; URL схемасын тексеру.
  6. Жол. 5-қадам. CSP және HttpOnly cookie - экрандау қатесі болғанда да зиянды шектеу.
  7. Тексер. Неге CSP экрандау қатесі болғанда да пайдалы? Жауап: Ол кірістірілген скрипттер мен onerror сияқты өңдегіштердің орындалуына тыйым салып, енгізілген тегтің зиянын шектейді.. Дұрыс: қорғаныс тереңдігі.
  8. Түйін. Экрандау контекстен шығармайды. (1) esc(s) мәтін контексіне қойылса, токенизатор esc(s) бойымен мәтін күйінде қалады - жаңа тег ашылмайды.
  9. Түйін. Жиі қате: Деректерді кірісте «тазалап», шығыста экрандамау. Дұрысы: Шығыстағы контекстік экрандау.

AОқу мақсаттары

  • XSS-ті (сайт аралық скрипт) пайдаланушы деректерінің HTML/JS коды ретінде орындалуы деп түсіндіру.
  • HTML мәтін және атрибут контекстерінде экрандаудың жаңа тег не атрибут енгізуге мүмкіндік бермейтінін дәлелдеу.
  • Контекстке сай экрандауды, шаблон қозғалтқышының автоматты экрандауын және CSP-ні қорғаныс қабаттары ретінде қолдану.

BАлғышарттар

  • SQL инъекция

CҰғымға кіріспе

XSS (Cross-Site Scripting) - SQL инъекциясының браузердегі егізі. Пайдаланушы түсініктеме жазады: <img src=x onerror=…>. Сервер оны бетке өзгеріссіз қойса, браузер оны тег ретінде оқиды және скриптті орындайды - басқа пайдаланушының браузерінде, сол сайттың атынан: cookie, токен, әрекеттер шабуылдаушының қолында.

Себебі бірдей: дерек пен код араласты (бұл жолы HTML коды). Шешім - контекстік экрандау: HTML мәтінде < > & белгілерін, атрибутта тырнақшаларды да сущность (entity) ретінде жазу. Маңызды сөз - контекстік: HTML мәтін, атрибут, URL, JavaScript ішіндегі жол - әрқайсысының ережесі әртүрлі. Сондықтан қолмен емес, автоматты экрандайтын шаблон қозғалтқыштарын (Jinja2) қолданамыз, ал CSP (Content Security Policy) - соңғы қорғаныс қабаты.

DАкадемиялық теория

Анықтама

Экрандау

esc(s): & → &amp;, < → &lt;, > → &gt;, " → &quot;, ' → &#x27; (& бірінші). HTML токенизаторының (жеңілдетілген моделі) күйлері: мәтін күйінде тек < жаңа тег бастай алады; тырнақшалы атрибут мәні күйінде тек сол тырнақша мәнді жабады.

Теорема

Экрандау контекстен шығармайды

(1) esc(s) мәтін контексіне қойылса, токенизатор esc(s) бойымен мәтін күйінде қалады - жаңа тег ашылмайды. (2) esc(s) тырнақшалы атрибут мәніне қойылса, атрибут мәні esc(s) аяқталғанша жабылмайды - жаңа атрибут не тег енгізілмейді. (3) esc(s) браузерде қайтадан s ретінде көрсетіледі (мағына сақталады).

Дәлелдеу

Дәлелдеу

esc(s)-тің таңбалары: s-тің ерекше емес таңбалары және &, #, x, сандар, әріптер, ; - сущностьтардың бөліктері. Ішінде <, >, ", ' жоқ: әр осындай таңба сущностьқа ауыстырылды, ал сущностьтардың өздерінде олар жоқ. (1) Мәтін күйінен тек < шығарады - ол жоқ, сондықтан токенизатор мәтінде қалады. (2) Тырнақшалы атрибут күйінен тек сол тырнақша шығарады - ол жоқ. (3) Браузер мәтін/атрибут күйінде сущностьтарды кері ауыстырады: &lt; → < және т.б.; & бірінші ауыстырылғандықтан екі рет экрандау болмайды - нәтиже дәл s. ∎ Шектеу: дәлел тек осы екі контекске. Тырнақшасыз атрибут, URL (javascript:…), <script> ішіндегі JS жолы, CSS - басқа ережелер; html.escape оларды қорғамайды.

Ескерту

Қорғаныс қабаттары

(1) Шаблондағы автоматты экрандау (Jinja2-де әдепкі). (2) Шикі HTML керек жерде - санитайзер (рұқсат етілген тегтер тізімі). (3) URL-дерде схеманы тексеру (тек http/https). (4) CSP тақырыбы: script-src 'self' - кірістірілген скрипттер мен onerror сияқты өңдегіштер орындалмайды. (5) Cookie-ге HttpOnly - скрипт оны оқи алмайды.

EКөрнекі түсіндірме

Қауіпті нұсқада бетте бір қосымша тег (img onerror) пайда болды. Экрандалған нұсқада &lt; сущностьқа айналды - қосымша тег 0, ал браузер мәтінді дәл бастапқыдай көрсетеді. Атрибутта тырнақша да экрандалды.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Пайдаланушы деректері бетке шығатын барлық орынды табу.
  2. Әр орынның контексін анықтау: мәтін, атрибут, URL, script, CSS.
  3. Контекстке сай экрандау (шаблон қозғалтқышының автоматты экрандауы).
  4. Шикі HTML керек жерде - allowlist санитайзері; URL схемасын тексеру.
  5. CSP және HttpOnly cookie - экрандау қатесі болғанда да зиянды шектеу.

GЖұмыс мысалдары

HИнтерактивті эксперимент

Экрандауды «қолмен» жасадық: тек <. Мәтін контексінде бұл жеткілікті ме? Енді атрибут мысалындағы html.escape-ті де осы қолмен нұсқаға ауыстырып көріңіз: не болады? Теорема қай таңбалардың экрандалуын талап етеді?

IЖаттығулар

JМатематикалық пайымдау

XSS теоремасы SQL инъекциясымен бір қағиданы көрсетеді, бірақ маңызды айырмамен: HTML-де «параметрлеу» жоқ, сондықтан қорғаныс экрандаудың дұрыстығына сүйенеді, ал ол контекстке тәуелді. Дәлел өз шектеуін ашық айтады - тек мәтін мен тырнақшалы атрибут. Senior тәсілі - контекстерді азайту (автоматты экрандайтын шаблон), қалғанына арнайы ереже (URL allowlist) және бәрінің астына CSP.

KЖиі қателер

  • Деректерді кірісте «тазалап», шығыста экрандамау.
    Себебі: Контекст шығыста ғана белгілі; бір дерек әртүрлі жерде көрсетіледі.
    Түзету: Шығыстағы контекстік экрандау.
  • Jinja2-де |safe фильтрін пайдаланушы деректеріне қолдану.
    Себебі: Автоматты экрандау өшеді.
    Түзету: |safe - тек өзіңіз жасаған, сенімді HTML-ге; пайдаланушыға - санитайзер.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.

MРефлексия

NТереңірек

Honors

  • Өз Flask оқу жобаңызға қатаң CSP (script-src 'self'; object-src 'none') қосып, браузер консоліндегі бұзушылықтарды түзетіңіз. Inline скрипттерді сыртқы файлдарға көшіріңіз.

Research

  • DOM-ға негізделген XSS (innerHTML, document.write) серверлік экрандаудан неге өтіп кетеді? Trusted Types API оны қалай шешеді?
