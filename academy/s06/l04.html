SQL инъекция

AОқу мақсаттары

  • SQL инъекциясының себебін дерек пен кодтың араласуы (жол біріктіру) ретінде түсіндіру.
  • Параметрленген сұрауда сұраудың құрылымы кіріске тәуелсіз екенін дәлелдеу.
  • Осал кодты табу және оны параметрленген сұрау мен ең аз артықшылықпен түзету.

BАлғышарттар

  • Аутентификация және қолтаңбалы токен

CҰғымға кіріспе

SQL инъекциясы - веб тарихындағы ең көп зиян келтірген осалдықтардың бірі, ал оның себебі бір жол: f"... WHERE name = '{name}'". Пайдаланушы енгізген мәтін сұрауға код ретінде қосылады. Егер ол admin' -- болса, тырнақша жолды жабады, ал -- қалғанын (құпиясөз тексерісін) түсініктемеге айналдырады. Дерекқор не «мәтін», не «код» екенін ажырата алмайды - ол біріктірілген жолды ғана көреді.

Шешім де бір қағида: дерек пен кодты араластырма. Параметрленген сұрауда (WHERE name = ?) сұраудың құрылымы алдымен талданады, ал мәндер кейін, тек мән ретінде байланыстырылады - олар ешқашан талданбайды. Бұл сабақта осалдықтың тетігін оқу моделінде (өз кодымызда, нақты дерекқорсыз) көріп, параметрлеудің неге толық қорғайтынын дәлелдейміз.

DАкадемиялық теория

Анықтама

Сұрау құрылымы

Сұрау үлгісі Q параметрлер орнында толтырғыштармен (?) жазылады. Лексер мен парсер (s05) Q-ды токендер тізбегі мен синтаксистік ағашқа T(Q) айналдырады. Жол біріктіруде талданатын - Q[x] (x мәні мәтінге қойылған), параметрлеуде - Q, ал x кейін ағаштың мән жапырағына байланыстырылады.

Теорема

Параметрлеу құрылымды бекітеді

Параметрленген сұрауда синтаксистік ағаш T(Q) кез келген x кірісі үшін бірдей; x тек мән жапырағында болады. Жол біріктіруде T(Q[x]) x-ке тәуелді және x-ті таңдау арқылы кез келген қосымша шартты не түсініктемені енгізуге болады.

Дәлелдеу

Дәлелдеу

Параметрлеу: дерекқор алдымен Q-ды талдайды - Q x-ке тәуелсіз мәтін, сондықтан T(Q) бір рет анықталған. Сосын x тек толтырғыш жапырағына мән ретінде қойылады; мәндер ешқашан лексерге берілмейді, демек x-тегі тырнақша не -- жаңа токенге айналмайды. Ағаш бірдей ⇒ сұраудың логикасы (қай кесте, қай шарттар) бірдей. Біріктіру: Q[x] мәтінінің токендері x-ке тәуелді. Конструктивті мысал: x = «admin' --» болса, x-тегі тырнақша жол литералын жабады, ал -- лексерде түсініктеме бастайды; T(Q[x])-те құпиясөз шарты жоқ. Демек құрылым кіріспен өзгереді. ∎ Салдар: кірісті «тазалау» (тырнақшаларды алып тастау) - әлсіз қорғаныс, себебі ол лексердің барлық ережесін (кодтаулар, контекстер) қайталауы керек; параметрлеу мәселені құрылым деңгейінде жояды.

Ескерту

Қорғаныс тереңдігі

Параметрлеу - негізгі қорғаныс. Қосымша қабаттар: дерекқор пайдаланушысына ең аз артықшылық (тек керек кестелерге SELECT/INSERT), қате хабарларында SQL мәтінін көрсетпеу, ORM-де «шикі SQL» функцияларын шолуда ерекше тексеру. Кесте не баған атауы сияқты параметрленбейтін бөліктер үшін - рұқсат етілгендер тізімі (allowlist).

EКөрнекі түсіндірме

Оқу моделі. Қалыпты кіріс екі тәсілде де бірдей. «admin' --» біріктіруде құпиясөз шартын түсініктемеге айналдырып, admin ретінде кіргізді; «x' OR 1=1 --» барлық пайдаланушыны қайтарды. Параметрленген нұсқа екі жағдайда да бос тізім: кіріс тек мән.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Кодтағы барлық SQL жолдарын табу: біріктіру (+, f-string, format) бар ма?
  2. Әр біріктірілген мәнді толтырғышпен (?) ауыстыру, мәнді бөлек беру.
  3. Параметрленбейтін бөліктер (кесте/баған атауы, ORDER BY) үшін allowlist.
  4. Дерекқор пайдаланушысының құқықтарын ең азға дейін қысқарту.
  5. Шабуыл кірістерімен (тырнақша, --, OR 1=1) тест жазу: нәтиже өзгермеуі керек.

GЖұмыс мысалдары

HИнтерактивті эксперимент

Тырнақшаларды екі еселеу арқылы «тазалау» қостық (тек name үшін). Біздің оқу моделіміз енді сұрауды мүлде талдай алмай, қатемен тоқтады: ол '' экрандауын және жол ішіндегі -- белгісін білмейді. Бұл не көрсетеді? Тазалау лексердің әр ережесін дәл қайталауы керек - бір айырма не қатеге, не осалдыққа апарады. pw өрісі тазаланбаған - оған қандай шабуыл қалды? Неге параметрлеу бұл мәселені мүлде жояды (теорема)?

IЖаттығулар

JМатематикалық пайымдау

SQL инъекция - s05-тегі компиляторлар модулінің қауіпсіздіктегі сабағы: лексер мен парсер кірісті кодқа айналдырады, ал біріктіру шабуылдаушыға «бағдарлама жазуға» мүмкіндік береді. Теорема қорғаныстың дұрыс деңгейін көрсетеді: кірістің мазмұнын емес, оның рөлін бекіту (тек мән). Дәл осы идея XSS (5-сабақ), командалық инъекция және шаблон инъекциясына да қолданылады.

KЖиі қателер

  • Кірісті қара тізіммен «тазалау» (тырнақша, --, ; алып тастау).
    Себебі: Кодтаулар мен контекстер көп, бірі әрқашан жіберіледі.
    Түзету: Параметрленген сұрау; атаулар үшін allowlist.
  • Дерекқорға қосымшаны әкімші құқығымен қосу.
    Себебі: Инъекция болса, бүкіл дерекқор (тіпті DROP) шабуылдаушының қолында.
    Түзету: Ең аз артықшылықты дерекқор пайдаланушысы.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.
