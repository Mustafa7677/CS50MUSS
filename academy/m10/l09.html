10·09C Programming Foundations

Анықталмаған әрекет

  • күрделі
  • ≈ 55 мин
  • 3 мақсат
  • 6 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. C стандарты кейбір жағдайларға ешқандай талап қоймайды : INT_MAX + 1, a[n], инициализацияланбаған айнымалыны оқу, x / 0.
  2. Жол. 1-қадам. Есеп: a + b асып кететінін тексеру (a, b - int).
  3. Жол. 2-қадам. Қате тәсіл: if (a + b < a) - асып кету болып қойды, UB; компилятор тексерісті жоюы мүмкін.
  4. Жол. 3-қадам. Дұрыс (b > 0 үшін): if (a > INT_MAX - b) - бұл өрнек ешқашан асып кетпейді.
  5. Жол. 4-қадам. b < 0 үшін: if (a < INT_MIN - b). Не long long-та есептеп, шектермен салыстыру.
  6. Тексер. Қайсысы анықталмаған әрекет ЕМЕС? Жауап: UINT_MAX + 1u (unsigned). Дұрыс: таңбасыз арифметика модуль 2ⁿ - анықталған (l02).
  7. Түйін. Компилятор x + 1 > x өрнегін 1 деп ауыстыра алады. x таңбалы int болса, компилятор x + 1 > x өрнегін әрқашан ақиқат деп есептей алады.
  8. Түйін. Жиі қате: «Менің компьютерімде жұмыс істейді» - UB-ді елемеу. Дұрысы: -Wall -Wextra -fsanitize=undefined,address-пен тестілеу.

AОқу мақсаттары

  • Анықталмаған әрекетті (undefined behavior, UB) анықтау: стандарт ешқандай талап қоймайтын жағдай.
  • Негізгі UB түрлерін тану: таңбалы асып кету, шекарадан тыс қатынау, инициализацияланбаған айнымалы, нөлге бөлу.
  • Санитайзерлер (-fsanitize=undefined, address) мен ескертулер арқылы UB-ді табу.

BАлғышарттар

  • Стандартты енгізу-шығару

CҰғымға кіріспе

C стандарты кейбір жағдайларға ешқандай талап қоймайды: INT_MAX + 1, a[n], инициализацияланбаған айнымалыны оқу, x / 0. Мұндай кезде бағдарлама кез келген нәрсе істеуі мүмкін: «дұрыс» жұмыс істеуі, құлауы, қате нәтиже беруі - тіпті компилятор оңтайландыру кезінде кодты «UB болмайды» деп болжап, күтпеген түрде өзгертуі мүмкін.

UB-нің ең қауіпті түрі - байқалмайтыны: бағдарлама бүгін жұмыс істейді, ертең басқа компиляторда сынады. Құралдар: -Wall -Wextra ескертулері және санитайзерлер - бағдарламаны орындау кезінде UB-ді ұстайтын арнайы компиляция режимдері. Бұл сабақтағы мысалдардың stderr шығысы нағыз санитайзерден алынған.

DАкадемиялық теория

Анықтама

Мінез санаттары

Анықталған (стандарт нақты айтады). Іске асыруға тәуелді (implementation-defined: компилятор таңдап, құжаттайды, мысалы sizeof(int)). Анықталмаған (UB: ешқандай талап жоқ, C11 J.2 тізімі - 200-ден астам жағдай).

Теорема

Компилятор x + 1 > x өрнегін 1 деп ауыстыра алады

x таңбалы int болса, компилятор x + 1 > x өрнегін әрқашан ақиқат деп есептей алады.

Дәлелдеу

Дәлелдеу

Екі жағдай: (1) x < INT_MAX - онда x + 1 математикалық тұрғыдан дәл есептеледі және x-тен үлкен: өрнек ақиқат. (2) x = INT_MAX - онда x + 1 таңбалы асып кету, UB: стандарт бұл жағдайда ешқандай нәтиже талап етпейді, сондықтан «ақиқат» нәтижесі де рұқсат етілген. Демек барлық рұқсат етілген орындауларда 1 қайтару стандартқа сай. ∎ Сондықтан «асып кетуді x + 1 < x арқылы тексеру» оңтайландырылған кодта жойылуы мүмкін; дұрыс тексеру - x == INT_MAX (не x > INT_MAX − 1) өрнегін қосуға дейін.

Ескерту

Санитайзерлер

gcc -fsanitize=undefined - таңбалы асып кету, нөлге бөлу, жарамсыз ығысу. gcc -fsanitize=address - шекарадан тыс қатынау, босатылған жадты пайдалану (m11). Бағасы - баяу орындау, сондықтан тек тестілеу кезінде.

EКөрнекі түсіндірме

Бұл машинада нәтиже −2147483648 болып «көрінді», бірақ бұл кепілдік емес. UBSan оны орындау кезінде ұстады.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Есеп: a + b асып кететінін тексеру (a, b - int).
  2. Қате тәсіл: if (a + b < a) - асып кету болып қойды, UB; компилятор тексерісті жоюы мүмкін.
  3. Дұрыс (b > 0 үшін): if (a > INT_MAX - b) - бұл өрнек ешқашан асып кетпейді.
  4. b < 0 үшін: if (a < INT_MIN - b). Не long long-та есептеп, шектермен салыстыру.

GЖұмыс мысалдары

HИнтерактивті эксперимент

Тексеріс қосуға ДЕЙІН жасалады, сондықтан ешқашан UB жоқ. Бұл функция -fsanitize=undefined-пен де таза. (*out - көрсеткіш, m11 l02.)

IЖаттығулар

JМатематикалық пайымдау

UB - C-ның жылдамдығы мен қауіпінің ортақ көзі: компилятор «UB болмайды» деп болжап, тексерістерді алып тастап, кодты жылдамдатады. Python-да UB жоқ: әр қате - анық ерекшелік. Сондықтан C бағдарламашысының тәртібі: ескертулер, санитайзерлер, шекараларды дәлелдеу (инвариант) және тесттер (m08).

KЖиі қателер

  • «Менің компьютерімде жұмыс істейді» - UB-ді елемеу.
    Себебі: Басқа компилятор, оңтайландыру не деректер нәтижені өзгертеді.
    Түзету: -Wall -Wextra -fsanitize=undefined,address-пен тестілеу.
  • Асып кетуді қосудан кейін тексеру (a + b < a).
    Себебі: Қосудың өзі UB - тексеріс кеш және оңтайландырылуы мүмкін.
    Түзету: a > INT_MAX − b (қосуға дейін).

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.

MРефлексия

NТереңірек

Honors

  • gcc -O2 -S арқылы int f(int x) { return x + 1 > x; } функциясын компиляциялап, ассемблерде тек «return 1» қалғанын тексеріңіз (теорема).

Research

  • Linux ядросы -fno-strict-overflow және -fwrapv жалаушаларын неге қолданады? Олар UB-ді қалай өзгертеді?

Дереккөз және лицензия
