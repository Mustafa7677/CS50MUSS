AОқу мақсаттары

  • PEP 8 атау ережелерін, docstring және типтік белгілерді (type hints) қолдану.
  • Деректерді тексеру функцияларын (валидация) шағын, тесттелетін бөліктерге бөлу.
  • Модуль жобасын (p08 Data Validation Toolkit) жоспарлау және тесттермен қорғау.

BАлғышарттар

  • Тестке негізделген әзірлеу

CҰғымға кіріспе

Кодты бір рет жазамыз, бірақ ондаған рет оқимыз. Код сапасы - кодтың дұрыстығынан бөлек қасиеттері: оқылатындығы, өзгертуге ыңғайлылығы, тесттелетіндігі.

Құралдар: PEP 8 (snake_case функциялар, UPPER_CASE тұрақтылар, 4 бос орын шегініс), docstring (функция не істейді, алғышарт пен нәтиже - m07 l03 келісімшарты), типтік белгілер def area(w: float, h: float) -> float - оқырманға және тексеру құралдарына (mypy) арналған кеңес; Python оларды орындау кезінде тексермейді.

DАкадемиялық теория

Анықтама

Сапа белгілері

  • Атау мағынасын айтады: total_price, x2 емес.
  • Бір функция - бір міндет.
  • Сиқырлы сан жоқ (m07 l10).
  • Docstring және типтік белгі.
  • Тесттер бар (l08).
Теорема

Валидацияны құрастыру

Әрқайсысы бір шартты тексеретін c₁, ..., cₖ функциялары берілсе, «барлық шарт орындалды» тексерісі - олардың конъюнкциясы, ал қателер тізімі - бұзылған шарттардың тізімі. Әр cᵢ бөлек тексерілгендіктен, құрама валидатордың дұрыстығы бөліктердің дұрыстығынан шығады.

Дәлелдеу

Дәлелдеу

Жазба r жарамды ⇔ c₁(r) ∧ ... ∧ cₖ(r) (анықтама бойынша, m01 l02). Валидатор errors = [i : ¬cᵢ(r)] қайтарады. errors бос ⇔ ешбір i үшін ¬cᵢ(r) жоқ ⇔ барлық i үшін cᵢ(r) (кванторлар терістеуі, m01 l07) ⇔ r жарамды. Әр cᵢ дұрыс болса (өз тесттерімен дәлелденген), errors-тің әр элементі шын бұзылған шарт. ∎

Ескерту

Типтік белгі - кепілдік емес

def f(x: int) -> int деп жазып, f('a') шақыруға болады - Python қарсы болмайды. Кепілдік керек болса, isinstance тексерісі не mypy сияқты статикалық талдаушы қолданылады.

EКөрнекі түсіндірме

Docstring help() арқылы көрінеді. '15' (жол) типтік белгіге қарамастан функцияға жетті - тексеріс isinstance арқылы.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Схема: {'name': 'str', 'age': 'int'} - әр өрістің күтілетін түрі.
  2. Әр өріс үшін: жоқ болса 'өріс: жоқ'; түрі сәйкес келмесе 'өріс: түр керек'.
  3. Түрді салыстыру: TYPES = {'str': str, 'int': int, 'float': float}; isinstance(v, TYPES[t]).
  4. Ерекшелік: True - int-тің ішкі класы (isinstance(True, int) = True). Сондықтан bool-ды бөлек тексереміз.

GЖұмыс мысалдары

HИнтерактивті эксперимент

area('ab', 3) қате бермей 'ababab' қайтарды - типтік белгілер тексерілмейді. Функцияға isinstance тексерісін қосып, TypeError көтеріңіз.

IЖаттығулар

JМатематикалық пайымдау

Сапа - талғам мәселесі емес, құн мәселесі: түсініксіз кодты өзгерту ұзақ және қауіпті. m08-де үйренген құралдар (дұрыс құрылым, файлдар, ерекшеліктер, тесттер) біріккенде деректерді сенімді өңдейтін бағдарлама шығады - p08 жобасы дәл осыны талап етеді.

KЖиі қателер

  • Docstring-те кодты қайталау: """x-ті y-ге көбейтеді""".
    Себебі: Оқырман бұны кодтан көреді.
    Түзету: Не үшін және қандай шартта: алғышарт, нәтиже, ерекшеліктер.
  • Типтік белгі қойдым - енді тексеріс керек емес деп ойлау.
    Себебі: Python оларды орындау кезінде тексермейді.
    Түзету: Сыртқы деректерді isinstance/валидатормен тексеріңіз.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.

NТереңірек

Honors

Модуль жобасы: Data Validation Toolkit

Мектеп деректерін (оқушылар тізімі, бағалар) тексеретін Python құралын жасаңыз. Құрал CSV не JSON файлын оқиды, әр жазбаны схема бойынша тексереді, қателері бар жазбаларды жол нөмірімен есепке шығарады және таза деректерді жаңа файлға жазады.

Функционалдық талаптар

  • Схема: өріс аты → түр, міндеттілігі және шектеуі (мысалы, age: int, 6..20; email: '@' бар).
  • Файлды оқу: CSV және JSON; файл жоқ не бұзық болса - түсінікті хабар (ерекшеліктер).
  • Есеп: әр қате үшін жол нөмірі, өріс және себеп; соңында жарамды/жарамсыз саны.
  • Таза деректерді жаңа файлға жазу (бастапқы файл өзгермейді).
  • Әр тексеру функциясына тесттер (кемінде 15); әр функцияда docstring мен типтік белгілер.

Кезеңдер

  • 1. Схема құрылымы және бір жазбаны тексеру.
  • 2. CSV оқу және жол нөмірлері.
  • 3. JSON қолдауы және қателерді өңдеу.
  • 4. Есеп және таза файл.
  • 5. Тесттер (мутанттармен тексеру) және README.

Қабылдау тесттері

  • Дайын үлгі файлда (20 жазба, оның 6-ы қате) барлық 6 қате дұрыс жол нөмірімен табылады.
  • Жоқ файл және бос файл бағдарламаны құлатпайды.
  • Тесттер кемінде екі әдейі енгізілген қатені (мутантты) ұстайды - README-де көрсетілсін.
  • Барлық тест өтеді.
