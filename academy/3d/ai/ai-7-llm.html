1Келесі токенді болжау

Идея

Барлық үлкен тілдік модельдердің (LLM) жалғыз міндеті:

P(келесі токен | алдыңғы токендер)

яғни берілген мәтіннен кейін әр мүмкін токеннің ықтималдығын есептеу. Сұраққа «жауап беру», код жазу, аудару: бәрі осы бір әрекеттің қайталануы.

Бұл зертханадағы модель

Мұнда триграмма моделі: соңғы екі сөзге қарап келесісін болжайды. Ол корпустағы жиіліктерден есептеледі:

P(w | a b) = count(a b w) / count(a b)

Сирек тіркестер үшін қысқарақ контекстермен араластырамыз (interpolation): 0.6·P₃ + 0.3·P₂ + 0.1·P₁.

Есептеп көрейік

Корпуста «компьютер»-ден кейін 2 рет «бағдарламаны», бір рет басқа сөз келсе: шамамен P ≈ 0.67 (интерполяциямен сәл аз).

Нақты LLM-нен айырмасы

Триграмма тек 2 сөзді «көреді». GPT мыңдаған токенді көреді, ал ықтималдықтарды санау кестесімен емес, transformer арқылы есептейді: ол бұрын көрмеген тіркестерге де жалпылай алады. Бірақ шығыс: дәл осындай үлестірім.

💡 Түйін: LLM «ойламайды» және «білмейді» деп айтудың орнына: ол мәтіннің статистикалық жалғасын өте жақсы болжайды.

Тереңірек: ықтималдықтың тізбек ережесі және perplexity

Кез келген мәтіннің ықтималдығы шартты ықтималдықтардың көбейтіндісі:

P(w₁…wₙ) = P(w₁) · P(w₂|w₁) · P(w₃|w₁w₂) · … · P(wₙ|w₁…wₙ₋₁)

Бұл: жуықтау емес, дәл теңдік. LLM тек бір нәрсені үйренеді: келесі токеннің шартты үлестірімін.

Триграмма мұны «тек соңғы 2 токен маңызды» деп жеңілдетеді: P(wₙ|wₙ₋₂wₙ₋₁) = count(wₙ₋₂wₙ₋₁wₙ)/count(wₙ₋₂wₙ₋₁). Сирек комбинацияларда 0 шықпауы үшін біз интерполяция қолданамыз: λ₃·P₃ + λ₂·P₂ + λ₁·P₁.

Perplexity: модель сапасы:

PPL = exp( −(1/n) Σ ln P(wᵢ | алдыңғылар) )

Түйсігі: модель әр қадамда орта есеппен неше нұсқа арасында «іркіледі». PPL = 1: мінсіз; әр қадамда 50 токенге бірдей сенімді болса, PPL = 50.

Енді сен

Prompt-ты кемінде 2 рет өзгертіп, ықтималдық бағандарының қалай өзгеретінін бақыла.

2Генерация

Идея

Үлестірім бар: енді одан бір токенді таңдау керек. Ең қарапайым әдіс: sampling: ықтималдыққа пропорционал кездейсоқ таңдау. Таңдалған токенді мәтінге қосамыз да, қайтадан болжаймыз. Бұл: авторегрессивті генерация:

loop:
    p = model(мәтін)
    t = sample(p)
    мәтін += t
    if t == "</s>": break

Есептеп көрейік

P(сүт) = 0.5, P(балық) = 0.3, P(үйде) = 0.2. Кездейсоқ сан r ∈ [0, 1):

r < 0.5          → «сүт»
0.5 ≤ r < 0.8    → «балық»
0.8 ≤ r < 1      → «үйде»

r = 0.63 болса: «балық».

Неге әр жолы әртүрлі

Кездейсоқтық болғандықтан, бір prompt әртүрлі жалғасулар береді. ChatGPT-ге бір сұрақты екі рет қойғанда басқа жауап алатының сол себепті.

⚠ Жиі қате: «Модель бүкіл сөйлемді бірден ойлап алады». Жоқ: ол әр қадамда тек бір токенді таңдайды, болашақты «жоспарламайды».

3Temperature

Идея

Temperature (T) үлестірімді sampling-тен бұрын өзгертеді:

pᵢ' = pᵢ^(1/T) / Σ pⱼ^(1/T)
  • T < 1: үлкен ықтималдықтар одан да үлкейеді → мәтін болжамды, қайталанатын.
  • T = 1: модельдің өз үлестірімі.
  • T > 1: үлестірім тегістеледі → сирек токендер жиі таңдалады, мәтін «шығармашыл», бірақ мағынасыз болуы мүмкін.
  • T → 0: әрдайым ең ықтимал токен (greedy).

Есептеп көрейік

p = (0.6, 0.4).

T = 0.5: 0.6² = 0.36, 0.4² = 0.16 → (0.69, 0.31)
T = 2:   √0.6 ≈ 0.775, √0.4 ≈ 0.632 → (0.55, 0.45)

Төмен T айырманы үлкейтеді, жоғары T: кішірейтеді.

Нақты әлемде

Код жазу, математика: төмен T (0-0.3). Өлең, идея: 0.8-1.2. «Галлюцинациялар» T-ға тікелей байланысты емес, бірақ жоғары T қате токендердің мүмкіндігін арттырады.

Тереңірек: temperature сандармен

pᵢ = exp(zᵢ/T) / Σⱼ exp(zⱼ/T)

Logit-тер z = (2, 1, 0):

  • T = 1: e² = 7.39, e¹ = 2.72, e⁰ = 1 → p = (0.665, 0.245, 0.090)
  • T = 0.5: z/T = (4, 2, 0) → 54.6, 7.39, 1 → p = (0.867, 0.117, 0.016)
  • T = 2: z/T = (1, 0.5, 0) → 2.72, 1.65, 1 → p = (0.506, 0.307, 0.186)

Шектер: T → 0: argmax (әрдайым ең ықтимал токен, детерминді); T → ∞: біркелкі үлестірім (бәрі бірдей, мағынасыз).

Энтропия H = −Σ pᵢ·log₂ pᵢ: «таңданыс» өлшемі. T = 0.5 → 0.64 бит, T = 1 → 1.20 бит, T = 2 → 1.47 бит (максимумы log₂3 ≈ 1.58). Temperature: энтропияны басқаратын бұранда.

Маңызды: T logit-тердің ретін өзгертпейді: тек олардың арасындағы айырмашылықты күшейтеді не әлсіретеді.

Енді сен

T ≤ 0.3 және T ≥ 1.5 мәндерінде кемінде 3 токеннен генерацияла. Нәтижелерді салыстыр.

3D симуляцияда орында

  • Temperature ≤ 0.3 болғанда 3 токен генерацияла
  • Temperature ≥ 1.5 болғанда 3 токен генерацияла

4Top-k және greedy

Идея

Temperature барлық токендерге әсер етеді, ал сөздікте ондаған мың өте сирек, мағынасыз токен бар. Top-k тек ең ықтимал k токенді қалдырып, қалғанын алып тастайды, сосын қайта қалыптайды.

  • k = 1: greedy decoding: әрдайым ең ықтимал токен. Бір prompt → әрдайым бір нәтиже.
  • k = 40: жиі қолданылатын мән.

Top-p (nucleus): жиынтық ықтималдығы p-ға (мысалы 0.9) жеткенше ең ықтимал токендерді алады: «сенімді» жағдайда аз, «екіұдай» жағдайда көп токен қалады.

Есептеп көрейік

p = (0.5, 0.3, 0.15, 0.05), k = 2:

қалды: (0.5, 0.3) → қалыптау: 0.5/0.8 = 0.625, 0.3/0.8 = 0.375

Greedy-дің кемшілігі

Әрдайым ең ықтимал токенді таңдау жиі қайталануға әкеледі («... және ... және ...»), себебі жергілікті ең жақсы таңдау: бүкіл мәтін үшін ең жақсы емес.

💡 Түйін: чат-боттың «мінезі» тек модельмен емес, декодтау параметрлерімен де анықталады: temperature, top-k, top-p.

Тереңірек: top-k және nucleus (top-p)

Top-k: ең ықтимал k токенді қалдырып, қалғанын 0 етеміз, сосын қайта нормаламыз:

p'ᵢ = pᵢ / Σ_{j ∈ top-k} pⱼ

Мысал: p = (0.5, 0.3, 0.15, 0.05), k = 2 → (0.5, 0.3)/0.8 = (0.625, 0.375).

Әлсіздігі: k тұрақты. Модель сенімді болғанда (0.97, 0.01, …) k = 40 әлі де қоқыс токендерді қалдырады; сенімсіз болғанда (40 тең нұсқа) k = 5 жақсы нұсқаларды кесіп тастайды.

Top-p (nucleus): қосынды ықтималдығы p-ға жеткенше ең ықтималдарды аламыз. Сенімді үлестірімде: 1-2 токен, біркелкіде: көп. Яғни шекара үлестірімге бейімделеді. Нақты жүйелер көбіне temperature + top-p қатар қолданады.

Top-k = 1 қойып, кемінде 3 токен генерацияла. «Тазалау» басып, қайта бастасаң: нәтиже өзгере ме?
