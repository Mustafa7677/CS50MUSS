Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақтың қадамдарынан құрастырылған)
  1. Сұрақ. y = 1. Қай болжам үшін loss ең үлкен?
  2. Бейне. Тұманда таудан түсіп келе жатырсың: алысты көрмейсің, бірақ аяғыңның астындағы еңісті сезесің. Ең тік төмен бағытқа бір қадам: тағы еңісті сезу: тағы қадам. Loss: биіктік, градиент: еңіс.
  3. Болжа. y = 1. Қай болжам үшін loss ең үлкен? Жауап: p = 0.05. −log(0.05) ≈ 3.0. Сенімді қате жауап (1 болуы керек, бірақ 5% деді) ең қатты жазаланады.
  4. Көр. 1-қадам, «Бірінші training». Training: салмақтарды автоматты түрде табу. Үш бөлік: 1. Loss (қате функциясы): модель қаншалықты қателесетінін бір санмен өлшейді. Мұнда: binary cross-entropy: 2.
  5. Көр. 2-қадам, «Learning rate». Learning rate (η): бір қадамның өлшемі. Тым үлкен: минимумнан секіріп өтеміз, loss тербеледі немесе жарылады (divergence). Тым кіші: дұрыс бағытта, бірақ өте баяу: мыңдаған epoch керек.
  6. Көр. 3-қадам, «Batch size». Градиентті барлық деректер бойынша есептеу: дәл, бірақ қымбат. Сондықтан деректерді шағын batch-тарға бөліп, әр batch-тан кейін салмақтарды жаңартамыз: mini-batch SGD. batch = 1: әр мысалдан кейін жаңарту.
  7. Көр. 4-қадам, «Мақсат: 95% test дәлдігі». Енді бәрін біріктір. ML инженерінің шынайы жұмыс циклі: 1. Гипотеза: «тереңірек желі көмектеседі». 2. Тәжірибе: бір ғана параметрді өзгерт. 3. Өлшеу: test дәлдігі (train емес!). 4. Қорытынды → келесі гипотеза.
  8. Көр. Нақты әлемде: Learning rate: ең маңызды гиперпараметр. Үлкен модельдерде оны уақыт өте азайтады (learning rate schedule) немесе Adam сияқты әр салмаққа өз қадамын беретін әдістерді қолданады.
  9. Түйін. Нақты gradient descent: learning rate, batch size және epoch-тың әсерін loss графигінен көр.
  10. Түйін. Жиі қате: Модельдің сапасын қай көрсеткішпен бағалаймыз? Жауап: «Train дәлдігі». Дұрысы: «Test дәлдігі». Test: модель көрмеген деректер. Ол ғана шын өмірдегі сапаны болжайды.

1Бірінші training

Идея

Training: салмақтарды автоматты түрде табу. Үш бөлік:

  1. Loss (қате функциясы): модель қаншалықты қателесетінін бір санмен өлшейді. Мұнда: binary cross-entropy:
L = −[ y·log(p) + (1−y)·log(1−p) ]
  1. Градиент: әр салмақты сәл өзгерткенде loss қалай өзгеретіні. Backpropagation оны тізбек ережесімен (chain rule) шығыстан кіріске қарай барлық салмақ үшін бір өтуде есептейді.
  2. Gradient descent: әр салмақты градиентке қарсы бағытта кішкене қадамға жылжыту:
w ← w − η · ∂L/∂w

Түйсік

Тұманда таудан түсіп келе жатырсың: алысты көрмейсің, бірақ аяғыңның астындағы еңісті сезесің. Ең тік төмен бағытқа бір қадам: тағы еңісті сезу: тағы қадам. Loss: биіктік, градиент: еңіс.

Есептеп көрейік

y = 1, модель p = 0.9 берді: L = −log(0.9) ≈ 0.105 (аз қате). p = 0.1 берді: L = −log(0.1) ≈ 2.30 (үлкен қате). Сенімді қате жауап: қатты жазаланады.

Epoch: барлық train деректерін бір рет көру.

Тереңірек: ∂L/∂z = p − y қорытуы (backprop жүрегі)

Бір нейрон: z = w·x + b, p = σ(z), L = −[y·ln p + (1−y)·ln(1−p)].

1-қадам: σ туындысы. σ(z) = 1/(1 + e⁻ᶻ). Туынды алсақ:

σ'(z) = e⁻ᶻ/(1 + e⁻ᶻ)² = σ(z)·(1 − σ(z)) = p(1 − p)

2-қадам: L-дің p бойынша туындысы:

∂L/∂p = −y/p + (1−y)/(1−p) = (p − y) / (p(1−p))

3-қадам: тізбек ережесі:

∂L/∂z = ∂L/∂p · ∂p/∂z = (p − y)/(p(1−p)) · p(1−p) = p − y

Керемет қысқарды: қате сигналы: жай ғана «болжам минус шындық». (Cross-entropy-ді sigmoid-пен жұптайтынымыздың себебі осы.)

4-қадам: салмақтар: z = Σ wᵢxᵢ + b болғандықтан ∂z/∂wᵢ = xᵢ, ∂z/∂b = 1:

∂L/∂wᵢ = (p − y)·xᵢ        ∂L/∂b = p − y

Сандармен. x = (1, 2), y = 1, w = (0.5, −0.25), b = 0.1, η = 0.5.

  1. z = 0.5 − 0.5 + 0.1 = 0.1 → p = σ(0.1) ≈ 0.525, L = −ln 0.525 ≈ 0.644
  2. p − y = −0.475 → ∂L/∂w = (−0.475, −0.95), ∂L/∂b = −0.475
  3. w ← w − η·∇: w = (0.7375, 0.225), b = 0.3375
  4. Жаңа z = 0.7375 + 0.45 + 0.3375 = 1.525 → p ≈ 0.821, L ≈ 0.197

Бір қадамда loss 3 есеге жуық азайды. Үлкен xᵢ бар салмақ көбірек өзгерді: ол болжамға көбірек «кінәлі».

Жасырын қабаттар. Шығыс қабаттың қатесі δ = p − y. Алдыңғы қабатқа:

δ_жасырын = (Wᵀ · δ_келесі) ⊙ f'(z_жасырын)
∂L/∂W = δ · (кіріс)ᵀ

Қате салмақтар арқылы кері таралады: атауы осыдан. Құны: бір backward ≈ 2 forward. Ал әр салмақты жеке «сәл өзгертіп тексеру» (finite differences) P параметр үшін P + 1 forward талап етер еді: миллиард параметрде мүмкін емес.

Енді сен

«Training бастау» бас. Loss графигі төмендеп, 3D бет деректерді «орап» жатқанын бақыла. Кемінде 50 epoch үйрет.

Gradient descent салмақты қай бағытта жылжытады?

Жауабы мен түсіндірмесі

Дұрыс жауап: Градиентке қарсы (loss азаятын жаққа)

Градиент loss-тың ең тез өсетін бағытын көрсетеді. Біз loss-ты азайтқымыз келеді, сондықтан минус таңбамен жүреміз: w ← w − η·∇L.

2Learning rate

Идея

Learning rate (η): бір қадамның өлшемі.

  • Тым үлкен: минимумнан секіріп өтеміз, loss тербеледі немесе жарылады (divergence).
  • Тым кіші: дұрыс бағытта, бірақ өте баяу: мыңдаған epoch керек.

Есептеп көрейік

Ең қарапайым мысал: L(w) = w², градиент 2w, бастауы w = 1.

η = 0.1:  w → 1 − 0.1·2·1 = 0.8 → 0.64 → 0.51 …  (баяу, бірақ сенімді)
η = 0.5:  w → 1 − 0.5·2·1 = 0                    (бір қадамда!)
η = 1.1:  w → 1 − 1.1·2·1 = −1.2 → 1.44 → −1.73  (жарылды)

Яғни η > 1 болғанда әр қадам минимумнан әрі қарай лақтырады.

Нақты әлемде

Learning rate: ең маңызды гиперпараметр. Үлкен модельдерде оны уақыт өте азайтады (learning rate schedule) немесе Adam сияқты әр салмаққа өз қадамын беретін әдістерді қолданады.

⚠ Жиі қате: «Үлкен learning rate = жылдам training». Белгілі бір шектен кейін үлкен η training-ті мүлдем бұзады.

Тереңірек: learning rate шекарасы η < 2/a

Ең қарапайым loss: парабола: L(w) = (a/2)·w², градиенті a·w. Gradient descent:

w ← w − η·a·w = (1 − ηa)·w

Әр қадамда w бір санға көбейтіледі: q = 1 − ηa.

  • 0 < q < 1 (η < 1/a): бір жақтан бірқалыпты жақындайды
  • −1 < q < 0 (1/a < η < 2/a): минимумнан ары-бері секіріп жақындайды: тербеліс
  • |q| > 1 (η > 2/a): әр қадам алыстатады: divergence

Мысал a = 4: η = 0.1 → q = 0.6 (тегіс); η = 0.4 → q = −0.6 (тербеліс); η = 0.6 → q = −1.4 (жарылыс: 1, −1.4, 1.96, −2.74 …).

Нақты loss беті: көп өлшемді, ал a-ның рөлін ең тік бағыттың қисықтығы (Hessian-ның ең үлкен меншікті мәні) атқарады. Сондықтан бір тік бағыт бүкіл η-ны шектейді: Adam сияқты әдістер әр параметрге жеке қадам беретіні осыдан.

Енді сен

Learning rate ≥ 1 етіп үйрет (графиктегі тербелісті көр), сосын «Training-ті қайта бастау» басып, ≤ 0.1-пен үйрет.

3D симуляцияда орында

  • Learning rate ≥ 1 болғанда кемінде 20 epoch үйрет
  • Learning rate ≤ 0.1 болғанда кемінде 20 epoch үйрет

Дұрыс жауап: 1

Градиент 2w = 4. w ← 2 − 0.25·4 = 1.

Жауабы мен түсіндірмесі

Дұрыс жауап: Learning rate-ті азайту

Тербеліс пен жарылу: қадам тым үлкен екенінің классикалық белгісі.

3Batch size

Идея

Градиентті барлық деректер бойынша есептеу: дәл, бірақ қымбат. Сондықтан деректерді шағын batch-тарға бөліп, әр batch-тан кейін салмақтарды жаңартамыз: mini-batch SGD.

  • batch = 1: әр мысалдан кейін жаңарту. Жаңарту жиі, бірақ әр градиент шулы.
  • үлкен batch: градиент дәл әрі тегіс, бірақ бір epoch-та жаңарту аз.

Есептеп көрейік

192 train нүктесі:

batch = 1   → 192 жаңарту / epoch
batch = 16  → 12 жаңарту / epoch
batch = 64  → 3 жаңарту / epoch

Сондықтан бірдей epoch санында batch = 1 көп «қадам» жасайды, бірақ қадамдары зигзаг.

Неге шу пайдалы болуы мүмкін

Сәл шулы градиент таяз жергілікті минимумдардан «секіріп шығуға» көмектеседі. Ал GPU-да үлкен batch параллель есептеледі: уақыт бойынша тиімдірек. Тәжірибеде 16-512 аралығы жиі қолданылады.

💡 Түйін: batch size: дәлдік пен жылдамдық арасындағы компромисс.

Тереңірек: batch өлшемі мен шудың математикасы

Толық градиент: барлық N мысалдың орташасы. Mini-batch оны B кездейсоқ мысалмен бағалайды. Статистикадан: B тәуелсіз үлгінің орташасының дисперсиясы σ²/B, ауытқуы σ/√B.

  • B = 1 → шу σ
  • B = 32 → шу σ/√32 ≈ σ/5.7
  • B = 256 → шу σ/16

Бірақ бір epoch-та N/B қадам ғана. N = 1000: B = 1 → 1000 қадам/epoch (шулы, бірақ көп), B = 1000 → 1 қадам (дәл, бірақ баяу).

Шудың пайдасы да бар: ол «тар» минимумдардан шығарып, тегіс, жақсы генерализацияланатын аймақтарға итереді. GPU-да B = 64 есептеу уақыты B = 1-ден аз ғана көп (параллель), сондықтан практикада 32-512 жиі таңдалады.

Енді сен

Batch = 1 және batch ≥ 32-мен үйретіп, loss қисығының пішінін салыстыр: қайсысы тегіс, қайсысы шулы?

3D симуляцияда орында

  • Batch = 1 болғанда кемінде 10 epoch үйрет
  • Batch ≥ 32 болғанда кемінде 10 epoch үйрет
Симуляцияны ашу

Бір мысал: бүкіл датасеттің нашар өкілі. Градиенттің бағыты әр қадам сайын «секіреді».

4Мақсат: 95% test дәлдігі

Идея

Енді бәрін біріктір. ML инженерінің шынайы жұмыс циклі:

  1. Гипотеза: «тереңірек желі көмектеседі».
  2. Тәжірибе: бір ғана параметрді өзгерт.
  3. Өлшеу: test дәлдігі (train емес!).
  4. Қорытынды → келесі гипотеза.

Пайдалы бастау нүктелері

  • Шеңберлер үшін: [8, 8], tanh: жеткілікті.
  • Learning rate: 0.1-0.5. Loss тербелсе: азайт.
  • Batch: 16-32.
  • Epoch: loss тегістелгенше (бірнеше жүз).

Неге «бір параметр»

Үш нәрсені бірден өзгертсең, нәтиже жақсарса да, нақты нені себеп болғанын білмейсің. Бұл: ғылыми әдіс, ML-де де дәл солай.

⚠ Жиі қате: тек train дәлдігіне қарау. 100% train: мақсат емес; мақсат: жаңа деректердегі дәлдік.

Енді сен

Test жиынында кемінде 95% дәлдікке жет. Тапсырма тұрақты болуы керек: training біткенде де 95% сақталсын.

3D симуляцияда орында

  • Test дәлдігі ≥ 95%
