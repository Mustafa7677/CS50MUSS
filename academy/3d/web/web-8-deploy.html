1Сайтыңды жаз

Идея

Сайт: ең қарапайым түрінде бір HTML файл. Енді сенің бетің. Жақсы беттің минимумы:

  • бір <h1>: беттің басты тақырыбы;
  • <p> абзацтар: мазмұн;
  • семантикалық тегтер және alt мәтіндері;
  • қатесіз құрылым (барлық тег дұрыс жабылған).

Құрылым үлгісі

<h1>Айгерімнің жобалары</h1>
<p>Мен 3D веб-қосымшалар жасауды үйреніп жүрмін.</p>
<ul>
  <li>INSIDE TECH: AI LAB</li>
</ul>

💡 Түйін: ең маңызды қадам өз идеяңды қолмен жасап шығару. Кішкентайдан баста, бірақ соңына дейін жеткіз: жұмыс істейтін қарапайым бет жартылай дайын күрделі беттен құнды.

Енді сен

Тақырыпты өз тақырыбыңа өзгерт және кемінде бір абзац жаз. Парсер ескертулері болмауы керек.

Таза HTML: болжамды нәтиже барлық браузерде.

2Интернетке шығар

Идея

Deploy: кодты серверге шығару, сонда ол интернетте қолжетімді болады. Бірақ адамдар IP адресті емес, домен атауын тереді. Сондықтан екі қадам:

  1. DNS жазбасы: mysite.kz → 93.184.10.9 (A record);
  2. Deploy: файлдарды сол IP-дегі серверге жүктеу.

Нақты әлемде

домен сатып алу → DNS-те A/CNAME жазбасы → хостинг (сервер, GitHub Pages, Vercel) → HTTPS сертификаты

INSIDE TECH-тің өзі де дәл осылай шығарылған: GitHub Actions әр өзгерістен кейін сайтты жинап, GitHub Pages-ке deploy жасайды. Бұл CI/CD: үздіксіз жеткізу.

Есептеп көрейік

DNS жазбасы жоқ болса: NXDOMAIN (7-сабақ). Жазба бар, бірақ deploy жоқ болса: сервер бар, бірақ / маршруты жоқ → 404. Екеуі де болса → 200.

⚠ Жиі қате: DNS-ті өзгертіп, бірден «жұмыс істемейді» деп ойлау: кэштер мен TTL (1-сабақ).

Енді сен

DNS-ке mysite.kz → 93.184.10.9 жазбасын қос, «Deploy» бас, сосын https://mysite.kz/ аш.

3Неге жаңа нұсқа көрінбейді?

Идея

Сервер жауапқа Cache-Control тақырыбын қосады:

Cache-Control: max-age=60

«Бұл жауапты 60 секунд сақта, серверге қайта келме». Бұл беттерді жылдамдатады және серверді жеңілдетеді. Бірақ: жаңа нұсқаны deploy жасасаң, браузер ескісін 60 секунд көрсете береді.

Есептеп көрейік

00:00  бетті аштың → кэшке түсті (60 с)
00:20  жаңа нұсқаны deploy жасадың
00:30  бетті аштың → ескі нұсқа (кэш әлі 30 с жарамды)
01:01  бетті аштың → жаңа нұсқа

Шешімдер

  • кэшті тазалау (тек өз браузеріңде!);
  • max-age-ті азайту (бірақ жылдамдық жоғалады);
  • файл атауына нұсқа қосу: app.3f9a.js: жаңа нұсқа = жаңа атау = кэш мәселесі жоқ. Next.js сияқты құралдар мұны автоматты жасайды.

💡 Түйін: «There are only two hard things in Computer Science: cache invalidation and naming things.»: Фил Карлтон.

Тереңірек: кэш стратегиясы: «мәңгі кэш + хеш атау»

Компьютерлік ғылымдағы екі қиын нәрсенің бірі: кэшті жарамсыз ету. Веб оны былай шешеді:

  1. HTML: Cache-Control: no-cache (әр жолы серверден тексер; өзгермесе 304 Not Modified, денесіз)
  2. JS/CSS/суреттер: атауында мазмұн хеші: app.3f9a1c.js, және Cache-Control: max-age=31536000, immutable (бір жыл)

Файл өзгерсе: хеш өзгереді: атау өзгереді: HTML жаңа атауға сілтейді. Ескі файлды кэштен «өшірудің» қажеті жоқ: оны енді ешкім сұрамайды.

Hit ratio математикасы. Кэштен жауап 5 мс, origin-нен 200 мс. Hit ratio h:

орташа = h·5 + (1 − h)·200
h = 0.90 → 24.5 мс      h = 0.99 → 6.95 мс

90%-дан 99%-ға өту орташаны 3.5 есе қысқартады: соңғы пайыздар ең құнды.

4Файлды сақта

Идея

Сенің бетің: жай мәтіндік файл: index.html. Оны кез келген статикалық хостингке салуға болады:

  • GitHub Pages: репозиторийден тегін (INSIDE TECH осында тұр);
  • Netlify, Vercel, Cloudflare Pages: файлды сүйреп тастау жеткілікті.

Статикалық vs динамикалық

  • Статикалық сайт: сервер дайын файлдарды береді. Жылдам, арзан, қауіпсіз.
  • Динамикалық: әр сұрауда сервер код орындайды (дерекқор, аккаунттар). Икемді, бірақ күрделі.

Көп заманауи сайттар аралас: беттер: статикалық, ал деректер: API арқылы (5-сабақ).

Бүкіл курс бір сызықта

URL → DNS → TCP → TLS → HTTP → сервер → маршрут → дерекқор → жауап → HTML → DOM → CSS → JS → экран. Сен әр кезеңді ұстап көрдің.
