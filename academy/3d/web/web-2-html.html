HTML және DOM

HTML & DOM

HTML мәтінінен браузер DOM ағашын құрады. Кодты өзгерт: 3D ағаш бірден өзгереді.

3D симуляцияны ашу Дәрісті оқу

  1. DOM ағашы
  2. Тізім құр
  3. Қатені тап
  4. Атрибуттар

1DOM ағашы

Идея

HTML: мәтін. Браузер оны оқып (parse), DOM (Document Object Model) деп аталатын ағаш құрады:

  • әр тег: түйін (node);
  • ішіндегі тегтер: оның балалары;
  • мәтін: жапырақ (text node).

Есептеп көрейік

<ul>
  <li>Бір</li>
  <li>Екі</li>
</ul>

Ағашы:

ul
├── li
│   └── "Бір"
└── li
    └── "Екі"

Неге ағаш?

CSS «ul ішіндегі li»-ді табады, JavaScript document.querySelector("li") арқылы түйінді өзгертеді, экран оқу бағдарламалары ағаш бойымен жүреді. Мәтінмен емес: ағашпен жұмыс істеу әлдеқайда оңай.

💡 Түйін: HTML: тек бастапқы нұсқа. JavaScript DOM-ды өзгерткенде бет өзгереді, ал бастапқы HTML файл өзгермейді.

Енді сен

3D ағаштағы кез келген түйінді бас. Ата-ана: бала қатынасына қара.

2Тізім құр

Идея

HTML тегтері: мағыналық (semantic) белгілер: <h1>: басты тақырып, <p>: абзац, <ul>: ретсіз тізім, <li>: тізім элементі. Тег сыртқы түрді емес, мағынаны білдіреді; түрін CSS береді.

Неге мағына маңызды

  • Экран оқу бағдарламасы (көзі көрмейтіндер үшін) «3 элементтен тұратын тізім» деп хабарлайды.
  • Іздеу жүйелері <h1>-ді беттің тақырыбы деп түсінеді.
  • <div> пен <span>: мағынасыз «қораптар», оларды тек басқа тег сәйкес келмегенде қолдан.

Есептеп көрейік

<ul>
  <li>Бірінші</li>
  <li>Екінші</li>
  <li>Үшінші</li>
</ul>

Әр <li>: <ul>-дің баласы. Ағашта ul-дан үш бұтақ шығады.

⚠ Жиі қате: тізімді <br> арқылы жасау. Көзге бірдей, бірақ браузер үшін бұл тізім емес: жай жолдар.

Енді сен

Кодқа тағы екі <li> қос: тізімде кемінде 3 элемент болсын. Ағаштың қалай өскенін бақыла.

3D симуляцияда орында

  • <ul> ішінде кемінде 3 <li> болсын
  • <h1> тақырыбы сақталсын
Симуляцияны ашу

Өзіңді тексер

Неге тізім үшін <ul><li> қолданамыз, <br> емес?

Жауабы мен түсіндірмесі

Дұрыс жауап: <ul><li> мағынаны білдіреді: браузер, іздеу жүйесі және экран оқу бағдарламасы оны тізім деп түсінеді

Семантикалық тегтер: машиналар үшін құрылым. Көрініс: CSS-тің ісі.

<div> тегі қашан орынды?

Жауабы мен түсіндірмесі

Дұрыс жауап: Ешбір семантикалық тег сәйкес келмейтін топтау үшін

<div>: мағынасыз контейнер. Алдымен мағыналы тег іздейміз.

3Қатені тап

Идея

HTML-де көптеген тегтер жұппен келеді: <b> ... </b>. Жабылмаған тег: оның ішіне ары қарайғының бәрі кіреді деген сөз. Браузер қателерді үнсіз «түзейді», бірақ оның түзетуі сенің ойыңдағыдай болмауы мүмкін.

Есептеп көрейік

<p>Бүгін <b>маңызды күн</p>
<p>Ертең демалыс</p>

<b> жабылмаған: браузер «Ертең демалыс»-ты да қалың қаріппен көрсетуі мүмкін. Дұрысы:

<p>Бүгін <b>маңызды</b> күн</p>

Тегтерді қалай тексеру керек

Стек сияқты ойла: ашылған тег стекке түседі, жабылатын тег: соңғы ашылғанын жабуы керек. <div><p></div>: қате: div жабылмас бұрын p жабылуы керек.

💡 Түйін: дәл осы «стекпен тексеру» компиляторлар мен парсерлердің ішінде жатыр: сен оны 4-сабақтағы call stack-та тағы көресің.

Енді сен

Парсердің ескертулерін оқы: қай жол, қай тег. Барлық қатені түзет.

3D симуляцияда орында

  • Барлық ескерту жойылсын
Симуляцияны ашу
Кеңес
  • <b> мен <li> жабылмаған, ал </span> артық: оның орнында </div> болуы керек.

Өзіңді тексер

<div><p>мәтін</div></p>: неге қате?

Жауабы мен түсіндірмесі

Дұрыс жауап: Тегтер ашылуына кері ретпен жабылмаған: p div-тен бұрын жабылуы керек

Соңғы ашылған: бірінші жабылады (LIFO). Дұрысы: <div><p>мәтін</p></div>.

Браузер қате HTML-ді көрсете ала ма?

Жауабы мен түсіндірмесі

Дұрыс жауап: Иә, бірақ өз ережесімен «түзейді»: нәтиже күтпеген болуы мүмкін

Браузерлер кешірімді, бірақ болжаусыз. Таза HTML жазу: сенімді жол.

4Атрибуттар

Идея

Атрибуттар тегке қосымша ақпарат береді: <тег атау="мән">.

  • <a href="https://inside.kz">: сілтеме қайда апарады;
  • <img src="cat.png" alt="Ұйықтап жатқан мысық">: суреттің файлы және мәтіндік сипаттамасы.

alt неге міндетті

  • Көзі көрмейтін адамның экран оқу бағдарламасы alt-ты дауыстап оқиды.
  • Сурет жүктелмесе, оның орнына alt көрінеді.
  • Іздеу жүйелері суретті alt арқылы түсінеді.

Сурет тек безендіру болса: alt="" (бос) қой, сонда оқу бағдарламасы оны өткізіп жібереді.

Есептеп көрейік

<a href="/about">Біз туралы</a>          ← сайт ішіндегі жол
<a href="https://wikipedia.org">Wiki</a>  ← басқа сайт

⚠ Жиі қате: <a> мәтінін «мұнда басыңыз» деп жазу. Сілтеме мәтіні өзі қайда апаратынын айтуы керек.

Енді сен

href атрибуты бар сілтеме және src пен alt атрибуттары бар сурет қос.

3D симуляцияда орында

  • href атрибуты бар <a> сілтемесін қос
  • alt атрибуты бар <img> қос
Симуляцияны ашу

Өзіңді тексер

<img> үшін alt атрибуты не үшін керек?

Жауабы мен түсіндірмесі

Дұрыс жауап: Суретті көре алмайтындарға (адам немесе бағдарлама) оның мазмұнын мәтінмен жеткізу үшін

alt: қолжетімділіктің (accessibility) негізгі бөлігі.

Сілтеменің қайда апаратынын қай атрибут анықтайды?
