1Маршрут және статус код

Идея

Сервер: сұрауларды тыңдап, жауап беретін бағдарлама. Әр сұрауда:

  • әдіс (method): GET: оқу, POST: жасау, PUT: жаңарту, DELETE: өшіру;
  • жол (path): /api/hello, /api/users/3.

Маршрутизация (routing): әдіс + жол бойынша қай кодты орындау керегін таңдау.

Статус кодтары

Жауаптың бірінші цифры: санат:

2xx: сәтті       (200 OK, 201 Created)
3xx: басқа жерге (301, 304 Not Modified)
4xx: клиент қатесі (400, 401, 403, 404)
5xx: сервер қатесі (500, 502, 503)

Есептеп көрейік

GET /api/users/3 → маршрут /api/users/:id → параметр id = 3 → дерекқордан 3-қолданушы → 200 OK + JSON. GET /api/nothing → маршрут жоқ → 404 Not Found.

💡 Түйін: 4xx: «сен қате сұрадың», 5xx: «мен (сервер) сындым». Қатені іздегенде бұл бірінші белгі.

Енді сен

/api/hello сұрауын жібер, сосын жоқ жолды сұрап, 404 ал.

3D симуляцияда орында

  • GET /api/hello → 200
  • Жоқ жолды сұрап, 404 ал

2Жаңа маршрут

Идея

Backend әзірлеуші жаңа мүмкіндікті көбінесе жаңа маршрут ретінде қосады: «GET /api/time уақытты қайтарсын». Бұл: API (Application Programming Interface): бағдарламалар бір-бірімен сөйлесетін келісім.

JSON

API-лер деректі әдетте JSON форматында қайтарады:

{ "time": "12:00", "zone": "Asia/Almaty" }

Бұл: мәтін, бірақ кез келген тіл (JS, Python, Go) оны оңай оқиды.

Жақсы API ережелері

  • Жол: зат есім: /api/users (етістік емес: /api/getUsers).
  • Әрекет: HTTP әдісімен: GET, POST, DELETE.
  • Қате болса: дұрыс статус код + түсінікті JSON: {"error": "not_found"}.

⚠ Жиі қате: барлық қатеге 200 қайтарып, денесіне «error» жазу. Клиенттер мен мониторинг статус кодқа қарайды.

Енді сен

Серверге GET /api/time маршрутын қос (түрі JSON), сосын оны браузерден сұрап, 200 ал.

3D симуляцияда орында

  • GET /api/time → 200

3Авторизация

Идея

Кейбір деректер бәріне ашық болмауы керек. Екі ұғымды шатастырма:

  • Аутентификация: «сен кімсің?» (кіру, token);
  • Авторизация: «саған не істеуге рұқсат?» (рөлдер).

Сервер сұраудағы token-ды тексереді. Әдетте ол тақырыпта жіберіледі:

Authorization: Bearer secret-123

Статус кодтары

  • 401 Unauthorized: сенің кім екеніңді білмейміз (token жоқ не қате);
  • 403 Forbidden: кім екеніңді білеміз, бірақ рұқсат жоқ.

Есептеп көрейік

GET /api/secret token-сіз → 401. Token-мен → 200 + {"plan":"premium"}.

⚠ Жиі қате: тексерісті тек фронтендте жасау («батырманы жасырдық»). Кез келген адам API-ді тікелей шақыра алады: тексеріс серверде болуы керек. Бұл INSIDE TECH API-інде де солай жасалған.

Тереңірек: парольді қалай сақтау керек

Ешқашан ашық мәтінмен емес. База ұрланса: бәрінің паролі кетеді (адамдар бір парольді көп жерде қолданады).

Жай хеш те (SHA-256) жеткіліксіз: GPU секундына миллиардтаған SHA-256 есептейді, ал адам паролінің көбі 10⁸-10¹⁰ нұсқаның ішінде. Бір GPU оларды минуттарда тексереді.

Дұрыс тәсіл:

  1. Тұз (salt): әр пайдаланушыға кездейсоқ қосымша: hash(salt + пароль). Бірдей парольдер әр түрлі хеш береді, алдын ала есептелген кестелер (rainbow tables) жұмыс істемейді.
  2. Әдейі баяу хеш: bcrypt, scrypt, Argon2: бір тексеріс ~100 мс және көп жад. Пайдаланушы үшін байқалмайды, ал шабуылшы үшін миллион есе баяу.

401 мен 403: 401 Unauthorized: «сен кімсің, білмеймін» (кіру керек). 403 Forbidden: «сені танимын, бірақ бұған рұқсатың жоқ». Аты шатастырады, бірақ мағынасы осы.

Енді сен

/api/secret-ті алдымен token-сіз сұрап, 401 ал. Сосын token енгізіп (secret-123), 200 ал.

4POST: деректерді жіберу

Идея

GET: деректерді оқиды және серверде ештеңе өзгертпеуі керек (қауіпсіз). POST: жаңа деректі жасайды. Сұраудың денесінде (body) жаңа жазбаның өрістері жіберіледі.

Есептеп көрейік

POST /api/users
body: name=Арман&city=Тараз

Сервер оны SQL-ге айналдырады:

INSERT INTO users (name, city) VALUES ('Арман', 'Тараз')

Жауап: 201 Created. Сосын GET /api/users: тізімде 9-жазба.

Idempotency

GET-ті 10 рет жіберсең: нәтиже бірдей. POST-ты 10 рет жіберсең: 10 жаңа қолданушы! Сондықтан «Төлеу» батырмасын екі рет басу қаупі бар; сервер мұндай қайталауды арнайы өңдеуі керек (INSIDE TECH-тің төлем webhook-ы дәл осыны жасайды).

⚠ Абай бол: пайдаланушы енгізген мәтінді SQL-ге тікелей жапсыруға болмайды: SQL injection. Мұнда параметрлер тырнақшаға алынып, қауіпсіз байланыстырылады.

Енді сен

POST /api/users арқылы жаңа қолданушы қос (name, city), сосын GET /api/users-те оны тап.

3D симуляцияда орында

  • POST /api/users → 201 Created
  • Сосын GET /api/users жаңа жазбаны көрсетсін
