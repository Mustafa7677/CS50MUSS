How Internet Works

URL енгізгеннен бет ашылғанға дейін: DNS, TCP, TLS, HTTP: әр қадам уақытымен.

3D симуляцияны ашу Дәрісті оқу

  1. Сұраудың саяхаты
  2. DNS кэші
  3. HTTP және HTTPS
  4. Кідіріс (latency)

1Сұраудың саяхаты

Идея

Браузерге https://inside.kz/ жазып, Enter басқанда шамамен 10 кезең өтеді:

  1. URL талдау: хаттама (https), хост (inside.kz), жол (/).
  2. DNS: «inside.kz» қай IP адресте? Компьютерлер аттарды емес, сандарды біледі.
  3. TCP handshake: сервермен байланыс орнату: SYN → SYN-ACK → ACK.
  4. TLS: байланысты шифрлау, сервердің шын inside.kz екенін сертификатпен тексеру.
  5. HTTP сұрау: GET / HTTP/1.1.
  6. Сервер: маршрутты тауып, жауап дайындайды.
  7. HTTP жауап: 200 OK + HTML.
  8. Көрсету: HTML → DOM → бет.

Түйсік

Хат жіберу: адрестер кітабынан мекенжайды табасың (DNS), алушыға «хат қабылдайсыз ба?» деп қоңырау шаласың (TCP), конвертті жабасың (TLS), хатты жібересің (HTTP).

Есептеп көрейік

Сервер 40 мс алыс (бір жаққа). HTTPS-те бетті алғанға дейін шамамен:

DNS 2×24 + TCP 3×40 + TLS 2×40 + HTTP 40 + жауап 40 ≈ 330 мс

Уақыттың көбі: есептеуге емес, сапарға кетеді.

💡 Түйін: интернет: бір-бірімен келісілген хаттамалар арқылы сөйлесетін компьютерлер.

Тереңірек: TCP үш жақты қол алысу және sequence нөмірлері

TCP: сенімді байт ағыны. Әр байттың реттік нөмірі (sequence number) бар, ал қабылдаушы «келесі күтетін байт нөмірін» ACK ретінде жібереді.

Клиент → Сервер:  SYN,     seq = 1000          (кездейсоқ бастапқы нөмір)
Сервер → Клиент:  SYN-ACK, seq = 5000, ack = 1001
Клиент → Сервер:  ACK,     seq = 1001, ack = 5001

SYN бір нөмірді «жейді», сондықтан ack = 1000 + 1. Бастапқы нөмір кездейсоқ: бөтен адам байланысқа жалған пакет қосуы қиын болуы үшін.

Енді клиент 200 байт жіберді (seq = 1001…1200). Сервер ack = 1201 қайтарады. Егер ack келмесе: таймерден кейін қайта жіберу (retransmission). Пакеттер ауысып келсе: seq бойынша ретке келтіріледі. Желі пакетті жоғалтады, қайталайды, ретін бұзады; TCP осының бәрін жасырады.

Бағасы: кешігу: деректер жібермес бұрын 1 RTT (round-trip time) қол алысуға кетеді.

Енді сен

«Жіберу» бас. Пакеттің жолын бақыла, оң жақтағы кезеңдерді оқы.

2DNS кэші

Идея

DNS сұрауы: бөлек серверге сапар. Оны әр бетте қайталамау үшін браузер (және операциялық жүйе) жауапты кэштейді: есінде сақтайды. Әр DNS жазбасының TTL (time to live) мерзімі бар: кэш сонша секунд жарамды.

Есептеп көрейік

Бірінші сұрау: DNS 48 мс + қалғаны ≈ 330 мс. Екінші сұрау: DNS ~1 мс (кэш) → ≈ 285 мс. 14% жылдамырақ: тек бір кезеңнің есебінен.

Нақты әлемде

Кэш барлық деңгейде: браузерде, ОЖ-да, провайдердің DNS серверінде. Сондықтан домен басқа IP-ге көшсе, барлығына «жету» үшін TTL-ге дейін уақыт кетеді.

⚠ Жиі қате: «DNS өзгертсем, бірден жұмыс істейді». Кэштер ескі IP-ні TTL біткенше сақтауы мүмкін.

Енді сен

Тағы бір рет жібер. Кезеңдер тізімінде «DNS (кэш)» пайда болғанын және уақыттың азайғанын көр.

3HTTP және HTTPS

Идея

HTTP-де деректер желіде ашық жүреді: жолдағы кез келген роутер, Wi-Fi иесі немесе провайдер құпия сөзіңді оқи алады. HTTPS = HTTP + TLS:

  • шифрлау: деректерді тек браузер мен сервер оқи алады;
  • аутентификация: сертификат сервердің шынымен inside.kz екенін дәлелдейді (алаяқ сервер емес);
  • тұтастық: деректер жолда өзгертілмегенін тексереді.

Бағасы

TLS handshake бір-екі қосымша сапар алады (мұнда 2 × 40 = 80 мс). TLS 1.3 мұны бір сапарға дейін қысқартты.

Есептеп көрейік

http://  : DNS + TCP + HTTP + жауап
https:// : DNS + TCP + TLS(+80 мс) + HTTP + жауап

⚠ Жиі қате: «Құлып белгісі = сайт қауіпсіз». Құлып тек байланыстың шифрланғанын білдіреді. Алаяқ сайттың да сертификаты болуы мүмкін.

Тереңірек: Диффи-Хеллман: ашық арнада ортақ құпия

TLS-тің негізгі айласы: екі жақ ешқашан құпияны жібермей-ақ бірдей кілтке келеді. Кішкене сандармен (шын өмірде: эллипстік қисықтар, 256 бит):

Ашық: p = 23, g = 5.

  1. Клиент құпия a = 4 таңдайды, жібереді A = 5⁴ mod 23 = 625 mod 23 = 4
  2. Сервер құпия b = 3 таңдайды, жібереді B = 5³ mod 23 = 125 mod 23 = 10
  3. Клиент: B^a = 10⁴ mod 23 = 10000 mod 23 = 18
  4. Сервер: A^b = 4³ mod 23 = 64 mod 23 = 18

Тыңдаушы 23, 5, 4, 10-ды көрді, бірақ 18-ді табу үшін «5 нешінші дәрежеде 4 болады?» (дискретті логарифм) есебін шешуі керек: үлкен сандарда іс жүзінде мүмкін емес.

Бірақ DH жалғыз өзі «ортадағы адамнан» (MITM) қорғамайды: шабуылшы екі жақпен бөлек DH жасай салады. Сондықтан сервер өзінің DH бөлігіне сертификаттағы кілтпен қол қояды, ал сертификатқа браузер сенетін CA қол қойған. Шифрлау + аутентификация = HTTPS.

TLS 1.3-те мұның бәрі 1 RTT алады (TLS 1.2-де 2 RTT).

4Кідіріс (latency)

Идея

Latency (кідіріс): сигналдың бір жаққа жету уақыты. Ол негізінен қашықтыққа тәуелді: оптикалық талшықтағы жарық ~200 000 км/с жүреді.

Bandwidth (өткізу қабілеті): секундына қанша дерек өтетіні. Бұл екеуі әртүрлі: кең, бірақ ұзын құбыр.

Есептеп көрейік

Алматы → Франкфурт ≈ 5000 км → бір жаққа ≈ 25 мс (тек физика), іс жүзінде 40-60 мс. Кідірісті 40 мс-тан 200 мс-қа көтерсек:

TCP 3 сапар + TLS 2 + HTTP 1 + жауап 1 = 7 сапар
7 × 200 мс = 1400 мс

Бет 7 есе баяу: бір де бір байт қосылмаса да!

Нақты әлемде

Сондықтан ірі сайттар CDN қолданады: көшірмелерді әлемнің әр қаласына қояды, ал HTTP/2, HTTP/3 және TLS 1.3 сапарлар санын азайтады.

💡 Түйін: веб-жылдамдықтың жауы көбінесе байттар емес, сапарлар саны × кідіріс.

Тереңірек: кешігу бюджеті: физикадан бастап

Жарық оптикалық талшықта ≈ 200 000 км/с (вакуумнан ⅔). Алматы → Франкфурт ≈ 5 000 км:

бір жақ ≥ 5 000 / 200 000 = 25 мс,   RTT ≥ 50 мс

Бұл: физикалық шек, ешбір инженерия оны жеңбейді. Жаңа HTTPS сұраныстың бірінші байтына дейін:

  1. DNS (кэш жоқ): 1 RTT
  2. TCP қол алысу: 1 RTT
  3. TLS 1.3: 1 RTT
  4. HTTP сұраныс → жауап: 1 RTT

Барлығы ≈ 4 RTT = 200 мс + сервер уақыты. Сондықтан:

  • CDN: серверді пайдаланушыға жақындатады (RTT 50 → 5 мс)
  • keep-alive / HTTP/2: бір байланысты қайта қолданады (TCP+TLS қайталанбайды)
  • DNS кэші: 1 RTT-ны үнемдейді

Өткізу қабілеті (bandwidth) мен кешігу (latency): әр түрлі нәрсе: 1 Гбит/с арна 50 мс RTT-ны қысқартпайды. Кішкене сұраныстар көп болғанда кешігу басым.

Енді сен

Сервердің кідірісін 200 мс-қа көтер, DNS кэшін тазала да, қайта жібер. 1 секундтан ұзақ сұрауды көр.
