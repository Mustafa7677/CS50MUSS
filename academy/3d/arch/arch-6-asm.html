Компьютер архитектурасы · 6-сабақ · ≈30 мин · 2 қадам · 4 сұрақ

Ассемблер

Assembly

Өз бағдарламаңды жаз: автотексеруші оны басқа деректермен де іске қосады.

3D симуляцияны ашу Дәрісті оқу

  1. mem[0] + mem[1]
  2. Кері санау

1mem[0] + mem[1]

Идея

Енді бағдарламаны өзің жазасың. Тапсырма: mem[0] мен mem[1]-ді қосып, нәтижені шығар.

Маңызды: автотексеруші сенің бағдарламаңды басқа деректермен де іске қосады: 2 + 3, 10 + 20, 0 + 0, 100 + 55. Нағыз автотексерушілер осылай жұмыс істейді: «менде жұмыс істейді» жеткіліксіз, бағдарлама кез келген кірісте дұрыс болуы керек.

Түйсік

Бағдарлама: функция: кіріс (жад) → шығыс (OUT). Тестер функцияны бірнеше нүктеде тексереді.

Есептеп көрейік

Ойлау реті:

  1. mem[0]-ді регистрге жүкте: LOAD R0, [0]
  2. mem[1]-ді басқа регистрге
  3. қос
  4. шығар, тоқта

Жадтағы мәнді тікелей қосу мүмкін емес: ALU тек регистрлермен жұмыс істейді. Бұл: load/store архитектурасы (RISC).

Нақты әлемде

Компиляторлар (C, Rust, Go) сенің a + b жазбаңды дәл осындай LOAD/ADD/STORE тізбегіне айналдырады. gcc -S командасы нақты ассемблерді көрсетеді.

⚠ Жиі қате: бағдарламаға жауапты «қатты жазу»: LI R0, 5. Бір тест өтеді, қалғандары құлайды.

Енді сен

Шаблонды толтыр, «Соңына дейін» бас. Тексеруші жасырын тесттердің нәтижесін көрсетеді.

3D симуляцияда орында

  • Бағдарлама барлық жасырын тесттен өтсін (4 тест)
Симуляцияны ашу
Кеңес
  • LOAD R0, [0] LOAD R1, [1] ADD R0, R1 OUT R0 HALT

Өзіңді тексер

Неге «ADD R0, [1]» деп жадтан тікелей қоса алмаймыз?

Жауабы мен түсіндірмесі

Дұрыс жауап: Біздің процессор load/store архитектурасы: ALU тек регистрлермен жұмыс істейді

RISC процессорларында жадпен тек LOAD/STORE жұмыс істейді. Бұл нұсқауларды қарапайым әрі бірдей ұзындықта етеді.

Неге автотексеруші бағдарламаны бірнеше түрлі деректермен іске қосады?

Жауабы мен түсіндірмесі

Дұрыс жауап: Бір мысалда дұрыс жауап бағдарламаның дұрыстығын дәлелдемейді

Жауапты қатты жазған бағдарлама бір тесттен өтеді. Әр түрлі, оның ішінде шеткі (0, 0) деректер нақты логиканы тексереді.

2Кері санау

Идея

Енді цикл жаз: mem[0] = N болса, N, N − 1, …, 1 сандарын кезекпен шығар. Мысалы N = 3 → 3, 2, 1.

Түйсік

Бұл: «әзірге R0 ≠ 0: шығар, азайт» циклы:

while (n != 0) { print(n); n = n − 1; }

Есептеп көрейік

Цикл қаңқасы:

      LOAD R0, [0]
loop: OUT R0
      DEC R0
      JNZ loop
      HALT

N = 3 болса: OUT 3, DEC → 2 (Z = 0, секір), OUT 2, DEC → 1, OUT 1, DEC → 0 (Z = 1): цикл бітті. Нұсқаулар: 1 + 3·N + 1.

Шеткі жағдай: тест N = 1 (бір ғана сан). Ал N = 0 болса не болар еді? (Тестте жоқ, бірақ ойлан: OUT 0, DEC → 255…)

Нақты әлемде

«Off-by-one» (бірге қате): бағдарламалаудағы ең жиі қателердің бірі: цикл бір рет артық не кем орындалады. Шеткі жағдайларды (0, 1, ең үлкен мән) тексеру: кәсіби әдет.

💡 Түйін: DEC нұсқауы Z жалауын өзі қояды: бөлек CMP керек емес.

Енді сен

Шаблонды аяқта. Тексеруші N = 3, 5, 1 мәндерімен іске қосады.

3D симуляцияда орында

  • N, N−1, …, 1 шығар (3 жасырын тест)
Симуляцияны ашу

Өзіңді тексер

N = 5 болса, жоғарыдағы кері санау бағдарламасы неше нұсқау орындайды?

Жауабы мен түсіндірмесі

Дұрыс жауап: 17

LOAD (1) + цикл 3 × 5 (15) + HALT (1) = 17.

Сол бағдарлама N = 0-де не істейді?

Жауабы мен түсіндірмесі

Дұрыс жауап: 0, 255, 254, …, 1 шығарады: 256 сан

OUT 0, сосын DEC 0 → 255 (Z = 0), цикл жалғасады. Бұл: шеткі жағдайды тексермеудің классикалық салдары.
