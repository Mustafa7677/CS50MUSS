Big O

Уақытты емес, қадамдарды өлшейміз. n екі есе өскенде не болады: тәжірибемен.

3D симуляцияны ашу Дәрісті оқу

  1. n-ді екі есе өсір
  2. n log n
  3. Жарыс

1n-ді екі есе өсір

Идея

Big O: алгоритмнің қадам саны кіріс өлшемі n өскен сайын қалай өсетінін сипаттайды. Тұрақтыларды және кіші мүшелерді елемейміз: n(n−1)/2 = n²/2 − n/2 → O(n²).

Ең жиі кездесетін кластар (жылдамнан баяуға):

  • O(1): тұрақты: массив элементін индекспен алу
  • O(log n): логарифмдік: екілік іздеу
  • O(n): сызықтық: сызықтық іздеу
  • O(n log n): merge sort
  • O(n²): квадраттық: bubble, selection, insertion
  • O(2ⁿ): экспоненциалдық: барлық ішкі жиындарды тексеру

Түйсік

Big O тек бір сұраққа жауап береді: n екі есе өссе, не болады? O(n): екі есе. O(n²): төрт есе. O(log n): бір ғана қадам қосылады.

Есептеп көрейік

Selection sort, n(n−1)/2 салыстыру:

  • n = 256 → 32 640
  • n = 512 → 130 816 (≈ 4.0 есе)
  • n = 1024 → 523 776 (≈ 4.0 есе)

Нақты әлемде

Инженерлер жаңа функцияны тексергенде дәл осы тәжірибені жасайды: кірісті 2 есе, 4 есе өсіріп, уақыттың өсуін өлшейді. Бұл: эмпирикалық күрделілік талдауы.

⚠ Жиі қате: O(n²) «баяу», O(n) «жылдам» деп абсолютті ойлау. n = 10-да 100n алгоритм n² алгоритмнен баяу. Big O: үлкен n туралы.

Тереңірек: Big O-ның формалды анықтамасы

f(n) = O(g(n)) дегеніміз: c > 0 тұрақтысы және n₀ табылып, барлық n ≥ n₀ үшін

f(n) ≤ c · g(n)

Мысал: f(n) = 3n² + 100n + 7. c = 4, n₀ = 101 алайық: n ≥ 101 болса, 100n + 7 ≤ n² (себебі n² − 100n − 7 = n(n − 100) − 7 ≥ 101 − 7 > 0). Демек f(n) ≤ 4n² → f = O(n²).

Ω (төменгі шек): f(n) ≥ c·g(n). Θ: екеуі де. Selection sort: Θ(n²), себебі салыстыру саны дәл n(n−1)/2.

Логарифм негізі маңызды емес: log₂ n = log₁₀ n / log₁₀ 2 ≈ 3.32·log₁₀ n: тек тұрақты көбейткіш. Сондықтан O(log n) деп негізсіз жазамыз.

Иерархия (үлкен n-де әр келесісі алдыңғысынан тез өседі): 1 ≺ log n ≺ √n ≺ n ≺ n log n ≺ n² ≺ n³ ≺ 2ⁿ ≺ n!

Енді сен

«Тәжірибе» бөлімінде selection sort-ты әр түрлі n-мен іске қос: мысалы 256, 512, 1024. Графиктегі қисықтың пішініне қара.

3D симуляцияда орында

  • Selection sort: кемінде 3 өлшем, ең үлкені ең кішісінен ≥ 4 есе
Симуляцияны ашу

Өзіңді тексер

3n² + 100n + 7 қандай класқа жатады?

Жауабы мен түсіндірмесі

Дұрыс жауап: O(n²)

Үлкен n-де n² мүшесі басым, ал тұрақты көбейткіш 3 класты өзгертпейді. Сондықтан O(n²).

Алгоритм n = 1000-да 2 секунд, n = 2000-да 8 секунд алды. Қай класс болуы ықтимал?

Жауабы мен түсіндірмесі

Дұрыс жауап: O(n²)

n екі есе → уақыт төрт есе. Бұл: квадраттық өсудің белгісі. O(2ⁿ) болса, n-ге 1000 қосылғанда уақыт 2¹⁰⁰⁰ есе өсер еді.

2n log n

Идея

O(n log n): салыстыру арқылы сұрыптаудың ең жақсы мүмкін шегі. Merge sort дәл осы класта.

Неге log n? Merge sort массивті екіге бөледі, сосын әр жартысын тағы екіге… log₂ n деңгей. Әр деңгейде барлық n элемент біріктіріледі: ≤ n салыстыру. Барлығы ≤ n·log₂ n.

Түйсік

n log n сызықтыққа өте жақын: n екі есе өссе: сәл ғана екі еседен көп (log n бір бірлікке өседі).

Есептеп көрейік

n·log₂ n:

  • n = 256 → 2 048
  • n = 512 → 4 608 (2.25 есе)
  • n = 1024 → 10 240 (2.22 есе)

Нақты merge sort бұдан сәл аз салыстыру жасайды (кейбір біріктірулер ерте бітеді).

Масштабты сезін: n = 10⁶ болса, n² = 10¹² (секундына 10⁹ операцияда ≈ 17 минут), ал n log₂ n ≈ 2·10⁷ (≈ 0.02 секунд).

Нақты әлемде

Барлық заманауи кітапханалардағы сұрыптау: O(n log n): Python (Timsort), Java (Timsort және dual-pivot quicksort), C++ (introsort), JavaScript V8 (Timsort).

💡 Түйін: O(n²)-ден O(n log n)-ге өту: компьютерді мың есе жылдамдатудан да көп әсер береді.

Енді сен

Merge sort-ты кемінде 3 түрлі n-мен іске қос, ең үлкені ≥ 1024. Қисық selection sort-тан қалай ерекшеленеді?

3D симуляцияда орында

  • Merge sort: кемінде 3 өлшем, ең үлкені ≥ 1024
Симуляцияны ашу

Өзіңді тексер

1024 элементті merge sort неше деңгейге бөледі?

Жауабы мен түсіндірмесі

Дұрыс жауап: 10

2¹⁰ = 1024. Әр деңгейде бөліктердің өлшемі екі есе кішірейеді: 1024 → 512 → … → 1. Біріктіру деңгейлері: 10.

Салыстыру арқылы сұрыптайтын кез келген алгоритмге ең нашар жағдайда кемінде қанша салыстыру керек?

Жауабы мен түсіндірмесі

Дұрыс жауап: ≈ n log₂ n

n элементтің n! мүмкін реті бар. Әр салыстыру нұсқаларды ең көбі екіге бөледі, сондықтан log₂(n!) ≈ n log₂ n салыстыру керек. Бұл: дәлелденген төменгі шек.

3Жарыс

Идея

Бір n-де екі алгоритмді қатар қойсақ, Big O-ның практикалық мағынасы айқын көрінеді.

Түйсік

n кішкене болса, айырма байқалмайды. n өскен сайын квадраттық қисық «жоғары ұшады», ал n log n қисығы түзуге жақын қалады.

Есептеп көрейік

n = 1024:

  • selection sort: 523 776 салыстыру
  • merge sort: ≤ 10 240 салыстыру

Ойлан: айырма ≈ 50 есе. n = 4096 болса: ≈ 170 есе (n/log₂ n өседі).

Бірақ merge sort-тың да бағасы бар: ол O(n) қосымша жад қолданады (уақытша массив), ал selection sort: O(1). Уақыт пен жад арасындағы бұл айырбас (time-space tradeoff): информатиканың негізгі тақырыптарының бірі.

Нақты әлемде

Big O: тек бастамасы. Нақты жылдамдыққа кэш, жадқа қатынау, тұрақты көбейткіштер әсер етеді. Сондықтан quicksort O(n²) ең нашар жағдайына қарамастан практикада жиі ең жылдам.

⚠ Жиі қате: «жылдам компьютер баяу алгоритмді құтқарады». 1000 есе жылдам компьютер O(n²) алгоритмге тек √1000 ≈ 32 есе үлкен n өңдеуге мүмкіндік береді.

Енді сен

Selection мен merge-ті бір n ≥ 1024-те іске қос. Графиктен айырманы көр.

3D симуляцияда орында

  • Бір n ≥ 1024-те selection мен merge-ті салыстыр
Симуляцияны ашу

Өзіңді тексер

Компьютер 100 есе жылдамдады. O(n²) алгоритм сол уақытта қанша есе үлкен n өңдей алады?

Жауабы мен түсіндірмесі

Дұрыс жауап: 10 есе

Уақыт ∝ n². 100 есе көп операция → n² 100 есе үлкен → n √100 = 10 есе үлкен.

Merge sort-тың selection sort-қа қарағанда «бағасы» қандай?

Жауабы мен түсіндірмесі

Дұрыс жауап: O(n) қосымша жад

Біріктіру үшін уақытша массив керек. Merge sort уақыттан ұтады, жадтан ұтылады.
