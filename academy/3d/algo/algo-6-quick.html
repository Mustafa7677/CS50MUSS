Жылдам сұрыптау

Quicksort

Pivot, бөлу (partition) және ең нашар жағдайдан қалай құтылу керегі.

3D симуляцияны ашу Дәрісті оқу

Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақтың қадамдарынан құрастырылған)
  1. Сұрақ. Бір partition-нан кейін не міндетті түрде дұрыс?
  2. Бейне. Сыныпты бойы бойынша бөлу: бір баланы таңдайсың, одан аласалар: солға, ұзындар: оңға. Ол бала енді дәл өз орнында тұр. Сосын әр топты сол тәсілмен бөлесің.
  3. Болжа. Бір partition-нан кейін не міндетті түрде дұрыс? Жауап: Pivot өзінің соңғы орнында тұр. Сол жақтағылардың бәрі ≤ pivot, оң жақтағылар > pivot. Демек сұрыпталған массивте pivot дәл осы орында тұрады. Ал бөліктердің іші әлі ретсіз.
  4. Көр. 1-қадам, «Partition». Quicksort да бөліп-жеңеді, бірақ басқаша: 1. Pivot (тірек) элементін таңда. 2. Partition: pivot-тан кішілердің бәрін сол жаққа, үлкендерін оң жаққа жина. Pivot өз соңғы орнына түседі. 3.
  5. Көр. 2-қадам, «Ең нашар жағдай». Quicksort-тың әлсіз жері: pivot таңдауы. Pivot әрдайым ең үлкен (не ең кіші) элемент болса, partition массивті тең екіге емес, «n − 1 және 0» етіп бөледі.
  6. Көр. 3-қадам, «Pivot-ты дұрыс таңда». Шешім: pivot-ты ақылмен таңдау: ортаңғы элемент: сұрыпталған деректе: дәл медиана кездейсоқ элемент: кез келген кірісте күтілетін уақыт O(n log n) үшеуінің медианасы (median-of-three): бірінші, ортаңғы,…
  7. Көр. Нақты әлемде: Introsort (C++ std:sort): quicksort-пен бастайды, рекурсия тым тереңдесе (> 2·log₂ n) heapsort-қа ауысады: ең нашар жағдайға O(n log n) кепілдік. Pdqsort (Rust, Go): ең нашар үлгілерді анықтап, араластырады.
  8. Түйін. Pivot, бөлу (partition) және ең нашар жағдайдан қалай құтылу керегі.
  9. Түйін. Жиі қате: Неге кездейсоқ pivot «шабуылға» төзімді? Жауап: «Кездейсоқ pivot әрдайым медиана болады». Дұрысы: «Шабуылшы алдын ала қай элемент pivot болатынын біле алмайды». Детерминді ереже үшін (мысалы, «соңғы элемент») әрдайым ең нашар кіріс құруға болады.…

1Partition

Идея

Quicksort да бөліп-жеңеді, бірақ басқаша:

  1. Pivot (тірек) элементін таңда.
  2. Partition: pivot-тан кішілердің бәрін сол жаққа, үлкендерін оң жаққа жина. Pivot өз соңғы орнына түседі.
  3. Сол және оң бөліктерді рекурсивті сұрыпта. Біріктіру керек емес!

Біз Ломуто бөлуін қолданамыз (pivot: бөліктің соңғы элементі):

pivot = a[hi]; i = lo
for j from lo to hi−1:
    if a[j] ≤ pivot: swap(a[i], a[j]); i = i + 1
swap(a[i], a[hi])        // pivot өз орнында

Түйсік

Сыныпты бойы бойынша бөлу: бір баланы таңдайсың, одан аласалар: солға, ұзындар: оңға. Ол бала енді дәл өз орнында тұр. Сосын әр топты сол тәсілмен бөлесің.

Есептеп көрейік

[3, 7, 1, 6, 4], pivot = 4:

  • 3 ≤ 4 → сол жаққа (i = 1)
  • 7 > 4 → қалады
  • 1 ≤ 4 → 7-мен ауыстыр: [3, 1, 7, 6, 4] (i = 2)
  • 6 > 4 → қалады
  • pivot-ты a[2]-мен ауыстыр: [3, 1, 4, 6, 7]

4 өз орнында. Енді [3, 1] мен [6, 7] бөлек сұрыпталады.

Нақты әлемде

Quicksort орташа жағдайда ≈ 1.39·n·log₂ n салыстыру жасайды, бірақ жадқа өте «жақсы» (in-place, кэшке ыңғайлы). Сондықтан C++ std:sort, Java примитивтерін сұрыптау, Go: бәрі quicksort-тың түрлері.

💡 Түйін: 3D-дегі күлгін элемент: pivot. Жасыл: өз орнына біржола түскен pivot-тар.

Енді сен

12 элементке quicksort жүргіз, кемінде 10 қадамды қолмен. Әр partition-нан кейін pivot жасыл болатынын бақыла.

3D симуляцияда орында

  • Quicksort-ты аяқта (кемінде 10 қадамды қолмен)

2Ең нашар жағдай

Идея

Quicksort-тың әлсіз жері: pivot таңдауы. Pivot әрдайым ең үлкен (не ең кіші) элемент болса, partition массивті тең екіге емес, «n − 1 және 0» етіп бөледі.

Түйсік

Сыныпты бөлу үшін әр жолы ең ұзын баланы таңдасаң: бәрі бір жаққа кетеді, тек бір бала орнына түседі. Бөлу ешнәрсені қысқартпайды.

Есептеп көрейік

Сұрыпталған [1, 2, …, n], pivot = соңғы элемент = әрдайым ең үлкені:

  • 1-деңгей: n − 1 салыстыру, сол жақта n − 1 элемент
  • 2-деңгей: n − 2 салыстыру…
(n−1) + (n−2) + … + 1 = n(n−1)/2

n = 32 → 496 салыстыру (bubble sort-тың ең нашар жағдайымен бірдей!) және рекурсия тереңдігі 31 (кездейсоқ деректе ≈ 8-12).

n = 100 000 сұрыпталған массивте рекурсия тереңдігі 100 000: бұл көп тілде stack overflow береді.

Нақты әлемде

Бұл теориялық қорқыныш емес: «сұрыпталған деректі қайта сұрыптау»: нақты жүйеде өте жиі. Сондай-ақ шабуылшы әдейі «нашар» кіріс жіберіп, серверді баяулатуы мүмкін (algorithmic complexity attack).

⚠ Жиі қате: «quicksort: O(n log n)». Тек орташа. Ең нашар жағдай: O(n²).

Тереңірек: quicksort-тың орташа жағдайы ≈ 1.39·n·log₂ n

Кездейсоқ ретте i-ші және j-ші ең кіші элементтер (i < j) қашан салыстырылады? Тек егер олардың біреуі i..j аралығындағы j − i + 1 элементтің ішінде бірінші pivot болып таңдалса. Әйтпесе олардың арасындағы pivot оларды әр түрлі бөлікке ажыратады. Ықтималдығы:

P(i мен j салыстырылады) = 2 / (j − i + 1)

Күтілетін салыстыру саны: барлық жұптар бойынша қосынды:

E = Σ_{i<j} 2/(j−i+1) ≈ 2n·Hₙ ≈ 2n·ln n ≈ 1.39·n·log₂ n

(Hₙ = 1 + ½ + … + 1/n ≈ ln n: гармоникалық қатар.)

Біздің тәжірибеде n = 32: 1.39·32·5 ≈ 222: бұл асимптотикалық баға; кіші n-де нақты сан одан аз (біз 133-172 көрдік).

Ал ең нашар жағдайда әр pivot: шеттегі элемент: T(n) = T(n − 1) + (n − 1) → n(n−1)/2.

Енді сен

Сұрыпталған 32 элементке pivot = «соңғы» quicksort жүргіз. Салыстыру 496 болатынын тексер.

Өзіңді тексер

Сұрыпталған 10 элемент, pivot = соңғы элемент. Quicksort неше салыстыру жасайды?

Жауабы мен түсіндірмесі

Дұрыс жауап: 45

Әр partition тек pivot-ты орнына қояды: 9 + 8 + … + 1 = 45 = n(n−1)/2.

Сол жағдайда рекурсия тереңдігі қандай?

Жауабы мен түсіндірмесі

Дұрыс жауап: ≈ n

Әр деңгейде бөлік тек бір элементке кішірейеді, сондықтан ≈ n деңгей. Үлкен n-де бұл стекті толтырады.

3Pivot-ты дұрыс таңда

Идея

Шешім: pivot-ты ақылмен таңдау:

  • ортаңғы элемент: сұрыпталған деректе: дәл медиана
  • кездейсоқ элемент: кез келген кірісте күтілетін уақыт O(n log n)
  • үшеуінің медианасы (median-of-three): бірінші, ортаңғы, соңғының медианасы

Түйсік

Сыныпты бөлу үшін бойы «орташа» баланы таңдасаң: екі топ шамамен тең. Әр бөлу есепті екі есе кішірейтеді, merge sort-тағыдай log₂ n деңгей.

Есептеп көрейік

Сол сұрыпталған 32 элемент, pivot = ортаңғы:

  • салыстыру: 103 (496 орнына: 5 есе аз)
  • рекурсия тереңдігі: 5 (31 орнына)

n·log₂ n = 160: 103 одан да аз.

Нақты әлемде

Introsort (C++ std:sort): quicksort-пен бастайды, рекурсия тым тереңдесе (> 2·log₂ n) heapsort-қа ауысады: ең нашар жағдайға O(n log n) кепілдік. Pdqsort (Rust, Go): ең нашар үлгілерді анықтап, араластырады.

💡 Түйін: алгоритмнің ең нашар жағдайын білу: оны жоюдың бірінші қадамы.

Енді сен

Pivot-ты «ортаңғы» етіп, сол сұрыпталған 32 элементті қайта сұрыпта. Салыстырулар n·log₂ n = 160-тан аз болуы керек.

3D симуляцияда орында

  • Сол деректе pivot = ортаңғы: < n·log₂n салыстыру

Неге кездейсоқ pivot «шабуылға» төзімді?

Жауабы мен түсіндірмесі

Дұрыс жауап: Шабуылшы алдын ала қай элемент pivot болатынын біле алмайды

Детерминді ереже үшін (мысалы, «соңғы элемент») әрдайым ең нашар кіріс құруға болады. Кездейсоқтық болса, ең нашар жағдайдың ықтималдығы шамалы: кіріс қандай болса да.

Introsort quicksort-тың ең нашар жағдайынан қалай қорғанады?

Жауабы мен түсіндірмесі

Дұрыс жауап: Рекурсия тым тереңдесе, heapsort-қа ауысады

Тереңдік > 2·log₂ n: нашар pivot-тардың белгісі. Heapsort-та ең нашар жағдай O(n log n), сондықтан жалпы кепілдік сақталады.
