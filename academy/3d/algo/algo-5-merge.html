Алгоритмдер · 5-сабақ · ≈25 мин · 2 қадам · 4 сұрақ

Біріктіріп сұрыптау

Merge Sort

Бөліп ал да, жеңе бер: рекурсия, біріктіру және n·log₂n.

3D симуляцияны ашу Дәрісті оқу

  1. Бөлу және біріктіру
  2. Кез келген деректе бірдей

1Бөлу және біріктіру

Идея

Бөліп ал да, жеңе бер (divide and conquer):

  1. Бөл: массивті екі жартыға бөл.
  2. Жең: әр жартысын сол алгоритммен сұрыпта (рекурсия).
  3. Біріктір: екі сұрыпталған жартыны бір сұрыпталған массивке қос.

Рекурсия тоқтайтын жер (base case): бір элементті массив: әлдеқашан сұрыпталған.

sort(a, lo, hi):
    if lo ≥ hi: return
    mid = (lo + hi) / 2
    sort(a, lo, mid)
    sort(a, mid+1, hi)
    merge(a, lo, mid, hi)

Түйсік

Екі сұрыпталған карта бумасын біріктіру: екі бумның үстіңгі карталарын салыстырып, кішісін алып қоясың. Әр салыстыру бір картаны орнына қояды.

Есептеп көрейік

[2, 5] және [1, 4] біріктіру:

  1. 2 мен 1 → 1 алынды
  2. 2 мен 4 → 2
  3. 5 пен 4 → 4
  4. Оң бума бітті → қалғаны 5

Нәтиже [1, 2, 4, 5], 3 салыстыру. Ұзындықтары p мен q бумаларды біріктіру ең көбі p + q − 1 салыстыру алады.

16 элемент: 4 деңгей (16 → 8 → 4 → 2 → 1). Біздің кездейсоқ массивте: 46 салыстыру (16·4 = 64 жоғарғы шегінен аз).

Нақты әлемде

Merge sort: тұрақты (stable): тең элементтердің бастапқы ретін сақтайды. Сондықтан кестені алдымен аты бойынша, сосын қаласы бойынша сұрыптасаң, бір қаладағылар әлі де алфавитпен тұрады. Python мен Java-ның Timsort-ы: merge sort пен insertion sort-тың гибриді.

💡 Түйін: 3D-де ашық аймақ: алгоритм қазір жұмыс істеп жатқан бөлік [lo..hi]. Ол кішірейіп (бөлу), сосын үлкейеді (біріктіру).

Тереңірек: T(n) = 2T(n/2) + n рекурренттік теңдеуі

Merge sort-тың уақыты: екі жартыны сұрыптау + біріктіру:

T(1) = 0,   T(n) = 2·T(n/2) + n

Рекурсия ағашымен шешеміз (n = 2ᵏ):

  • 0-деңгей: 1 есеп, n өлшемді → n жұмыс
  • 1-деңгей: 2 есеп, n/2 өлшемді → 2·(n/2) = n
  • i-деңгей: 2ⁱ есеп, n/2ⁱ өлшемді → n
  • деңгейлер саны: k = log₂ n

Барлығы: T(n) = n·log₂ n.

Тексеру: T(n) = 2·(n/2)·log₂(n/2) + n = n·(log₂ n − 1) + n = n·log₂ n ✓

Master theorem бұл түрдегі теңдеулерді жалпы шешеді: T(n) = a·T(n/b) + f(n). Мұнда a = 2, b = 2, f(n) = n = n^(log_b a) → T = Θ(n log n). Екілік іздеу: T(n) = T(n/2) + 1 → Θ(log n).

Енді сен

Кемінде 10 қадамды қолмен жүр: бөлінген аймақтар қалай кішірейетінін бақыла. Сосын соңына дейін жеткіз.

3D симуляцияда орында

  • Merge sort-ты 16 элементте аяқта (кемінде 10 қадамды қолмен)
Симуляцияны ашу

Өзіңді тексер

[1, 3, 5] мен [2, 4, 6] біріктіргенде неше салыстыру болады?

Жауабы мен түсіндірмесі

Дұрыс жауап: 5

1<2, 3>2, 3<4, 5>4, 5<6: 5 салыстыру, сосын 6 салыстырусыз қосылады. Ең нашар жағдай p + q − 1 = 5.

Merge sort рекурсиясы қашан тоқтайды?

Жауабы мен түсіндірмесі

Дұрыс жауап: Бөлік бір (не нөл) элементтен тұрғанда

Бір элемент: әрдайым сұрыпталған. Бұл base case болмаса, рекурсия шексіз бөлуге тырысып, stack overflow-ға әкелер еді.

2Кез келген деректе бірдей

Идея

Merge sort-тың басты артықшылығы: кепілдік: кез келген деректе ол O(n log n). Ең нашар жағдай да, ең жақсы жағдай да: бірдей класс.

Түйсік

Merge sort деректерге «қарамайды»: ол әрдайым бірдей бөледі, бірдей деңгейлермен біріктіреді. Тек біріктірудегі салыстыру саны сәл өзгереді.

Есептеп көрейік

32 элемент, біздің симуляцияда:

  • кері ретті: 80 салыстыру
  • сұрыпталған: 80
  • кездейсоқ: 123
  • жоғарғы шегі: n·log₂ n − n + 1 = 129

Неге кері ретте аз? Әр біріктіруде бір жартының бәрі екіншісінен кіші: ол бірден «таусылады», қалғаны салыстырусыз көшіріледі. Ал bubble sort-қа кері рет: ең нашар жағдай (496)!

Нақты әлемде

Сыртқы сұрыптау (external sort): деректер жадқа сыймайтын болса (мысалы 100 ГБ), оларды бөліктерге бөліп, әрқайсысын сұрыптап дискіге жазып, сосын біріктіреді. Бұл: merge sort-тың тікелей қолданысы. Дерекқорлар мен MapReduce жүйелері осылай жұмыс істейді.

⚠ Жиі қате: merge sort-ты «әрқашан ең жақсы» деп ойлау. Ол O(n) қосымша жад алады және кішкене массивтерде insertion sort-тан баяу.

Енді сен

Кері ретті және кездейсоқ 32 элементке merge sort жүргіз. Салыстыруларды bubble sort-тың 496-сымен салыстыр.

3D симуляцияда орында

  • Кері ретті 32 элемент
  • Кездейсоқ 32 элемент
Симуляцияны ашу

Өзіңді тексер

Merge sort-тың ең нашар жағдайындағы күрделілігі қандай?

Жауабы мен түсіндірмесі

Дұрыс жауап: O(n log n)

Бөлу әрдайым тең жартыға → log₂ n деңгей, әр деңгейде ≤ n салыстыру. Деректер оны өзгерте алмайды.

Оқушылар бағасы бойынша сұрыпталды. Тең бағалылардың бастапқы реті (мысалы, алфавит) сақталуы үшін сұрыптау қандай болуы керек?

Жауабы мен түсіндірмесі

Дұрыс жауап: Тұрақты (stable)

Тұрақты сұрыптау тең кілттердің салыстырмалы ретін өзгертпейді. Merge sort: тұрақты; біздің quicksort: тұрақты емес.
