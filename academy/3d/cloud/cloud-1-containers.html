1Қабаттар мен кэш

Комикс · Нұрай, Мустафа және Бота

Менің компьютерімде жұмыс істеді!

Барлық комикстер

Идея

Контейнер: бағдарлама мен оның барлық тәуелділіктері бір «қорапта»: кітапханалар, жүйелік файлдар, баптаулар. Ол кез келген серверде бірдей жұмыс істейді: «менің компьютерімде жұмыс істейді» мәселесінің шешімі.

Контейнер образдан (image) іске қосылады, ал образ Dockerfile бойынша қабаттармен жиналады: әр нұсқау: бір қабат.

Кэш ережесі: қабаттың кірісі өзгермесе, ол кэштен алынады. Бір қабат өзгерсе: одан кейінгі барлық қабаттар қайта жиналады (олар алдыңғыға тәуелді).

Түйсік

Торт: қабаттарды төменнен жоғары саласың. Ортаңғы қабатты ауыстырсаң, оның үстіндегінің бәрін қайта салу керек.

Есептеп көрейік

Ағымдағы рет:

FROM node:20              0 с
WORKDIR /app              0.1 с
COPY src ./src            0.5 с   ← код өзгерді
COPY package.json .       0.2 с
RUN npm install           45 с
RUN npm run build         20 с

Код (src) өзгерсе: COPY src-тен бастап барлығы қайта: 0.5 + 0.2 + 45 + 20 = 65.7 с. Әр өзгерісте тәуелділіктер қайта жүктеледі: олар өзгермесе де!

Нақты әлемде

Docker (2013) контейнерлерді жаппай танымал етті; бүгін бұлттағы бағдарламалардың көбі контейнерде. Бір күнде жүздеген жинау: 45 секунд үнем × 100 = әр әзірлеушіге күніне 1+ сағат.

💡 Түйін: 3D-де әр қабат: бір блок; қызыл: қайта жиналатындар, жасыл: кэштен.

Ағымдағы реттегі образды «код өзгерді» деп қайта жина.

Контейнердің басты пайдасы?

Жауабы мен түсіндірмесі

Дұрыс жауап: Бағдарлама тәуелділіктерімен бірге кез келген ортада бірдей жұмыс істейді

Ортаның айырмашылықтары (кітапхана нұсқалары, ОЖ баптаулары): өндірістегі қателердің жиі себебі. Контейнер ортаны кодпен бірге «қаптайды».

2Ретті түзет

Идея

Ереже: сирек өзгеретін нәрселер: жоғарыда, жиі өзгеретіндер: төменде. Тәуелділіктер тізімі (package.json) сирек өзгереді, ал код: күніне ондаған рет.

FROM node:20
WORKDIR /app
COPY package.json .     ← сирек
RUN npm install         ← кэштен (package.json өзгермесе)
COPY src ./src          ← жиі
RUN npm run build
CMD [...]

Түйсік

Шкафтағы киім: күнде киетінді алдыға, жылына бір киетінді артқа. Сонда күнделікті «қазу» аз.

Есептеп көрейік

Жаңа ретте код өзгерсе: COPY src (0.5) + build (20) = 20.5 с: 65.7 с-тың орнына, 3.2 есе жылдам. package.json өзгерсе: бәрібір 65.7 с (тәуелділіктер шынымен жаңартылуы керек).

Бірақ рет еркін емес: npm install үшін package.json алдымен көшірілуі керек, ал build үшін: код пен тәуелділіктер. Біздің симулятор мұны тексереді.

Нақты әлемде

Тағы бір тәсіл: multi-stage build: жинау құралдары бар үлкен образда жинап, тек нәтижені кішкене образға көшіру. Образ 1 ГБ-тан 50 МБ-қа түседі: жылдам жүктеу, аз осалдық.

⚠ Жиі қате: COPY . .: бәрін бір қабатта көшіру. Кез келген файл (тіпті README) өзгерсе, npm install қайта жүреді.

Тереңірек: контейнер іші: namespaces, cgroups және overlay

Контейнер: виртуалды машина емес. Ол: Linux ядросының үш мүмкіндігімен оқшауланған кәдімгі процесс:

  • namespaces: процесс өзінің жеке PID кеңістігін (ішінде ол PID 1), желісін, файлдық жүйесін, hostname-ін көреді
  • cgroups: CPU, жад, дискіге шектеулер («ең көбі 512 МБ»)
  • overlay файлдық жүйесі: образ қабаттары бір-бірінің үстіне «қабатталады»; ортақ қабаттар дискіде бір рет сақталады, ал контейнердің өзгерістері ең үстіңгі жазылатын қабатқа түседі (copy-on-write)

Сондықтан контейнер миллисекундтарда іске қосылады (ОЖ жүктелмейді: ядро ортақ), ал 100 контейнер бір base образды бөліскенде диск бір рет қана жұмсалады.

Қабаттың кэш кілті: нұсқаудың мәтіні + COPY-дің файлдарының хэші (Cybersecurity зертханасындағы SHA-256!). Файлдың бір байты өзгерсе: хэш өзгереді: кэш жарамсыз.
