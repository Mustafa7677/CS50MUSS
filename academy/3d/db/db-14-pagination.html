Pagination: OFFSET vs Keyset

Тереңдегі бетті ашу неге баяу, ал лента неге бір жазбаны екі рет көрсетеді. OFFSET-тің бағасы және «осы id-ден кейінгілер» әдісі.

3D симуляцияны ашу Дәрісті оқу

  1. Тереңдегі бет
  2. Қозғалатын лента

1Тереңдегі бет

Идея

Үлкен тізімді беттерге бөлудің ең қарапайым жолы:

SELECT ... ORDER BY id LIMIT 20 OFFSET 4980

Бірақ OFFSET тегін емес. Дерекқор 4980 жолды индекс бойымен оқиды, оларды санайды да, лақтырып тастайды. Бет неғұрлым терең болса, соғұрлым баяу: 1-бет 20 жол, 250-бет 5000 жол.

Keyset (seek) беттеу басқаша сұрайды: «қай орында» емес, «қай мәннен кейін»:

SELECT ... WHERE id > 4980 ORDER BY id LIMIT 20

Индекс B-ағаш: ол id = 4980 орнын логарифмдік уақытта табады, сосын тек 20 жол оқиды. Тереңдік маңызды емес.

Түйсік

Кітаптың 250-бетін ашу. OFFSET: бірінші беттен бастап парақтарды санап шығу. Keyset: бетбелгі қойылған жерден ашу.

Есептеп көрейік

EXPLAIN нәтижесінде «оқылды» санын қара:

  • OFFSET 4980: 5000 жол оқылды, 20 жол қайтарылды. Оқылғанның 99,6%-ы босқа.
  • WHERE id > 4980: 20 жол оқылды, 20 қайтарылды.

Мыңдаған пайдаланушы ары қарай парақтаса, бұл айырма серверлердің санына айналады.

Нақты әлемде

Twitter, Instagram, GitHub API-лері «келесі бет» үшін сан емес, курсор береді (мысалы, ?after=4980): бұл keyset. Бағасы: «250-бетке бірден өту» мүмкіндігі жоғалады, тек алға не артқа жүруге болады.

⚠ Keyset үшін сұрыптау бағаны бірегей және индекстелген болуы керек. Бірдей мәндер болса, (created_at, id) сияқты екі бағанды кілт керек.

Енді сен

Дайын OFFSET сұранысын орында да, оқылған жолдарды көр. Сосын сол 20 жолды WHERE id > 4980 арқылы ал.

3D симуляцияда орында

  • Соңғы бетті OFFSET-пен аш: 20 жол үшін 5000 жол оқылды
  • Сол бетті WHERE id > ... арқылы аш: 20 жол оқылды
Симуляцияны ашу

Алдымен болжа

events кестесінде 5000 жол, id бойынша индекс бар. «ORDER BY id LIMIT 20 OFFSET 4980» сұранысы неше жолды оқиды?

Жауабы мен түсіндірмесі

Дұрыс жауап: 5000: алдымен 4980 жолды оқып, лақтырады, сосын 20-сын береді

Индекс жолдарды ретімен береді, бірақ «4980-орын» қай жерде екенін білмейді. OFFSET жолдарды бір-бірлеп санап өтуге мәжбүрлейді.

Өзіңді тексер

Неге OFFSET беттің тереңдігіне қарай баяулайды?

Жауабы мен түсіндірмесі

Дұрыс жауап: Дерекқор өткізіп жіберілетін жолдарды да оқып, санап өтуі керек

Индекс ретті береді, бірақ «N-орынға» секіре алмайды. Ал мәнге (id > 4980) секіре алады.

Keyset беттеуге не керек?

Жауабы мен түсіндірмесі

Дұрыс жауап: Бірегей әрі индекстелген сұрыптау кілті және алдыңғы беттің соңғы мәні

«Осы мәннен кейінгілер» деп сұрау үшін соңғы көрген мәнді есте сақтау жеткілікті.

2Қозғалатын лента

Идея

OFFSET орынмен санайды, ал орындар жылжиды. Беттер арасында:

  • басына жаңа жол қосылса: келесі бетте бір жазба қайталанады;
  • алдыңғы беттен жол өшірілсе: бір жазба көрінбей қалады, ешкім байқамайды.

Keyset мәнмен санайды: «id < 4981 болғандар». Жаңа жолдың id-і үлкен, ол шартқа кірмейді. Ығысу жоқ.

Түйсік

Кезекте тұрғанда «маған 20-орыннан кейінгілерді шақыр» десең, біреу алдыға кіріп кетсе, сен бір адамды екі рет көресің. «Мына кісіден кейінгілерді шақыр» десең, ешкім шатаспайды.

Есептеп көрейік

1-бет (DESC): 5000, 4999, ..., 4981. Жаңа оқиға: id = 5001.

  • OFFSET 20: 4981, 4980, ..., 4962. 4981 екі бетте де бар.
  • WHERE id < 4981: 4980, 4979, ..., 4961. Қайталану жоқ.

Нақты әлемде

Шексіз айналдырылатын ленталарда (жаңалықтар, чат, хабарламалар) OFFSET-тің бұл ақауы жиі кездеседі: пайдаланушы бір постты екі рет көреді, не біреуін мүлде көрмейді. Сондықтан ленталар әрқашан курсормен жасалады.

Енді сен

  1. 1-бетті аш.
  2. Жаңа оқиға қос: INSERT INTO events (id, user_id, kind, amount) VALUES (5001, 1, 'buy', 100).
  3. 2-бетті OFFSET 20-пен аш да, қайталанған id-ді тап.
  4. Сол бетті WHERE id < 4981 арқылы аш.

3D симуляцияда орында

  • 1-бетті аш, жаңа оқиға қос, 2-бетті OFFSET 20-пен аш: бір жазба қайталанды
  • Жаңа оқиғадан кейін 2-бетті WHERE id < ... арқылы аш: қайталану жоқ
Симуляцияны ашу

Алдымен болжа

Лента ең жаңасынан басталады (ORDER BY id DESC). Сен 1-бетті көрдің, сол кезде біреу жаңа оқиға қосты. 2-бетті OFFSET 20-пен ашсаң не болады?

Жауабы мен түсіндірмесі

Дұрыс жауап: 1-беттің соңғы жазбасы 2-беттің басында тағы шығады

Жаңа жол басына қосылды да, бәрін бір орынға ығыстырды. 20-орындағы жол енді 21-орында: OFFSET 20 оны тағы береді.

Өз сөзіңмен түсіндір

Жаңа оқиға қосылғанда неге OFFSET 20 бір жазбаны қайталады, ал WHERE id < ... қайталамады?

Жақсы түсіндірмеде болатын ойлар
  • OFFSET орынмен санайды, орындар жылжиды
  • жаңа жол басына қосылды
  • keyset мәнмен санайды

Өзіңді тексер

Беттер арасында басына жол қосылғанда OFFSET неге қайталайды?

Жауабы мен түсіндірмесі

Дұрыс жауап: Барлық жолдың орны бір орынға жылжиды, ал OFFSET орынмен санайды

OFFSET 20 «21-орыннан баста» дейді. Жаңа жол қосылғанда бұрынғы 20-орын 21-орынға айналды.

Ал беттер арасында бірінші беттен жол өшірілсе, OFFSET беттеуде не болады?

Жауабы мен түсіндірмесі

Дұрыс жауап: Бір жазба ешбір бетте көрсетілмей қалады

Жолдар бір орын алға жылжиды. 21-орындағы жол 20-орынға келіп, келесі беттің сыртында қалады.
