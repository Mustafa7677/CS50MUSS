Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. Құжаттамасыз бағдарламаны авторынан басқа ешкім (тіпті үш айдан кейінгі автор да) қолдана алмайды.
  2. Жол. 1-қадам. README-ге орнату мен мысал жазамыз: python stats.py data.csv → «3 оқушы, орташа 85.0».
  3. Жол. 2-қадам. Бұл мысалды CI-да іске қосып, шығысын салыстырамыз - README ескірмейді.
  4. Жол. 3-қадам. Әр жария функцияға docstring: не істейді, параметрлер, қайтару мәні, ерекшеліктер, мысал (>>>).
  5. Жол. 4-қадам. Жаңа нұсқа: үйлесімсіз өзгеріс болса MAJOR++, CHANGELOG-қа жазба.
  6. Тексер. Функцияның параметрі жойылды (ескі шақырулар енді қате береді). Нұсқа 2.3.1 болса, келесі: Жауап: 3.0.0. Дұрыс: үйлесімсіз өзгеріс - MAJOR.
  7. Түйін. Нұсқаларды салыстыру - лексикографиялық рет. Нұсқаларды (MAJOR, MINOR, PATCH) бүтін сандар кортежі ретінде лексикографиялық салыстыру толық реттілік береді (кез келген екі нұсқа салыстырылады, транзитивті), ал…
  8. Түйін. Жиі қате: README-де «оңай орнатылады» деп, қадамдарды жазбау. Дұрысы: Таза машинада орнату қадамдарын бір-бірден тексеріп жазу.

AОқу мақсаттары

  • README-нің негізгі бөлімдерін (не, неге, қалай орнату, қалай қолдану, шектеулер) жазу.
  • Docstring пен doctest арқылы орындалатын, ескірмейтін мысалдар жазу.
  • Семантикалық нұсқалауды (MAJOR.MINOR.PATCH) түсіну және нұсқаларды дұрыс салыстыру.

CҰғымға кіріспе

Құжаттамасыз бағдарламаны авторынан басқа ешкім (тіпті үш айдан кейінгі автор да) қолдана алмайды. Үш деңгей: README - жобаның «есігі» (не істейді, қалай іске қосу, мысал); API құжаттамасы - әр функцияның келісімшарты (docstring, m07 l03); өзгерістер журналы (CHANGELOG) - нұсқалар арасындағы айырма.

Құжаттаманың басты қаупі - ескіру: код өзгереді, мысал өзгермейді. Python-ның doctest модулі docstring-тегі мысалдарды тест ретінде іске қосады - мысал қате болса, тест құлайды. Бұл AO17 сабақтарының өзі қолданатын тәсіл: әр мысалдың шығысы build кезінде тексеріледі.

DАкадемиялық теория

Анықтама

Семантикалық нұсқалау

MAJOR.MINOR.PATCH: MAJOR - үйлесімсіз өзгеріс (API бұзылды), MINOR - үйлесімді жаңа мүмкіндік, PATCH - үйлесімді түзету. 1.4.2 → 1.5.0 (жаңа функция), → 2.0.0 (ескі код сынуы мүмкін).

Теорема

Нұсқаларды салыстыру - лексикографиялық рет

Нұсқаларды (MAJOR, MINOR, PATCH) бүтін сандар кортежі ретінде лексикографиялық салыстыру толық реттілік береді (кез келген екі нұсқа салыстырылады, транзитивті), ал жолдар ретінде салыстыру ('1.10.0' < '1.9.0') қате.

Дәлелдеу

Дәлелдеу

Лексикографиялық рет: (a₁, a₂, a₃) < (b₁, b₂, b₃) ⇔ бірінші ерекшеленетін i-де aᵢ < bᵢ. Толықтық: екі кортеж не тең, не бірінші ерекшеленетін позиция бар, онда бүтін сандардың толық реті бойынша біреуі кіші. Транзитивтілік: a < b < c болсын; i, j - бірінші айырма позициялары; k = min(i, j) позициясына дейін үшеуі тең, ал k-да aₖ ≤ bₖ ≤ cₖ, кемінде біреуі қатаң - демек a < c. ∎ Жолдарды салыстыру таңбалар бойынша: '1' = '1', '.' = '.', '1' < '9' - сондықтан '1.10.0' < '1.9.0', бірақ сан ретінде 10 > 9.

Ескерту

Жақсы README құрылымы

  1. Бір сөйлеммен: не істейді.
  2. Жылдам бастау: орнату + бір мысал (шығысымен).
  3. Қолдану: негізгі мүмкіндіктер.
  4. Шектеулер мен белгілі мәселелер (адал).
  5. Лицензия, авторлар, байланыс.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. README-ге орнату мен мысал жазамыз: python stats.py data.csv → «3 оқушы, орташа 85.0».
  2. Бұл мысалды CI-да іске қосып, шығысын салыстырамыз - README ескірмейді.
  3. Әр жария функцияға docstring: не істейді, параметрлер, қайтару мәні, ерекшеліктер, мысал (>>>).
  4. Жаңа нұсқа: үйлесімсіз өзгеріс болса MAJOR++, CHANGELOG-қа жазба.
