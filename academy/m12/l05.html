Кино-түсіндіру: сабақтың өзегі бір минуттық мультфильмде. Мәтіні төменде.

Фильмнің мәтіні (сабақ қадамдарынан құрастырылған)
  1. Сұрақ. «Ерте оңтайландыру - бар зұлымдықтың тамыры» (Д. Кнут). Алдымен өлшеу : бағдарлама уақытының қай бөлігі қайда жұмсалады? Профилдеуші (cProfile) әр функцияның шақырулар санын және уақытын көрсетеді. Көбіне уақыттың 90%-ы кодтың 10%-ында.
  2. Жол. 1-қадам. Өлшеу: cProfile - slow_unique уақыттың ~95%-ы (p ≈ 0.95).
  3. Жол. 2-қадам. Оңтайландыру: тізім орнына set (m08 l04) - бұл бөлік, мысалы, 50 есе жылдамдайды (s = 50).
  4. Жол. 3-қадам. Амдал: S = 1/(0.05 + 0.95/50) = 1/0.069 ≈ 14.5 есе.
  5. Жол. 4-қадам. Қайта өлшеу: енді тар жер басқа жерде - цикл қайталанады.
  6. Тексер. Оңтайландыруды неден бастау керек? Жауап: Профилдеп, уақыттың көбі жұмсалатын жерді табу. Дұрыс.
  7. Түйін. Амдал заңы. S = 1 / ((1 − p) + p/s), және кез келген s үшін S
  8. Түйін. Жиі қате: Болжам бойынша оңтайландыру («бұл цикл баяу болуы керек»). Дұрысы: cProfile, perf_counter (m09 l10).

AОқу мақсаттары

  • Профилдеу (cProfile) арқылы бағдарламаның «тар жерін» (bottleneck) табу.
  • Амдал заңын дәлелдеп, оңтайландырудың шегін бағалау.
  • Жад өлшеу (tracemalloc) және уақыт пен жадтың алмасуын талдау.

BАлғышарттар

  • Python мен C бірге
  • Эмпирикалық салыстыру

CҰғымға кіріспе

«Ерте оңтайландыру - бар зұлымдықтың тамыры» (Д. Кнут). Алдымен өлшеу: бағдарлама уақытының қай бөлігі қайда жұмсалады? Профилдеуші (cProfile) әр функцияның шақырулар санын және уақытын көрсетеді. Көбіне уақыттың 90%-ы кодтың 10%-ында.

Амдал заңы оңтайландырудың шегін береді: бағдарлама уақытының тек p үлесін s есе жылдамдатсақ, жалпы жылдамдау 1 / ((1 − p) + p/s). p = 0.5 болса, s шексіз болса да, тек 2 есе. Сондықтан тар жерді табу - бірінші қадам.

DАкадемиялық теория

Анықтама

Жылдамдау

S = T_ескі / T_жаңа. Бағдарлама екі бөліктен: оңтайландырылмайтын (1 − p)·T және оңтайландырылатын p·T; соңғысы s есе жылдамдайды.

Теорема

Амдал заңы

S = 1 / ((1 − p) + p/s), және кез келген s үшін S < 1 / (1 − p) (p < 1).

Дәлелдеу

Дәлелдеу

T_жаңа = (1 − p)·T + p·T/s (бірінші бөлік өзгермейді, екіншісі s есе жылдамырақ). S = T / T_жаңа = 1 / ((1 − p) + p/s). p/s > 0 (p > 0, s шекті), сондықтан бөлім > 1 − p, демек S < 1/(1 − p). s → ∞ кезінде p/s → 0 және S → 1/(1 − p) - бұл шекке жетуге болмайды, тек жақындауға. ∎ Мысал: p = 0.9, s = 10 → S = 1/(0.1 + 0.09) ≈ 5.26; шек - 10.

Ескерту

Уақыт пен жад

Көп оңтайландыру уақытты жадқа айырбастайды: мемоизация (m09 l08), кэш, индекс. tracemalloc бағдарламаның ең көп жад бөлген жолдарын көрсетеді. Шешім - өлшемдерге негізделген, болжамға емес.

EКөрнекі түсіндірме

Профиль slow_unique-те уақыттың көбі жұмсалатынын көрсетеді (x not in out - O(n), m08 l04). parse - арзан. Оңтайландыру қайда керек екені енді анық. (Браузерде трасса уақытты өзгертеді - тек салыстырмалы үлестерге қараңыз.)

Интерактивті модель: өзің басқар

Оңтайландыру алгоритмі де өлшенетін процесс: η (қадам) мен бастапқы нүктені өзгертіп, қашан жылдам жинақталатынын, қашан алшақтайтынын көріңіз.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. Өлшеу: cProfile - slow_unique уақыттың ~95%-ы (p ≈ 0.95).
  2. Оңтайландыру: тізім орнына set (m08 l04) - бұл бөлік, мысалы, 50 есе жылдамдайды (s = 50).
  3. Амдал: S = 1/(0.05 + 0.95/50) = 1/0.069 ≈ 14.5 есе.
  4. Қайта өлшеу: енді тар жер басқа жерде - цикл қайталанады.

GЖұмыс мысалдары

HИнтерактивті эксперимент

Тізім барлық 20 000 санды жадта сақтайды, генератор - бір-бірден. Бір нәтиже, жадтағы айырма ондаған-жүздеген есе. Уақыт пен жадтың айырбасы - өлшеммен шешіледі.

IЖаттығулар

JМатематикалық пайымдау

Өнімділік - сезім емес, өлшем. m09 l10 бір алгоритмді өлшеді; мұнда бүкіл жүйені өлшейміз және Амдал заңы қайда күш жұмсау керектігін айтады. Көп жағдайда ең үлкен жылдамдау - алгоритмді ауыстыру (O(n²) → O(n)), тілді ауыстыру емес.

KЖиі қателер

  • Болжам бойынша оңтайландыру («бұл цикл баяу болуы керек»).
    Себебі: Интуиция тар жерді жиі қате табады.
    Түзету: cProfile, perf_counter (m09 l10).
  • Микро-оңтайландыру (x * 2 орнына x << 1) - оқылуды бұзу.
    Себебі: Ұтыс болмашы, компилятор/интерпретатор өзі жасайды.
    Түзету: Алгоритм мен деректер құрылымына назар.
