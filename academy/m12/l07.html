Нұсқа бақылау (Git)

  • орта
  • ≈ 55 мин
  • 3 мақсат
  • 6 тапсырма

нұсқа 1.0.0 · тексеру: author-checked

AОқу мақсаттары

  • Git моделін түсіндіру: commit - сурет (snapshot) + ата-аналарына сілтеме, тарих - бағытталған ациклдік граф.
  • Тармақты (branch) commit-ке жылжымалы көрсеткіш ретінде, merge-ті екі тарихты біріктіру ретінде сипаттау.
  • Біріктіру негізін (merge base) және fast-forward шартын граф алгоритмімен табу.

BАлғышарттар

  • Сенімді енгізу
  • Графты аралау

CҰғымға кіріспе

Git - кодтың тарихын сақтайтын жүйе. Әр commit - жобаның сол сәттегі толық суреті және ата-ана commit(тер)іне сілтеме. Барлық commit-тер бірге бағытталған ациклдік граф (DAG) құрайды (m03 l09, m09 l09). Тармақ - жай ғана атауы бар көрсеткіш (m11 l02 ұғымы!): жаңа commit жасағанда ол алға жылжиды.

Merge екі тармақты біріктіреді: Git олардың ортақ ата-бабасын (merge base) тауып, екі жақтағы өзгерістерді салыстырады. Бір тармақ екіншісінің тікелей жалғасы болса - fast-forward: көрсеткіш жай жылжиды. Бұл сабақтағы Python модельдері нағыз Git-тің негізгі алгоритмдерін қайталайды.

DАкадемиялық теория

Анықтама

Негізгі ұғымдар

commit c: parents(c) - ата-аналар тізімі (бос - бірінші commit, екеу - merge commit). ancestors(c) - c және оған parents бойымен жетуге болатын барлық commit. Тармақ b → commit. merge base(x, y) - ортақ ата-бабалардың ішіндегі «ең жаңасы» (басқа ортақ ата-бабаның ата-бабасы емес).

Теорема

Fast-forward шарты

main тармағын feature-ге fast-forward арқылы біріктіруге болады ⇔ main көрсететін commit feature көрсететін commit-тің ата-бабасы (main ∈ ancestors(feature)).

Дәлелдеу

Дәлелдеу

(⇐) m = main ∈ ancestors(f). Онда f-тің тарихы m-нің бүкіл тарихын қамтиды (ата-бабалық транзитивті: ancestors(m) ⊆ ancestors(f)). main-ді f-ке жылжыту ешбір commit-ті жоғалтпайды - бұл fast-forward. (⇒) Fast-forward - main-ді f-ке жылжыту, нәтижеде main-нің жаңа тарихы ancestors(f). Ешбір commit жоғалмауы үшін ескі тарих ancestors(m) ⊆ ancestors(f) болуы керек, атап айтқанда m ∈ ancestors(f). ∎ Әйтпесе тарихтар айырылған - merge commit (екі ата-аналы) қажет.

Ескерту

Неге hash?

commit идентификаторы - мазмұны мен ата-аналарының криптографиялық хэші (SHA). Сондықтан тарихты байқатпай өзгерту мүмкін емес: бір байт өзгерсе, барлық кейінгі хэштер өзгереді (Merkle ағашы идеясы).

EКөрнекі түсіндірме

A ← B ← C (main), B ← D ← E (feature), M - merge commit (C мен E). feature main-ге енген: E ∈ ancestors(M). C мен E-нің ортақ ата-бабалары A, B; merge base - B.

FҚадамдап қорыту

Анимациялық түсіндіру: қадамдар кезекпен ашылады. «Ойнату» не → пернесі.

  1. git init; файл; git add; git commit -m 'бастау' - commit A.
  2. git switch -c feature - жаңа көрсеткіш, сол A-ға.
  3. feature-де commit-тер: D, E. main-де: C. Енді тарихтар айырылды.
  4. git switch main; git merge feature - merge base B, екі жақтың өзгерістері біріктіріліп, M commit-і (ата-аналары C, E).

GЖұмыс мысалдары

HИнтерактивті эксперимент

Теорема бойынша: B ∈ ancestors(E) - fast-forward мүмкін; C ∉ ancestors(E) - тарихтар айырылған, merge commit керек. Модельге жаңа commit қосып (F: ['E']), feature-ді F-ке жылжытыңыз да, қайта тексеріңіз.

IЖаттығулар

JМатематикалық пайымдау

Git - Level I ұғымдарының тамаша жиынтығы: граф (m03, m09), көрсеткіштер (m11), хэш (m08 сөздіктері), өзгермейтіндік (m08 l02 - commit ешқашан өзгермейді, жаңасы жасалады). Оны «командалар тізімі» емес, деректер құрылымы ретінде түсінсеңіз, кез келген күрделі жағдайды (rebase, cherry-pick) өзіңіз түсіндіре аласыз.

KЖиі қателер

  • Үлкен, әртүрлі өзгерістерді бір commit-ке салу.
    Себебі: Қатені іздеу (git bisect, m09 l02) мен қайтару қиындайды.
    Түзету: Бір commit - бір логикалық өзгеріс, нақты хабарламамен.
  • Құпия кілттер мен парольдерді commit-ке қосу.
    Себебі: Тарих мәңгі сақталады - кейін өшіру жеткіліксіз.
    Түзету: .gitignore, орта айнымалылары; қате болса - кілтті ауыстыру.

LМеңгеруді бағалау

Барлық сұраққа дұрыс жауап берсеңіз, сабақ «меңгерілді» деп белгіленеді. Тексеру браузерде өтеді: бұл оқу тексерісі, емтихан емес.
