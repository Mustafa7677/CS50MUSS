    Django

    Осы кезге дейін біз тек қозғалмайтын беттер жасадық. Енді Python мен Django фреймворкінің көмегімен өзі өзгеретін, сұрауға қарай жауап беретін нағыз динамикалық веб-қосымша жазамыз: URL-дер, көріністер, шаблондар, формалар, CSRF және сессиялар.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)
    Бұл апта не туралы

    Өткен екі аптада HTML, CSS, Git және Python-ды үйрендік. Бүгін соның бәрін біріктіреміз: Python кодымыз HTML-ді «жазып» береді. Django кодын сайттың өзінде іске қосу мүмкін емес, өйткені ол сервер қажет етеді. Сондықтан Django мысалдарын өз компьютеріңізде қайталап көріңіз (pip3 install Django), ал бұл бетте HTTP сұрау-жауаптарын, шаблондардың нәтижесін және таза Python бөліктерін көре аласыз. Апта соңында ресми Project 1: Wiki жобасы мен бірнеше ұсақ жаттығу бар.

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен кодтың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Кіріспе

    Қысқаша еске түсірейік. Біз HTML мен CSS арқылы қарапайым веб-беттер жасауды үйрендік. Git пен GitHub көмегімен код өзгерістерін қадағалап, басқалармен бірге жұмыс істеуді білдік. Python тілімен де таныстық. Бүгін Python-ға сүйеніп, оның Django деген фреймворкімен динамикалық қосымшалар жасаймыз.

    Веб-қосымшалар

    Осы уақытқа дейін жазған барлық беттеріміз статикалық (static) болды. Бұл дегеніміз, бетті қашан ашсақ та, ол дәл бұрынғыдай көрінеді. Ал күнделікті кіретін сайттарды ойлаңызшы. New York Times не Facebook-ке бүгін кірсеңіз бір нәрсе көресіз, ертең кірсеңіз мүлде басқа нәрсе көресіз. Бейнелеп айтсақ, статикалық сайт - қабырғаға ілінген плакат, ал динамикалық сайт - күнде жаңарып тұратын электронды табло.

    Осындай үлкен сайттарда қызметкерлер әр өзгеріс болған сайын үлкен HTML файлын қолмен өңдеп отырады деп елестетуге бола ма? Әрине, жоқ. Міне, осы жерде динамикалық (dynamic) веб-сайттар көмекке келеді. Динамикалық сайт дегеніміз - бағдарламалау тілін (мысалы, Python) пайдаланып, HTML мен CSS файлдарын сол сәтте өзі жасап шығаратын сайт. Бүгінгі лекцияда алғашқы динамикалық қосымшаларымызды жасауды үйренеміз.

    HTTP

    Алдымен бір мәселені түсінейік: браузер мен сайт бір-бірімен қалай сөйлеседі? Әңгіме дұрыс жүру үшін екі жақ та бірдей «тілде» сөйлесуі керек. Ондай ортақ тіл бар, оны HTTP дейді. Ол HyperText Transfer Protocol дегеннің қысқартылған түрі, қазақша айтсақ, гипермәтінді жіберу хаттамасы (protocol). Хаттама дегенміз - екі жақ хабарламаны қандай форматта жіберуге келіскен ереже. Телефонмен сөйлескенде де алдымен «алло» деп амандасасыз ғой, бұл да соның сияқты.

    Интернеттегі ақпарат әдетте екі жақтың арасында алмасады: клиент (client), яғни сіз бен сіздің браузеріңіз, және сервер (server), яғни сайтты сақтап тұрған компьютер. Асхананы елестетіңіз: клиент - тапсырыс беретін қонақ, сервер - ас үй.

    Бұл хаттамада клиент серверге сұрау (request) жібереді. Ол шамамен мынадай көрінеді:

    GET / HTTP/1.1
Host: www.example.com
...

    Мұндағы GET - сұрау түрі (бұл курста біз үш түрімен танысамыз, қазір екеуін көреміз: GET және POST). / белгісі әдетте сайттың басты бетін сұрап тұрғанымызды білдіреді. Ал үш нүкте сұраудың ішінде басқа да ақпарат болуы мүмкін екенін көрсетеді.

    Сұрауды алған соң сервер HTTP жауабын (response) қайтарады. Ол шамамен былай болады:

    HTTP/1.1 200 OK
Content-Type: text/html
...

    Жауаптың ішінде HTTP нұсқасы, күй коды (status code; 200 дегеніміз «бәрі жақсы, OK»), мазмұнның сипаттамасы және тағы басқа қосымша ақпарат болады.

    200 - күй кодтарының тек біреуі. Кейбірін сіз бұрын-ақ көрген шығарсыз:

    КодМағынасы
    200 OKБәрі жақсы: сұрау орындалды
    301 Moved PermanentlyБет басқа мекенжайға біржола көшті
    403 ForbiddenБұл бетке кіруге рұқсатыңыз жоқ
    404 Not FoundСұралған бет табылмады
    500 Internal Server ErrorСерверде бірдеңе бұзылды (көбіне код қатесі)
    Ойланып көріңіз: Django-да өз қатеңіз болса, браузер қандай код алады?

    Көрініс (view) функциясындағы Python қатесі серверді құлатпайды, бірақ браузер 500 алады. Ал мекенжай жазылмаған болса - 404. Лекцияда екеуін де көреміз. Есіңізде болсын: 4xx кодтары әдетте клиенттің қатесі (қате мекенжай), 5xx кодтары сервердің қатесі.

    Django

    Django - Python негізіндегі веб-фреймворк (framework). Ол арқылы HTML мен CSS-ті динамикалық түрде жасайтын Python коды жаза аламыз. Фреймворктің басты артықшылығы мынау: көп код бізге дайын тұр, оны қайтадан жазудың қажеті жоқ. Үй салғанда кірпішті өзіміз күйдірмейтініміз сияқты.

    Бастау үшін Django-ны орнату керек. Ол үшін pip болуы тиіс (орнату нұсқаулығы). Pip болған соң терминалға мынаны жазамыз:

    $ pip3 install Django

    Django орнаған соң жаңа жоба (project) жасау қадамдарынан өтеміз:

    1. Терминалда django-admin startproject PROJECT_NAME командасын жазамыз. Ол жобаның бастапқы файлдарын жасап береді.
    2. cd PROJECT_NAME деп жаңа жоба қалтасына кіреміз.
    3. Қалтаны өзіңіз ұнататын редакторда ашамыз. Бірнеше файл дайын тұрғанын көресіз. Көбіне қазір оларға қарамаймыз, бірақ үшеуі басынан бастап маңызды:
      • manage.py - терминалдан команда орындау үшін қолданамыз. Оны өзгертпейміз, бірақ жиі шақырамыз.
      • settings.py - жобаның маңызды баптаулары. Әдепкі мәндері бар, бірақ уақыты келгенде кейбірін өзгертеміз.
      • urls.py - пайдаланушы белгілі бір URL-ге барғанда оны қайда бағыттау керегін көрсететін нұсқаулар.
    4. Жобаны python manage.py runserver командасымен іске қосамыз. Бұл әзірлеу сервері (development server) ашады, терминалда көрсетілген URL арқылы кіре аласыз. Сервер сіздің компьютеріңізде ғана жұмыс істейді, яғни басқа адамдар сіздің сайтыңызды көре алмайды. Алдымен Django-ның әдепкі «қош келдіңіз» беті шығады.
    5. Келесі қадам - қосымша (application) жасау. Django жобасы бір не бірнеше қосымшаға бөлінеді. Біздің жобалардың көбіне бір қосымша жеткілікті, ал үлкен сайттар сайтты бірнеше қосымшаға бөле алады. Қосымша жасау үшін: python manage.py startapp APP_NAME. Ол қосымша қалталар мен файлдар жасайды, олардың ішінде жақында керек болатын views.py бар.
    6. Жаңа қосымшаны жобаға орнату керек. settings.py ашып, INSTALLED_APPS тізіміне дейін төмен түсіп, қосымшамыздың атын сол тізімге қосамыз.
    INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'hello',
]

    Жоба мен қосымшаны жасайтын командалар мынадай:

    $ django-admin startproject myproject
$ cd myproject
$ python manage.py startapp hello

    Маршруттар

    Енді қосымшамызды тірілтейік. Алдымен views.py файлына барамыз. Онда бірнеше көрініс (view) болады. Көріністі әзірге «пайдаланушы көргісі келетін бір бет» деп түсінсек болады. Алғашқы көрінісімізді жазу үшін request қабылдайтын функция жазамыз. Әзірге ол жай HttpResponse қайтарсын. HttpResponse - өте қарапайым жауап: күй коды 200 және браузерде көрсетілетін мәтін жолы. Ол үшін from django.http import HttpResponse импорттау керек. Файл былай болады:

    from django.shortcuts import render
from django.http import HttpResponse

# Create your views here.

def index(request):
    return HttpResponse("Hello, world!")

    Енді осы көрініс белгілі бір URL-ге байланысуы керек. Ол үшін views.py жатқан қалтада тағы бір urls.py файлын жасаймыз. Бүкіл жобаның urls.py файлы бар екені рас, бірақ әр қосымшаға өз файлын жасаған дұрыс: бір үлкен қоймаға бәрін тықпай, әр бөлімге өз сөресін береміз.

    Жаңа urls.py ішінде пайдаланушы кіре алатын URL-дердің тізімін жасаймыз:

    1. Алдымен екі импорт жасаймыз: from django.urls import path (URL-дерді бағыттау мүмкіндігін береді) және from . import views (views.py ішіндегі функцияларды әкеледі).
    2. urlpatterns деген тізім жасаймыз.
    3. Қалаған әр URL үшін тізімге path функциясын шақыратын элемент қосамыз. Оның екі не үш аргументі болады: URL жолын білдіретін жол, сол URL-ге кірілгенде шақырылатын views.py функциясы және қосымша, яғни жолдың аты: name="something" түрінде.

    Біздің қарапайым қосымша қазір былай көрінеді:

    from django.urls import path
from . import views

urlpatterns = [
    path("", views.index, name="index")
]

    Қосымшаға арналған urls.py дайын. Енді бүкіл жобаға арналған urls.py файлын өзгертеміз. Онда admin деген жол бұрыннан бар, оған кейінгі лекцияларда оралады. Біз жаңа қосымша үшін тағы бір жол қосамыз. Бұл жолы екінші аргумент ретінде views.py функциясын емес, қосымшамыздың urls.py файлындағы барлық жолдарды қосып жіберетін нәрсені береміз. Ол үшін include("APP_NAME.urls") деп жазамыз. include функциясын да django.urls модулінен импорттау керек:

    from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('hello/', include("hello.urls"))
]

    Осылайша, пайдаланушы біздің сайтқа кіріп, мекенжай жолағына /hello қосқанда, ол жаңа қосымшамыздың ішіндегі жолдарға бағытталады.

    Енді python manage.py runserver арқылы қосымшаны іске қосып, берілген URL-ге кірсем, мынадай 404 бетін көремін. Неге? Себебі біз тек localhost:8000/hello URL-ін анықтадық, ал соңына ештеңе қосылмаған localhost:8000 үшін ештеңе жазған жоқпыз. Ал мекенжай жолағына /hello қоссам, «Hello, world!» жазуын көремін. Жетістікке жеттік! Енді не болып жатқанын қадам-қадаммен талдайық:

    1. localhost:8000/hello/ мекенжайына кіргенде Django базалық URL-ден (localhost:8000/) кейін не тұрғанына қарайды. Ол жобаның urls.py файлына барып, hello жолына сәйкес келетін үлгіні іздейді.
    2. Ол үлгіні табады, өйткені біз оны анықтап қойғанбыз. Сол жол кездескенде қосымшамыздың urls.py файлын include ету керектігін көреді.
    3. Содан кейін Django URL-дің қайта бағыттауға қолданылып қойған бөлігін (бұл жағдайда localhost:8000/hello/, яғни бәрін) тастап, қалған бөлігіне сәйкес келетін үлгіні екінші urls.py ішінен іздейді.
    4. Біздің жалғыз жолымыз ("") қалған бөлікке сәйкес келеді, сондықтан Django бізді сол жолға байланған views.py функциясына жібереді.
    5. Соңында Django views.py ішіндегі функцияны орындап, нәтижесін (HttpResponse("Hello, world!")) браузерімізге қайтарады.
    Ойланып көріңіз: path('hello/', ...) деп жазсақ, неге ішкі urls.py ішінде "hello/" қайталамаймыз?

    Себебі Django жоба деңгейінде hello/ бөлігін «жеп қойып», қалған бөлігін ғана қосымшаға береді. Қосымшаның ішіндегі path("", ...) дегеніміз «hello/-дан кейін ештеңе жоқ» дегенді білдіреді. Сондықтан қосымшаның urls.py файлы өз префиксін білмейді, оны кейін басқа жерге оңай көшіре аламыз.

    Қаласақ, views.py ішіндегі index функциясын кез келген нәрсе қайтаратындай етіп өзгерте аламыз. Функцияның ішінде айнымалыларды сақтап, есептеулер жасап, содан кейін ғана нәтижені қайтаруға да болады.

    Бірнеше көрініс

    Енді қосымшамызға бір емес, бірнеше көрініс қосып көрейік. Брайанға да, Дэвидке де сәлем айтатын беттер жасаймыз. Алдыңғы қадамдарды қайталаймыз.

    views.py ішінде:

    from django.shortcuts import render
from django.http import HttpResponse

# Create your views here.

def index(request):
    return HttpResponse("Hello, world!")

def brian(request):
    return HttpResponse("Hello, Brian!")

def david(request):
    return HttpResponse("Hello, David!")

    Қосымшаның urls.py ішінде:

    from django.urls import path
from . import views

urlpatterns = [
    path("", views.index, name="index"),
    path("brian", views.brian, name="brian"),
    path("david", views.david, name="david")
]

    Енді localhost:8000/hello бұрынғыдай «Hello, world!» көрсетеді, ал соңына brian не david қоссақ, басқа беттер ашылады: «Hello, Brian!» және «Hello, David!».

    URL-дегі параметрлер

    Көп сайттың беті URL-ге жазылған нәрсеге байланысты өзгереді. Мысалы, twitter.com/cs50 CS50-нің барлық жазбаларын көрсетеді, ал github.com/cs50 CS50-нің GitHub бетіне апарады. Өз ашық репозиторийлеріңізді де github.com/СІЗДІҢ_АТЫҢЫЗ арқылы таба аласыз.

    Ойланып қарасақ, GitHub пен Twitter-де әр пайдаланушыға арнап бөлек URL жолын қолмен жазбаған болар. Сондықтан біз де анағұрлым икемді жол жасауды үйренейік. Алдымен views.py ішіне жалпы greet функциясын қосамыз:

    def greet(request, name):
    return HttpResponse(f"Hello, {name}!")

    Бұл функция request ғана емес, пайдаланушының атын білдіретін қосымша аргумент та қабылдайды да, сол атқа байланысты жауап қайтарады. Енді urls.py ішінде икемді жол жасаймыз:

    path("<str:name>", views.greet, name="greet")

    Синтаксис жаңа көрінеді, бірақ мағынасы қарапайым: енді URL-де нақты сөз немесе ат іздемейміз, пайдаланушы жазатын кез келген жолды (str) қабылдаймыз да, оны name деген атпен көріністің аргументі ретінде береміз. Енді /hello/harry не /hello/connor деп көріңіз: сайт жұмыс істейді.

    Мұны сәл әдемілеуге болады: greet функциясына Python-ның бас әріпке түрлендіретін capitalize функциясын қосамыз:

    def greet(request, name):
    return HttpResponse(f"Hello, {name.capitalize()}!")

    Енді «harry» деп жазсақ та, жауап «Hello, Harry!» болады. Бұл Python-да істей алатын кез келген нәрсені Django-да нәтижені қайтармай тұрып қолдана алатынымызды көрсетеді. Мысалы, дәл осы өрнекті мына жерде өзіңіз де сынап көре аласыз (бұл таза Python):

    name = "harry"
print(f"Hello, {name.capitalize()}!")
    Ойланып көріңіз: URL-дер тізімінде path("brian", ...) пен path("<str:name>", ...) қатар тұрса, /hello/brian қайсысына түседі?

    Django жолдарды жоғарыдан төмен тексереді де, бірінші сәйкес келгенін алады. brian жолы жоғары тұрса, ол жеңеді. Ал <str:name> бірінші тұрса, ол «brian» сөзін де «кез келген жол» ретінде ұстап алар еді. Сондықтан нақты жолдарды жалпыларынан бұрын жазады. Төмендегі жаттығуда осы мінезді өзіңіз кодтап көресіз.

    Шаблондар

    Осы уақытқа дейінгі HTTP жауаптарымыздың бәрі жай мәтін еді. Бірақ оған кез келген HTML элементтерін де қоса аламыз! Мысалы, index функциясы жай мәтіннің орнына көк тақырып қайтарсын:

    def index(request):
    return HttpResponse("<h1 style=\"color:blue\">Hello, world!</h1>")

    Браузер мұны нағыз HTML ретінде түсініп, көк «Hello, world!» тақырыбын көрсетеді. Мынау сол жауаптың нәтижесі:

    <h1 style="color:blue">Hello, world!</h1>

    Бірақ бүкіл HTML бетін views.py ішінде жол ретінде жазу өте жалықтырарлық болар еді. Және бұл жаман дизайн: жобаның әр бөлігін мүмкіндігінше бөлек файлдарда ұстағанымыз жөн. Міне, сондықтан Django шаблондарымен (templates) таныс боламыз: олар HTML мен CSS-ті бөлек файлдарда жазып, Django арқылы көрсетуге мүмкіндік береді. Шаблонды көрсетудің синтаксисі мынадай:

    def index(request):
    return render(request, "hello/index.html")

    Енді шаблонның өзін жасау керек. Қосымшамыздың ішінде templates деген қалта, оның ішінде hello (немесе қосымшаңыздың аты) деген қалта, ал соның ішінде index.html файлы тұруы керек:

    hello/
    templates/
        hello/
            index.html
    Ойланып көріңіз: неге hello деген қалта екі рет қайталанады?

    Django барлық қосымшалардың templates қалталарын бір жерге жинап қарайды. Екі қосымшада да index.html болса, Django қайсысын алу керегін шатастырып алуы мүмкін. Ішкі қалта қосымшаның атымен аталып, шаблондарды «аты бар» етеді: hello/index.html мен newyear/index.html бір-біріне кедергі келтірмейді.

    Жаңа файлға қалаған HTML-ді жазамыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Hello</title>
    </head>
    <body>
        <h1>Hello, World!</h1>
    </body>
</html>

    Енді қосымшамыздың басты бетіне кірсек, тақырып пен беттің атауы жаңарғанын көреміз.

    Статикалық HTML беттерін жазумен қатар, Django шаблон тілін пайдаланып, HTML файлдарының мазмұнын кірген URL-ге қарай өзгерте аламыз. Жоғарыдағы greet функциясын өзгертіп көрейік:

    def greet(request, name):
    return render(request, "hello/greet.html", {
        "name": name.capitalize()
    })

    Назар аударыңыз: render функциясына үшінші аргумент берілді. Оны контекст (context) дейді. Контекстке HTML файлдарының ішінде қолжетімді болуын қалайтын ақпаратты саламыз. Контекст Python сөздігі (dictionary) түрінде беріледі. Енді greet.html файлын жасаймыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Hello</title>
    </head>
    <body>
        <h1>Hello, {{ name }}!</h1>
    </body>
</html>

    Жаңа синтаксисті байқадыңыз: қос бұйра жақша. Ол context аргументінде берген айнымалыларымызды HTML ішінде қолдануға мүмкіндік береді. Енді /hello/harry не /hello/connor бетіне кірсек, тақырыпта сәйкес ат шығады. Қос жақшаның шаблонды толтыруын мына үлгі арқылы елестетіңіз: Django {{ name }} орнына «Harry» мәнін қояды да, дайын HTML-ді браузерге жібереді:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Hello</title>
    </head>
    <body>
        <h1>Hello, Harry!</h1>
    </body>
</html>

    Біз HTML шаблондарын берген контекстімізге қарай өзгерте алатынымызды көрдік. Бірақ Django шаблон тілі бұдан да қуатты. Тағы бірнеше мүмкіндігін қарастырайық.

    Шарттар

    Кейде сайттың мазмұны белгілі бір шартқа байланысты өзгергенін қалаймыз. Мысалы, isitchristmas.com сайтына кірсеңіз, көбіне «NO» деген бет көресіз. Бірақ Рождество күні сайт «YES» деп жауап береді. Осыған ұқсас бірдеңе жасайық: бүгін Жаңа жыл ма, жоқ па, соны тексеретін қосымша. Қосымшаны қалай жасайтынымызды еске түсіріп, жаңа қосымша жасаймыз:

    1. Терминалда python manage.py startapp newyear орындаймыз.
    2. settings.py ішіндегі INSTALLED_APPS тізіміне «newyear» қосамыз.
    3. Жобаның urls.py файлына hello қосымшасындағыдай жол қосамыз:
    path('newyear/', include("newyear.urls"))
    1. Жаңа қосымша қалтасында тағы бір urls.py жасап, оған hello ішіндегі index жолына ұқсас жол қосамыз:
    from django.urls import path
from . import views

urlpatterns = [
    path("", views.index, name="index"),
]
    1. views.py ішінде index функциясын жасаймыз.

    Жаңа қосымшамыз дайын. Енді бүгін Жаңа жыл ма, соны қалай білеміз? Ол үшін Python-ның datetime модулін импорттаймыз. Модуль қалай жұмыс істейтінін түсіну үшін құжаттаманы қарап, Django-дан тыс Python интерпретаторында сынап көруге болады.

    Python интерпретаторы (Python interpreter) - шағын Python кодтарын сынау құралы. Іске қосу үшін терминалға python деп жазамыз, содан кейін Python кодын тікелей терминалға теріп, бірден орындай аламыз. Аяқтағанда exit() деп шығамыз.

    $ python
>>> import datetime
>>> now = datetime.datetime.now()
>>> now.day
9
>>> now.month
10
>>> exit()

    (Сандар сіздің бүгінгі күніңізге байланысты болады.) Осы біліммен бүгін дәл Жаңа жыл екенін ғана ақиқат (True) етіп бағалайтын логикалық өрнек жаза аламыз: now.day == 1 and now.month == 1. Мұны мына жерде жүргізіп көріңіз (бұл таза Python):

    import datetime

now = datetime.datetime.now()
print(now.month == 1 and now.day == 1)

    Бүгін Жаңа жыл екенін тексеретін өрнегіміз бар, енді views.py ішіндегі index функциясын жаңартамыз:

    def index(request):
    now = datetime.datetime.now()
    return render(request, "newyear/index.html", {
        "newyear": now.month == 1 and now.day == 1
    })

    (Файлдың басында import datetime болуын ұмытпаңыз.) Енді index.html шаблонын жасаймыз. Тағы да templates қалтасын, оның ішінде newyear қалтасын, ал соның ішінде index.html файлын жасаймыз. Файлдың мазмұны шамамен мынадай:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Is it New Year's?</title>
    </head>
    <body>
        {% if newyear %}
            <h1>YES</h1>
        {% else %}
            <h1>NO</h1>
        {% endif %}
    </body>
</html>

    Назар аударыңыз: HTML файлдарына логика қосқымыз келсе, логикалық операторды {% және %} белгілерімен қоршаймыз. Және Django шаблон тілі if-else блогы аяқталғанын көрсететін жабушы тегті ({% endif %}) міндетті түрде талап етеді. Енді бетті ашсақ, «NO» шығады.

    Сахна артында не болып жатқанын жақсырақ түсіну үшін бетті «Inspect element» арқылы тексеріп көрейік. Браузерге жіберілген HTML-де тек NO тақырыбы бар екенін көреміз. Яғни Django біз жазған HTML шаблонын алып, одан жаңа HTML файлын жасап, соны браузерге жіберді. Шарттың қолданылмаған тармағы браузерге ешқашан жетпейді. Мынау браузер алатын нақты нәтиже:

    <!-- Бүгін Жаңа жыл емес: браузер дәл осыны алады -->
<!DOCTYPE html>
<html lang="en">
    <head>
        <title>Is it New Year's?</title>
    </head>
    <body>
        <h1>NO</h1>
    </body>
</html>

    Енді «алдап көрейік»: шартты әрдайым ақиқат етіп қойсақ, керісінше тармақ шығады:

    def index(request):
    now = datetime.datetime.now()
    return render(request, "newyear/index.html", {
        "newyear": True
    })

    Бұл жолы бет «YES» көрсетеді де, «Inspect element» ішінде енді тек YES тақырыбы тұрғанын көреміз.

    Ойланып көріңіз: браузерге {% if %} тегі жете ме?

    Жоқ. Шаблонды Django серверде өңдейді, сондықтан браузер дайын HTML ғана алады, оның ішінде {% if %} да, {{ name }} да болмайды. Бұл динамикалық сайттың мәні: сервер бетті сол сәтте құрастырып береді.

    Стильдер

    CSS файлын қосқымыз келсе, оны статикалық (static) файл деп атаймыз, өйткені ол өзгермейді. Алдымен қосымшаның ішінде static деген қалта, соның ішінде newyear қалтасы, ал оның ішінде styles.css файлын жасаймыз:

    newyear/
    static/
        newyear/
            styles.css
    templates/
        newyear/
            index.html

    Бұл файлға бірінші лекциядағыдай кез келген стильді жаза аламыз:

    h1 {
    font-family: sans-serif;
    font-size: 90px;
    text-align: center;
}

    Бұл стильді HTML файлымызға қосу үшін шаблонның басына {% load static %} жолын қоямыз. Ол Django-ға «static қалтасындағы файлдарға қол жеткізгім келеді» деп хабарлайды. Сосын стиль кестесіне сілтемені бұрынғыдай қолмен жазбай, Django-ға тән синтаксиспен береміз:

    {% load static %}
<!DOCTYPE html>
<html lang="en">
    <head>
        <title>Is it New Year's?</title>
        <link rel="stylesheet" href="{% static 'newyear/styles.css' %}">
    </head>
    <body>
        {% if newyear %}
            <h1>YES</h1>
        {% else %}
            <h1>NO</h1>
        {% endif %}
    </body>
</html>

    Серверді қайта іске қоссақ, стиль өзгерістері қолданылғанын көреміз: «NO» енді үлкен әрі ортада тұр.

    <style>
h1 { font-family: sans-serif; font-size: 90px; text-align: center; }
</style>
<h1>NO</h1>
    Серверді қайта қосу

    Жаңа статикалық файл қосқанда әзірлеу серверін тоқтатып (Ctrl+C), қайта іске қосу (python manage.py runserver) керек болуы мүмкін. Лекцияда да дәл солай жасалды.

    Тапсырмалар тізімі

    Үйренгенімізді шағын жобаға қолданайық: істер тізімін (TODO list) жасаймыз. Тағы да жаңа қосымшадан бастаймыз:

    1. Терминалда python manage.py startapp tasks орындаймыз.
    2. settings.py ішіндегі INSTALLED_APPS тізіміне «tasks» қосамыз.
    3. Жобаның urls.py файлына hello қосымшасындағыдай жол қосамыз:
    path('tasks/', include("tasks.urls"))
    1. Қосымша қалтасында urls.py жасап, hello ішіндегі index жолына ұқсас жол қосамыз:
    from django.urls import path
from . import views

urlpatterns = [
    path("", views.index, name="index"),
]
    1. views.py ішінде index функциясын жасаймыз.

    Алдымен тапсырмалар тізімін жасап, оны бетке шығарып көрейік. views.py файлының жоғарғы жағында Python тізімін жасап, тапсырмаларды сонда сақтаймыз. Сосын index функциясы шаблонды көрсетіп, жаңа тізімімізді контекст ретінде берсін:

    from django.shortcuts import render

tasks = ["foo", "bar", "baz"]

# Create your views here.
def index(request):
    return render(request, "tasks/index.html", {
        "tasks": tasks
    })

    Енді HTML шаблонын жасаймыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Tasks</title>
    </head>
    <body>
        <ul>
            {% for task in tasks %}
                <li>{{ task }}</li>
            {% endfor %}
        </ul>
    </body>
</html>

    Тапсырмаларымызды цикл арқылы аралап шығып отырмыз. Синтаксис алдыңғы шарттарға, сондай-ақ екінші лекциядағы Python циклына ұқсас, тек жабушы {% endfor %} тегі қосылады. Тапсырмалар бетіне кірсек, тізім шығады. Django әр тапсырма үшін бір <li> жасап, мынадай HTML жібереді:

    <ul>
    <li>foo</li>
    <li>bar</li>
    <li>baz</li>
</ul>

    Формалар

    Қазір барлық тапсырмаларды тізім ретінде көре аламыз. Енді жаңа тапсырма қосқымыз келеді. Ол үшін веб-бетті жаңартуға арналған формаларды (forms) қолданамыз. views.py ішіне форма бар бетті көрсететін тағы бір функция қосамыз:

    # Add a new task:
def add(request):
    return render(request, "tasks/add.html")

    urls.py файлына да жаңа жол қосуды ұмытпаймыз:

    path("add", views.add, name="add")

    Енді add.html файлын жасаймыз. Ол index.html-ге өте ұқсас, тек денесінде тізім емес, форма болады:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Tasks</title>
    </head>
    <body>
        <h1>Add Task:</h1>
        <form action="">
            <input type="text" name="task">
            <input type="submit">
        </form>
    </body>
</html>

    Шаблон мұрагерлігі

    Бірақ жазғанымыз ең жақсы дизайн емес: HTML-дің негізгі бөлігін екі файлда қайталап тұрмыз. Django шаблон тілінде бұл жаман дизайнды жоятын құрал бар: шаблон мұрагерлігі (template inheritance). Ол беттің жалпы құрылымы бар layout.html файлын жасауға мүмкіндік береді:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Tasks</title>
    </head>
    <body>
        {% block body %}
        {% endblock %}
    </body>
</html>

    Тағы да {%...%} қолданып тұрмыз: бұл HTML емес, қандай да бір логиканы білдіреді. Мұнда Django-ға «бұл блокты басқа файлдағы мәтінмен толтыр» деп айтып тұрмыз. Енді қалған екі HTML файлымызды былай өзгертеміз.

    index.html:

    {% extends "tasks/layout.html" %}

{% block body %}
    <h1>Tasks:</h1>
    <ul>
        {% for task in tasks %}
            <li>{{ task }}</li>
        {% endfor %}
    </ul>
{% endblock %}

    add.html:

    {% extends "tasks/layout.html" %}

{% block body %}
    <h1>Add Task:</h1>
    <form action="">
        <input type="text" name="task">
        <input type="submit">
    </form>
{% endblock %}

    Көріп отырсыз, layout файлын кеңейту (extends) арқылы қайталанатын кодтың көбінен құтылдық. Басты бет бұрынғыдай, ал енді «add» беті де бар. Формаға көз салайық:

    <h1>Add Task:</h1>
<form action="">
    <input type="text" name="task">
    <input type="submit">
</form>

    Беттер арасындағы сілтемелер

    Жаңа тапсырма қосқымыз келген сайын URL-ге қолмен «/add» жазу ыңғайсыз. Сондықтан беттерді бір-бірімен сілтемелеген дұрыс. Бірақ сілтемені қолмен жазбай, urls.py ішінде әр жолға берген name айнымалысын қолдана аламыз:

    <a href="{% url 'add' %}">Add a New Task</a>

    Мұндағы «add» - сол жолдың аты. add.html ішінде де осылай істей аламыз:

    <a href="{% url 'index' %}">View Tasks</a>

    Бірақ мұнда мәселе туындауы мүмкін: әртүрлі қосымшаларда index деп аталатын бірнеше жол бар. Мұны әр қосымшаның urls.py файлына app_name айнымалысын қосып шешеміз. Файл мынадай болады:

    from django.urls import path
from . import views

app_name = "tasks"
urlpatterns = [
    path("", views.index, name="index"),
    path("add", views.add, name="add")
]

    Енді сілтемелерде жай index мен add емес, tasks:index және tasks:add деп жазамыз:

    <a href="{% url 'tasks:index' %}">View Tasks</a>

<a href="{% url 'tasks:add' %}">Add a New Task</a>

    POST және CSRF

    Енді форма пайдаланушы жібергенде шынымен бірдеңе істейтінін қамтамасыз етейік. Ол үшін add.html ішіндегі формаға action қосамыз:

    <form action="{% url 'tasks:add' %}" method="post">

    Бұл форма жіберілгенде бізді қайтадан add URL-іне бағыттайды деген сөз. Мұнда get емес, post әдісін қолданатынымызды көрсеттік. Форма веб-беттің күйін өзгерте алатын болса, әдетте post қолданылады. Ал get тек деректерді сұрау үшін.

    Бірақ формаға тағы бір нәрсе қосу керек, себебі Django CSRF (Cross-Site Request Forgery, «сайт аралық сұрауды қолдан жасау») шабуылынан қорғау үшін арнайы белгі талап етеді. Бұл шабуылда зиянды адам сіздің серверіңізге сіздің сайтыңыздан емес, басқа жерден сұрау жіберуге тырысады. Кейбір сайттар үшін бұл өте үлкен қауіп. Банк сайтында бір пайдаланушыдан екіншісіне ақша аударатын форма бар делік. Біреу банк сайтынан тыс жерден аударым жібере алса, бұл апат болар еді ғой!

    Мұны шешу үшін Django шаблонды көрсетіп жауап жібергенде CSRF токенін (CSRF token) де береді. Ол сайттағы әр жаңа сессияға бірегей. Сұрау жіберілгенде Django сұрауға тіркелген токен жуырда өзі берген токенмен сәйкес келетінін тексереді. Сондықтан басқа сайттағы зиянды адам сұрау жіберуге тырысса, CSRF токені жарамсыз болғандықтан, оның сұрауы бұғатталады. Бұл тексеру Django ортаңғы қабатына (middleware) кірістірілген: ол Django қосымшасының сұрау-жауап өңдеуіне араласа алатын тетік. Бұл курста ортаңғы қабатқа тереңдемейміз, қызықсаңыз құжаттаманы оқыңыз.

    Мұны кодқа қосу үшін add.html ішіндегі формаға бір жол қосамыз:

    <form action="{% url 'tasks:add' %}" method="post">
    {% csrf_token %}
    <input type="text" name="task">
    <input type="submit">
</form>

    Бұл жол CSRF токені бар жасырын енгізу өрісін қосады, сондықтан бетті қайта жүктегенде ештеңе өзгермегендей көрінеді. Бірақ «Inspect element» арқылы қарасақ, жаңа енгізу өрісі қосылғанын байқаймыз:

    <input type="hidden" name="csrfmiddlewaretoken" value="...">
    Ойланып көріңіз: {% csrf_token %} жоқ формамен POST жіберсек не болады?

    Django сұрауды қабылдамайды және 403 Forbidden жауабын қайтарады (CSRF тексеруі өтпеді). Бұл қателік емес, қорғаныс жұмыс істеп тұрғанының белгісі.

    Django формалары

    Біз HTML-ді қолмен жазып форма жасай алатынымызды көрдік, бірақ Django пайдаланушыдан ақпарат жинаудың одан да оңай жолын ұсынады: Django формалары. Ол үшін views.py басына forms модулін импорттаймыз:

    from django import forms

    Енді views.py ішінде NewTaskForm деген Python класын жасап, жаңа форма анықтаймыз:

    class NewTaskForm(forms.Form):
    task = forms.CharField(label="New Task")

    Бұл класта не болып жатқанын талдайық:

    • NewTaskForm жақшасында forms.Form тұр. Себебі біздің жаңа форма forms модулінде бар Form деген класстан мұра алады (inherits). Мұрагерлікті біз Django шаблон тілінде көрдік. Бұл да сондай: жалпы сипаттамадан (forms.Form) өзімізге керегін (жаңа форма) нақтылаймыз. Мұрагерлік объектіге бағытталған бағдарламалаудың негізгі бөлігі, бірақ бұл курста оған тереңдемейміз, онлайн материал көп.
    • Класс ішінде пайдаланушыдан қандай ақпарат алғымыз келетінін көрсетеміз, бұл жағдайда тапсырма атауын.
    • forms.CharField арқылы бұл мәтіндік енгізу екенін көрсетеміз. Django форма модулінде басқа да көп өріс түрлері бар.
    • CharField ішінде бет жүктелгенде пайдаланушыға көрінетін label (белгі) беруге болады. Бұл форма өрісіне берілетін көптеген аргументтің біреуі ғана.

    NewTaskForm класын жасадық, енді оны add бетін көрсеткенде контекстке қосамыз:

    # Add a new task:
def add(request):
    return render(request, "tasks/add.html", {
        "form": NewTaskForm()
    })

    Енді add.html ішіндегі енгізу өрісін жаңа форманың өзімен ауыстыра аламыз:

    {% extends "tasks/layout.html" %}

{% block body %}
    <h1>Add Task:</h1>
    <form action="{% url 'tasks:add' %}" method="post">
        {% csrf_token %}
        {{ form }}
        <input type="submit">
    </form>
    <a href="{% url 'tasks:index' %}">View Tasks</a>
{% endblock %}

    forms модулін қолданудың HTML формасын қолмен жазудан бірнеше артықшылығы бар:

    • Формаға жаңа өріс қосқымыз келсе, HTML жазбай-ақ views.py ішінде қоса саламыз.
    • Django автоматты түрде клиенттік тексеруді (client-side validation) жасайды, яғни пайдаланушы компьютерінде орындалатын тексеру: форма толық емес болса, жіберуге рұқсат бермейді.
    • Django қарапайым серверлік тексеруді (server-side validation) де ұсынады: бұл форма деректері серверге жеткен соң жасалады.
    • Келесі лекцияда деректерді сақтау үшін модельдерді қолдана бастаймыз, ал Django модельге негізделген форманы өте оңай жасайды.

    POST сұрауын өңдеу

    Форма дайын, енді пайдаланушы жіберу батырмасын басқанда не болатынын жазайық. Пайдаланушы сілтемені басып не URL-ді жазып add бетіне кіргенде серверге GET сұрауын жібереді, оны add функциясы бұрыннан өңдейді. Ал форманы жібергенде серверге POST сұрауы барады, оны қазір add өңдемейді. POST әдісін функцияға берілген request аргументіне негізделген шартпен өңдей аламыз. Төмендегі код ішіндегі комментарийлер әр жолдың мақсатын түсіндіреді:

    # Add a new task:
def add(request):

    # Check if method is POST
    if request.method == "POST":

        # Take in the data the user submitted and save it as form
        form = NewTaskForm(request.POST)

        # Check if form data is valid (server-side)
        if form.is_valid():

            # Isolate the task from the 'cleaned' version of form data
            task = form.cleaned_data["task"]

            # Add the new task to our list of tasks
            tasks.append(task)

            # Redirect user to list of tasks
            return HttpResponseRedirect(reverse("tasks:index"))

        else:

            # If the form is invalid, re-render the page with existing information.
            return render(request, "tasks/add.html", {
                "form": form
            })

    return render(request, "tasks/add.html", {
        "form": NewTaskForm()
    })

    Ескерту: сәтті жібергеннен кейін пайдаланушыны қайта бағыттау (redirect) үшін тағы екі импорт қажет:

    from django.urls import reverse
from django.http import HttpResponseRedirect

    Кодты баяу оқып шығайық. Егер сұрау POST болса, пайдаланушы жіберген деректерді NewTaskForm(request.POST) ішіне саламыз. Содан кейін form.is_valid() арқылы серверлік тексеру жасаймыз. Жарамды болса, «тазартылған» деректерден (cleaned_data) тапсырманы алып, тізімге қосамыз да, reverse("tasks:index") арқылы тізім бетіне қайта бағыттаймыз (reverse жол атынан нақты URL-ді тауып береді, {% url %} сияқты). Жарамсыз болса, бетті қайта көрсетеміз, бірақ бұл жолы бос форманың орнына пайдаланушы толтырған формамен, сонда ол қателерін көріп түзете алады. Ал GET болса, бос форма көрсетеміз.

    Ойланып көріңіз: неге сәтті жібергеннен кейін бетті қайта көрсетпей, HttpResponseRedirect қолданамыз?

    Қайта бағыттау браузерді тізім бетіне жаңа GET сұрауымен жібереді. Егер жай render жасасақ, пайдаланушы бетті жаңартқанда браузер ескі POST сұрауын қайта жіберіп, тапсырма екі рет қосылар еді. Ал тізімге жіберу пайдаланушыға жаңа тапсырма тізімде тұрғанын бірден көрсетеді.

    Сессиялар

    Осы жерге дейін біз тізімге тапсырма қосатын қосымша жасадық. Бірақ тапсырмаларды жаһандық айнымалыда сақтап тұрғанымыз мәселе болуы мүмкін: сайтқа кірген барлық адам дәл бірдей тізімді көреді. Асханадағы ортақ тақтаға жазып қойғандай: біреу жазса, бәрі көреді. Мұны шешу үшін сессиялар (sessions) деген құралды қолданамыз.

    Сессия - сайтқа әр жаңа кіру үшін серверде бірегей деректерді сақтау тәсілі. Әр пайдаланушының өз «сөмкесі» бар сияқты.

    Қосымшамызда сессияларды қолдану үшін алдымен жаһандық tasks айнымалысын өшіреміз, сосын index функциясын өзгертеміз, ал tasks айнымалысы қолданылған басқа жердің бәрінде оны request.session["tasks"] деп ауыстырамыз:

    def index(request):

    # Check if there already exists a "tasks" key in our session

    if "tasks" not in request.session:

        # If not, create a new list
        request.session["tasks"] = []

    return render(request, "tasks/index.html", {
        "tasks": request.session["tasks"]
    })

# Add a new task:
def add(request):
    if request.method == "POST":

        # Take in the data the user submitted and save it as form
        form = NewTaskForm(request.POST)

        # Check if form data is valid (server-side)
        if form.is_valid():

            # Isolate the task from the 'cleaned' version of form data
            task = form.cleaned_data["task"]

            # Add the new task to our list of tasks
            request.session["tasks"] += [task]

            # Redirect user to list of tasks
            return HttpResponseRedirect(reverse("tasks:index"))
        else:

            # If the form is invalid, re-render the page with existing information.
            return render(request, "tasks/add.html", {
                "form": form
            })

    return render(request, "tasks/add.html", {
        "form": NewTaskForm()
    })

    Ақырында, Django бұл деректі сақтай алуы үшін терминалда python manage.py migrate орындау керек. Миграция (migration) деген не екенін келесі аптада толығырақ айтамыз, әзірге бұл команда сессияларды сақтауға мүмкіндік беретінін білсеңіз жеткілікті.

    $ python manage.py migrate
    Ойланып көріңіз: екі түрлі браузерде тізім бірдей бола ма?

    Жоқ. Әр браузер өз сессиясын алады, сондықтан біреуіне қосқан тапсырма екіншісінде көрінбейді. Жаһандық tasks болса, екеуі де бірдей тізімді көрер еді.

    Бүгінгі лекция осымен біткен. Келесі жолы Django арқылы деректерді сақтау, оқу және өңдеуді үйренеміз.

    Қорытынды

    • Статикалық сайт әрдайым бірдей, динамикалық сайт кодпен HTML жасап береді.
    • HTTP: клиент сұрау (GET, POST) жібереді, сервер күй коды бар жауап қайтарады (200, 301, 403, 404, 500).
    • Django жобасы: startproject, startapp, INSTALLED_APPS, runserver; негізгі файлдар manage.py, settings.py, urls.py, views.py.
    • Маршруттар: path(...), include(...), <str:name> параметрлері; көрініс request алып, HttpResponse қайтарады.
    • Шаблондар: render, контекст (сөздік), {{ айнымалы }}, {% if %}, {% for %}, {% extends %} мен {% block %}, {% url %}, app_name.
    • Статикалық файлдар: static қалтасы және {% load static %}.
    • Формалар: method="post", {% csrf_token %} (CSRF шабуылынан қорғау), forms.Form, is_valid(), cleaned_data, HttpResponseRedirect(reverse(...)).
    • Сессиялар: request.session әр пайдаланушыға жеке деректі серверде сақтайды (migrate қажет).

    Өзіңізді тексеріңіз

    1. Мына сайттардың қайсысы «динамикалық» деп аталады?

    Динамикалық сайтта HTML алдын ала дайын тұрмайды, оны код сұрау кезінде жасайды. Сондықтан мазмұн күн сайын өзгере алады.

    2. Браузер сұрау жіберіп, 404 күй коды бар жауап алды. Бұл не дегенді білдіреді?

    404 - Not Found. Код қатесі 500 береді, рұқсат жоқ - 403, сәтті жауап - 200.

    3. Жобаның urls.py ішінде path('hello/', include("hello.urls")), ал қосымшаның urls.py ішінде path("david", views.david, name="david") бар. localhost:8000/hello/david URL-іне кіргенде не болады?

    Django алдымен жоба деңгейіндегі префиксті сәйкестендіріп, қалған бөлікті include арқылы қосымшаның жолдарымен салыстырады.

    4. localhost:8000 (соңында ештеңесіз) адресіне кіргенде 404 шықты, ал localhost:8000/hello жұмыс істеді. Неге?

    Django тек анықталған жолдарға жауап береді. Бос жол үшін жобаның urlpatterns тізімінде жол жоқ, сондықтан 404.

    5. Шаблонда <h1>Hello, {{ name }}!</h1> бар. Көрініс render(request, "hello/greet.html", {"name": "Harry"}) шақырды. Браузер нені алады?

    Шаблон тілі серверде орындалады. Браузерге {{ }} да, {% %} да жетпейді, тек дайын HTML барады.

    6. Формадан {% csrf_token %} жолын алып тастап, POST жібердік. Не болады және неге?

    CSRF токені зиянды сайттан келген жалған сұрауларды тоқтатады. Токенсіз POST ортаңғы қабатта бұғатталады.

    7. Пайдаланушы бос не жарамсыз форма жіберді, form.is_valid() нәтижесі False. Лекциядағы add функциясы не істейді?

    Тек жарамды форма ғана тізімге жазылып, қайта бағыттауға әкеледі. Әйтпесе бет қайта көрсетіледі.

    8. Тапсырмалар жаһандық tasks = [...] тізімінде сақталған. Айгүл мен Данияр бір серверге кірді. Айгүл «сүт алу» тапсырмасын қосты. Данияр тізімді ашса, не көреді және мәселені не шешеді?

    Жаһандық айнымалы бүкіл серверге ортақ. Сессия әр кіру үшін жеке деректі сақтайды (алдымен python manage.py migrate керек).

    Ресми жоба беті: cs50.harvard.edu/web/projects/1/wiki. CS50W-да лекциялар мен жобалар бір-біріне бір-бірден сәйкес келмейді. Бұл жобаны 3-лекцияны қарап болмай тұрып бастасаңыз, ерте бастағаныңыз болады.

    Бұл жоба компьютерде орындалады

    Wiki - нағыз Django жобасы, сондықтан ол сайттың ішінде жұмыс істемейді. Оны өз компьютеріңізде орындайсыз: Python, Django (pip3 install Django) және Markdown кітапханасы (pip3 install markdown2) қажет. Төмендегі тізім өзіңізді тексеруге арналған.

    Күрделі

    Wiki (Уикипедияға ұқсас энциклопедия)

    Уикипедияға ұқсас онлайн энциклопедия жасаңыз.

    Алғышарт

    Уикипедия - түрлі тақырыптағы көптеген мақаладан тұратын ақысыз онлайн энциклопедия. Әр мақаланың өз беті бар. Мысалы, https://en.wikipedia.org/wiki/HTML HTML мақаласын көрсетеді. Назар аударыңыз: сұралған беттің аты (HTML) /wiki/HTML маршрутында көрсетілген. Бетінің мазмұны браузер көрсететін HTML екенін де ұмытпаңыз.

    Іс жүзінде Уикипедияның әр бетін HTML-мен жазу жалықтырарлық болар еді. Сондықтан мақалаларды жеңілірек, адамға ыңғайлы белгілеу тілінде сақтаған пайдалы. Уикипедия Wikitext тілін қолданады, ал біз бұл жобада мақалаларды Markdown тілінде сақтаймыз.

    Markdown синтаксисінің қалай жұмыс істейтінін түсіну үшін GitHub-тың Markdown нұсқаулығын оқып шығыңыз. Тақырыптар, қою мәтін, сілтемелер және тізімдер Markdown-да қалай жазылатынына ерекше назар аударыңыз.

    Әр энциклопедия мақаласын бір Markdown файлымен көрсетсек, мақалаларды жазу мен өңдеу адамға ыңғайлырақ болады. Бірақ пайдаланушы мақаланы көргенде, біз Markdown-ды HTML-ге түрлендіріп көрсетуіміз керек.

    Бастау

    Дистрибутивті кодты https://cdn.cs50.net/web/2020/spring/projects/1/wiki.zip сілтемесінен жүктеп, архивті ашыңыз.

    Түсіну

    Дистрибутивте wiki деген Django жобасы бар, оның ішінде бір encyclopedia қосымшасы бар.

    • Алдымен қосымшаның URL конфигурациясы анықталған encyclopedia/urls.py файлын ашыңыз. Сізге views.index функциясымен байланысқан бір әдепкі маршрут дайын берілген.
    • Содан кейін encyclopedia/util.py қараңыз. Онда ештеңе өзгертудің қажеті жоқ, бірақ мақалалармен жұмыс істеуге пайдалы үш функция бар: list_entries қазіргі сақталған барлық мақалалардың аттарының тізімін қайтарады; save_entry жаңа мақаланы оның атауы мен Markdown мазмұны бойынша сақтайды; get_entry мақаланы атауы бойынша алып, бар болса оның Markdown мазмұнын, жоқ болса None қайтарады. Жазатын кез келген көрінісіңіз осы функцияларды қолдана алады.
    • Әр мақала entries/ қалтасында Markdown файлы ретінде сақталады. Онда бірнеше үлгі мақала дайын тұр, қаласаңыз көбірек қоса аласыз!
    • encyclopedia/views.py ішінде қазір бір ғана index көрінісі бар. Ол encyclopedia/index.html шаблонын көрсетіп, оған энциклопедиядағы барлық мақалалар тізімін береді (util.list_entries арқылы).
    • Шаблонды encyclopedia/templates/encyclopedia/index.html ішінен табасыз. Ол негізгі layout.html шаблонынан мұра алады да, беттің атауы мен денесін (мақалалар тізімі) көрсетеді. Ал layout.html беттің жалпы құрылымын анықтайды: әр бетте іздеу өрісі бар бүйір панелі (әзірге ештеңе істемейді), басты бетке сілтеме және жаңа бет жасау не кездейсоқ бетке өту сілтемелері (олар да әзірге жұмыс істемейді).

    Талаптар

    Wiki энциклопедиясын аяқтаңыз. Мына талаптардың бәрін орындау керек:

    • Entry Page (мақала беті): /wiki/TITLE адресіне кіргенде (TITLE - мақала атауы) сол мақаланың мазмұнын көрсететін бет шығуы тиіс.
      • Көрініс мақаланың мазмұнын тиісті util функциясы арқылы алуы керек.
      • Жоқ мақала сұралса, пайдаланушыға сұралған бет табылмағанын көрсететін қате беті шығуы тиіс.
      • Мақала бар болса, оның мазмұны бар бет көрсетіледі. Беттің атауында (title) мақала аты болуы керек.
    • Index Page (негізгі бет): index.html файлын жаңартыңыз, сонда ол мақала аттарын жай тізіп қоймай, пайдаланушы кез келген атты басқанда сол мақала бетіне тікелей өте алатын болсын.
    • Search (іздеу): пайдаланушы бүйір панелдегі іздеу өрісіне сұрау жазып, мақаланы іздей алсын.
      • Сұрау мақала атына дәл сәйкес келсе, пайдаланушы сол мақаланың бетіне қайта бағытталуы керек.
      • Сұрау ешбір мақала атына дәл сәйкес келмесе, пайдаланушы сұрауды ішкі жол (substring) ретінде қамтитын барлық мақалалар тізімі бар іздеу нәтижелері бетіне барады. Мысалы, сұрау ytho болса, нәтижелерде Python шығуы тиіс.
      • Нәтижелер бетіндегі кез келген мақала атын басса, пайдаланушы сол мақала бетіне өтуі керек.
    • New Page (жаңа бет): бүйір панелдегі «Create New Page» сілтемесі пайдаланушыны жаңа мақала жасайтын бетке апаруы керек.
      • Пайдаланушы бет атауын енгізіп, textarea ішіне бет үшін Markdown мазмұнын енгізе алуы керек.
      • Пайдаланушы жаңа бетін сақтау үшін батырманы басады.
      • Бет сақталғанда, берілген атаумен мақала бұрыннан бар болса, пайдаланушыға қате туралы хабар көрсетілуі керек.
      • Әйтпесе мақала дискіге сақталып, пайдаланушы жаңа мақаланың бетіне өтуі керек.
    • Edit Page (бетті өңдеу): әр мақала бетінде пайдаланушы мақаланың Markdown мазмұнын textarea ішінде өңдей алатын бетке өту сілтемесін басып көре алуы керек.
      • textarea бетте бар Markdown мазмұнымен алдын ала толтырылуы керек (яғни бар мазмұн textarea-ның бастапқы value мәні болуы тиіс).
      • Пайдаланушы мақалаға енгізген өзгерістерді сақтау үшін батырманы басады.
      • Мақала сақталған соң, пайдаланушы сол мақаланың бетіне қайта бағытталуы керек.
    • Random Page (кездейсоқ бет): бүйір панелдегі «Random Page» сілтемесі пайдаланушыны кездейсоқ энциклопедия мақаласына апаруы керек.
    • Markdown to HTML Conversion (Markdown-ды HTML-ге түрлендіру): әр мақала бетінде мақала файлындағы Markdown мазмұны пайдаланушыға көрсетілмей тұрып HTML-ге түрлендірілуі тиіс. Түрлендіру үшін python-markdown2 пакетін қолдануға болады, оны pip3 install markdown2 арқылы орнатасыз.
      • Өзін жақсы сезінетіндерге қосымша тапсырма: сыртқы кітапханасыз Markdown-ды HTML-ге түрлендіруді жасап көріңіз. Ол тақырыптарды, қою мәтінді, реттелмеген тізімдерді, сілтемелерді және абзацтарды қолдасын. Python-дағы тұрақты өрнектер көмектесуі мүмкін.
    Кеңес

    Django шаблонында мәнді қойғанда Django оны әдепкіде HTML-escape жасайды, яғни кездейсоқ HTML шығып кетпейді. Егер HTML жолын шынымен HTML ретінде шығарғыңыз келсе, ауыстыратын айнымалы атының артына |safe деп жазып, safe сүзгісін қолданыңыз. Мысалы: {{ content|safe }}.

    CS50 Codespace қолдансаңыз

    CS50 Codespace-те форма жібергенде «403 - CSRF Origin checking» қателігі шықса, жобаңыздың settings.py файлына мына жолды қосыңыз:

    CSRF_TRUSTED_ORIGINS = ['https://CODESPACE-URL-8000.preview.app.github.dev']

    CODESPACE-URL орнына браузер адрес жолағында көрінетін Codespace-тің нақты URL-ін қойыңыз.

    Қалай тапсыру керек

    Тапсыру кезінде web50/projects/2020/x/wiki тармағының құрылымы алынған дистрибутив кодының құрылымымен бірдей болуы керек: файлдарыңыз өзіңіз жасаған басқа қалталардың ішіне салынбасын, тек осы жобаның коды болсын (үш қалта: encyclopedia, entries, wiki және manage.py файлы). Тапсыру үшін submit50 орнатылған болса:

    $ submit50 web50/projects/2020/x/wiki

    Әйтпесе Git арқылы жұмысыңызды https://github.com/me50/USERNAME.git репозиторийіндегі web50/projects/2020/x/wiki тармағына жіберіңіз (USERNAME - GitHub атыңыз). Сонымен қатар 5 минуттан аспайтын скринкаст жазып, YouTube-қа жүктеу керек: онда веб-қосымшаңыздың жеті талаптың бәрі орындалып жатқанын көрсетесіз (код түсіндірмей), бейне басында edX және GitHub аттарыңыз болсын, сипаттамада әр талап көрінген уақыт белгіленсін. Толық нұсқаулық пен форма ресми беттерде.

    Тексеру
    • Entry Page: /wiki/TITLE мақаланы көрсетеді (атауында мақала аты бар), жоқ мақала үшін қате беті шығады.
    • Index Page: мақала аттары сілтеме, басқанда мақала беті ашылады.
    • Search: дәл сәйкестік мақалаға бағыттайды, әйтпесе ішкі жол бойынша нәтижелер беті шығады (ytho -> Python).
    • New Page: атау мен Markdown textarea бар, бар атау үшін қате хабары шығады, әйтпесе мақала сақталып, оның беті ашылады.
    • Edit Page: textarea бар мазмұнмен толтырылған, сақтағаннан кейін мақала бетіне қайта бағытталады.
    • Random Page: кездейсоқ мақалаға апарады.
    • Markdown to HTML: мақала мазмұны HTML-ге түрленіп көрсетіледі (|safe қолданылған).
    • Файл құрылымы дистрибутивтегідей; submit50 web50/projects/2020/x/wiki орындалды және скринкаст жасалды.

    Сайттың өз жаттығулары (ресми емес)

    Төмендегі екі жаттығуды ресми курс бермейді, оларды біз Wiki жобасына дайындық ретінде қостық. Олар таза Python-да жазылады, сондықтан браузерде тексеріледі. Бірінші жаттығуда Django-ның path жолдарының мінезін, екіншісінде Wiki іздеуінің логикасын өзіңіз кодтайсыз.

    Орташа

    Мини URL-маршрутизатор (resolve)

    resolve.py файлында resolve(path, urlpatterns) функциясын жазыңыз. urlpatterns - (маршрут, ат) жұптарының тізімі, мысалы [("", "index"), ("brian", "brian"), ("posts/<int:id>", "post"), ("<str:name>", "greet")]. Функция жолдарды жоғарыдан төмен тексеріп, бірінші сәйкес келгенін (ат, параметрлер_сөздігі) түрінде қайтарсын. <str:x> бос емес кез келген бөлікті қабылдайды, <int:x> тек цифрларды қабылдайды және мәнін int қылады. Жолдың басы мен соңындағы / ескерілмейді. Ештеңе сәйкес келмесе, None қайтарсын.

    Кеңес

    Жолды да, маршрутты да strip("/").split("/") арқылы бөліктерге бөліңіз (бос жол үшін бос тізім алыңыз). Бөліктер саны тең болмаса, келесі маршрутқа өтіңіз. Әр бөлікті салыстырғанда <...> болса, түрін (str/int) тексеріп, параметрлер сөздігіне қосыңыз.

    Тексеру
    • Маршруттар тізімдегі ретімен тексеріледі, бірінші сәйкес келгені қайтарылады.
    • <int:id> мәні int болады, әріп болса сәйкес келмейді.
    • Сәйкестік болмаса, None қайтарылады.

    Оңай

    Wiki іздеуі (search)

    search.py файлында search(query, entries) функциясын жазыңыз, ол Wiki-дің іздеу талабын орындайды. entries - мақала аттарының тізімі. Егер query бір мақала атына (регистрге қарамай) дәл тең болса, ("redirect", сол_мақала_аты) қайтарыңыз. Әйтпесе ("results", тізім) қайтарыңыз: тізімде query-ді (регистрге қарамай) ішкі жол ретінде қамтитын барлық аттар entries ретімен тұрады.

    Кеңес

    Салыстырудың екі жағын да .lower() етіңіз. Ішкі жолды query in title арқылы тексересіз, ал startswith жеткіліксіз: ytho сөзі Python ортасында тұр.

    Тексеру
    • Дәл сәйкестік (регистрге қарамай) redirect береді, мақаланың түпнұсқа аты қайтарылады.
    • Әйтпесе ішкі жол бойынша нәтижелер тізімі қайтарылады.
