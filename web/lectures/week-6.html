    Пайдаланушы интерфейстері

    Сайт тек жұмыс істеп қана қоймай, пайдаланушыға ыңғайлы болуы керек: бет қайта жүктелмей ауысу, шексіз айналдыру, анимациялар және React.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)
    Бұл апта не туралы

    Алдыңғы аптада сайтымызға JavaScript қостық. Бүгін соны «адам жайлы» ету жолдарын қарастырамыз: беттер арасында бет қайта жүктелмей ауысу, төмен айналдырғанда жаңа мазмұн келіп тұру, жылпылдаған анимациялар және осының бәрін ықшамдайтын React. Мысалдардың көбін бетте-ақ «▶» батырмасымен іске қосып көре аласыз. Серверді қажет ететін Django мысалдарын біз өз бетімізде «жалған сервермен» (қарапайым JavaScript функциясымен) ауыстырып көрсетеміз, ал нағыз Django коды өз күйінде жазылған.

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен кодтың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Кіріспе

    Қысқаша есімізге түсіріп алайық. Біз HTML мен CSS арқылы қарапайым беттерді жасай білеміз. Git пен GitHub арқылы кодтағы өзгерістерді қадағалап, басқалармен бірге жұмыс істейміз. Python тілімен танысып, Django арқылы веб-қосымшалар жаздық, Django модельдерімен мәліметті сайтта сақтауды үйрендік. Ең соңында JavaScript келді де, беттерімізді интерактивті етті.

    Бүгін біз пайдаланушы интерфейстерінің (user interface) жалпы қабылданған тәсілдерін қарастырамыз: сайтты пайдаланушыға мейлінше ыңғайлы ету үшін JavaScript пен CSS-ті қалай қолдануға болады.

    Пайдаланушы интерфейстері

    Пайдаланушы интерфейсі дегеніміз - сайтқа кірген адам бетпен қалай әрекеттесетіні. Біз, веб-әзірлеушілер, осы әрекеттесуді мүмкіндігінше жағымды қылуымыз керек. Дүкенге кіргенде бәрі қолыңның астында тұрса, ештеңе іздеп қиналмасаң, сол дүкенге қайта келесің. Сайт та солай. Ыңғайлы болудың бірнеше әдісі бар, бүгін соның ең танымалдарын көреміз.

    Бір беттік қосымшалар

    Бұрын көп беттері бар сайт жасағымыз келсе, оны Django-дағы әртүрлі маршруттар (route) арқылы жасадық: әр маршрут - жеке бет. Енді бізде басқа мүмкіндік бар: бір ғана бетті жүктеп алып, одан әрі DOM-ды JavaScript-пен өзгерту. Мұндай сайт бір беттік қосымша (Single Page Application, SPA) деп аталады.

    Мұның басты артықшылығы неде? Бетте шынымен өзгеретін бөлікті ғана жаңартамыз. Мысалы, сайттың жоғарғы навигация жолағы бір беттен екінші бетке өткенде өзгермейді. Сонда оны әр жолы қайтадан салып отырудың қажеті не? Мектептегі сабақ кестесіндей: бөлме де, парталар да сол күйінде, ауысатыны тек тақтадағы жазу.

    Беттерді JavaScript-пен ауыстыру

    Беттер арасындағы ауысуды JavaScript-те қалай бейнелеуге болатынын көрейік. Мынау - HTML:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Single Page</title>
        <style>
            div {
                display: none;
            }
        </style>
        <script src="singlepage.js"></script>
    </head>
    <body>
        <button data-page="page1">Page 1</button>
        <button data-page="page2">Page 2</button>
        <button data-page="page3">Page 3</button>
        <div id="page1">
            <h1>This is page 1</h1>
        </div>
        <div id="page2">
            <h1>This is page 2</h1>
        </div>
        <div id="page3">
            <h1>This is page 3</h1>
        </div>
    </body>
</html>

    HTML-де үш түйме мен үш div бар екеніне назар аударыңыз. Қазір div-терде азғана мәтін ғана тұр, бірақ әрқайсысының ішінде сайттың бір толық бетінің мазмұны тұр деп елестетіңіз. CSS-те барлық div-ке display: none бердік, яғни әуелде бәрі жасырын. Енді түймелермен беттерді ауыстыратын JavaScript қосайық:

    // Shows one page and hides the other two
function showPage(page) {

    // Hide all of the divs:
    document.querySelectorAll('div').forEach(div => {
        div.style.display = 'none';
    });

    // Show the div provided in the argument
    document.querySelector(`#${page}`).style.display = 'block';
}

// Wait for page to loaded:
document.addEventListener('DOMContentLoaded', function() {

    // Select all buttons
    document.querySelectorAll('button').forEach(button => {

        // When a button is clicked, switch to that page
        button.onclick = function() {
            showPage(this.dataset.page);
        }
    })
});

    Логика қарапайым: showPage алдымен барлық div-ті жасырады, сосын сұралған біреуін ғана көрсетеді. Түймелердің data-page атрибуты қай div-ті ашу керегін айтады. Екеуін біріктіріп, төменде бір бетке жинадық (скрипт файлын бөлек жасамай, тікелей ішіне қойдық). Түймелерді басып көріңіз:

    Мазмұнды серверден алу

    Бірақ көп жағдайда сайтқа алғаш кіргенде бүкіл беттердің мазмұнын бірден жүктеу тиімсіз. Жаңалықтар сайтын елестетіңіз: ол ашылғанда сайттағы бар мақаланы жүктей берсе, бет мәңгі жүктелер еді. Сондықтан жаңа мәліметті керек кезде серверден сұраймыз. Бұл өткен аптадағы валюта бағамын жүктеуге ұқсас тәсіл. Бұл жолы Django-ны қолданып, бір беттік қосымшамызбен ақпарат алмасуды көрейік. Қарапайым Django қосымшасының urls.py файлында екі URL үлгісі бар:

    urlpatterns = [
    path("", views.index, name="index"),
    path("sections/<int:num>", views.section, name="section")
]

    Ал views.py-да оларға сәйкес екі маршрут бар. section маршруты бүтін санды қабылдап, сол санға байланысты мәтіндік жолды HTTP жауабы ретінде қайтарады:

    from django.http import Http404, HttpResponse
from django.shortcuts import render

# Create your views here.
def index(request):
    return render(request, "singlepage/index.html")

# The texts are much longer in reality, but have
# been shortened here to save space
texts = ["Text 1", "Text 2", "Text 3"]

def section(request, num):
    if 1 <= num <= 3:
        return HttpResponse(texts[num - 1])
    else:
        raise Http404("No such section")

    Енді index.html файлында өткен лекцияда үйренген AJAX-ты қолданамыз: серверден белгілі бір бөлімнің мәтінін сұрап алып, экранға шығарамыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Single Page</title>
        <style>
        </style>
        <script>

            // Shows given section
            function showSection(section) {
                
                // Find section text from server
                fetch(`/sections/${section}`)
                .then(response => response.text())
                .then(text => {
                    // Log text and display on page
                    console.log(text);
                    document.querySelector('#content').innerHTML = text;
                });
            }

            document.addEventListener('DOMContentLoaded', function() {
                // Add button functionality
                document.querySelectorAll('button').forEach(button => {
                    button.onclick = function() {
                        showSection(this.dataset.section);
                    };
                });
            });
        </script>
    </head>
    <body>
        <h1>Hello!</h1>
        <button data-section="1">Section 1</button>
        <button data-section="2">Section 2</button>
        <button data-section="3">Section 3</button>
        <div id="content">
        </div>
    </body>
</html>

    Міне, енді бүкіл HTML бетін қайта жүктемей-ақ, серверден жаңа мәліметті алатын сайт жасадық! Біздің сайтта Django жоқ, сондықтан fetch орнына «жалған сервер» қойдық: ол да Promise қайтарады, сондықтан .then тізбегі өзгеріссіз жұмыс істейді. Түймелерді басыңыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Single Page</title>
        <script>
            // Жалған сервер: шынайы fetch(`/sections/${n}`) орнына
            const texts = ["Text 1", "Text 2", "Text 3"];
            function fakeFetch(section) {
                return Promise.resolve({ text: () => Promise.resolve(texts[section - 1]) });
            }

            function showSection(section) {
                fakeFetch(section)
                .then(response => response.text())
                .then(text => {
                    console.log(text);
                    document.querySelector('#content').innerHTML = text;
                });
            }

            document.addEventListener('DOMContentLoaded', function() {
                document.querySelectorAll('button').forEach(button => {
                    button.onclick = function() {
                        showSection(this.dataset.section);
                    };
                });
            });
        </script>
    </head>
    <body>
        <h1>Hello!</h1>
        <button data-section="1">Section 1</button>
        <button data-section="2">Section 2</button>
        <button data-section="3">Section 3</button>
        <div id="content"></div>
    </body>
</html>

    Тарих API (History API)

    Бірақ біздің сайттың бір кемшілігі бар: URL енді аз ақпарат береді. Түпнұсқа бейнеде көрінетіндей, бөлімнен бөлімге көшкенде мекенжай жолағы өзгермей тұра береді. Қазір не болып жатқанын сіз де байқайсыз: Section 2-ні ашып, Артқа түймесін бассаңыз, бұрынғы бөлімге емес, мүлде басқа жерге кетіп қаласыз. Бұл мәселені JavaScript тарих API-мен (History API) шешеміз. Ол браузердің тарихына ақпарат қосып, URL-ді қолмен жаңартуға мүмкіндік береді. Алдыңғы жоба сияқты Django жобасы бар делік, тек скриптті тарих API-ді қолданатындай өзгертеміз:

    // When back arrow is clicked, show previous section
window.onpopstate = function(event) {
    console.log(event.state.section);
    showSection(event.state.section);
}

function showSection(section) {
    fetch(`/sections/${section}`)
    .then(response => response.text())
    .then(text => {
        console.log(text);
        document.querySelector('#content').innerHTML = text;
    });

}

document.addEventListener('DOMContentLoaded', function() {
    document.querySelectorAll('button').forEach(button => {
        button.onclick = function() {
            const section = this.dataset.section;

            // Add the current state to the history
            history.pushState({section: section}, "", `section${section}`);
            showSection(section);
        };
    });
});

    Мұнда history.pushState функциясын қолдандық. Ол браузердің тарихына жаңа жазба қосады және үш аргумент алады:

    1. күйге байланысты кез келген мәлімет (біздегі {section: section});
    2. тақырып параметрі, оны көптеген браузерлер елемейді (сондықтан бос жол "" береміз);
    3. URL жолағында не көрінуі керек.

    Екінші өзгеріс - onpopstate параметрі. Ол пайдаланушы артқа көрсеткіні басқанда не істейтінімізді көрсетеді. Біздің жағдайда алдыңғы бөлімді қайта көрсетеміз: тарихқа жазылған event.state.section дәл сол үшін керек еді. Енді сайт әлдеқайда ыңғайлы.

    Сайттағы мысал туралы

    history.pushState нақты мекенжайға (сервер немесе localhost) байланысты жұмыс істейді. Біздің сайттағы қорғалған мысал терезесінде URL-ді өзгерту рұқсат етілмейді, сондықтан төмендегі мысал тарихтың жұмысын модельдейді: біз тарихты өзіміз массив ретінде ұстаймыз. Негізгі идея - әр басуда тарихқа күй қосу және «Артқа» басқанда соңғы күйге оралу - сол күйінде.

    <button data-section="1">Section 1</button>
<button data-section="2">Section 2</button>
<button data-section="3">Section 3</button>
<button id="back">Артқа</button>
<p>Тарих: <span id="stack"></span></p>
<div id="content"></div>

<script>
    const texts = ["Text 1", "Text 2", "Text 3"];
    const historyStack = [];   // history.pushState орнына

    function showSection(section) {
        document.querySelector('#content').innerHTML = texts[section - 1];
        document.querySelector('#stack').innerHTML = historyStack.map(s => 'section' + s).join(' > ') || '(бос)';
    }

    document.querySelectorAll('button[data-section]').forEach(button => {
        button.onclick = function() {
            const section = this.dataset.section;
            historyStack.push(section);      // ~ history.pushState({section: section}, "", `section${section}`)
            showSection(section);
        };
    });

    // ~ window.onpopstate
    document.querySelector('#back').onclick = () => {
        historyStack.pop();
        const previous = historyStack[historyStack.length - 1];
        if (previous) showSection(previous);
        else { document.querySelector('#content').innerHTML = ''; document.querySelector('#stack').innerHTML = '(бос)'; }
    };
</script>

    Айналдыру (Scroll)

    Браузер тарихын жаңарту үшін біз маңызды JavaScript объектісін қолдандық: window. Сайтымызды көркемдеу үшін қолдануға болатын тағы бірнеше қасиеті бар:

    • window.innerWidth: терезенің ені (пиксельмен);
    • window.innerHeight: терезенің биіктігі (пиксельмен).

    Бұл жерде «терезе» мен «құжатты» ажырату керек. window - қазір пайдаланушыға көрініп тұрған бөлік, ал document - бүкіл веб-бет. Құжат терезеден әлдеқайда ұзын болуы мүмкін, сондықтан біз жоғары-төмен айналдырамыз. Айналдыруды басқару үшін мына шамалар бар:

    • window.scrollY: беттің жоғарғы шетінен қанша пиксельге айналдырғанымыз;
    • document.body.offsetHeight: бүкіл құжаттың биіктігі (пиксельмен).

    Осы шамалармен пайдаланушы беттің соңына жеткенін білуге болады: window.scrollY + window.innerHeight >= document.body.offsetHeight. Қалай ойлайсыз, неге дәл осылай? Жоғарыдан қанша айналдырдық (scrollY) және терезенің өзі қанша орын алады (innerHeight) - екеуін қосқанда, терезенің төменгі шеті құжаттың қай жерінде тұрғанын аламыз. Ол құжаттың биіктігіне жетсе (не асса), төменге жеттік.

    Мысалы, мына бет төменгі шетке жеткенде фон түсін жасылға ауыстырады:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Scroll</title>
        <script>

            // Event listener for scrolling
            window.onscroll = () => {

                // Check if we're at the bottom
                if (window.innerHeight + window.scrollY >= document.body.offsetHeight) {

                    // Change color to green
                    document.querySelector('body').style.background = 'green';
                } else {

                    // Change color to white
                    document.querySelector('body').style.background = 'white';
                }

            };

        </script>
    </head>
    <body>
        <p>1</p>
        <p>2</p>
        <!-- More paragraphs left out to save space -->
        <p>99</p>
        <p>100</p>
    </body>
</html>

    Түпнұсқада орын үнемдеу үшін аралық абзацтар қалдырылған. Төмендегі тірі нұсқада 100 абзацты цикл арқылы жасадық. Нәтиже терезесін төмен қарай айналдырыңыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Scroll</title>
        <script>
            window.onscroll = () => {
                if (window.innerHeight + window.scrollY >= document.body.offsetHeight) {
                    document.querySelector('body').style.background = 'green';
                } else {
                    document.querySelector('body').style.background = 'white';
                }
            };

            document.addEventListener('DOMContentLoaded', () => {
                for (let i = 1; i <= 100; i++) {
                    const p = document.createElement('p');
                    p.innerHTML = i;
                    document.body.append(p);
                }
            });
        </script>
    </head>
    <body>
    </body>
</html>

    Шексіз айналдыру (Infinite Scroll)

    Төменге жеткенде фон түсін өзгерту онша пайдалы емес шығар. Бірақ беттің соңына жеткенімізді анықтау қабілеті бізге шексіз айналдыруды (infinite scroll) жасауға мүмкіндік береді. Әлеуметтік желіні қарап көріңіз: бүкіл жазбаны бірден жүктемейді, алғашқы он жазбаны береді, ал төменге жеткенде келесі ондықты әкеледі. Осындай Django қосымшасына қарайық. urls.py-да екі жол бар:

    urlpatterns = [
    path("", views.index, name="index"),
    path("posts", views.posts, name="posts")
]

    Ал views.py-да екі сәйкес көрініс:

    import time

from django.http import JsonResponse
from django.shortcuts import render

# Create your views here.
def index(request):
    return render(request, "posts/index.html")

def posts(request):

    # Get start and end points
    start = int(request.GET.get("start") or 0)
    end = int(request.GET.get("end") or (start + 9))

    # Generate list of posts
    data = []
    for i in range(start, end + 1):
        data.append(f"Post #{i}")

    # Artificially delay speed of response
    time.sleep(1)

    # Return list of posts
    return JsonResponse({
        "posts": data
    })

    posts көрінісі екі аргумент күтетінін байқаңыз: start (басталу) және end (аяқталу) нүктелері. Бұл көрініс арқылы біз өз API-мізді жасадық. Оны localhost:8000/posts?start=10&end=15 мекенжайына кіріп тексеруге болады, ол мынадай JSON қайтарады:

    {
    "posts": [
        "Post #10",
        "Post #11", 
        "Post #12", 
        "Post #13", 
        "Post #14", 
        "Post #15"
    ]
}

    Енді сайт жүктейтін index.html үлгісінде денеде бос қана div мен азғана стиль бар. Статикалық файлдарды бастапқыда жүктеп алып, сосын static қалтасындағы JavaScript файлына сілтеме жасағанымызды байқаңыз:

    {% load static %}
<!DOCTYPE html>
<html>
    <head>
        <title>My Webpage</title>
        <style>
            .post {
                background-color: #77dd11;
                padding: 20px;
                margin: 10px;
            }

            body {
                padding-bottom: 50px;
            }
        </style>
        <script scr="{% static 'posts/script.js' %}"></script>
    </head>
    <body>
        <div id="posts">
        </div>
    </body>
</html>
    Түпнұсқадағы қате

    Лекция конспектісінде <script scr=...> деп жазылған: бұл жазу қатесі. Дұрысы - src. Біз кодты түпнұсқадағыдай қалдырдық, бірақ нағыз жобаңызда src деп жазыңыз, әйтпесе скрипт жүктелмейді.

    Енді JavaScript-пен пайдаланушы беттің соңына жеткенше күтіп, содан кейін API арқылы жаңа жазбаларды жүктейміз:

    // Start with first post
let counter = 1;

// Load posts 20 at a time
const quantity = 20;

// When DOM loads, render the first 20 posts
document.addEventListener('DOMContentLoaded', load);

// If scrolled to bottom, load the next 20 posts
window.onscroll = () => {
    if (window.innerHeight + window.scrollY >= document.body.offsetHeight) {
        load();
    }
};

// Load next set of posts
function load() {

    // Set start and end post numbers, and update counter
    const start = counter;
    const end = start + quantity - 1;
    counter = end + 1;

    // Get new posts and add posts
    fetch(`/posts?start=${start}&end=${end}`)
    .then(response => response.json())
    .then(data => {
        data.posts.forEach(add_post);
    })
};

// Add a new post with given contents to DOM
function add_post(contents) {

    // Create new post
    const post = document.createElement('div');
    post.className = 'post';
    post.innerHTML = contents;

    // Add post to DOM
    document.querySelector('#posts').append(post);
};

    Кодты ретімен оқып көрейік. counter - келесі жүктелетін жазбаның нөмірі (1-ден бастаймыз), ал quantity - бір жолғы жүктеу көлемі (20). Бет жүктелгенде load шақырылады. Ол start пен end нөмірлерін есептейді, counter-ді келесі жолға жылжытады да, API-ға сұраныс жібереді. Жауап келгенде әр жазба үшін add_post шақырылады: ол жаңа div жасап, оны #posts ішіне қосады. Ал window.onscroll төменге жеткен сайын load-ты қайта шақырады. Нәтижесінде шексіз айналдыру шықты!

    Төмендегі тірі мысалда Django орнына «жалған API» бар: ол нағыз серверді еске түсіру үшін жарты секундтай кідіріп жауап береді. Айналдырып көріңіз:

    <!DOCTYPE html>
<html>
    <head>
        <title>My Webpage</title>
        <style>
            .post {
                background-color: #77dd11;
                padding: 20px;
                margin: 10px;
            }

            body {
                padding-bottom: 50px;
            }
        </style>
        <script>
            // Жалған API: шынайы fetch(`/posts?start=...&end=...`) орнына
            function fakePosts(start, end) {
                const data = [];
                for (let i = start; i <= end; i++) data.push(`Post #${i}`);
                return new Promise(resolve => setTimeout(() => resolve({ posts: data }), 500));
            }

            let counter = 1;
            const quantity = 20;

            document.addEventListener('DOMContentLoaded', load);

            window.onscroll = () => {
                if (window.innerHeight + window.scrollY >= document.body.offsetHeight) {
                    load();
                }
            };

            function load() {
                const start = counter;
                const end = start + quantity - 1;
                counter = end + 1;

                fakePosts(start, end).then(data => {
                    data.posts.forEach(add_post);
                });
            };

            function add_post(contents) {
                const post = document.createElement('div');
                post.className = 'post';
                post.innerHTML = contents;
                document.querySelector('#posts').append(post);
            };
        </script>
    </head>
    <body>
        <div id="posts">
        </div>
    </body>
</html>
    Ойланып көріңіз: counter = end + 1 жолын fetch шақырылғаннан кейін, then ішінде жазсақ не болады?

    Алдымен болжап көріңіз. Жауап (жарты секунд, не сервер баяу болса одан да ұзақ) келгенше пайдаланушы айналдыруды жалғастырады, ал onscroll бірнеше рет load-ты шақырады. Егер counter әлі жаңармаса, барлық шақыру бір ғана start нөмірін алып, бірдей жазбаларды қайталап жүктейді. Сондықтан есептегішті жауап келмей тұрып, fetch-ке дейін жаңартамыз.

    Анимация

    Сайтымызды қызықтырақ етудің тағы бір жолы - анимация қосу. Тек стильмен шектелмей, CSS HTML элементтерін анимациялауды да оңай етеді.

    CSS анимациясы: @keyframes

    CSS-те анимация жасау үшін төмендегі пішімді қолданамыз. Анимацияның егжей-тегжейінде басталу мен аяқталу стильдері (from және to) не ұзақтықтың әр кезеңіндегі стильдер (0%-дан 100%-ға дейін) болады. Мысалы:

    @keyframes animation_name {
    from {
        /* Some styling for the start */
    }

    to {
        /* Some styling for the end */
    }
}

    Не болмаса:

    @keyframes animation_name {
    0% {
        /* Some styling for the start */
    }

    75% {
        /* Some styling after 3/4 of animation */
    }

    100% {
        /* Some styling for the end */
    }
}

    Анимацияны элементке қолдану үшін animation-name (аты), animation-duration (секундпен ұзақтығы) және animation-fill-mode (әдетте forwards) қосамыз. Мысалы, бетке кіргенде тақырып өсіп шығатын бет:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Animate</title>
        <style>
            @keyframes grow {
                from {
                    font-size: 20px;
                }
                to {
                    font-size: 100px;
                }
            }

            h1 {
                animation-name: grow;
                animation-duration: 2s;
                animation-fill-mode: forwards;
            }
        </style>
    </head>
    <body>
        <h1>Welcome!</h1>
    </body>
</html>

    Тек өлшемді емес, басқа нәрсені де өзгертуге болады. Міне, бірнеше жолды ауыстырып, тақырыптың орнын жылжытамыз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Animate</title>
        <style>
            @keyframes move {
                from {
                    left: 0%;
                }
                to {
                    left: 50%;
                }
            }

            h1 {
                position: relative;
                animation-name: move;
                animation-duration: 2s;
                animation-fill-mode: forwards;
            }
        </style>
    </head>
    <body>
        <h1>Welcome!</h1>
    </body>
</html>

    Енді аралық кезеңдердің стильдерін де орнатайық. Кез келген пайыздық кезеңде стиль көрсетуге болады. Төмендегі мысалда тақырыпты солдан оңға, сосын қайтадан солға жылжытамыз. Жоғарғы мысалдан тек анимацияны ғана өзгерттік:

    @keyframes move {
    0% {
        left: 0%;
    }
    50% {
        left: 50%;
    }
    100% {
        left: 0%;
    }
}

    Анимацияны бірнеше рет қайталағымыз келсе, animation-iteration-count мәнін біреуден үлкен санға (не шексіз қайталау үшін infinite) ауыстырамыз. Анимацияның аспектілерін өзгертетін басқа да көптеген қасиеттер бар. Төменде артқа-алға қозғалатын, шексіз қайталанатын тақырып:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Animate</title>
        <style>
            @keyframes move {
                0% {
                    left: 0%;
                }
                50% {
                    left: 50%;
                }
                100% {
                    left: 0%;
                }
            }

            h1 {
                position: relative;
                animation-name: move;
                animation-duration: 2s;
                animation-fill-mode: forwards;
                animation-iteration-count: infinite;
            }
        </style>
    </head>
    <body>
        <h1>Welcome!</h1>
    </body>
</html>

    Анимацияны JavaScript-пен басқару

    CSS-тен басқа, анимацияны басқару үшін JavaScript-ті де қолдануға болады. Шексіз қайталанатын қозғалатын тақырыбымыздың мысалында анимацияны бастайтын және тоқтататын түйме жасайық. Анимация, түйме және тақырып дайын болса, анимацияны іске қосу және кідірту үшін мына скриптті қосамыз:

    document.addEventListener('DOMContentLoaded', function() {

    // Find heading
    const h1 = document.querySelector('h1');

    // Pause Animation by default
    h1.style.animationPlayState = 'paused';

    // Wait for button to be clicked
    document.querySelector('button').onclick = () => {

        // If animation is currently paused, begin playing it
        if (h1.style.animationPlayState == 'paused') {
            h1.style.animationPlayState = 'running';
        }

        // Otherwise, pause the animation
        else {
            h1.style.animationPlayState = 'paused';
        }
    }

})

    Оны бетке қосып, түймені басып көріңіз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <title>Animate</title>
        <style>
            @keyframes move {
                0% {
                    left: 0%;
                }
                50% {
                    left: 50%;
                }
                100% {
                    left: 0%;
                }
            }

            h1 {
                position: relative;
                animation-name: move;
                animation-duration: 2s;
                animation-fill-mode: forwards;
                animation-iteration-count: infinite;
            }
        </style>
        <script>
            document.addEventListener('DOMContentLoaded', function() {
                const h1 = document.querySelector('h1');
                h1.style.animationPlayState = 'paused';

                document.querySelector('button').onclick = () => {
                    if (h1.style.animationPlayState == 'paused') {
                        h1.style.animationPlayState = 'running';
                    }
                    else {
                        h1.style.animationPlayState = 'paused';
                    }
                }
            })

    </head>
    <body>
        <button>Start / Pause</button>
        <h1>Welcome!</h1>
    </body>
</html>

    Жазбаны жасыру анимациясы

    Енді жаңа білгенімізді бұрынғы жазбалар бетіне қолданайық. Айталық, оқып болған жазбаларды жасыру мүмкіндігін қосқымыз келеді. Бұрынғымен бірдей Django жобасы, тек HTML мен JavaScript сәл басқаша. Бірінші өзгеріс - add_post функциясында жазбаның оң жағына түйме қосамыз:

    // Add a new post with given contents to DOM
function add_post(contents) {

    // Create new post
    const post = document.createElement('div');
    post.className = 'post';
    post.innerHTML = `${contents} <button class="hide">Hide</button>`;

    // Add post to DOM
    document.querySelector('#posts').append(post);
};

    Енді hide түймесі басылғанда жазбаны жасыруға көшейік. Ол үшін бетте кез келген жерді басқанда іске қосылатын оқиға тыңдаушысын қосамыз. Функция оқиғаны event аргументі ретінде алады. Бұл ыңғайлы, себебі event.target арқылы нақты нені басқанымызды білеміз. Сондай-ақ parentElement арқылы берілген элементтің DOM-дағы ата-анасын табамыз.

    // If hide button is clicked, delete the post
document.addEventListener('click', event => {

    // Find what was clicked on
    const element = event.target;

    // Check if the user clicked on a hide button
    if (element.className === 'hide') {
        element.parentElement.remove()
    }
    
});

    Жасыру түймесі жұмыс істейді, бірақ ол онша әдемі емес: жазба кенеттен жоқ болып кетеді. Жазба жойылмай тұрып, баяу өшіп, кішірейсе жақсы болар еді. Ол үшін алдымен CSS анимациясын жасаймыз. Төмендегі анимация уақытының 75%-ын opacity мәнін 1-ден 0-ге дейін өзгертуге жұмсайды, яғни жазба баяу өшеді. Қалған уақытта биіктікке қатысты барлық қасиетті нөлге жеткізіп, жазбаны жоққа дейін кішірейтеді:

    @keyframes hide {
    0% {
        opacity: 1;
        height: 100%;
        line-height: 100%;
        padding: 20px;
        margin-bottom: 10px;
    }
    75% {
        opacity: 0;
        height: 100%;
        line-height: 100%;
        padding: 20px;
        margin-bottom: 10px;
    }
    100% {
        opacity: 0;
        height: 0px;
        line-height: 0px;
        padding: 0px;
        margin-bottom: 0px;
    }
}

    Келесі қадамда осы анимацияны жазбаның CSS-іне қосамыз. Бастапқыда animation-play-state мәнін paused қойғанымызға назар аударыңыз: яғни жазба әдепкіде жасырылмайды.

    .post {
    background-color: #77dd11;
    padding: 20px;
    margin-bottom: 10px;
    animation-name: hide;
    animation-duration: 2s;
    animation-fill-mode: forwards;
    animation-play-state: paused;
}

    Ақырында hide түймесі басылғанда анимацияны іске қосып, содан кейін жазбаны жою керек. Ол үшін JavaScript-ті өзгертеміз:

    // If hide button is clicked, delete the post
document.addEventListener('click', event => {

    // Find what was clicked on
    const element = event.target;

    // Check if the user clicked on a hide button
    if (element.className === 'hide') {
        element.parentElement.style.animationPlayState = 'running';
        element.parentElement.addEventListener('animationend', () => {
            element.parentElement.remove();
        });
    }
    
});

    Көріп отырғаныңыздай, жасыру енді әлдеқайда әдемі. Бұл жерде animationend оқиғасы маңызды: ол анимация аяқталғанда ғана жазбаны DOM-нан жояды, яғни өшіп-кішірею соңына дейін көрінеді. Ресми қосымша серверді қажет еткені үшін, төмендегі мысалда бес дайын жазбамен жұмыс істейміз:

    <!DOCTYPE html>
<html>
    <head>
        <style>
            @keyframes hide {
                0% {
                    opacity: 1;
                    height: 100%;
                    line-height: 100%;
                    padding: 20px;
                    margin-bottom: 10px;
                }
                75% {
                    opacity: 0;
                    height: 100%;
                    line-height: 100%;
                    padding: 20px;
                    margin-bottom: 10px;
                }
                100% {
                    opacity: 0;
                    height: 0px;
                    line-height: 0px;
                    padding: 0px;
                    margin-bottom: 0px;
                }
            }

            .post {
                background-color: #77dd11;
                padding: 20px;
                margin-bottom: 10px;
                animation-name: hide;
                animation-duration: 2s;
                animation-fill-mode: forwards;
                animation-play-state: paused;
            }

            .hide {
                float: right;
            }
        </style>
        <script>
            function add_post(contents) {

                post.className = 'post';

    Ойланып көріңіз: неге түймеге емес, бүкіл document-ке click тыңдаушысын қойдық?

    Түймелер бет жүктелгенде жоқ: оларды add_post кейін, жазбалар келген сайын жасайды. Егер әр түймеге тыңдаушыны бет жүктелгенде қоясақ, кейін қосылған жазбалардың түймелері тыңдаушысыз қалар еді. Ал document-тегі бір тыңдаушы кез келген басуды ұстайды, ал event.target оның түйме екенін айтады. Мұндай тәсіл оқиға делегациясы (event delegation) деп аталады.

    React

    React мысалдары үшін интернет керек

    Осы бөлімдегі «▶ Көрсету» мысалдары React, ReactDOM және Babel кітапханаларын unpkg.com желісінен жүктейді. Сондықтан оларды іске қосу үшін интернет қосылған болуы керек. Ал код блоктарын оқуға интернет қажет емес.

    Күрделірек сайтқа қанша JavaScript коды керек болатынын елестете аласыз. Қажет кодтың көлемін JavaScript фреймворкі арқылы азайтуға болады. Дәл CSS жазуды қысқарту үшін Bootstrap қолданғанымыз сияқты. Ең танымал JavaScript фреймворктерінің бірі - React деп аталатын кітапхана.

    Императивті және декларативті бағдарламалау

    Осы курста біз әзірге императивті бағдарламалау (imperative programming) әдісін қолдандық: компьютерге орындайтын нұсқауларды қатар-қатар береміз. Мысалы, беттегі санауышты жаңарту үшін мынадай код жазуымыз мүмкін.

    Көрініс (View):

    <h1>0</h1>

    Логика (Logic):

    let num = parseInt(document.querySelector("h1").innerHTML);
num += 1;
document.querySelector("h1").innerHTML = num;

    React бізге декларативті бағдарламалауды (declarative programming) қолдануға мүмкіндік береді: біз не көрсеткіміз келетінін жазамыз, ал оны қалай көрсету керегін ойламаймыз. Тапсырыс беру сияқты: асханада «шай әкеліңіз» дейсіз, шайды қалай қайнату керегін айтып отырмайсыз. React-те санауыш мынадай көрінеді.

    Көрініс (View):

    <h1>{num}</h1>

    Логика (Logic):

    num += 1;

    React-тің негізінде компоненттер (components) идеясы жатыр, олардың әрқайсысында өзінің күйі (state) болуы мүмкін. Компонент - веб-беттегі көзге көрінетін нәрсе: мысалы, жазба немесе навигация жолағы. Ал күй - сол компонентке байланысты айнымалылар жиыны. React-тің сұлулығы мынада: күй өзгергенде React DOM-ды өзі автоматты түрде өзгертеді. Біз «DOM-ды қалай жаңартамыз» деп алаңдамаймыз.

    Алғашқы React қосымшасы

    React-ті қолданудың көптеген жолы бар (соның ішінде Facebook шығарған танымал create-react-app командасы), бірақ бүгін тікелей HTML файлынан бастаймыз. Ол үшін үш JavaScript пакетін қосу керек:

    • React: компоненттерді және олардың мінез-құлқын анықтайды;
    • ReactDOM: React компоненттерін алып, DOM-ға салады;
    • Babel: біз React-те жазатын JSX тілін браузер түсінетін қарапайым JavaScript-ке аударады. JSX (JSX) JavaScript-ке өте ұқсас, бірақ қосымша мүмкіндіктері бар: оның ішінде код ішінде HTML-ді жазуға болады.

    Бірінші React қосымшамызды жасайық!

    <!DOCTYPE html>
<html lang="en">
    <head>
        <script src="https://unpkg.com/react@17.0.2/umd/react.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/react-dom@17.0.2/umd/react-dom.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/babel-standalone@6.26.0/babel.min.js"></script>
        <title>Hello</title>
    </head>
    <body>
        <div id="app"></div>

        <script type="text/babel">
            function App() {
                return (
                    <div>
                        Hello!
                    </div>
                );
            }

            ReactDOM.render(<App />, document.querySelector("#app"));
        </script>
    </body>
</html>
    Нұсқалар туралы

    Түпнұсқа конспектте react@17 және babel-standalone@6 нұсқалары қолданылған (нақты нұсқасын көрсетпей). Біз тұрақты болу үшін нақты нұсқаларын жаздық: react@17.0.2, babel-standalone@6.26.0. Жаңа React нұсқаларында ReactDOM.render орнына басқа жазу ұсынылады, бірақ бұл лекцияда түпнұсқадағыдай қолданамыз.

    Бұл біздің алғашқы React қосымшамыз, сондықтан әр бөлікті егжей-тегжейлі талдайық:

    • Тақырыптан жоғарғы үш жолда React, ReactDOM және Babel-дің нұсқаларын импорттаймыз.
    • Денеде id мәні app болатын жалғыз div бар. Оны әрдайым дерлік бос қалдырамыз да, төмендегі React кодымен толтырамыз.
    • Скрипт тегінде type="text/babel" көрсетеміз. Бұл браузерге: «келесі скриптті алдымен Babel-мен аудару керек» дегенді білдіреді.
    • Содан кейін App деп аталатын компонент жасаймыз. React-те компоненттерді JavaScript функциялары ретінде бейнелеуге болады.
    • Компонент DOM-ға салғымыз келетін нәрсені қайтарады. Біздің жағдайда жай ғана <div>Hello!</div>.
    • Скрипттің соңғы жолы ReactDOM.render функциясын қолданады. Оның екі аргументі бар: 1) салынатын компонент; 2) компонент салынатын DOM элементі.

    Код не істейтінін түсінген соң, нәтиже бетіне қарасақ: экранда «Hello!» жазуы шығады.

    Компоненттер мен пропстар

    React-тің пайдалы мүмкіндігі - компоненттерді басқа компоненттердің ішіне салу. Мұны көрсету үшін Hello деп аталатын тағы бір компонент жасайық:

    function Hello(props) {
    return (
        <h1>Hello</h1>
    );
}

    Енді App компонентінің ішіне үш Hello компонентін саламыз:

    function App() {
    return (
        <div>
            <Hello />
            <Hello />
            <Hello />
        </div>
    );
}

    Бұл бізге үш «Hello» тақырыбы бар бетті береді. Әзірге компоненттер өте қызықсыз: барлығы дәл бірдей. Оларды икемді ету үшін қасиеттер (React тілінде props, properties) қосуға болады. Мысалы, үш түрлі адамға сәлем бергіміз келсін. Олардың аттарын HTML атрибуттарына ұқсас түрде береміз:

    function App() {
    return (
        <div>
            <Hello name="Harry" />
            <Hello name="Ron" />
            <Hello name="Hermione" />
        </div>
    );
}

    Оларға props.PROP_NAME арқылы қол жеткіземіз. Оны JSX ішіне ирек жақшамен ({ }) қыстырамыз:

    function Hello(props) {
    return (
        <h1>Hello, {props.name}!</h1>
    );
}

    Енді бетімізде үш есім көрінеді! Түгел бетті мына жерде көріңіз:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <script src="https://unpkg.com/react@17.0.2/umd/react.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/react-dom@17.0.2/umd/react-dom.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/babel-standalone@6.26.0/babel.min.js"></script>
        <title>Hello</title>
    </head>
    <body>
        <div id="app"></div>

        <script type="text/babel">
            function Hello(props) {
                return (
                    <h1>Hello, {props.name}!</h1>
                );
            }

            function App() {
                return (
                    <div>
                        <Hello name="Harry" />
                        <Hello name="Ron" />
                        <Hello name="Hermione" />
                    </div>
                );
            }

            ReactDOM.render(<App />, document.querySelector("#app"));
        </script>
    </body>
</html>

    Күй және useState хугы

    Енді React-ті пайдаланып, JavaScript-пен алғаш жұмыс істегенде жасаған санауыш бетін қайта жасап көрейік. Жалпы құрылым бұрынғыдай қалады, бірақ App компонентінің ішінде оған күй қосу үшін React-тің useState хугын (hook) қолданамыз. useState аргументі - күйдің бастапқы мәні, біз оны 0 етіп қоямыз. Функция екі нәрсе қайтарады: күйді білдіретін айнымалы және күйді жаңартуға мүмкіндік беретін функция.

    const [count, setCount] = React.useState(0);

    Енді функция нені салатынына көшейік: тақырып пен түйме. Түйме басылғанда оқиға тыңдаушысын да қосамыз. React мұны onClick атрибуты арқылы өңдейді:

    return (
    <div>
        <h1>{count}</h1>
        <button onClick={updateCount}>Count</button>
    </div>
);

    Ақырында updateCount функциясын анықтайық. Ол үшін setCount функциясын қолданамыз, оның аргументі күйдің жаңа мәні болады:

    function updateCount() {
    setCount(count + 1);
}

    Міне, жұмыс істейтін санауыш сайтымыз! Барлығын жинап көрейік:

    <!DOCTYPE html>
<html lang="en">
    <head>
        <script src="https://unpkg.com/react@17.0.2/umd/react.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/react-dom@17.0.2/umd/react-dom.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/babel-standalone@6.26.0/babel.min.js"></script>
        <title>Counter</title>
    </head>
    <body>
        <div id="app"></div>

        <script type="text/babel">
            function App() {
                const [count, setCount] = React.useState(0);

                function updateCount() {
                    setCount(count + 1);
                }

                return (
                    <div>
                        <h1>{count}</h1>
                        <button onClick={updateCount}>Count</button>
                    </div>
                );
            }

            ReactDOM.render(<App />, document.querySelector("#app"));
        </script>
    </body>
</html>
    Ойланып көріңіз: updateCount ішінде count = count + 1 деп жазсақ не болады?

    Алдымен болжап көріңіз. count - жай айнымалы, оның мәнін қолмен өзгертсек, React бұл туралы білмейді, сондықтан бет қайта салынбайды. Түйме басылса да, экрандағы сан өзгермей қалады. Күйді тек setCount арқылы өзгерту керек: сонда React күйдің өзгергенін біліп, компонентті қайта салады.

    Қосу ойыны

    React-пен танысып алған соң, білгенімізді қолданып, пайдаланушылар қосу есептерін шығаратын ойын тәрізді сайт жасайық. Басқа React беттеріндегідей баптаудан бастаймыз. Қосымшаны құру үшін күйде нені сақтау керек екенін ойланайық. Бет ашық тұрғанда өзгеруі мүмкін барлық нәрсе күйде болуы керек. Біздің күйде мыналар болады:

    • num1: қосылатын бірінші сан;
    • num2: қосылатын екінші сан;
    • response: пайдаланушы теріп жатқан жауап;
    • score: пайдаланушы дұрыс жауап берген сұрақтар саны.

    Күйіміз осы ақпараттың бәрін қамтитын JavaScript объектісі бола алады:

    const [state, setState] = React.useState({
    num1: 1,
    num2: 1,
    response: "",
    score: 0
});

    Енді күйдегі мәндерді пайдаланып, қарапайым интерфейсті салуға болады:

    return (
    <div>
        <div>{state.num1} + {state.num2}</div>
        <input value={state.response} />
        <div>Score: {state.score}</div>
    </div>
);

    Сайттың негізгі көрінісі осындай болады (түпнұсқада скриншот): жоғарыда «1 + 1», астында енгізу өрісі, ең төменде «Score: 0».

    Қазір пайдаланушы енгізу өрісіне ештеңе тере алмайды, себебі өрістің мәні state.response деп бекітілген, ол әзірге бос жол. Мұны түзету үшін input элементіне onChange атрибутын қосып, оны updateResponse функциясына теңейміз:

    onChange={updateResponse}

    Енді updateResponse функциясын анықтаймыз. Ол функцияны шақырған оқиғаны аргумент ретінде алады да, response мәнін өрістің қазіргі мәніне қояды. Осылай пайдаланушы тере алады, ал терген мәтіні state-те сақталады:

    function updateResponse(event) {
    setState({
        ...state,
        response: event.target.value
    });
}

    Мұндағы ...state жазуына назар аударыңыз: ол «state объектісіндегі барлық өрісті көшір» дегенді білдіреді, сосын тек response өрісін жаңасымен ауыстырамыз. Егер ...state болмаса, жаңа объектіде тек response қалып, num1, num2 және score жоғалып кетер еді.

    Енді пайдаланушыға есепті жіберу мүмкіндігін қосайық. Алдымен тағы бір оқиға тыңдаушысын қосып, оны жазатын функцияға байлаймыз:

    onKeyPress={inputKeyPress}

    Енді inputKeyPress функциясын анықтаймыз. Бұл функцияда алдымен Enter пернесі басылғанын, содан кейін жауаптың дұрыс-бұрыстығын тексереміз. Пайдаланушы дұрыс жауап берсе, ұпайды 1-ге арттырамыз, келесі есепке кездейсоқ сандар таңдаймыз және жауап өрісін тазалаймыз. Жауап қате болса, ұпайды 1-ге азайтып, өрісті тазалаймыз:

    function inputKeyPress(event) {
    if (event.key === "Enter") {
        const answer = parseInt(state.response);
        if (answer === state.num1 + state.num2) {
            // User got question right
            setState({
                ...state,
                score: state.score + 1,
                response: "",
                num1: Math.ceil(Math.random() * 10),
                num2: Math.ceil(Math.random() * 10)
            });
        } else {
            // User got question wrong
            setState({
                ...state,
                score: state.score - 1,
                response: ""
            })
        }
    }
}

    Қосымшаға соңғы әдемілік беру үшін бетке стиль қосайық. Қосымшаның бәрін ортаға орналастырамыз, есептің өзін үлкейту үшін есеп тұрған div-ке problem деген id береміз де, style тегіне мына CSS-ті қосамыз:

    #app {
    text-align: center;
    font-family: sans-serif;
}

#problem {
    font-size: 72px;
}

    Ең соңында 10 ұпай жинағанда ойында жеңіс мүмкіндігін қосайық. Ол үшін render функциясына шарт қосамыз: 10 ұпай болғанда мүлде басқа нәрсе қайтарамыз:

    if (state.score === 10) {
    return (
        <div id="winner">You won!</div>
    );
}

    Жеңісті қызықтырақ ету үшін балама div-ке де стиль береміз:

    #winner {
    font-size: 72px;
    color: green;
}

    Енді дайын қосымшамызға қарайық! Жиналған толық нұсқа мынау. Жауабын теріп, Enter басыңыз. Қате жауап ұпайды азайтатынын, сондықтан ұпай теріс болуы да мүмкін екенін ұмытпаңыз.

    <!DOCTYPE html>
<html lang="en">
    <head>
        <script src="https://unpkg.com/react@17.0.2/umd/react.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/react-dom@17.0.2/umd/react-dom.production.min.js" crossorigin></script>
        <script src="https://unpkg.com/babel-standalone@6.26.0/babel.min.js"></script>
        <title>Addition</title>
        <style>
            #app {
                text-align: center;
                font-family: sans-serif;
            }

            #problem {
                font-size: 72px;
            }

            #winner {
                font-size: 72px;
                color: green;
            }
        </style>
    </head>
    <body>
        <div id="app"></div>

        <script type="text/babel">
            function App() {
                const [state, setState] = React.useState({
                    num1: 1,
                    num2: 1,
                    response: "",
                    score: 0
                });

                function updateResponse(event) {
                    setState({
                        ...state,
                        response: event.target.value
                    });
                }

                function inputKeyPress(event) {
                    if (event.key === "Enter") {
                        const answer = parseInt(state.response);
                        if (answer === state.num1 + state.num2) {
                            // User got question right
                            setState({
                                ...state,
                                score: state.score + 1,
                                response: "",
                                num1: Math.ceil(Math.random() * 10),
                                num2: Math.ceil(Math.random() * 10)
                            });
                        } else {
                            // User got question wrong
                            setState({
                                ...state,
                                score: state.score - 1,
                                response: ""
                            })
                        }
                    }
                }

                if (state.score === 10) {
                    return (
                        <div id="winner">You won!</div>
                    );
                }

                return (
                    <div>
                        <div id="problem">{state.num1} + {state.num2}</div>
                        <input
                            autoFocus={true}
                            onKeyPress={inputKeyPress}
                            value={state.response}
                            onChange={updateResponse}
                        />
                        <div>Score: {state.score}</div>
                    </div>
                );
            }

            ReactDOM.render(<App />, document.querySelector("#app"));
        </script>
    </body>
</html>
    Ойланып көріңіз: неге ойында жеңіс туралы шарт useState шақырылғаннан кейін жазылады?

    useState сияқты хуктар компонент әр қайта салынғанда бірдей ретпен шақырылуы керек. Егер return хуктан бұрын орындалып кетсе, келесі қайта салуда хуктардың саны өзгеріп, React шатасады. Сондықтан алдымен күйді жарияласақ, содан кейін ғана «не салу керек» деген шарттарды жазамыз. Ал мұндағы score === 10 шарты ескі көріністің орнына мүлде басқа div қайтарады, мұны декларативті жазудың артықшылығы деуге болады: тек «күй мынадай болса, көрініс мынадай» деп сипаттаймыз.

    Бүгінгі лекция осымен біткен. Келесі жолы үлкенірек веб-қосымшалар құрудың үздік тәжірибелері туралы айтамыз.

    Қорытынды

    • Бір беттік қосымша (SPA): бір ғана бет жүктеледі, ал мазмұнның өзгеретін бөлігін JavaScript DOM-ды өзгертіп (не fetch арқылы серверден мәлімет алып) жаңартады.
    • History API: history.pushState(күй, тақырып, url) тарихқа жазба қосып, URL-ді жаңартады, ал window.onpopstate «Артқа» басқанда не істеу керегін анықтайды.
    • Айналдыру: window.innerHeight, window.scrollY, document.body.offsetHeight шамалары арқылы беттің соңына жеткенімізді анықтаймыз: window.scrollY + window.innerHeight >= document.body.offsetHeight.
    • Шексіз айналдыру: төменге жеткенде fetch арқылы API-дан келесі жазбалар бөлігін жүктейміз.
    • CSS анимациясы: @keyframes (from/to не 0%...100%) және animation-name, animation-duration, animation-fill-mode, animation-iteration-count, animation-play-state қасиеттері.
    • JavaScript + анимация: style.animationPlayState арқылы анимацияны іске қосу/кідірту, animationend оқиғасымен анимациядан кейін элементті жою.
    • React декларативті: біз көріністі күйге сүйеніп сипаттаймыз, ал DOM-ды React жаңартады. Негізгі ұғымдар: компонент (функция), JSX, пропстар (props), күй (useState).
    • Күйді жаңарту: күйді тікелей өзгертпейміз, setState/setCount шақырамыз; объект күйде қалған өрістерді ...state арқылы сақтаймыз.

    Өзіңізді тексеріңіз

    1. SPA-да history.pushState({section: 2}, "", "section2") шақырылды, URL өзгерді. Бірақ пайдаланушы «Артқа» түймесін басқанда, URL бұрынғыға қайтады да, бет мазмұны өзгермей қалады. Негізгі себеп қандай?

    pushState бетті өзгертпейді. Бет мазмұнын біз өзіміз showSection арқылы жаңартамыз. «Артқа» басылғанда onpopstate оқиғасы шығады, ал онда event.state арқылы бұрынғы күйді алып, бетті қайта көрсету керек.

    2. Терезе биіктігі window.innerHeight = 700, window.scrollY = 1250, ал document.body.offsetHeight = 2000. window.innerHeight + window.scrollY >= document.body.offsetHeight шарты қандай болады?

    scrollY + innerHeight - терезенің төменгі шетінің құжаттағы орны. Ол құжат биіктігіне тең не одан үлкен болғанда ғана төменге жеттік деген сөз.

    3. Шексіз айналдыру кодында counter = 1, quantity = 20. Бет жүктелгенде load бір рет шақырылды, пайдаланушы төменге жетіп, екінші рет шақырылды. Екінші fetch қандай URL-ге барады?

    Бірінші шақыруда start = 1, end = 1 + 20 - 1 = 20, содан кейін counter = end + 1 = 21. Екінші шақыруда start = 21, end = 21 + 20 - 1 = 40.

    4. h1 элементіне grow анимациясы (20px-тен 100px-ке) берілген, бірақ animation-fill-mode: forwards жазылмаған. Анимация аяқталған соң не болады?

    forwards анимацияның соңғы кадрындағы стильді сақтайды. Онсыз элемент анимациядан кейін алғашқы стиліне оралады.

    5. Жазбаны жасыру кодында неге element.parentElement.remove() шақыруын тікелей емес, animationend оқиғасының ішінде жазамыз?

    Алдымен animationPlayState = 'running' анимацияны іске қосады. Анимация 2 секундқа созылады, ал animationend оқиғасы оның аяқталғанын хабарлайды. Сол кезде ғана жазбаны DOM-нан жоямыз.

    6. Төмендегілердің қайсысы декларативті жазу стиліне жатады?

    Үш бірінші нұсқа - DOM-мен қадам-қадаммен жұмыс істейтін императивті код. React-те тек «num мәнін көрсет» деп сипаттаймыз, ал DOM-ды жаңартуды React өзі жасайды.

    7. React санауышында түйме басылғанда count = count + 1; деп жазылды (setCount орнына). Нәтиже қандай?

    Күйді жаңартудың жалғыз жолы - useState қайтарған функцияны (setCount) шақыру. Тікелей өзгерту көрініске жетпейді.

    8. Қосу ойынында updateResponse функциясын былай жазып қойдық: setState({response: event.target.value}) (...state жоқ). Пайдаланушы өріске бір әріп тергенде не болады?

    setState күйді қосып емес, толық ауыстырады (useState-ның бұл түрінде). Сондықтан қалған өрістерді сақтау үшін ...state жазамыз.

    Жаттығулар: күй редьюсері және массивті жаңарту

    Сайттың өз жаттығулары, ресми тапсырма емес

    Төмендегі үш жаттығуды біз осы сайт үшін қостық. Бұл CS50 ресми problem set-і емес. Лекцияда React-тің ең басты қағидасын көрдік: күйді тікелей өзгертпейміз, ал жаңа күйді (жаңа объект немесе массив) жасап, соны береміз ({...state, score: state.score + 1}). Бұл ойды таза JavaScript функциясына бөліп алуға болады: редьюсер (reducer) - ескі күй мен action (не істеу керек) алып, жаңа күйді қайтаратын функция. Оны React-сіз-ақ, браузердегі кәдімгі JS-те тексеруге болады. Кодыңызды .js файлына жазып, автотексерушіге жүктеңіз (немесе қойыңыз): ол кодты браузерде, бөлек ағында (Web Worker) орындайды, шексіз цикл қауіпсіз тоқтатылады.

    Оңай

    reducer: санауыш

    reducer(state, action) функциясын жазыңыз. state - {count: 0, label: "Санауыш"} түріндегі объект. action.type мәніне қарай жаңа объект қайтарсын: "increment" - count 1-ге артады; "decrement" - 1-ге кемиді; "add" - count мәніне action.amount қосылады; "reset" - count 0 болады. Белгісіз түр келсе, бұрынғы state-ті қайтарыңыз. Бастапқы state объектісі өзгермеуі керек, label өрісі сақталуы керек.

    Кеңес

    switch (action.type) { case "increment": return {...state, count: state.count + 1}; ... default: return state; } жазылымын қолданыңыз. ...state ескі объектінің барлық өрісін (соның ішінде label) жаңа объектіге көшіреді, ал содан кейін жазылған count оны қайта жазады. state.count += 1 деп жазбаңыз: бұл бастапқы объектіні бұзады.

    Орташа

    reducer: қосу ойыны

    Лекциядағы қосу ойынының логикасын редьюсерге айналдырыңыз. state - {num1, num2, response, score}. {type: "respond", value} келсе, response өрісін value етіп өзгертіңіз (қалған өрістер сақталады). {type: "submit", next: [a, b]} келсе: егер parseInt(state.response) === state.num1 + state.num2 болса - score 1-ге артады, response бос жол "" болады, num1 = a және num2 = b болады; әйтпесе score 1-ге кемиді, response бос жол болады, ал num1 мен num2 өзгермейді. Белгісіз түр үшін state-тің өзін қайтарыңыз. Кездейсоқ сандарды редьюсердің өзі таңдамайды: оларды action.next арқылы береміз (сонда функцияны тексеру оңай болады).

    Кеңес

    Бұл лекциядағы updateResponse мен inputKeyPress функцияларындағы setState({...}) шақыруларының дәл өзі, тек setState орнына нәтижені return етесіз. Әр return-да ...state жазуды ұмытпаңыз, әйтпесе қалған өрістер жоғалады.

    Орташа

    addPost, likePost, removePost (массивті өзгертпей жаңарту)

    Әр жазба - объект {id, text, likes}. Үш функцияны жазыңыз, олардың әрқайсысы жаңа массив қайтарсын, бастапқы массивті өзгертпесін. addPost(posts, text) тізімнің соңына {id, text, likes: 0} қосады, мұндағы id - бар id мәндерінің ең үлкені + 1 (массив бос болса 1). likePost(posts, id) сол id-ге ие жазбаның likes мәнін 1-ге арттырады, қалған жазбалар өзгермейді (жоқ id берілсе, ештеңе өзгермейді). removePost(posts, id) сол id-лі жазбаны алып тастайды.

    Кеңес

    Қосу үшін [...posts, newPost], жаңарту үшін posts.map(p => p.id === id ? {...p, likes: p.likes + 1} : p), жою үшін posts.filter(p => p.id !== id) қолданыңыз. push, splice және p.likes++ бастапқы массивті өзгертеді, сондықтан оларды қолданбаңыз. id-ті posts.length + 1 деп алмаңыз: жазбалар жойылса, id қайталанып кетуі мүмкін.

      • пайдаланушының жазылушылар саны және ол өзі жазылған адамдар саны көрсетіледі;
      • пайдаланушының барлық жазбасы кері хронологиялық ретпен көрсетіледі;
      • жүйеге кірген кез келген басқа пайдаланушыға «Follow» (жазылу) не «Unfollow» (жазылудан бас тарту) түймесі көрсетіледі: ол арқылы ағымдағы пайдаланушы осы адамның жазбаларына жазылуды қосып-өшіре алады. Бұл тек «басқа» пайдаланушыларға қатысты: пайдаланушы өзіне жаза алмауы керек.
    • Following (Жазылғандар): навигация жолағындағы «Following» сілтемесі пайдаланушыны ағымдағы пайдаланушы жазылған адамдардың барлық жазбасын көретін бетке апаруы керек. Бұл бет «All Posts» бетіндей жұмыс істеуі тиіс, тек жазбалар жиыны шағынырақ. Бұл бет тек жүйеге кірген пайдаланушыларға қолжетімді болуы керек.
    • Pagination (Беттеу): жазбалар көрсетілетін кез келген бетте бір бетке тек 10 жазба көрсетілуі керек. Он жазбадан көп болса, келесі жазбалар бетіне апаратын «Next» түймесі пайда болуы керек (ол бет қазіргіден ескірек жазбаларды көрсетеді). Бірінші бетте болмасаңыз, алдыңғы бетке апаратын «Previous» түймесі де көрінуі керек. Іске асыру жолдары туралы кеңесті төмендегі Кеңестер бөлімінен қараңыз.
    • Edit Post (Жазбаны өңдеу): пайдаланушылар өз жазбаларының кез келгенінде «Edit» түймесін (не сілтемесін) басып, жазбаны өңдей алуы керек.
      • Пайдаланушы өз жазбасының «Edit» түймесін басқанда, жазба мазмұны орнына жазбаны өңдеуге болатын textarea шығуы керек.
      • Содан кейін пайдаланушы өңделген жазбаны «Save» арқылы сақтай алуы керек. JavaScript арқылы мұны бүкіл бетті қайта жүктемей жасау керек.
      • Қауіпсіздік үшін қосымшаңыз ешбір жолмен пайдаланушының басқа адамның жазбасын өңдей алмайтындай жасалуы керек.
    • «Like» және «Unlike»: пайдаланушылар кез келген жазбаға түйме не сілтеме арқылы «лайк» басып-алып тастай алуы керек. JavaScript арқылы серверге лайк санын жаңарту туралы асинхронды түрде хабарлаңыз (мысалы, fetch шақыруымен), сосын бетте көрсетілген жазба лайктарының санын бүкіл бетті қайта жүктемей жаңартыңыз.

    Кеңестер (Hints)

    • fetch шақыруларының JavaScript мысалдары үшін 3-жобадағы кейбір маршруттарды қарап шығуға болады.
    • Қажетті мәліметті сақтау үшін network/models.py файлында бір не бірнеше модель жасауыңыз және/немесе бар User моделін өзгертуіңіз керек шығар.
    • Django-ның Paginator класы беттеуді серверде (Python кодында) жасауға көмектеседі.
    • Bootstrap-тың Pagination мүмкіндіктері беттерді алдыңғы жақта (HTML-де) көрсетуге көмектеседі.
