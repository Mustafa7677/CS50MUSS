Мазмұны

    1-апта

    Git

    Кодты қалай сақтаймыз, командамен қалай бөлісеміз, қате жасасақ қалай артқа қайтамыз? Git пен GitHub: коммиттер, тармақтар, біріктіру, fork, pull request және GitHub Pages.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)
    Бұл апта не туралы

    Бұл жолы код жазбаймыз, жазылған кодты қалай сақтау мен бөлісуді үйренеміз. Git - кез келген бағдарламашының күнделікті құралы: онсыз бірде-бір жоба, бірде-бір команда жұмыс істемейді. Интернет жоқ жерде де, терминал мен браузер ғана болса, барлығын бір апта ішінде үйреніп алуға болады. Алдағы Django, JavaScript апталарының бәрінде код GitHub-та жатады.

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен командалардың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Кіріспе

    Қайта қош келдіңіздер! Нөлінші лекцияда HTML, CSS және Sass арқылы қарапайым веб-беттер жасауды үйрендік. Ал бүгін мүлде басқа сұрақ қоямыз: бет жасалып қойған соң, оны қалай сақтаймыз? Егер екі адам бір сайтты бірге жасаса ше? Ал кеше жұмыс істеп тұрған код бүгін бұзылып қалса, кешегі нұсқаға қалай оралуға болады?

    Мектепте реферат жазғанда файлды «реферат_нұсқа1», «реферат_нұсқа2», «реферат_СОҢҒЫ», «реферат_СОҢҒЫ_шын» деп сақтап жүргеніңіз есіңізде ме? Міне, дәл осы қиындықты Git автоматты түрде, әрі әлдеқайда ақылды түрде шешеді. Бүгін Git пен GitHub-ты үйренеміз.

    Git

    Git - команда жолынан (терминалдан) жұмыс істейтін құрал. Оның міндетін нұсқаларды басқару (version control) деп атайды. Нақтырақ айтқанда, Git бізге мына төрт нәрсені береді.

    • Өзгерістерді қадағалау. Git кодымыздың белгілі бір сәттегі «суретін» сақтап қояды. Бұл суреттің аты - коммит (commit). Файлды өзгерткен сайын жаңа сурет түсіре аламыз да, бүкіл тарихты көре аламыз.
    • Адамдар арасында синхрондау. Бір жобамен бірнеше адам жұмыс істей алады. Әрқайсысы интернеттегі ортақ репозиторийден ақпаратты тартып алады (pull) және өз өзгерісін оған жібереді (push).
    • Тармақтар. Негізгі кодты бұзбай, бөлек тармақта (branch) жаңа нәрсені сынап көруге болады. Ұнаса, кейін екеуін біріктіреміз.
    • Артқа қайту. Қате жасап алсақ, кодтың бұрынғы жұмыс істеген нұсқасына оралуға болады.

    Сызбаға қараңыз: әр коммит - сол сәттегі бүкіл жобаның суреті. Үшінші коммитте script.js қосылған, ал бірінші коммитте әлі тек index.html бар. Қалаған кезде осы суреттердің кез келгеніне қайта ораламыз.

    Жоғарыда «репозиторий» дедік, бірақ оның не екенін айтпадық. Репозиторий (repository) - бір жобаға қатысты барлық файлдар сақталатын орын. Ол екі түрлі болады: қашықтағы (remote), яғни интернетте сақталған, және жергілікті (local), яғни сіздің компьютеріңіздегі. Ең басты ұғым осы: бір жобаның бірнеше көшірмесі бар, ал Git солардың арасын байланыстырады.

    GitHub

    GitHub - Git репозиторийлерін интернетте сақтайтын сайт. Git - құрал, ал GitHub - сол құралмен жасалған жұмыс сақталатын «қойма». Дәл осылай электрондық пошта хаты бар да, оны сақтайтын Gmail бар.

    Алдымен интернетте жаңа репозиторий жасап көрейік.

    1. GitHub-та аккаунтыңыз бар екеніне көз жеткізіңіз. Жоқ болса, github.com/join бетінен тіркеліңіз.
    2. Жоғарғы оң бұрыштағы + белгісін басып, «New repository» таңдаңыз.
    3. Репозиторийге жобаңызды сипаттайтын ат беріңіз.
    4. (Міндетті емес) Репозиторийдің сипаттамасын жазыңыз.
    5. Репозиторий жария (public, интернеттегі кез келген адам көреді) немесе жеке (private, тек сіз және өзіңіз рұқсат берген адамдар көреді) болатынын таңдаңыз.
    6. (Міндетті емес) README қосуды таңдаңыз. README - репозиторий туралы сипаттама жазылатын файл.

    Репозиторий дайын болды. Бірақ ол әзірге интернетте ғана тұр, ал бізге оған файл қосу керек. Ол үшін қашықтағы репозиторийдің компьютерімізде көшірмесін жасаймыз. Бұл әрекетті клондау (clone) дейді. Нәтижесінде компьютерімізде жергілікті репозиторий пайда болады.

    1. Терминалға git деп жазып, Git орнатылғанын тексеріңіз. Орнатылмаған болса, git-scm.com/downloads бетінен жүктеңіз.
    2. Репозиторийіңіздің бетіндегі жасыл «Code» (бұрын «Clone or Download») түймесін басып, ашылған сілтемені көшіріп алыңыз. README жасамаған болсаңыз, сілтеме беттің жоғарғы жағындағы «Quick Setup» бөлімінде тұрады.
    3. Терминалда мынаны орындаңыз:
    $ git clone <репозиторий сілтемесі>
Cloning into 'my-site'...
warning: You appear to have cloned into an empty repository.

    README қоспаған болсаңыз, «You appear to have cloned into an empty repository» деген ескерту шығады. Қорықпаңыз, бұл қалыпты жағдай: репозиторий жай ғана бос. Әрі қарай:

    1. ls командасы ағымдағы қалтадағы файлдар мен қалталарды көрсетеді. Енді жаңа ғана клондаған репозиторийдің атын көресіз.
    2. cd <репозиторий аты> арқылы сол қалтаға кіріңіз.
    3. touch <жаңа файл аты> командасымен жаңа файл жасаңыз, енді оны өзгерте аласыз. Балама: қалтаны мәтін редакторында ашып, файлды қолмен қосуға болады.
    4. Git жаңа файлды қадағалауы үшін оған айту керек: git add <файл аты> бір файлды, ал git add . қалтадағы барлық файлды қадағалауға қосады.
    $ ls
my-site
$ cd my-site
$ touch index.html
$ git add index.html

    Коммиттер

    Міне, Git-тің шын мәнінде пайдалы жері осы жерден басталады. Файлға өзгеріс енгізген соң, оны коммит жасай аламыз, яғни кодтың қазіргі күйінің суретін түсіреміз. Ол үшін:

    $ git commit -m "some message"

    Тырнақшадағы хабарда нақты не өзгергенін қысқаша жазасыз: «Бастапқы бет қостым», «Түймені түзеттім». Үш айдан кейін тарихқа қарағанда осы хабарлар сізді құтқарады, сондықтан «жаңа» не «қате түзедім» деп ғана жазудан аулақ болыңыз.

    Сызбада өзгерістің қалай жүретіні көрсетілген. Файлдарды жұмыс қалтасында өзгертесіз, git add оларды коммитке дайындайды (бұл аралық орынды дайындық аймағы деп атайды, ағылшынша staging area), git commit суретті жергілікті репозиторийге сақтайды, ал git push оны GitHub-қа жібереді. Қайтарым жолы да бар: git pull GitHub-тағы өзгерісті сізге әкеледі.

    Коммиттен кейін git status командасын орындасақ, жергілікті кодымыздың қашықтағы репозиторийге қатысты күйін көреміз:

    $ git status
On branch main
Your branch is ahead of 'origin/main' by 1 commit.
  (use "git push" to publish your local commits)

nothing to commit, working tree clean

    «Ahead by 1 commit» дегені: сізде GitHub-та әлі жоқ бір коммит бар. Оны жариялауға дайын болған кезде:

    $ git push

    Енді GitHub бетін браузерде жаңартсаңыз, өзгерістеріңізді сол жерден көресіз.

    Бір ыңғайлы лайфхак. Егер файлдарды жаңадан жасамай, тек бар файлдарды өзгерткен болсаңыз, git add . пен git commit ... командасының орнына екеуін бірден орындайтын қысқа команда бар:

    $ git commit -am "some message"

    Бұл команда сіз өзгерткен барлық бұрыннан қадағаланатын файлды коммитке қосады. Назар аударыңыз: ол жаңа файлдарды қосмайды, олар үшін git add бәрібір керек.

    Кейде керісінше болады: GitHub-тағы нұсқа компьютеріңіздегіден жаңарақ болып шығады (мысалы, серіктесіңіз код жіберіп қойды). Онда алдымен өз өзгерістеріңізді коммит жасап, сосын:

    $ git pull

    Бұл қашықтағы өзгерістерді сіздің жергілікті репозиторийіңізге алып келеді.

    Үшеуінің қарым-қатынасы осындай: Ана код жазып, push жасайды, Дәурен pull жасап, жаңалықты алады, өз өзгерісін қосып push жасайды, Ана қайтадан pull жасайды. GitHub - ортақ қойма болғандықтан, екеуі де бір-бірінің жұмысын көреді.

    Біріктіру қайшылықтары

    Бірге жұмыс істегенде міндетті түрде кездесетін мәселе бар: біріктіру қайшылығы (merge conflict). Ол екі адам бір файлды бір-біріне қайшы етіп өзгерткенде пайда болады. Қарапайым мысал: Ана да, Дәурен де бір жолды өзгертті, бірақ әрқайсысы өзінше. Git «қайсысын қалдыруым керек?» деп қиналып қалады да, шешімді адамға қалдырады.

    Қайшылық әдетте git push немесе git pull жасағанда шығады. Сондайда Git файлды автоматты түрде өзгертіп, қайшылықтың қайда екенін анық көрсететін пішінге келтіреді. Мысалы, бір жолға екі адам әртүрлі мән жазған жағдай:

    a = 1
<<<<<<< HEAD
b = 2
=======
b = 3
>>>>>>> 56782736387980937883
c = 3
d = 4
e = 5

    Мұнда сіз b = 2 деген жолды қостыңыз, ал басқа біреу b = 3 деп жазды. Енді біреуін таңдауымыз керек. <<<<<<< HEAD пен ======= арасындағы бөлік - сіздікі, ======= пен >>>>>>> арасындағы бөлік - екінші адамдікі. Ұзын санды хэш (hash) дейді: ол сіздің өзгерісіңізбен қайшылыққа түскен коммитті білдіреді.

    Белгілердің саны

    Лекция конспектісінде белгілер бес таңбамен жазылған, ал нақты Git жеті таңба (<<<<<<<, =======, >>>>>>>) қояды. Мәні бірдей. Қайшылықты түзеткен соң, осы үш белгі жолын міндетті түрде өшіріп тастау керек, әйтпесе олар кодыңыздың бір бөлігіне айналып кетеді.

    Мұны қолмен өшірудің қажеті жоқ: көптеген мәтін редакторлары (VS Code сияқты) қайшылықты бөлектеп көрсетіп, «Accept Current» (менікін қалдыр) және «Accept Incoming» (келгенін қалдыр) деген түймелер ұсынады. Түймені басасыз, белгілер өздігінен жойылады. Екеуін де қалдырғыңыз келсе, файлды қолмен өңдеп аласыз. Түзеткен соң файлды қайта add және commit жасайсыз, қайшылық шешілді.

    Ойланып көріңіз: екеуі де бір файлды өзгертсе, қайшылық міндетті түрде шыға ма?

    Жоқ. Қайшылық тек екеуі бір жолды (немесе іргелес жолдарды) әртүрлі етіп өзгерткенде шығады. Ана файлдың жоғарғы жағын, Дәурен төменгі жағын өзгертсе, Git екі өзгерісті өздігінен біріктіреді. Сондықтан командада жұмысты бөліп алу қайшылықтарды азайтады.

    Тарихты көру: git log

    Тағы бір пайдалы команда - git log. Ол репозиториядағы барлық коммиттердің тарихын көрсетеді:

    $ git log
commit e92b1c4a7f03d18c5b6e2a9d0f4817c3b5a6d2e1 (HEAD -> main, origin/main)
Author: Ana <ana@example.com>
Date:   Mon Jan 8 14:32:10 2024 +0500

    Бастапқы бет

    Әр коммитте ұзын хэш, автор, уақыт және сіз жазған хабар бар. Міне, жақсы хабардың пайдасы осында. Хэш - әр коммиттің жеке «жеке куәлік нөмірі».

    Артқа қайту: git reset

    Одан да пайдалысы: қате жасап алғаныңызды түсінсеңіз, алдыңғы коммитке қайта аласыз. Ол үшін git reset командасы бар, екі түрлі қолданылады.

    • git reset --hard <коммит> кодыңызды көрсетілген коммиттен кейінгі күйге дәл қайтарады. Коммитті көрсету үшін git log арқылы тапқан хэшті қолданасыз.
    • git reset --hard origin/master кодыңызды GitHub-та сақталған нұсқаға қайтарады. Жергілікті өзгерістерді «жоққа шығарып», GitHub-тағыға оралғыңыз келгенде керек.
    $ git reset --hard 7c3d9a05
HEAD is now at 7c3d9a0 Стиль қостым
    Абай болыңыз

    --hard коммит жасалмаған өзгерістерді мәңгіге өшіреді. Мұны жасамас бұрын не жоғалатыныңызды ойлаңыз. Және бір ескерту: бұрынғы Git нұсқаларында негізгі тармақ master деп аталатын, қазір GitHub оны әдепкіде main деп атайды. Лекцияда master айтылады, ал сіздің репозиторийіңізде main болуы мүмкін. Екеуі де бір нәрсе.

    Тармақтау

    Жобаңызбен біраз жұмыс істедіңіз делік. Енді соған жаңа функция қосқыңыз келеді. Қарапайым жол - жаңа функцияның коммиттерін де сол бір жолға жалғай беру:

    Бірақ мынандай жағдай болса ше? Бір күні бастапқы кодта қате (баг) табылды, оны түзеткіңіз келеді, ал жаңа функция әлі аяқталмаған. Түзеткен кезде жаңа функцияның жартылай жазылған коды да араласып кетеді. Дәл осы жерде тармақтау керек болады.

    Тармақтау дегеніміз - жаңа функцияны бөлек бағытта жазып, дайын болған соң ғана негізгі бөлікпен, яғни негізгі тармақпен біріктіру. Мұны ағаштың бұтағына ұқсатуға болады: діңі (main) өсе береді, ал жаңа бұтақ (feature) бөлек өседі де, пісіп жетілген соң діңге қайта қосылады.

    Сызбада main жолы жоғарыда, feature тармағы төменде. C2 коммитінен кейін жаңа тармақ бөлініп, C4a мен C4b коммиттері сонда жиналды. Сол уақытта main-де жұмыс жалғасып, C3 қосылды. Соңында екі жол M коммитінде қосылды.

    Қазіргі уақытта қай тармақта тұрғаныңызды HEAD анықтайды. Ол екі тармақтың біріне нұсқап тұрады. Әдепкіде HEAD негізгі тармақты көрсетеді, бірақ біз басқа тармаққа да «ауыса» аламыз (ағылшынша check out дейді).

    Енді бұл нәрсені іс жүзінде қалай жасайтынымызды көрейік.

    1. git branch командасы қай тармақта тұрғаныңызды көрсетеді: оның атының сол жағында жұлдызша (*) болады.
    $ git branch
* main
    1. Жаңа тармақ жасау үшін git checkout -b <жаңа тармақ аты> орындаймыз. Бұл команда тармақты жасайды және бірден сол тармаққа ауысады.
    $ git checkout -b feature
Switched to a new branch 'feature'
$ git branch
* feature
  main
    1. Тармақтар арасында git checkout <тармақ аты> арқылы ауысасыз. Әр тармақтағы өзгерістерді сол тармақта коммит жасайсыз. Файлдарыңыз тармақты ауыстырған сайын сәйкесінше өзгеріп тұрады, ол өте таңқаларлық көрінеді.
    2. Екі тармақты біріктіруге дайын болғанда, қалдырғыңыз келетін тармаққа ауысасыз (көбіне негізгі тармақ) да, мынаны орындайсыз:
    $ git checkout main
Switched to branch 'main'
$ git merge feature
Updating 7c3d9a0..e92b1c4
Fast-forward
 script.js | 12 ++++++++++++
 1 file changed, 12 insertions(+)

    git merge push не pull сияқты жұмыс істейді, сондықтан бұл жерде де біріктіру қайшылықтары шығуы мүмкін. Шықса, жоғарыда үйренгеніміздей шешесіз.

    Қазіргі команда

    Жаңа Git нұсқаларында тармақ ауыстыру үшін жеке команда да бар: git switch <тармақ> және git switch -c <жаңа тармақ>. Олар git checkout мен git checkout -b командаларымен бірдей жұмыс істейді, тек оқуға оңай. Лекцияда checkout қолданылады, сондықтан біз де соны қолданамыз.

    Ойланып көріңіз: тармақты біріктіргенде қай тармақта тұру керек?

    Біріктіру қалатын тармақта жасалады. feature-ды main-ге қосқыңыз келсе, алдымен git checkout main, сосын git merge feature. Егер feature-де тұрып git merge main жазсаңыз, керісінше, негізгі тармақтың өзгерістерін өз тармағыңызға аласыз. Бұл да керек, бірақ мақсат басқа.

    GitHub-тың қосымша мүмкіндіктері

    Жоба үстінде жұмыс істегенде көмектесетін, тек GitHub-қа тән бірнеше мүмкіндік бар.

    Форк (Forking)

    GitHub пайдаланушысы ретінде сізде рұқсат бар кез келген репозиторийді форктай (fork) аласыз. Бұл дегеніміз - репозиторийдің иесі сіз болатын жеке көшірмесін жасау. Ол үшін беттің жоғарғы оң бұрышындағы «Fork» түймесін басасыз. Көшірме сіздің аккаунтыңызда пайда болады, онымен не істесеңіз де, түпнұсқаға әсер етпейді.

    Pull request

    Репозиторийді форктап, өз нұсқаңызға өзгеріс енгізген соң, сол өзгерістерді негізгі нұсқаға қосуды сұрағыңыз келуі мүмкін. Мұны pull request (қазақша «қосып алу сұрауы») деп атайды. Мысалы, Bootstrap-қа жаңа мүмкіндік қосқыңыз келсе, Bootstrap репозиторийін форктайсыз, өзгерістер жасайсыз да, pull request жібересіз. Оны Bootstrap-ты жүргізетін адамдар қарап шығады, ұнаса, қабылдайды.

    Адамдардың аздап өзгеріс жасап, оны негізгі репозиторийге қосуды сұрау үрдісі ашық бастапқы кодты бағдарламалық жасақтама (open source software) үшін өте маңызды. Мұндай бағдарламалардың коды ашық, оны көптеген әзірлеушілер бірге жазады. Біздің Linux, Python, Bootstrap сияқты құралдарымыз дәл осылай жасалған.

    GitHub Pages

    GitHub Pages - статикалық сайтты интернетке шығарудың ең оңай жолы. (Статикалық және динамикалық сайттардың айырмашылығын кейінірек үйренеміз.) Ол үшін:

    1. Жаңа GitHub репозиторийін жасаңыз.
    2. Репозиторийді клондап, өзгерістерді жергілікті түрде жасаңыз. Міндетті түрде index.html файлы болсын: ол сайттың бастапқы беті болады.
    3. Өзгерістерді GitHub-қа push жасаңыз.
    4. Репозиторийдің Settings бетіне барып, GitHub Pages бөліміне дейін төмен түсіңіз де, ашылмалы мәзірден негізгі тармақты (лекцияда master) таңдаңыз.
    5. Қайтадан GitHub Pages бөліміне барыңыз. Бірнеше минуттан кейін «Your site is published at: ...» деген хабарландыру пайда болады, онда сайтыңыздың сілтемесі көрсетіледі.

    Міне, бүгінгі лекция осымен біткен. Келесі жолы Python-ды үйренеміз!

    Қорытынды

    Бүгін Git пен GitHub-тың негізін үйрендік. Қысқаша қайталайық:

    • Git - нұсқаларды басқаратын құрал: өзгерістерді қадағалау, адамдар арасында синхрондау, тармақтау және артқа қайту.
    • репозиторий (қашықтағы және жергілікті) және GitHub қашықтағы репозиторийлерді сақтайтын сайт екені;
    • git clone, git add, git commit -m / git commit -am, git push, git pull, git status;
    • біріктіру қайшылығы және белгілері <<<<<<<, =======, >>>>>>>; оны қолмен немесе редактор көмегімен шешу;
    • git log арқылы тарихты көру; git reset --hard арқылы артқа қайту;
    • тармақтар: git branch, git checkout -b, git checkout, git merge; HEAD ұғымы;
    • GitHub мүмкіндіктері: fork, pull request, GitHub Pages.

    Өзіңізді тексеріңіз

    1. Ана GitHub-тағы репозиторийдің компьютерінде көшірмесін алғысы келеді. Қай команда керек?

    git clone қашықтағы репозиторийдің жергілікті көшірмесін жасайды. push керісінше, жергілікті коммиттерді GitHub-қа жібереді.

    2. Ана жаңа style.css файлын жасады. Содан кейін git commit -am "стиль" жазды. Не болады?

    -a тек бұрыннан қадағаланатын файлдардағы өзгерістерді қосады. Жаңа файл үшін алдымен git add орындау қажет.

    3. git commit жасадыңыз, бірақ GitHub бетінде өзгерісті көрмейсіз. Неге?

    Коммит - жергілікті сурет. GitHub-қа жіберу үшін бөлек git push қажет, git status «ahead by 1 commit» деп еске салады.

    4. Мына файлда не болды?

    <<<<<<< HEAD
title = "Басты бет"
=======
title = "Үй"
>>>>>>> 4f2a9c1

    <<<<<<<, ======= және >>>>>>> белгілері қайшылықты көрсетеді. Қалдыратын бөлікті таңдап, белгілерді өшірген соң, файлды қайта add және commit жасаймыз.

    5. feature тармағындағы жұмысты main-ге қосу үшін дұрыс ретті таңдаңыз.

    Біріктіру қалдыратын тармақта жасалады: алдымен main-ге ауысамыз, сосын feature-ды соған қосамыз.

    6. git branch шығысы мынадай болса, сіз қазір қай тармақтасыз?

      main
* login
  feature

    Қазіргі тармақтың атының сол жағында жұлдызша (*) тұрады. HEAD дәл соған нұсқап тұр.

    7. Біреудің ашық репозиторийіне өз түзетуіңізді ұсынғыңыз келеді, бірақ оған жазу рұқсатыңыз жоқ. Қалай жасайсыз?

    Ашық бастапқы кодты жобалардың дәстүрлі жолы осы: fork, өзгерту, pull request. Иесі қарап, қабылдауы немесе қабылдамауы мүмкін.

    8. Жобаңыздағы кодты екі коммит бұрынғы күйге қайтарғыңыз келеді, ал соңғы екі коммиттегі жұмысты керек етпейсіз. Қай команда сәйкес келеді?

    git log арқылы керекті коммиттің хэшін тауып, git reset --hard береміз. Соңғы коммиттер тарихтан алынып тасталады, сондықтан абай болу керек.

    Жаттығу

    Бұл апта үшін жеке тапсырмалар жинағы жоқ: алғашқы жоба (Project 0: Search) нөлінші аптаның материалына жатады. Бірақ Git тек оқумен үйренілмейді, қолмен жасау керек. Төменде бес-алты командадан тұратын шағын сеанс бар, сосын төрт жаттығу.

    Git сайтта жоқ

    Бұл сайтта нағыз Git жұмыс істемейді, сондықтан интерактивті терминал жасамадық. Орнына төмендегі терминал блоктарында командалардың нақты шығысын көрсетеміз. Командалар компьютеріңіздегі терминалда орындалады: Git орнатыңыз да, қатарынан қайталап көріңіз. Бұл жаттығулардың автотексерушісі жоқ, өзіңізді checklist арқылы тексересіз.

    Алты команданың бір сеансы

    Ең алдымен бос қалта жасап, ішінде репозиторий бастайық. Әр команданың астындағы шығысты өз терминалыңызда да көресіз.

    $ mkdir my-site
$ cd my-site
$ git init
Initialized empty Git repository in /home/ana/my-site/.git/
$ git status
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)

    git init қалтаны Git репозиторийіне айналдырады (ішінде жасырын .git қалтасы пайда болады). Енді бір файл жасап, күйді қайта қарайық:

    $ echo "<h1>Сәлем</h1>" > index.html
$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	index.html

nothing added to commit but untracked files present (use "git add" to track)
$ git add index.html
$ git status
On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
	new file:   index.html

    Байқадыңыз ба? Файл алдымен «Untracked» (қадағаланбайды) болды, git add-тен кейін «Changes to be committed» (коммитке дайын) болды. Бұл - жоғарыдағы дайындық аймағы. Енді коммит жасап, тарихты қараймыз:

    $ git commit -m "Бастапқы бет"
[main (root-commit) a1f04e7] Бастапқы бет
 1 file changed, 1 insertion(+)
 create mode 100644 index.html
$ git log --oneline
a1f04e7 (HEAD -> main) Бастапқы бет
$ git branch
* main
    Оңай

    Алғашқы репозиторий

    Жоғарыдағы сеансты өз компьютеріңізде қайталаңыз, бірақ өз сайтыңызбен. git init жасаңыз, index.html мен style.css файлдарын жасаңыз. Алдымен тек біреуін git add етіп, git status шығысын қараңыз: екінші файл қай бөлімде тұр? Сосын екеуін де қосып, екі бөлек коммитке бөліңіз: «Бет қостым», «Стиль қостым». Соңында git log жасаңыз.

    Кеңес

    Екі бөлек коммит жасау үшін: git add index.html, git commit -m "Бет қостым", сосын git add style.css, git commit -m "Стиль қостым". git log --oneline тарихты бір жолға сыйғызып көрсетеді.

    Тексеру
    • git status жаңа файлды «Untracked files» ретінде көрсетті, git add-тен кейін «Changes to be committed» болды.
    • git log екі коммитті екі түрлі хабармен көрсетеді.
    • git status соңында «nothing to commit, working tree clean» дейді.

    Орташа

    Тармақ жасап, біріктіру

    Алдыңғы репозиторийде git checkout -b contact орындаңыз. contact.html файлын жасап, коммит жасаңыз. Сосын git checkout main жасап, ls шығысын қараңыз: contact.html қайда кетті? Содан кейін git merge contact жасап, ls шығысын қайта қараңыз.

    $ git checkout -b contact
Switched to a new branch 'contact'
$ touch contact.html
$ git add contact.html
$ git commit -m "Байланыс беті"
$ git checkout main
$ ls
index.html  style.css
$ git merge contact
$ ls
contact.html  index.html  style.css

    Мұндағы шығыс - сіздің компьютеріңізде шығуы тиіс нәрсе. Егер шығыс өзгеше болса, неге екенін ойланыңыз.

    Кеңес

    contact.html файлы main-ге ауысқанда жоғалып кетеді, өйткені ол тек contact тармағының коммитінде бар. merge-ден кейін ол main-ге де келеді. Тармақты біріктіру кезінде қай тармақта тұрғаныңызды git branch арқылы тексеріңіз.

    Тексеру
    • git branch екі тармақты көрсетеді, жұлдызша қазіргі тармақтың жанында тұр.
    • main-ге ауысқанда contact.html көрінбейді, ал merge-ден кейін пайда болады.

    Орташа

    Қайшылықты шешу

    Әдейі қайшылық жасап көріңіз. main-де index.html ішіндегі тақырыпты <h1>Басты бет</h1> етіп өзгертіп, коммит жасаңыз. Сосын git checkout contact тармағына өтіп, сол index.html жолын <h1>Үй</h1> етіп өзгертіңіз, коммит жасаңыз. Соңында git checkout main жасап, git merge contact орындаңыз. Git мынаны айтады:

    $ git merge contact
Auto-merging index.html
CONFLICT (content): Merge conflict in index.html
Automatic merge failed; fix conflicts and then commit the result.

    index.html файлын ашсаңыз, мынаны көресіз:

    <<<<<<< HEAD
<h1>Басты бет</h1>
=======
<h1>Үй</h1>
>>>>>>> contact

    Тапсырма: қай жолдың қайсысының өзгерісі екенін анықтаңыз, «Басты бет» нұсқасын қалдырыңыз, белгілерді өшіріңіз, сосын git add index.html және git commit жасаңыз.

    Кеңес

    HEAD белгісінен кейінгі бөлік - сіз тұрған тармақтың (main) нұсқасы, ал =======-тен кейінгісі - contact тармағынан келгені. Соңында файлда тек <h1>Басты бет</h1> жолы қалуы керек. Біріктіруді git commit аяқтайды, жаңа хабар жазбасаңыз да, Git өзі ұсынады.

    Тексеру
    • Git қайшылық туралы хабар шығарды және файлда үш белгі жолы пайда болды.
    • Түзетілген файлда <<<<<<<, =======, >>>>>>> белгілері қалған жоқ.
    • git log біріктіру коммитін көрсетеді.

    Күрделі

    GitHub-қа жіберіп, сайт жариялау

    GitHub-та жаңа жария репозиторий жасаңыз, клондаңыз, ішіне index.html салыңыз (кез келген мазмұн), add, commit, push жасаңыз. Сосын Settings бетінде GitHub Pages-ті қосып, сайтыңыздың сілтемесін ашыңыз. Одан кейін бетке бір сөйлем қосып, қайтадан git commit -am және git push жасаңыз; бірнеше минуттан кейін сайт жаңарғанын тексеріңіз.

    Ойланып көріңіз: git commit -am жаңа файлды неге қоспайды?

    -a тек Git бұрыннан білетін (қадағалап жүрген) файлдарға әсер етеді. Жаңа файл Git үшін «бейтаныс», оны бір рет git add арқылы таныстыру керек. Содан кейін ол да бұрыннан қадағаланатын файлға айналады.

    Кеңес

    Pages баптауы GitHub-тың интерфейсіне байланысты өзгеріп тұрады: «Settings», сосын «Pages» бөлімінен «Deploy from a branch» және негізгі тармақты таңдайсыз. Сайт сілтемесі әдетте https://<аты>.github.io/<репозиторий>/ түрінде болады.

    Тексеру
    • Репозиторий GitHub-та, index.html файлы онда көрінеді.
    • GitHub Pages сілтемесі ашылып, бетіңізді көрсетеді.
    • Екінші push-тен кейін бет жаңарды.
