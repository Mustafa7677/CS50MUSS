    Flask

    Python мен SQL-ды вебке қайтарамыз: Flask фреймворкі, маршруттар, Jinja шаблондары, GET және POST, Frosh IMs тіркеу сайты, cookie мен сессиялар, дүкен себеті, MVC, API және JSON.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)

    Кіріспе

    Бұл CS50, 9-апта. Бұл апта курстан кейін бағдарламалауды жалғастырсаңыз, шын өмірде істейтініңізге ең жақын. Оған ең ұқсасы 6-апта болды: онда жаңа ұғымдар аз еді, біз бәрін C-дан Python-ға аудардық. Бұл аптаның мақсаты — соңғы 10 аптаны біріктіру. Құралдар жәшігіңіздегі құрылыс блоктарын жаңа мәселеге, веб-бағдарламалауға қолданамыз.

    Өткен аптада HTML, CSS және клиент жағындағы JavaScript-ті көрдік. Бүгін сервер жағын қайтарамыз: қайтадан Python мен SQL жазып, өз толыққанды веб-қосымшаларымызды жасаймыз.

    Статикалық беттерден маршруттарға

    Өткен аптада http-server қолдандық. Ол ағымдағы қалтадағы файлдарды жай статикалық түрде таратады. URL-дер нақты файлға сілтейтін: /file.html, /folder/, /folder/file.html. Жалпы айтқанда, бұл сервердегі жол (path).

    Бүгін URL-дегі осы бөлікті маршрут (route) деп атаймыз. Ол енді міндетті түрде файл емес: доменнен кейінгі бөлікті талдап, оны серверге жай кіріс ретінде қолданамыз. Параметрлер бұрынғыдай: /route?key=value&key=value. Google-да мысықтарды іздегенде, конвертте мынау болды:

    GET /search?q=cats HTTP/2
Host: www.google.com

    /search — search.html емес, қалта да емес. Бұл Google серверінде жұмыс істейтін бағдарламаның аты, яғни біз бүгін өзіміз бағдарламалайтын маршрут.

    Flask

    Веб-серверді C-да жазу азап болар еді: тым төменгі деңгейлі тіл. Python-да да бәрін нөлден жасасақ, конверттің ішін талдап, кірістерді шығарып алатын көп код жазу керек. Әлем әдетте мұны қайта ойлап таппайды. Біз Flask қолданамыз. Бұл фреймворк, дәлірек айтқанда микрофреймворк: басқалар жазған кітапхана, ол GET және POST сұрауларын өңдеу, URL-ден кілт-мән жұптарын алу сияқты кез келген веб-қосымшаға керек «тауарлық» жұмысты істейді. Bootstrap сияқты, фреймворк — кітапхана және оны қолдану келісімдері. Оларды құжаттамадан не осындай курстан үйренесіз.

    http-server-дің орнына енді мына команданы іске қосамыз:

    $ flask run

    Ол ағымдағы қалтадан келісімге сай кодты іздейді. Ең аз дегенде app.py файлы керек. Сондай-ақ келісім бойынша requirements.txt файлы болады: ішінде қосымша қолданатын кітапханалардың аттары, әр жолға біреуден. Flask-ты өзіңіз орнатуға болады:

    $ pip install flask

    Ал requirements.txt болса, кітапханаларды есте сақтап, қолмен теріп отырудың қажеті жоқ.

    Ең қарапайым қосымша

    from flask import Flask

app = Flask(__name__)


@app.route("/")
def index():
    return "hello, world"
    • from flask import Flask — flask пакетінен (кіші әріппен) Flask функциясын (бас әріппен) аламыз. Бұл көшіріп қоятын жол.
    • app = Flask(__name__) — «осы файлды Flask қосымшасына айналдыр». __name__ — ағымдағы файлдың аты, 6-аптадағы if __name__ == "__main__": есіңізде ме?
    • @app.route("/") — Python декораторы (decorator): келесі функцияның мінезіне әсер ететін функция. «/ маршрутын index функциясымен байланыстыр».
    • Функцияны кез келген атпен атауға болады, бірақ / сайттың әдепкі беті болғандықтан, келісім бойынша index.

    flask run іске қосылғанда, жасыл батырма шығады. http-server 8080 портын қолданатын, ал Flask әдепкіде 5000 портын қолданады. Браузерде «hello, world» көрінеді. Бірақ View page source ашсаңыз, HTML жоқ, тек бір жол мәтін. Әзірлеуші құралдары браузердің бос орындарды өзі толтырғанын көрсетеді.

    Толық HTML-ді Python жолы ретінде қайтаруға болар еді, бірақ бұл ақымақтық. HTML-ді бөлек файлға шығарайық:

    from flask import Flask, render_template

app = Flask(__name__)


@app.route("/")
def index():
    return render_template("index.html")

    render_template HTML шаблонын «шығарады». Flask құжаттамасы бойынша HTML файлдарын templates атты қалтаға салу керек (бас әріптер маңызды). Сонымен құрылым мынадай:

    app.py
requirements.txt
templates/
    index.html

    URL-ден кіріс алу

    ?name=David берсек, «hello, David» көргіміз келеді. URL-ді ?, =, & бойынша өзіміз бөлшектеудің қажеті жоқ: Flask-та request.args деген арнайы глобалды айнымалы бар. args — HTTP сұрауымен берілген аргументтер (параметрлер).

    from flask import Flask, render_template, request

app = Flask(__name__)


@app.route("/")
def index():
    name = request.args["name"]
    return render_template("index.html", placeholder=name)

    render_template-ке 6-аптадағы атаулы аргумент беріп отырмыз. Ал шаблонда:

    <!DOCTYPE html>

<html lang="en">
    <head>
        <title>hello</title>
    </head>
    <body>
        hello, {{ placeholder }}
    </body>
</html>

    Қос фигуралы жақша Flask-қа айнымалының мәнін қою (interpolate) керегін айтады. Бұл — тағы бір синтаксис: Python-да f-жолдар, C-да %s болды. Енді ?name=David → «hello, David», ?name=Kelly → «hello, Kelly». JavaScript мысалдарынан айырмашылығы: View page source көрсеткендей, «David» сөзі серверден келді.

    Термин: Jinja және шаблон Flask Jinja деген басқа кітапхананы қолданады. Ол шаблондау тілі (templating language): қос фигуралы жақшадағы айнымалылардың орнына мәнді қоюды біледі. Flask авторлары бұл дөңгелекті қайта ойлап таппады. Шаблон — пайдаланушы көретін беттің жобасы (blueprint), ол мәндерді қою арқылы динамикалық түрде жасалады. Сондықтан ол templates қалтасында.

    Бірақ қате бар: параметрсіз /-ге кірсек, 400 Bad Request шығады, яғни пайдаланушы күтілген параметрді бермеді. URL-ді ешкім қолмен термейді, бұл бизнес үшін жаман. Шарт қосайық:

    @app.route("/")
def index():
    if "name" in request.args:
        name = request.args["name"]
    else:
        name = "world"
    return render_template("index.html", placeholder=name)

    ?name= деп мәнсіз берсек, «hello,» ғана шығады: кілт бар, бірақ мәні жоқ. Бұл өрнек соншалық жиі қолданылатындықтан, қысқа жолы бар:

    @app.route("/")
def index():
    name = request.args.get("name", "world")
    return render_template("index.html", name=name)

    get (HTTP етістігіне қатысы жоқ) — «маған мынаны бер, болмаса әдепкі мәнді бер». Төрт жол бір жолға айналды. name=name оғаш көрінеді, бірақ Flask-та бұл келісім: сол жақтағысы — шаблондағы айнымалының аты, оң жақтағысы — мәні. Шаблонда енді hello, {{ name }}.

    Формалар және екінші маршрут

    Пайдаланушыны URL теруге мәжбүрлемей, форма көрсетейік. index.html:

    <form action="/greet" method="get">
    <input autocomplete="off" autofocus name="name" placeholder="Name" type="text">
    <button type="submit">Greet</button>
</form>

    Мұндағы name="name" — HTML атрибуты, Python-дағы name емес. action="/greet" — біз ойлап тапқан маршрут. Оны app.py-ге қосамыз:

    @app.route("/")
def index():
    return render_template("index.html")


@app.route("/greet")
def greet():
    return render_template("greet.html", name=request.args.get("name", "world"))

    Функция атын маршрутпен бірдей қойдық: шешім саны азаяды. Форманы жібергенде, URL /greet?name=David болады. Google-дан айырмашылығы: action өз серверімізде. Бірақ 500 Internal Server Error шығады! Бұл «сенің кінәң» дегенді білдіреді. Пайдаланушыға тек жалпы қара-ақ хабар көрінеді: сервердегі қателерді көрсету киберқауіпсіздік үшін жаман. Ал flask run іске қосылған терминалда:

    jinja2.exceptions.TemplateNotFound: greet.html

    Мен жай greet.html-ды жасамадым. Оны жасағаннан кейін бәрі жұмыс істейді. (Екі терминал ыңғайлы: біреуінде сервер жұмыс істеп тұрады, екіншісінде команда тересіз.)

    Шаблондарды мұралау: layout.html

    index.html мен greet.html салыстырсақ, форма мен «hello» бөлігінен басқа бәрі бірдей. Үш, төрт, бес маршрут болса, бірдей HTML-ді қайта-қайта жазу ақымақтық. Ортақ бөлікті layout.html-ге шығарамыз (Flask құжаттамасындағы келісім):

    <!DOCTYPE html>

<html lang="en">
    <head>
        <meta name="viewport" content="initial-scale=1, width=device-width">
        <title>hello</title>
    </head>
    <body>
        {% block body %}{% endblock %}
    </body>
</html>

    {% ... %} — Jinja тегтері. block body — body деп атаған (кез келген атау болар еді) блок. Бұл бір сөз емес, тұтас код блогына арналған орын. HTML авторлары бұрыштық жақшаларды, Jinja авторлары фигуралы жақша мен пайыз белгісін таңдады: олар кәдімгі HTML-мен шатаспайды.

    Енді index.html:

    {% extends "layout.html" %}

{% block body %}

    <form action="/greet" method="get">
        <input autocomplete="off" autofocus name="name" placeholder="Name" type="text">
        <button type="submit">Greet</button>
    </form>

{% endblock %}

    және greet.html:

    {% extends "layout.html" %}

{% block body %}

    hello, {{ name }}

{% endblock %}

    Беттер оғаш көрінеді, бірақ олар мәніне дейін «сығылды». viewport тегі бетті мобильді құрылғыларға бейімдейді: онсыз телефонда бәрі кішкентай болады. Браузерге жіберілген HTML-де шегіністер онша әдемі емес, бірақ браузерге бәрібір.

    GET-тен POST-қа

    Неге әр мысалда атымыз URL-де көрінеді? GET осылай жұмыс істейді: параметрлер URL-ге жазылып, браузер тарихында сақталады. Қызық бауырыңыз браузеріңізге отырса, бәрін көреді. Ал бұл аты емес, пайдаланушы аты, құпиясөз, карта нөмірі болса ше? GET Google іздеуі сияқты маңызы аз нәрселерге, не тікелей сілтеме беруге ыңғайлы. Ал POST деректерді конверттің тереңіне салады: URL-де көрінбейді, бірақ сервер оқи алады.

    <form action="/greet" method="post">

    Енді URL жай /greet, бірақ 405 Method Not Allowed шығады. Flask маршруттар әдепкіде тек GET-ті қолдайды деп есептейді:

    @app.route("/greet", methods=["POST"])
def greet():
    return render_template("greet.html", name=request.form.get("name", "world"))

    Маңызды: GET параметрлері request.args-та, ал POST параметрлері request.form-да. Екеуі де формалардан келетіндіктен, атаулары түсініксіз, оны жай есте сақтау керек. Әзірлеуші құралдарының Network қойындысында сұрауды таңдап, Payload бөлімінде name: David деген форма деректерін көресіз. Gmail-ға кіргенде де өз пернетақтаңыз жіберген деректерді осылай көре аласыз.

    Бір маршрутпен

    Әр форма үшін екі маршрут (біреуі форманы көрсетеді, біреуі өңдейді) болса, маршруттар екі есе көбейеді. Біріктірейік:

    @app.route("/", methods=["GET", "POST"])
def index():
    if request.method == "POST":
        return render_template("greet.html", name=request.form.get("name", "world"))
    return render_template("index.html")

    Пайдаланушы мұнда POST арқылы келсе, демек форманы жіберді, сәлемдесеміз. Әйтпесе (GET, жай сайтқа кірді), форманы көрсетеміз. else жазудың қажеті жоқ: тек екі етістік қолдайтындықтан, GET болғаны анық. index.html-дағы action-ды "/"-ке өзгерту керек (не action-ды мүлде алып тастау: сонда форма өзі келген жерге жіберіледі).

    Логиканы шаблонға да қоюға болады. Jinja Python-ға ұқсас шарттарды қолдайды:

    {% extends "layout.html" %}

{% block body %}

    hello,
    {% if name %}
        {{ name }}
    {% else %}
        world
    {% endif %}

{% endblock %}

    «hello,»-дан кейін көп бос орын бар, бірақ HTML артық бос орындарды бір бос орынға жинайды.

    Frosh IMs

    Дэвид CS50-ді екінші курста оқығанда, курста веб-бағдарламалау болған жоқ, әлемде веб те әлі жаңа еді. Бірінші курс студенттерінің спорт бағдарламасына (freshman intramural sports, Frosh IMs) тіркелу үшін Matthews ғимаратынан Wigglesworth-қа қағаз парақ алып барып, проктордың есігінің астынан итеретін. Курстан кейін Дэвидтің алғашқы жобаларының бірі сол кезде танымал Perl тілі мен CSV файлдарын қолданып, тіркелуге арналған веб-сайт жасау болды. (Қайталанатын фон суреттері 1997 жылы да сәнді емес еді.) Соның бастамасын қайта жасайық.

    {% extends "layout.html" %}

{% block body %}
    <h1>Register</h1>
    <form action="/register" method="post">
        <input autocomplete="off" autofocus name="name" placeholder="Name" type="text">
        <select name="sport">
            <option disabled selected value="">Sport</option>
            <option value="Basketball">Basketball</option>
            <option value="Soccer">Soccer</option>
            <option value="Ultimate Frisbee">Ultimate Frisbee</option>
        </select>
        <button type="submit">Register</button>
    </form>
{% endblock %}
    • POST — бөлмелестер бір-бірінің қайда тіркелгенін тарихтан көрмеуі үшін.
    • select — ашылмалы мәзір. Еркін мәтіндік өріс қателерге, түрлі бас әріптерге толы болар еді. Мәзір пайдаланушының таңдауын стандарттайды.
    • option-ның value-і серверге жіберіледі, ал тегтер арасындағы мәтінді пайдаланушы көреді.
    • Басында баскетболды таңдап қою — пайдаланушы абайсызда тіркелуі мүмкін. Сондықтан мәні бос «Sport» нұсқасы әдепкіде таңдалған (selected).
    @app.route("/register", methods=["POST"])
def register():
    if not request.form.get("name") or not request.form.get("sport"):
        return render_template("failure.html")
    return render_template("success.html")

    Есімі не спорты жоқ болса, «You are not registered», әйтпесе «You are registered». (Дэвид екі рет тырнақшаны жабуды ұмытып, екі рет 500 қатесін алды. Терминал қатені тіпті астын сызып көрсетеді. Сол бетті қайта жүктесеңіз, браузер форманы қайта жіберуді растауды сұрайды.)

    Сервер жағында тексеру

    Студент волейболға тіркелгісі келсе ше? Әзірлеуші құралдарында Edit as HTML арқылы <option value="Volleyball">Volleyball</option> қосып, Келли «волейболға тіркелді». Пайдаланушы енгізгеніне ешқашан сенбеңіз. Абайсыздықтан, ақымақтықтан не, Келлидің жағдайындағыдай, әдейі. Шешімі — серверде тексеру.

    Спорттарды app.py-де де, index.html-да да қолмен жазу — қайталау. Глобалды тізім жасайық (бас әріптер — «өзгертпе» деген ар-ұждан келісімі, Python-да C-дағыдай const жоқ):

    SPORTS = [
    "Basketball",
    "Soccer",
    "Ultimate Frisbee"
]

    MVC

    Біздің қалтамыз: app.py, requirements.txt, static/, templates/. Бұл Flask-қа ғана тән емес жалпы парадигма, MVC (model–view–controller):

    • Controller (контроллер) — бизнес-логика: айнымалылар, функциялар, шарттар, циклдер. Біздің app.py.
    • View (көрініс) — пайдаланушы көретін және әрекеттесетін интерфейс. Біздің templates.
    • Model (модель) — тұрақты деректер. Алдымен жадтағы сөздік, сосын froshims.db.

    Шекара анық емес: көріністерде де айнымалылар, циклдер, шарттар бар. Бұл — мәселелерді ойлауға арналған ой үлгісі.

    Cookie

    Gmail-ға кіріп, «Келесі» батырмасын басқанда, браузер Google серверіне шамамен мынаны жібереді:

    POST / HTTP/2
Host: accounts.google.com
...

    Ішінде пайдаланушы аты мен құпиясөз. Бәрі дұрыс болса, сервер жауап береді, бірақ ішінде тағы бір тақырып бар:

    HTTP/2 200
Set-Cookie: session=value
...

    Cookie — компьютеріңізге орнатылатын кілт-мән жұбы. Оның жаман атағы бар: бақылау мен жарнамаға жиі қолданылады. Бірақ негізінде ол пайдалы HTTP мүмкіндігі. Google cookie-ге пайдаланушы аты мен құпиясөзді сақтаса, бұл қауіпті болар еді: бөлмелесіңіз оларды браузерден табады. Сондықтан әдетте үлкен кездейсоқ мән сақталады. Ертең Gmail-ды ашып, бір хатты бассаңыз, браузер сол cookie-ді қайта жібереді:

    GET / HTTP/2
Host: gmail.com
Cookie: session=value

    Бұл барға, клубқа не саябаққа кіргенде қолыңызға басылатын мөр сияқты: билетті бір рет көрсетесіз, сосын кіріп-шыққанда тек қолыңызды көрсетесіз. Set-Cookie — мөр басу, Cookie — мөрді көрсету. Жарнама берушілер де сізді осылай таниды. Incognito режимі терезені жапқанда cookie-лерді өшіреді, яғни мөрді сүртеді.

    Сессиялар

    Сессия (session) — HTTP күйсіз (stateless) болса да, яғни серверге тұрақты байланыс болмаса да, браузер мен сервер арасындағы тұрақты байланыстың иллюзиясы. Ноутбукты жауып, ертеңіне ашсаңыз да, «кірген» күйде қаласыз. Python тұрғысынан сессия — әр пайдаланушыға тиесілі кілт-мән сөздігі. Мөрді көрсету сервердің қай жұптар сізге тиесілі екенін білуін қамтамасыз етеді.

from flask_session import Session

app.config["SESSION_PERMANENT"] = False
app.config["SESSION_TYPE"] = "filesystem"

@app.route("/cart", methods=["GET", "POST"])
def cart():

    # Себет бар екеніне көз жеткізу
    if "cart" not in session:
        session["cart"] = []

    # POST
    if request.method == "POST":
        book_id = request.form.get("id")
        if book_id:
            session["cart"].append(book_id)
        return redirect("/cart")

    # GET
    books = db.execute("SELECT * FROM books WHERE id IN (?)", session["cart"])
    return render_template("cart.html", books=books)

Network қойындысы жауапта толық бет емес, тек li тегтері келгенін көрсетеді: search.html енді layout.html-ды кеңейтпейді.

    Бірақ контекстсіз HTML кесегін қайтарып, пайдаланушыны li қолдануға мәжбүрлеу онша таза емес. Шикі деректерді жіберген дұрыс. JSON (JavaScript Object Notation):

    • Flask — Python микрофреймворкі. flask run, 5000 порты. Құрылым: app.py, requirements.txt, templates/, static/.
    • @app.route("/path", methods=["GET", "POST"]) — маршрутты функциямен байланыстыратын декоратор.
    • render_template("file.html", key=value); redirect("/path"); jsonify(data).
    • GET параметрлері — request.args, POST параметрлері — request.form; .get(key, default), .getlist(key); request.method.
    • Jinja: {{ variable }}, {% if %}, {% for %}, {% extends "layout.html" %}, {% block body %}{% endblock %}.
    • Пайдаланушы енгізгеніне сенбеңіз: серверде тексеріңіз, SQL-да ? қолданыңыз. Деректерді өзгертетін әрекеттерге POST.
    • Cookie («қолдағы мөр»): Set-Cookie және Cookie тақырыптары. Сессиялар: session сөздігі, flask_session; кіру, шығу, сауда себеті.
    • MVC: модель (дерекқор), көрініс (шаблондар), контроллер (app.py).
    • API және JSON: бүкіл беттің орнына деректерді қайтару.

    Өзіңізді тексеріңіз

    1. Flask-та POST арқылы жіберілген форма деректері қайда?

    request.args — GET (URL) параметрлері.

    2. Маршрут тек GET-ті қолдаса, оған POST жіберсек, қандай код шығады?

    405 Method Not Allowed. methods=["POST"] қосу керек.

    3. Flask шаблондарды қай қалтадан іздейді?

    Суреттер, CSS, JS — static-та.

    4. {% extends "layout.html" %} не істейді?

    Ортақ HTML бір жерде жазылады, әр бет тек өз блогын анықтайды.

    5. Неге /deregister маршруты POST-ты қолдануы керек?

    Деректерді өзгертетін әрекеттер GET арқылы болмауы керек.

    6. Cookie-ге не сақтаған дұрыс?

    Деректердің өзі серверде сақталады, cookie — тек «мөр».

    7. MVC-да app.py қай рөлде?

    Шаблондар — View, дерекқор — Model.

    Жаттығулар

    Оңай

    Flask порты

    flask run әдепкіде қай портты қолданады?

    Орташа

    Квадрат

    Flask қосымшасын жазыңыз: /square?n=7 маршруты «49» шығарсын. n берілмесе не сан болмаса, «Invalid number» шығарсын.

    Шешімі
    from flask import Flask, request

app = Flask(__name__)


@app.route("/square")
def square():
    try:
        n = int(request.args.get("n", ""))
    except ValueError:
        return "Invalid number", 400
    return str(n * n)

    Flask-та функция (мәтін, код) қайтарса, сол күй кодымен жауап береді.

    Қиын

    Кіру санағышы

    Сессияны қолданып, пайдаланушы басты бетке неше рет кіргенін көрсетіңіз: «Сіз бұл бетке 3 рет кірдіңіз». /reset маршруты санағышты нөлдесін.

    Шешімі
    from flask import Flask, redirect, session
from flask_session import Session

app = Flask(__name__)
app.config["SESSION_PERMANENT"] = False
app.config["SESSION_TYPE"] = "filesystem"
Session(app)


@app.route("/")
def index():
    session["visits"] = session.get("visits", 0) + 1
    return f"Сіз бұл бетке {session['visits']} рет кірдіңіз"


@app.route("/reset")
def reset():
    session.clear()
    return redirect("/")

    Басқа браузерден (не Incognito-дан) кірсеңіз, санағыш бөлек болады: cookie әртүрлі.

    Орташа

    Birthdays

    Достардың туған күндерін сақтайтын веб-қосымша. birthdays.db-де birthdays кестесі бар: id, name, month, day.

    • index.html-да аты, айы, күні бар форма. Ол /-ге POST жібереді.
    • app.py: POST болса, жаңа туған күнді дерекқорға қосып, /-ге бағыттаңыз. GET болса, барлық туған күндерді кестеде көрсетіңіз.
    Кеңес
    • db.execute("INSERT INTO birthdays (name, month, day) VALUES(?, ?, ?)", name, month, day)
    • birthdays = db.execute("SELECT * FROM birthdays"), сосын render_template("index.html", birthdays=birthdays).
    • Шаблонда: {% for birthday in birthdays %}, {{ birthday.name }}, {{ birthday.month }}/{{ birthday.day }}.
    • Бос өрістер мен жарамсыз ай/күнді серверде тексеріңіз.
    • Қосымша: туған күнді өшіру не өңдеу мүмкіндігін қосыңыз.
    Тексеру
    • Форма жаңа туған күнді қосады.
    • Кестеде дерекқордағы барлық жазба көрсетіледі.
    • Бет қайта жүктелгенде жазбалар сақталады.
    • SQL-да тек ? орын толтырғыштары.

    Қиын

    Finance

    Акцияларды «сатып алу» мен «сатуды» модельдейтін C$50 Finance веб-қосымшасын жасаңыз. Бағаларды helpers.py-дегі lookup(symbol) функциясы алады. Әр жаңа пайдаланушыда $10 000 виртуалды ақша бар. login, logout дайын. Сіз іске асырасыз:

    • register — пайдаланушы аты, құпиясөз, құпиясөзді растау. Құпиясөзді generate_password_hash арқылы хэштеп сақтаңыз.
    • quote — акция символы бойынша бағаны көрсету.
    • buy — акция сатып алу (ақша жеткілікті ме тексеріңіз).
    • index — пайдаланушының акциялары, саны, ағымдағы бағасы, жалпы құны, қолма-қол ақшасы.
    • sell — бар акцияларды сату.
    • history — барлық операциялар тарихы.
    • personal touch — өз мүмкіндігіңіз: құпиясөзді өзгерту, ақша қосу және т.б.
    Кеңес
    • Операцияларды сақтайтын жаңа кесте жасаңыз (мысалы, transactions: user_id, symbol, shares, price, timestamp). Сыртқы кілт пен индекстер туралы ойланыңыз.
    • Ағымдағы пайдаланушы: session["user_id"].
    • Қателер үшін дайын apology(message, code) функциясы бар.
    • Ақша үшін usd(value) сүзгісі: {{ value | usd }}.
    • Портфельді GROUP BY symbol және SUM(shares) арқылы есептеңіз.
    • Сандарды тексеріңіз: оң бүтін сан ба? "1.5", "-1", "foo" жарамсыз.
    • Тапсырма бетіндегі сілтеме арқылы қызметкерлердің шешімін көріп, мінезін салыстырыңыз.
    Тексеру
    • Тіркелу: бос өрістер, құпиясөздердің сәйкес келмеуі, бос емес пайдаланушы аты тексеріледі.
    • Quote: жарамсыз символға қате хабары.
    • Buy: ақша жетпесе, сатып алмайды; ақша азаяды.
    • Index: акциялар, бағалар, жалпы сома дұрыс.
    • Sell: бардан көп сатуға болмайды.
    • History: барлық операция көрсетіледі.
    • Personal touch қосылды.
