Мазмұны

    3-апта

    Алгоритмдер

    Іздеу және сұрыптау алгоритмдері, олардың жұмыс уақытын бағалау (Big O, Ω, Θ), өз деректер типімізді жасау (struct), рекурсия және біріктіру арқылы сұрыптау.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)

    Кіріспе

    Сабақ сұрыптау алгоритмдерінің дыбыстық-көрнекі көрінісімен басталды. 0-аптадан еске түсірейік: алгоритм — есепті шешуге арналған қадамдық нұсқаулық. Сұрыптау (sorting) нақты өмірдегідей мәліметтерді ретке келтіру: кішіден үлкенге, алфавит бойынша не басқа ереже бойынша. Ал іздеу (searching), 0-аптадағыдай, ақпаратты табу.

    Бүгінгі мақсаттардың бірі — информатиканың кейбір негізгі «құрылыс блоктарымен» таныстыру. Информатиканы оқыған кез келген адам білетін және техникалық сұхбатта міндетті түрде сұралатын канондық алгоритмдер көп. Бірақ одан да маңыздысы, есеп шығарудың әртүрлі ойша модельдері мен әдістерін беріп, нақты өмірдегі алгоритмдерді өзіңіз басқаратын компьютерге қалай аударуға болатынын көрсету.

    Залдағыларды санау

    Залдағыларды қалай санауға болады? Әрине, кірерде сканерлер бар, бірақ ескі тәсілмен де санауға болады: 1, 2, 3, 4... Бұл әр адамға бір қадам кетеді. Мектепте үйреткендей екіден санасақ, 2, 4, 6, 8... әлдеқайда тез. Бірақ 0-аптаны еске түсірсек, бұдан да жақсырақ тәсіл бар. Дэвид бүкіл залдан мынаны өтінді:

    1. Орныңыздан тұрып, 1 санын ойға сақтаңыз.
    2. Әлі тұрған біреумен жұптасып, оның санын өз саныңызға қосыңыз да, қосындыны есте сақтаңыз.
    3. Екеуіңнің біреуің отырыңыз.
    4. Әлі тұрсаңыз, 2-қадамға қайтыңыз.

    Бұл — цикл: 2 → 3 → 4 → 2... Әр секунд сайын отырғандар көбейіп, тұрғандар азаяды. Соңына қарай тұрғандар залдың әр жерінде алыс-алыста қалды, сондықтан Дэвид соңғы қосуға өзі көмектесті (32, 20, 27, 47, 15...). Нәтижесі 141 адам болды. Ал CS50 преценторы Келли адамдарды бір-бірлеп санап, шамамен 160 алды. Сәл айырмашылық бар, шамасы, ойша қосуда қателер болған шығар. Бірақ теория бойынша үшінші алгоритм әлдеқайда жылдам болуы керек.

    Неге? Бәрі тұрғанда, есептің жартысы бірден «шешілді»: залдың жартысы отырды. Сосын тағы жартысы, тағы жартысы... Адамдар бір-біріне жақын болса, ақырында бір адамның ойында жалпы сан қалар еді. Бұл 0-аптадағы телефон кітабының ең жылдам алгоритміне ұқсайды.

    Бір-бірлеп санау — түзу сызық: әр жаңа адам бір қадам қосады, яғни еңісі 1. Екіден санау да түзу сызық, бірақ тезірек. Ал үшінші алгоритм керісінше ойлағанда түсінікті: залда адам саны екі есе көп болса, тек бір қосымша қадам керек. Адам саны 4 есе көп болса, 2 қадам. Яғни уақыт өте баяу өседі.

    Бүгін алгоритмдердің тек дұрыстығы туралы емес, жобалануы туралы да айтамыз. Жобалау неғұрлым ақылды болса, алгоритм соғұрлым тиімді болады, ал оның «құны» соғұрлым баяу өседі. Құн дегеніміз уақыт, ақша, сақтау орны не кез келген шектеулі ресурс. Біз оны өте дәл өлшемейміз, «кең штрихтармен» стандартты тәсілдерді қолданып, алгоритмнің (демек кодтың) жұмыс уақытын (running time) сипаттаймыз.

    Массивтер: жабық есіктер

    Өткен аптада массивтерді қарастырдық. Олар ең қарапайым деректер құрылымы: компьютер жадын бөліктерге бөліп, бүтін сандарды, жолдарды не басқасын қатар сақтаймыз. Массивтің басты қасиеті: ішіндегі мәндердің бәрі жадта бір-бірінің жанында тұрады.

    ┌───┬───┬───┬───┬───┬───┬───┐
│ 1 │ 5 │10 │20 │50 │100│500│
└───┴───┴───┴───┴───┴───┴───┘
  0   1   2   3   4   5   6

    Бізге «50-ді тап» десе, көзбен бірден көреміз, себебі бүкіл экранды «құстың көзімен» көріп тұрмыз. Бірақ компьютерлер мен біз жазатын код бұлай істей алмайды. Массивтер шын мәнінде жабық есіктер қатары сияқты. Компьютер белгілі бір орында не бар екенін көру үшін сол орынға барып, есікті ашып, қарап, жауып, келесіге өтуі керек. Яғни компьютер бір мезетте тек бір мәнге қарай алады. Мұнан да мықты компьютерлер жасауға болады, бірақ біз жазатын кодтың бәрі осы модельге сүйенеді.

    Бүгіннен бастап жад орындары туралы айтқанда 0-ден санаймыз: 0-шкаф, 1-шкаф, ..., 6-шкаф. «6-орын» десек, кем дегенде 7 орын бар екенін білдіреді.

    Іздеу

    Сахнада жеті қызыл шкаф тұр, олардың ішінде Монополия ойынының ақшалары жасырылған. Мақсат — 50 долларлық купюраны табу. Кіріс — есіктері жабық 7 шкаф, шығыс — bool мән: «иә, бар» не «жоқ».

    Демо: Хосе және сызықтық іздеу

    Бірінші ерікті Хосе солдан оңға қарай әр шкафты ашып, ішіндегі купюраны көрсетті: 20, 500, 10, 5, 100, 1... және ақырында соңғы шкафтан 50-ді тапты! Оның алгоритмі: «бірінші есікке барып, ашып, іздегенім бе екенін тексеріп, жауып, келесіге өту».

    Бұл өте қисынды: 50 ішінде болса, Хосе оны міндетті түрде табады, тек баяу. Оңнан бастаса ше? Бұл жолы бір қадамда тапар еді. Бірақ Хосе айтқандай, сандар қандай ретпен тұрғанын білмесек, бұл жалпы жағдайда көмектеспейді. Жарты уақытта сәтті, жарты уақытта сәтсіз болады. Кездейсоқ таңдасақ ше? Жолымыз болуы мүмкін, бірақ қай есікті ашқанымызды есте сақтау керек. 7 шкафта бұл қиын емес, бірақ 70 не 700 болса, кездейсоқ тәсіл тиімді болмас еді.

    Демо: Кейтлин және екілік іздеу

    Екінші ерікті Кейтлинге артықшылық берілді: Келли купюраларды кішіден үлкенге қарай сұрыптап қойды. Кейтлин ортасынан бастады: 20. 50 одан үлкен, демек оң жақта. Қалған үш шкафтың ортасын ашты: 100, тым үлкен. Демек, ортасындағы шкаф: 50! (Ойыншылар Монополия купюраларын білетіндіктен, біраз «интуиция» көмектесті. Бірақ жалпы жағдайда, сандарды білмесек те, тек сұрыпталғанын білсек, ортасына, ортасының ортасына бару есепті жарты-жартыға бөледі.) Екеуіне де Гарвард маңындағы жерлердің аттары жазылған Монополияның «Кембридж нұсқасы» сыйға берілді.

    Сызықтық іздеу

    Хосенің алгоритмі сызықтық іздеу (linear search) деп аталады, себебі ол түзу сызық бойымен солдан оңға жүреді:

    Солдан оңға қарай әр есік үшін:
    Егер есіктің артында 50 болса:
        true қайтар
false қайтар

    Мұнда да шегініс маңызды. Мына нұсқа неге қате?

    Солдан оңға қарай әр есік үшін:
    Егер есіктің артында 50 болса:
        true қайтар
    Әйтпесе:
        false қайтар

    Студент айтқандай, 50 бірінші есіктің артында болмаса, else бірден false қайтарады. C-дағыдай, мән қайтарылса, функция жұмысын тоқтатады. Яғни қалған 6 шкафқа қарамай-ақ, қате жауап береміз. Бірінші нұсқада false тек барлық есіктен өткеннен кейін ғана қайтарылады.

    Информатиктер сол ойды айнымалылар мен стандартты белгілер арқылы былай жазады. Бір қарағанда түсініксіз, бірақ ойыңызды әлдеқайда анық әрі дәл жеткізеді:

    i 0-ден n−1-ге дейін:
    Егер 50 doors[i] артында болса:
        true қайтар
false қайтар

    Неге n емес, n−1? Студент айтқандай, 0-ден санасақ, n элементтің соңғысы n−1 орында тұрады. n-ге дейін барсақ, n+1 элемент болар еді. Тапсырмалар күрделене бергенде мұндай псевдокод жазу пайдалы: одан кейін нағыз кодқа аудару оңай.

    Екілік іздеу

    Кейтлиннің алгоритмі екілік іздеу (binary search) деп аталады. «Bi» екі дегенді білдіреді, себебі есепті қайта-қайта екіге бөлеміз:

    Егер есік қалмаса:
    false қайтар
Егер 50 ортаңғы есіктің артында болса:
    true қайтар
Әйтпесе, егер 50 < ортаңғы есік болса:
    Сол жақ жартысын ізде
Әйтпесе, егер 50 > ортаңғы есік болса:
    Оң жақ жартысын ізде

    Тағы бір жағдайды ескеру керек: есік мүлдем жоқ болса не есіктер таусылса. Сондықтан ең басында «есік қалмаса, false қайтар» тексерісі тұр. «Сол жақ жартысын ізде» дегенді қалай істейміз? Дәл осы алгоритмді қайта қолданамыз, бірақ есіктер азырақ. Бүгін соңында осы өте қуатты әдіске ораламыз. Массив белгілерімен:

    Егер есік қалмаса:
    false қайтар
Егер 50 doors[middle] артында болса:
    true қайтар
Әйтпесе, егер 50 < doors[middle]:
    doors[0]-ден doors[middle − 1]-ге дейін ізде
Әйтпесе, егер 50 > doors[middle]:
    doors[middle + 1]-ден doors[n − 1]-ге дейін ізде

    Бұл псевдокод middle-ді, яғни ортаңғы элементтің индексін есептеп алғанымызды болжайды. 7 есік болса, 7 ÷ 2 = 3,5. Индекс бүтін сан болуы керек, сондықтан төмен дөңгелектейміз: 3. Шынымен де 0, 1, 2, 3 — ортаңғы шкаф.

    Неге middle − 1 және middle + 1? Студент айтқандай, ортаңғы есікті тексеріп қойдық, оны қайта қарау уақытты ысырап ету болар еді.

    Жұмыс уақыты

    0-аптадағы графикке оралайық. Бірінші алгоритм n қадам (бүкіл кітапты іздесек не бәрін санасақ), екіншісі n/2, ал үшіншісі log₂ n қадам кетеді. log₂ n — n өлшемді есепті қанша рет екіге бөлгенде бір адам не бір бет қалатынын көрсетеді.

    Бірақ информатиктер алгоритмдердің тиімділігін бұдан да «кең штрихтармен» сипаттайды. Нақты қадам санының орнына алгоритм шамамен қанша қадам жасайтынын айтамыз. Ол үшін Big O белгісін қолданамыз: үлкен O және жақша, «биг оу» деп оқылады.

    • Бірінші алгоритм O(n): шамамен n қадам.
    • Екіншісін O(n/2) деп жазғымыз келеді, ал үшіншісін O(log₂ n).

    Бірақ бізге алгоритмдердің ең маңызды қасиеті — есеп ұлғайғанда уақыттың қалай өсетіні. Қазіргі компьютерлер өте жылдам. 1000 не 2000 санды сұрыптасаңыз, бәрібір секундтың бір бөлігінде бітеді. Ал 1000, миллион не миллиард сан болса, айырмашылықты адамдар байқай бастайды. Сондықтан Big O-да:

    • кіші ретті мүшелерді және тұрақты көбейткіштерді елемейміз, тек ең басым мүшеге қараймыз;
    • O(n/2) іс жүзінде O(n)-мен бірдей: екеуі де сызықтық, тек бірі сәл тезірек өседі;
    • O(log₂ n) жай ғана O(log n), логарифмнің негізі маңызды емес.

    Графикті ойша «ұзақтатайық». X осі 0-ден миллионға емес, миллиардқа дейін болсын. Бәрі көзге «сығылып», екі түзу сызық бір-біріне жақындап, бір сызық сияқты болады. Ал жасыл логарифмдік қисық әлі де айқын ерекшеленеді. Сондықтан информатиктер кіші ретті мүшелермен айналыспайды.

    O(n²)квадраттық(жақын арада көреміз)
    O(n log n)(жақын арада көреміз)
    O(n)сызықтықсызықтық іздеу
    O(log n)логарифмдікекілік іздеу
    O(1)тұрақты1, 2 не 10 қадам, n-ге тәуелсіз

    Сызықтық іздеудің жұмыс уақыты? Студент айтқандай, O(n). Ең нашар жағдайда, Хосенің мысалындағыдай, іздегеніміз ең соңында тұруы мүмкін. Жолымыз болуы мүмкін, бірақ Big O-ны әдетте ең нашар жағдай (worst case) контекстінде қолданамыз. Бұл алгоритм деректер бізге қарсы «жұмыс істегенде» қаншалықты нашар болуы мүмкін екенін көрсетеді. Big O жоғарғы шекараны (upper bound) білдіреді.

    Екілік іздеу ше? Деректер сұрыпталған болса, ең нашар жағдайда да O(log n). Сандар сұрыпталса, телефон кітабындағыдай жарты-жартыға бөлінеді. Сұрыпталмаған массивте екілік іздеуді неге қолдануға болмайды? Студент айтқандай, «кіші» не «үлкен» деген шешімдердің ешқандай негізі болмайды. Солға не оңға кездейсоқ жүресіз, кіші сандар солда, үлкен сандар оңда тұр деуге себеп жоқ. Сондықтан іздегеніңізді мүлдем өткізіп алуыңыз мүмкін.

    Әуелі сұрыптап, сосын іздеу әрқашан тиімді ме? Жоқ! Студенттің сұрағы: «сұрыптауға көп уақыт кетсе, сызықтық іздеу кейде тиімдірек емес пе?». Әбден мүмкін. Бұл кез келген алгоритмді іске асырудағы жобалау шешімінің бір бөлігі. 7 емес, 70, 7000, 7 миллион сан болса және сізге тек бір рет іздеу керек болса, сұрыптауға уақыт жұмсаудың не керегі бар? Ал Google сияқты компанияларда іздеу қайта-қайта жасалады. Сондықтан деректерді бір рет сұрыптаудың құнын көптеген іздеуге «бөліп» (amortize) жібереді.

    Дэвид магистратурада үлкен деректерді талдайтын код жазғанын еске алады. Кейде кодты «CS50 стилінде» мұқият жазудың орнына, нашар, бірақ дұрыс код жазып, 7 сағат ұйықтауға кететін. Таңертең жауап дайын болатын. Бірақ кодта қате болса, 7 сағаттан кейін бүкіл түн босқа кеткенін білетін. Бұл да ресурстар арасындағы таңдау (trade-off). Кейде қымбатырақ шешім дұрыс болуы мүмкін, бірақ оны біле тұра таңдау керек.

    Ω (омега) және Θ (тета)

    Big O — жоғарғы шекара: деректер бізге қарсы болғанда жағдай қаншалықты нашарлауы мүмкін. Ал Ω (бас омега әрпі) — төменгі шекара: ең жақсы жағдайда алгоритм ең аз дегенде қанша қадам жасайды?

    ΩМысал
    Ω(n²)
    Ω(n log n)
    Ω(n)
    Ω(log n)
    Ω(1)сызықтық іздеу, екілік іздеу
    • Сызықтық іздеу Ω(1): Хосенің жолы болып, 50 бірінші шкафта тұруы мүмкін еді. Ал 7 емес, 70 шкаф болса да, бәрібір бір қадамда табуы мүмкін.
    • Екілік іздеу де Ω(1): ізделген сан дәл ортада тұруы мүмкін.

    Сондықтан жоғарғы және төменгі шекараны бірге айтамыз: алгоритм кейде өте жылдам болуы мүмкін, бірақ жалпы жағдайда бізге үнемі жол болмайды, сондықтан шындыққа Big O жақынырақ.

    Үшінші белгі — Θ (бас тета әрпі). Оны Big O мен Ω бірдей болғанда қолданамыз. Жоғарыдағы алгоритмдердің ешқайсысына Θ жарамайды, себебі олардың O мен Ω-сы әртүрлі. Бірақ бүгін Θ-мен сипатталатын алгоритмдерді де көреміз. Бұл басқа информатикке жоғарғы және төменгі шекараны бірден айтқанмен бірдей.

    Big O, Ω және Θ бірге асимптоталық белгілеу (asymptotic notation) деп аталады. «Асимптоталық» дегеніміз мән үлкейіп, үлкейіп, бірақ ешқашан белгілі бір шекараға жетпеуі. Яғни біз n өте үлкен болғанда не болатынын айтамыз.

Компилятор жақшадағы сандарды өзі санайды, сондықтан тік жақшаға 7 жазудың қажеті жоқ (санауда қателесіп, 7 деп жазып, 8 сан берудің не керегі бар?).

    • Цикл бітіп, ештеңе табылмаса, «Not found» шығарып, 1 қайтарамыз.

Онда жолдың ұзындығын беретін strlen-нен басқа strcmp (string compare, жолдарды салыстыру) функциясы бар. Бүгін тек мынаны біліңіз: екі жолды == арқылы салыстыруға болмайды. Интуиция бойынша: компьютер үшін екі бүтін санды салыстыру өте оңай. Ал жол бір таңба емес, мұнда 7 таңба, ол жақта бірнеше таңба бар. Жолдардың әр таңбасын салыстырып шығу керек. strcmp дәл осыны істейді: оны жылдар бұрын біреу while не for циклімен жазған, ол жолдарды солдан оңға қарап, әр таңбаны салыстырады.

    if (strcmp(strings[i], s) == 0)

    Құжаттаманы оқысаңыз, бұл анық емес, бірақ жолдар бірдей болса strcmp 0 қайтарады. Әйтпесе оң не теріс сан қайтарады. (Бірінші нұсқада string.h қосуды ұмытып кеттім. clang strcmp деген сөзді кездестіріп, оның не екенін білмеді.) Енді battleship, boot, top hat табылды, ал 50 табылмады.

    Неге strcmp оң не теріс сан да қайтарады? Студент тапқырлықпен жауап берді: екі жол бірдей ме екенін білу жақсы, бірақ сол функция қайсысы бірінші келетінін де айта алса, жолдарды сұрыптауға көмектеседі. Нақтырақ айтқанда, бұл алфавит бойынша емес, «ASCII-бет бойынша» (ASCIIbetically) салыстыру: ол таңбалардың ASCII мәндерін салыстырады. Теңсіздік керек болса, 0-ден кіші не үлкенін тексересіз. Бірақ мұнда тек теңдік керек.

    Деректер құрылымдары: struct

    Деректер құрылымы (data structure) — деректерді компьютер жадында қалай ұйымдастыратыныңыз. Массив — ең қарапайым деректер құрылымы: мәндерді солдан оңға қатар сақтайды. Бірақ олардың бәрі бір типті болуы керек: int, int, int не string, string, string. Әзірге бір int пен бір string-ті, не екі жолды бірге, «жұп-жұп» етіп сақтайтын тәсіліміз жоқ.

    Телефон кітабына person (адам) деген деректер типі болса жақсы болар еді. Сонда person people[2]; деп, адамдар массивін жасай алар едік. Бірақ C-ны ондаған жыл бұрын ойлап тапқанда, онда person типі болмаған. int, float, char, bool және т.б. бар. Дегенмен, өз деректер типімізді ойлап табуға болады:

    typedef struct
{
    string name;
    string number;
}
person;
    • typedef (type definition) — жаңа тип анықта.
    • struct (structure) — бұл тип бірнеше нәрседен тұратын құрылым.
    • Фигуралы жақшалардың ішіне біріктіргіңіз келген екі нәрсені жазасыз: string name және string number.
    • Фигуралы жақшадан кейін жаңа типтің атын жазасыз: person. (Style50 бойынша, өнеркәсіптегідей, ат соңғы фигуралы жақшамен бір жолда тұруы керек. Бұл сәл оғаш көрінеді, бірақ солай келісілген.)

    Бұл жолдар C-ға «person атты жаңа тип жаса. Әлемдегі әр адамның name және number атты жолы болсын» дейді.

    #include <cs50.h>
#include <stdio.h>
#include <string.h>

typedef struct
{
    string name;
    string number;
}
person;

int main(void)
{
    person people[3];

    people[0].name = "Kelly";
    people[0].number = "+1-617-495-1000";

    people[1].name = "David";
    people[1].number = "+1-617-495-1000";

    people[2].name = "John";
    people[2].number = "+1-949-468-2750";

    string name = get_string("Name: ");
    for (int i = 0; i < 3; i++)
    {
        if (strcmp(people[i].name, name) == 0)
        {
            printf("Found %s\n", people[i].number);
            return 0;
        }
    }
    printf("Not found\n");
    return 1;
}
    • Құрылымды main-нің үстіне жаздық, сонда оны кейін жазатын басқа функциялар да пайдалана алады.
    • person people[3]; — people атты массив, ішінде 3 адамға орын бар, әр адамда ат пен нөмірге орын бар. (Ағылшынша person-ның көпше түрі people, сондықтан грамматикалық тұрғыдан дұрыс болсын деп осылай атадық.)
    • Нүкте (.) — жаңа синтаксис. Ол «құрылымның ішіне кіріп, name өрісіне (атрибутына) жүгін» дегенді білдіреді.
    • Мәндерді «қатаң кодтадық», бірақ оларды get_string-пен сұрауға болар еді.

    Нәтиже бұрынғыдай: John іздесек, оның нөмірі шығады. Ұзақ уақыт пен көп код кетсе де, бұл жақсырақ жобаланған. people[0]-де бір адам және ол туралы бар ақпарат, people[1]-де келесі адам. Бұл инкапсуляция (encapsulation): фигуралы жақшалар деректер типтерін бір құрылымның ішінде «құшақтап», оларды компьютер жадында да бірге ұстайды.

    Таңдау арқылы сұрыптау (selection sort)

    Еріктілер бастапқы ретке оралды. Дэвид ең кіші санды таңдауға тырысты: 7, ең кішісі әзірге осы. 2, кішірек, есте сақтаймын. 5 емес, 4 емес. 1, одан да кіші. 6 емес. 0! Тізімді соңына дейін тексеру керек (мүмкін −1 бар шығар), 3 емес. Ең кішісі 0, оны басына қою керек.

    Бірақ Прешеске (7) не істейміз? Бұл 8 бүтін саннан тұратын массив болса, кенеттен солға орын жасай алмаймыз. Онда қоқыс мәндер не басқа бірдеңе болуы мүмкін, бізге тиесілі емес деректерді өзгерткіміз келмейді. Сондықтан Прешес 0-дің орнына барады. Екі мәнді ауыстырамыз (swap).

0 2 5 4 1 6 7 3   0 мен 7 ауысты
0 1 5 4 2 6 7 3   1 мен 2 ауысты
0 1 2 4 5 6 7 3   2 мен 5 ауысты

    Әр «өтуде» келесі ең кіші санды іздейміз. Кейде ауыстыру жағдайды уақытша нашарлатады (мысалы, 4 артқа ығысып кетті), бірақ кейін ол түзеледі. Дэвидтің тәсілі еріктілердікінен баяу, себебі олар параллель жұмыс істеді, ал Дэвид әдістемелі түрде қадам-қадаммен жүрді. Бірақ оның алгоритмі кодқа аударуға әлдеқайда жеңіл. Бұл — таңдау арқылы сұрыптау (selection sort): әр өтуде ең кіші элементті таңдаймыз.

    Көпіршікті сұрыптау (bubble sort)

    Еріктілер бастапқы ретке қайта тұрды. Бұл жолы алыс жүрмей, тек көршілерді салыстырайық:

    • 7 мен 2: реті дұрыс емес, ауыстырамыз.
    • 7 мен 5: ауыстырамыз. 7 мен 4: ауыстырамыз. 7 мен 1, 7 мен 6, 7 мен 0, 7 мен 3: бәрін ауыстырамыз.
    7 2 5 4 1 6 0 3   бастапқы
2 5 4 1 6 0 3 7   1-өтуден кейін: 7 соңына «көпіршіктеп» шықты
2 4 1 5 0 3 6 7   2-өтуден кейін
2 1 4 0 3 5 6 7   3-өтуден кейін
1 2 0 3 4 5 6 7   4-өтуден кейін
1 0 2 3 4 5 6 7   5-өтуден кейін
0 1 2 3 4 5 6 7   6-өтуден кейін

    Бірінші өтуден кейін 8 мәселенің біреуі шешілді: Прешес (7) соңына дейін «көпіршіктеп» шықты. Алгоритмнің атауы да осыдан: көпіршікті сұрыптау (bubble sort). Ең үлкен элементтер тізімнің соңына біртіндеп «көтеріліп» шығады. Бірақ әлі де ретсіз элементтер бар. Сондықтан қайта бастаймыз. Соңғы өтуден кейін бәрі сұрыпталды, бірақ тағы бір рет тексеру керек. Еріктілерге Pez диспенсерлері сыйға берілді.

    Таңдау арқылы сұрыптауды талдау

    Массивтің бірінші элементі 0-орында, соңғысы n−1-де:

    i 0-ден n−1-ге дейін:
    numbers[i] мен numbers[n−1] арасындағы ең кіші санды тап
    Ең кіші санды numbers[i]-мен ауыстыр

    Алдымен i = 0: 0 мен n−1 аралығындағы ең кішісін тауып, 0-орынмен ауыстырамыз (Джейден осылай басына келді). Сосын i = 1: 1 мен n−1 арасындағы ең кішісін тауып, 1-орынмен ауыстырамыз. Ал n өзгермейді, ол элементтердің жалпы саны.

    Дэвид неге әр жолы ең кіші санды «тауып таң қалды», бірінші өтуде бәрін көрді емес пе? Ол тек бір айнымалыны (ойындағы ағымдағы ең кіші сан) пайдаланды. Бәрін есте сақтауға болар еді, бірақ бұл көбірек жад керек етеді. Алдағы апталарда жиі кездесетін тақырып: жадты көбірек пайдаланып уақытты үнемдеуге не керісінше болады. Уақыт пен жад арасында таңдау жасау керек.

    Қанша салыстыру жасадық? Бірінші өтуде n адамды бір-бірімен салыстыру үшін n−1 салыстыру керек. Сосын бір есеп шешілді, келесі өтуде n−2, сосын n−3, ..., соңында 1:

    (n−1) + (n−2) + ... + 1 = n(n−1)/2 = n²/2 − n/2

    (Математика оқулығының соңындағы «шпаргалкадан» осы қатардың формуласын еске түсірсеңіз болды.) Big O-ны қолданайық: кіші ретті мүшелерді елемей, ең басым мүшені қалдырамыз. n өте үлкен болса, n², 2, n және 2-нің қайсысы маңыздырақ? Әрине n². Сондықтан таңдау арқылы сұрыптау O(n²). Бұл бүгін көргендердің ең нашары, тіпті сызықтық іздеуден де баяу.

    Ал Ω ше? Ең жақсы жағдайда, деректер бұрыннан сұрыпталған болса (бұл кез келген алгоритм үшін тексеруге тұрарлық «зұлым» жағдай), Дэвидтің «ақымақ» алгоритмі бәрібір алға-артқа жүре береді. Себебі код «мұны осынша рет істе, әр жолы ең кішісін тап» дейді, деректердің бастапқы ретін ешқалай ескермейді. Сондықтан Ω(n²). Big O мен Ω бірдей болғандықтан, таңдау арқылы сұрыптау Θ(n²). Бұл жақсы емес, себебі ол тым баяу.

    Көпіршікті сұрыптауды талдау

    n−1 рет қайтала:
    i 0-ден n−2-ге дейін:
        Егер numbers[i] мен numbers[i+1] реті дұрыс болмаса:
            Оларды ауыстыр

    Неге i n−1-ге емес, n−2-ге дейін? i мен i+1-ді сол және оң қол деп елестетіңіз. Сол қол n−1-ді көрсетсе, оң қол n-ді көрсетеді, ал ол массивтен тыс, себебі массив 0-ден n−1-ге дейін. Бұл массив шетінен шығып кетпеу үшін. Неге n−1 рет? 7 мәселе шешілсе, 8-сі өздігінен шешіледі: соңғы адам өз орнында тұрады.

    Псевдокод жақсы жазылса, ондағы әр жолдың қанша қадам алатынын байқауға болады. Бірінші жол n−1 рет қайталайды. Ішкі цикл 0-ден n−2-ге дейін, яғни n−1 қадам. Салыстыру мен ауыстыру тұрақты сан қадам, деректердің көлеміне тәуелсіз. Сонда:

    (n−1)(n−1) = n² − 2n + 1 → O(n²)

    Ешқандай жақсару жоқ сияқты. Бірақ көпіршікті сұрыптауға таңдау арқылы сұрыптаудан айырмашылығы бар бір жақсарту енгізуге болады:

    n−1 рет қайтала:
    i 0-ден n−2-ге дейін:
        Егер numbers[i] мен numbers[i+1] реті дұрыс болмаса:
            Оларды ауыстыр
    Егер ешқандай ауыстыру болмаса:
        Тоқта

    Тізімді солдан оңға бір өтіп, бірде-бір ауыстыру жасамасақ, қайталаудың мәні жоқ. Сондықтан Ω жақсарады: Ω(n). Тізімнің сұрыпталғанын бір рет тексермей айту мүмкін емес, ал n элементтің бәріне қарау керек. Бірақ жұмыс болмаса, қайта-қайта өтудің қажеті жоқ. Big O мен Ω әртүрлі болғандықтан, Θ туралы ештеңе айта алмаймыз. Бұл жақсарту тек тізім толық не жартылай сұрыпталғанда ғана уақыт үнемдейді, ал орташа және ең нашар жағдайда екеуі де O(n²).

    Визуализация

    Нақты өмірдегі бір досымыз жасаған анимацияда күлгін тік бағандар бар. Кіші баған кіші санды, үлкен баған үлкен санды білдіреді. Мақсат: солдан оңға қарай кішіден үлкенге қою.

    • Selection sort: қызғылт түс ағымдағы ең кіші элементті және Дэвидтің сахнада солдан оңға қайта-қайта жүргенін көрсетеді. Джейден сияқты ең кішісі солға келеді. Бірақ Прешес сияқты 7-нің оңға жетуіне көп уақыт кетеді, себебі әр өтуде тек бір есеп шешіледі. Барлығы n есеп, демек n² қадам.
    • Bubble sort: қызғылт түс салыстырылып жатқан екі санды көрсетеді (сол қол мен оң қол). Ол сонша әдемі емес, бірақ ең үлкен элементтер біртіндеп соңына қарай «көпіршіктеп» шығады. Мұнда n² көрінеді: элементтерге қайта-қайта қарап, өте көп салыстыру жасаймыз. Бар болғаны бірнеше ондаған баған болса да, бұл қатты жалықтырады. Жүздеген, мыңдаған не миллиондаған мән болса ше?

    Бізге bubble sort-тан да, selection sort-тан да жақсы алгоритм керек.

    Төмендегі визуализацияда сұрыптау алгоритмдерін өзіңіз іске қосып көріңіз. Деректерді «Кері ретпен» не «Сұрыпталған» етіп, салыстырулар санының қалай өзгеретінін бақылаңыз: көпіршікті сұрыптау сұрыпталған массивте бір айналымда тоқтайды (Ω(n)), ал таңдау арқылы сұрыптау бәрібір n² салыстыру жасайды.

    Рекурсия

    Математикадан не нақты өмірден таныс болуы мүмкін бір әдіс бар. Рекурсия (recursion) — математика мен бағдарламалауда есепке түбегейлі басқаша қарауға мүмкіндік беретін әдіс. Рекурсивті функция — өзі арқылы анықталатын функция. Математикада f(x) = f(...) сияқты өрнек болса, ол рекурсивті болар еді. Бағдарламалауда рекурсивті функция — өзін-өзі шақыратын функция.

    Бұл оғаш естіледі: функция өзін-өзі шақырса, бұл шексіз циклге түсудің ең оңай жолы емес пе? Өзін, өзін, өзін шақыра берсе, қашан тоқтайды? Бұл мәселені шешу керек. Бірақ бұл курста рекурсияны бұрыннан, тіпті 0-аптада да, жанама түрде көрдік. Екілік іздеудің псевдокодын еске түсірейік:

    Егер есік қалмаса:
    false қайтар
Егер 50 ортаңғы есіктің артында болса:
    true қайтар
Әйтпесе, егер 50 < ортаңғы есік болса:
    Сол жақ жартысын ізде      ← рекурсивті шақыру
Әйтпесе, егер 50 > ортаңғы есік болса:
    Оң жақ жартысын ізде       ← рекурсивті шақыру

    «Сол жақ жартысын қалай іздеймін?» деп сұрасаңыз, жауабы экранда тұр: дәл осы алгоритмді қолданыңыз. Сол жақ жартысының сол жақ жартысын, не сол жақ жартысының оң жақ жартысын осылай іздейміз. «Жартысын ізде» деген жолдар — алгоритмнің (функцияның) өзін шақыруы.

    Неге шексіз цикл болмайды? Бірінші шарт тоқтататыны рас. Бірақ одан да маңыздысы, студент айтқандай, біз өзімізге кішірек есеп береміз: кішірек, кішірек, кішірек. Сол санды есіктермен «мыналарды ізде, мыналарды ізде» деп айта берсек, ешқашан алға жылжымас едік. Есіктер азайған сайын, ақырында іздегенімізді табамыз не таппаймыз.

    Базалық жағдай және рекурсивті жағдай Базалық жағдай (base case) — жауабы бірден «иә» не «жоқ» болатын қарапайым сұрақты қоятын шарт. Мысалы, «есік қалмаса», «50 ортада болса». Рекурсивті жағдай (recursive case) — соңғы жауапқа жету үшін функция өзін кішірек есеппен шақыратын жағдай.

    0-аптадағы телефон кітабының псевдокодын да рекурсивті жазуға болар еді. Онда біз «3-жолға қайт» деп, циклді механикалық түрде жасадық. Ал 7–8-жолдар «сол жақ жартысының ортасын ашып, 3-жолға қайт» дегенді білдірсе, оны жай ғана «кітаптың сол жақ жартысын ізде» деп қысқартуға болады. Онда «сол жақ жартысын қалай іздеймін?» деген сұраққа жауап: сол алгоритмді жарты есеппен қайта бастаймыз. 0-аптада процедуралық тәсіл қолдандық, ал мұнда рекурсивті тәсіл.

    Super Mario Bros-тағы мұндай жартылай пирамида — өзі арқылы анықталатын қызықты нақты өмірлік құрылым. Биіктігі 4 пирамида деген не? Әдейі қиындатып айтсақ: биіктігі 3 пирамида және тағы бір қатар. Биіктігі 3 пирамида деген не? Биіктігі 2 пирамида және тағы бір қатар. Биіктігі 2? Биіктігі 1 пирамида және тағы бір қатар. Биіктігі 1? Бір кірпіш. Соңғы жауапта дауысымды өзгерттім, себебі бұл базалық жағдай: мәселені кейінге ысырмай, жауапты бірден айттым. Ал басқаларының бәрі кішірек құрылым арқылы анықталды.

    Google әзілі Google-да «recursion» деп іздеңіз. Google «Did you mean: recursion?» («Сіз recursion дегенді айтқыңыз келді ме?») деп сұрайды. Оны бассаңыз, сол бетке қайта ораласыз 🙂 Мұндай «пасхалық жұмыртқалар» көп, себебі оларды информатиктер жазады.

    Алдымен итерация (iteration), яғни циклдер арқылы:

    #include <cs50.h>
#include <stdio.h>

void draw(int n);

int main(void)
{
    int height = get_int("Height: ");
    draw(height);
}

void draw(int n)
{
    for (int i = 0; i < n; i++)
    {
        for (int j = 0; j < i + 1; j++)
        {
            printf("#");
        }
        printf("\n");
    }
}

    Бұл 1-есептер жинағынан оңайырақ, себебі пирамида басқа жаққа еңкейген. Сыртқы цикл әр қатар үшін, ішкі цикл әр баған үшін. i + 1 неге? Бірінші қатар 0-қатар, бірақ онда 0 емес, 1 кірпіш болуы керек. Сондықтан ішкі цикл 0-ден i + 1-ге дейін жүреді. (Прототипті ұмытып кеттім, компилятор 8-жолда шағымданды.)

    Енді сол draw функциясын рекурсия арқылы жазайық. main пен прототип өзгермейді:

    void draw(int n)
{
    // Базалық жағдай: салатын ештеңе жоқ
    if (n <= 0)
    {
        return;
    }

    // n−1 биіктікті пирамида сал
    draw(n - 1);

    // Тағы бір қатар сал
    for (int i = 0; i < n; i++)
    {
        printf("#");
    }
    printf("\n");
}

    Бірінші нұсқада базалық жағдай жоқ еді. clang тіпті компиляцияламай, «all paths through this function will call itself» (бұл функцияның барлық жолы өзін шақырады) деп қате берді. Яғни бұл шексіз цикл болар еді. Сондықтан алдымен салатын бірдеңе бар ма деп тексереміз. void функциядан ештеңе қайтармаймыз, тек return; жазамыз. Неге n == 0 емес, n <= 0? Теріс сан берілсе де ештеңе салмасын, бұл қауіпсіздеу. 1-ді базалық жағдай етсек, бір кірпішті өзіміз салуымыз керек болар еді, бұл кодты сәл күрделендіреді.

    Нәтиже бірдей. Код аз болмаса да, мұнда сұлулық бар. Итерациялық нұсқа «мұны шығар, мынаны шығар, бір циклдің ішінде тағы бір цикл» деп өте ауыр. Ал рекурсиялық нұсқа, әсіресе түсініктемелер мен бір жолдық шарттағы фигуралы жақшаларды алып тастасақ, Mario пирамидасын салудың өте әдемі іске асырылуы. Себебі ол өзін-өзі шақырады.

    — Көріну аймағы (scope) мәселесі бар ма? Жоқ. Бірақ i-дің ағымдағы мәні функцияның келесі шақыруында көрінбейді. Әр шақырудың өз i-і болады.

    Рекурсияның бағасы Биіктікке өте үлкен сан (мысалы, 10 000 000) берсек, мынадай қате шығады: Segmentation fault (core dumped). Оны офис-сағаттарда не тапсырмада кездестірген шығарсыз. Бұл жадқа байланысты: draw әр шақырылған сайын сәл көбірек жад пайдаланады, ал компьютер жады шектеулі. Итерациялық нұсқада бұл қате болмас еді. Мұны айналып өтудің жолдары бар, бірақ бұл — рекурсияның сұлулығы үшін төлейтін бағамыз. Келесі аптада бұл туралы толығырақ айтамыз.

    Біріктіру арқылы сұрыптау (merge sort)

    Неге Mario-ға «ауытқыдық»? Бүгінгі үшінші, соңғы сұрыптау алгоритмі есепті шешу үшін рекурсияны қолданады. Ол тек әдемі ғана емес, bubble sort пен selection sort-тан әлдеқайда жылдам. Себебі ол салыстыруды әлдеқайда аз жасайды, бір сандарды қайта-қайта салыстырып, уақытты босқа кетірмейді.

    Егер тек бір сан болса:
    Тоқта
Сандардың сол жақ жартысын сұрыпта
Сандардың оң жақ жартысын сұрыпта
Сұрыпталған екі жартыны біріктір

    Бұл оғаш алгоритм. «Сандарды қалай сұрыптаймын?» десеңіз, «сол жақ жартысын сұрыпта, оң жақ жартысын сұрыпта» деп жауап береміз. Бұл қиқарланғанға ұқсайды. Бірақ үшінші жолда сиқыр бар: бұрыннан сұрыпталған екі жартыны біріктіру. Базалық жағдай да бар: тек бір сан болса, ол сұрыпталған, ештеңе істемейміз.

    Біріктіру деген не?

    Сол жақта 1 3 4 6, оң жақта 0 2 5 7 бар делік. Екеуі де сұрыпталған. Сол қолмен сол жақ тізімнің басын, оң қолмен оң жақ тізімнің басын көрсетіп, әр қадамда кішісін жоғарғы сөреге (сұрыпталған тізімге) аламыз:

    сол: [1] 3 4 6     оң: [0] 2 5 7    → 0
сол: [1] 3 4 6     оң:  0 [2] 5 7   → 0 1
сол:  1 [3] 4 6    оң:  0 [2] 5 7   → 0 1 2
сол:  1 [3] 4 6    оң:  0  2 [5] 7  → 0 1 2 3
сол:  1  3 [4] 6   оң:  0  2 [5] 7  → 0 1 2 3 4
сол:  1  3  4 [6]  оң:  0  2 [5] 7  → 0 1 2 3 4 5
сол:  1  3  4 [6]  оң:  0  2  5 [7] → 0 1 2 3 4 5 6
сол:  (бітті)      оң:  0  2  5 [7] → 0 1 2 3 4 5 6 7

    Қолдарым алға-артқа жүрмейді, тек оңға қарай кішкене қадамдармен жылжиды. Әр санды тек бір рет көрсетемін. 8 сан, 8 сұрақ. Сондықтан осындай екі тізімді біріктіру n қадам алады.

    Толық мысал

    6 3 4 1 5 2 7 0 тізімін сұрыптайық:

    1. Сол жақ жартысын сұрыпта: 6 3 4 1. Төрт санды қалай сұрыптаймыз? Сол жақ жартысын сұрыптаймыз: 6 3. Екі санды қалай сұрыптаймыз? Сол жақ жартысын: 6. Бір сан бар, ол сұрыпталған! Оң жақ жартысын: 3, ол да сұрыпталған. Енді біріктіреміз: 3 6.
    2. Сол жақ жартысының (6 3 4 1) енді оң жақ жартысын сұрыптаймыз: 4 1 → 4 және 1 → біріктіреміз: 1 4.
    3. 3 6 мен 1 4-ті біріктіреміз: 1 3 4 6. Сол жақ жартысы сұрыпталды. Бұл шамдармен бастапқыда көрсеткен 1 3 4 6-ға әдейі сәйкес келеді.
    4. Оң жақ жартысын сұрыпта: 5 2 7 0 → 5 2 → 2 5; 7 0 → 0 7; біріктіреміз: 0 2 5 7.
    5. Сұрыпталған екі жартыны біріктір: 1 3 4 6 + 0 2 5 7 → 0 1 2 3 4 5 6 7.

    Көп сөз айтылса да, алға-артқа жүру аз болды. Бір сандарды қайта-қайта салыстырмадық. Әртүрлі «ұғымдық деңгейде» әртүрлі жұмыс жасадық, бірақ барлығы небәрі 3 деңгей болды, n деңгей емес.

    Талдау

    6 3 4 1 5 2 7 0          8 элемент
3 6 | 1 4 | 2 5 | 0 7    1-деңгей: n қадам біріктіру
1 3 4 6 | 0 2 5 7        2-деңгей: n қадам біріктіру
0 1 2 3 4 5 6 7          3-деңгей: n қадам біріктіру

    8 элементтен тұратын тізімнен 3 деңгейлік жұмыс шықты. Әр деңгейде элементтерді біріктірдік. 4 және 4 элементті біріктіру барлығы 8 қадам, яғни n. Осы деңгейде 2 және 2 элементтен тұратын екі жұпты біріктірдік, бұл да барлығы n. Ең төменгі деңгейде 8 жалғыз тізімді біріктірдік, бұл да n.

    Неге 3? Егер n = 8 болса, log₂ 8 = log₂ 2³ = 3. Яғни n қандай болса да, деңгейлер саны log₂ n, ал әр деңгейде n қадам. Сондықтан merge sort O(n log n), яғни n² емес. Ағымдағы іске асыруда bubble sort сияқты ақылды оңтайландыру жоқ, сондықтан ол Ω(n log n), демек Θ(n log n).

    Бағасы: жад Merge sort екі есе көп кеңістік қажет етеді. Демодағыдай, екі тізімді біріктіру үшін екі сөре керек болды. Тағы да уақыт пен жад арасындағы таңдау.
    АлгоритмO (ең нашар)Ω (ең жақсы)Θ
    Сызықтық іздеуO(n)Ω(1)—
    Екілік іздеуO(log n)Ω(1)—
    Selection sortO(n²)Ω(n²)Θ(n²)
    Bubble sortO(n²)Ω(n)—
    Merge sortO(n log n)Ω(n log n)Θ(n log n)

    Визуализацияда merge sort-ты іске қоссақ, компьютердің жылдамдығы өзгермесе де, ол әлдеқайда тез бітеді. Себебі элементтерге әлдеқайда аз рет қол тигізеді, есепті кішірек бөліктерге бөліп, бөліп, «жеңіп» алады. Соңында шамдар өшірілді, ал экранда үш алгоритм музыкамен қатар жұмыс істеді: жоғарыда selection sort, төменде bubble sort, ортада merge sort. Merge sort бірден бітті. O(n²) пен O(n log n) айырмашылығын өз көзіңізбен «сезуге» болады.

    Қорытынды

    • Компьютер массивтегі мәндерді бірден көрмейді, оларға бір-бірлеп қарайды (жабық есіктер).
    • Сызықтық іздеу O(n), екілік іздеу O(log n), бірақ деректер сұрыпталған болуы керек.
    • Big O жоғарғы шекара, Ω төменгі шекара, Θ екеуі бірдей болғанда. Тек ең басым мүше маңызды.
    • Жолдарды strcmp арқылы салыстырамыз, == арқылы емес.
    • typedef struct арқылы өз деректер типімізді жасаймыз. Өрістерге нүкте арқылы жүгінеміз.
    • Selection sort және bubble sort: O(n²). Merge sort: O(n log n), бірақ көбірек жад керек.
    • Рекурсия: функция өзін кішірек есеппен шақырады. Міндетті түрде базалық жағдай болуы керек.

    Өзіңізді тексеріңіз

    1. 1 000 000 сұрыпталған элементте екілік іздеу ең көп дегенде шамамен неше қадам жасайды?

    log₂ 1 000 000 ≈ 20, себебі 2²⁰ ≈ 1 048 576.

    2. O(3n² + 100n + 5) қалай жеңілдетіледі?

    Тек ең басым мүше қалады, тұрақты көбейткіштер елеусіз.

    3. Сұрыпталмаған массивке екілік іздеу неге жарамайды?

    Кіші сандар солда, үлкендері оңда деп болжауға болмайды, сондықтан іздегенді өткізіп алуымыз мүмкін.

    4. Қай алгоритмнің Ω-сы мен O-сы бірдей, демек Θ-мен сипатталады?

    Selection sort әрқашан n² қадам жасайды, тіпті деректер сұрыпталған болса да: Θ(n²).

    5. Неге if (s == t) екі жолды дұрыс салыстырмайды?

    Келесі аптада бұның нақты себебін көреміз: == жолдардың мекенжайларын салыстырады.

    6. Рекурсивті функцияда базалық жағдай болмаса не болады?

    clang мұндай жағдайды кейде компиляция кезінде-ақ байқайды: «all paths through this function will call itself».

    7. Merge sort-тың басты кемшілігі қандай?

    Біріктіру үшін екінші «сөре», яғни қосымша массив керек.

    Орташа

    Екілік іздеу C тілінде

    Сұрыпталған int массивінде bool binary_search(int value, int values[], int n) функциясын циклмен (итерация арқылы) жазыңыз.

    Кеңес

    Екі айнымалы ұстаңыз: low = 0 және high = n − 1. low <= high болғанша ортасын тексеріңіз, сосын шекараның бірін жылжытыңыз.

    Шешімі
    bool binary_search(int value, int values[], int n)
{
    int low = 0;
    int high = n - 1;
    while (low <= high)
    {
        int middle = (low + high) / 2;
        if (values[middle] == value)
        {
            return true;
        }
        else if (value < values[middle])
        {
            high = middle - 1;
        }
        else
        {
            low = middle + 1;
        }
    }
    return false;
}
    Орташа

    Рекурсивті факториал

    n! = n × (n−1)! және 0! = 1. int factorial(int n) функциясын рекурсия арқылы жазыңыз. 5! неге тең?

    Шешімі
    int factorial(int n)
{
    // Базалық жағдай
    if (n <= 1)
    {
        return 1;
    }
    // Рекурсивті жағдай
    return n * factorial(n - 1);
}

    string name;

    Runoff

    Рейтингтік сайлау (instant runoff): сайлаушылар үміткерлерді артықшылық ретімен қояды. Біреу дауыстардың жартысынан көбін жинаса, жеңеді. Әйтпесе ең аз дауыс алған үміткер шығарылады, ал оның сайлаушыларының дауысы келесі таңдауына өтеді. Бұл бір үміткер көпшілік алғанша қайталанады.

    Tideman

    Тайдман әдісі (ranked pairs): әр үміткер жұбы үшін сайлаушылардың қаншасы біреуін екіншісінен артық көретінін санап, «граф» құрасыз. Жұптар жеңіс күші бойынша сұрыпталып, графқа цикл туғызбайтын жағдайда ғана «бекітіледі». Жеңімпаз — графтың «көзі», яғни оған ешбір жебе бағытталмаған үміткер.
