    C тілі

    Scratch-тағы идеяларды мәтіндік C тіліне көшіреміз: бастапқы код, компилятор, айнымалылар, шарттар, циклдер, өз функцияларымыз, Linux командалары және компьютердің шектеулері.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)

    Кіріспе

    Бұл CS50, екінші аптамыз, яғни 1-апта. Өткен аптада (0-апта) Scratch тілімен таныстық. Онда пазл бөліктерін тек мағынасы болғанда ғана бір-біріне жалғауға болатын. Көбіңіз оны мектепте ойнаған боларсыз. Ал біз үшін Scratch-тың мақсаты бүгін C тілінде, бірнеше аптадан кейін Python-да және одан кейін де қайта-қайта кездесетін негізгі құрылымдардың ойша бейнесін қалыптастыру еді. Олар: функциялар, қайтарылатын мәндер, аргументтер, айнымалылар, циклдер, шарттар және басқалары.

    Бүгінгі сабақ «өрт сөндіргіштің шлангісінен су ішкендей» сезілуі мүмкін. Бірақ бүгінгі идеялардың көбі өткен аптадағы идеялармен бірдей, тек синтаксис (жазылу ережесі) өзгереді. Ол басқаша, сәл қорқыныштырақ көрінеді, оны жаттап алу да қиынырақ. Бірақ жаттығу арқылы «бұлшықет жадыңыз» қалыптасады.

    MIT-тің «хагы» Көрші MIT университетінде жыл сайын студенттердің ақылсыз бір нәрсе істейтін «hack» дәстүрі бар. Бірде олар нағыз өрт гидрантына жұмыс істейтін су ішетін фонтанды жалғаған. Жанындағы жазуда: «MIT-те білім алу өрт сөндіргіштің шлангісінен су ішкенмен бірдей» деп жазылған. Информатика, бағдарламалау және CS50 кейде осылай сезіледі. Бірақ ең маңыздысы күн сайын қай жерде тұрғаныңыз емес, 3 айдан кейін 0-аптамен салыстырғанда қай жерде тұрғаныңыз.

    Бастапқы код және машиналық код

    0-аптада мысыққа «hello, world» дейтін ең қарапайым бағдарламаны жаздық. Бүгін сол код былай көрінеді:

    #include <stdio.h>

int main(void)
{
    printf("hello, world\n");
}

    Scratch-та бағдарламаны іске қосатын сарғыш «when green flag clicked» бөлігі болды. Ол өзі ештеңе істемейтін, бірақ бағдарламаны бастайтын. Нағыз жұмысты күлгін «say» блогы атқаратын. Бүгін де дәл солай: біраз уақыт жоғарыдағы «сары» кодқа (#include, int main(void)) мән бермейміз, ең маңыздысы — printf жолы және ішіндегі ақ мәтін. Келесі бірнеше аптада бұл жолдардың бәрін ашамыз.

    Термин: бастапқы код Бастапқы код (source code) — бағдарламашылар жазатын код. Scratch-та сіз оны пазл бөліктерін сүйреп жаздыңыз, ал бүгіннен бастап пернетақтада тересіз. Біраз жаттығудан кейін оны адам түсінеді.

    Бірақ компьютерлер түптеп келгенде қандай тілді түсінеді? Тек екілік 0 мен 1-ді. Сондықтан біз бастапқы код жазамыз, ал машиналар тек 0 мен 1-ді түсінеді. Оларды машиналық код (machine code) деп атаймыз. Демек, бастапқы кодты машиналық кодқа қалай да аудару керек.

    бастапқы код  ──▶  [  компилятор  ]  ──▶  машиналық код
 (source code)        (compiler)            (0 мен 1)
    Термин: компилятор Компилятор (compiler) — бастапқы кодты кіріс ретінде алып, машиналық кодты шығыс ретінде беретін арнайы бағдарлама. Әлемде көптеген компилятор бар, біз ең танымалдарының бірін пайдаланамыз. Ол бір тілді (мысалы, C) басқа тілге (Mac, PC, телефон түсінетін 0 мен 1-ге) аударатын бағдарлама ғана.

    Visual Studio Code

    Бұл жұмысты қайда және қалай істейміз? 0-аптада чатбот жасау үшін қолданған Visual Studio Code (VS Code) құралын пайдаланамыз, бұл жолы Python үшін емес, C үшін. VS Code өнеркәсіпте өте танымал. Нағыз бағдарламашылар оны үнемі пайдаланады. Бұрын бағдарламалап көргендеріңіз басқа құралдарды да пайдаланған шығарсыз. Бірақ бұл CS50-ден кейін де кездесетін құрал. Курс соңында оны өз Mac не PC-іңізге тегін орнатып, CS50 құралдарынан толық тәуелсіз бола аласыз.

    Курстың басында біз оның бұлттағы нұсқасын ұсынамыз: cs50.dev. Тек браузер керек, бәрі алдын ала орнатылған және бапталған. Сондықтан семестр басында техникалық қолдаудың «ақымақ» мәселелерімен айналыспайсыз. Технологияға көбірек үйренген соң, оны өз компьютеріңізге орнатып, толық бақылауға алуға болады.

    Интерфейстің бөліктері:

    • Код қойындылары (жоғарғы оң жақ): код жазатын жер. Мысалы, бүгінгі алғашқы файл hello.c. Ол .c деп аталады, себебі C тілінде жазылған.
    • Синтаксисті бояу (syntax highlighting): VS Code танылған тілдегі кодтың бөліктерін автоматты түрде түрлі түске бояйды. Бұл түстер туралы ойлаудың қажеті жоқ, олар кодтың әр бөлігін көзге түсіру үшін ғана.
    • Терминал терезесі (төменгі оң жақ): кодты компиляциялау және іске қосу үшін командалар жазатын жер. Бүгіннен бастап тышқанды азырақ, пернетақтаны көбірек пайдаланасыз. Бұл кері қадам сияқты көрінуі мүмкін, бірақ көп бағдарламашы пернетақтамен жұмыс істегенде әлдеқайда өнімді болатынын байқайды.
    • Файлдар мен қалталар (сол жақ): уақыт өте келе жасайтын файлдарымыз.
    • Белсенділік жолағы (ең сол жақ): заманауи мәзір.
    Термин: GUI және CLI Иконкалары мен батырмалары бар бүкіл орта — графикалық интерфейс (graphical user interface, GUI). Ал команда теретін терминал — командалық жол интерфейсі (command-line interface, CLI). Бағдарламалар әлемі GUI мен CLI-ге бөлінеді, кейде бір бағдарламада екеуі де болады.

    Терминалда доллар белгісі $ тұр. Бұл шақыру (prompt): командаларыңызды осы жерге жазасыз. Оның валютаға қатысы жоқ, жай ғана дәстүр. Кейбір жүйелерде оның орнына > не басқа белгі тұрады.

    Алғашқы бағдарлама: hello.c

    Терминалда мына команданы жазамыз (сөздердің арасында бір бос орын):

    $ code hello.c

    Файл атында бос орын жоқ, бас әріп те жоқ. Бұл дәстүр. Mac не PC-де файл аттарында бос орын мен бас әріп жиі қолданылады, бірақ бағдарламалауда кіші әріп пен бос орынсыз ат өміріңізді жеңілдетеді. Enter басқанда hello.c атты жаңа қойынды ашылады, курсор 1-жолда жыпылықтайды. VS Code кодыңыздың бірінші жолын күтіп тұр. Мына кодты жазамыз:

    #include <stdio.h>

int main(void)
{
    printf("hello, world\n");
}

    Фигуралы жақшалардың ({ }) ішіндегі жол 4 бос орынмен шегініс жасап жазылады. Курс сайтында сабақтағы барлық кодтың көшірмесі бар, сондықтан әр жолды қағазға жазып отырудың қажеті жоқ.

    Mac не PC-де командалық жол болмаса, жұмыс үстелінде hello атты иконка пайда болып, екі рет басып іске қосар едік. Бірақ біз GUI мен CLI аралас ортада жұмыс істейміз. Әзірге код тек бастапқы код күйінде, сондықтан алдымен оны компиляциялау керек:

    $ make hello

    make hello «hello атты бағдарлама жаса» дегенді білдіреді. hello.c деп жазбағанымызға назар аударыңыз. Компилятор (әзірге оны make деп атайық, бұл сәл жеңілдетілген түсіндірме) hello атты бағдарлама жасау керек болса, hello.c файлын автоматты түрде іздейді.

    Ештеңе шықпаса, бұл жақсы белгі Мұндай команданың шығысы болмаса, бұл көбіне жақсы. Әдетте компиляция кезінде бірдеңе шықса, сіз (не мен) бір нәрсені қате жасадыңыз деген сөз.

    Енді бағдарламаны іске қосамыз:

    $ ./hello
hello, world

    ./hello сәл түсініксіз көрінеді. make жасаған hello бағдарламасы ағымдағы қалтада пайда болады (ол бұлттағы бір серверде, оған кейін ораламыз). ./ «ағымдағы қалтаға кір де, ондағы hello атты бағдарламаны іске қос» дегенді білдіреді.

    Үш команданы қайталайық. Бағдарламаның аты қандай болса да, бұл үлгі қайта-қайта кездеседі:

    1. code hello.c: VS Code-қа тән команда, hello.c атты жаңа файл жасайды.
    2. make hello: бастапқы кодты машиналық кодқа компиляциялап, hello атты жаңа файл жасайды.
    3. ./hello: бағдарламаны іске қосады.

    Студенттің сұрағы: «make hello» жазғанда компьютер кодтың қай бөлігі hello-ға тиесілі екенін қайдан біледі? Ол hello.c файлының бүкіл мазмұнын алып, бағдарламаға айналдырады. Аты міндетті түрде hello болмауы керек, goodbye не myfirstprogram деп те атауға болады, тек командаларды сәйкес өзгерту керек.

    Scratch-тан C-ға

    Scratch-тағы «when green flag clicked → say hello, world» бағдарламасы шамамен мына кодқа сәйкес келеді: сарғыш блок int main(void) жолына, күлгін блок printf-ке, ақ сопақ тырнақшадағы мәтінге сәйкес келеді.

    Функция — бір әрекет не етістік, ол шағын жұмысты орындайды. C тілінде күлгін бөліктің орнына print сөзін, дәлірек айтқанда printf деп жазамыз. f әрпі formatted (пішімделген) дегенді білдіреді, себебі бұл функция жай мәтін шығарудан гөрі қуаттырақ. Одан кейін сол және оң дөңгелек жақшалар келеді. MIT функциялардың кірісіне сопақ пішінді кездейсоқ таңдамаған: ол жақшаларға ұқсайды.

    printf("hello, world\n");

    Жақшаның ішінде кем дегенде hello, world болуы керек. Бірақ C-да Scratch-тағыдай емес, компьютерге не шығару керегін түсіндіру үшін қосымша синтаксис керек:

    • Қос тырнақша "...": hello деген сөз арнайы функция не айнымалы емес, шығаруға тиісті мәтін екенін білдіреді. Бір тырнақша басын, екіншісі соңын көрсетеді.
    • \n: көп жағдайда шығарғыңыз келген сөздің соңына осыны қоясыз. Төменде оның не істейтінін көреміз.
    • Нүктелі үтір ;: бағдарламалаудағы ең тітіркендіретін нәрсе. Ағылшын (не қазақ) тілінде сөйлемді нүктемен аяқтағандай, C-да ойыңызды нүктелі үтірмен аяқтайсыз.

    Бағдарламалаудың, әсіресе C-ның ерекшелігі: осы ұсақ-түйектің кез келгенін қате жазсаңыз, бірдеңе бұзылады. Сондықтан алғаш жазған не компиляциялаған бағдарламаңыз жұмыс істемесе, жалғыз емессіз. Уақыт өте келе мұндай ұсақ, бірақ компьютер үшін маңызды егжей-тегжейді байқауды үйренесіз.

    Математикадағы функциялар да осыған ұқсайды: f(x) функциясы x-ті кіріс ретінде алып, шығыс береді. Ал кодта шығыстың түрі әртүрлі болуы мүмкін. Кейде ол жанама әсер болады: экранда бірдеңе пайда болады не динамиктен дыбыс шығады. Өткен аптада «hello, world» кірісі «say» функциясына берілгенде, жанама әсер ретінде мысықтың сөз бұлты пайда болды. printf те дәл солай жұмыс істейді.

    \n не істейді?

    \n-нің не істейтінін білмейміз, сондықтан оны өшіріп көрейік:

    printf("hello, world");

    Терминалда қайта ./hello деп іске қоссақ, ештеңе өзгермеген сияқты. Неге? Себебі біз қайта компиляцияламадық. Компилятор бастапқы кодты машиналық кодқа бірнеше минут бұрын айналдырған еді. Бастапқы код өзгерсе, жаңа машиналық код алу үшін оны қайта компиляциялау керек:

    $ make hello
$ ./hello
hello, world$

    Енді айырмашылық көрінеді. Функционалды тұрғыдан бағдарлама «hello, world» деп шығарады, бірақ эстетикалық қате бар: $ шақыруы сол жолда қалып қойды. Яғни \n бізге жаңа жол (new line) береді. Біз оны эстетика үшін қойдық: бағдарлама аяқталғаннан кейін шақыру сол жолда қалса, жай ғана ұсқынсыз көрінеді.

    Қашу тізбектері

    \n — қашу тізбегі (escape sequence). Бұл ерекше әрекет жасайтын арнайы таңбалар тізбегі. Кейбіреулері (толық тізім емес):

    ТізбекМағынасы
    \nЖаңа жолға көшу
    \rКаретканы қайтару (carriage return): ескі баспа машинасындағыдай курсорды жолдың басына апарады, яғни көлденең жылжытады
    \"Қос тырнақшаның өзі
    \'Жалқы тырнақша (апостроф)
    \\Кері қиғаш сызықтың өзі

    Неге \" керек? Студент айтқандай, "hello, "world"" деп жазсақ, компьютер қай тырнақша қайсысына сәйкес келетінін білмейді, бұл екіұшты. Тырнақша ішінде нағыз қос тырнақшаны шығару керек болса, қашу тізбегі компьютерге «бұл ойдың басы мен соңын білдіретін тырнақша емес, жай таңба» деп айтады.

    \n-ді білмесек, курсорды келесі жолға апару үшін Enter-ді басып, тырнақша мен жақшаны келесі жолға көшірер едік. Бірақ бұл көптеген тілдің бір принципін бұзады: тілдердің көбі жолға негізделген, ойды бір жолда бастап, бір жолда аяқтау керек. Оның үстіне, кодты алғаш көрсеңіз де, ойдың бір бөлігін келесі жолға көшіру ұқыпсыз көрінеді. Сондықтан C, Python және басқа көп тіл осы қашу тізбектерін береді.

    Қателер және тақырыптық файлдар

    Терминалды clear командасымен не Ctrl+L арқылы тазалауға болады. Бұл тек эстетика үшін.

    Нүктелі үтірді ұмытсақ

    Код дұрыс, бірақ нүктелі үтірді ұмыттық делік:

    $ make hello
hello.c:5:29: error: expected ';' after expression
    printf("hello, world\n")
                            ^
                            ;
1 error generated.

    Кодтың өзіндей ұзын қате хабары шықты, бірақ қорықпайық. Мұнда мәселе бар файлдың аты (hello.c), жол нөмірі (5) және таңба нөмірі (29) көрсетілген. Хабардың өзі де түсінікті: «өрнектен кейін нүктелі үтір күтілді». Жасыл ^ белгісі қатеге нұсқап тұр. Бұл компилятордың тағы бір пайдасы: ол бастапқы кодты машиналық кодқа айналдырумен қатар, кодтағы қателерді табуға да шебер. Нүктелі үтірді қосып, make hello-ны қайта іске қоссақ, бәрі түзеледі.

    #include-ты ұмытсақ

    Енді код дұрыс, бірақ бірінші жолды, яғни #include <stdio.h> жолын ұмыттық делік:

    $ make hello
hello.c:3:5: error: call to undeclared library function 'printf' with type
'int (const char *, ...)'; ISO C99 and later do not support implicit
function declarations [-Wimplicit-function-declaration]

    Бұл хабар әлдеқайда түсініксіз. Кодтың қалған бөлігі шынымен дұрыс болса, мұндай хабар нені білдіретінін бұрын көрмеген адамға шешімі айқын емес. «Жарияланбаған кітапхана функциясы printf» деген не?

    Термин: тақырыптық файл және кітапхана C тілімен бірге көп тақырыптық файл (header file) келеді. Олардың аты .c-мен емес, .h-пен аяқталады. Оларда басқа адамдар жазған, сіз өз бағдарламаңызда пайдалана алатын код бар. Тақырыптық файл кітапханаға (library) қол жеткізуге мүмкіндік береді. Кітапхана — басқа біреу жазған, сіз пайдалана алатын код.

    0-аптада import жолымен OpenAI-ді қолданғанда да кітапхана пайдаландық. Чатботты қалай іске асыруды білмей тұрып, сол компания жазған кодтың «иығына шықтық». Мұнда да солай: printf C-ның бір мүмкіндігі болса да, оны пайдалану үшін ол анықталған тақырыптық файлды қосуыңыз керек. Бұл файл — stdio.h (standard input/output, стандартты енгізу-шығару).

    Жиі кездесетін қате Ол studio.h емес! Студия емес, st-d-io: standard I/O. Интернетте бұл өте жиі кездесетін қате.

    Бірінші жол компиляторға: «айтпақшы, мен пайдаланатын кодтың бәрін өзім жазған жоқпын. printf-тің анықтамасын stdio.h атты басқа файлдан қос» деп айтады. Мұны тек анықтамалықтан, сабақтан не біреу айтқанда ғана білесіз.

    Нұсқаулық беттері

    Мұндай нәрселерді қайдан іздейміз? C тілі туралы жүздеген кітап, көп сайт бар. C-да нәрсені іздеудің дәстүрлі тәсілі — ресми нұсқаулық беттері (manual pages, қысқаша man pages). Өкінішке қарай, олардың көбі ондаған жыл бұрын тәжірибелі бағдарламашылар үшін жазылған. Сондықтан CS50 сол тегін құжаттаманы manual.cs50.io сайтына жинап, «бастаушыларға арналған» (less comfortable) режимде жеңілдетіп жазды. Мысалы:

    • manual.cs50.io/#stdio.h: stdio.h құжаттамасы.
    • manual.cs50.io/3/printf: printf құжаттамасы.

    Әр бетте функцияның аты, қысқаша сипаттамасы (synopsis), қай тақырыптық файлда анықталғаны, прототипі (функцияның бірінші жолы, бұған кейін ораламыз), ағылшынша сипаттамасы және мысал коды бар. Сайтқа «less comfortable» құсбелгісін алып тастасаңыз, түпнұсқа ресми құжаттаманы көресіз. cs50.ai үйрегі де бар, бірақ ресми құжаттаманы қарауды әдетке айналдырыңыз. Қазіргі AI-лардың бәрі де осындай құжаттамада үйретілген.

    CS50 кітапханасы

    Ресми функциялардан басқа, CS50 өзі ойлап тапқан функциялар да бар. Олар алғашқы бірнеше аптаға арналған «жаттықтыру дөңгелектері» (training wheels). Кейін оларды алып тастаймыз. C-да кейбір нәрселер, мысалы, қолданушыдан мәтін не сан алу, бастаушы үшін тым қиын әрі тітіркендіретін. Кейін оны «нағыз» тәсілмен жасауды да көрсетеміз.

    CS50 кітапханасының тақырыптық файлы cs50.h деп аталады (құжаттамасы). Онда мынадай функциялар бар:

    • get_char
    • get_double
    • get_float
    • get_int
    • get_long
    • get_string
    Термин: жол (string) Бағдарламалауда жол (string) мәтінді, яғни нөл не одан көп таңбаны білдіреді. Мысалы, H-E-L-L-O W-O-R-L-D. Бұл 50 сияқты сан емес, пернетақтада теретін мәтін. Бұл еңбекте string сөзі көбіне «жол» не «мәтін» деп аударылады.

    Қолданушыдан мәтін алу

    0-аптада сұрақ қойып, жауапты пайдаланатын бағдарлама жаздық: көгілдір «ask What's your name? and wait» блогы. «say» блогынан айырмашылығы, ол тек жанама әсер бермей, қайтарылатын мән, яғни адамның атын қайтарады. Scratch-та ол автоматты түрде answer айнымалысына сақталатын.

    C-да бұл былай жазылады:

    string answer = get_string("What's your name? ");

    Бөлшектеп қарайық:

    • C-да ask атты функция жоқ, оның ең жақын баламасы CS50 кітапханасындағы get_string. Оны әдейі осылай атадық: ол жол (string) алады (get).
    • Дөңгелек жақша ішіне сұрақты жазамыз. Тырнақшалар міндетті, себебі бұл ерекше сөздер емес, қолданушыға көрсетілетін тұтас фраза.
    • Сұрақ белгісінен кейін бір бос орын қалдырдық. Бұл эстетика үшін: курсор сұрақ белгісіне тиіп тұрмай, сәл оңға жылжиды. Ал \n қоймадық, себебі қолданушы жауабын сол жолда терсін дейміз.
    • Қайтарылған мәнді сақтау үшін теңдік белгісін пайдаланамыз, ал оның сол жағына айнымалының атын жазамыз. Айнымалыға кез келген ат қоюға болады. Дәстүр бойынша олар кіші әріппен жазылады және ішінде бос орын болмайды.
    • C Scratch-тан гөрі дәлірек: айнымалыға тек ат беру жеткіліксіз, компиляторға оған қандай типтегі мән салатыныңызды айту керек. Мәтін болса, string, сан болса, басқа тип.
    • Соңында тағы да нүктелі үтір.

    Scratch-тан бастағанымыздың себебі де осы: интуицияны тез ұғасыз, ал оң жақтағы кодтың ешқайсысы қиын емес. Тек уақыт өте келе бойға сіңіретін ұсақ-түйектер көп. Курста тілдердің қалай дамығанын да көреміз. Мысалы, Python-да бұл синтаксистің біразы жойылады, себебі адамдар ескі тілдерден жалықты: «жолдың соңы екені анық болса, неге нүктелі үтір қоюым керек?».

    Орынбасарлар: %s

    Енді hello.c-ны өзгертейік. Жоғарыға cs50.h-ты қосамыз, яғни екі тақырыптық файл болады:

    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    string answer = get_string("What's your name? ");
    printf("hello, answer\n");
}

    Бұл интуитивті, бірақ дұрыс емес. Бұрын бағдарламаламасаңыз да, қатені көріп тұрған боларсыз. get_string экранға «What's your name?» деп шығарады, демек ол ішінде printf-ті өзі пайдаланады. Бұл хабарды өзіміз шығарудың қажеті жоқ. Компиляциялап, David деп енгізсек, экранда hello, answer шығады. Компьютер айтқанымызды сөзбе-сөз орындады. Біз оған «hello, answer» деп шығар дедік.

    Scratch-та бұл үшін join блогын пайдаланатынбыз. C-да бүгін көретін тікелей баламасы жоқ, сондықтан басқаша жасаймыз. «hello, », сосын орынбасар шығар, ал есімі белгілі болғанда сол орынға қойылсын дейміз. Код жазған кезде ойынды кім ойнайтынын (мен, Kelly не басқа біреу) білмеймін.

    printf("hello, %s\n", answer);
    • %s — жолға арналған орынбасар (format code). Мұны тек біреу айтқанда не анықтамалықтан ғана білесіз.
    • Жақшада енді екінші аргумент бар: answer, яғни орынбасардың орнына қойылатын мән сақталған айнымалы.
    • Үтірлердің «соқтығысуына» назар аударыңыз. Тырнақша ішіндегі үтір — жай ағылшын грамматикасы. Ал тырнақшадан тыс үтір C үшін маңызды: ол бірінші аргументті екіншісінен ажыратады. Функцияның қанша аргумент қабылдайтыны оның қалай жобаланғанына байланысты: 1, 2, 3, 4...
    $ make hello
$ ./hello
What's your name? David
hello, David

    Залдан келген сұрақтар

    — Тақырыптық файлдар қайдан алынады? Сіз көріп отырған GUI бұлтта, cs50.dev сайтында орналасқан. Ол бір компьютерде жұмыс істейді, ол компьютерде қатты диск не SSD бар. cs50.h, stdio.h және басқа файлдар сол серверге алдын ала орнатылған әрі стандартты жерде сақталған, сондықтан компилятор оларды қай жерден іздеу керегін біледі.

    — Неге get_string-те \n жоқ? Бұл менің бағдарламашы ретіндегі таңдауым. Мен «What's your name?» сұрағын көріп, атымды бірден сол жолға жазғым келді.

    — Әр бағдарламада бастапқы 4 жолды жаза беру керек пе? Әзірге иә, маған сеніңіз. Келесі аптада олар не істейтінін толық түсінеміз. Тек бір ескерту: cs50.h-ты тек біздің функцияларымызды пайдаланғанда ғана қосыңыз. Бірінші мысалдағыдай жай мәтін шығарсаңыз, ол қажет емес.

    — Бірінші аргумент кіріс сияқты емес, ол жай ғана менің қойған сұрағым ғой? Иә, бірінші кірісті мен береді, екіншісін қолданушы береді. Бірақ екеуі де функцияға берілгендіктен, екеуі де кіріс болып саналады. Біріншісін алдын ала білемін, ал екіншісін білмеймін, сондықтан оны айнымалыда сақтаймын.

    Linux және терминал командалары

    Тақырыптық файлдар қайда сақталатыны туралы сұраққа қайта оралайық. Көбіңіз macOS не Windows пайдаланасыз, бірақ әлемде басқа да операциялық жүйелер бар: телефонда iOS, iPad-та iPadOS, Android құрылғыларында Android. Операциялық жүйе құрылғыдағы ең негізгі әрекеттерді орындайды: оны іске қосады, сөндіреді, құжатты принтерге жібереді, экранға бірдеңе көрсетеді, терезелер мен иконкаларды басқарады.

    Бағдарламалау әлемінде және бұлттағы, интернеттегі серверлер әлемінде өте танымал операциялық жүйе — Linux. Ол көптен бері бар Unix-тің ұрпағы. Көп бағдарламашы оны пайдаланады, себебі Linux өте өнімді: серверлерде мыңдаған, миллиондаған қолданушыға қызмет көрсете алады. Оның графикалық интерфейсі болуы мүмкін, бірақ көбіне болмайды. Сондықтан ол тезірек жұмыс істейді, себебі тек адамға арналған графиканың қажеті жоқ. Linux-тың көп командасы бар:

    КомандаМағынасыНе істейді
    cdchange directoryБасқа қалтаға (директорияға) өту
    cpcopyФайлды көшіру
    lslistАғымдағы қалтадағы файлдардың тізімі
    mkdirmake directoryЖаңа қалта жасау
    mvmoveФайлды жылжыту не атын өзгерту

    rmdirremove directoryҚалтаны өшіру

    Командалар өте қысқа, себебі командалық жол интерфейсінің мақсаты жылдам жұмыс істеу. Оларды жаттауға уақыт пен жаттығу керек. Есептер жинақтарында (problem sets) алғашында қандай команда жазу керегін қадам-қадаммен айтамыз, кейін бұл әдетке айналады.

    Демо: қалталармен жұмыс

    Файлдар панелінде (сіздікі сәл басқаша болады, онда өз бірегей идентификаторыңыз тұрады) бүгін жасаған hello.c және make жасаған hello бар. ./hello жұмыс істейтіні де сондықтан: ағымдағы қалтада шынымен hello атты бағдарлама бар.

    Семестр бойы бағдарламалар көбейгенде бір қалтада «бейберекеттік» пайда болады. Сондықтан ішкі қалталар жасайық. Мұны тышқанмен де жасауға болады (оң жақ батырма → New Folder), бірақ CLI-ды үйренейік:

    $ rm hello
rm: remove regular file 'hello'? y
$ mkdir hello
$ mv hello.c hello
$ ls
hello/
$ cd hello
hello/ $ ls
hello.c
hello/ $ make hello
hello/ $ rm hello
rm: remove regular file 'hello'? y
hello/ $ mv hello.c old.c
hello/ $ mv old.c hello.c
hello/ $ cp hello.c backup.c
hello/ $ ls
backup.c  hello.c
hello/ $ rm backup.c
hello/ $ mv hello.c ..
hello/ $ cd ..
$ rmdir hello
$ ls
hello.c

    Не болды?

    • rm hello: компиляцияланған бағдарламаны (hello.c-ны емес!) өшірдік. y (иә) деп растадық. Жоғарғы сол жақтағы файлдар панелінен ол бірден жоғалды.
    • mkdir hello: hello атты қалта жасадық.
    • mv hello.c hello: файлды қалтаға жылжыттық. mv командасына екі сөз береміз: қайдан және қайда. Қалта екенін анық көрсету үшін соңына / қоюға болады. hello қалтасы бар болғандықтан, Linux файлдың атын өзгертпей, оны қалтаның ішіне салатынын біледі.
    • ls: тек hello/ көрінеді. Түспен белгіленген және соңында / бар, себебі бұл қалта.
    • cd hello: қалтаға кірдік. Шақыру hello/ $ болып өзгерді. Бұл қай қалтада тұрғаныңызды еске салатын CS50-дің дәстүрі.
    • mv hello.c old.c: екі файл атын берсек, mv жай ғана атын өзгертеді. Жеке «rename» командасы жоқ.
    • cp hello.c backup.c: «бүлдіріп алсам» деп резервтік көшірме жасадық.
    • mv hello.c ..: .. — ата-аналық қалта (бір деңгей жоғары). Ал жалғыз нүкте . — ағымдағы қалта. Үш не төрт нүкте деген жоқ.
    • cd ..: бір деңгей жоғары шықтық. Шатасып қалсаңыз, жай ғана cd деп Enter басыңыз. Сонда үй қалтаңызға (home directory) ораласыз.

    Яғни осы негізгі командалармен Mac не PC-де тышқанмен жасап жүрген нәрселердің бәрін жасай аласыз.

    — Қалтада 5 файл болса, біреуін қалай ашамын? code командасына файлдың атын бересіз. Кейін жұлдызша * (wildcard) арқылы «осы қалтадағының бәрін аш» сияқты әдістерді де көреміз.

    — hello қалтасының ішінде hello бағдарламасын жасауға бола ма? Иә. Бір жерде бірдей аты бар екі нәрсе болмайды, олар «соқтығысады» (Mac пен PC-де де солай). Бірақ бір нәрсені басқа қалтаның ішіне салуға болады.

    Шарттар

    Енді Scratch-тағы басқа мүмкіндіктерді C-ға көшірейік. Шарттар жолдың айрығы сияқты: логикалық өрнектің жауабына қарай мынаны не ананы істейміз.

    Scratch-тағы «if x < y then say x is less than y» блогы C-да былай жазылады:

    if (x < y)
{
    printf("x is less than y\n");
}
    • if, бос орын, дөңгелек жақшалар. Бұл жақшалардың функцияға қатысы жоқ: if функция емес, ол шартты іске асыратын C тілінің бір мүмкіндігі (Scratch-тағы сарғыш блок сияқты).
    • Жақша ішінде логикалық өрнек. Слайдта көрсетілмесе де, жоғарыда x пен y айнымалылары жасалып, оларға мән берілген деп есептейміз. < математикадағы «кіші» таңбасы. Жауабы ақиқат не жалған: не кіші, не кіші емес.
    • Фигуралы жақшалар ішінде ескі досымыз printf.
    • Фигуралы жақшалар Scratch-тағыдай кодты «құшақтап» тұр. Шындығында, C-да тек бір жол болса, олар міндетті емес. Бірақ көптеген компаниялар сияқты, CS50 де бәрі бірдей көрінетін код жазу үшін белгілі бір стильді ұстанады. Бұл — сақтауыңыз керек дәстүр.
    • Ішіндегі жол 4 бос орынмен шегіністе жазылады. Бұл ол тек сұрақтың жауабы «иә» болғанда орындалатынын көрсетеді.

    Екі жолды айрық, яғни «if / else»:

    if (x < y)
{
    printf("x is less than y\n");
}
else
{
    printf("x is not less than y\n");
}

    Үш жолды айрық:

    if (x < y)
{
    printf("x is less than y\n");
}
else if (x > y)
{
    printf("x is greater than y\n");
}
else if (x == y)
{
    printf("x is equal to y\n");
}
    = және == айырмашылығы == қате емес. Бір теңдік белгісі = — меншіктеу операторы (assignment operator). Мысалы, get_string қайтарған мәнді answer-ге сақтағанда оңнан солға көшіреміз. Шамасы, тілді ойлап тапқан адамдар шарттың синтаксисіне келгенде «теңдік белгісін меншіктеуге пайдаланып қойдық, теңдікті не белгілейміз?» деп ойлаған. C-дағы және көп басқа тілдегі шешім: екі теңдік белгісі ==, яғни теңдікті салыстыру операторы. Scratch кішкентай балаларға арналғандықтан, оларды шатастырмау үшін бір = қолданады.

    Бұл код дұрыс, бірақ жақсы жобаланбаған. Неге? Студент айтқандай, үшінші сұрақтың қажеті жоқ. Әдеттегі сандармен жұмыс істесек, x не кіші, не үлкен, не тең. Алғашқы екеуі жалған болса, теңдік сөзсіз ақиқат. Үшінші сұрақ компьютердің, демек қолданушының уақытын ысырап етеді. Үш мүмкіндіктің екеуін ғана тексерсе жеткілікті:

    if (x < y)
{
    printf("x is less than y\n");
}
else if (x > y)
{
    printf("x is greater than y\n");
}
else
{
    printf("x is equal to y\n");
}

    Бұл шағын оңтайландыру (optimization), бірақ оны кодыңызда қайта-қайта қолданатыныңызды елестетіңіз.

Бағдарламалауда леп белгісі әдетте терістеуді (negation) білдіреді. Логика бойынша !== болуы керек сияқты, бірақ олар пернені үнемдеген.

    C-да жолдардан басқа да деректер типтері бар:

    ТипНе сақтайды

    charБір ғана таңба (жол емес). C бір таңба мен көп таңбаны ажыратады
    doubleОндық бөлшегі бар сан, 64 бит, яғни дәлірек
    floatОндық бөлшегі бар сан (floating-point), әдетте 32 бит

    float-тың шектеуі: 32 битпен шамамен 4 миллиард мән ғана беруге болады. Ал математикада нақты сан қанша? Шексіз көп. Біз кодта бере алатын сандар мен әлемдегі сандар арасында сәйкессіздік бар. Дәлдік (маңызды цифрлар) көбірек керек болса, double-ға «жаңартуға» болады. Ол 64 бит, яғни әлдеқайда дәл. Бірақ ол мәселені түбегейлі шешпейді, себебі бәрібір шексіз емес, шектеулі. Сабақ соңында мұның нақты салдарын көреміз.

    32 биттік int-пен шамамен 4 миллиардқа дейін санауға болады. Теріс сандар да керек болса, бұл шама теріс 2 миллиардтан оң 2 миллиардқа дейін болады. Қазіргі кезде бұл онша көп емес. long 64 бит, ауқымы әлдеқайда үлкен, бірақ ол да шектеулі.

    cs50.h қосылса, get_char, get_double, get_float, get_int, get_long, get_string функциялары қолжетімді. get_bool жоқ, себебі әдетте тек ақиқат не жалған мәнді сұраудың пайдасы аз. Оны жасауға болар еді, бірақ жасамауды жөн көрдік.

    printf үшін әр типтің өз пішім коды (format code) бар:

    КодТип

    Бұл интеллектуалдық тұрғыдан қызықты емес, бірақ пайдалы, уақыт өте келе бойға сіңетін практикалық нәрселер.

    Айнымалылар

    Scratch-та ұпайды санау үшін counter айнымалысын жасап, оны 0-ге орнатып, кейін 1, 2 қосып отыратынбыз. C-да:

    int counter = 0;

    Айнымалының атын (counter) таңдаймыз, оған бастапқы мән (0) береміз. Ал сол жаққа тағы не қосу керек? Тип. Санаушы сан болғандықтан, мәтін емес. Саусақпен санағандай, үтірдің де қажеті жоқ. Сондықтан int жеткілікті: 2 миллиардтан көп мән қажет болмаса, ол сандар үшін ең бірінші таңдау. Соңына нүктелі үтір қоямыз.

    Scratch-тағы «change counter by 1» блогы C-да бірнеше тәсілмен жазылады:

    counter = counter + 1;
counter += 1;
counter++;

    Біріншісі қате сияқты көрінеді: counter қалайша counter + 1-ге тең бола алады? Бірақ бұл теңдік емес, меншіктеу: оң жақтағы мәнді алып, сол жақтағы айнымалыға көшір. Ағымдағы мән 0 болса, оған 1 қосып, 1-ді counter-ге сақтаймыз. Тағы орындасақ 2, 3, 4...

    Бұл соншалықты жиі қолданылатындықтан, қысқартылған жазулары бар: counter += 1 дәл солай істейді, ал counter++ одан да қысқа. +++ немесе одан көп плюс жоқ, ++ тек 1-ге арттыру үшін. Сондықтан алғашқы екі нұсқа икемдірек, олармен 2 не 3 қоса аласыз. Азайту үшін де балама жазулар бар: counter -= 1, counter--.

    Демо: compare.c

    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    int x = get_int("What's x? ");
    int y = get_int("What's y? ");

    if (x < y)
    {
        printf("x is less than y\n");
    }
}

    get_int функциясын екі рет шақырып, екі түрлі мән аламыз. Қызық бағдарлама емес, бірақ динамикалық. make compare жұмыс істеді ме, оны ls арқылы тексеруге болады: compare.c және compare* пайда болды. Жұлдызша оның орындалатын (executable) бағдарлама екенін білдіреді.

    1 мен 2 берсек, «x is less than y». 2 мен 1 берсек, ештеңе шықпайды. Себебі «үлкен» не «тең» жағдайы үшін шарт жазған жоқпыз. Сондықтан else қосып, «x is not less than y» деп шығарамыз. Бірақ 1 мен 1 берсек, жауап дұрыс болғанымен, онша дәл емес. Сондықтан алдыңғы бөлімдегідей үш жағдайды толық жазамыз және соңғы артық сұрақты алып тастаймыз.

    Неге үш бөлек if жазбаймыз? Кодты былай да жазуға болар еді:

    if (x < y) { ... }
if (x > y) { ... }
if (x == y) { ... }

    Студент айтқандай, бұл да жаман жобалау. Енді қандай жағдай болса да үш сұрақ қойылады. x басынан y-тен кіші болса да, «x үлкен бе? x тең бе?» деп бәрінің уақытын текке кетіреміз.

    Блок-сызбалар Көрнекі түрде оқитындар үшін кодты блок-сызба (flowchart) түрінде салуға болады. Бастау, ромб ішінде логикалық өрнек (иә/жоқ), тіктөртбұрышта әрекет (шығару), соңында «тоқта». if / else if / else нұсқасында «x < y» ақиқат болса, бірден соңына «қысқа жолмен» жетеміз. Ал үш бөлек if нұсқасында блок-сызба ұзынырақ, үш сұрақтың бәрінен өтеміз. Кез келген кодты осындай суретке айналдыруға болады, ол шегініс пен синтаксис білдіретін логикалық ағынды көрсетеді.

    Демо: agree.c (char және логикалық операторлар)

    Қазір бізден «шарттармен келісесіз бе?» деп жиі сұрайды. Иә/жоқ жауабы үшін тұтас жол емес, бір char жеткілікті:

    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    char c = get_char("Do you agree? ");

    if (c == 'y')
    {
        printf("Agreed.\n");
    }
    else if (c == 'n')
    {
        printf("Not agreed.\n");
    }
}

    Неге бұл жолы жалқы тырнақша? Себебі бұл бір таңба. C-да бір таңбаны салыстырғанда char және жалқы тырнақша ' ', ал бірнеше таңба, сөз не сөйлем болса string және қос тырнақша " " пайдаланылады.

    Қолданушы бірнеше таңба терсе (мысалы, «no»), get_char қайта сұрайды. CS50 функциялары деректердің типін қадағалайды, қолданушы ынтымақтаспаса, қайта-қайта сұрай береді. Мұндай қателерді тексерумен өзіңіз айналыспайсыз.

    Бірақ бас әріппен Y терсек ше? Бұл қате сияқты. Тек y мен n-ді қабылдасақ та, олардың бас әріпті нұсқасын қолдамау тітіркендіреді. else if (c == 'Y') қосып, ішіне сол printf-ті жазуға болар еді. Бірақ бұл код артық: көшіріп-қоймасақ та, екі жол бірдей. Мәтінді өзгерткіміз келсе, екі жерде өзгерту керек. Шешімі — логикалық операторлар:

    if (c == 'y' || c == 'Y')
{
    printf("Agreed.\n");
}
else
{
    printf("Not agreed.\n");
}
    • || (екі тік сызық) — логикалық НЕМЕСЕ. Екі кіші логикалық өрнектің кем дегенде біреуі ақиқат болса жеткілікті. Бұл таңба пернетақтада сирек басылады, оның орны тілге байланысты.
    • && (екі амперсанд) — логикалық ЖӘНЕ. Бірақ мұнда ол мағынасыз. Неге? Бір айнымалы бір мезетте әрі кіші, әрі бас әріп бола алмайды.
    • Тек y-ді қабылдап, қалғанының бәрін «келіспеді» деп санасақ, else if-тің орнына else жеткілікті.

    Циклдер

    Scratch-та мысықты 3 рет мияулату үшін «repeat 3» блогын қолдандық. C-да мұны бірнеше тәсілмен жасауға болады. Біріншісі — while циклі:

    int i = 3;
while (i > 0)
{
    printf("meow\n");
    i--;
}

    C-да repeat деген кілт сөз жоқ, сондықтан Scratch-ты сөзбе-сөз аудара алмаймыз. Бірақ while (әзірге) оның ең жақын баламасы. i айнымалысын (integer, яғни бүтін сан деген сөзден) 3-ке теңестіреміз. «i 0-ден үлкен болғанша» мына әрекетті орындаймыз. Цикл қайта басталар алдында i-- арқылы i-ден 1-ді азайтамыз. Сонда i 3 → 2 → 1 → 0 болады. 0 болғанда логикалық өрнек жалған болып, цикл өздігінен тоқтайды. Ішінде meow үш рет шығады.

    Қызығы, мен саусақпен 1, 2, 3 деп санадым, ал кодта 3, 2, 1 деп кері санап отырмыз. 0-ден жоғары санауға да болады:

    int i = 0;
while (i < 3)
{
    printf("meow\n");
    i++;
}

    Логикасы: i = 0, 0 < 3 ақиқат, meow шығады, i = 1. Цикл басына оралып, шарт қайта тексеріледі. while циклі осылай жұмыс істейді: шарт үнемі қайта-қайта тексеріледі. i 0 → 1 → 2 → 3 болады. 3 < 3 жалған, сондықтан цикл тоқтайды, барлығы 3 meow.

    Бірнеше рет қайталау өте жиі кездесетіндіктен, while міндетті емес. for циклі де бар. Оның синтаксисі сәл оғаштау, жаттау қиындау, бірақ бір жолға көбірек код жазып, кодты азайтуға мүмкіндік береді:

    for (int i = 0; i < 3; i++)
{
    printf("meow\n");
}

    for циклін оқу тәсілі де дәл сондай:

    1. Бірінші нүктелі үтірге дейінгі бөлік инициализация: айнымалы жасалып, оған мән беріледі. Бұл тек бір рет орындалады.
    2. Екі нүктелі үтірдің арасы шарт: i < 3 бе? Иә болса, фигуралы жақша ішіндегі код орындалады.
    3. Екінші нүктелі үтірден кейінгі бөлік жаңарту: i++ автоматты түрде орындалады, i 0-ден 1-ге өтеді.
    4. Шарт қайта тексеріледі, т.с.с. 3 < 3 жалған болғанда for циклі тоқтайды.

    Нәтижесі бірдей, бірақ «сиқырдың» көбі бірінші жолда орындалады. Бұл кеңірек тараған дәстүр, бірақ while да, for да дұрыс.

    Демо: cat.c

    Алдымен «дұрыс емес» тәсіл: printf("meow\n"); жолын көшіріп, үш рет қоямыз. Бұл жаман, себебі көшіріп отырмыз, бірақ мысық үш рет мияулайды, демек бағдарлама дұрыс. Енді жаңа құрылыс блоктарымызды қолданамыз:

    #include <stdio.h>

int main(void)
{
    for (int i = 0; i < 3; i++)
    {
        printf("meow\n");
    }
}

    1-ден бастап, «қалыпты адамдай» 3-ке дейін санағымыз келсе, int i = 1; i < 4 деп жазуға болады. Бұл дұрыс, 3 рет қайталанады, бірақ шатастырады: «4-тен кіші» дегеннің «3-ке тең» екенін ойлау керек. i <= 3 деп анығырақ жазуға болады. Қайсысы ең дұрыс? Кодта 0-ден бастап, керекті санға дейін, бірақ сол санды қоспай санау дәстүрге айналған. Сонда бастапқы және соңғы нүкте экранда бірге көрінеді.

    Мәңгілік цикл

    Scratch-тағы «forever» блогы C-да жоқ, бірақ while жеткілікті. while логикалық өрнек күтеді, ал бір нәрсені мәңгі істеу үшін әрқашан ақиқат өрнек керек. «2 > 1» не «1 < 2» сияқты өзгермейтін фактіні жазуға болар еді. Бірақ бағдарламалаудағы дәстүр бойынша жай ғана былай жазады:

    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    while (true)
    {
        printf("meow\n");
    }
}

    true үшін cs50.h қостық, себебі C-ның ескі нұсқаларында bool бірден қолжетімді болмаған (оны stdbool.h береді, CS50 кітапханасы оны автоматты түрде қосады). Мұндай бағдарлама шексіз мияулай береді: терминалды бақылаудан айырылып қаламыз. Үзіліс кезінде VS Code «код кеңістігінде CPU жүктемесі жоғары» деп ескертті!

    Ctrl + C — сіздің досыңыз Бағдарлама шексіз циклге түсіп кетсе (әдейі не кездейсоқ), терминалда Ctrl+C басыңыз. Бұл ағымдағы процесті үзеді. Кешіктіріп алсаңыз, браузер бетін қайта жүктеуге тура келуі мүмкін.

    Қолданушыдан сан сұрау және тексеру

    Мысық қанша рет мияулау керегін қолданушыдан сұрайық:

    int n = get_int("What's n? ");
for (int i = 0; i < n; i++)
{
    printf("meow\n");
}

    n айнымалысы (number деген сөзден) циклдегі 3-тің орнын басады. 3 енгізсек, 3 мияу, ал 4 енгізсек, 4 мияу. get_int не істейді? dog не bird сияқты бүтін сан емес нәрсені терсеңіз, ол кірісті қабылдамай, қайта сұрайды. Оның ішінде мұндай тексерісті жасайтын цикл бар. Бірақ ол бәрін тексермейді: бүтін сан теріс шексіздіктен оң шексіздікке дейінгі кез келген сан болуы мүмкін. Мысықтың −1 рет мияулауы мағынасыз, бірақ бағдарлама оны қабылдайды. Жақсы жобаланған бағдарлама «жоқ, −1 мағынасыз» деп айтуы керек.

    Бірінші ойға келетін тәсіл:

    int n = get_int("What's n? ");
if (n < 0)
{
    n = get_int("What's n? ");
}

    Назар аударыңыз: 6-жолда біз екі нәрсе істейміз: бүтін сан аламыз және n айнымалысын жасаймыз (declare). Айнымалының типі мен аты көрсетілсе, ол компьютердің жадында жасалады. Ал айнымалы бар болып, тек оның мәнін өзгерту керек болса, атын жазу жеткілікті. Типті қайта жазу ақымақтық болар еді, себебі компилятор оны біледі.

    Тексерейік: −1 енгізсек, қайта сұрайды, 3 енгізсек, жұмыс істейді. Бірақ −1, −1 енгізсек, бағдарлама екінші рет сұрамайды. Бізде тек екі мүмкіндік бар. Ішіне тағы if қосып отыру шексіз жалғаса береді, яғни көшіріп отырмыз. Қолданушыға қанша мүмкіндік береміз? Дұрыс кіріс алу үшін қажет болғанша сұрау керек. Ол үшін циклдің өзі бар!

    while (true)
{
    int n = get_int("What's n? ");
    if (n < 0)
    {
        continue;
    }
    else
    {
        break;
    }
}
    • continue — циклдің басына қайт, сол әрекетті қайталау.
    • break — циклдан шығып, оның жабылатын фигуралы жақшасынан кейінгі кодқа өт.

    Логикалық тұрғыдан дұрыс, бірақ компиляция қате береді:

    cat.c:19:25: error: use of undeclared identifier 'n'

    19-жолда n-ді пайдаланамыз, ал оны 8-жолда жасадық. Мәселе неде? Біз n-ді цикл ішінде, яғни 7- және 17-жолдардағы фигуралы жақшалардың арасында жасадық. C-ның жұмыс тәсілі бойынша ол айнымалы тек сол цикл ішінде ғана бар. Бұл көріну аймағы (scope) мәселесі: айнымалы тек өзі жарияланған фигуралы жақшалардың ішінде ғана өмір сүреді.

    Шешімі: n-ді циклдан тыс, бірақ main-нің фигуралы жақшаларының ішінде жариялау:

    int n;
while (true)
{
    n = get_int("What's n? ");
    if (n >= 0)
    {
        break;
    }
}

    int n; — мәнсіз жарияланған айнымалы. Онда не бар, белгісіз (кейін ораламыз). Цикл ішінде оны қайта жасамаймыз, тек мән береміз. Енді −1, −1, −123, −50 деп енгізсек те, бағдарлама сұрай береді, ал 3 бергенде мияулайды. continue мен break-тің екеуі де міндетті емес: логиканы аударып, «n ≥ 0 болса, break» деп жазу жеткілікті. !(n < 0) деп те жазуға болар еді, бірақ оны оқу қиындау.

    do-while циклі

    while (true) деп мәжбүрлеп, кейін break-пен шығудың орнына, C-да тағы бір цикл түрі бар: do-while.

    int n;
do
{
    n = get_int("What's n? ");
}
while (n < 0);

    «Мынаны істе: фигуралы жақша ішіндегіні; әзірге n 0-ден кіші болса, қайтала». Логика сәл аударылған, бірақ ықшамырақ. Ең маңызды айырмашылығы: шарт циклдің басында емес, соңында тексеріледі. Бұл бір нәрсені кем дегенде бір рет істеу керек болғанда өте ыңғайлы. Қолданушыдан сұрақты кем дегенде бір рет сұрау керек екені анық, сондықтан алдымен істеп, өрнек ақиқат болса ғана қайталаймыз.

    Мем: жол жүгіргіш пен қасқыр Looney Tunes мультфильміндегі белгілі бір мем бар. Жол жүгіргіш (Road Runner) «жардың шетінде емеспін бе?» деп алдымен тексеріп, сосын жүгіреді, бұл while. Ал қасқыр (Wile E. Coyote) алдымен жүгіреді, тек кейін «шетте ме едім?» деп тексереді, бұл do-while. Бірақ ол кезде тым кеш болады 🙂

    Өз функцияларымыз

    0-аптада өз функцияңызды жасау туралы айттық. C әр қажетіңізді бермейді, CS50 кітапханасы да бермейді. Бағдарламалаудың едәуір бөлігі — идеяларды абстракциялау: есепті бір рет шешіп, кейін оны қайта-қайта пайдалану. Тіпті оны біз сияқты кітапханаға жинап, басқаларға да беруге болады.

    Scratch-та «play sound meow until done» блогын абстракциялап, meow атты жаңа блок жасадық. C-да бұл сәл оғаш көрінеді, бірақ келесі аптада түсінікті болады:

    void meow(void)
{
    printf("meow\n");
}
    • Бірінші void — функцияның қайтару типі. void ештеңе қайтармайды дегенді білдіреді.
    • meow — функцияның аты.
    • Жақша ішіндегі void — функцияның кірістері (аргументтері). void ештеңе қабылдамайды дегенді білдіреді.

    Бұл мағыналы: meow ештеңе қайтармайды, ештеңе қабылдамайды, тек мияулайды. Оның экранға «meow» шығаратын жанама әсері бар. Өткен аптада бұл дыбыс болатын.

    #include <stdio.h>

void meow(void)
{
    printf("meow\n");
}

int main(void)
{
    for (int i = 0; i < 3; i++)
    {
        meow();
    }
}

    Бұл жұмыс істейді. Енді өткен аптадағыдай драмалық түрде meow-ды файлдың ең соңына, мысалы 100-жолға көшірейік. «Көзден таса, көңілден таса». Бірақ C-да бір шарт бар. Компиляцияласақ, кодтан көп қате шығады:

    cat.c:9:9: error: call to undeclared function 'meow'; ...

    Неге компилятор осынша «ақымақ»? Себебі C компиляторлары өте қарапайым. Олар файлдың соңына дейін өздігінен қарап шықпайды, сізді сөзбе-сөз түсінеді. 9-жолда meow әлі жоқ болса, бұл қате. Функцияны қайта жоғарыға жылжытуға болады. Бірақ main — бағдарламаның басты бөлігі, файлды ашқанда оны бірінші көрген дұрыс. Функцияларды үнемі жоғарыға қойсақ, main төмен ығыса береді.

    Шешімі (бұл көшіріп-қоюдың орынды болатын жалғыз жағдайы): функцияның бірінші жолын (оның «қолтаңбасын», signature) көшіріп, main-нің үстіне нүктелі үтірмен қоямыз:

    #include <stdio.h>

void meow(void);

int main(void)
{
    for (int i = 0; i < 3; i++)
    {
        meow();
    }
}

void meow(void)
{
    printf("meow\n");
}
    Термин: прототип Прототип (prototype) — компиляторға берілген ишара, тіпті уәде: «meow атты функция болады, ол ештеңе қабылдамайды, ештеңе қайтармайды». Ол файлдың кейінгі бөлігінде анықталады деп сенім білдіреміз. Неге бұлай жұмыс істейтіні туралы келесі аптада көбірек айтамыз.
    Термин: түсініктеме C-да //-мен басталатын кез келген мәтін түсініктеме (comment). Бұл Scratch-тағы жапсырма қағаз сияқты: компьютерге емес, адамға арналған ескертпе. Ол өзіңізге не басқа біреуге сол жолда не болып жатқанын еске салады.

    Аргумент қабылдайтын функция

    Өткен аптада блокты өңдеп, оған n кірісін қосып, «meow n times» дедік. C-да:

    void meow(int n)
{
    for (int i = 0; i < n; i++)
    {
        printf("meow\n");
    }
}

    Функция әлі ештеңе қайтармайды (void), бірақ кіріс қабылдайды. Айнымалыны жасағандағыдай, функцияға кіріс (аргумент) бергенде оның типі мен атын көрсетесіз. Жақша ішінде нүктелі үтір қойылмайды. Енді main-де жай ғана meow(3); деп жазамыз. Прототипті де void meow(int n); деп өзгертуді ұмытпаңыз.

    Енді 3-ті қатаң кодтаудың орнына қолданушыдан сұрайық. Бұл көріну аймағын жақсырақ түсінуге көмектеседі:

    int main(void)
{
    int n = get_int("What's n? ");
    meow(n);
}

    n-ді main-де жасадық, оны meow-ға береміз. Ал meow-да тағы n бар... Бұл әдейі шатастырады. Мен ұмытып кетіп, «n бәрібір main-де анықталған ғой» деп void meow(void) қалдырсам, for-дағы n үшін «undeclared identifier n» қатесі шығады. Себебі n тек main-нің фигуралы жақшаларының ішінде бар. Сондықтан оны кіріс ретінде беру керек. Атын бірдей қоюға болады, бірақ шатастырмау үшін басқа ат берген жақсы:

    void meow(int times)
{
    for (int i = 0; i < times; i++)
    {
        printf("meow\n");
    }
}

    main ішінде мән n деп аталады, ал meow ішінде сол мән times деп аталады. Оны кіріс ретінде бергенде жаңа ат бересіз, бұл сіздің еркіңіз.

    Мән қайтаратын функция

    Енді теріс сан енгізуге болмайтындай, тек оң не нөл бүтін санды алатын өз функциямызды жазайық:

    #include <cs50.h>
#include <stdio.h>

int get_n(void);
void meow(int n);

int main(void)
{
    int n = get_n();
    meow(n);
}

// Теріс емес бүтін сан алу
int get_n(void)
{
    int n;
    do
    {
        n = get_int("What's n? ");
    }
    while (n < 0);
    return n;
}

// n рет мияулау
void meow(int n)
{
    for (int i = 0; i < n; i++)
    {
        printf("meow\n");
    }
}

    Жаңа нәрсе: return n;. Біз алғаш рет мәнді анық қайтарып отырмыз. Бұл функцияның атының алдындағы int-ке сәйкес келеді: get_n void емес, бүтін сан қайтарады. Оның жалғыз міндеті де осы. Енді get_n-нің жанама әсері жоқ, оның қайтарылатын мәні бар. Прототипті де жоғарыға қостық.

    Код сапасы: дұрыстық, жобалау, стиль

    Жақсы кодты CS50 де, жалпы әлем де үш өлшеммен бағалайды:

    • Дұрыстық (correctness): код ойлағандай жұмыс істей ме? Курста бұл тапсырманың (problem set) талабы, ал нақты өмірде өнім менеджері не директор шешкен талап.
    • Жобалау (design): код қаншалықты жақсы құрылған? Дұрыс бола тұра, компьютердің не адамның уақытын ысырап ететін, артық логикалық өрнектері бар мысалдарды көрдік. Ағылшын тілінде (не қазақ тілінде) тек дұрыс айту емес, дәлелді әрі жақсы айту сияқты.
    • Стиль (style): эстетика. Код әдемі шегіністермен жазылған ба, айнымалылар x, y, z емес, мағыналы аталған ба? Стиль компьютер үшін емес, басқа адамдар үшін маңызды.

    1-есептер жинағынан бастап мына құралдар беріледі:

    • check50: кодыңыздың дұрыстығын тексереді. Әр тапсырмада slug, яғни тапсырманың бірегей идентификаторы көрсетіледі. Ол кодтың жақсы жобаланғанын не стилін тексермейді, бірақ бұл бірінші кезең.
    • design50: CS50 үйрегіне негізделген. Ашық тұрған бағдарлама бойынша ChatGPT сияқты, бірақ жақсы ассистент айтатындай жобалау туралы кеңес береді. Жобалау субъективті.
    • style50: сол жақта кодыңыздың қалай көрінетінін, оң жақта курстың стиль нұсқаулығына (style guide) сай қалай көріну керегін көрсетеді.

    Бұрын бағдарламалаған кейбіреулерге CS50-нің стильдік таңдаулары ұнамауы мүмкін. Бұл нақты өмірде де солай. Бірақ компанияларда әдетте ресми стиль нұсқаулығы болады. Әртүрлі адам жазса да, бәрінің коды бірдей көрінуі үшін бәрі соны ұстанады.

    Mario

    Сабаққа кіргенде экранда ескі Super Mario Bros. ойыны көрсетіліп тұрды. Ол — бүйірге жылжитын ойын: Марио жоғары-төмен, солға-оңға жүгіріп, тиын жинап, деңгейдің соңына жетуге тырысады. Жолда кедергілер көп. Аспанда сұрақ белгілері бар төрт блок тұр. Олардың артында тиын жасырылған, Марио оларды басымен соғып, ұпай жинайды. Графиканы әзірге Scratch-та қалдырамыз, бірақ C-да осы идеялардың кейбірін іске асыра аламыз.

    Төрт сұрақ белгісі

    #include <stdio.h>

int main(void)
{
    for (int i = 0; i < 4; i++)
    {
        printf("?");
    }
    printf("\n");
}

    Ең қарапайым жолы — printf("????\n");. Бірақ 4-тің орнына 3, 5 не басқа сан керек болса, цикл ыңғайлы. Бірінші нұсқада мен printf("?\n") деп жазып, қатар емес, баған алдым. Студент байқағандай, әр сұрақ белгісінен кейін \n қойылған. Оны өшірсек, бәрі бір жолда шығады, бірақ курсор келесі жолға өтпейді. Шешімі: \n-ді циклдан тыс, сұрақ белгілерінің бәрі шыққаннан кейін бір рет шығару. \n — қашу тізбегі, оны жеке шығаруға әбден болады.

    Кірпіштер бағаны

    Кейін Марио секіріп өтуі керек кірпіштер бағаны кездеседі. Бұл шешім бізде бар: printf("#\n"); 3 рет. # белгісі шаршыға сәл ұқсайды.

    3×3 тор: кірістірілген циклдер

    Жер астында 3×3 кірпіш торы бар. Бұл қызық, себебі біз әлі екі өлшемде жұмыс істеген жоқпыз. Ескі баспа машинасын елестетіңіз: бір қатар кірпіш басамыз, басына қайтамыз, тағы бір қатар... printf әрқашан осылай, жол-жолмен басып шығарады, жоғары-төмен секірмейді.

    #include <stdio.h>

int main(void)
{
    // Әр қатар үшін
    for (int i = 0; i < 3; i++)
    {
        // Әр баған үшін
        for (int j = 0; j < 3; j++)
        {
            // Бір кірпіш шығару
            printf("#");
        }

        // Қатар соңында жаңа жолға өту
        printf("\n");
    }
}

    Циклдерді осылай кірістіруге (nested loops) әбден болады. Бірақ ішкі циклдің айнымалысы сыртқы циклдің айнымалысымен «таласпауы» үшін оған басқа ат береміз. Тағы бір бүтін сан керек болса, i бос болмаса, j қолдану дәстүрге айналған. i, j, тіпті k жарайды. Ал l, m, o-ға жетсеңіз, бір нәрсені дұрыс жасамай тұрсыз, жақсырақ атаулар ойлап табу керек.

    Бірінші нұсқада \n жоқ болғандықтан, 9 кірпіш бір жолда шықты. Студент «13-жолдан кейін» деп дұрыс тапты: бағандағы кірпіштер шыққан соң, сыртқы циклдің ішінде бір \n. Пішіні дәл шаршы емес, себебі # белгісі көлденеңінен гөрі тігінен ұзынырақ. Бірақ жеткілікті жақын.

    Айнымалыларды row және column (қатар, баған) деп атасақ, ойымыз анығырақ болады. Сыртқы цикл қатар-қатармен жүреді, ал әр қатарда ішкі цикл баған-бағанмен жүреді.

    Тұрақты

    Бұл программада тағы бір нәзік мәселе бар. Студент байқағандай, 3 саны екі жерде қатаң кодталған. Шаршыны үлкейтсек, екі жерде өзгерту керек. Біз оны «кейін зиянын тигізеді» деп айттық: әріптесіңіз 3-тің бірнеше жерде тұрғанын байқамауы мүмкін. Шешімі: айнымалы.

    const int n = 3;
for (int i = 0; i < n; i++)
{
    for (int j = 0; j < n; j++)
    {
        printf("#");
    }
    printf("\n");
}

    Одан да жақсысы: тұрақты (constant). const компиляторға бұл мән ешқашан өзгермеуі керек екенін айтады. Кейін кодта кездейсоқ n-ге басқа мән бергіңіз келсе, компилятор рұқсат бермейді, сізді өзіңізден қорғайды.

    Компьютердің шектеулері

    Енді компьютерлер онша жақсы істей алмайтын нәрселерге тоқталайық. Арифметикалық операторлар:

    ОператорМағынасы
    +қосу
    -азайту
    *көбейту
    /бөлу
    %бөлгендегі қалдық (модуль)

    Калькулятор

    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    int x = get_int("x: ");
    int y = get_int("y: ");
    printf("%i\n", x + y);
}

    Бүтін сан үшін орынбасар %i. Бастапқы нұсқада int z = x + y; деп үшінші айнымалы жасадық. Бірақ айнымалыны бір рет қана, келесі жолда ғана қолдансаңыз, оны жасау әдетте артық. Кейде ол кодты оқуға жеңілдетеді, мысалы, оны sum деп атасақ, екі айнымалының қосындысы екені түсінікті болады. Бірақ мұнда x + y-ті тікелей printf ішіне жазу да түсінікті. Бұл жобалаудың субъективті екенін көрсетеді: кейбір ассистенттер менімен келіспеуі мүмкін, ең маңыздысы — кодтың оқылуы.

    Тезірек теру тәсілдері
    • Файл атының бірнеше әрпін теріп, Tab бассаңыз, қалғаны автоматты толтырылады (autocomplete).
    • ↑ және ↓ көрсеткілерімен бұрын терген командаларыңыздың тарихын ақтарып, уақыт үнемдейсіз.

    Көбейту операторы *. x * 2 арқылы: 1 → 2, 2 → 4, 3 → 6.

    «Екі есе көбейтіп, келесі адамға бер» мемі және бүтін санның толып кетуі

    Соңғы жылдардағы бір мемді іске асырайық:

    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    int dollars = 1;
    while (true)
    {
        char c = get_char("Here's $%i. Double it and give to next person? ", dollars);
        if (c == 'y')
        {
            dollars *= 2;
        }
        else
        {
            break;
        }
    }
    printf("Here's $%i.\n", dollars);
}

    Назар аударыңыз: printf сияқты, CS50-дің get_char, get_int, get_string функциялары да орынбасарларды қолдайды. Сондықтан сұрақ қойғанда, сұрап отырған ақша сомасын көрсете аламыз. dollars *= 2 — dollars = dollars * 2-нің қысқа жазуы. ** деген жоқ.

    Y, y, y... $2, $4, $8, ..., $1 073 741 824 ... Экспоненциалды өсудің күшін көреміз! Сосын кенеттен теріс сан шықты, одан кейін 0. Мемдерде бұлай болмайды. Не болды?

    Студент дұрыс болжады: компьютер әр бүтін санға шектеулі бит бөледі. Әдетте 32, кейде 64. Бүтін сан оң да, теріс те бола алатындықтан, ол шамамен 2 миллиардқа дейін ғана санай алады. Біз бүтін санды толтырып жібердік.

    Термин: бүтін санның толып кетуі Бүтін санның толып кетуі (integer overflow) — бүтін санға тым үлкен мәнді сақтауға тырысу. Ноутбуктағы жад микросхемаларында көп бит бар, бірақ олар 8, 16, 32, 64-тен бөлінеді. Әр мәнге шектеулі бит бөлінеді.

    Мұны 0-аптада шамдармен де көрдік. 3 битпен 0-ден 7-ге дейін санай аламыз. 8 үшін төртінші бит керек. Төртінші бит болмаса, сан іс жүзінде 000, яғни 0 болады. Ал сандарды беру тәсіліне байланысты кейде бірінші 1 бит санның теріс екенін білдіреді. Сондықтан VS Code-та екі белгіні де көрдік: алдымен теріске «оралдық», сосын 0-ге түстік.

    long-қа көшсек (64 бит, пішім коды %li), «мәселені кейінге ысырамыз». Дэвид ұзақ сөйлеп тұрып Y-ді басып отырды да, ол да толып кетті! Экспоненциалды өсу өте жылдам.

    Нақты өмірдегі мысалдар

    • Boeing 787. Бірнеше жыл бұрын New York Times газеті былай деп жазды: үздіксіз 248 күн бойы қуат беріліп тұрған 787 моделі генераторды басқару блоктары бір мезетте апаттық режимге ауысқандықтан, айнымалы токтың барлығынан айырылуы мүмкін. Себебі блоктардағы ішкі бағдарламалық санауыш 248 күннен кейін толып кетеді. Авиацияда «уақыт — ақша», ұшақтарды түнде сөндірмейді. Компания түзетуді жасағанша уақытша шешім не болды? Ұшақты сөндіріп, қайта қосу. Телефон мен компьютер «ақылынан айырылғанда» дәл осылай істейміз. Қайта іске қосқанда айнымалылар бастапқы мәніне (мысалы, 0) оралады. Мәселенің түп-тамыры: олар 32 биттік таңбалы бүтін сан пайдаланған, демек оң сандар үшін 31 бит бар. Ал 248 күн шамамен секундтың оннан бір бөлігімен саналатын уақыт. Секундтың оннан бірімен 248 күн санағанда бүтін сан толып кетеді.
    • Pac-Man. Бұл ойынды 255-деңгейге дейін ойнауға болады. Бірақ қай деңгейде тұрғаныңызды тексеретін if шарты болмағандықтан, Pac-Man-да өте шебер болсаңыз, 256-деңгейде экран бұзылады. Олар да бүтін санды толтырып жіберген, экранда кездейсоқ таңбалар пайда болады. 256-деңгейге жету — мақтаныш белгісі.

    Бөлу және кесу

    int x = get_int("x: ");
int y = get_int("y: ");
printf("%i\n", x / y);

    1 ÷ 3 = 0? 2 ÷ 3 = 0, ал 0,66 болуы керек еді. 3 ÷ 3 = 1 дұрыс. 4 ÷ 3 = 1, ал 1,33 болуы керек.

    Термин: кесу Кесу (truncation): бүтін санды бүтін санға бөлгенде, нәтиже де бүтін сан болады. Ондық үтірден кейінгі нәрсенің бәрі лақтырылады, тіпті дөңгелектенбейді де.

    int-ті float-қа, ал %i-ді %f-ке ауыстырсақ, 1 ÷ 3 = 0.333333 шығады.

    Жылжымалы нүкте дәлсіздігі

    %f-ті %.50f деп өзгертейік. Бұл ондық үтірден кейін 50 цифр көрсету керегін білдіреді:

    x: 1
y: 3
0.33333334326744079589843750000000000000000000000000

    Мектепте 1/3 = 0,3333... шексіз деп оқыдық, бірақ мұнда соңында кездейсоқ цифрлар пайда болды. Себебі компьютерлер жылжымалы нүктелі сандар үшін де шектеулі бит пайдаланады. Мұндай сандар шексіз көп болса, олардың бәрін дәл беру мүмкін емес. Біз 1/3-тің ең жақын жуықтауын көріп отырмыз.

    Термин: жылжымалы нүкте дәлсіздігі Жылжымалы нүкте дәлсіздігі (floating-point imprecision): ондық бөлшегі бар сандарды шектеулі битпен беру мүмкін еместігі. Шешімі жоқ, тек float-тың орнына double пайдаланып, бит көбейтуге не мәселені анықтап, ескеруге болады. Ғылыми және қаржылық есептеулерде бұл өте маңызды.

    Y2K және 2038 жылғы мәселе

    Бұлар үнемі болып тұрады. Дэвид мектепті бітіріп жатқанда Y2K (2000 жыл) мәселесі болды. Ондаған жыл бойы компьютерлер жылды 4 цифрмен емес, 2 цифрмен сақтады. Бұл ыңғайлы әрі тиімді болды, себебі 1999 сияқты жылды сақтауға жад екі есе аз керек. Бірақ 1999-дан 2000 жылға өткенде, жадта сол цифрлар болмаса, 2000 жылды 1900 жылмен шатастыруға болады. Әлем асығыс түзеді. Сол кездегі Wikipedia мен жаңалықтарды оқысаңыз, бәрі ақырзаман болады деп ойлаған, бірақ болмады.

    Біз бұдан сабақ алдық деп ойлайсыз ғой? Өкінішке қарай, тағы бір мәселе 2038 жылы болады. 1970-жылдардан бері компьютерлер уақыт пен күнді 32 биттік бүтін санмен сақтап келеді: 1970 жылдың 1 қаңтарынан бері қанша секунд өткенін санайды. Барлық есептеу сол күнге қатысты, себебі компьютерлер шамамен сол кезде пайда бола бастады. Бірақ 1970 жылдың 1 қаңтарынан бастап тек 4 миллиардқа дейін (теріс сандарды қоса есептесе, 2 миллиардқа дейін) санауға болады. 2038 жылдың 19 қаңтарында 32 биттік санауыш толып кетеді. Сіз не басқалар бұны 2038 жылға дейін түзетпесе, компьютерлер мен телефондар бұл күнді 1901 жылдың 13 желтоқсаны деп ойлауы мүмкін.

    Бұл мәселелердің шешімі бар. CS50 сізге осындай мәселелерді шешуге мүмкіндік береді.

    Қорытынды

    • Бастапқы кодты адам жазады. Компилятор оны компьютер түсінетін машиналық кодқа айналдырады: make hello, сосын ./hello.
    • Әр нұсқау ;-мен аяқталады. printf үшін stdio.h, ал CS50 функциялары үшін cs50.h қосылады.
    • Айнымалының типі болады: int, long, float, double, char, bool, string. Әрқайсысының printf үшін өз пішім коды бар.
    • = меншіктеу, ал == теңдікті салыстыру. || НЕМЕСЕ, && ЖӘНЕ.
    • Циклдер: while, for, do-while. break циклдан шығарады.
    • Айнымалы тек өзі жарияланған фигуралы жақшалардың ішінде ғана бар (көріну аймағы).
    • Өз функцияңыздың прототипін main-нің үстіне жазыңыз.
    • Компьютердің шектеулері: бүтін санның толып кетуі, кесу, жылжымалы нүкте дәлсіздігі.

    Өзіңізді тексеріңіз

    1. hello.c файлын өзгерттіңіз. Өзгерісті көру үшін не істеу керек?

    Бастапқы код өзгерсе, жаңа машиналық код алу үшін қайта компиляциялау керек.

    2. if (x = y) мен if (x == y) айырмашылығы неде?

    = меншіктеу, == теңдікті салыстыру.

    3. printf("%i\n", 7 / 2); не шығарады?

    Бүтін санды бүтін санға бөлгенде кесу (truncation) болады: 3,5 → 3.

    4. 7 % 3 нәтижесі қандай?

    7 = 3 × 2 + 1, қалдығы 1.

    5. Кірісті кем дегенде бір рет сұрап, қате болса қайта сұрау үшін қай цикл ең ыңғайлы?

    do-while шартты соңында тексереді, сондықтан денесі кем дегенде бір рет орындалады.

    6. Функцияны main-нен кейін анықтасаңыз, не қосу керек?

    Компилятор кодты жоғарыдан төменге оқиды, сондықтан прототип оған функцияның кейін болатынын алдын ала айтады.

    7. 32 биттік int-ке тым үлкен мән сақтасақ не болады?

    Бұл integer overflow. Boeing 787 және Pac-Man мысалдарын еске түсіріңіз.

    Жаттығулар

    Шағын жаттығулар. Алдымен өзіңіз жазып көріңіз, сосын шешімін ашыңыз.

    Оңай

    Жұп па, тақ па?

    Қолданушыдан бүтін сан сұрап, оның жұп не тақ екенін шығаратын parity.c бағдарламасын жазыңыз.

    $ ./parity
n: 7
odd
    Кеңес

    % операторын пайдаланыңыз: n % 2 == 0 болса, сан жұп.

    Шешімі
    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    int n = get_int("n: ");
    if (n % 2 == 0)
    {
        printf("even\n");
    }
    else
    {
        printf("odd\n");
    }
}
    Оңай

    1-ден n-ге дейінгі қосынды

    Қолданушыдан оң бүтін n сұрап (теріс не 0 болса, қайта сұрасын), 1 + 2 + ... + n қосындысын шығарыңыз.

    Тексеру: n = 100 болғанда бағдарламаңыз не шығарды?

    Шешімі
    #include <cs50.h>
#include <stdio.h>

int main(void)
{
    int n;
    do
    {
        n = get_int("n: ");
    }
    while (n < 1);

    int sum = 0;
    for (int i = 1; i <= n; i++)
    {
        sum += i;
    }
    printf("%i\n", sum);
}
    Орташа

    Көбейту кестесі

    Кірістірілген циклдер арқылы 1-ден 5-ке дейінгі көбейту кестесін шығарыңыз. Сандарды \t (табуляция) арқылы бөліңіз.

    1	2	3	4	5
2	4	6	8	10
3	6	9	12	15
4	8	12	16	20
5	10	15	20	25
    Шешімі
    #include <stdio.h>

int main(void)
{
    const int n = 5;
    for (int row = 1; row <= n; row++)
    {
        for (int col = 1; col <= n; col++)
        {
            printf("%i\t", row * col);
        }
        printf("\n");
    }
}
    Орташа

    Өз функцияңыз: square

    int square(int n) функциясын жазыңыз, ол n² қайтарсын. main қолданушыдан сан сұрап, оның квадратын шығарсын. Функцияны main-нен кейін анықтаңыз (прототипті ұмытпаңыз!).

    Шешімі
    #include <cs50.h>
#include <stdio.h>

int square(int n);

int main(void)
{
    int x = get_int("x: ");
    printf("%i\n", square(x));
}

int square(int n)
{
    return n * n;
}

    Mario (оңай нұсқасы)

    mario-less/mario.c бағдарламасы қолданушыдан пирамиданың биіктігін сұрап, оң жаққа тураланған жартылай пирамида салсын. Биіктік оң бүтін сан болмаса, бағдарлама қайта сұрасын. Биіктігі 4 болса:

    $ ./mario
Height: 4
   #
  ##
 ###
####
    Кеңес
    • Кірісті тексеру үшін do-while қолданыңыз.
    • Әр қатарда алдымен бос орындар, сосын # шығады. i-ші қатарда (0-ден санағанда) қанша бос орын және қанша # бар? Биіктікпен байланысын табыңыз.

    Cash

    Сатушы қайтарымды ең аз тиынмен бергісі келеді. АҚШ тиындары: 25¢ (quarter), 10¢ (dime), 5¢ (nickel), 1¢ (penny). cash.c бағдарламасы қанша цент қайтару керегін сұрап (теріс болса, қайта сұрасын), ең аз тиын санын шығарсын.

    $ ./cash
Change owed: 41
4

    41 = 25 + 10 + 5 + 1, яғни 4 тиын. Бұл «ашкөз» (greedy) алгоритм: әр қадамда ең үлкен тиынды аламыз.

    Өзіңізді тексеріңіз: бағдарламаңыз 160 цент үшін қанша тиын шығарды?

    Кеңес
    • Әр тиын түрі үшін «неше рет сыяды?» деп сұрайсыз. Бүтін санды бөлу (кесу!) мен % бұл жерде өте пайдалы.
    • int calculate_quarters(int cents) сияқты көмекші функциялар жазыңыз.
    Тексеру
    • 0 → 0, 1 → 1, 15 → 2, 41 → 4, 70 → 4.
    • Теріс сан не мәтін енгізгенде қайта сұрайды.
    • check50 cs50/problems/2026/x/cash өтеді.

    Қиын

    Credit

    Несие картасының нөмірі дұрыс па, оны Лун алгоритмімен (Luhn's algorithm) тексеріңіз және картаның түрін анықтаңыз:

    • AMEX: 15 цифр, 34 не 37-ден басталады;
    • MASTERCARD: 16 цифр, 51, 52, 53, 54 не 55-тен басталады;
    • VISA: 13 не 16 цифр, 4-тен басталады;
    • әйтпесе INVALID.

    Лун алгоритмі:

    1. Соңғыдан бұрынғы цифрдан бастап, әр екінші цифрды 2-ге көбейтіп, нәтиженің цифрларын қосыңыз (мысалы, 7 × 2 = 14 → 1 + 4).
    2. Бұл қосындыға 2-ге көбейтілмеген цифрларды қосыңыз.
    3. Жалпы қосындының соңғы цифры 0 болса (яғни 10-ға бөлінсе), нөмір дұрыс.
    $ ./credit
Number: 4003600000000014
VISA

    Өзіңізді тексеріңіз: 4003600000000014 үшін Лун алгоритмінің жалпы қосындысы неге тең?

    Кеңес
    • Нөмір 16 цифрлы, сондықтан int жетпейді. get_long қолданыңыз.
    • Соңғы цифрды n % 10, ал соңғы цифрды алып тастауды n / 10 арқылы аласыз.
    • Цифрларды санап, ең бірінші екі цифрды есте сақтаңыз, сонда картаның түрін анықтайсыз.
    Тексеру
    • 378282246310005 → AMEX
    • 5555555555554444 → MASTERCARD
    • 4111111111111111 → VISA
    • 1234567890 → INVALID
