    SQL

    Деректермен жұмыс: CSV файлдары, реляциялық деректер базалары, SQL тілі (SELECT, INSERT, UPDATE, DELETE), кестелер арасындағы байланыстар, JOIN, индекстер, Python-нан SQL пайдалану, SQL инъекциясы және жарыс жағдайлары.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)

    Кіріспе

    Бұл CS50, 7-апта. Бүгін тағы бір тіл енгіземіз: құрылымдық сұраныстар тілі (Structured Query Language), қысқаша SQL («сиквел» деп те оқылады). SQL өткен апталардағы есептердің көбін шешуге мүмкіндік береді, бірақ көп жағдайда оңайырақ шешеді. Бүгінгі мақсаттардың бірі: бір есепті шешуге бірнеше құрал жарайтынын көрсету.

    SQL есеп шешуге басқаша қарайды. C, ішінара Python да — процедуралық тілдер: компьютерге не істеу керегін циклдер, шарттар арқылы қадам-қадаммен айтатын функциялар жазасыз. Ал SQL — декларативті (declarative) тіл: сіз қандай есепті шешкіңіз келетінін не қандай сұрағыңыз бар екенін жариялайсыз, ал циклдер мен шарттар арқылы жауапты қалай табу керегін тілдің өзі шешеді.

    Сонымен бүгін тағы бір тілді үйретеміз. Оның мақсаты — жаңа тілдерді өзіңізге өзіңіз үйретуге дағдылану. Курстан кейін процедуралық, объектіге бағытталған және бүгінгі декларативті сияқты әртүрлі парадигмаларды көргендіктен, жаңа тіл үйрену онша қиын болмайды. Бүгінгі тақырып — деректер.

    Деректерді жинау: Google Forms

    Сабақ басында студенттер телефондарымен QR кодты сканерлеп, Google Forms-тағы екі сұраққа жауап берді: «Қай тілді ұнатасыз?» (Scratch, C, Python) және «Қай тапсырма ұнады?». Google Forms жауаптарды жинап, әдемі дөңгелек диаграммалар көрсетеді. Python бірден 70%-дан астам дауыспен көш бастады, Scratch-та 11%, C-да 18%.

    Бірақ бізге диаграммалардан гөрі шикі деректер маңыздырақ. Google Forms-та «View in Sheets» батырмасы бар, ол жауаптарды Google Sheets кестесіне ашады. Кестеден деректерді Excel, мәтін, PDF түрінде жүктеуге болады. Біз оны CSV (comma-separated values) түрінде жүктейміз: File → Download → Comma Separated Values. Кестедегі деректерді кодқа жүктеудің ең қарапайым тәсілі осы. Файлды favorites.csv деп қысқартып атадық та, VS Code-қа сүйреп әкелдік. Бұл файлды сол сәттегі күйінде жүктеп салады.

    Timestamp,language,problem
10/27/2025 13:30:12,Python,Hello World
10/27/2025 13:30:15,Python,Mario
10/27/2025 13:30:16,C,Credit
...
    Термин: жалпақ файлды деректер базасы Бұл — жалпақ файлды деректер базасы (flat-file database): көп дерек сақтайтын жеңіл база, ол жай ғана мәтіндік файл. Дәстүр бойынша мәндер үтірмен бөлінеді. Басқа дәстүрлер де бар: TSV (tab-separated values, табуляциямен бөлінген), PSV (тік сызықпен бөлінген). Деректерде кездеспейтін таңбаны таңдап, жолдар мен бағандарды бөледі.

    Google Sheets бізге үш баған берді: автоматты түрде жасалған уақыт белгісі (timestamp), тіл және тапсырма. Кейбір студенттер бүгінгі деректерге асығып, тым ерте жауап берген, ал қалғандары шамамен 13:30-дан бастап. Бағандардың ені әртүрлі, себебі кейбір жауаптар ұзын, кейбірі қысқа. Бірақ үтірлер бір бағанның қай жерде аяқталып, келесісі қай жерде басталатынын көрсетуге жеткілікті.

    CSV-ді Python-мен оқу

    Ең танымал тіл мен тапсырма қайсы? Google Forms мұны пай-диаграммамен көрсетті. Бірақ ол мұны қалай есептейді? Олар да осындай код жазған шығар:

    import csv

with open("favorites.csv", "r") as file:
    reader = csv.reader(file)
    for row in reader:
        print(row[1])
    • csv — Python-мен бірге келетін кітапхана. Оны біреу жылдар бұрын жазған, үтірлердің қайда екенін табу кодын өзіміз жазбаймыз.
    • "r" — файлды тек оқу (read) режимінде ашамыз. Бұл әдепкі режим, бірақ анық жаздық. C-дағы fopen сияқты.
    • csv.reader(file) ашылған файлды алып, үтірлерді табады. Цикл әр жолда бізге бір тізім береді: row[0] бірінші баған, row[1] екінші, row[2] үшінші.

    Нәтижесінде барлық тілдер шығады, бірақ ең жоғарыда «language» сөзі тұр. Бұл қате: біз тек тілдерді көргіміз келді. Студент айтқандай, бұл тақырып жолы. Оны өткізіп жіберу үшін циклдан бұрын next(reader) шақырамыз. reader өзінің қай жерде тұрғанын есте сақтайды (stateful). C-дағы fread да солай болатын: ескі кассета не бейненің төменгі жолағы сияқты, келесі бөлікті оқиды, ал жадтағы бірдеңе оның орнын біледі.

    Бірақ бағандар реті өзгерсе ше? Біреу Excel не Google Sheets-те бағанды сүйреп, «timestamp, problem, language» не уақытты ең оң жаққа қоюы мүмкін. Сонда 0, 1, 2 индекстері бұзылады. Шешімі: csv.DictReader. Ол әр жолды тізім емес, сөздік ретінде береді, сондықтан сандардың орнына сөздерді индекс ретінде пайдаланамыз:

    import csv

with open("favorites.csv", "r") as file:
    reader = csv.DictReader(file)
    for row in reader:
        favorite = row["language"]
        print(favorite)

    DictReader бірінші жолды автоматты түрде «жейді», себебі баған аттарын сол жолдан алады. Сондықтан next керек емес.

    Дауыстарды санау

    Бірінші тәсіл: үш айнымалы.

    scratch, c, python = 0, 0, 0

for row in reader:
    favorite = row["language"]
    if favorite == "Scratch":
        scratch += 1
    elif favorite == "C":
        c += 1
    elif favorite == "Python":
        python += 1

print(f"Scratch: {scratch}")
print(f"C: {c}")
print(f"Python: {python}")

    (scratch, c, python = 0, 0, 0 — Python-да бірнеше айнымалыны бір жолда инициализациялаудың тәсілі. Соңғы else емес, elif, себебі келесі семестрде формаға төртінші тіл қосылса, Scratch не C емес нәрсенің бәрі Python деп есептемеу керек.) Алғашқы нұсқада f әрпін ұмытып кеттім. Нәтижесі: Python 109, C 58, Scratch 24.

    Бұл неге жақсы жобаланбаған? Студент айтқандай, тілдер көбейсе, 4-ші, 5-ші, 10-шы, 20-шы тіл үшін айнымалы көбейе береді. Мұнда сөздік керек: кілттері тілдер, мәндері сандар.

    counts = {}

for row in reader:
    favorite = row["language"]
    if favorite not in counts:
        counts[favorite] = 0
    counts[favorite] += 1

for favorite in counts:
    print(f"{favorite}: {counts[favorite]}")

    counts = {} не counts = dict() — бос сөздік. Бірінші нұсқада тек counts[favorite] += 1 жазып, KeyError алдым. Студент айтқандай, ең алғашқы айналымда сөздікте «Python», «C» не «Scratch» кілті әлі жоқ, ал += сол жерге барып, мәнді арттырмақ болады. Сондықтан кілт жоқ болса, алдымен 0 қоямыз. Мұны бірнеше тәсілмен шешуге болады: if/else арқылы 1 не +1, немесе ерекше жағдай арқылы:

    try:
    counts[favorite] += 1
except KeyError:
    counts[favorite] = 1

    Сұрыптау

    for favorite in sorted(counts):                                 # кілт бойынша (алфавит)
    ...
for favorite in sorted(counts, key=counts.get):                 # мән бойынша
    ...
for favorite in sorted(counts, key=counts.get, reverse=True):   # кемуі бойынша
    ...

    Сөздікті sorted функциясына берсеңіз, ол кілттер бойынша сұрыпталады. Мән бойынша сұрыптау үшін key атаулы параметріне сөздіктің get әдісін береміз, ал кері рет үшін reverse=True. Қысқасы, бұл қарапайым сұраққа жауап беру үшін көп код жазу тітіркендіреді. Google Sheets, Apple Numbers не Excel-де бағанды белгілесеңіз, жауап төменгі оң жақ бұрышта бірден көрінеді, не кестедегі функцияны пайдаланасыз. 20-ға жуық жол «қызба» сияқты. Жақсырақ жол бар сияқты, және ол шынымен бар.

    Реляциялық деректер базасы және SQL

    Жалпақ файлдың орнына реляциялық деректер базасына (relational database) көшейік. Бұл — деректер арасында байланыстар (relations) анықтауға болатын база. Қазір бұл онша маңызды емес (уақыт белгісі тілмен, тіл тапсырмамен байланысты), бірақ деректер үлкейіп, күрделенгенде, бірнеше дерек арасындағы байланыстарды көрсету өте құнды болады.

    SQL — осындай базамен жұмыс істейтін тіл. Ол жаңа тіл, бірақ оның тек 4 негізгі амалы бар. Бүгін басталған тілден бүгін-ақ шығамыз 🙂 Әрине, кез келген тілді меңгеру үшін уақыт пен жаттығу керек, бірақ SQL-да тек осы 4 амал бар:

    АмалCRUDSQL командасы
    Жасау (create)CCREATE, INSERT
    Оқу (read)RSELECT
    Жаңарту (update)UUPDATE
    Жою (delete)DDELETE, DROP

    Бұлардың аббревиатурасы CRUD. Реляциялық базада деректерді жасай, оқи, жаңарта және жоя аласыз. Бұл толық мүмкіндіктер жиыны.

    Термин: деректер базасы Деректер базасы (database) — компьютерде (Mac, PC, бұлт, не веб-серверлер кластері) жұмыс істейтін бағдарлама. Оның ішінде көп дерек сақталады, ал ол сол деректерге кез келген уақытта қол жеткізуге мүмкіндік береді.

    Техникалық тұрғыдан SQL-да «оқу» SELECT деп аталады. Ал қалған үшеуі деректерді жазу, яғни өзгерту туралы. Деректерді INSERT арқылы қосамыз, ал тек жеке жолдарды емес, тұтас кестелерді DROP арқылы өшіреміз.

    CREATE TABLE table (column type, ...);

    Кестені «қолмен» жасау үшін CREATE TABLE деп, кестенің (яғни электрондық кестедегі парақтың) атын жазып, барлық бағандарды көрсетесіз. Терминология өзгереді: электрондық кестеде парақтар (sheets) бар, оларда жолдар мен бағандар бар. Деректер базасында кестелер (tables) бар, оларда да жолдар мен бағандар бар. Атауы басқа, мәні бірдей.

    SQLite CS50-де SQL-дың нақты бір нұсқасын, SQLite-ты пайдаланамыз. Бұл — SQL-дың жеңіл нұсқасы. Ол веб және мобильді қосымшаларда өте кең қолданылады, бірақ Oracle, SQL Server, PostgreSQL, MySQL, Microsoft Access сияқты коммерциялық және ашық кодты өнімдердің барлық мүмкіндіктері не масштабы жоқ. Олар — SQL-дың үлкенірек әрі жылдамырақ нұсқалары. Команданың өзі sqlite3, ол код кеңістігіңізге алдын ала орнатылған.

    CSV-ді SQLite-қа жүктеу

    $ sqlite3 favorites.db
Are you sure you want to create favorites.db? [y/N] y
sqlite> .mode csv
sqlite> .import favorites.csv favorites
sqlite> .quit
$ ls
favorites.csv  favorites.db  favorites.py
    • sqlite3 favorites.db жаңа база жасайды (.db — database дәстүрі). Енді шақыру sqlite> болды. SQL кодын бөлек .sql файлдарында да жазуға болады (7-тапсырмада көресіз), бірақ қазір интерактивті түрде теріп, Enter басып отырамыз.
    • Нүктемен басталатын командалар SQLite-қа тән. Нүктесіз командалар көп SQL базаларында жұмыс істейді.
    • .mode csv — CSV деректерін жүктейтінімізді айтамыз.
    • .import favorites.csv favorites — файлды favorites атты кестеге жүктейміз.
    • Қате хабары жоқ, демек бәрі жақсы өтті.

    favorites.db-ны VS Code-та ашсақ, «This file is not displayed in the text editor because it is either binary...» деген хабар шығады. Бұл күтілген нәрсе: база 0 мен 1 түрінде, екілік форматта сақталады. Оны sqlite3 бағдарламасы оқи алады. Деректерді екілік түрде сақтау таза мәтіннен тиімдірек, себебі апталар бойы талқылаған деректер құрылымдары мен алгоритмдерді қолдануға оңайырақ.

    sqlite> .schema
CREATE TABLE IF NOT EXISTS "favorites"(
"Timestamp" TEXT, "language" TEXT, "problem" TEXT);

    Схема (schema) — деректер базасының құрылымы: қандай кестелер, жолдар, бағандар бар. .import бізге 3 бағаны бар кесте жасады, бәрі TEXT (шикі мәтін) типінде. Кейін типтерді өзіміз басқарамыз. Бірақ .import CSV-ді SQLite базасына айналдырудың ең оңай тәсілі.

    SELECT: деректерді оқу

    Деректерді алу үшін SELECT қолданылады. Ол декларативті: тек қандай деректерді таңдағымыз келетінін жариялаймыз. Файлды ашу, for не while циклі, айнымалылар туралы ойламаймыз.

    SELECT * FROM favorites;

    Өкінішке қарай, SQL кодында нүктелі үтір қайта оралды. Нәтиже — кестенің ASCII-сурет түріндегі нұсқасы, ол тіпті шикі CSV-дан да жақсы көрінеді. * (жұлдызша) — барлық бағандарды білдіретін «қалқымалы таңба» (wildcard). Деректер хронологиялық ретпен шықты, базаға қалай жүктелсе, солай.

    SELECT language FROM favorites;
SELECT language, problem FROM favorites;

    Тек керек бағандарды таңдауға болады. Python-дағы 12-ге жуық жолдың орнына дерекқордан не керек екенін ғана айтамыз.

    Функциялар

    Excel, Numbers, Google Sheets сияқты, SQLite-та да кірістірілген функциялар көп:

    ФункцияНе істейді
    AVGорташа мән
    COUNTжолдар санау
    DISTINCTқайталанбайтын мәндер
    LOWER, UPPERкіші не бас әріпке айналдыру
    MAX, MINең үлкен, ең кіші мән
    SELECT COUNT(*) FROM favorites;
-- 272

SELECT DISTINCT(language) FROM favorites;
-- C, Python, Scratch

SELECT COUNT(DISTINCT(language)) FROM favorites;
-- 3

    Файлды жүктеген сәтте 272 жауап болды. DISTINCT арқылы ешкім қате дерек енгізбегеніне көз жеткіземіз: тек 3 тіл бар. Мұны көзбен көру оңай, бірақ әр сұраққа солдан оңға оқылатын, ағылшын тіліне ұқсас бір ғана нұсқау жеткілікті.

    WHERE, LIKE, GROUP BY, ORDER BY, LIMIT

    SQL нұсқауларына қосуға болатын кілт сөздер:

    Кілт сөзНе істейді
    WHEREшарт (Python-дағы if-ке ұқсас, бірақ қысқа)
    LIKEжолды шамамен (үлгі бойынша) салыстыру
    GROUP BYбірдей мәндерді топтау
    ORDER BYсұрыптау
    LIMITжолдар санын шектеу
    SELECT COUNT(*) FROM favorites WHERE language = 'C';
-- 58

SELECT COUNT(*) FROM favorites WHERE language = 'C' AND problem = 'Hello, World';
-- 5

    58 адам C-ны таңдады, оның 5-еуінің сүйікті тапсырмасы «Hello, World» 🙂 SQL-да бір теңдік белгісі = теңдікті тексереді (C мен Python-дағы == емес).

    «Hello, It's Me» тапсырмасы ше? Апостроф бізді шатастырады: ортасындағы апостроф бірінші тырнақшаға жата ма, екіншісіне ме? C-да кері қиғаш сызықпен «қашар» едік. SQLite-та басқаша: екі жалқы тырнақша жазасыз. Мұны есте сақтау не іздеп табу керек.

    SELECT COUNT(*) FROM favorites WHERE language = 'C' AND problem = 'Hello, It''s Me';
-- 0

SELECT COUNT(*) FROM favorites
WHERE language = 'C' AND (problem = 'Hello, World' OR problem = 'Hello, It''s Me');

SELECT COUNT(*) FROM favorites WHERE language = 'C' AND problem LIKE 'Hello, %';

    C-ны таңдап, «Hello, It's Me»-ні ұнатқандар жоқ болып шықты. LIKE арқылы үлгі іздеуге болады: SQL жолында % «нөл не одан көп кез келген таңба» дегенді білдіреді. Сонда «Hello, » деп басталатын екі тапсырманың бірі де табылады.

    — Регистр маңызды ма? = үшін иә, ал LIKE регистрге тәуелсіз.

    Стиль: неге бас әріп? CS50 және көп компания мен қауымдастықтың стилі бойынша SQL кілт сөздерін бас әріппен жазамыз. Сонда сіз таңдаған кесте мен баған аттарынан (кіші әріппен) олар ерекшеленіп тұрады. Бұл тек келісім, әрқашан бірізді болыңыз. 
    SELECT language, COUNT(*) FROM favorites GROUP BY language;
    +----------+----------+
| language | COUNT(*) |
+----------+----------+
| C        | 58       |
| Python   | 190      |
| Scratch  | 24       |
+----------+----------+

    Python-дағы 20 жолдық кодтың орнына бір жол! GROUP BY бірдей тілдерді бір топқа жинап, әр топтың санын береді. Бастығыңыз CSV беріп, оны талдауды сұраса, оны SQLite-қа жүктеп, бір команда орындап, нәтиже бере аласыз.

    SELECT language, COUNT(*) AS n FROM favorites GROUP BY language ORDER BY n DESC;

SELECT language, COUNT(*) AS n FROM favorites GROUP BY language ORDER BY n DESC LIMIT 1;
    • ORDER BY n DESC — кемуі бойынша (descending) сұрыптау. ASC — өсуі бойынша.
    • AS n — бүркеншік ат (alias), бағанның уақытша атауы. COUNT(*)-ты екі рет жазбаймыз.
    • LIMIT 1 — тек бірінші жол: Python, 190.

    Әр SELECT іс жүзінде уақытша кесте қайтарады. Ол еш жерде сақталмайды. Жауап алған соң, компьютер жадынан жоғалады. .import бүкіл деректерді жадқа жүктеді, ал біз оның сұрағымызға жауап беретін бөлігін ғана аламыз.

    INSERT, NULL, DELETE, UPDATE, DROP

    INSERT INTO table (column, ...) VALUES(value, ...);

    Форманы таратқанда 7-тапсырма әлі берілмеген еді. Бірақ онда Fiftyville атты тапсырма бар, ол бір аптадан кейін біреудің сүйіктісі болуы мүмкін. Оны алдын ала қосайық:

    INSERT INTO favorites (language, problem) VALUES ('SQL', 'Fiftyville');
SELECT * FROM favorites;

    Уақыт белгісінің пішімін ойламау үшін оны көрсетпедім. Кестенің соңында жаңа жол пайда болды, бірақ уақыт белгісі бос емес, онда NULL тұр. Бұл көрсеткіштегі NULL емес, тек аты бірдей. Ол деректің саналы түрде жоқ екенін білдіреді.

    Бұл пайдалы. Google Sheets не Excel-де бос ұяшық нені білдіреді? Онда шынымен ештеңе жоқ па, әлде дерек белгісіз бе? «N/A» деп жазып, «қолмен» шешуге болар еді. Бірақ сонда ешкім «NA» деп жауап бере алмайды. Ал SQL-да NULL бос жол '' емес, ол деректің саналы түрде жоқ екенін білдіреді.

    DELETE FROM table WHERE condition;

DELETE FROM favorites WHERE Timestamp IS NULL;

    — Неге NULL тырнақшада емес? NULL ерекше белгі. Тырнақшаға алсаңыз, CSV-де сөзбе-сөз «NULL» деп жазылған мәтінді (мысалы, тілдің не тапсырманың аты) іздейсіз. Бізге деректің мүлдем болмауы керек. Ол IS NULL арқылы тексеріледі.

    DELETE өте қауіпті! DELETE FROM favorites; деп, WHERE-ді жазуды ұмытып, Enter-ді ерте басып қалсаңыз, бүкіл кестедегі деректер жойылады. Google-да компанияның дерекқорына тым көп рұқсаты бар тағылымдамашылардың (интерндердің) дәл осылай істегені туралы мақалалар бар. Резервтік көшірмелер не нұсқалар болмаса, деректер біржола жоғалады. Әрқашан WHERE жазып, оның дұрыс екеніне көз жеткізіңіз! 
    UPDATE table SET column = value WHERE condition;

UPDATE favorites SET language = 'SQL', problem = 'Fiftyville';

    Fiftyville бір күнде бәрінің сүйікті тапсырмасына айналды делік. Бұл жолы шартсыз UPDATE орындадық. SELECT * FROM favorites;: бәрі «SQL, Fiftyville» болды, ал алдыңғы нұсқаға қайтудың жолы жоқ (тек CSV-ді қайта импорттау арқылы).

    DELETE FROM favorites;
DROP TABLE favorites;

    DELETE барлық жолды жойды, ал DROP TABLE кестенің өзін жойды: .schema енді ештеңе көрсетпейді. Бұл одан да нашар. Не істеп отырғаныңызды білмесеңіз, бұл командаларды іске қоспаңыз.

    — Деректерді ұдайы резервтік көшіріп отыра ма? Иә, әрине. CS50-дің барлық веб-қосымшалары белгілі бір кестемен резервтік көшіріледі. Бірақ күнделікті болса, 23 сағат 59 минуттық деректі жоғалтуыңыз мүмкін. Компаниялар деректерді әр 5 минут, әр минут сайын нұсқалауы мүмкін, бірақ бұл көп орын алады. Тағы да таңдау. Сонымен қатар қол жеткізуді басқару (access control) бар. SQLite-та қолданушы аты не құпиясөз жоқ, деректерге қол жеткізсеңіз, бәрін өзгерте аласыз. Ал Oracle, SQL Server, PostgreSQL, MySQL-да тағылымдамашыға тек SELECT жасауға, бірақ UPDATE, DELETE не INSERT жасамауға рұқсат беруге болады.

    Нақты деректер: IMDb

    Нақты өмірдегі деректермен ойнайық. IMDb (Internet Movie Database) — фильмдер, телешоулар, актерлер туралы деректер қоры. Оның сайтынан деректерді TSV (tab-separated values) түрінде жүктеуге болады. Біз оларды телешоуларға қатысты бірнеше SQL кестесіне айналдырдық.

    Деректерді модельдеу

    Алдымен телешоу деректерін өзім кестеде қалай сақтар едім? АҚШ-тағы «The Office» сериалында Стив Карелл және басқалар ойнады. Бірінші нұсқа:

    titlestarstarstarstarstar
    The OfficeSteve CarellRainn WilsonJohn KrasinskiJenna FischerB.J. Novak

    Жаман жері? Студенттер айтқандай: «star, star, star» қайталанады, ал актер саны әр шоуда әртүрлі. Аз актерлі шоуларда бос ұяшықтар көп, ал көп актерлі шоуларға бағандар жетпейді. Кесте өте «сирек» болады.

    titlestar
    The OfficeSteve Carell
    The OfficeRainn Wilson
    The OfficeJohn Krasinski

    Екінші нұсқа: бір «тесікті» жапсақ, басқа жерден ағып кетеді. Енді «The Office» қайталанады. Қолмен терсек, бірінде қате жазылып, бірдеңе бұзылады. Үшінші нұсқа ақыры әрі «академиялық» тұрғыдан дұрыс, оны үш парақпен (sheet) жасадым:

    showspeoplestars
    idtitleidnameshow_idperson_id
    386676The Office136797Steve Carell386676136797
    ……386676…

    Гарвард студентінің не қызметкердің бірегей нөмірі сияқты, «The Office»-қа да IMDb-дағыдай бірегей идентификатор бердім. Адамдардың да бірегей ID-лері бар. Ал үшінші парақ шоулар мен адамдарды байланыстырады. Бір қарағанда бұл ең түсініксіз нұсқа, тек сандар. Бірақ біз деректерді қалыпқа келтірдік (normalized): тек бүтін сандар ғана қайталанады. Бүтін сандардың өлшемі тұрақты (32 не 64 бит), олар массивте сақтауға не екілік іздеуге ыңғайлы, себебі бір-бірінен бірдей қашықтықта тұрады. Ал «Steve Carell» не «John Krasinski» сияқты аттардың ұзындығы әртүрлі. Кестенің өзі адамға онша түсінікті емес, бірақ осы жерде SQL көмекке келеді. Бүгінгі веб және мобильді қосымшалар көп деректі CSV-де емес, SQLite, MySQL, PostgreSQL, Oracle сияқты SQL базаларында сақтайды. IMDb-ның өзі де солай істейтін шығар.

    shows.db

    Біз shows.db базасын дайындадық, онда жүздеген мың жол бар. Оның 6 кестесі бар: people, shows, stars, writers, ratings, genres. Олардың арасында байланыстар бар, реляциялық базаның «реляциясы» осы.

    people (id, name, birth)        shows (id, title, year, episodes)
        ▲                              ▲    ▲    ▲
        │                              │    │    │
stars (show_id, person_id) ───────────┘    │    │
writers (show_id, person_id)               │    │
ratings (show_id, rating, votes) ──────────┘    │
genres (show_id, genre) ────────────────────────┘
    .schema shows
SELECT * FROM shows LIMIT 10;
SELECT COUNT(*) FROM shows;    -- 250 087
SELECT COUNT(*) FROM people;   -- 704 315

    SELECT * FROM shows; орындасақ, деректер экранда шексіз ағып өтеді, кейбір атаулар өте ұзын. Ctrl+C арқылы тоқтатамыз. LIMIT 10 арқылы алғашқы 10-ын көреміз, олар 1970-жылдардан басталады. Жаңа деректер жиынын түсінудің ең жақсы тәсілі — деректерді жай ғана SELECT арқылы қарау.

    SQLite типтері және шектеулер

    ТипМағынасы
    INTEGERбүтін сан
    NUMERICуақыт, күн және басқа сандық мәндер үшін жалпы тип
    REALондық бөлшегі бар сан (float сияқты)
    TEXTмәтін
    BLOBbinary large object: шикі 0 мен 1 (мысалы, файлдар). Файлдарды базада сақтау әдетте құпталмайды, бірақ кейде керек

    SQLite-та тек осы 5 тип бар. Oracle, MySQL, PostgreSQL-да типтер одан да көп.

    • NOT NULL: бағанда NULL болмауы керек. Мысалы, уақыт белгісі бос болмасын десеңіз, кестені жасағанда осыны жазасыз. Сонда NULL мәні бар жол енгізу сәтсіз болады. Python не электрондық кестеден айырмашылығы осы: деректеріңізді өзіңізден және басқалардан қорғайтын кірістірілген қорғаныстар бар.
    • UNIQUE: бағандағы барлық мән бірегей болуы керек. Мысалы, екі адамға бірдей ID берілмейді.
    Термин: бастапқы кілт және сыртқы кілт Бастапқы кілт (primary key) — кестедегі әр жолды бірегей түрде анықтайтын баған: шоу ID, адам ID, Гарвард ID, қызметкер ID. Ол көбіне бүтін сан. Сыртқы кілт (foreign key) — басқа кестеде кездесетін сол ID. Ол «бөтен» кестеде тұрғандықтан, сыртқы деп аталады. Екеуі де бір нәрсені білдіреді. 
    CREATE TABLE shows (
    id INTEGER,
    title TEXT NOT NULL,
    year NUMERIC,
    episodes INTEGER,
    PRIMARY KEY(id)
);

CREATE TABLE ratings (
    show_id INTEGER NOT NULL UNIQUE,
    rating REAL NOT NULL,
    votes INTEGER NOT NULL,
    FOREIGN KEY(show_id) REFERENCES shows(id)
);

    ratings кестесінде show_id UNIQUE: бір шоудың тек бір рейтингі болады. Бұл бір-біріне (one-to-one) байланыс. Рейтингті shows кестесінің өзіне қосуға да болар еді. Бірақ IMDb рейтингтерді жеке TSV файлында береді, сондықтан біз де солай сақтадық.

    Ішкі сұраулар

    Енді рейтингі жақсы шоуларды тапқымыз келеді. Алдымен рейтингі 6.0 және одан жоғары шоулардың ID-ін табайық:

    SELECT show_id FROM ratings WHERE rating >= 6.0 LIMIT 10;

    Бірақ бізге сандар емес, атаулар керек. Атаулар shows кестесінде. Бір сұраудың нәтижесін екінші сұрауға беруге болады. Бұл ішкі сұрау (nested query, subquery):

    SELECT title FROM shows
WHERE id IN (
    SELECT show_id FROM ratings WHERE rating >= 6.0
)
LIMIT 10;

    Жақша ішіндегі сұрау бірінші орындалады (математикадағы сияқты). Ол ID тізімін береді, ал IN «осы тізімде бар ма» деп тексереді. Сұрауды бірнеше жолға бөліп, шегініспен жазу оқуды жеңілдетеді.

    JOIN: кестелерді біріктіру

    Бірақ енді атауларды көрдік, ал рейтингтерді көрмейміз. Екі кестені бірге көргіміз келеді. Бір кестеде id мен title, екіншісінде show_id мен rating бар. Екі кестедегі ID-лер бірдей болатын жолдарды «тігіп», бір кең кесте жасауға болады. Бұл JOIN:

    SELECT * FROM shows
JOIN ratings ON shows.id = ratings.show_id
WHERE rating >= 6.0
LIMIT 10;

    ON кестелерді қандай бағандар арқылы біріктіретінін айтады. shows.id — shows кестесіндегі id бағаны (C-дағы құрылымның өрісі сияқты нүкте белгісі). Нәтижеде id, title, year, episodes, сосын show_id, rating, votes бағандары қатар тұрады. Тек керек бағандарды таңдауға болады:

    SELECT title, rating FROM shows
JOIN ratings ON shows.id = ratings.show_id
WHERE rating >= 6.0
LIMIT 10;

    Бір-көпке: жанрлар

    Бір шоудың бірнеше жанры болуы мүмкін (комедия, драма, ...). Бұл бір-көпке (one-to-many) байланыс. genres кестесі:

    CREATE TABLE genres (
    show_id INTEGER NOT NULL,
    genre TEXT NOT NULL,
    FOREIGN KEY(show_id) REFERENCES shows(id)
);

    Мұнда show_id UNIQUE емес: бір шоу бірнеше жолда кездеседі. Мысалы, 1970-жылдардағы Catweazle шоуы (ID 63881):

    SELECT genre FROM genres WHERE show_id = 63881;
-- Adventure
-- Comedy
-- Family

    Екі кестені біріктірсек, шоу ақпараты әр жанр үшін қайталанады:

    SELECT * FROM shows
JOIN genres ON shows.id = genres.show_id
WHERE id = 63881;

    Нәтижеде Catweazle үш рет көрінеді. Бұл деректердің базада қайталанғанын білдірмейді. Бұл тек уақытша нәтиже, көз алдымызға келтіру үшін жасалған. Базада атау тек бір рет сақталған.

    Көп-көпке: актерлер

    Бір шоуда көп актер ойнайды, бір актер көп шоуда ойнайды. Бұл көп-көпке (many-to-many) байланыс. Оны үшінші, «байланыстырушы» stars кестесі арқылы көрсетеміз:

    CREATE TABLE people (
    id INTEGER,
    name TEXT NOT NULL,
    birth NUMERIC,
    PRIMARY KEY(id)
);

CREATE TABLE stars (
    show_id INTEGER NOT NULL,
    person_id INTEGER NOT NULL,
    FOREIGN KEY(show_id) REFERENCES shows(id),
    FOREIGN KEY(person_id) REFERENCES people(id)
);

    stars кестесінде тек екі сан бар. Ол «осы адам осы шоуда ойнады» дегенді білдіреді. Мысалы, The Office шоуында кім ойнады? Алдымен шоуды табамыз:

    SELECT id FROM shows WHERE title = 'The Office';

    Бірнеше The Office бар екен (түрлі елдердің нұсқалары). Бізге американдық нұсқа керек, ол 2005 жылы шыққан:

    SELECT id FROM shows WHERE title = 'The Office' AND year = 2005;
-- 386676

    Енді ID-ді қолмен жазбай, сұрауларды бір-біріне салайық:

    SELECT name FROM people WHERE id IN (
    SELECT person_id FROM stars WHERE show_id = (
        SELECT id FROM shows WHERE title = 'The Office' AND year = 2005
    )
);

    Ең ішкі сұрау шоу ID-ін береді, ортаңғысы сол шоудағы адамдардың ID-лерін, ал сыртқысы олардың аттарын. Нәтижеде Steve Carell, Rainn Wilson, John Krasinski, Jenna Fischer және басқалар шығады.

    Керісінше: Steve Carell қай шоуларда ойнады?

    SELECT title FROM shows WHERE id IN (
    SELECT show_id FROM stars WHERE person_id = (
        SELECT id FROM people WHERE name = 'Steve Carell'
    )
);

    Steve Carell есімді адам бір ғана болса, бұл дұрыс жұмыс істейді. (Оның ID-і 136797.) Сол сұрауды JOIN арқылы да жазуға болады:

    SELECT title FROM shows
JOIN stars ON shows.id = stars.show_id
JOIN people ON stars.person_id = people.id
WHERE name = 'Steve Carell';

    Немесе жасырын (implicit) біріктіру арқылы: кестелерді үтірмен тізіп, байланыс шарттарын WHERE-ге жазамыз:

    SELECT title FROM shows, stars, people
WHERE shows.id = stars.show_id
AND people.id = stars.person_id
AND name = 'Steve Carell';

    Үш тәсіл де бірдей нәтиже береді. Қайсысы өзіңізге түсінікті болса, соны қолданыңыз.

    Кеңес Атауды толық білмесеңіз, LIKE қолданыңыз: WHERE name LIKE 'Steve C%'. Бірақ ол бірнеше адамды табуы мүмкін, сондықтан = орнына IN жазыңыз.

    Индекстер

    Деректер көп болғанда сұраулар баяулайды. Уақытты өлшеп көрейік:

    sqlite> .timer on
sqlite> SELECT * FROM shows WHERE title = 'The Office';
...
Run Time: real 0.042

    0.042 секунд көп емес сияқты. Бірақ бұл бір ғана сұрау. Миллиондаған қолданушысы бар сайт секундына мыңдаған сұрау жібереді. SQLite атауды табу үшін барлық 250 мың жолды басынан аяғына дейін қарайды, яғни сызықтық іздеу жасайды.

    Шешімі — индекс (index):

    CREATE INDEX title_index ON shows (title);
    sqlite> SELECT * FROM shows WHERE title = 'The Office';
...
Run Time: real 0.001

    Енді 0.001 секунд! Индекс құру біраз уақыт алады, бірақ бір-ақ рет жасалады. Сосын әр іздеу әлдеқайда жылдам.

    Термин: B-ағаш Индекс ішінде B-ағаш (B-tree) деп аталатын деректер құрылымы қолданылады. Ол 5-аптадағы екілік іздеу ағашына ұқсайды, бірақ әр түйіннің екіден көп баласы болуы мүмкін. Сондықтан ағаш өте аласа әрі кең болады, ал іздеу логарифмдік уақыт алады.

    Индекстер тегін емес. Олар қосымша жад алады, ал INSERT және UPDATE әрекеттерін баяулатады, себебі ағашты да жаңарту керек. Сондықтан индексті барлық бағанға емес, жиі іздейтін бағандарға ғана жасаймыз. Мысалы, JOIN-де жиі қолданылатын сыртқы кілттерге:

    CREATE INDEX person_index ON stars (person_id);
CREATE INDEX show_index ON stars (show_id);
CREATE INDEX name_index ON people (name);

    Осы индекстерден кейін Steve Carell туралы күрделі сұрау бірнеше есе жылдам орындалады. Бастапқы кілттерге SQLite индексті автоматты түрде жасайды.

    Python және SQL

    SQL-ды Python-нан да шақыруға болады. Бұл жерде CS50 кітапханасының SQL функциясын қолданамыз (кейін веб-бағдарламалауда да керек болады):

    from cs50 import SQL

db = SQL("sqlite:///favorites.db")

favorite = input("Favorite: ")

rows = db.execute("SELECT COUNT(*) AS n FROM favorites WHERE problem = ?", favorite)

row = rows[0]

print(row["n"])
    • SQL("sqlite:///favorites.db") — базаға қосылу. Үш қиғаш сызық — URL синтаксисі.
    • db.execute(...) SQL-ды орындап, сөздіктер тізімін қайтарады. Әр сөздік — бір жол, кілттері — баған аттары.
    • ? — орын толтырғыш (placeholder). C-дағы printf-тің %s-і сияқты: оның орнына келесі аргумент қойылады.
    • COUNT(*) AS n бағанға қысқа ат береді. Сондықтан row["n"] деп жаза аламыз.
    $ python favorites.py
Favorite: Hello, World
...

    Python-да CSV-ді оқып, сөздікпен санағанда ондаған жол код жаздық. SQL-да бір ғана жол жеткілікті. Әр құралдың өз орны бар: SQL деректерді алу мен сұрыптауға жақсы, ал Python қалған логикаға.

    SQL инъекциясы

    Неге ? қолдандық? Неге f-жолмен сұрауды өзіміз құрастырмадық? Себебі қолданушы енгізгенді ешқашан тікелей сұрауға қоспау керек. Мысалы, GitHub сияқты сайтқа кіру формасы бар деп елестетейік. Сервер мынадай сұрау жасауы мүмкін:

    # ҚАУІПТІ! Мұны ешқашан жасамаңыз
rows = db.execute(f"SELECT * FROM users WHERE username = '{username}' AND password = '{password}'")

if rows:
    ...  # қолданушы кірді

    Зиянкес пайдаланушы аты ретінде malan@harvard.edu'-- деп жазса не болады? SQL-да -- — түсініктеме. Сұрау мынаған айналады:

    SELECT * FROM users WHERE username = 'malan@harvard.edu'--' AND password = '...'

    Тырнақша жолды жабады, ал -- құпия сөзді тексеретін бөлікті түсініктемеге айналдырады. Нәтижеде зиянкес құпия сөзсіз басқа біреудің аккаунтына кіреді! Бұл SQL инъекциясы (SQL injection attack). Дәл осылай деректерді өшіруге не ұрлауға да болады.

    Дұрыс тәсіл — орын толтырғыштар:

    rows = db.execute("SELECT * FROM users WHERE username = ? AND password = ?", username, password)

    Кітапхана (немесе база) енгізілген мәндегі қауіпті таңбаларды экрандайды (escape). Мысалы, жалғыз тырнақшаны екі тырнақшаға айналдырады (''), сонда ол мәтіннің бөлігі болып қалады. Мұны өзіңіз қолмен жасамаңыз: кітапханалар мұны көп жылдар бойы сыналған тәсілмен жасайды.

    Әзіл Лекцияда XKCD-тің атақты «Bobby Tables» комиксі көрсетілді. Онда ана баласына оқушылар базасын өшіретін SQL командасы бар ат қояды. Сондай-ақ көлік нөміріне SQL командасын жазып, жылдамдық камераларын «алдамақ» болған адамның суреті көрсетілді. Екеуі де инъекцияның шын қауіп екенін еске салады.

    Жарыс жағдайлары

    Тағы бір мәселе: бір уақытта көп адам базамен жұмыс істегенде не болады? Мұны түсіну үшін тоңазытқыш туралы оқиға бар. Сіз үйге келіп, тоңазытқышта сүт жоқ екенін көресіз. Дүкенге сүт алуға кетесіз. Сол кезде бөлмелесіңіз де келіп, сүт жоқ екенін көріп, ол да дүкенге кетеді. Нәтижесінде үйде сүт екі есе көп болады. Мәселе: сіз тоңазытқыштың күйін тексердіңіз, бірақ оны өзгертпей тұрып кетіп қалдыңыз. Шешімдердің бірі — тоңазытқышқа «сүтке кеттім» деп жазып қою немесе оны құлыптау.

    Базада да солай. Instagram-да атақты біреудің жазбасына бір уақытта мыңдаған адам «ұнату» басады дейік. Әр серверде мынадай код орындалуы мүмкін:

    rows = db.execute("SELECT likes FROM posts WHERE id = ?", id)
likes = rows[0]["likes"]
db.execute("UPDATE posts SET likes = ? WHERE id = ?", likes + 1, id)

    Екі сервер бір уақытта likes-ті оқыса (мысалы, екеуі де 100 алса), екеуі де 101 жазады. Бір «ұнату» жоғалып кетеді! Бұл жарыс жағдайы (race condition).

    Шешімі — транзакциялар (transactions). Олар бірнеше әрекетті бөлінбейтін (atomic) етеді: не бәрі бірге орындалады, не ештеңе орындалмайды.

    db.execute("BEGIN TRANSACTION")
rows = db.execute("SELECT likes FROM posts WHERE id = ?", id)
likes = rows[0]["likes"]
db.execute("UPDATE posts SET likes = ? WHERE id = ?", likes + 1, id)
db.execute("COMMIT")
    • BEGIN TRANSACTION — транзакцияны бастау.
    • COMMIT — өзгерістерді сақтау.
    • ROLLBACK — бір нәрсе дұрыс болмаса, барлық өзгерісті болдырмау.

    Бағасы — жылдамдық: бір транзакция жүріп жатқанда басқалар күтуі мүмкін. Бірақ деректер дұрыс болады. Банктер, бағалар, тапсырыстар сияқты маңызды деректер үшін бұл міндетті.

    Қорытынды

    • Жалпақ файлды база (CSV) қарапайым, бірақ үлкен деректерге ыңғайсыз. Python-мен csv.reader, csv.DictReader, сөздіктер және sorted арқылы талдай аламыз.
    • Реляциялық база — кестелер, жолдар, бағандар және олардың арасындағы байланыстар. SQL декларативті тіл: не керек екенін айтамыз, қалай екенін емес.
    • CRUD: CREATE/INSERT, SELECT, UPDATE, DELETE/DROP.
    • WHERE, LIKE, GROUP BY, ORDER BY, LIMIT, AS; функциялар: COUNT, AVG, MAX, MIN, SUM, DISTINCT, LOWER, UPPER.
    • SQLite типтері: INTEGER, NUMERIC, REAL, TEXT, BLOB. Шектеулер: NOT NULL, UNIQUE.
    • Бастапқы кілт жолды анықтайды, сыртқы кілт басқа кестеге сілтейді. Байланыстар: бір-біріне, бір-көпке, көп-көпке.
    • Ішкі сұраулар (IN), JOIN ... ON ... және жасырын біріктіру.
    • Индекстер (B-ағаштар) іздеуді жылдамдатады, бірақ жад алады және жазуды баяулатады.
    • Python-да db.execute және ? орын толтырғыштары. Олар SQL инъекциясынан қорғайды.
    • Жарыс жағдайлары транзакциялармен шешіледі: BEGIN TRANSACTION, COMMIT, ROLLBACK.

    Өзіңізді тексеріңіз

    1. SQL қандай тіл?

    SQL-да нәтижені сипаттаймыз, ал оны қалай табуды база өзі шешеді.

    2. Әр тілді неше адам таңдағанын санау үшін қандай сөз керек?

    SELECT language, COUNT(*) FROM favorites GROUP BY language;

    3. DELETE FROM favorites; (WHERE-сіз) не істейді?

    Сондықтан DELETE және UPDATE-те WHERE-ді ұмытпаңыз. Кестені өзін DROP TABLE өшіреді.

    4. Шоулар мен актерлер арасындағы байланыс қандай?

    Бір шоуда көп актер, бір актер көп шоуда. Сондықтан stars кестесі керек.

    5. Индекстің кемшілігі қандай?

    Әр INSERT/UPDATE кезінде B-ағашты да жаңарту керек.

    6. SQL инъекциясынан қалай қорғанамыз?

    Кітапхана мәндерді өзі дұрыс экрандайды.

    7. Екі сервер бір уақытта «ұнату» санын оқып, екеуі де +1 жазса, не болады?

    Транзакция (BEGIN TRANSACTION ... COMMIT) мұның алдын алады.

    Жаттығулар

    Төмендегілер лекциядағы shows.db-ға арналған. Оны лекция бетінен жүктеп, sqlite3 shows.db арқылы ашыңыз. Нақты сандар базаның нұсқасына қарай өзгеруі мүмкін, сондықтан мұнда тек шешімдерді тексеріңіз.

    2005 жылғы шоулар

    Орташа

    Ең жақсы 10 комедия

    Жанры Comedy болатын, кемінде 10 000 дауысы бар шоулардың ішінен рейтингі ең жоғары 10 шоудың атауы мен рейтингін шығарыңыз.

    Кеңес

    Үш кесте керек: shows, ratings, genres. Екі JOIN, сосын ORDER BY rating DESC LIMIT 10.

    Шешімі
    SELECT title, rating FROM shows
JOIN ratings ON shows.id = ratings.show_id
JOIN genres ON shows.id = genres.show_id
WHERE genre = 'Comedy' AND votes >= 10000
ORDER BY rating DESC
LIMIT 10;
    Орташа

    Қауіпті кодты табыңыз

    Төмендегі жолдардың қайсысы SQL инъекциясына осал? Жауап ретінде әріпті жазыңыз (a, b немесе c).

    # a
db.execute("SELECT * FROM shows WHERE title = ?", title)
# b
db.execute(f"SELECT * FROM shows WHERE title = '{title}'")
# c
db.execute("SELECT * FROM shows WHERE year = ?", int(year))
    Түсіндірме

    b қолданушы енгізгенді тікелей сұрауға қояды. title ішінде ' болса, ол сұраудың құрылымын өзгертеді.

    Қиын

    Python-дан іздеу

    Қолданушыдан актер атын сұрап, ол ойнаған шоулардың атауларын әліпби бойынша шығаратын search.py бағдарламасын жазыңыз. Орын толтырғышты қолданыңыз.

    Шешімі
    from cs50 import SQL

db = SQL("sqlite:///shows.db")

name = input("Name: ")

rows = db.execute("""
    SELECT title FROM shows
    JOIN stars ON shows.id = stars.show_id
    JOIN people ON stars.person_id = people.id
    WHERE name = ?
    ORDER BY title
""", name)

for row in rows:
    print(row["title"])

    Fiftyville

    CS50 үйрегі Fiftyville қаласында ұрланды! Сіз детективсіз. Ұрлық 2024 жылдың 28 шілдесінде Humphrey Street-те болғаны белгілі. fiftyville.db базасында қаланың деректері бар: қылмыс есептері, сұхбаттар, тұрақ журналдары, банкомат операциялары, телефон қоңыраулары, ұшақ рейстері, жолаушылар, адамдар.

    Мақсатыңыз:

    • Ұры кім?
    • Ол қай қалаға қашты?
    • Оған кім көмектесті (сыбайлас)?

    Барлық орындаған сұрауларыңызды түсініктемелерімен log.sql файлына жазыңыз, ал жауаптарды answers.txt-ке.

    Алдымен жаттығып алыңыз!Fiftyville-ге ұқсас, бірақ өзіміздің қазақша детектив ойыны: «Алтын домбыраның құпиясы» 🕵️. Нағыз SQLite браузерде, кеңестерімен.
    Кеңес
    • Алдымен .tables және .schema арқылы базаны зерттеңіз.
    • crime_scene_reports кестесінен бастаңыз: сол күн мен көшеге сәйкес есептерді табыңыз.
    • Есепте куәлар туралы айтылса, interviews кестесіндегі сол күнгі сұхбаттарды оқыңыз.
    • Әр куәның айтқанын тексеріңіз: тұрақ камерасы, банкомат, телефон, рейс. Әр жолы күдіктілер тізімі тарылады.
    • Күдіктілер тізімін бірнеше IN (...) шартымен қиыстыруға болады.
    • Детектив тәрізді ойланыңыз: асықпаңыз және әр қадамды log.sql-ге жазыңыз.
    Тексеру
    • Қылмыс есебі мен сұхбаттар табылды.
    • Тұрақ, банкомат, телефон деректері бойынша күдіктілер тарылды.
    • Ұры, қала және сыбайлас анықталды.
    • log.sql түсініктемелермен толтырылды.
