    Деректер құрылымдары

    Кезектер, стектер, сөздіктер; массивті кеңейту; байланысқан тізімдер; екілік іздеу ағаштары; хэш-кестелер және trie. Әр құрылымның уақыт пен жад арасындағы таңдауы.

    Кіріспе

    Бұл CS50, 5-апта. Бүгін деректер құрылымдарына (data structures) тоқталамыз. Олармен бұрын қарапайым түрде таныстық, ал бүгін тереңірек қарастырамыз. Бұл C тілімен соңғы аптамыз. Келесі аптада Python-ға көшеміз. Ол «жоғары деңгейлі» тіл, өміріміз әлдеқайда жеңілдейді. Сол есептерді адам ретінде әлдеқайда жылдам шеше аламыз, бірақ көретініміздей, компьютерде олар C-дағыдай жылдам жұмыс істемеуі мүмкін. Бұл аптада да, келесі аптада да басты тақырып: таңдаулар (trade-offs).

    Джек пен Лу туралы әңгіме

    Сабақ Илон университетінің профессоры Шеннон Дюваллдың шағын анимациясымен басталды. Онда Джек есімді жігіт дос таба алмай, ең танымал танысы Луға кеңес сұрайды. Лу Джекке «әрқашан бір киім киесің» дейді. Джек киімдерін жуып, бір қорапқа үстінен салады екен, ал таңертең киімді де қораптың үстінен алады. Сондықтан ылғи соңғы жуылған киімді кие береді. Ол кітаптарын да, дискілерін де осылай стек етіп сақтайды. Лу қорапты лақтырып, киімдерді шкафқа іледі: «кешке киімді сол жаққа іл, таңертең оң жақтан, кезектің соңынан ал. Сонда бір киімді екінші рет кимес бұрын, бәрін бір-бір рет киесің». Яғни кезекті үйретеді.

    Бұл нақты өмірде бәріміз кездестіретін екі нәрсенің суреті. Техникалық тұрғыдан бұлар абстрактілі деректер типтері (abstract data types). Олар деректер құрылымдары, бірақ маңыздысы — олардың жобасы: олар қандай қасиеттерді, мүмкіндіктерді береді. Олардың қалай іске асырылатыны, яғни төменгі деңгейдегі егжей-тегжейлері маңызды емес. Кезек пен стекті көптеген тәсілмен іске асыруға болады. Ал таңдалған тәсіл оларды қалай пайдалана алатыныңызға және қандай есептерді шеше алатыныңызға нақты әсер етеді.

    Кезектер

    Кезекті (queue) үнемі көресіз: дүкенге, концертке кіру үшін не тауарды төлеу үшін кезекке тұрасыз. Кезекте әділдік болғанын қалаймыз: бірінші келген бірінші кіреді, соңғы келген соңғы кіреді. Информатиктер мұны FIFO (first in, first out) қасиеті дейді: бірінші кірген бірінші шығады. Әділдік маңызды көп есепке бұл жақсы шешім.

    Техникалық тұрғыдан кезектің екі операциясы бар:

    • enqueue (кезекке қосу): кезектің соңына тұру;
    • dequeue (кезектен шығару): кезектің басынан шығу.

    Бұл екі операцияны кодта әртүрлі тәсілмен іске асыруға болады. Мысалы, C-да адамдар кезегі:

    const int CAPACITY = 50;

typedef struct
{
    person people[CAPACITY];
    int size;
}
queue;

    Бұл кезекке 50-ден көп адам сыймайды, бұл оның сыйымдылығы (capacity). Құрылымда 50 өлшемді person массиві және кезектің ағымдағы өлшемі (size) бар. Сыйымдылық — барлығы неше адам сыя алады, ал өлшем — қазір нешеуі тұр. Сонда массивтің қай орындары бос екенін білеміз.

    Мұның шектеуі қандай? Студент айтқандай, тек 50 адам сыяды. 51-ші адам кезекке тұрғысы келсе, оны есте сақтау мүмкін емес. 50-ді 51-ге, 500-ге, 5000-ға өзгертіп, кодты қайта компиляциялауға болады. Бірақ бұл да таңдау: үлкен концертке келген адамдар саны бәрібір көп болуы мүмкін. Ал 5000 орын бөліп, бірнеше адам ғана келсе, жадты босқа жұмсаймыз. Компьютер жады шектеулі. Сондықтан компиляциялаудан бұрын құрылымның өлшемін шешу, қанша жадты босқа жұмсайтыныңызды шешу ақымақтық. Кезекті қажетінше үлкейтіп-кішірейтіп, өткен аптадағыдай операциялық жүйеден жад сұрап, керек болмаса қайтарған дұрыс. Сондықтан бұлай статикалық массив (компиляция кезінде өлшемі қатаң бекітілген) қолайсыз. Оның үстіне, кезекте адамдар басынан шыққан сайын кезектің басы қай жерде екенін есте сақтау керек, бірақ мұны кодта шешуге болады.

    Стектер

    Мүлдем басқа қасиеті бар құрылым — стек (stack). Анимациядағы Джек киімдерін қорапқа салды. Ол үнемі үстіндегі киімді алғандықтан, қара свитерді ылғи кие береді, ал астындағы көк не қызыл свитерге дейін жетпес бұрын тағы жуып қоюы мүмкін.

    Стектің LIFO (last in, first out) қасиеті бар: соңғы кірген бірінші шығады. Кір жуып, тағы бірнеше свитер үстіне қойсам, соңғы салғанымды бірінші киемін. Ең астындағыны тартып шығарып, бәрін шашып жіберу қиынырақ болар еді. Сондықтан LIFO кейбір есептерге әділ болмаса да, ыңғайлы әрі тиімді.

    Стектер барлық жерде:

    • Gmail не Outlook: пошта жәшігінде жаңа хаттар үнемі жоғарыда пайда болады. Бәріміз келесі бетке түсіп кеткен хаттарды елемей, соңғы келгеніне (last in) бірінші жауап беретініміз (first out) рас. Бұл хат жіберушілерге онша жақсы емес, бірақ баптауларды өзгертпесеңіз, бұл интерфейстер осылай жұмыс істейді.
    • Асханадағы подностар: Гарвардтағы асханаларда подностар бірінің үстіне бірі қойылады. Бәріңіз ең үстіңгісін аласыз, себебі ең астындағыны алу қиын. Сондықтан ең төменгі подносқа ешкім жетпеуі мүмкін.

    Стектің екі операциясы:

    • push (итеру): стектің үстіне бірдеңе қосу;
    • pop (шығару): стектің үстінен бірдеңе алу.
    const int CAPACITY = 50;

typedef struct
{
    person people[CAPACITY];
    int size;
}
stack;

    Қызығы, кодты queue-дан stack-қа ауыстырсақ болды. Стекті осылай іске асыру оңайырақ: әрқашан массивтің соңынан алып, соңына қоса аламыз, ал бірінші кірген элемент әрдайым 0-орында қала береді. Бірақ дәл сол шектеу бар: стекке тек 50 свитер, 50 поднос сыяды.

    Бұл тек бір іске асыру тәсілі. Бұл шектеу стек пен кезектің өзінің шектеуі емес. Олар абстрактілі, яғни оларды жақсырақ іске асыруға болады: жадты өзіміз басқарып, массивтің өлшемін алдын ала бекітпей, құрылымды өсіріп-кішірейте аламыз.

    Сөздіктер

    Курстың басында көрген, бірақ бұлай атамаған тағы бір абстрактілі тип — сөздік (dictionary). Ол бүкіл әлемде бар: сөздер мен анықтамалар жазылған нағыз сөздіктер сияқты. Тақтаға салсақ, ол екі бағанды кесте: сол жақта сөз, оң жақта анықтама. Кітапта да сол: жуан қаріппен жазылған сөздер, жанында анықтамалары.

    0-аптада бастаған телефон кітабы да сөздік: сөз бен анықтаманың орнына аттар мен нөмірлер. Информатик мұны жалпылап, сол жақтағысын кілт (key), ал оң жақтағысын мән (value) деп атайды.

    Бұл есептеуіш техникада барлық жерде кездеседі. Бір деректі екіншісімен байланыстыру керек болса, яғни кілт-мән жұбы керек болса, сөздік — бірінші таңдау. Бірақ мұны да әртүрлі тәсілмен іске асыруға болады: массив болса, өлшемі шектеулі болуы мүмкін. Бір тәсілмен іске асырылған сөздік жылдам, екіншісі баяу болуы мүмкін. iPhone не Android-тағы Contacts бағдарламасы массивпен жасалып, тек 50 досқа рұқсат етсе, бұл тітіркендіретін шектеу болар еді. Шамасы, Apple мен Google оны динамикалық түрде іске асырған.

    Массивті кеңейту

    2-аптадағы алғашқы деректер құрылымына оралайық. Массив — мәндер қатар (contiguous) сақталатын жад бөлігі. Оның өлшемін әдетте алдын ала шешеміз:

    #include <stdio.h>

int main(void)
{
    int list[3];

    list[0] = 1;
    list[1] = 2;
    list[2] = 3;

    for (int i = 0; i < 3; i++)
    {
        printf("%i\n", list[i]);
    }
}

    Нәтиже 1, 2, 3. Енді «4-ші сан қосу керек» делік, мысалы, 4-ші свитер сатып алдым, кезекке 4-ші адам тұрды не телефоныма 4-ші досымды қостым. Ең қисынды жер — 3-тен кейінгі орын. Сонда бәрі қатар тұрып, код та өзгермейді, тек сәл көбірек жад қолданамыз.

    Бірақ массивті белгілі өлшеммен жариялағанда, тек сол жад бөлігі ғана уәде етіледі. Оң жағында, сол жағында не жоғарыда бос жад бар деген кепілдік жоқ. Күрделірек бағдарламада 1, 2, 3 мына жерге түсіп, «hello, world» жолы дәл жанында тұруы мүмкін. 4-ті «H»-тың орнына салсақ, басқа жерде қолданылып жатқан жолды «4ello, world»-қа айналдырып, өзімізге тиесілі емес байтты алып қоямыз.

    Жадта басқа бос орын көп сияқты. Оскар сияқты «қоқыс мәндермен» белгіленген байттар бұрын пайдаланылған, бірақ қазір қолданылмайды. Сондықтан 1, 2, 3, 4-ті сол жаққа қоюға болады. Ол үшін алғашқы үшеуін көшіріп, төртіншісін қосып, ескі жадты операциялық жүйеге қайтару керек. Бұл массивті пайдаланғанда толық дұрыс шешім.

    #include <stdio.h>
#include <stdlib.h>

int main(void)
{
    // 3 бүтін санға жад бөлу
    int *list = malloc(3 * sizeof(int));
    if (list == NULL)
    {
        return 1;
    }

    list[0] = 1;
    list[1] = 2;
    list[2] = 3;

    // Біраз уақыттан кейін: 4 бүтін санға жад керек
    int *tmp = malloc(4 * sizeof(int));
    if (tmp == NULL)
    {
        free(list);
        return 1;
    }

    // Ескі тізімді жаңасына көшіру
    for (int i = 0; i < 3; i++)
    {
        tmp[i] = list[i];
    }

    // 4-ші санды қосу
    tmp[3] = 4;

    // Ескі жадты босату
    free(list);

    // Жаңа тізімді есте сақтау
    list = tmp;

    for (int i = 0; i < 4; i++)
    {
        printf("%i\n", list[i]);
    }

    free(list);
    return 0;
}
    • Массивті статикалық емес, динамикалық түрде бөлеміз: malloc арқылы. int әдетте 4 байт, бірақ сенімді болу үшін sizeof(int). malloc бірінші байттың мекенжайын қайтарады, сондықтан оны int *list-ке сақтаймыз.
    • Өткен аптада көргендей, көрсеткішті массив сияқты пайдалануға болады: list[0] = 1 — *list = 1-дің «синтаксистік қанты». list[1] — *(list + 1). Бұларды ешкім жаза бергісі келмейді.
    • Неге list = malloc(4 * sizeof(int)) деп бірден жазбаймыз? Студент айтқандай, бұл алғашқы 3 санды жоғалтады. list «көбік саусақ» сияқты мына жерді көрсетіп тұрса, оны басқа жерге бұрсақ, ескі жадтың қайда екенін ұмытамыз. Бұл — жадтың ағуы. Сондықтан уақытша айнымалы (tmp) керек.
    • Екінші malloc сәтсіз болса, бірден 1 қайтаруға болмайды. Алдымен бірінші жадты free арқылы босату керек. Әрине, бағдарлама аяқталғанда жад бәрібір қайтарылады, бірақ кодыңызда қате болып қалады. Ал біз жиі минуттар, сағаттар, күндер бойы үздіксіз жұмыс істейтін бағдарламалар жазамыз.
    • malloc үшін stdlib.h қостық (бірінші рет ұмытып кеттім).

    realloc

    Бұл көп қиындық. stdlib.h-та realloc (re-allocate) функциясы бар. Ол ақылдырақ жұмыс істейді: мүмкін болса, бар жадты ұлғайтады (сонда 4-ті соңына қоя саламыз), ал оның жанында «hello, world» сияқты бірдеңе тұрса, деректерді өзі жаңа жерге көшіреді.

    int *tmp = realloc(list, 4 * sizeof(int));
if (tmp == NULL)
{
    free(list);
    return 1;
}
list = tmp;
list[3] = 4;
    • — realloc қай жадты қайта бөлу керегін қайдан біледі? Мен бастапқыда бұл қатені жібердім! Құжаттама бойынша realloc-тың бірінші аргументі бұрын malloc-пен алынған жадтың мекенжайы. Сонда ол сол жерге барып, соңынан бос орын бар-жоғын тексереді.
    • — Неге әлі де tmp керек? list = realloc(...) деп жазсақ және бірдеңе бұзылса, realloc NULL қайтарады, бірақ бастапқы жадқа қол тигізбейді. Сонда біз ол жадтың қайда екенін ұмытамыз: оны шығара да, өзгерте де, босата да алмаймыз.
    • — Ол қанша деректі көшіру керегін қайдан біледі? Операциялық жүйе, нақтырақ айтқанда stdlib, сізге бұрын қанша жад бөлінгенін есте сақтайды. Оның «сөздік» сияқты іздеу кестесі бар.

    Синтаксис: struct, нүкте, жұлдызша және көрсеткі

    Енді информатиктердің бәрі білуі тиіс деректер құрылымдарын құралдар жинағыңызға қосамыз. Оларды үнемі өзіңіз іске асырмайсыз. Бірақ Python, Java, C++ не басқа тілдің бір мүмкіндігін пайдаланғанда, басқа біреу жазған осы құрылымдардың біреуін таңдайсыз. Сонда FIFO не LIFO сияқты қасиеттерді егжей-тегжейге көп кірмей-ақ пайдаланасыз.

    Бізде қазір мына құралдар бар:

    • struct: өз деректер құрылымыңызды жасау;
    • .: құрылымның ішіндегі өріске (мысалы, адамның аты не нөмірі) жүгіну;
    • *: көрсеткішті дереференс жасау, яғни мекенжайға бару (мысалы, құрылымның ішіне).

    Бүгін тағы бір оператор қосамыз. Ол . пен *-ты бір операторға біріктіреді және сөзбе-сөз көрсеткіге ұқсайды: ->. Ол өткен апталарда сары-қара суреттерде салған жебелерге сәйкес келеді.

    Байланысқан тізімдер

    Массивтің артықшылығы: ол өте жылдам. Барлық деректер бір жерде тұрғандықтан, 0-аптадан бергідей екілік іздеуді қолданып, ортасына, ортасының ортасына оңай секіре аламыз. Кемшілігі: өлшемі статикалық, мысалы 3 не 4, бірақ әйтеуір шектеулі. Қате болжасаңыз, қайта бөліп, көшіру керек. 3 емес, 3 миллион мән болса, оларды ескі жерден жаңа жерге көшіруге өте көп уақыт кетеді.

    Осы қиындықтың алдын алайық. Мәндер жадтың қай жерінде тұрғанына қарамастан, оларды бір-бірімен байланыстырайық. Компьютерде мұнда бірнеше байт, анда бірнеше байт бос болса, бірақ олардың ешқайсысы массивке жеткіліксіз болса да, жалпы жеткілікті болса, бүкіл қолжетімді жадты пайдаланғымыз келеді.

      0x123        0x456        0x789
┌───────┐    ┌───────┐    ┌───────┐
│   1   │    │   2   │    │   3   │
├───────┤    ├───────┤    ├───────┤
│ 0x456 │──▶ │ 0x789 │──▶ │ NULL  │
└───────┘    └───────┘    └───────┘

    1 саны 0x123-те, 2 саны 0x456-да, 3 саны 0x789-да тұр делік. Олар қатар тұрмағандықтан, бір санды арттыру арқылы біріне-бірінен өте алмаймыз. Сондықтан әр мәнге бір байттың орнына екі бөлік береміз: жоғарғысында бізге қажет мән, ал төменгісінде келесі мәннің мекенжайы. Соңғы мәннің жанына 0x0, яғни NULL қоямыз, бұл тізімнің соңы. Мәндер жадтың кез келген жерінде болуы мүмкін, бірақ әрқайсысымен бірге келесісінің мекенжайын сақтап, «қазына картасын» не «нан үгінділерін» жасаймыз.

    Термин: деректер және метадеректер, түйін Деректер (data) — бізге қажет мәндер. Метадеректер (metadata) — деректерді басқаруға көмектесетін деректер, мысалы келесі мәннің мекенжайы. Деректер мен метадеректерден тұратын құрылым түйін (node) деп аталады. Бұл суреттер масштабта салынбаған: бүтін сан әдетте 4 байт, ал көрсеткіш 8 байт.

    Ал 0x123, 0x456 мекенжайлары бізге маңызды емес. Оларды жебелермен саламыз. Бірақ тізімді бақылау үшін тағы бір нәрсе керек: list атты айнымалы. Ол бірінші түйіннің мекенжайын сақтайтын көрсеткіш. Бірінші түйін бізді екіншісіне, екіншісі үшіншісіне апарады.

    Төртінші мән керек болса, оны жадтың кез келген жеріне қойып, жебені соған бұрсақ болды. Ешқандай көшіру жоқ. 1, 2, 3 бағдарлама аяқталғанша сол орнында қала береді. Бұл байланысқан тізім (linked list). Python-дағы list осындай тізім. Басқа тілдерде олар вектор деп аталады. Негізінде бұлар өздігінен үлкейіп-кішірейетін массивтер.

    Түйінді кодта жазу

    Бұрынғы person құрылымынан бастайық: name және number, екеуі де char *. Ішін өшіріп, атын node деп ауыстырамыз. Ішіне мәнге арналған int number және келесі түйінге көрсеткіш саламыз:

    typedef struct node
{
    int number;
    struct node *next;
}
node;
    • next — келесі түйіннің мекенжайы, сондықтан жұлдызша бар.
    • Неге node *next емес, struct node *next? Техникалық бір мәселе бар. C кодты жоғарыдан төменге, солдан оңға оқиды. Құрылымның ішінде node сөзін қолдансақ, компилятор оны тек ең соңында ғана көреді. Функциялар үшін прототипті жоғарыға қойып, бұл мәселені шештік. Мұнда да соған ұқсас: бірінші жолда құрылымға уақытша ат береміз: struct node. Сонда ішінде struct node * деп жаза аламыз, себебі компилятор ол сөзді көріп қойды.

    Тізімді құру

    #include <cs50.h>
#include <stdio.h>
#include <stdlib.h>

typedef struct node
{
    int number;
    struct node *next;
}
node;

int main(void)
{
    // Бос тізім
    node *list = NULL;

    for (int i = 0; i < 3; i++)
    {
        // Жаңа түйінге жад бөлу
        node *n = malloc(sizeof(node));
        if (n == NULL)
        {
            return 1;
        }
        n->number = get_int("Number: ");
        n->next = NULL;

        // Түйінді тізімнің басына қосу
        n->next = list;
        list = n;
    }
}

    (cs50.h-ты char * үшін емес, get_int үшін қостық. scanf-сыз C-да сан алу әлі де қиын.)

    • node *list = NULL;: бос тізімді қалай береміз? Байланысқан тізімнің типі не? Ол бірінші түйіннің мекенжайы. Әзірге түйін жоқ, сондықтан NULL.
    • Циклда 3 рет: жаңа түйінге жад бөлеміз (бүтін тіктөртбұрыш үшін, яғни sizeof(node), шамасы 4 + 8 = 12 байт, бірақ оны sizeof-қа есептетеміз), оның мекенжайын уақытша n айнымалысына сақтаймыз. Сондықтан оның типі node *.
    • NULL тексеру. Бұл malloc қолданған сайын жазатын шаблон код.
    • (*n).number = ...: n-нің мекенжайына барып, ішіндегі number өрісіне жүгін. Жақша қажет, себебі операциялар реті маңызды.
    • Бұл синтаксис түсініксіз болса, C-да әлдеқайда қарапайым жазу бар: n->number. «n-ге бар, жебе бойымен number өрісіне өт». -> операторы * мен .-ның бірігуі, оны үнемі жақшамен жазу ыңғайсыз.

    Суретпен түсіну

    Кодты қадам-қадаммен суретке айналдырайық:

    1. node *list;: тек жарияланса, бұл қоқыс мәні бар бір шаршы, Оскар. Сондықтан оған NULL береміз, қоқыс мән болмайды.
    2. node *n = malloc(sizeof(node));: тұтас тіктөртбұрышқа жад бөлінеді, ал n оны көрсетеді. Түйін өрістерінде әзірге қоқыс мәндер бар.
    3. n->number = 1; (адам 1 енгізді делік) және n->next = NULL;.
    4. list = n;: n-де мекенжай бар, сондықтан list те сол түйінді көрсетеді. Енді n маңызды емес, ол уақытша еді.
    list
┌───┐     ┌───┬──────┐
│ ●─┼───▶ │ 1 │ NULL │
└───┘     └───┴──────┘

    Циклдың екінші айналымында жаңа түйін бөлінеді, оған 2 саламыз. Енді list = n деп жазсақ не болады?

    list ──┐     ┌───┬──────┐
       │     │ 1 │ NULL │   ← оны ешкім көрсетпейді!
       │     └───┴──────┘
       └───▶ ┌───┬──────┐
     n ────▶ │ 2 │ NULL │
             └───┴──────┘

    Студент айтқандай, бірінші түйінге апаратын жебе жоғалды. Біз оны «жетім» (orphaned) қалдырдық: адам көзімен оны көріп тұрсақ та, кодта ол қайда екенін білмейміз. Бұл жадтың ағуы: бағдарлама аяқталғанша оны қайтара алмаймыз. Сондықтан ретін ауыстыру керек:

    n->next = list;   // 1) жаңа түйін ескі тізімнің басын көрсетсін
list = n;         // 2) тізім енді жаңа түйіннен басталсын
    list ──▶ ┌───┬───┐     ┌───┬──────┐
         │ 2 │ ●─┼───▶ │ 1 │ NULL │
         └───┴───┘     └───┴──────┘

    Рождество кезінде попкорнды жіпке тізгенді елестетіңіз. Біз түйіндерді бірінен соң бірін байланыстырамыз, бірақ жіптің бір бөлігін ешқашан жіберіп алмауымыз керек. Үшінші айналымнан кейін тізім: 3 → 2 → 1. Тізім жадта ұзын әрі «шұбатылған», мәндер кез келген жерде болуы мүмкін, бірақ көрсеткіштер арқылы біреуінен екіншісіне өтеміз. Тек олар кері ретпен шықты, оған кейін ораламыз.

    Тізімді аралау

    // Тізімді шығару
node *ptr = list;
while (ptr != NULL)
{
    printf("%i\n", ptr->number);
    ptr = ptr->next;
}

    Тағы бір уақытша ptr (pointer) айнымалысын жасаймыз. Ол тағы бір «көбік саусақ» сияқты, тізімнің басын көрсетеді. Ол NULL болмағанша: санды шығарамыз, сосын ptr-ды ptr->next-ке, яғни жебе бойымен келесі түйінге жылжытамыз. Үшінші түйіннен кейін ptr NULL болып, цикл тоқтайды.

    Сол логиканы for циклімен де жазуға болады:

    for (node *ptr = list; ptr != NULL; ptr = ptr->next)
{
    printf("%i\n", ptr->number);
}

    Бұл ықшамырақ, бірақ біріншісі қадам-қадаммен түсініктірек. Курс сайтында екеуі де бар.

    — Жадты жоғалтпаймыз дейміз, бірақ мұнда әр санға екі есе көп жад жұмсап отырмыз ғой? Иә, бұл барлық деректер құрылымына тән тақырып. Динамикалық өсіп-кішірею сияқты артықшылық алу үшін бірдеңе беру керек: мұнда көбірек кеңістік. Үзілістен кейін алгоритмдерді жылдамдатамыз, бірақ ол үшін тағы көбірек кеңістік жұмсаймыз. Уақыт, кеңістік, ақша, адам уақыты — барлығы ресурс. Бағдарламашы не менеджер ретінде қайсысы маңызды екенін шешесіз. Қазір бізге кеңістіктен гөрі динамикалықтық маңыздырақ.

    — Неге n-ді қайта қолданбадыңыз? Қолдануға болар еді. Бірақ мұнда оның мақсаты басқа, сондай-ақ ол көріну аймағынан шығып қойды. Әр айнымалы әртүрлі нәрсе істесе, түсініктірек.

    — Көрсеткіштер уақытша ма? Міндетті емес. Байланысқан тізімнің өзі көрсеткіштер арқылы құрылады және бағдарлама жұмыс істеп тұрғанша сақталады. Ал n пен ptr — тек түйіндерді байланыстыруға арналған уақытша айнымалылар.

    Байланысқан тізімнің жұмыс уақыты

    • Басына қосу (prepend), жоғарыдағыдай: O(1). Тізімде 1000 элемент болса да, біз тек сол жақтағы бірнеше көрсеткішті өзгертеміз. Тұрақты қадам саны, тізімнің ұзындығына тәуелсіз.
    • Бірақ элементтер ретсіз, тіпті кері ретпен тұр. Сондықтан іздеу: O(n). Ең нашар жағдайда іздегеніміз ең соңында болуы мүмкін.
    • Барлығын аралау/шығару: O(n), бұл түсінікті.
    • Жою: O(n), себебі жойылатын элемент ең соңында болуы мүмкін.

    Соңына қосу (append) ше? Онда 1, 2, 3 «кездейсоқ» ретімен шығады. Бірақ қосу O(n) болады, себебі әр жолы соңына дейін жүру керек. (Тізімнің соңын көрсететін тағы бір көрсеткіш ұстауға болады, бұл заңды шешім.)

    Сұрыпталған тізім

    Мақсат: сандар қандай ретпен енгізілсе де (1 2 3, 3 2 1, 2 1 4 3...), олар әрқашан сұрыпталған болсын. Телефондағы контактілер сияқты. Енді жаңа түйінді жай ғана басына қоя алмаймыз, оны қай жерге салу керегін мұқият ойлау керек.

    Мысалы, 2, 1, 4, 3 енгізілді: 2 бос тізімге түседі. 1 оның алдына. 4 соңына. 3 2 мен 4-тің арасына. Қағаз бен қаламмен бұл оңай, бірақ кодта түйіндерді «жетім» қалдырып алу мүмкіндігі өте көп. Сондықтан есепті төрт жағдайға бөлейік:

    1. Тізім бос: жаңа түйін тізімнің жалғыз элементі болады.
    2. Жаңа сан басына тиесілі: оны басына қосамыз (prepend), бұл оңай.
    3. Жаңа сан соңына тиесілі: соңына қосамыз (append).
    4. Жаңа сан ортасына тиесілі: ең қиын жағдай.

    Енді бір үлкен, анықталмаған есептің орнына 4 нақты есеп бар, яғни кодта 4 блок. «Нәресте қадамдарымен» жүруге болады.

    // Тізім бос болса
if (list == NULL)
{
    list = n;
}

// Сан тізімнің басына тиесілі болса
else if (n->number < list->number)
{
    n->next = list;
    list = n;
}

// Сан кейінірек тиесілі болса
else
{
    for (node *ptr = list; ptr != NULL; ptr = ptr->next)
    {
        // Соңына жеттік
        if (ptr->next == NULL)
        {
            ptr->next = n;
            break;
        }

        // Ортасына салу
        if (n->number < ptr->next->number)
        {
            n->next = ptr->next;
            ptr->next = n;
            break;
        }
    }
}

    Жаңа түйіннің next-ін алдын ала NULL-ға теңестірдік. Бұл міндетті емес (кейін бәрібір өзгертеміз), бірақ ол соңына түсуі мүмкін, сондықтан көрсеткіштерді мәні белгілі болғанша NULL ұстау жақсы әдет. Ортасына салу логикасын (ptr->next->number, екі жебе қатар) бүгін толық талдамаймыз, ол 5-есептер жинағында асықпай, қадам-қадаммен қарауға тұрарлық. Көрсеткіштерді байланыстыру реті өте маңызды.

    Тізімді босату

    // Тізімді босату
node *ptr = list;
while (ptr != NULL)
{
    node *next = ptr->next;
    free(ptr);
    ptr = next;
}

    Бұл жай ғана free(list) емес. free мен malloc онша ақылды емес: malloc-ты 3 рет шақырсаңыз, free-ді де 3 рет шақыруыңыз керек. Оған тізімнің басын беріп, «қалғанын өзің тап» деп айта алмайсыз, ол байланысқан тізімнің не екенін білмейді. Мұндағы айла: 1-ді босатар алдында 2-ні көрсететін уақытша көрсеткіш ұстау. 1-ді босатып, 3-ке көрсеткіш ұстап, 2-ні босатамыз...

    Тағы бір жасырын қате malloc циклдың 2-не 3-айналымында сәтсіз болса, бірден return 1 жасау дұрыс емес. Алдыңғы айналымдарда бөлінген түйіндерді де босату керек. Төмендегі кодты көшіріп қоюдың орнына, оны unload функциясына шығарып, екі жерден де шақырған дұрыс. Курс сайтындағы соңғы нұсқада солай жасалған.

    Қорытынды бағалау

    Сұрыпталған тізімде: қосу O(n), іздеу O(n), жою O(n). Бәрі O(n)! Бір сағат бұрын массивтен бастап, динамикалық түрде өсіп-кішірейетін тізімге жеттік. Бірақ массивте бізде екілік іздеу болатын, ол O(log n) еді. Енді біз көп кеңістік жұмсаймыз, ал тізім баяу. Телефондағы контактілер мұндай болмауы керек! Бұл массивтер мен байланысқан тізімдердің ең жақсы қасиеттерін біріктіретін құрылымдарға өтетін баспалдақ ғана. Бірақ алдымен 10 минуттық печенье үзілісі 🍪

    Ағаштар

    Массивтің сұлулығы: деректер қатар тұрғандықтан, ұзындығын, ортасын, ортасының ортасын қарапайым арифметикамен табамыз. Ал байланысқан тізімде ортасын табу үшін басынан бастап, ұзындығын білу үшін бүкіл тізімді аралау керек, сосын тағы ортасына дейін жүру керек. Бұл O(n) болады. «Ортасын көрсететін көрсеткіш ұстасам ше?» деп ойлауыңыз мүмкін. Бірақ екілік іздеу ортасының ортасына, оның ортасына барады. Әр орынға көрсеткіш ұстасаңыз, бұл қайтадан массивке айналады. Екі жақты байланысқан тізім (doubly linked list) де бар: оның көрсеткіштері екі бағытта да жүреді. Бұл кейбір кодты жеңілдетеді, бірақ жылдамдықты түбегейлі өзгертпейді.

    Сондықтан массив пен байланысқан тізімді «Франкенштейн стилінде» біріктіріп, массивтің жылдамдығын және тізімнің динамикалықтығын алайық. Ағаштар (trees). Отбасылық шежіре ағашын елестетіңіз: ата-аналар, балалар, немерелер. Әдетте ол табиғи ағашқа қарағанда жоғарыдан төменге салынады. Ең жоғарғы элемент түбір (root) деп аталады. Массив пен тізім бір өлшемді, ал ағаш — алғашқы екі өлшемді деректер құрылымымыз.

    Екілік іздеу ағашы

    Бізге ең пайдалысы — екілік іздеу ағашы (binary search tree, BST). Ол екілік іздеуді қайтарады, бірақ деректерді массивтен ақылдырақ сақтайды.

    массив:   1  2  3  4  5  6  7

ағаш:              4
                 /   \
                2     6
               / \   / \
              1   3 5   7

    Екілік іздеуде алдымен ортасына (4), сосын ортасының ортасына (2 және 6), сосын олардың ортасына (1, 3, 5, 7) барамыз. Массивте 8-ді, 9-ды не 10-ды қосу үшін, жолымыз болып оң жақта бос орын тұрса жақсы, әйтпесе malloc/realloc арқылы бәрін көшіру керек. Ал ағашта мәндерді Y осі бойымен «жарып», екі өлшемге шығардық. Ортасындағы 4 ағаштың түбірінде. Қалған мәндер оның сол және оң жағында. Ең төменгі 1, 3, 5, 7 — жапырақтар (leaves), олардың балалары жоқ. Деректердің бәрі сақталды, тек бір өлшемнен екі өлшемге шықты.

    Енді әр түйінде бір емес, екі көрсеткіш болады: сол және оң бала. Сонда 5-ті қалай іздейміз? Түбірден бастаймыз: 4. 4 < 5, демек 5 оң жақта. Сол жақ тармақты ойша «қиып тастаймыз». Есептің жартысынан бірден құтылдық, телефон кітабын жыртқандай. 6-ға барамыз: 5 < 6, демек сол жақта. Оң тармақты қиямыз. Табылды!

    Екілік іздеу ағашының қасиеті Әр түйін өзінің сол жақ баласынан үлкен және оң жақ баласынан кіші (бірдей мәндер болмаса). Бұл рекурсивті қасиет: түбірге қатысты айтқанымыз 2-ге де (1 < 2 < 3), 6-ға да (5 < 6 < 7) қатысты, ал жапырақтарда баласы жоқ болғандықтан, бұл анықтама бұзылмайды.
    • Іздеу: n элемент болса, ағаштың биіктігі log₂ n. 7 элементте 2 «секіріс», 8 элементте 3 (2³ = 8). Сондықтан O(log n).
    • Қосу: O(log n). 8-ді қосу үшін ағаштың шетіне жаңа түйін қосу жеткілікті. 5.5 үшін де орнын табу оңай. Тек көрсеткіштерді жаңартамыз, массивтегідей бәрін көшірмейміз.
    • Жою: шамамен сол.

    Бағасы? Студент айтқандай: әр түйінде бір сан мен екі көрсеткіш бар. Бүтін сан үшін 4 байт емес, шамамен 20 байт (4 + 8 + 8). Қазір кеңістік арзан: Dropbox пен iCloud-та үлкен қалталарымыз бар. 7 сан үшін бұл маңызды емес, бірақ 7 миллион сан болса, жылдамдық маңызды болса да, бұл ең жақсы құрылым болмауы мүмкін. Бәрі нақты жағдайыңызға байланысты.

    typedef struct node
{
    int number;
    struct node *left;
    struct node *right;
}
node;

    Ағашта рекурсивті іздеу

    Екілік іздеу ағашы рекурсивті болғандықтан, оны кодта әдемі пайдалануға болады:

    bool search(node *tree, int number)
{
    if (tree == NULL)
    {
        return false;
    }
    else if (number < tree->number)
    {
        return search(tree->left, number);
    }
    else if (number > tree->number)
    {
        return search(tree->right, number);
    }
    else
    {
        return true;
    }
}
    • Ағаш бос болса (NULL), бірден false. Бұл базалық жағдай.
    • Іздеген сан ағымдағы түйіндегіден кіші болса, оң тармақты «қиып», сол жақ ішкі ағашты (subtree) іздейміз.
    • Үлкен болса, оң жақ ішкі ағашты іздейміз.
    • Тек 4 жағдай бар: жоқ, солда, оңда не дәл осында. Сондықтан соңғы else if (number == tree->number) артық, оның орнына жай else жеткілікті.

    Бағдарламалаудағы мансабыңыздың осы кезеңінде келісесіз бе, жоқ па, бірақ көп бағдарламашы бұл кодты сұлу деп санайды. Тек бір мәнді тексеріп, сосын дәл сол құрылымның кішірек бөлігін аралау — рекурсияның әдемі қолданылуы. Сол жақ не оң жақ бала да кішкене ағаш, ата-ана түйінге жалғанған «бала ағаш» қана. Мән жоқ болса, жапыраққа жетіп, баласы жоқ болғанда, tree NULL болады да, false қайтарылады.

    Ағаштың теңгерімі

    Бұл 7 элементтің ағашта әдемі, теңгерімді орналасуы әдейі жасалған. Ағаш бос болса, адам 2-ні енгізсе, ол түбір болады. Сосын 1 (сол жақ бала), 3 (оң жақ бала). Әдемі әрі теңгерімді. Бірақ адам «нашар» ретпен енгізсе ше? 1, сосын 2 (оң жақ бала), сосын 3 (2-нің оң жақ баласы), 4, 5, 6...

    1
 \
  2
   \
    3
     \
      4   ← бұл енді байланысқан тізім!

    Біз кездейсоқ байланысқан тізім жасадық! Ол екілік іздеу ағашының анықтамасын бұзбайды, бірақ теңгерімді емес. Демек, ол қайтадан O(n) болып кетеді. Жоғары курстарда екілік іздеу ағашының түрлі нұсқаларын оқисыз. Оларда әр қосу не жою кезінде ағашты аздап қайта теңгерімдейтін алгоритмдер бар. Мысалы, 3 қосылғанда ағашты «бұрып», 2-ні түбір етеді, 1 мен 3 одан салбырап тұрады. Бұл аздап уақыт алады, бірақ ағаштың O(n)-ге айналуына жол бермейді. Біз оны кодта жазбаймыз.

    Тұрақты уақыт: «қасиетті граль»

    Ағашты қайта теңгерімдеп отырсақ, логарифмдік биіктік сақталады, O(log n) аламыз. Бірақ деректер құрылымдарының «қасиетті гралі» — O(1), яғни тұрақты уақыт. Құрылымда қанша ат, сан не свитер болса да, ол 1, 3, тіпті 100 қадам алады, бірақ бұл сан құрылымдағы деректер санына тәуелсіз. Онда ондаған, жүздеген, миллиондаған элемент болса да, ол уақыт өте келе баяуламайды.

    1-аптадағы суретті еске түсірейік: сызықтық алгоритм — түзу сызық, логарифмдік — қисық, ал тұрақты уақыт — көлденең түзу. Логарифм мәңгі өсе береді, ал тұрақты уақыт ешқашан өзгермейді. Телефонда біреуді іздегенде, Google-да бірдеңе іздегенде не ChatGPT-ге сұрақ қойғанда, жауапты құрылымда қанша дерек болса да, бірден аласыз деп қалаймыз.

    Хэштеу

    Ол үшін жаңа құрылыс блогы керек: хэштеу (hashing). Формальды түрде хэштеу шексіз аймақтағы (domain) мәндерді шектеулі ауқымға (range) сәйкестендіреді. Мектептегі математикадан: аймақ — кіріс, ауқым — шығыс.

    Нақты өмірде мұны ойыннан кейін жинастырғанда көресіз. Сахнада 52 үлкен ойын картасы бар. Оларды ретке келтіру үшін бәрін жайып, екілерді анда, төрттерді мұнда, «червиді» мұнда, «трефті» анда деп ауыр жолмен сұрыптауға болады. Ал одан оңайы — карталарды алдымен «шелектерге» бөлу (bucketize). Әр картаға қарап, оны масть бойынша 4 шелектің біріне саламыз: ромбыны мұнда, трефті мұнда, пикті анда... Сонда 52 картадан тұратын есеп 13 картадан тұратын 4 есепке айналады. Әр шелектегі карталар бір масть болғандықтан, оларды тұздан король дейін ретке келтіру оңай, себебі олар енді жай сандар сияқты.

    Мәндерді белгілі бір кіріске қарай шелектерге бөлу процесін хэш-функция (hash function) деп атаймыз. Бұл кірісті (картаны, сөзді, атты) алып, оның қай шелекке түсетінін білдіретін санды қайтаратын математикалық функция не кодтағы функция.

    Телефонның Contacts бағдарламасын алайық. Apple не Google контактілерді жоғарыдан төменге сызықтық іздеуі мүмкін. Массив пайдаланып, екілік іздеу арқылы логарифмдік уақытқа жетуі мүмкін. Бірақ контактілер өте көп болса, бір қадамда жетсек жақсы болар еді.

    Mario-ны іздейік. Ағылшын әліпбиінде 26 әріп бар. Карталарды масть бойынша бөлгендей, A-дан басталатын аттарды бірінші шелекке, B-дан басталатындарды екінші шелекке, Z-тен басталатындарды соңғы шелекке салсақ ше? Сонда хэш-функцияға «Mario» берсек, ол 12 қайтарады (M — 13-ші әріп, бірақ шелектерді 0-ден санаймыз). «Luigi» берсек, 11. Аттардың саны теориялық тұрғыдан шексіз, бірақ хэш-функцияның жауабы тек 26 түрлі, 0-ден 25-ке дейін. Бұл — шексіз аймақтың 26 түрлі мәннен тұратын шектеулі ауқымға сәйкестенуі.

    #include <ctype.h>

unsigned int hash(const char *word)
{
    return toupper(word[0]) - 'A';
}
    • Ол адамның атының бірінші әрпін бас әріпке айналдырады (регистрге тәуелсіз болу үшін), сосын одан 'A'-ны, яғни ASCII 65-ті азайтады. Бас әріптен кіші әріпті азайтып, есепті бүлдірмеу үшін бас әріпке айналдырдық. Сонда A-дан басталатын атқа 0, Z-ке 25 шығады.
    • Ағылшын емес таңбалар енгізілсе, функция бұзылады, бірақ бұл мысалда атты ағылшынша деп есептейміз.
    • const: атты сілтеме бойынша (мекенжаймен) береміз. Демек, функция сол мекенжайға барып, атты өзгертіп жіберуі мүмкін. const бұған тыйым салады: функция атты тек пайдалана алады.
    • unsigned int: массивке арналған хэш-функция 0, 1, 2... қайтаруы керек, ешқашан теріс сан емес. unsigned (өткен аптадағы unsigned char сияқты) бұл мүмкіндікті жабады.

    Бұлар кіші жақсартулар, бірақ олар кодты жақсырақ жобаланған етеді, себебі қате жіберу мүмкіндігі азаяды.

    Хэш-кестелер

    Хэш-кесте (hash table) — деректер құрылымдарының «швейцар пышағы». Кейбір информатиктер «шөл аралда тек бір деректер құрылымы болса, мен соны таңдар едім» деген. Неге? Ол өте жан-жақты: кілттерді мәндермен байланыстырады. Сабақ басындағы сөздіктерді төменгі деңгейде көбіне хэш-кестемен іске асырады: телефон кітабы (аттар мен нөмірлер), Oxford сөздігі (сөздер мен анықтамалар). Бір деректі екіншісімен байланыстыру жиі керек.

    Хэш-кесте — байланысқан тізімдердің массиві:

    typedef struct node
{
    char *name;
    struct node *next;
}
node;

node *table[26];
    • table — 26 көрсеткіштен тұратын массив, әр әріпке бір шелек. Бастапқыда бәрі NULL.
    • Әр түйін бұрынғы person сияқты, бірақ бүгін қоңырау шалмайтындықтан, нөмірді алып тастадық. Оның орнына келесі түйінге көрсеткіш бар.
     0 A │ NULL
 1 B │ ──▶ [Bowser] ──▶ [Boo] ──▶ NULL
 …   │
11 L │ ──▶ [Luigi] ──▶ [Lakitu] ──▶ [Link] ──▶ NULL
12 M │ ──▶ [Mario] ──▶ NULL
 …   │
15 P │ ──▶ [Peach] ──▶ NULL
 …   │
25 Z │ ──▶ [Zelda] ──▶ NULL

    Массив тігінен салынды, бірақ бұл маңызды емес, тек экранға сыйдыру үшін. 0-орын — A, 25-орын — Z. Mario-ны қосқанда, оны массивтің ішіне тікелей салмаймыз. Жадта жаңа түйін жасап, Mario-ны соған салып, массивтің 12-ші ұяшығынан көрсетеміз. Нинтендо әлемінде кейіпкерлер көп, ал жанкүйерлер білетіндей, M, L және басқа әріптерден басталатын аттар бірнешеу. Сондықтан бізді соқтығысулар (collisions) күтіп тұр.

    Термин: соқтығысу Соқтығысу (collision) — екі түрлі кілттің бір шелекке түсуі. Шексіз нәрсені шектеулі нәрсеге сәйкестендірсек, анықтама бойынша соқтығысулар міндетті түрде болады.

    Шынайы өмірде аты M-ден басталатын жаңа адаммен танысып, телефоныңызда Mario бар болса, не істейсіз? Mario-ны өшіріп, орнына жаңа досты жазу ақымақтық. Келесі ұяшыққа, ол толса одан кейінгісіне салсақ, бәрі араласып кетеді: кім қай жерде екенінің логикасы жойылып, M әріпті достарды табу үшін бәрін іздеуге тура келеді. Ал массив пен байланысқан тізімді біріктіргенде: атты керекті ұяшыққа хэштеп, соқтығысса, байланысқан тізімге тізбектеп (chaining) қосамыз. Соқтығысулар көп болмаса екен деп үміттенеміз, бірақ кем дегенде құрылымды бүлдірмейміз.

    Хэш-кестенің жұмыс уақыты

    A-дан Z-ке дейінгі жай байланысқан тізімде іздеу O(n) болар еді: алфавит бойынша сұрыпталса да, Zelda сияқты Z-тен басталатын кейіпкерді табу үшін бүкіл тізімнен өту керек. Ал хэш-кестеде, аттар әліпби бойынша біркелкі таралған болса (L, M, A, B әріптерінен басталатын аттар шамамен тең болса), n ат k = 26 шелекке бөлінеді. Әр тізім шамамен n/k ұзындықта болады.

    Бірақ Big O-да кіші ретті мүшелер мен тұрақтылар не болатынын білеміз: O(n/k) = O(n). Яғни ол байланысқан тізімнен 26 есе жылдам болады, бірақ асимптоталық, яғни теориялық тұрғыдан, бәрібір деректер көлеміне сызықтық тәуелді.

    Тұрақты уақытқа қалай жетеміз? Ақылдырақ хэш-функция керек. Мысалы, бірінші әріпті емес, алғашқы үш әріпті қарастырайық: LAA, LAB, ..., LIN, ..., LUI, ... Сонда Link өз ұяшығына (LIN), Luigi өз ұяшығына (LUI) түседі. Бұл мысалда соқтығысулар жоғалады. Бірақ бағасы? Студент айтқандай, әлдеқайда көп жад. 26³ = 17 576 ұяшық! Олардың көбі мағынасыз: ағылшын тілінде не Нинтендо әлемінде AAA, AAB, AAC, ... ZZZ деп басталатын ат жоқ шығар. Соқтығысу ықтималдығын азайту үшін өте көп орынды босқа жұмсаймыз.

    Хэш-кестені қолданудағы шиеленіс осы: бірінші әріптен ақылдырақ, бірақ шелектер саны мен жад шамадан тыс өсіп кетпейтін жақсы хэш-функция табу керек.

    Trie

    Өте көп орын жұмсауға рұқсат етсеңіз, «граль» шынымен бар: trie. Бұл сөз «retrieval» (іздеп алу) сөзінен шыққан, бірақ «трай» деп оқылады. Trie — массивтерден жасалған ағаш. Бір кезде информатиктер нәрселерді Франкенштейн стилінде араластыра бастады: байланысқан тізім мен массив, енді ағаш пен массив. Сіз де өзіңізше бірдеңе ойлап табуыңызға болады 🙂

    Trie-дің әр түйіні, ағылшын тілі мысалында, A-дан Z-ке дейінгі 26 көрсеткіштен тұратын массив. Массив 0-ден 25-ке дейін индекстеледі, ал әр элемент trie-дің басқа түйініне көрсеткіш. Құрылымда сақталатын аттар жанама түрде сақталады: атауының бірінші әрпіне сәйкес ұяшықтан көрсеткіш шығып, екінші әрпін білдіретін түйінге, одан үшінші әрпіне апарады.

    түбір: [A … T … Z]
            │
            ▼
       [A … O … Z]          T
            │
            ▼
       [A … M … Z]          O
        │       │
        ▼       ▼
   [A … D … Z]  ✔ (TOM)     A / M
        │
        ▼
   ✔ (TOAD) ──▶ … E → T → T → E ✔ (TOADETTE)
    • TOAD қосу: түбірдегі T ұяшығы NULL-дан O әрпін білдіретін жаңа түйінге көрсеткішке айналады. Сосын A үшін жаңа түйін, сосын D. Түсінікті болу үшін оны жасылмен боялған деп елестетейік. Жадта бұл bool болады: «Toad аты осы жерде аяқталады».
    • Trie-да 4 түйін бар, әрқайсысы 26 өлшемді массив. Бірақ «toad» сөзі ешқайда анық сақталмаған, char * «toad» жоқ. T, O, A ұяшықтары NULL емес, ал D-дан кейін «бұл жерде ат аяқталады» белгісі бар.
    • TOADETTE: сол жолмен жүріп, E, T, T, E түйіндерін қосамыз да, соңғысын тағы белгілейміз. Яғни бір атауы екіншісінің бөлігі болса да, екеуін де сақтай аламыз.
    • TOM: T мен O-ны бөлісеміз, M ұяшығына белгі қоямыз. Массивтерді қайта қолданып отырмыз.

    Toad-ты қалай іздейміз? Түбірден бастап, бірінші әріпті «хэштеп», T-ге барып тексереміз: NULL емес. Келесі түйінде O, сосын A, сосын D. Жасыл белгі (boolean) бар, демек Toad бар.

    Маңыздысы: trie-да 3 ат болсын, 3 миллион ат болсын, Toad-ты табу үшін 4 қадам кетеді. Аттардың ұзындығы әртүрлі, бірақ белгілі бір шегі бар. Нинтендо 10, 20, 30 әріптен ұзын ат ойлап таппайды. Сондықтан Toad, Toadette, Tom, Mario, Luigi, Peach және кез келген атты іздеу O(1), тұрақты уақыт.

    typedef struct node
{
    struct node *children[26];
    char *number;
}
node;

node *trie = NULL;

    Әр түйін — children атты 26 көрсеткіштен тұратын массив, ол сол түйіннің балалары. Белгінің орнына адамның телефон нөмірін сақтауға да болады. Сонда «Toad-тың нөмірі қандай?» деген сұраққа да жауап береміз: аттар — кілттер, нөмірлер — мәндер. Ағаш алдымен NULL, сосын әр атты қосқанда бірінші, екінші, ..., соңғы әріпке хэштеп, қажет болса жаңа түйін бөліп, белгі не нөмір қоямыз.

    Сонда неге 5-тапсырмада trie емес, барлық бағдарламашы білетін хэш-кестені іске асырасыз? Бағасы қандай? Студент айтқандай, өте көп жад. Бір int-тен басталып, оған көрсеткіш, сосын екі көрсеткіш қостық, ал енді 26 көрсеткіш және тағы бір мән. Toad, Toadette, Tom мысалынан көргендей, trie-да көп жад босқа жұмсалады: массивтердегі көрсеткіштердің көбі NULL болып, пайдаланылмай қалады. Нәтижесінде есепті дұрыс шешсеңіз де, компьютерді баяулататындай көп жад қолданасыз. Тапсырмада бұл шектеуді қалай азайтуға болатынын көресіз.

    Нақты өмірдегі хэш-кесте

    Нақты өмірде стектер де, кезектер де, хэш-кестелер де бар. Гарвард алаңындағы (және АҚШ-тың басқа жерлеріндегі) Sweetgreen мейрамханасында салат алған боларсыз. Тапсырысты алдын ала берсеңіз, олар салатыңызды мына сияқты ағаш сөрелерге хэштеп қояды: A–E, F–J, K–N және O–Z шелектері. Дэвидтің «Malan» тегі K–N аралығында, сондықтан салаты сол жерге қойылады.

    Бірақ нақты өмірде де шектеулер бар. Не дұрыс болмай кетуі мүмкін? Студент айтқандай, орын таусылуы мүмкін. Бұрын бұл жүйеде әр әріпке жеке шелек болған. Кейін біреу A шелегі жиі B-ге, B шелегі C-ға «толып кететінін», ал Q не Z-ті ешкім пайдаланбайтынын байқаған. Сондықтан әріптердің көбін алып тастап, шелектерді үлкейтті. Енді K–N аралығы толып кетуі екіталай. Бұл — бүгін көрген деректер құрылымының нақты өмірдегі мысалы.

    Көрсеткіштер мен дереференсті жазу қаншалықты түсініксіз көрінсе де, кодта біз басқа адамдар бұрын ойлап тапқан нақты өмірлік шешімдерді жаңа салаға аударып отырмыз. Бұл аптадағы ең соңғы тапсырма — өз емле тексергішіңіз (spell checker). Сізге 100 000-нан астам ағылшын сөзі бар үлкен файл беріледі. Оны жадқа ақылмен әрі тиімді жүктеу керек. Біз кодыңыздың қаншалықты жылдам не баяу екенін, қанша жад пайдаланатынын өлшейтін құралдар береміз. Сонда өз нәтижеңізді басқалармен салыстыра аласыз.

    1. Асханадағы подностар қандай құрылымға мысал?

    Әр түйінде 26 көрсеткіш бар, бірақ олардың көбі пайдаланылмайды.

    Түйіндерді санау

    Байланысқан тізімдегі түйіндер санын қайтаратын int count(node *list) функциясын жазыңыз. Алдымен циклмен, сосын рекурсиямен жазып көріңіз.

    Шешімі
    // Цикл арқылы
int count(node *list)
{
    int n = 0;
    for (node *ptr = list; ptr != NULL; ptr = ptr->next)
    {
        n++;
    }
    return n;
}

// Рекурсия арқылы
int count_recursive(node *list)
{
    if (list == NULL)
    {
        return 0;
    }
    return 1 + count_recursive(list->next);
}

    Ағашқа қосу

    Екілік іздеу ағашына жаңа санды қосатын рекурсивті функция жазыңыз: node *insert(node *tree, int number). Ол ағаштың (мүмкін, жаңа) түбірін қайтарсын.

    Шешімі
    node *insert(node *tree, int number)
{
    if (tree == NULL)
    {
        node *n = malloc(sizeof(node));
        if (n == NULL)
        {
            return NULL;
        }
        n->number = number;
        n->left = NULL;
        n->right = NULL;
        return n;
    }
    if (number < tree->number)
    {
        tree->left = insert(tree->left, number);
    }
    else if (number > tree->number)
    {
        tree->right = insert(tree->right, number);
    }
    return tree;
}

    Inheritance

    Отбасылық ағашта қан тобының тұқым қуалауын модельдеңіз. Әр адамда екі аллель бар (A, B не O), әрқайсысы ата-анасының біреуінен кездейсоқ алынады. Сізге берілген person құрылымында parents[2] (ата-аналарға көрсеткіштер) және alleles[2] бар. create_family(generations) және free_family(p) функцияларын іске асыру керек.

    Кеңес
    • create_family рекурсивті: алдымен ата-аналарды create_family(generations - 1) арқылы жасап, сосын әр ата-анадан кездейсоқ бір аллель аласыз.
    • Ең үлкен ұрпақтың ата-аналары жоқ (NULL), олардың аллельдері random_allele() арқылы кездейсоқ беріледі.
    • free_family те рекурсивті: алдымен ата-аналарды, сосын баланы босатыңыз. Базалық жағдай: p == NULL.
    Тексеру
    • 3 ұрпақ дұрыс шығарылады, әр баланың аллельдері ата-аналарының аллельдерінен алынған.
    • valgrind ./inheritance ешқандай ағып кету көрсетпейді.

    Кеңес
    • fscanf(file, "%s", word) сөздік файлынан бір сөзді оқиды. Ол EOF қайтарғанша оқыңыз.
    • Әр сөз үшін жаңа node бөліп, сөзді strcpy арқылы көшіріп, оны тиісті шелектің басына қосыңыз (O(1)).
    • Шелектер саны (N) көп болса және хэш-функция жақсы болса, тізімдер қысқа болып, check жылдамдайды. Бірінші әріптен ақылдырақ функция ойлап табыңыз.
    • check регистрге тәуелсіз болуы керек. Хэштеу мен салыстыру үшін tolower және strcasecmp (strings.h) пайдалы.
    • Сөздер санын load кезінде санап, size-та жай ғана қайтарыңыз.
