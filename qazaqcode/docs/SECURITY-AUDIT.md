# QazaqCode: қауіпсіздік аудиті (3-кезең)

Күні: 2026-10-14. Аудитор: Claude (автоматтандырылған кодты оқу + шабуыл тесттері). **Бұл тәуелсіз пентест емес.** Төменде не тексерілгені, не табылғаны, не түзетілгені, және **не тексерілмегені** шынайы жазылған.

## 1. Әдіснама

1. **Кодты оқу:** `src/lib/{auth,context,db,rate-limit,errors,env}`, барлық server action-дар (`src/app/**/actions.ts`, `courses-actions.ts`), `src/app/api/**`, экспорт маршруттары (CSV/XLSX/PDF), `db/migrations/0001-0011`, `next.config.mjs`, `Dockerfile`, `docker-compose.yml`.
2. **Автоматты шабуыл тесттері** (production build, нақты PostgreSQL + RLS, нақты Chromium):
   - `e2e/security.spec.ts` (49 тест): бөтен мектеп/сынып/жұмыс/курс ID-лары, рөл эскалациясы, server action-дарды тікелей POST (манифесттен action id-мен, React reply пішімі), Origin/CSRF, жалған JWT, brute force (rate limit қосулы бөлек сервер), XSS (нақты браузерде `window.__xss`/`dialog`/CSP консоль қателері), CSV/XLSX формула инъекциясы, ILIKE/SQL инъекция, тақырыптар, қате мәтіндері, бумада құпия, жасырын жауап кілттері, git-те құпия, аудит.
     Әр «жабық» тест алдында **позитивті бақылау** бар (иесі деректі көреді; әйтпесе тест бос өтер еді). Бөтен мектеп деректері `ZZBMARK` белгісімен және XSS жүктемесімен толтырылған, жауапта осы белгі болмауы тексеріледі.
   - `db/tests/security2.test.mjs` (16 тест): каталог тексерулері (RLS, грант, PUBLIC EXECUTE, `proconfig`), әдепкі құқықтар, аудит, тікелей жазу тыйымы.
   - `tests/unit/security.test.mjs` (3 тест): IP таңдау, `env.ts` өндіріс тексерістері, Supabase драйвері (моктелген `fetch`).
3. **Қайта шығару → түзету → регрессиялық тест.** DB мәселелері үшін `0010_hardening.sql`-сыз миграция жиынында `security2` тесттері сәтсіз өтті (16-дан 7-і қызыл: RLS, PUBLIC EXECUTE, ішкі функциялар, әдепкі құқықтар, аудит ×3), 0010-нан кейін 16/16 жасыл.
4. **Қолмен:** `grep` арқылы динамикалық SQL (барлық `q()`/`raw()` шақыруы параметрленген; `${}` тек тұрақтыларда: `TZ`, `LIMIT`, көмекші өрнектер), `dangerouslySetInnerHTML` (тек `brandStyle()` ішінде HEX regexp-пен сүзілген түстер + theme-init скрипті), `NEXT_PUBLIC_` (жоқ), `<input type=file>` (жоқ).

## 4. Deployment тексерісі (Docker-сыз қолмен дәлел)

`docker build` **жүргізілмеді** (демон жоқ). Дәлелденген бірдей қадамдар:
- `NEXT_OUTPUT=standalone NEXT_DIST_DIR=.next-fs npx next build` → сәтті; `standalone` (90 МБ) + `static` таза каталогқа көшіріліп, репозиторийсіз `node server.js` жұмыс істеді (Dockerfile құрылымын қайталайды).
- `/api/health` → `200 {"status":"ok","db":"ok"}`; DB қолжетімсіз болғанда `503 {"status":"degraded","db":"down"}`, жауапта/логта пароль жоқ.
- Таза каталогта PDF (`%PDF-1.3`, 30 КБ, қазақ әріптері үшін DejaVu) және XLSX жүктелді → шрифттер standalone трассировкада бар (`outputFileTracingIncludes` та қосылды). Шрифтсіз → `500 «Есепті жасау мүмкін болмады»` (stack тек серверлік логта); Dockerfile `assets/`-ті айқын көшіреді.
- **Superuser емес DB рөлімен** (`scripts/init-db-roles.sh` → `qc_app`, NOSUPERUSER NOBYPASSRLS NOINHERIT) қосымша толық жұмыс істеді (мұғалім беті, сынып, PDF, CSV+аудит).
- Өндіріс режимінде әлсіз JWT құпиясы → сервер `process.exit(1)`.
- `db/migrate.sh`: `--check`, checksum (өзгертілген қолданылған миграцияда код 4), advisory lock; `--dev-shim` өндірісте / Supabase URL-де / нақты `auth` схемасында бас тартады (код 3) - үшеуі де қолмен тексерілді.
- `scripts/backup.sh` → шифрланған `.dump.enc` + `.sha256`; `scripts/restore.sh` бос дерекқорға: 34 пайдаланушы / 527 аудит жазбасы / 42 жұмыс / 31 баға сәйкес; қате құпиясөз және бұзылған файл қалпына келтіруді тоқтатты.
- `docker-compose.yml` YAML ретінде жарамды (парсер); `docker compose config` **жүргізілмеді**.

## 5. Әлі тексерілмеген аймақтар (тәуелсіз пентест қажет)

Мынадай нәрселер **тексерілмеді**; өндіріс алдында тәуелсіз пентест (кемінде web app + инфрақұрылым) керек:
- Нақты Supabase Cloud/self-hosted: Auth драйвері, default privileges, `on_auth_user_created` триггері, pooler мінезі, PostgREST экспозициясы (қосымша PostgREST-ті қолданбайды, бірақ Supabase оны қосады: `public` схемасы арқылы тікелей RPC шақыру мүмкін; RLS/грант сұраулары бұған қарсы қорған, бірақ нақты жобада сыналмаған).
- Docker образы/compose, TLS, reverse proxy конфигі, firewall, хост ОЖ қатаңдатуы, supply chain (npm тәуелсіздіктер `npm audit`/SCA, образ сканері).
- DoS/жүктеме: тесттер жоқ (ауыр есеп PDF/XLSX 20/мин/қолданушы ғана шектелген; үлкен ұйым деректерінде жады/CPU өлшенбеген).
- Бизнес-логика тереңдігі: лицензия лимиттерінен айналып өту, жарыс жағдайлары (race conditions: бір мезгілде `join_classroom` лимит, `submit_assignment`), баға манипуляциясы - тек DB тесттері қамтыған бөлігі.
- Next.js/React/Node/pg/jose нұсқаларындағы белгілі осалдықтар (CVE) жүйелі тексерілмеген.
- Sandbox/код орындау (D агентінің жұмысы, `docs/SANDBOX.md`) бұл аудитте қамтылмаған.
- AI көмекші (`/api/ai/chat`, 0011) бұл аудитте қамтылмаған: prompt injection, деректер ағуы, құны.
- Браузерлер матрицасы (тек Chromium), қолжетімділік/кері байланыс каналдары, e-mail жіберу (қосымша e-mail жібермейді; Supabase жібереді).
- Әлеуметтік инженерия, физикалық қауіпсіздік, қызметкерлер құқықтары процесі.

## 6. ҚР дербес деректер туралы заңы бойынша чеклист (заңгер растауы керек)

> **Бұл заңды кеңес емес.** ҚР «Дербес деректер және оларды қорғау туралы» Заңы мен оның жаңа редакциясы/қаулылары талаптарын лицензиялы заңгер нақтылауы тиіс. Төменде - техникалық дайындық және заңгер шешуі керек сұрақтар.

| Тақырып | Қазіргі техникалық күй | Заңгер/ұйым шешуі керек |
|---|---|---|
| Деректер локализациясы | Деректер сіз таңдаған Postgres-те. Supabase Cloud - шетелде. Self-hosted (Қазақстандағы VPS/дата-орталық) нұсқасы бар (DEPLOY.md Нұсқа B) | ҚР аумағында сақтау/өңдеу міндеті бар ма; шетелге беру шарттары; қай хостингті таңдау |
| Кәмелетсіздер деректерін азайту | Жиналады: аты-жөні, e-mail, жұмыс мазмұны, баға, белсенділік уақыты. **Жиналмайды:** ЖСН, телефон, мекенжай, тууы, сурет жүктеу | e-mail оқушыдан міндетті ме (мектеп аккаунты/бүркеншік ат нұсқасы); ата-ана келісімі үшін жас шегі |
| Келісім | Платформада келісім алу/тіркеу механизмі **жоқ** (экран, чекбокс, журнал) | Келісім кімнен (оқушы/ата-ана/мектеп) және қалай алынады; келісімді қайтарып алу; мектеп пен платформа арасындағы келісімшарт/DPA (оператор/өңдеуші рөлдері) |
| Өшіру құқығы | Өшіру **UI жоқ**. Оқушы аккаунтын `auth.users`-тан өшіру (Supabase Dashboard/SQL) схема бойынша каскадты жояды: профиль, мүшелік, жұмыс, баға, прогресс (`on delete cascade`; нақты Supabase-те тексерілмеген). Мұғалім/курс авторы `on delete restrict` (алдымен сынып/курс көшіру керек). `audit_logs.actor_id` және backup-тар пайдаланушы id-ін сақтайды (псевдоним) | Өшіру процедурасы мен мерзімі; журнал мен backup-тағы деректер; аккаунтты анонимдеу функциясын жазу (ашық жұмыс) |
| Экспорт (қол жеткізу/тасымалдау) | Әкімші/мұғалім сынып/мектеп есебін алады (CSV/XLSX/PDF, журналға жазылады). **Оқушының өз деректерінің экспорты жоқ** | Субъект сұранысына жауап беру мерзімі мен форматы; қажет болса экспорт функциясы |
| Сақтау мерзімі | Автоматты өшіру/мерзім **жоқ**: деректер лицензия аяқталса да сақталады; backup `BACKUP_KEEP_DAYS` (әдепкі 14 күн) | Оқу жылынан кейін деректі сақтау мерзімі; лицензия тоқтағанда өшіру; backup шифрлау құпиясын басқару |
| Қауіпсіздік шаралары | RLS, ролдік қолжетім, шифрланған backup (AT REST шифрлау - хостингте), TLS, аудит журналы (экспорт, құқық өзгерістері), қолжетімділікті қысқарту | Қолжетімділік тізімдері, қызметкерлерді оқыту, оқиғаны хабарлау процесі (мерзімдері), қауіпсіздік қызметі тағайындау |
| Үшінші тараптар | Сыртқы суреттер/видео (оқушы IP-ы үшінші тарапқа), Supabase (өңдеуші), e-mail жеткізуші, мониторинг (Sentry қосылса) | Өңдеушілер тізімі, келісімшарттар, трансшекаралық беру |
| Ашықтық | Құпиялылық саясаты/пайдалану шарттары **жоқ** (маркетинг бетінде қысқа ғана) | Саясат мәтіні, мектепке арналған DPA, оқушы/ата-анаға хабарлама |

## 7. Тесттерді қайта жүргізу

```bash
# DB (бөлек тест дерекқоры!)
TEST_DATABASE_URL=... node --test --test-concurrency=1 db/tests/*.test.mjs
# Unit
npm run test:unit
# E2E қауіпсіздік (production build, seed-demo; 3206: RATE_LIMIT_DISABLED=yes, 3216: rate limit ҚОСУЛЫ + COOKIE_SECURE=true)
DATABASE_URL=... AUTH_JWT_SECRET=... E2E_BASE_URL=http://127.0.0.1:3206 E2E_RL_BASE_URL=http://127.0.0.1:3216 E2E_DIST=.next-f npx playwright test e2e/security.spec.ts
```
