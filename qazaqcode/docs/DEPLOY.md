# QazaqCode: орналастыру нұсқаулығы

> Күй: жергілікті PostgreSQL-де және `next start`-та сыналған. Supabase жобасына қарсы, Docker образы және бұлттық хостингте **әлі сыналмаған**: пилоттан бұрын төмендегі «Тексеру тізімін» орындаңыз.

GitHub Pages бұл өнімге жарамайды (сервер мен дерекқор керек). CS50 қазақша сайты Pages-те қалады; QazaqCode бөлек орналастырылады.

## Нұсқа A: Supabase (дерекқор + Auth) + Node хостинг

1. Supabase жобасын жасаңыз (аймақ - қолжетімді ең жақын; қараңыз «Дербес деректер»).
2. **Дерекқор схемасы**: Supabase SQL Editor-да немесе `psql`-мен `db/migrations/0001...0005` файлдарын тәртібімен орындаңыз
   (`DATABASE_URL=<direct connection> bash db/migrate.sh` - `--dev-shim` флагынсыз!). Supabase-те `auth` схемасы бар, shim қосылмайды.
3. **Auth**: Authentication → Providers → Email қосыңыз; өндірісте e-mail растауды қосыңыз; Site URL = `APP_URL`; redirect URL-ларына `APP_URL/**`.
4. **SUPER ADMIN**: Supabase Auth-та өз аккаунтыңызды жасаңыз, сосын: `DATABASE_URL=... node scripts/create-super-admin.mjs email@x.kz`.
5. **Орта айнымалылары** (`.env.example`): `DATABASE_URL` (pooler, transaction mode), `AUTH_DRIVER=supabase`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_JWT_SECRET`, `APP_URL`, `COOKIE_SECURE=true`.
   `service_role` кілті қажет емес және қосымшаға берілмейді.
6. `npm ci && npm run build && npm start` (не Vercel/Render/Fly.io). Standalone шығысы: `output: "standalone"`.
7. HTTPS міндетті (хостинг не reverse proxy). `Strict-Transport-Security` тақырыбы қосымшада бар.

## Нұсқа B: өз серверіңізде (Docker + PostgreSQL)

`Dockerfile` және `docker-compose.yml` дайын (сыналмаған: бұл ортада Docker жоқ). Мұнда `AUTH_DRIVER=supabase` өз Supabase (self-hosted) не басқа GoTrue-ға ғана жарайды;
жергілікті драйвер өндірісте өшірулі. Қазақстандағы дата-орталықта сақтау қажет болса, осы нұсқаны (self-hosted Supabase) қарастырыңыз.

## Дербес деректер (Қазақстан)

Платформа оқушылардың аты-жөнін, e-mail-ын және оқу нәтижесін сақтайды. **Нақты оқушылар деректерін жинамас бұрын:**
- «Дербес деректер және оларды қорғау туралы» ҚР Заңы талаптарын (оның ішінде деректерді Қазақстан аумағындағы серверде сақтау/өңдеу міндеті бар-жоғын) заңгермен нақтылаңыз; шетелдік бұлт (Supabase Cloud) сай келмеуі мүмкін.
- Кәмелетке толмағандардың деректерін барынша аз жинаңыз (қазір: аты, e-mail, жұмыс/баға; телефон, ЖСН, мекенжай сұралмайды). Ата-аналардан келісім алу тәртібін мектеппен белгілеңіз.
- Деректерді сақтау мерзімі, өшіру/экспорт тәртібі, оқиғаларды хабарлау процесі құжатталуы тиіс (келісімшарт/DPA).
Бұл заңды кеңес емес.

## Резервтік көшірме және мониторинг

- Supabase: күнделікті backup + PITR (жоспарға байланысты). Өз Postgres: `pg_dump` кестесі + сыртқы сақтау + қалпына келтіруді тексеру (кемінде айына бір рет).
- Қателер мониторингі: Sentry не ұқсас (қосымша DSN env-мен). Журналдарда құпиялар мен құпиясөздер жоқ.
- Rate limiting қосымшада жадта; бірнеше дана болса Redis не WAF қосыңыз.

## Тексеру тізімі (пилоттан бұрын)

- [ ] `db/migrate.sh` нақты Supabase-те қателіксіз өтті; `on_auth_user_created` триггері жұмыс істейді.
- [ ] `AUTH_DRIVER=supabase`: тіркелу, кіру, шақыруды қабылдау, сыныпқа қосылу E2E нақты Supabase-те.
- [ ] `COOKIE_SECURE=true`, HTTPS, құпиялар тек хостингтің secret store-ында.
- [ ] Лицензия, SUPER ADMIN, аудит журналы тексерілді; демо ұйым өшірілді не белгіленген.
- [ ] Заңгер: дербес деректер, келісімшарт, лицензия (қараңыз NOTICE.md).
