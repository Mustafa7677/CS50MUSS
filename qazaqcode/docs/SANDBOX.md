# Қауіпсіз код бағалау (sandbox): дизайн. ӘЗІРГЕ ІСКЕ ҚОСЫЛМАҒАН

> **Ескерту: оқушының браузеріндегі «жеке тексеру» sandbox ЕМЕС.** Платформада оқушының Python кодын ТЕК оқушының өз браузерінде (Pyodide / WebAssembly, web worker) көрінетін тест кейістерімен іске қосатын «Сынап көру» функциясы бар (docs/SELFCHECK.md). Ол серверде код орындамайды, нәтижесін серверге жібермейді, баға емес және оқушы оны өзгерте алады; сондықтан төмендегі серверлік sandbox дизайнін алмастырмайды: автоматты БАҒАЛАУ (сервер тексеретін, жасырын тесттермен) бұрынғыдай ІСКЕ ҚОСЫЛМАҒАН, баға қоюшы мұғалім ғана.

**Күйі: іске асырылмаған және өндірісте өшірулі.** Бұл құжат - 3-кезеңдегі жүзеге асырудың талаптары. Sandbox толық сыналғанша
қауіпті пайдаланушы кодын орындау функциясы өндіріске қосылмайды. Қазір код тапсырмалары мұғалім қолмен бағалайтын түрде жұмыс істейді; тест (quiz) серверде автоматты бағаланады.

## Принциптер

1. Пайдаланушы кодын **негізгі API серверінде ешқашан** орындамаймыз.
2. Нақты баға тек сервер жағындағы runner нәтижесінен; жасырын тест жағдайлары браузерге жіберілмейді.
3. Runner API-дан бөлек желіде, дерекқорға тікелей қолжетімсіз.

## Архитектура

```
Student ──submit──► Next.js/DB: submissions(status=queued) ──► jobs queue (Postgres SKIP LOCKED / Redis)
                                                                   │
                                      Runner worker (бөлек хост/VM, ішкі API кілті)
                                        1. job алады (submission_id, kind, code, test_cases[hidden қоса])
                                        2. әр тест үшін бір реттік контейнер іске қосады
                                        3. нәтиже: passed/total, stdout/stderr (қысқартылған), time_ms
                                        4. нәтижені `record_sandbox_result(job, jsonb)` (service рөлі) арқылы жазады
                                        5. контейнерді жояды
```

## Контейнер талаптары (docker run / gVisor/Firecracker)

- `--network none`; `--read-only` + шағын `tmpfs` (/tmp, 16 МБ); `--cap-drop ALL`; `--security-opt no-new-privileges`; seccomp профилі.
- `--memory 128m --memory-swap 128m`; `--cpus 0.5`; `--pids-limit 64`; `ulimit` (nofile, fsize).
- Орындау тайм-ауты (мысалы 5 сек/тест) + хост жағындағы watchdog (kill); stdout/stderr 64 КБ-пен шектеледі.
- Жеке, бекітілген тілдік образдар (Python/Node/SQLite), тапсырма сайын жаңа контейнер, аяқталғаннан кейін `--rm`.
- Ешқандай құпия/env контейнерге берілмейді; код бір файл ретінде (stdin/volume read-only).
- Рұқсат етілген кітапханалар тізімі; `pip/npm install` жоқ.

## Қосымша қорғаныс

- Бір оқушыға/ұйымға job rate limit және кезек терендігі; лицензия күйі тексеріледі.
- Runner нәтижесі қол қойылған (HMAC); DB функциясы тек runner рөлімен шақырылады.
- Fork-bomb, жад толтыру, шексіз цикл, файл жазу, желіге шығу, `/proc` оқу, символдық сілтеме шабуылы үшін қауіпсіздік тесттері міндетті (қабылдау критерийі).
- Нәтижелерді қайта есептеу (идемпотент), аудит журналына жазу.

## Деректер моделі (жоспар)

`sandbox_jobs(id, org_id, submission_id, status, attempts, locked_at, result jsonb)`; `submission_results.kind='sandbox'` (кесте дайын); `assignment_test_cases` (дайын).
