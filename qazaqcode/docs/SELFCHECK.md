# Жеке тексеру: оқушының браузеріндегі Python («Сынап көру»)

**Қысқаша.** Python тапсырмасында оқушы «Сынап көру» батырмасын басады; коды ОЗ БРАУЗЕРІНДЕ (Pyodide = CPython WebAssembly-ге, web worker ішінде) тек **көрінетін** (`is_hidden=false`) тест кейістерімен іске қосылады. Нәтиже: өтті/өтпеді, күтілген және шыққан шығыс, айырмашылық жолдары, уақыт. Бұл **жеке тексеру, түпкілікті баға емес**: нәтиже серверге жіберілмейді, «Жіберу» (`submit_assignment`) және мұғалім бағасы өзгермейді. Мұғалім беті өзгермеген.

## Бұл не емес
- Бұл **sandbox емес** және серверде код орындау емес (docs/SANDBOX.md). Серверде оқушы коды ЕШҚАШАН орындалмайды: child_process/docker/runner жоқ.
- Бұл **автоматты бағалау емес**. Балл қойылмайды, дерекқорға ештеңе жазылмайды. Мұғалім жібергеннен кейін өзі қарап баға қояды.
- Нәтижеге сенуге болмайды: оқушы өз браузерінде не істесе де (DevTools, кодты өзгерту) қолы жетеді. Сондықтан нәтиже ешқайда жіберілмейді, «өз тексеруім: 3/4» сияқты қол жазба мұғалімге де ЖІБЕРІЛМЕЙДІ (жалған нәтиже мен құпиялылық тәуекелі). Кейін қосылса, тек оқушы келісімімен және «сервер тексермеген» белгісімен болуы тиіс.

## Дизайн
| Бөлік | Файл | Рөлі |
|---|---|---|
| Хостинг | `public/vendor/pyodide/` | Pyodide 314.x файлдары өз доменімізде; `scripts/vendor-pyodide.mjs` көшіреді; лицензия `LICENSE-NOTICE` (MPL-2.0) |
| Worker | `public/workers/py-runner.js` | Pyodide жүктейді, кейістерді бірінен соң бірін орындайды, stdout/stderr жинайды (64 КБ шегі) |
| Runner | `src/lib/selfcheck/runner.ts` | Main ағын жағы: бір мезгілде 1 жұмыс, әр кейіске таймаут (5 с), жүктелу таймауты (90 с), салыстыру (`normalizeOutput`, `diffLines`) |
| UI | `src/app/student/assignments/[id]/SelfCheck.tsx` | Тек `kind=python` және тапсырма өңделетін күйде; Workspace.tsx-ке қосылған |

Протокол (JSON хабарлар): `main -> worker {type:"run", code, cases:[{input}]}`; `worker -> main {type:"loading"|"ready"|"case"|"done"|"fatal"}`. Worker-ге күтілетін нәтиже берілмейді, салыстыру main жағында.

### Жасырын кейістер
`page.tsx` тек `is_hidden = false` кейістерді сұрайды (RLS қосымша кепіл), тек `kind=python` үшін компонентке береді. Жасырын кіріс/шығыс HTML-де де, network-те де жоқ (e2e/selfcheck.spec.ts тексереді; db/tests қауіпсіздік тесттері RLS-ті бөлек тексереді).

### Әрекет ету ережелері
- **Таймаут.** Әр кейіске 5 с. Шексіз цикл worker-ді қатырады, сондықтан таймерді main ағын ұстайды: мерзімі өтсе `worker.terminate()`, кейіс «Уақыт өтті», қалғандары «Орындалмады». Бет қатпайды (орындау бөлек ағында).
- **Таза күй.** Әр «Сынап көру» басылғанда жаңа worker (және жаңа Python интерпретаторы) жасалады, аяқталғанда өлтіріледі. Ішінде әр кейіс жаңа `globals` сөздігінде (`__name__ == "__main__"`) жүреді. Бір іске қосу ішіндегі кейістер интерпретаторды бөліседі (мысалы `sys.modules` өзгерісі келесі кейіске әсер етуі мүмкін).
- **Шығыс шегі.** stdout және stderr әрқайсысы 64 КБ-пен қиылады («қысқартылды» белгісімен).
- **Салыстыру.** Жол соңындағы бос орындар мен соңғы бос жолдар ескерілмейді; жол ішіндегі бос орын мен регистр маңызды. (Мұғалімнің серверлік тексерісі басқаша болуы мүмкін.)
- **Кіріс.** `input()` кейістің `input` мәтінінен жол-жолмен оқиды; бітсе EOF.
- **Жүктелу.** Алғашқы іске қосуда ~13 МБ (wasm 9,6 МБ + stdlib 2,5 МБ). `Cache-Control: immutable`, кейін кэштен. UI: ескерту, айналмалы индикатор, қате/қайталау. «Тоқтату» батырмасы бар. Тек stdlib: сыртқы пакеттер (numpy т.б.) жоқ.
- **Қате күйлері.** Жүктелмесе/таймаут/worker қатесі: түсінікті хабар + «Қайталау»; жұмыс (автосақтау, «Жіберу») бұған тәуелсіз.

## Қауіпсіздік және шектеулер (ашық)
1. **Желі/файл жүйесі.** Қабаттар: (a) worker жауабындағы CSP: `default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'` (сыртқы доменге сұраныс браузер деңгейінде бұғатталады; `unsafe-eval` жоқ); (b) бет CSP-інде `worker-src 'self'` (blob: жоқ, сыртқы CDN жоқ); (c) Pyodide жүктелгеннен кейін, оқушы коды алдында worker-де `fetch`, `XMLHttpRequest`, `WebSocket`, `importScripts`, `Worker`, `indexedDB` т.б. өшіріледі және `js`/`pyodide_js` Python модульдері импорттан жабылады. Файл жүйесі: Emscripten виртуалды жады ФЖ-і ғана (хост дискісі жоқ).
2. **Нақты шектеу, ашық айтылады:** (c) қабаты **кедергі, кепіл емес**. Шебер оқушы `js` өшірілгеннен кейін де басқа жолмен JS нысандарына жетуі мүмкін (Pyodide-тің `js` көпірі интерпретатордың ішкі құрылымы). Бұл қауіп емес деп есептелінеді: код оқушының ӨЗ браузерінде, оның өз құқығымен, ол DevTools-та да дәл осыны істей алады; сервер ешқашан бұл нәтижеге сенбейді. Қалған тәуекел: worker same-origin, сондықтан `connect-src 'self'` өз сайтымызға оқушының cookie-мен сұраныс жасай алады (оқушы өз аккаунтымен бәрібір істей алатынынан артық емес). Тәуелсіз пентестке енгізіңіз.
3. **Ресурстар.** Жады/CPU баптауы жоқ (браузер шегі). Таймаут CPU-ны, 64 КБ шығысты шектейді. Әлсіз құрылғыда (телефон) жүктелу баяу болуы мүмкін.
4. **Бұзу.** Оқушы кодты/нәтижені бұзуы мүмкін, ол маңызды емес: баға мұғалімде.
5. **Құпиялылық.** Код сыртқы сервиске жіберілмейді (CDN жоқ). Сервер тек әдеттегі автосақтауды (`save_draft`) көреді, ол өзгермеген.
6. **Сыналмағаны:** нақты ескі Android/iOS құрылғылары; оффлайн режим; Safari-дегі WebAssembly жады шегі; өте ұзын шығыс 64 КБ-тан асқанда кейіс таймаутқа дейін Python-ның жұмыс істеуі (қиылады, бірақ процесс жалғасады).

## Тесттер
- `tests/unit/selfcheck.test.mjs`: салыстыру, runner протоколы (жалған worker: өту/өтпеу, таймаут + worker өлтірілуі, бір мезгілде 1 жұмыс, жүктелу қателері, cancel), worker файлы (сыртқы URL жоқ, желі API жабылады, 64 КБ, таза namespace), vendor файлдары мен лицензия.
- `e2e/selfcheck.spec.ts` (production build): локальді жүктелу және сыртқы сұраныс жоқ, дұрыс/қате код, желіге шығу әрекеттері, шексіз цикл таймауты және бет қатпауы, жасырын кейіс ағып кетпеуі, CSP консоль қатесі жоқ, «Жіберу» өзгермеуі, worker/vendor тақырыптары, 390px.
- `e2e/security.spec.ts`: бет CSP-інде `worker-src 'self'` және сыртқы көз жоқ.
