# QazaqCode Platform: архитектура

## Мақсат және шекара

Мектептерге, колледждерге және IT академияларына арналған көп ұйымды (multi-tenant) бағдарламалауды оқыту платформасы.
**Бөлек коммерциялық өнім**: ашық «CS50 қазақша» сайтының (CC BY-NC-SA 4.0) контентін қамтымайды, қараңыз `NOTICE.md` және `scripts/check-licence.mjs`.

## Қабаттар

```
Браузер ── Next.js 15 (App Router, server components + server actions) ── PostgreSQL 16 (RLS)
                │                                                            ▲
                │  withUser(userId): begin; set local role authenticated;    │
                │  set_config('request.jwt.claims', {sub}); ... commit       │
                └──────── auth: AUTH_DRIVER=supabase | local (dev/test) ─────┘
```

- **Деректер қабаты - шешуші қауіпсіздік шекарасы.** Клиент рөлі (`authenticated`) кестелерді тек оқиды (RLS), барлық жазу `SECURITY DEFINER` RPC функциялары арқылы
  (`db/migrations/0002_functions.sql`). Әр функция құқықты өзі тексереді (рөл, меншік, лицензия, лимит). Қосымшаны бұзса да, SQL деңгейінде басқа ұйымның деректеріне қол жеткізілмейді.
- **Қосымша қабаты** (Next.js): рөл бойынша бағыттау, формалар, валидация (zod), қазақша қате хабарлары, rate limiting, қауіпсіздік тақырыптары. Қосымша құпия (service-role) кілтті қажет етпейді.
- **Аутентификация**: өндірісте Supabase Auth (GoTrue) - құпиясөз, e-mail растау, қалпына келтіру. `AUTH_DRIVER=local` тек әзірлеу/тест үшін (`db/dev/auth_shim.sql`), өндірісте іске қосылмайды (env тексерісі). Дерекқор `auth.uid()` арқылы кім екенін біледі, сондықтан RLS саясаттары Supabase-пен сәйкес.

## Рөлдер

| Рөл | Көреді | Істейді |
|---|---|---|
| SUPER ADMIN (`platform_admins`) | ұйымдар, лицензиялар, аудит, **тек жиынтық** пайдалану (`platform_usage()`) | ұйым тіркейді, лицензия/лимит/күй басқарады. **Оқушы жұмысы мен бағасын көрмейді.** |
| SCHOOL ADMIN | өз ұйымының барлығы (мүшелер, сыныптар, статистика, аудит) | мұғалім шақырады/өшіреді, брендинг, лицензия күйін көреді |
| TEACHER | өз сыныптары, тапсырмалары, оқушылардың жұмысы | сынып, тапсырма, баға |
| STUDENT | өз сыныбы, жарияланған тапсырмалары, өз жұмысы мен бағасы | код/жауап жазады, жібереді |

## Негізгі шешімдер

- **Ұйымдар оқшаулауы**: әр кестеде `org_id`; RLS саясаттары `is_org_member/is_org_admin/is_class_teacher/is_class_student` функцияларына сүйенеді; кросс-ұйым тесттері (`db/tests/security.test.mjs`) CI-да міндетті.
- **Жасырын жауаптар**: тест кілті (`assignment_answer_keys`) бөлек кестеде, оқушыға RLS-пен жабық; тест бағалауы серверде (`submit_assignment`). Жасырын тест жағдайлары (`is_hidden`) оқушыға көрінбейді.
- **Баға сенімділігі**: ресми баға тек сервер функцияларынан (`submit_assignment` автоматты тест үшін, `grade_submission` мұғалім үшін). Браузердегі JavaScript нәтижесі бағаға әсер етпейді.
- **Лицензия**: `licenses` (STARTER/PRO/ENTERPRISE, лимиттер, мерзім, күй). Мерзімі өтсе: жаңа сынып/тапсырма/шақыру/қосылу бұғатталады; оқу және экспорт сақталады; деректер өшірілмейді; оқушы бұрын берілген тапсырманы тапсыра алады. Ұйым «тоқтатылса» (suspended) тапсыру да тоқтайды.
- **Аудит**: `audit_logs` (лицензия, мүшелік, баға, ұйым, тапсырма, сынып өзгерістері); клиент жаза алмайды.
- **White-label**: `organization_settings` (логотип, 2 түс, қарсы алу мәтіні, байланыс); кіру беті `?org=<slug>`; панельде түстер CSS айнымалылары арқылы. Custom domain: `custom_domain` бағаны дайын, маршрутизация 4-кезеңде.
- **Демо режим**: `organizations.is_demo` + `scripts/seed-demo.mjs`; панельде үнемі «демонстрациялық дерек» ескертуі.

## Масштабтау және шектеулер

- Бір Next.js данасы + бір Postgres жүздеген мектепке жеткілікті; көп дана болса rate-limit жадтан Redis/WAF-ке көшуі тиіс.
- Аналитика SQL функциялары нақты деректен есептейді; ауыр есептер үшін кейін materialized view қосуға болады.
