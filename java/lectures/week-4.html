    4-апта

    Мұрагерлік, интерфейстер және полиморфизм

    Үшінші аптада бір класс жазуды үйрендік. Енді класстар бір-бірімен туыстық қатынасқа түседі: бірі екіншісінің қасиетін алады, бірнеше түрлі нысан бір ортақ «шартты» орындайды, ал бағдарлама олардың қайсысы екенін білмей-ақ дұрыс жұмыс істейді. Бүгін extends, super, абстракт класс, интерфейс және полиморфизмнің сыры ашылады.

    Неге мұрагерлік керек?

    Домбыра, қобыз және сыбызғы жайлы бағдарлама жазып жатқанымызды елестетіңіз. Үшеуінің де атауы бар, үшеуі де дыбыс шығарады, үшеуін де көрмеге қоюға болады. Егер әр аспапқа бөлек класс жазып, ataui өрісін, tanystyr() әдісін үш рет көшіре берсек, не болады? Бір жерде қате тапсақ, оны үш жерден түзетуге тура келеді, ал төртінші аспап қосылғанда тағы бір көшірме пайда болады. Бағдарламашылар бұны «көшіріп қою ауруы» деп атайды, одан құтылудың ең қарапайым жолы - ортақ нәрсені бір жерге жинау.

    Қазақ тілінде де осындай ойлау бар: «Түбі бір - түркі», «Әкеден бала туады, қасиет қалады». Нысандық бағдарламалауда да солай: ортақ қасиеттерді ата-класқа (superclass, parent class) жинаймыз, ал нақты түрлер оны мұра етіп алады (inheritance) және өзіне тән нәрсені ғана қосады. Мұра етіп алатын класты бала-класс (subclass, child class) дейді.

    Мұрагерліктің екі пайдасы бар:

    • Қайталауды азайтады. Ортақ код бір жерде тұрады және бір жерде түзетіледі.
    • Түрлерді біріктіреді. Домбыра да, қобыз да «аспап» болғандықтан, оларды бір тізімге салып, бірдей өңдеуге болады. Бұл екінші пайда - полиморфизм - бүгінгі лекцияның жүрегі.

    Лекцияның соңына қарай мына сұрақтарға өзіңіз жауап бере аласыз: super не үшін керек? Абстракт класс пен интерфейстің айырмашылығы неде? Aspap a = new Dombyra(); деген жолдың мағынасы қандай және a.dybys() қай класстың кодын орындайды?

    Атаулар туралы

    Кодтағы класс пен әдіс аттары латынша транслитпен (Dombyra, dybys, ojna) жазылған, ал экранға шығатын мәтін қазақша. Нақты жұмыс жобаларында атауларды ағылшынша беру қабылданған, бірақ оқу барысында қазақша мағына тез ұғылсын деп осылай жазамыз. Ережені есте ұстаңыз: класс аты бас әріптен (Dombyra), әдіс пен айнымалы кіші әріптен (ojna) басталады.

    extends және super

    Мұрагерлікті Java-да extends («кеңейтеді») кілт сөзімен жазады. Төмендегі кодта Aspap - жалпы ата-класс, ал Dombyra оны кеңейтеді. Кодты оқып, қандай нәрсе шығатынын алдын ала болжап көріңіз:

    class Aspap {
    String ataui;
    String tur;

    Aspap(String ataui, String tur) {
        this.ataui = ataui;
        this.tur = tur;
        System.out.println("Aspap конструкторы: " + ataui);
    }

    void tanystyr() {
        System.out.println(ataui + " - " + tur + " аспап");
    }
}

class Dombyra extends Aspap {
    int isekSany = 2;

    Dombyra() {
        super("Домбыра", "ішекті");
        System.out.println("Dombyra конструкторы: ішек саны = " + isekSany);
    }
}

public class Main {
    public static void main(String[] args) {
        Dombyra d = new Dombyra();
        d.tanystyr();
    }
}

    Мұнда үш маңызды жайт бар.

    Бірінші. Dombyra класында tanystyr() әдісі жазылмаған, бірақ d.tanystyr() жұмыс істеді. Себебі Dombyra әдісті Aspap-тан мұра етіп алды. ataui пен tur өрістері де сондай: оларды Dombyra нысаны өзінің ішінде алып жүреді. Екінші. super(...) жолы ата-класстың конструкторын шақырады. Нысан жасалғанда ол «қабат-қабат» құрылады: алдымен ата-класс бөлігі дайындалады, содан кейін бала-класс бөлігі. Сондықтан нәтижеде «Aspap конструкторы» жолы «Dombyra конструкторы» жолынан бұрын шықты. Үйді салғанда алдымен іргетас қаланатыны сияқты, ата-класстың бөлігі бала-класстың бөлігінен бұрын дайын болуы керек. Үшінші. super(...) бала-класс конструкторының ең бірінші жолы болуы шарт. Егер оны жазбасақ, Java өзі super(); (аргументсіз) деп қояды. Ал ата-класта аргументсіз конструктор болмаса (біздегідей Aspap(String, String) ғана бар), онда super(...) жазбау компиляция қатесіне әкеледі. Бұл туралы «Жиі қателер» бөлімінде тағы айтамыз.
    Java-да бір ғана ата-класс

    Java-да класс extends арқылы тек бір класты кеңейте алады. Екі ата-класстан бірдей мұра алуға болмайды (бұл «алмаз проблемасын» болдырмау үшін жасалған). Ал бірнеше интерфейсті жүзеге асыруға болады, оны төменде көреміз.

    Java-да кез келген класс, егер extends жазылмаса, үнсіз ғана Object класын кеңейтеді. Яғни бүкіл Java әлемі - бір үлкен «шежіре», оның түбірінде Object тұр. toString(), equals() және hashCode() сияқты әдістер барлық нысанда болатыны содан: олар Object-тан келеді. Бұған кейінірек оралып, өз toString() әдісімізді жазамыз.

    Әдісті қайта анықтау

    Бала-класс ата-класстан мұра болып келген әдіске көңілі толмауы мүмкін. Домбыра мен қобыз «дыбыс шығарады», бірақ екеуінің дыбысы әртүрлі. Бала-класс мұра болып келген әдістің өз нұсқасын жаза алады, оны қайта анықтау (method overriding) деп атайды.

    class Aspap {
    String ataui;

    Aspap(String ataui) {
        this.ataui = ataui;
    }

    void dybys() {
        System.out.println(ataui + ": қандай да бір дыбыс");
    }
}

class Dombyra extends Aspap {
    Dombyra() {
        super("Домбыра");
    }

    @Override
    void dybys() {
        System.out.println(ataui + ": тық-тық, күй шертіледі");
    }
}

class Qobyz extends Aspap {
    Qobyz() {
        super("Қобыз");
    }

    @Override
    void dybys() {
        super.dybys();
        System.out.println(ataui + ": ішек садақпен тартылады");
    }
}

public class Main {
    public static void main(String[] args) {
        new Aspap("Белгісіз").dybys();
        new Dombyra().dybys();
        new Qobyz().dybys();
    }
}

    super.әдіс() жазбасы «ата-класстың нұсқасын шақыр» дегенді білдіреді. Бұл үлгі өте жиі кездеседі: ата-класстың жұмысын қайталамай, оған «үстеме» қосу керек болғанда қолданамыз.

    Қайта анықтаудың үш шарты бар: әдістің аты, параметрлер тізімі және қайтару типі ата-класстағыдай болуы керек, ал қол жеткізу деңгейі ата-класстағыдан тарылмауы керек (мысалы, public әдісті private қылып қайта анықтауға болмайды).

    Жоғарыдағы кодта әр қайта анықталған әдістің алдында @Override деген белгі тұр. Бұл аннотация (annotation): компиляторға берілген ескерту. Мағынасы: «мен бұл әдісті ата-класстағы әдістің орнына жазып жатырмын, егер ондай әдіс жоқ болса, қате бер». Аты бір әріпке қателессе де, компилятор бірден ұстайды. @Override-ты ешқашан тастамаңыз: ол кейін көп сағат қателік іздеуден құтқарады. Мұны жаттығуларда өз көзіңізбен көресіз.

    Overload пен override - екі бөлек нәрсе

    Бірдей аты бар, бірақ параметрлері әртүрлі әдіс жазу - бұл overload (overloading, қайта жүктеу): жаңа әдіс пайда болады, ал ата-класстағы бұрынғысы сол күйінде қалады. Ал параметрлері бірдей әдісті бала-класста қайта жазу - override: ата-класстың әдісі ауысады. Екеуін шатастыру - бастаушылардың ең жиі жасайтын қателерінің бірі.

    protected және Object класы

    Бала-класс ата-класстың бәрін көре ме? Жоқ. Қол жеткізу деңгейі (access modifier) мұны шешеді:

    • private - тек сол класстың ішінде көрінеді. Бала-класс тікелей көре алмайды, бірақ ата-класстың public немесе protected әдістері арқылы қолдана алады.
    • protected - сол класс, бала-кластар және сол пакеттегі басқа кластар көреді.
    • public - барлығына ашық.
    • ештеңе жазылмаса (пакеттік деңгей) - тек сол пакеттің ішінде.
    class Aspap {
    protected String ataui;
    private int bagasy;

    Aspap(String ataui, int bagasy) {
        this.ataui = ataui;
        this.bagasy = bagasy;
    }

    int getBagasy() {
        return bagasy;
    }
}

class Dombyra extends Aspap {
    Dombyra(int bagasy) {
        super("Домбыра", bagasy);
    }

    void aqparat() {
        System.out.println(ataui);           // protected: көреміз
        // System.out.println(bagasy);       // private: қате болар еді
        System.out.println(getBagasy() + " теңге");
    }
}

public class Main {
    public static void main(String[] args) {
        new Dombyra(45000).aqparat();
    }
}

    bagasy өрісін private етіп, оған getBagasy() арқылы қол жеткіздік. Бұл инкапсуляцияны сақтайды: ата-класс өзінің ішкі құрылымын жасырып, тек қажетті есікті ашады. Тәжірибелі бағдарламашылар өрістерді әдетте private қылады, ал protected-ті сирек қолданады.

    Енді Object классына оралайық. Ол барлық класстың түбірі болғандықтан, әр нысанда үш маңызды әдіс бар. Оларды көбіне өз класымызға лайықтап қайта анықтаймыз:

    • toString() - нысанды мәтінге айналдырады. System.out.println(нысан) жазғанда Java осыны шақырады. Қайта анықтамасаңыз, Qala@1b6d3586 сияқты түсініксіз мәтін шығады.
    • equals(Object o) - екі нысан «мазмұны жағынан тең бе» деген сұраққа жауап береді. Ал == операторы нысандардың сілтемесін салыстырады, яғни олар жадтағы бір нысан ба деп сұрайды.
    • hashCode() - нысанды санға айналдырады; HashMap және HashSet үшін қажет (келесі аптада көреміз). Қағида: equals бойынша тең нысандардың hashCode() мәні де тең болуы керек.
    import java.util.Objects;

class Qala {
    private final String atau;
    private final int halyq;   // мың адам

    Qala(String atau, int halyq) {
        this.atau = atau;
        this.halyq = halyq;
    }

    @Override
    public String toString() {
        return atau + " (" + halyq + " мың)";
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Qala q)) return false;
        return atau.equals(q.atau);
    }

    @Override
    public int hashCode() {
        return Objects.hash(atau);
    }
}

public class Main {
    public static void main(String[] args) {
        Qala a = new Qala("Қарағанды", 500);
        Qala b = new Qala("Қарағанды", 501);
        Object c = new Object();
        System.out.println(a);                       // toString() автоматты шақырылады
        System.out.println(a == b);                  // сілтеме салыстырады
        System.out.println(a.equals(b));             // біздің equals
        System.out.println(a.hashCode() == b.hashCode());
        System.out.println(c.toString().startsWith("java.lang.Object@"));
    }
}

    Абстракт класс

    Кейде ата-класстың нақты нысанын жасаудың мәні жоқ. «Жай аспап» дегеніміз не? Нақты дыбыс шығаратын домбыра, қобыз бар, ал «жалпы аспап» - тек ұғым. Дәл осындай жағдайда абстракт класс (abstract class) қолданылады.

    Абстракт класс abstract сөзімен белгіленеді және оның нысанын new арқылы жасауға болмайды. Оның ішінде денесі жоқ абстракт әдіс болады: ол «бала-кластар осыны міндетті түрде жазсын» деген талап қана.

    abstract class Aspap {
    protected final String ataui;

    Aspap(String ataui) {
        this.ataui = ataui;
    }

    // абстракт әдіс: денесі жоқ, әр ұрпақ өзі жазады
    abstract String dybys();

    // жай әдіс: ортақ логика
    void ojna() {
        System.out.println(ataui + " ойналуда -> " + dybys());
    }
}

class Dombyra extends Aspap {
    Dombyra() { super("Домбыра"); }
    @Override String dybys() { return "тық-тық-тық"; }
}

class Sybyzgy extends Aspap {
    Sybyzgy() { super("Сыбызғы"); }
    @Override String dybys() { return "ыңылдаған жұмсақ үн"; }
}

public class Main {
    public static void main(String[] args) {
        Aspap a = new Dombyra();
        a.ojna();
        new Sybyzgy().ojna();
    }
}

    Мұнда ең тамаша нәрсе - ojna() әдісі. Ол Aspap ішінде бір рет жазылған, бірақ dybys() шақырғанда әр нақты аспаптың өз нұсқасы орындалады. Бұл үлгі шаблон әдіс (template method) деп аталады: жалпы жоспар ата-класта, ал нақты қадамдар ұрпақтарда.

    Абстракт класстың нысанын жасамақ болсақ, не болады? Жасап көрейік:

    abstract class Aspap {
    abstract String dybys();
}

public class Main {
    public static void main(String[] args) {
        Aspap a = new Aspap();
        System.out.println(a.dybys());
    }
}

    Абстракт класс қашан керек?

    Бала-кластардың ортақ күйі (өрістері) мен ортақ кодын бір жерде ұстағыңыз келсе, және кейбір әдісті нақты түрлер өзі жазуы керек болса, абстракт класс қолданыңыз. Мысалы, Aspap: оның ataui өрісі бар, ojna() ортақ, ал dybys() әркімде өзінше.

    Интерфейс

    Интерфейс (interface) - бұл «шарт», «келісімшарт». Ол «мына әдістерді орындай алатын болсаң, сен менің түрімсің» деп айтады. Интерфейс не істеу керегін сипаттайды, ал қалай істеуді класстардың өзіне қалдырады. Аналогия: теміржол вокзалындағы «жолаушы» ұғымын алыңыз. Кім екені маңызды емес, билеті барлығы жеткілікті. Билеті бар кез келген адам перронға кіре алады.

    Интерфейсті класс implements («жүзеге асырады») кілт сөзімен қабылдайды. Интерфейстің әдістері әдетте public және абстракт болады. Java 8-ден бері интерфейсте тағы екі түрлі әдіс жазуға болады:

    • default әдіс - денесі бар. Класс өзі қайта жазбаса, осы нұсқа жұмыс істейді.
    • static әдіс - интерфейстің өзіне тиесілі, нысансыз Интерфейс.әдіс() деп шақырылады.
    interface Baptalatyn {
    int MIN_TEMP = 1;                 // интерфейстегі өріс - автоматты түрде static final

    void baptau();                    // абстракт әдіс

    default void baptauHabary() {     // default әдіс: денесі бар
        System.out.println("Баптау басталды...");
        baptau();
        System.out.println("Баптау аяқталды.");
    }

    static boolean dausDuryspa(int herts) {   // static әдіс: интерфейстің өзіне тиесілі
        return herts >= 400 && herts <= 480;
    }
}

}

}

        Baptalatyn b = d;                 // интерфейс - тип ретінде

    }
}

    Полиморфизм

    Енді бәрін біріктіретін ұғымға келдік. Полиморфизм (polymorphism) грек тілінен «көп пішінділік» деген мағына береді. Қарапайым тілмен: ата-класстың айнымалысы кез келген бала-класстың нысанын ұстай алады, ал әдісті шақырғанда нақты нысанның нұсқасы орындалады.

    Аналогия: «Қонақтарды қарсы алыңдар!» деген бір ғана бұйрық берсеңіз, әр үй өз дәстүрімен қарсы алады: біреу шай құяды, біреу бесбармақ әзірлейді, біреу күй тартады. Бұйрық бір, орындалу әртүрлі.

    import java.util.ArrayList;
import java.util.List;

abstract class Aspap {
    final String ataui;
    Aspap(String ataui) { this.ataui = ataui; }
    abstract String dybys();
}

class Dombyra extends Aspap {
    Dombyra() { super("Домбыра"); }
    @Override String dybys() { return "тық-тық"; }
}

class Qobyz extends Aspap {
    Qobyz() { super("Қобыз"); }
    @Override String dybys() { return "ыңыл-ыңыл"; }
}

class Sybyzgy extends Aspap {
    Sybyzgy() { super("Сыбызғы"); }
    @Override String dybys() { return "сыбыз-сыбыз"; }
}

public class Main {
    static void tyndau(Aspap a) {
        System.out.println(a.ataui + " -> " + a.dybys());
    }

    public static void main(String[] args) {
        List<Aspap> orkestr = new ArrayList<>();
        orkestr.add(new Dombyra());
        orkestr.add(new Qobyz());
        orkestr.add(new Sybyzgy());

        for (Aspap a : orkestr) {
            tyndau(a);          // әр нысан өз dybys() әдісін орындайды
        }
        System.out.println("Аспап саны: " + orkestr.size());
    }
}

Қазір сіз Aspap-тан бесінші, оныншы аспапты мұра етіп қоссаңыз, tyndau әдісінің бір әрпін де өзгертпейсіз. Бағдарлама жаңа түрді «өзі қабылдайды». Міне, осы - полиморфизмнің күші, оны «ашық-жабық принципі» деп те атайды: кеңейтуге ашық, өзгертуге жабық.

    Мұнда екі кезең бар, оларды ажырата білу керек:

    1. Компиляция уақытында Java айнымалының жарияланған типін (Aspap) қарайды және тек сол типте бар әдістерді шақыруға рұқсат береді.
    2. Орындау уақытында JVM нысанның нақты типін (Dombyra) қарайды және сол класстың нұсқасын орындайды. Мұны динамикалық байланыс (dynamic dispatch) дейді.

    Сондықтан Aspap a = new Dombyra(); деген жолда a.perne сияқты тек Dombyra-да бар нәрсеге қол жеткізу мүмкін емес, өйткені компилятор a-ны жай Aspap деп біледі. Оған қол жеткізу үшін типті тексеру және түрлендіру қажет, бұл келесі бөлімнің тақырыбы.

    Ойланып көріңіз: өріс те полиморфты ма?

    Жоқ. Полиморфизм тек әдістерге қатысты. Өрістер айнымалының жарияланған типі бойынша таңдалады. Ата-класта да, бала-класта да бірдей аты бар өріс болса, Ата p = new Бала(); p.t ата-класстың өрісін береді, ал p.get() бала-класстың әдісін шақырады. Мұны тестте тексеріп көресіз. Сондықтан бала-класта ата-класстың өрісін «жасыру» жаман әдет: оны жасамаңыз.

    instanceof және үлгіні сәйкестендіру

    Бізде List<Aspap> бар делік. Оның ішіндегі аспаптың нақты түрін білу керек болса не істейміз? instanceof операторы нысанның белгілі типке жататынын тексереді. Java 16-дан бастап ол үлгіні сәйкестендіру (pattern matching for instanceof) мүмкіндігімен келеді: тексеріп қана қоймай, нәтижені бірден жаңа айнымалыға салады.

    import java.util.List;

abstract class Aspap {
    final String ataui;
    Aspap(String ataui) { this.ataui = ataui; }
}

class Dombyra extends Aspap {
    final int perne;
    Dombyra(int perne) { super("Домбыра"); this.perne = perne; }
}

class Qobyz extends Aspap {
    Qobyz() { super("Қобыз"); }
    String sadaq() { return "жылқы қылынан жасалған садақ"; }
}

class Sybyzgy extends Aspap {
    Sybyzgy() { super("Сыбызғы"); }
}

public class Main {
    static void sipattau(Aspap a) {
        if (a instanceof Dombyra d) {
            System.out.println(d.ataui + ": " + d.perne + " перне");
        } else if (a instanceof Qobyz q) {
            System.out.println(q.ataui + ": " + q.sadaq());
        } else {
            System.out.println(a.ataui + ": басқа аспап");
        }
    }

    public static void main(String[] args) {
        List<Aspap> tizim = List.of(new Dombyra(18), new Qobyz(), new Sybyzgy());
        for (Aspap a : tizim) {
            sipattau(a);
        }
        Object o = "Алматы";
        if (o instanceof String s && s.length() > 3) {
            System.out.println(s.toUpperCase() + " (" + s.length() + " әріп)");
        }
    }
}

    instanceof-ты көп қолданбаңыз

    Егер кодыңызда instanceof-тар тізбегі ұзарып бара жатса, бұл жақсы белгі емес. Көбіне осыдан құтылудың жолы - әр түр өзінің мінез-құлқын өз ішінде атқаруы (яғни әдісті ата-класқа шығарып, полиморфизмді қолдану). instanceof нақты түр ерекше өңдеуді қажет еткен жағдайда ғана қолайлы, мысалы, equals ішінде не sealed иерархияларда.

    «is-a» және «has-a»

    Мұрагерлікті шамадан тыс қолданып жіберу - жаңа бағдарламашылардың классикалық қателігі. «Бұл класс бұл кластың кеңейтілген нұсқасы ма?» деген сұрақты өзіңізге қойыңыз. Қарапайым тест бар:

    • is-a («...болып табылады»): «Домбыра - аспап» - рас. Демек Dombyra extends Aspap дұрыс.
    • has-a («...бар»): «Киіз үйдің шаңырағы бар» - рас, бірақ «Киіз үй - шаңырақ» деген дұрыс емес. Демек KiizUy класында Shanyrak типті өріс болады, мұрагерлік емес.

    Диаграммада сол жақта мұрагерлік (бос үшбұрышты көрсеткі Aspap-қа қарай), оң жақта құрама (composition) көрсетілген: KiizUy өзінің ішінде Shanyrak пен Kerege[] нысандарын ұстайды. Мұны мәтінмен айтқанда: «Домбыра - аспаптың бір түрі», ал «Киіз үйдің құрамында шаңырақ пен кереге бар».

    class Shanyrak {
    final int uyq;
    Shanyrak(int uyq) { this.uyq = uyq; }
}

class Kerege {
    final int kanat;
    Kerege(int kanat) { this.kanat = kanat; }
}

// Киіз үй - шаңырақ ПЕН керегеден тұрады (has-a), олардың "түрі" емес
class KiizUy {
    private final Shanyrak shanyrak;
    private final Kerege[] kereger;

    KiizUy(int kanatSany, int uyqSany) {
        this.shanyrak = new Shanyrak(uyqSany);
        this.kereger = new Kerege[kanatSany];
        for (int i = 0; i < kanatSany; i++) {
            kereger[i] = new Kerege(i + 1);
        }
    }

    void sipattau() {
        System.out.println("Киіз үй: " + kereger.length + " қанат, шаңырақта " + shanyrak.uyq + " уық");
    }
}

public class Main {
    public static void main(String[] args) {
        new KiizUy(6, 60).sipattau();
    }
}

    Құрама мұрагерліктен гөрі икемді. Мысалы, егер Avtobus extends Dvigatel деп жазсақ, автобус «қозғалтқыштың бір түрі» болып шығады, бұл мағынасыз. Дұрысы - Avtobus ішінде Dvigatel dvigatel өрісі болу. Сонда қозғалтқышты ауыстыру да оңай, бұл автобустың «кім» екенін бұзбайды. Тәжірибелі бағдарламашылардың мақалы бар: «Мұрагерліктен гөрі құраманы жөн көр» (favor composition over inheritance).

    Енді жоғарыда сөз болған түрлердің бәрін бір картаға жинайық. Төмендегі диаграммада Aspap абстракт класы, оның үш ұрпағы және екеуі жүзеге асыратын Baptalatyn интерфейсі көрсетілген:

    Мәтіндік балама: жоғарыда Aspap (абстракт, ataui, dybys(), ojna()), одан төменде Sybyzgy, Dombyra, Qobyz кластары extends арқылы байланысқан. Одан да төмен Baptalatyn интерфейсі (baptau(), baptauHabary()), оны тек Dombyra мен Qobyz жүзеге асырады, үзік сызықпен көрсетілген.

    Enum: тұрақты мәндер жиыны

    Кейде айнымалы бірнеше нақты мәннің бірін ғана қабылдай алады: апта күні, жыл мезгілі, бағдарлама күйі. Оны int (1, 2, 3) немесе String арқылы белгілесек, қателесу оңай: бағдарламашы 5 деп жазады, бірақ ол не екенін ешкім білмейді. Мұндай жағдайда enum (enumeration, санау типі) қолданылады.

    Java-дағы enum - тек атау тізімі емес, ол шын мәнінде ерекше класс. Оның өрісі, конструкторы және әдісі болады. Ал мәндер - сол класстың алдын ала жасалып қойған бірегей нысандары.

    enum Juz {
    ULY("Ұлы жүз", "Оңтүстік және Оңтүстік-Шығыс"),
    ORTA("Орта жүз", "Орталық, Солтүстік және Шығыс"),
    KISHI("Кіші жүз", "Батыс");

    private final String atau;
    private final String aimaq;

    Juz(String atau, String aimaq) {
        this.atau = atau;
        this.aimaq = aimaq;
    }

    String qysqa() {
        return atau + " (" + aimaq + ")";
    }
}

enum Mezgil { KOKTEM, JAZ, KUZ, QYS }

public class Main {
    static String kiim(Mezgil m) {
        return switch (m) {
            case KOKTEM -> "жеңіл күртеше";
            case JAZ -> "көйлек пен тақия";
            case KUZ -> "плащ";
            case QYS -> "тон мен бөрік";
        };
    }

    public static void main(String[] args) {
        for (Juz j : Juz.values()) {
            System.out.println(j.ordinal() + ". " + j + " -> " + j.qysqa());
        }

    Sealed класстарға қысқа шолу

    Мұрагерліктің бір кемшілігі: кез келген адам сіздің класыңыздан мұра алып кете алады. Кейде иерархияның тұйық болғанын қалаймыз: «Бұл фигураның түрі үшеу ғана, одан өзге болмайды». Java 17-де мұны sealed («мөрленген») класстар мен интерфейстер шешеді. permits сөзімен рұқсат етілген ұрпақтар тізіледі.

    Мысалға бірге record те қолданып көрейік. record (Java 16) - деректерді сақтайтын қысқа класс: компилятор конструктор, toString(), equals(), hashCode() және оқу әдістерін (radius() сияқты) автоматты жасап береді.

    sealed interface Tulga permits Shanyrak, Tortburysh, Ushburysh {}

record Shanyrak(double radius) implements Tulga {}
record Tortburysh(double a, double b) implements Tulga {}
record Ushburysh(double negiz, double biiktik) implements Tulga {}

public class Main {
    static double audan(Tulga t) {
        if (t instanceof Shanyrak s) {
            return Math.PI * s.radius() * s.radius();
        } else if (t instanceof Tortburysh q) {
            return q.a() * q.b();
        } else if (t instanceof Ushburysh u) {
            return 0.5 * u.negiz() * u.biiktik();
        }
        throw new IllegalStateException("мүмкін емес");
    }

    public static void main(String[] args) {
        Tulga[] tulgalar = { new Shanyrak(1.5), new Tortburysh(4, 3), new Ushburysh(6, 5) };
        for (Tulga t : tulgalar) {
            System.out.printf("%s -> %.2f%n", t, audan(t));
        }
    }
}

    Java 17 мен 21

    Java 21-де switch пен sealed біріге алады: switch (t) { case Shanyrak s -> ... } және компилятор барлық түрді қамтуды өзі тексереді. Бірақ бұл мүмкіндік Java 17-де әлі превью күйінде, сондықтан курста тек instanceof пен if қолдандық. Негізгі идея бірдей: тұйық иерархия.

    Жиі қателер

    1. super(...) тастау немесе ата-класта аргументсіз конструктор болмауы

    Aspap(String ataui, String tur) бар, ал Dombyra конструкторында super("Домбыра", "ішекті") жазылмаса, компилятор constructor Aspap in class Aspap cannot be applied to given types деген қате береді. Шешімі: super(...) жолын бірінші жолға жазыңыз.

    2. @Override-ты ұмыту және аты/параметрін қате жазу

    dybys(int k) деп жазсаңыз, бұл override емес, overload. Бағдарлама іске қосылады, бірақ ата-класстың нұсқасы орындалады. @Override қойсаңыз, компилятор қателікті бірден көрсетеді.

    3. Интерфейс әдісін public етпеу

    Интерфейстің әдістері әрқашан public. Оны жүзеге асырған кезде public жазбасаңыз, attempting to assign weaker access privileges; was public қатесі шығады (тесттегі 4-сұрақты қараңыз).

    4. Абстракт класты new арқылы жасау

    new Aspap() жазсаңыз, Aspap is abstract; cannot be instantiated. Нақты ұрпақты жасаңыз (new Dombyra()), ал ата-класты тек айнымалы типі ретінде қолданыңыз.

    5. Мұрагерлікті is-a сынақсыз қолдану

    «Автобус - қозғалтқыш» емес, «автобустың қозғалтқышы бар». Егер «A - B-ның бір түрі» деген сөйлем мағынасыз шықса, мұрагерлік емес, құраманы (өріс) қолданыңыз.

    6. Нысандарды == арқылы салыстыру

    Жолдар мен нысандардың мазмұнын equals арқылы салыстырыңыз. == тек екі айнымалы жадтағы бір нысанға сілтеме жасайтынын тексереді.

    Қорытынды

    Бүгін біз нысандық бағдарламалаудың төрт тірегінің екеуін (мұрагерлік пен полиморфизм) терең қарастырдық. Оқығанымызды жинақтайық:

    • extends - бала-класс ата-класстың өріс пен әдісін мұра етеді; super(...) ата-класстың конструкторын шақырады және ең бірінші жол болуы керек;
    • @Override - мұра болып келген әдісті қайта анықтау; super.әдіс() ата-класстың нұсқасын шақырады;
    • abstract класс нысан бола алмайды, оның абстракт әдісін ұрпақтар жазады;
    • interface - «қабілет» шарты; класс бірнеше интерфейсті implements ете алады; default пен static әдістер Java 8-ден бар;
    • полиморфизм - ата-класс/интерфейс типті айнымалы әртүрлі нысанды ұстайды, әдіс нақты нысанның нұсқасымен орындалады (динамикалық байланыс);
    • instanceof үлгісі (a instanceof Dombyra d) типті тексеріп, түрлендіруді бірге жасайды;
    • is-a болса мұрагерлік, has-a болса құрама; «мұрагерліктен гөрі құраманы жөн көр»;
    • enum - тұрақты мәндер жиыны, өрісі мен әдісі бар ерекше класс;
    • sealed мен record - тұйық иерархия мен қысқа деректер класы (Java 17).

    Өзіңізді тексеру тізімі:

    • Мен extends пен super(...) қалай жұмыс істейтінін түсіндіре аламын.
    • Мен override мен overload айырмашылығын білемін және @Override қоямын.
    • Мен абстракт класс пен интерфейсті қашан таңдау керегін айта аламын.
    • Мен Aspap a = new Dombyra(); жолындағы статикалық және нақты типті ажыратамын.
    • Мен instanceof үлгісін қолданып, тізімдегі нысанның түрін тексере аламын.
    • Мен is-a мен has-a сынағын өз мысалымда қолдана аламын.
    • Мен өз enum және record жаза аламын.

    Келесі аптада бір нысанды емес, көптеген нысанды қалай сақтап, іздеп, сұрыптайтынымызды көреміз: Collections және generics.

    Жаттығулар

    Жаттығулар қиындық бойынша үш деңгейде: оңай, орташа және қиын. Әр тапсырманың «Кеңес» және «Шешімі» бөлімдері бар, бірақ алдымен өзіңіз жазып көріңіз. Дайын шешімдер компилятормен тексерілген.

    Оңай

    Конструкторлар тәртібі

    Мына үш класс берілген. new C(); жолы орындалғанда әріптер қандай ретпен шығады? Жауабыңызды әріптерді бос орынмен бөліп жазыңыз (мысалы, X Y Z).

    class A { A() { System.out.println("A"); } }
class B extends A { B() { System.out.println("B"); } }
class C extends B { C() { System.out.println("C"); } }
    Кеңес

    Бала-класс конструкторының бірінші жолы үнсіз super(); болады. Ең ұзақ тізбектің ең басына қарай жүріп көріңіз: C шақырады B-ны, B шақырады A-ны, ал A бірінші болып өз денесін орындайды.

    Шешімі

    Конструкторлар «жоғарыдан төмен», яғни ата-класстан бастап орындалады. Тексеру:

    class A { A() { System.out.println("A"); } }
class B extends A { B() { System.out.println("B"); } }
class C extends B { C() { System.out.println("C"); } }

public class Main {
    public static void main(String[] args) {
        new C();
    }
}

    default әдіс пен override

    Мына бағдарлама бір жолға не шығарады? Жауабыңызды дәл шыққандай, бос орынсыз жазыңыз.

    interface Salem {

    Көлік иерархиясы

    Kolik абстракт класын жазыңыз: жеке өрісі nomer (мемлекеттік нөмір), абстракт әдісі int jolaqy(int km), ал жай әдісі shot(int km) нөмірді, қашықтықты және жол ақысын шығарады. Екі ұрпағын жазыңыз: Avtobus (әр километрге 90 теңге) және Taksi (500 теңге отыру ақысы және әр километрге 150 теңге). main-де екеуін де Kolik[] массивіне салып, 10 км үшін есепті шығарыңыз.

    Кеңес

    Kolik ішінде nomer өрісі private final болсын, ал оны ұрпақтар super(nomer) арқылы береді. shot әдісінде тек jolaqy(km) шақырыңыз, оның қалай есептелетінін білудің қажеті жоқ: бұл полиморфизм.

    Шешімі
    abstract class Kolik {
    private final String nomer;

    Kolik(String nomer) { this.nomer = nomer; }

    String getNomer() { return nomer; }

    // жол ақысы (теңге) - әр көлік өзінше есептейді
    abstract int jolaqy(int km);

    void shot(int km) {
        System.out.println(nomer + ": " + km + " км -> " + jolaqy(km) + " теңге");
    }
}

class Avtobus extends Kolik {
    Avtobus(String nomer) { super(nomer); }

    @Override
    int jolaqy(int km) { return 90 * km; }
}

class Taksi extends Kolik {
    Taksi(String nomer) { super(nomer); }

    @Override
    int jolaqy(int km) { return 500 + 150 * km; }
}

public class Main {
    public static void main(String[] args) {
        Kolik[] kolikter = { new Avtobus("A 123 KZ"), new Taksi("B 777 AB") };
        for (Kolik k : kolikter) {
            k.shot(10);
        }
    }
}
    $ javac Main.java && java Main
A 123 KZ: 10 км -> 900 теңге
B 777 AB: 10 км -> 2000 теңге
    Өзіңізді тексеріңіз
    • Kolik абстракт және нысаны new арқылы жасалмайды.
    • Avtobus пен Taksi jolaqy-ды @Override арқылы жазған.
    • main-де Kolik[] массиві бар, shot әр элемент үшін шақырылады.
    • Нәтиже: автобус 900 теңге, такси 2000 теңге.

    Орташа

    override па, overload па?

    Мына бағдарламада a.dybys() не шығарады? Бір сөзбен жазыңыз.

    class Aspap {
    String dybys() { return "жалпы"; }
}
class Dombyra extends Aspap {
    String dybys(int k) { return "тық".repeat(k); }
}
// main ішінде:
Aspap a = new Dombyra();
System.out.println(a.dybys());
    Кеңес

    Dombyra.dybys(int) параметрі бар әдіс, ал a.dybys() параметрсіз шақырылады. Бұл әдіс ата-класстағы dybys() әдісін ауыстыра ма, әлде жаңа әдіс пе? @Override қойып көрсеңіз, компилятор не дер еді?

    Шешімі

    dybys(int) мен dybys() - әртүрлі әдістер (overload), сондықтан override болған жоқ. a.dybys() Aspap-тың нұсқасын шақырады. @Override қойсақ, компилятор method does not override or implement a method from a supertype деп қате берер еді. Екінші нұсқаны шақыру үшін типті түрлендіру керек:

    class Aspap {
    String dybys() { return "жалпы"; }
}

class Dombyra extends Aspap {
    String dybys(int k) { return "тық".repeat(k); }
}

public class Main {
    public static void main(String[] args) {
        Aspap a = new Dombyra();
        System.out.println(a.dybys());
        System.out.println(((Dombyra) a).dybys(2));
    }
}
    $ javac Main.java && java Main
жалпы

    Фигуралар жиынтығы

    Мына фигуралар тізімінің жалпы ауданын (2 ондық таңбаға дейін дөңгелектеп) табыңыз. Tulga интерфейсін, Shanyrak, Tortburysh, Ushburysh record-тарын лекциядағыдай жазып, audan әдісін қолданыңыз. Тізім: Shanyrak(2), Tortburysh(5, 2), Ushburysh(10, 3). Жауап - санның өзі (нүктемен).

    Кеңес

    Шаңырақ (дөңгелек) ауданы: π·r². Төртбұрыш: a·b. Үшбұрыш: 0,5·негіз·биіктік. Үш санды қосыңыз: ≈12,57 + 10 + 15. Нәтижені printf("%.2f%n", jiny) арқылы шығарыңыз.

    Шешімі
    import java.util.List;

sealed interface Tulga permits Shanyrak, Tortburysh, Ushburysh {}
record Shanyrak(double radius) implements Tulga {}
record Tortburysh(double a, double b) implements Tulga {}
record Ushburysh(double negiz, double biiktik) implements Tulga {}

public class Main {
    static double audan(Tulga t) {
        if (t instanceof Shanyrak s) return Math.PI * s.radius() * s.radius();
        if (t instanceof Tortburysh q) return q.a() * q.b();
        if (t instanceof Ushburysh u) return 0.5 * u.negiz() * u.biiktik();
        throw new IllegalStateException();
    }

    public static void main(String[] args) {
        List<Tulga> tizim = List.of(new Shanyrak(2), new Tortburysh(5, 2), new Ushburysh(10, 3));
        double jiny = 0;
        for (Tulga t : tizim) jiny += audan(t);
        System.out.printf("%.2f%n", jiny);
    }
}
    $ javac Main.java && java Main
37.57

    Мектеп кітапханасы

    Кітапхана қорын модельдеңіз. Qaitarylatyn интерфейсі: int berilgenKun() және default әдіс keshikkenAiyppul(int otkenKun) (әр артық күнге 20 теңге; артық күн жоқ болса 0). Абстракт Material класы (atau өрісі, toString әдісі). Екі ұрпақ: Kitap (автор өрісі бар, 14 күнге беріледі) және Gazet (3 күнге беріледі). main-де екі материал үшін 10 күннен кейінгі айыппұлды шығарыңыз.

    Кеңес

    Material өзі Qaitarylatyn интерфейсін жүзеге асырсын, бірақ berilgenKun() әдісін жазбасын (абстракт болып қалады). Оны Kitap пен Gazet жазады. toString-де getClass().getSimpleName() класс атын береді, ал Kitap өз toString ішінде super.toString() шақырып, авторды қосады.

    Шешімі
    interface Qaitarylatyn {
    int berilgenKun();

    default int keshikkenAiyppul(int otkenKun) {
        int artyq = otkenKun - berilgenKun();
        return artyq > 0 ? artyq * 20 : 0;     // әр артық күн - 20 теңге
    }
}

abstract class Material implements Qaitarylatyn {
    protected final String atau;
    Material(String atau) { this.atau = atau; }

    @Override
    public String toString() { return getClass().getSimpleName() + " «" + atau + "»"; }
}

class Kitap extends Material {
    private final String avtor;
    Kitap(String atau, String avtor) { super(atau); this.avtor = avtor; }

    @Override public int berilgenKun() { return 14; }
    @Override public String toString() { return super.toString() + ", " + avtor; }
}

class Gazet extends Material {
    Gazet(String atau) { super(atau); }
    @Override public int berilgenKun() { return 3; }
}

public class Main {
    public static void main(String[] args) {
        Material[] tizim = {
            new Kitap("Абай жолы", "М. Әуезов"),
            new Gazet("Егемен Қазақстан")
        };
        for (Material m : tizim) {
            System.out.println(m + " | мерзімі: " + m.berilgenKun() + " күн | 10 күннен кейін айыппұл: " + m.keshikkenAiyppul(10) + " теңге");
        }
    }
}
    $ javac Main.java && java Main
Kitap «Абай жолы», М. Әуезов | мерзімі: 14 күн | 10 күннен кейін айыппұл: 0 теңге
Gazet «Егемен Қазақстан» | мерзімі: 3 күн | 10 күннен кейін айыппұл: 140 теңге
    Өзіңізді тексеріңіз
    • Qaitarylatyn интерфейсінде default әдіс бар.
    • Material абстракт, berilgenKun() әдісін ұрпақтар жазады.
    • Kitap үшін айыппұл 0 теңге, Gazet үшін 140 теңге шықты (10 - 3 = 7 күн × 20).
    • Kitap.toString() ішінде super.toString() қолданылған.
