    6-апта

    Ерекше жағдайлар, файлдар, lambda және Stream

    Нағыз бағдарлама тек жақсы күнде жұмыс істемейді: файл табылмайды, қолданушы сан орнына әріп жазады, желі үзіледі. Бұл аптада қателермен сыпайы жұмыс істеуді (try/catch), файлға жазуды және оқуды, сондай-ақ lambda мен Stream арқылы деректерді бірнеше жолмен өңдеуді үйренеміз.

    Бағдарлама қателескенде не болады?

    Қалаға автобуспен бара жатқаныңызды елестетіңіз. Жолда доңғалақ жарылса, үш жағдай болуы мүмкін: жүргізуші жөндеп, жолды жалғастырады; не қосалқы доңғалақ салады; не жағдай өте ауыр болса, жолаушыларға хабарлап, рейсті тоқтатады. Бағдарламада да солай. Қателіктің бәрін алдын ала болжап болмайды: файл жоқ болып шығады, қолданушы жасына «жиырма» деп жазады, нөлге бөлу болады. Мәселе - қате болмау емес, қате болғанда бағдарламаның қалай әрекет ететіні.

    Java-да мұндай жағдайлар ерекше жағдай (exception) деп аталады. Ерекше жағдай - бұл нысан: онда қатенің түрі, хабарламасы және оның қай жерде болғаны жазылған. Бағдарлама қателескенде Java осындай нысанды «лақтырады» (throw). Біреу оны «ұстамаса» (catch), бағдарлама тоқтап қалады.

    Бұл аптаның екінші жартысы мүлде басқа тақырыпқа арналған, бірақ бір ойға біріккен: бағдарламаны қысқа, анық және сенімді жазу. Мұнда lambda өрнектері мен Stream API - деректерді «қалай істеу» емес, «не істеу» деп сипаттаудың заманауи тәсілі. Мысалы, «85-тен жоғары балл алғандардың аттарын шығар» дегенді цикл мен шарттарсыз бір құбырмен айтуға болады.

    Жоспар былай:

    1. Қате қалай көрінеді және try/catch/finally не істейді.
    2. Checked және unchecked қателер, өз ерекше жағдайымызды жасау.
    3. try-with-resources және файлмен жұмыс (Files, Path).
    4. Lambda, функционалды интерфейстер.
    5. Stream және Optional.

    Қате қалай көрінеді

    Алдымен бағдарлама қатені ұстамаса, не болатынын көрейік. Әдейі нөлге бөлеміз:

    public class Main {
    static int bol(int a, int b) {
        return a / b;
    }

    public static void main(String[] args) {
        System.out.println("Бастау");
        System.out.println(bol(10, 2));
        System.out.println(bol(10, 0));
        System.out.println("Бұл жол орындалмайды");
    }
}

    Қатені оқуды үйреніңіз

    Жаңа бастаған адамдар қызыл жазуды көргенде оқымай-ақ шошып кетеді. Ал жақсы бағдарламашылар алдымен үш нәрсені оқиды: қатенің атын, хабарламасын және өз кодыңыздың жол нөмірін. Көп қателік тек осымен-ақ шешіледі.

    try, catch және finally

    Қатені ұстап, бағдарламаны жалғастыру үшін try («байқап көр»), catch («ұста») және finally («әрқашан орында») блоктарын қолданамыз:

    public class Main {
    static void oqy(String matin) {
        try {
            int n = Integer.parseInt(matin);
            System.out.println("Сан: " + n + ", екі еселенгені: " + n * 2);
        } catch (NumberFormatException e) {
            System.out.println("Бұл сан емес: \"" + matin + "\"");
        } finally {
            System.out.println("-- " + matin + " тексерілді");
        }
    }

    public static void main(String[] args) {
        oqy("25");
        oqy("жиырма");

        try {
            String s = null;
            System.out.println(s.length());
        } catch (NullPointerException | ArrayIndexOutOfBoundsException e) {
            System.out.println("Ұсталды: " + e.getClass().getSimpleName());
        }

        try {
            int[] bal = {5, 4, 3};
            System.out.println(bal[3]);
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Массив қатесі: " + e.getMessage());
        } catch (RuntimeException e) {
            System.out.println("Басқа қате");
        }
    }
}

    Қадамдап түсінейік:

    • try { ... } ішіне қате беруі мүмкін код жазамыз. Қате болмаса, catch өткізіп жіберіледі.
    • catch (NumberFormatException e) - тек осы түрдегі (және оның ұрпақтарындағы) қатені ұстайды. e - ерекше жағдай нысаны: e.getMessage() хабарламаны, e.getClass().getSimpleName() түрін береді.
    • finally блогы қате болса да, болмаса да орындалады. Мысалы, нәтижеде 25 үшін де, жиырма үшін де «тексерілді» жолы шықты. Ресурсты (файлды, желі байланысын) жабу сияқты «әрқашан істелетін» жұмыстар үшін қолайлы.
    • Бірнеше catch жазуға болады: Java оларды жоғарыдан төмен тексереді де, біріншісіне сәйкес келгенін орындайды. Сондықтан нақты түрлер жоғарыда, жалпы түрлер (мысалы, Exception) төменде тұруы керек. Керісінше жазсаңыз, компилятор «бұл қате бұрын ұсталған» деп ескертеді (тесттегі 4-сұрақты қараңыз).
    • catch (A | B e) - бір әрекет жасайтын бірнеше түрді біріктіру.

    Соңғы екі блоктағы null.length() пен массив шегінен шығу - Java-дағы ең танымал екі қате: NullPointerException («бос» нысанға қол жеткізу) және ArrayIndexOutOfBoundsException (индекс шектен тыс).

    Бос catch жазбаңыз

    catch (Exception e) { } - қатені үнсіз жұтып қояды. Бағдарлама жұмыс істеп тұрғандай көрінеді, бірақ дұрыс емес нәтиже береді, ал себебін таппайсыз. Ең болмағанда хабарламаны шығарыңыз не қатені әрі қарай лақтырыңыз. Және жалпы Exception не Throwable ұстамаңыз: тек нақты күткен түрді ұстаңыз.

    Checked және unchecked қателер

    Java ерекше жағдайларды екіге бөледі, бұл ең маңызды ұғымдардың бірі.

    • Checked (checked exception, «тексерілетін») - компилятор өңдеуді талап етеді. Әдетте бұл бағдарламадан тыс себептен болатын қателер: файл жоқ, желі үзілді. Мысалы, IOException. Оны не try/catch ұстау керек, не әдіс қолтаңбасында throws арқылы «мен мұны өңдемеймін, шақырушы өңдесін» деп жариялау керек.
    • Unchecked (unchecked exception, «тексерілмейтін») - RuntimeException ұрпақтары. Мысалы, NullPointerException, ArithmeticException, IllegalArgumentException. Бұл - көбіне бағдарламашының өз қатесі, сондықтан компилятор өңдеуді талап етпейді. Қатені өңдеудің орнына кодты түзету керек.
    • Error - OutOfMemoryError сияқты ауыр қателер, оларды ұстау мағынасыз.

    Бәрі бір Throwable ағашына жинақталған:

    Мәтіндік балама: жоғарыда Throwable, одан Exception (checked) және Error (unchecked) тарайды. Exception-нан IOException (оның ұрпақтары FileNotFoundException, NoSuchFileException) және RuntimeException (оның ұрпақтары NullPointerException, ArithmeticException, IllegalArgumentException және оның ұрпағы NumberFormatException) шығады. Error астында OutOfMemoryError және StackOverflowError бар.

    Мысалмен көрейік. Файл оқу checked қатеге әкеледі, ал дұрыс емес аргумент unchecked қате болады:

    import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.NoSuchFileException;
import java.nio.file.Path;
import java.util.List;

public class Main {
    // checked exception: әдіс қолтаңбасында "throws" жазуы МІНДЕТТІ
    static List<String> oqy(String jol) throws IOException {
        return Files.readAllLines(Path.of(jol));
    }

    static void tekser(int bal) {
        if (bal < 0 || bal > 100) {
            // unchecked exception: throws жазу міндетті емес
            throw new IllegalArgumentException("Бал 0..100 аралығында болуы керек: " + bal);
        }
        System.out.println("Бал қабылданды: " + bal);
    }

    public static void main(String[] args) {
        try {
            List<String> joldar = oqy("жоқ-файл.txt");
            System.out.println(joldar.size());
        } catch (NoSuchFileException e) {
            System.out.println("Файл табылмады: " + e.getMessage());
        } catch (IOException e) {
            System.out.println("Басқа I/O қатесі");
        }

        tekser(85);
        try {
            tekser(120);
        } catch (IllegalArgumentException e) {
            System.out.println("Қате: " + e.getMessage());
        }
    }
}

    • oqy әдісінің қолтаңбасындағы throws IOException - «мен қате лақтыруым мүмкін» деген ескерту. Шақыратын main оны ұстауға міндетті. Ұстамаса, компиляция қатесі шығады: unreported exception IOException; must be caught or declared to be thrown.
    • catch (NoSuchFileException e) - нақтырақ түр. Ол IOException-нің ұрпағы, сондықтан алдымен жазылды; жалпы IOException одан кейін тұр.
    • tekser ішінде throw new IllegalArgumentException(...) қолмен лақтыру. Мұнда throws жазу міндетті емес, себебі қате unchecked.

    Есіңізде болсын: throw пен throws - екі бөлек сөз. throw - әрекет: нақты қате нысанын лақтыру (throw new IllegalArgumentException("...")). throws - жариялау: әдіс қолтаңбасына жазылып, «бұл әдіс мынадай қате лақтыруы мүмкін» деп шақырушыға ескертеді. Біріншісі әдіс ішінде, екіншісі әдіс атының жанында тұрады.

    Ереже: checked қатені әдіс шақырушының қолынан келетін жағдайда (файл таңдау, қайталап көру) қолданыңыз, ал бағдарламашының қатесі (дұрыс емес аргумент) үшін unchecked лақтырыңыз.

    Өз ерекше жағдайымызды жазу

    Кейде Java-ның дайын қателері жеткіліксіз: «бал 0..100 аралығынан шықты» деген жағдайға арнайы атау беру керек. Ол үшін Exception (checked) не RuntimeException (unchecked) класын кеңейтеміз. Тақырыпты төртінші аптадағы мұрагерліктен білесіз:

    // өз checked exception классы
class BalQateligi extends Exception {
    private final int bal;

    BalQateligi(String habar, int bal) {
        super(habar);
        this.bal = bal;
    }

    int getBal() { return bal; }
}

// өз unchecked exception классы
class OqushyTabylmady extends RuntimeException {
    OqushyTabylmady(String aty) {
        super("Оқушы табылмады: " + aty);
    }
}

public class Main {
    static void bal(String aty, int bal) throws BalQateligi {
        if (bal < 0 || bal > 100) {
            throw new BalQateligi(aty + " үшін бал дұрыс емес", bal);
        }
        System.out.println(aty + ": " + bal);
    }

    static void izde(String aty) {
        if (!aty.equals("Дана")) {
            throw new OqushyTabylmady(aty);
        }
        System.out.println("Табылды: " + aty);
    }

    public static void main(String[] args) {
        try {
            bal("Дана", 95);
            bal("Ерлан", 150);
            bal("Сая", 80);              // орындалмайды
        } catch (BalQateligi e) {
            System.out.println(e.getMessage() + " (" + e.getBal() + ")");
        }

        izde("Дана");
        try {
            izde("Асхат");
        } catch (OqushyTabylmady e) {
            System.out.println(e.getMessage());
        }
    }
}

    Тағы бір пайдалы нәрсе: қатені басқа қатеге орап лақтыруға болады (exception chaining). Конструкторда super(habar, sebep) жазсақ, түпкі себеп сақталады. Мұны 3-жаттығуда жасайсыз.

    try-with-resources

    Файл, желі байланысы, дерекқор қосылымы сияқты нәрселерді ресурс дейді. Ресурсты ашқан соң міндетті түрде жабу керек: әйтпесе жад пен жүйе ресурстары таусылады. Ескі тәсілде бұл finally ішінде жасалатын еді, код ұзын әрі қате жіберуге бейім болатын. Java 7-ден бері try-with-resources бар: try (...) жақшасына ашылатын ресурсты жазамыз, ал блоктан шыққанда (қатемен болса да) Java оны өзі жабады. Ресурс AutoCloseable интерфейсін жүзеге асыруы керек.

    class Resurs implements AutoCloseable {
    private final String aty;

    Resurs(String aty) {
        this.aty = aty;
        System.out.println(aty + " ашылды");
    }

    void paydalan() {
        System.out.println(aty + " қолданылуда");
    }

    @Override
    public void close() {
        System.out.println(aty + " жабылды");
    }
}

public class Main {
    public static void main(String[] args) {
        try (Resurs a = new Resurs("Файл-1"); Resurs b = new Resurs("Файл-2")) {
            a.paydalan();
            b.paydalan();
            throw new IllegalStateException("ортасында қате!");
        } catch (IllegalStateException e) {
            System.out.println("Ұсталды: " + e.getMessage());
        } finally {
            System.out.println("finally орындалды");
        }
    }
}

    Нәтижеде екі маңызды нәрсе бар:

    • Қате лақтырылса да, екі ресурс та жабылды, ал жабу ретті болды: кері ретпен (соңғы ашылған - бірінші жабылады). Мұны үй есігіне ұқсатуға болады: кіргенде екі есікті ашасыз, шыққанда соңғысын бірінші жабасыз.
    • catch пен finally ресурстар жабылғаннан кейін орындалды.

    Жаңа бағдарламаларда ресурсты тек try-with-resources арқылы ашу керек. Бұл тәсілдің тағы бір артықшылығы бар: ресурсты жабу кезінде де қате шықса, Java бастапқы қатені жоғалтпайды, жабу қатесін оған «қосымша» (suppressed) етіп тіркейді. Қолмен жазылған finally бұл жағдайда бастапқы қатені жасырып жіберуі мүмкін еді. Сондықтан файлмен, желімен, дерекқормен жұмыс істегенде ережені қатаң ұстаныңыз: try-with-resources қолданбасаңыз, ресурстың жабылатынына сенімді бола алмайсыз.

    Файлмен жұмыс: Path және Files

    Бағдарламаның деректері тек жадта ғана болса, оны өшірген соң бәрі жоғалады. Ұзақ сақтау үшін файлға жазамыз. Java-да жаңа, ыңғайлы жолды java.nio.file пакеті береді:

    • Path - файлдың не қалтаның жолы. Path.of("zhurnal.txt").
    • Files - файлмен жұмыс істейтін статик әдістер: exists, size, readAllLines, readString, write, writeString, lines, delete...
    import java.io.BufferedReader;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;
import java.util.List;

public class Main {
    public static void main(String[] args) throws IOException {
        Path jol = Path.of("zhurnal.txt");

        // жазу: файл жоқ болса жасалады, бар болса үстінен жазылады
        Files.write(jol, List.of("Дана;92", "Ерлан;78", "Сая;85"), StandardCharsets.UTF_8);
        System.out.println("Файл бар ма? " + Files.exists(jol) + ", өлшемі: " + Files.size(jol) + " байт");

        // қосып жазу
        Files.writeString(jol, "Асхат;64\n", StandardOpenOption.APPEND);

        // барлық жолды оқу
        List<String> joldar = Files.readAllLines(jol);
        System.out.println("Жол саны: " + joldar.size());
        for (String j : joldar) {
            String[] b = j.split(";");
            System.out.println(b[0] + " -> " + b[1]);
        }

        // үлкен файлды жолмен оқу: try-with-resources автоматты жабады
        try (BufferedReader br = Files.newBufferedReader(jol)) {
            String birinshi = br.readLine();
            System.out.println("Бірінші жол: " + birinshi);
        }

        System.out.println("Файлдың аты: " + jol.getFileName());
        Files.deleteIfExists(jol);
        System.out.println("Жойылғаннан кейін бар ма? " + Files.exists(jol));
    }
}

    • Соңында файлды deleteIfExists арқылы тазаладық, сондықтан мысал қайта-қайта қатесіз іске қосылады.
    Файл қайда жасалады?

    Қысқа жол ("zhurnal.txt") іске қосылған қалтаға қатысты. Яғни терминалда java Main жазған қалтада жасалады. VS Code-та іске қосқанда кейде жұмыс қалтасы басқа болады, сондықтан файл күтпеген жерде пайда болса, таңғалмаңыз. Файлдың нақты орнын білу үшін jol.toAbsolutePath() шығарып қараңыз.

    Lambda өрнектері

    Алдыңғы апталарда жолдарды Comparator арқылы сұрыптағанда «lambda» сөзі бірнеше рет кездесті. Енді оны түсіндірейік. Lambda (lambda expression) - бұл аты жоқ қысқа әдіс, оны айнымалыға салуға не басқа әдіске беруге болады.

    Неге керек? Көп жағдайда біз әдіске «деректі» емес, «әрекетті» беруіміз керек: «осы шартпен сұрыпта», «әр элементті шығар». Ертеде бұл үшін анонимді класс жазылатын, ал ол өте ұзын болатын. Lambda бұл жазуды бір жолға қысқартады:

    import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        // 1. Анонимді класс (eski жол) пен lambda - бірдей
        Runnable eski = new Runnable() {
            @Override
            public void run() {
                System.out.println("Сәлем, анонимді класс!");
            }
        };
        Runnable jana = () -> System.out.println("Сәлем, lambda!");
        eski.run();
        jana.run();

        // 2. Параметрлі lambda
        Comparator<String> uzyndyqqa = (a, b) -> Integer.compare(a.length(), b.length());
        List<String> attar = new ArrayList<>(List.of("Айгерім", "Ер", "Бауыржан", "Дана"));
        attar.sort(uzyndyqqa);
        System.out.println(attar);

        // 3. Блокты lambda
        Comparator<String> ayaqtalu = (a, b) -> {
            char x = a.charAt(a.length() - 1);
            char y = b.charAt(b.length() - 1);
            return Character.compare(x, y);
        };
        attar.sort(ayaqtalu);
        System.out.println(attar);

        // 4. Әдіс сілтемесі (method reference)
        attar.forEach(System.out::println);
    }
}

    Lambda жазылуы: (параметрлер) -> дене. Нұсқалары:

    • () -> expr - параметрсіз;
    • x -> expr - бір параметр (жақшасыз жазуға болады);
    • (a, b) -> expr - екі параметр;
    • (a, b) -> { ...; return ...; } - блокты дене: бірнеше жол және return.

    Параметрлердің типін көрсетудің қажеті жоқ: компилятор оны контексттен шығарады. Lambda қай функционалды интерфейске сәйкес келетінін де контекст анықтайды: Runnable, Comparator<String> және т.б.

    Соңғы жолдағы System.out::println - әдіс сілтемесі (method reference). Ол x -> System.out.println(x) жазбасының қысқа түрі. Негізгі түрлері: Класс::статикӘдіс, нысан::әдіс, Класс::әдіс (String::length) және Класс::new.

    Lambda ішінде сыртқы айнымалыны өзгертуге болмайды

    Lambda сыртқы әдістегі айнымалыны қолдана алады, бірақ ол айнымалы тиімді өзгермейтін (effectively final) болуы керек: оған бір рет қана мән берілген болуы шарт. Мысалы, lambda ішінде сыртқы int sany айнымалысын арттыра алмайсыз. Бұл жағдайда Stream-нің count(), sum() сияқты әдістерін қолданыңыз.

    Функционалды интерфейстер

    Lambda қай типке сәйкес келеді? Тек функционалды интерфейске (functional interface): яғни тек бір абстракт әдісі бар интерфейске. Runnable (void run()), Comparator<T> (int compare(T, T)) - сондай. Өз интерфейсіңізді @FunctionalInterface деп белгілесеңіз, компилятор бір ғана абстракт әдісті қамтамасыз етеді.

    java.util.function пакетінде ең көп қажет болатын дайын интерфейстер жинағы бар. Негізгі бесеуін жаттап алған жөн:

    ИнтерфейсҚолтаңбаМағынасыМысал
    Function<T,R>R apply(T)бір мәнді басқасына айналдыруs -> s.length()
    Predicate<T>boolean test(T)шарт: иә/жоқb -> b >= 85
    Consumer<T>void accept(T)мәнді «жұту» (нәтиже жоқ)s -> println(s)
    Supplier<T>T get()мән «беру» (параметр жоқ)() -> "12:30"

    import java.util.function.BiFunction;
import java.util.function.Consumer;
import java.util.function.Function;
import java.util.function.Predicate;
import java.util.function.Supplier;
import java.util.function.UnaryOperator;

public class Main {
    public static void main(String[] args) {
        Function<String, Integer> uzyndyq = s -> s.length();          // T -> R
        Predicate<Integer> jaqsy = bal -> bal >= 85;                  // T -> boolean
        Consumer<String> shygar = s -> System.out.println("> " + s);  // T -> void
        Supplier<String> sagat = () -> "12:30";                        // () -> T
        BiFunction<Integer, Integer, Integer> qosu = (a, b) -> a + b;  // (T, U) -> R
        UnaryOperator<String> bas = s -> s.toUpperCase();              // T -> T

        System.out.println(uzyndyq.apply("Қарағанды"));
        System.out.println(jaqsy.test(90) + " " + jaqsy.test(70));
        shygar.accept("Сәлем");
        System.out.println(sagat.get());
        System.out.println(qosu.apply(20, 22));
        System.out.println(bas.apply("астана"));

        // біріктіру
        Predicate<Integer> nashar = jaqsy.negate();
        Predicate<Integer> ortasha = jaqsy.negate().and(b -> b >= 50);
        System.out.println(nashar.test(40) + " " + ortasha.test(40) + " " + ortasha.test(60));

        Function<String, String> eki = bas.andThen(s -> s + "!");
        System.out.println(eki.apply("әлем"));
        Function<Integer, Integer> eselen = x -> x * 2;
        Function<Integer, Integer> bir = x -> x + 1;
        System.out.println(eselen.andThen(bir).apply(5) + " " + eselen.compose(bir).apply(5));
    }
}

    • UnaryOperator<T> - кіріс пен шығыс типі бірдей Function<T,T>.

    Бұл интерфейстерді өзіңіз ойлап табудың қажеті жоқ: Stream әдістері дәл осы типтерді күтеді.

    Stream API

    Енді бәрін біріктіретін тақырыпқа келдік. Stream (stream, ағын) - деректер жинағын өңдеудің «құбыр» тәсілі. Аналогия: кәсіпорындағы конвейер. Шикізат (деректер) басынан кіреді, әр станция бір әрекет жасайды (сүзеді, өзгертеді, сұрыптайды), соңында дайын өнім шығады.

    Stream-нің үш бөлігі бар:

    1. Бастау: list.stream(), Stream.of(...), Files.lines(...).
    2. Аралық операциялар (intermediate): filter, map, sorted, distinct, limit. Олар жаңа stream қайтарады және бірден орындалмайды: соңғы операция шақырылғанша «жалқау» күтеді.
    3. Қорытынды операция (terminal): toList(), collect(...), count(), sum(), reduce(...), forEach(...). Ол құбырды іске қосады.

    Stream бастапқы жинақты өзгертпейді, әрқашан жаңа нәтиже жасайды. Құбырдың қалай жұмыс істейтіні:

    Мәтіндік балама: алты оқушыдан filter(бал ≥ 85) Дана 92, Сая 85, Мадина 97, Нұрлан 85 төртеуін қалдырады (Ерлан 78 мен Асхат 64 түседі); map(Oqushy::aty) оларды аттарға айналдырады; toList() соңында [Дана, Сая, Мадина, Нұрлан] тізімін береді.

    Енді нақты кодта көрейік (оқушылар record ретінде берілген):

    import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class Main {
    record Oqushy(String aty, String sinip, int bal) {}

    public static void main(String[] args) {
        List<Oqushy> tizim = List.of(
            new Oqushy("Дана", "7А", 92), new Oqushy("Ерлан", "7Б", 78),
            new Oqushy("Сая", "7А", 85), new Oqushy("Асхат", "7Б", 64),
            new Oqushy("Мадина", "7А", 97), new Oqushy("Нұрлан", "7Б", 85));

        // filter + map + collect
        List<String> jaqsylar = tizim.stream()
            .filter(o -> o.bal() >= 85)
            .map(Oqushy::aty)
            .toList();
        System.out.println("85+: " + jaqsylar);

        // sorted
        System.out.println(tizim.stream()
            .sorted((a, b) -> Integer.compare(b.bal(), a.bal()))
            .limit(3)
            .map(o -> o.aty() + "(" + o.bal() + ")")
            .collect(Collectors.joining(", ")));

        // reduce / қорытынды операциялар
        int jiny = tizim.stream().mapToInt(Oqushy::bal).sum();
        double orta = tizim.stream().mapToInt(Oqushy::bal).average().orElse(0);
        int maks = tizim.stream().map(Oqushy::bal).reduce(0, Integer::max);
        long sany = tizim.stream().filter(o -> o.sinip().equals("7А")).count();
        System.out.println("Қосынды=" + jiny + ", орташа=" + orta + ", макс=" + maks + ", 7А=" + sany);

        // groupingBy
        Map<String, Double> sinipOrta = tizim.stream().collect(
            Collectors.groupingBy(Oqushy::sinip, TreeMap::new, Collectors.averagingInt(Oqushy::bal)));
        sinipOrta.forEach((k, v) -> System.out.printf("%s: %.1f%n", k, v));

        System.out.println(tizim.stream().map(Oqushy::bal).distinct().sorted().toList());
        System.out.println(tizim.stream().anyMatch(o -> o.bal() == 100) + " " + tizim.stream().allMatch(o -> o.bal() > 60));
    }
}

    Әр блокқа назар аударайық:

    • filter(...).map(...).toList() - ең жиі кездесетін үлгі, диаграммадағы құбырдың өзі. toList() Java 16-дан бар (бұрын collect(Collectors.toList()) жазылатын).
    • sorted(...) + limit(3) - үздік үшеуді алады. Дана мен Сая сияқты тең балдарда сұрыптау тұрақты. Collectors.joining(", ") - элементтерді бір жолға біріктіреді.
    • mapToInt(...).sum() және average() - сандық stream-дер (IntStream). average() OptionalDouble қайтарады, сондықтан orElse(0) қостық. reduce(0, Integer::max) - «жинақтап» бір мәнге келтіру: бастапқы мән 0, әр қадамда үлкенін ұстайды.
    • Collectors.groupingBy(...) - SQL-дегі GROUP BY тәрізді: сыныпқа қарай топтап, әр топтың орташа балын (averagingInt) есептейді. TreeMap::new нәтижені сұрыпталған картаға салады.
    • distinct() - қайталанбайтын, anyMatch / allMatch - «қандай да бір» / «барлығы» шарт.
    Stream-ді бір рет қана қолдануға болады

    Қорытынды операция шақырылған соң stream «жабылады». Сол нысанды қайта қолдансаңыз, IllegalStateException: stream has already been operated upon or closed шығады. Қайта керек болса, жинақтан жаңа stream() алыңыз.

    Stream-ді қашан қолданбау керек? Қарапайым жағдайда оңай for циклі айқынырақ болса, цикл жазыңыз. Stream екі-үш қадамдық өңдеуде жақсы көрінеді; он қадамдық құбыр оқуға қиын. Мақсат - код оқылатын болуы.

    Optional: «мән болмауы мүмкін»

    Бағдарламалаудағы ең танымал қателердің бірі - null. «Мән жоқ» дегенді null деп белгілесек, оны тексеруді ұмытқан сәтте NullPointerException шығады. Java 8-ден бері бұл мәселенің көркем шешімі бар: Optional<T> (Optional, «міндетті емес мән»). Ол «қорап»: не ішінде мән бар, не бос. Қорап типі әдіс қайтаратын мәннің жоқ болуы мүмкін екенін алдын ала ескертеді.

    import java.util.List;
import java.util.Map;
import java.util.Optional;

public class Main {
    static Optional<Integer> tap(Map<String, Integer> bal, String aty) {
        return Optional.ofNullable(bal.get(aty));
    }

    public static void main(String[] args) {
        Map<String, Integer> bal = Map.of("Дана", 92, "Ерлан", 78);

        Optional<Integer> d = tap(bal, "Дана");
        Optional<Integer> j = tap(bal, "Жанар");

        System.out.println(d.isPresent() + " " + j.isPresent());
        System.out.println(d.get());
        System.out.println(j.orElse(-1));
        System.out.println(j.map(b -> b + 5).orElse(0));
        System.out.println(d.map(b -> "Бал: " + b).orElse("Жоқ"));
        d.ifPresent(b -> System.out.println("Табылды: " + b));
        j.ifPresentOrElse(b -> System.out.println("Табылды"), () -> System.out.println("Жанар жоқ"));

        Optional<String> birinshi = List.of("қала", "ауыл", "дала").stream()
            .filter(s -> s.startsWith("д")).findFirst();
        System.out.println(birinshi.orElse("-"));

        try {
            j.orElseThrow(() -> new IllegalStateException("бал табылмады"));
        } catch (IllegalStateException e) {
            System.out.println("Қате: " + e.getMessage());
        }
    }
}

    Мини-жоба: файлдан оқып, Stream-мен өңдеу

    Енді оқығанымыздың бәрін біріктіретін шағын мысал: CSV форматты (үтірмен бөлінген) файл жазамыз, оны оқимыз, әр оқушының орташа балын есептейміз және ең үздігін табамыз. Бұл - келесі аптадағы қорытынды жобаның кішкентай алдын ала көрінісі.

    import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) throws IOException {
        Path f = Path.of("ballar.csv");
        Files.write(f, List.of(
            "Дана,математика,92", "Дана,физика,88",
            "Ерлан,математика,70", "Ерлан,физика,74",
            "Сая,математика,85", "Сая,физика,96"));

        // файл -> Stream -> Map<оқушы, орташа бал>
        Map<String, Double> orta;
        try (var joldar = Files.lines(f)) {
            orta = joldar
                .map(j -> j.split(","))
                .collect(Collectors.groupingBy(
                    b -> b[0], TreeMap::new, Collectors.averagingInt(b -> Integer.parseInt(b[2]))));
        }
        orta.forEach((aty, b) -> System.out.printf("%-6s %.1f%n", aty, b));

        String uzdik = orta.entrySet().stream()
            .max(Map.Entry.comparingByValue())
            .map(Map.Entry::getKey)
            .orElse("-");
        System.out.println("Үздік: " + uzdik);
        Files.delete(f);
    }
}

    Жиі қателер

    1. Бос catch (қатені жұтып қою)

    catch (Exception e) {} қатені жасырады. Ең кемі хабарлама шығарыңыз, ал жалпы Exception орнына нақты түрді ұстаңыз.

    2. catch ретін қателесу

    catch (Exception e) блогын catch (IOException e)-тен бұрын жазсаңыз, компилятор «exception IOException has already been caught» қатесін береді. Нақты түр жоғарыда, жалпысы төменде тұруы керек.

    3. Ресурсты жаппау

    FileReader не Scanner ашып, жаппай қалдыру. Ресурсты әрқашан try-with-resources ішінде ашыңыз.

    4. finally ішінде return жазу

    finally ішіндегі return try/catch ішіндегі return мен қатені де бүркемелеп жібереді. finally ішінде тек тазалау жұмысын жасаңыз.

    5. Optional.get() шақыру

    Алдымен isPresent() тексермей, Optional.get() жазсаңыз, бос қорапта NoSuchElementException шығады. orElse, orElseThrow не ifPresent қолданыңыз.

    6. Stream-ді қайта қолдану не lambda ішінде сыртқы айнымалыны өзгерту

    Stream бір рет қана қолданылады. Lambda ішіндегі сыртқы айнымалы тиімді түрде final болуы керек, әйтпесе local variables referenced from a lambda expression must be final or effectively final қатесі шығады.

    Қорытынды

    Бүгін біз:

    • ерекше жағдайлар нысан екенін және stack trace-тің қатені табуға көмектесетінін көрдік;
    • try/catch/finally блоктарын, көп catch және | белгісін үйрендік;
    • checked (IOException: өңдеу міндетті) мен unchecked (RuntimeException: міндетті емес) қателердің айырмашылығын ажыраттық;
    • өз ерекше жағдай кластарымызды жасадық (extends Exception не RuntimeException);
    • try-with-resources ресурсты қатемен болса да жабатынын көрдік;
    • Path пен Files арқылы мәтін файлды оқып, жазуды үйрендік;
    • lambda өрнектерін, әдіс сілтемелерін және Function, Predicate, Consumer, Supplier интерфейстерін меңгердік;
    • Stream API арқылы filter, map, sorted, collect, reduce құбырларын жаздық;
    • Optional арқылы «мән жоқ» жағдайын null-сыз өңдедік.
    • Мен stack trace-ті оқып, қате қай жолда екенін таба аламын.
    • Мен checked және unchecked қателердің айырмашылығын түсіндіре аламын.
    • Мен try/catch/finally және try-with-resources жаза аламын.
    • Мен өз ерекше жағдай класымды жасап, лақтыра және ұстай аламын.
    • Мен Files арқылы мәтін файл жазып, оқи аламын.
    • Мен Function, Predicate, Consumer үшін lambda жаза аламын.
    • Мен filter, map, sorted, collect арқылы Stream құбырын құра аламын.
    • Мен Optional қолданып, null-ға қарағанда қауіпсіз код жаза аламын.

    Келесі апта - соңғы: бір мезгілде бірнеше жұмысты орындайтын көп ағынды бағдарламалар, жоба құралдары (Maven, Gradle), тест жазу идеясы және толыққанды қорытынды жоба «Оқушы журналы».

    Өзіңізді тексеріңіз

    1. Мына ерекше жағдайлардың қайсысы checked (компилятор өңдеуді талап етеді)?

    IOException - Exception ұрпағы, бірақ RuntimeException емес, сондықтан checked: try/catch не throws керек. Қалғандары RuntimeException ұрпақтары, яғни unchecked.

    2. Мына бағдарлама не шығарады?

    public class Main {
    static int f() {
        try {
            System.out.print("1 ");
            return 10;
        } finally {
            System.out.print("2 ");
        }
    }

    public static void main(String[] args) {
        System.out.println(f());
    }
}

    return 10 орындалғанға дейін finally блогы орындалады. Сондықтан алдымен 1 , сосын 2 шығады, ал 10 мәні main ішіндегі println арқылы соңында шығады.

    3. Мына код компиляцияда не береді?

    import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

public class Main {
    public static void main(String[] args) {
        String t = Files.readString(Path.of("a.txt"));
        System.out.println(t);

}

    Files.readString IOException (checked) лақтыра алады. main оны не catch арқылы ұстамаған, не throws арқылы жарияламаған, сондықтан компилятор кодты қабылдамайды.

    4. Мына жерде не қате?

    import java.io.IOException;

public class Main {
    static void oqy() throws IOException {
        throw new IOException("қате");
    }

    public static void main(String[] args) {
        try {
            oqy();
        } catch (Exception e) {
            System.out.println("1");
        } catch (IOException e) {
            System.out.println("2");
        }
    }
}

    Exception - IOException-нің ата-класы, сондықтан бірінші catch барлығын ұстайды. Екінші блок ешқашан орындалмайды, сондықтан компилятор exception IOException has already been caught деген қате береді. Реті кері болуы керек: алдымен нақты түр.

    5. Мына бағдарлама не шығарады?

    import java.util.stream.Stream;

public class Main {
    public static void main(String[] args) {
        long n = Stream.of("қала", "ауыл", "көл", "дала", "су")
            .filter(s -> s.contains("а"))
            .count();
        System.out.println(n);

}

    Тізімдегі «а» әрпі бар сөздер: қала, ауыл, дала. «көл» мен «су»-да а жоқ. count() 3 қайтарады.

    6. Мына бағдарлама не шығарады?

    import java.util.Optional;

public class Main {
    public static void main(String[] args) {
        int r = Optional.of(5)
            .map(x -> x * 2)
            .filter(x -> x > 20)
            .orElse(-1);
        System.out.println(r);
    }
}

    Optional.of(5) - map 10 жасайды, бірақ filter(x -> x > 20) оны өткізбейді, қорап бос болып қалады. orElse(-1) әдепкі мәнді береді: -1.

    7. Қай функционалды интерфейс бір мән қабылдайды, бірақ ештеңе қайтармайды?

    Consumer<T> әдісі void accept(T): мәнді «жұтады» (forEach ішінде). Predicate - boolean, Function - нәтиже түрін, Supplier - параметрсіз мән береді.

    8. Мына бағдарлама не шығарады?

    class R implements AutoCloseable {

    public void close() { System.out.print("C" + n + " "); }
}

public class Main {

    Оңай

    try, catch және finally ретін болжау

    Мына әдіс шақырылғанда, әріптер қандай ретпен шығады? Әріптерді бос орынмен бөліп жазыңыз.

    static void f() {
    try {
        System.out.println("A");
        int nol = 0;
        int x = 5 / nol;
        System.out.println("B");
    } catch (ArithmeticException e) {
        System.out.println("C");
    } finally {

    Кеңес

    A шықты. 5 / nol қайда лақтырады? Лақтырған соң try ішіндегі қалған жолдар (B) орындала ма? Әрі қарай catch, сосын finally, ал finally-дан кейін бағдарлама жалғасады.

    Балды оқитын әдіс және өз қатесі

    BalQateligi атты checked ерекше жағдай класын жазыңыз (конструкторы хабарлама мен себепті қабылдасын). static int oqyBal(String matin) throws BalQateligi әдісін жазыңыз: ол мәтінді trim() арқылы тазалап, бүтін санға айналдырсын; сан болмаса (NumberFormatException), оны BalQateligi ішіне орап лақтырсын; сан 0..100 аралығынан тыс болса, BalQateligi лақтырсын. main-де "90", "abc", "120", " 75 " мәндерін сынап, дұрыс балдардың санын және қосындысын шығарыңыз.

    Кеңес

    NumberFormatException ұстағанда throw new BalQateligi("...", e) жазыңыз, мұнда e - себеп. Конструкторда super(habar, sebep) қолданыңыз. Циклде әр мәнді try ішінде өңдеп, catch (BalQateligi e) арқылы e.getMessage() шығарыңыз.

    Шешімі
    class BalQateligi extends Exception {
    BalQateligi(String habar, Throwable sebep) {
        super(habar, sebep);
    }

    BalQateligi(String habar) {
        super(habar);
    }
}

public class Main {
    static int oqyBal(String matin) throws BalQateligi {
        int bal;
        try {
            bal = Integer.parseInt(matin.trim());
        } catch (NumberFormatException e) {
            throw new BalQateligi("«" + matin + "» сан емес", e);
        }
        if (bal < 0 || bal > 100) {
            throw new BalQateligi("бал 0..100 аралығында болуы керек: " + bal);
        }
        return bal;
    }

    public static void main(String[] args) {
        String[] kirister = {"90", "abc", "120", " 75 "};
        int jiny = 0;
        int sany = 0;
        for (String k : kirister) {
            try {
                int b = oqyBal(k);
                jiny += b;
                sany++;
                System.out.println("OK: " + b);
            } catch (BalQateligi e) {
                System.out.println("Қате: " + e.getMessage());
            }
        }
        System.out.println("Дұрыс балдар: " + sany + ", қосындысы: " + jiny);
    }
}

    Алдымен жұп сандарды қалдырыңыз: 2, 4, 6. Содан кейін әрқайсысының квадратын алыңыз. Соңында қосыңыз.

    Шешімі

    filter жұп сандарды қалдырады: 2, 4, 6. map квадраттайды: 4, 16, 36. sum() 4 + 16 + 36 = 56.

    import java.util.List;

public class Main {
    public static void main(String[] args) {
        int s = List.of(1, 2, 3, 4, 5, 6).stream()
            .filter(x -> x % 2 == 0)
            .map(x -> x * x)
            .mapToInt(Integer::intValue)
            .sum();
        System.out.println(s);
    }
}

    groupingBy нәтижесі

    Мына тізімдегі сөздерді ұзындығы бойынша топтап, әр топтағы сөз санын TreeMap арқылы шығарсақ, нәтиже қандай болады? Тізім: "қала", "дала", "ауыл", "көл", "су", "жер", "өзен". Код:

    Map<Integer, Long> m = sozder.stream().collect(
    Collectors.groupingBy(String::length, TreeMap::new, Collectors.counting()));
System.out.println(m);
    Жауапты дәл шыққандай жазыңыз ({...} ішінде).
    Кеңес

    Ұзындықтарын санаңыз: қала - 4, дала - 4, ауыл - 4, көл - 3, су - 2, жер - 3, өзен - 4. TreeMap кілттерді өсу ретімен шығарады, ал Map.toString() форматы: {кілт=мән, кілт=мән}.

    Шешімі

    Ұзындығы 2: су (1 сөз). Ұзындығы 3: көл, жер (2 сөз). Ұзындығы 4: қала, дала, ауыл, өзен (4 сөз).

    import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;

public class Main {
    public static void main(String[] args) {
        List<String> sozder = List.of("қала", "дала", "ауыл", "көл", "су", "жер", "өзен");
        Map<Integer, Long> m = sozder.stream().collect(
            Collectors.groupingBy(String::length, TreeMap::new, Collectors.counting()));
        System.out.println(m);
    }
}

    Файлдан оқу және Stream

    ballar.txt файлына 6 жол жазыңыз: Аты;Пән;Бал форматында (мысалы, Дана;математика;92). Файлды қайта оқып, жолдарды record Jazba(String aty, String pan, int bal) нысандарына айналдырыңыз. Математикадан 80-ден кем емес балл алғандардың ішінен ең жоғары екеуін балы кему ретімен табыңыз, жазбалар санын шығарыңыз. Соңында файлды жойыңыз. Деректер: Дана;математика;92, Ерлан;физика;78, Сая;математика;85, Асхат;математика;64, Мадина;физика;97, Нұрлан;математика;88.

    Кеңес

    Files.write(f, List.of(...)) жазады, Files.readAllLines(f).stream() оқиды. map(j -> j.split(";")), содан соң map(b -> new Jazba(b[0], b[1], Integer.parseInt(b[2]))). Сүзгі: filter(j -> j.pan().equals("математика") && j.bal() >= 80). Сұрыптау: sorted((a, b) -> Integer.compare(b.bal(), a.bal())), limit(2).

    Шешімі
    import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.List;
import java.util.stream.Collectors;

public class Main {
    record Jazba(String aty, String pan, int bal) {}

    public static void main(String[] args) throws IOException {
        Path f = Path.of("ballar.txt");
        Files.write(f, List.of(
            "Дана;математика;92", "Ерлан;физика;78", "Сая;математика;85",
            "Асхат;математика;64", "Мадина;физика;97", "Нұрлан;математика;88"));

        List<Jazba> barlygy = Files.readAllLines(f).stream()
            .map(j -> j.split(";"))
            .map(b -> new Jazba(b[0], b[1], Integer.parseInt(b[2])))
            .toList();

        String top2 = barlygy.stream()
            .filter(j -> j.pan().equals("математика") && j.bal() >= 80)
            .sorted((a, b) -> Integer.compare(b.bal(), a.bal()))
            .limit(2)
            .map(j -> j.aty() + " " + j.bal())
            .collect(Collectors.joining(", "));
        System.out.println("Математика, үздік 2: " + top2);
        System.out.println("Барлық жазба: " + barlygy.size());
        Files.delete(f);
    }
}
    $ javac Main.java && java Main
Математика, үздік 2: Дана 92, Нұрлан 88
Барлық жазба: 6
    Өзіңізді тексеріңіз
    • Файл жазылады, оқылады және соңында Files.delete арқылы жойылады.
    • Нәтиже: Дана 92, Нұрлан 88 (Сая 85 үшінші, Мадина физикадан).
    • record Jazba және Files.readAllLines қолданылған.
    • Жазбалар саны 6 шықты.
