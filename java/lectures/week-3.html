Мазмұны

    3-апта

    Класстар және нысандар

    Өз типтерімізді жасаймыз: класс пен нысан, конструкторлар, this, инкапсуляция, static, toString/equals/hashCode, record, пакеттер, нысанның жадтағы орны және қоқыс жинаушы.

    Бүгін бетбұрыс апта

    Осы уақытқа дейін біз int, String, массив сияқты дайын типтермен жұмыс істедік. Бүгін өз типімізді жасаймыз. Бұл - Java-ның жүрегі: нысандық бағдарламалау (object-oriented programming, OOP). Өткен аптадағы «атау мен баға екі бөлек массивте» мәселесін шешеміз: бір нысан екеуін бірге ұстайды.

    Неге класс керек?

    Кітап дүкенін елестетіңіз. Әр кітаптың аты, авторы, бағасы, беті бар. Өткен аптадағыдай оны бөлек массивтерде сақтасақ: String[] atau, String[] avtor, double[] baga - онда «үшінші кітап» деген ұғым жоқ, тек үш массивтегі үшінші ұяшық бар. Біреуін сұрыпталсақ, қалғандары сәйкес келмей қалады. Әдістерге үш массивті бере беру де ыңғайсыз.

    Шешімі - класс (class) жазу. Класс - нысанның сызбасы, үлгісі: онда қандай деректер (өрістер, fields) бар және нысан не істей алады (әдістер, methods). Ал нысан (object, кейде instance) - сол сызба бойынша жасалған нақты дана. Аналогия: киім тігу үлгісі (қалып) бір, ал одан тігілген көйлектер көп; әр көйлектің өз өлшемі, түсі бар. Не болмаса шаңырақтың жобасы бір, ал үйлер көп.

    Мәтінмен: сол жақта Kitap класының карточкасы: үш өріс (atau, avtor, baga) және екі әдіс. Оң жақта сол класстан жасалған екі нысан бар: k1 («Абай жолы», 3200) және k2 («Көшпенділер», 4100). Үзік көрсеткілер «осы сызбадан жасалған» дегенді білдіреді.

    Алғашқы класс

    Класс жазу өте қарапайым. class кілт сөзі, оның ішінде өрістер (айнымалылар) және әдістер. Нысанды new операторымен жасаймыз, ал оның өрісіне не әдісіне нүкте арқылы жетеміз: k1.atau. Бір файлда бірнеше класс бола алады, бірақ тек біреуі public және оның аты файл атына тең болуы тиіс.

    class Kitap {
    String atau;
    String avtor;
    double baga;

    void bagaTomendet(double payyz) {
        baga = baga - baga * payyz / 100;
    }

    void kersetu() {
        System.out.println(atau + " (" + avtor + ") - " + baga + " тг");
    }
}

    Бұл код жұмыс істейді, бірақ екі кемшілігі бар: нысан жасаған соң өрістерді бір-бірлеп толтыру керек (біреуін ұмытып кетуіміз мүмкін), және кез келген адам k1.baga = -500 деп жаза алады. Екеуін де келесі бөлімдерде түзетеміз.

    Конструкторлар және this

    Конструктор (constructor) - нысан жасалғанда new шақыратын арнайы әдіс. Оның аты класс атымен бірдей, қайтару типі жоқ (void да жазылмайды). Мақсаты - нысанды алғашқы мәндермен дұрыс дайындау.

    Параметр аты өріс атымен бірдей болса, не болады? Параметр өрісті «көлеңкелейді». Сондықтан this кілт сөзі бар: ол «осы нысан» дегенді білдіреді. this.atau = atau - «осы нысанның atau өрісіне параметр atau-ды сал».

    class Kitap {
    String atau;
    String avtor;
    double baga;
    int bet;

    // толық конструктор
    Kitap(String atau, String avtor, double baga, int bet) {
        this.atau = atau;
        this.avtor = avtor;
        this.baga = baga;
        this.bet = bet;
    }

    // қысқа конструктор: беті белгісіз, бағасы әдепкі
    Kitap(String atau, String avtor) {
        this(atau, avtor, 2000, 0);   // басқа конструкторды шақыру
    }

    void kersetu() {
        System.out.println(atau + " | " + avtor + " | " + baga + " тг | " + bet + " бет");
    }
}

    Бұл жерде конструкторды қайта жүктеу (overloading) қолданылды: екі конструктор бар, біреуі төрт параметрлі, екіншісі екі параметрлі. Екіншісі this(...) арқылы біріншісін шақырады (бұл конструктор тізбегі, constructor chaining; ол конструктордың бірінші жолы болуы тиіс). Сонда негізгі дайындау жұмысы бір жерде ғана тұрады.

    Әдепкі конструктор

    Егер класста бірде-бір конструктор жазбасаңыз, Java параметрсіз, ештеңе істемейтін Kitap() конструкторын өзі қосады (алдыңғы бөлімде біз соны қолдандық). Бірақ бір конструктор жазсаңыз, әдепкі жоғалады: new Kitap() енді қате береді, өйткені параметрсіз конструктор жоқ.

    Инкапсуляция: private, getter, setter

    Өрістерді ашық қалдырсақ, кез келген код оларды бүлдіре алады: бағаны теріс, бетті нөл қылады. Қорғану үшін инкапсуляция (encapsulation) қолданамыз: өрістерді private (тек осы класс көреді) етіп, оларға қол жеткізуді public әдістер арқылы береміз. Оқитын әдіс - getter, жазатын - setter. Setter ішінде деректі тексеруге болады: ол тексеру нысанның әрқашан дұрыс күйде болуына кепіл.

    Аналогия: банкомат. Шотыңыздағы ақшаға бірден қол сұқпайсыз: интерфейс (экран, түймелер) арқылы «қанша алам» деп сұрайсыз, ал банк ережелерді тексереді. Мысал - әмиян (шартты теңгемен):

    class Hamyan {
    private final String iesi;
    private long qaldyq;           // теңгемен

    Hamyan(String iesi, long bastapqy) {
        this.iesi = iesi;
        this.qaldyq = Math.max(0, bastapqy);
    }

    String getIesi() {
        return iesi;
    }

    long getQaldyq() {
        return qaldyq;
    }

    boolean salu(long soma) {
        if (soma <= 0) {
            return false;
        }
        qaldyq += soma;
        return true;
    }

    boolean aluy(long soma) {
        if (soma <= 0 || soma > qaldyq) {
            return false;          // қарыз болуға болмайды
        }
        qaldyq -= soma;
        return true;
    }
}

public class HamyanSynaq {
    public static void main(String[] args) {
        Hamyan h = new Hamyan("Нұрлан", 10000);
        System.out.println(h.getIesi() + ": " + h.getQaldyq());
        System.out.println(h.salu(5000));
        System.out.println(h.aluy(20000));    // жетпейді
        System.out.println(h.aluy(3500));
        System.out.println("Қалдық: " + h.getQaldyq());
    }
}

    МодификаторҚайдан көрінеді?
    privateтек осы класстың ішінен
    (жазылмайды), package-privateосы пакеттің кластарынан

    Бастапқы ереже: өрісті әрқашан private жасаңыз, ал әдістерді қажетіне қарай public етіңіз. Getter мен setter жазуды IDE автоматты жасап береді (IntelliJ-де Generate, VS Code-та Source Action), бірақ setter-ді тек шынымен қажет болса қосыңыз: көп нысан өзгермейтін болғаны жақсы.

    static: нысанға емес, класқа тиесілі

    Әдетте өріс пен әдіс нысанға тиесілі. Бірақ кейде бір мән барлық нысанға ортақ болу керек: мысалы, нысандардың жалпы саны, не ҚҚС = 12% тұрақтысы. Ол үшін static қолданамыз: static өріс (static field) бір ғана, класқа тиесілі, нысандарды қанша жасасақ та, көшірмесі біреу. Оған класс аты арқылы жетеміз: Kitap.sany. static әдіс нысансыз-ақ шақырылады: Math.sqrt(16), Integer.parseInt("5"). Біздің main де static: бағдарлама басталғанда әлі ешбір нысан жоқ.

    class Oqushy {
    static int sany = 0;                       // барлық оқушыға ортақ
    static final String MEKTEP = "№12 мектеп"; // тұрақты

    private final int nomer;
    private final String ataui;

    Oqushy(String ataui) {
        sany++;
        this.nomer = sany;
        this.ataui = ataui;
    }

    String tanystyru() {
        return nomer + ". " + ataui + " (" + MEKTEP + ")";
    }

    static String statistika() {
        return "Барлығы: " + sany + " оқушы";
    }
}

public class StaticMysal {
    public static void main(String[] args) {
        System.out.println(Oqushy.statistika());
        Oqushy a = new Oqushy("Аружан");
        Oqushy b = new Oqushy("Бекзат");
        Oqushy c = new Oqushy("Дана");
        System.out.println(a.tanystyru());
        System.out.println(c.tanystyru());
        System.out.println(Oqushy.statistika());
        System.out.println(Math.sqrt(144) + " " + Math.max(3, 8) + " " + Math.abs(-4.5));
    }
}

    static-ті шектен тыс қолданбаңыз

    Бастаушылар көп жағдайда компилятор қатесінен құтылу үшін бәріне static жазып жібереді. Бұл нысандық бағдарламалаудың мәнін жоққа шығарады. Ереже: егер әдіс нысанның күйін пайдаланса, ол нысан әдісі болуы тиіс; егер күйсіз көмекші есеп болса (математика, түрлендіру), static жарайды.

    toString, equals, hashCode

    Java-да барлық класс жасырын түрде Object класының мұрагері; осыдан үш пайдалы әдісті «мұраға» алады, бірақ олардың әдепкі іске асыруы көп жағдайда жарамайды. Оларды қайта анықтау (override) керек. Алдымен, toString()-ті қарайық. Нысанды println-ге берсек, Java toString()-ті шақырады.

    class Aspap {
    String ataui;
    int baga;

    Aspap(String ataui, int baga) {
        this.ataui = ataui;
        this.baga = baga;
    }
}

    Шыққан Aspap@... - класс аты және нысанның «хэш-коды» (оның мәні әр іске қосуда өзгеруі мүмкін). Бұл пайдасыз. Өз toString жазсақ:

    class Aspap {
    private final String ataui;
    private final int baga;

    Aspap(String ataui, int baga) {
        this.ataui = ataui;
        this.baga = baga;
    }

    @Override
    public String toString() {
        return "Aspap{" + ataui + ", " + baga + " тг}";
    }
}

    @Override - «мен мұрагерленген әдісті әдейі қайта жазып жатырмын» деген белгі; аты қате болса, компилятор ескертеді. Енді equals. Әдепкі equals да == сияқты сілтемені салыстырады, яғни бір нысан ба? Бірақ біз «екі аспаптың аты мен бағасы бірдей болса, олар тең» деп санағымыз келеді. Бұл үшін equals пен hashCode-ті қайта анықтау керек және екеуін де бірге. Қағида: егер a.equals(b) ақиқат болса, олардың hashCode()-тары да бірдей болуы тиіс. HashSet және HashMap сияқты жинақтар алдымен хэш-кодқа қарайды, сондықтан біреуін ғана жазсаңыз, олар қате жұмыс істейді. Көрейік.

    import java.util.HashSet;
import java.util.Objects;

class Jaman {                        // equals бар, hashCode жоқ
    String ataui;
    Jaman(String a) { ataui = a; }
    @Override
    public boolean equals(Object o) {
        return o instanceof Jaman j && Objects.equals(ataui, j.ataui);
    }
}

class Jaksy {                        // екеуі де бар
    String ataui;
    Jaksy(String a) { ataui = a; }
    @Override
    public boolean equals(Object o) {
        return o instanceof Jaksy j && Objects.equals(ataui, j.ataui);
    }
    @Override
    public int hashCode() {
        return Objects.hash(ataui);
    }
}

public class EqualsMysal {
    public static void main(String[] args) {
        Jaman j1 = new Jaman("Домбыра"), j2 = new Jaman("Домбыра");
        System.out.println(j1.equals(j2) + " " + (j1 == j2));

        HashSet<Jaman> a = new HashSet<>();
        a.add(j1);
        System.out.println("hashCode жоқ: " + a.contains(j2));

        Jaksy k1 = new Jaksy("Домбыра"), k2 = new Jaksy("Домбыра");
        HashSet<Jaksy> b = new HashSet<>();
        b.add(k1);
        System.out.println("hashCode бар: " + b.contains(k2));
        System.out.println(k1.hashCode() == k2.hashCode());
    }
}

    Екі Jaman нысаны equals бойынша тең, бірақ hashCode әртүрлі болғандықтан, HashSet оны табуға тырыспайды да: contains жалған қайтарды. Jaksy класында екеуі бірлесе жұмыс істейді. Мұндағы o instanceof Jaksy j - Java 16-дан бастап қолжетімді үлгі бойынша тексеру (pattern matching for instanceof): тип сәйкес болса, бірден j айнымалысын береді. Objects.equals пен Objects.hash - null-ға төзімді көмекшілер.

    record: деректер класын қысқа жазу

    Жоғарыдағы Aspap класы: екі private final өріс, конструктор, екі getter, toString, equals, hashCode - жиырма шақты жол. Тек деректерді ұстайтын класстар үшін Java 16-да record (жазба) енгізілді: бір жолмен бәрі шығады.

    record Qala(String ataui, int halyq) {
    // компактты конструктор: деректі тексеру
    Qala {
        if (halyq < 0) {
            throw new IllegalArgumentException("Халық теріс болмайды: " + halyq);
        }
    }

    // қосымша әдіс
    boolean millionnyq() {
        return halyq >= 1_000_000;
    }
}

public class RecordMysal {
    public static void main(String[] args) {
        Qala a = new Qala("Астана", 1350000);
        Qala b = new Qala("Астана", 1350000);

        System.out.println(a);                    // toString дайын
        System.out.println(a.ataui() + " " + a.halyq());   // getter: өріс аты (), get жоқ
        System.out.println(a.equals(b) + " " + (a == b));
        System.out.println(a.hashCode() == b.hashCode());
        System.out.println(a.millionnyq());

        Qala c = new Qala("Қала", -5);
    }
}

Соңғы жолда теріс халық берсек, IllegalArgumentException лақтырылды: бұл - біз тексерісті өзіміз енгізген қателіктің «ерекше жағдайы».

    Қашан record, қашан әдеттегі класс? Егер нысан негізінен деректер тасушы болса (қала, нүкте, транзакция), өзгермесе - record. Егер нысанның күйі өзгеріп, күрделі мінез-құлқы болса (әмиян, оқушы журналы), әдеттегі класс.

    Пакеттер

    Жоба өскен сайын кластар көбейеді, оларды ұйымдастыру керек. Пакет (package) - кластарды топтайтын аты бар «қалта». Тура файл жүйесіндегі қалталар сияқты: kz.dukan.Kitap класы kz/dukan/Kitap.java файлында тұрады. Пакеттің міндеті - 1) кластарды реттеу, 2) аттар қақтығысын болдырмау (екі түрлі Kitap бола алады), 3) қолжетімділікті басқару.

    • Файлдың бірінші жолы: package kz.dukan;.
    • Басқа пакеттегі класты қолдану: import kz.dukan.Kitap; (не барлығын import kz.dukan.*;).
    • java.lang (String, Math, System) автоматты импортталады.
    • Басқа пакеттен көрінуі үшін класс пен оның қажетті мүшелері public болуы тиіс.

    Пакет аттары әдетте кіші әріппен жазылады, ал домен атауын кері жазу келісімі бар (kz.edu.marun). Екі файлдан тұратын шағын жоба көрейік:

    Нысан жадта: стек, үйме және сілтемелер

    2-аптада массив мен String үймеде тұрады деп білдік. Барлық нысан дәл солай жұмыс істейді. Kitap k = new Kitap(...) жолында екі әрекет бар: оң жақта new үймеде нысанға орын бөліп, конструкторды орындайды; сол жақта k айнымалысы стекте сілтемені (мекенжайды) сақтайды. Сондықтан бір нысанға бірнеше сілтеме болуы мүмкін.

    class Qala {
    private String ataui;
    private int halyq;

    Qala(String ataui, int halyq) {
        this.ataui = ataui;
        this.halyq = halyq;
    }

    int getHalyq() { return halyq; }
    void setHalyq(int halyq) { this.halyq = halyq; }
    String getAtaui() { return ataui; }
}

public class Siltemeler {
    static void ostiru(Qala q) {
        q.setHalyq(q.getHalyq() + 50000);     // нысанның ішін өзгертеді
    }

    static void almastyru(Qala q) {
        q = new Qala("Жаңа", 1);              // тек жергілікті сілтеме өзгереді
    }

    public static void main(String[] args) {
        Qala a = new Qala("Қарағанды", 500000);
        Qala b = a;                           // екінші сілтеме, бір нысан
        Qala c = new Qala("Қарағанды", 500000);

        b.setHalyq(510000);
        System.out.println(a.getHalyq() + " " + c.getHalyq());
        System.out.println((a == b) + " " + (a == c));

        ostiru(a);
        System.out.println(a.getHalyq());
        almastyru(a);
        System.out.println(a.getAtaui() + " " + a.getHalyq());

        Qala jok = null;
        System.out.println(jok == null);
        System.out.println(jok.getHalyq());   // NullPointerException
    }

    Диаграмманы мәтінмен оқыңыз: стекте төрт айнымалы тұр. a мен b үймедегі бірінші Qala нысанына көрсетеді, сондықтан b.setHalyq(510000) арқылы өзгерткенде, a да 510000 көреді. c - екінші нысан, оның мазмұны бастапқыда бірдей, бірақ ол бөлек, тәуелсіз. jok - null, ешбір нысанға көрсетпейді.

    Нәтижелерді түсіндірейік. ostiru(a) нысанның ішін өзгертті, және бұл шақырушыда көрінді (510000 + 50000 = 560000). Ал almastyru(a) параметрге жаңа нысан берді, бірақ параметр сілтеменің көшірмесі болғандықтан, шақырушының a сілтемесі өзгермеді: ол бұрынғыша «Қарағанды». Бұл Java-ның «мәнмен беру» ережесінің дәл түсіндірмесі: нысанның ішін өзгертуге болады, ал сілтеменің өзін әдіс ішінде ауыстырсаңыз, оның сырттағы көшірмесіне әсер етпейді. Соңында null арқылы әдіс шақырғанда NullPointerException болды. Ең жиі кездесетін Java қатесі осы: null «ештеңе жоқ» дегенді білдіреді, одан ештеңе сұрай алмайсыз.

    Қате хабарындағы <local4> жазуына таңданбаңыз: javac әдепкі бойынша жергілікті айнымалылардың аттарын .class файлына жазбайды, сондықтан JVM «төртінші жергілікті айнымалы null» дейді. IDE-де не javac -g арқылы жинағанда бұл жерде jok деп айтылар еді. Мәселенің мәні өзгермейді: жолдың нөміріне (Siltemeler.java:40) қарап, сол жолдағы сілтемелердің қайсысы null екенін табасыз.

    Жинақтаушы (garbage collection)

    Нысандар үймеде жасалады. Бірақ оларды кім өшіреді? Java-да delete не free жоқ. Оның орнына қоқыс жинаушы (garbage collector, GC) JVM ішінде автоматты жұмыс істейді: ол қолжетімсіз нысандарды тауып, олар алып тұрған жадты босатады. Нысан қолжетімсіз болады, егер оған бірде-бір сілтеме қалмаса (стектегі айнымалылардан, не басқа қолжетімді нысандардан тізбектеліп жету мүмкін болмаса).

    Мәтінмен: үймеде үш нысан бар. Стектегі a бірінші нысанға, b екіншіге көрсетеді. Үшінші нысанға ешбір сілтеме жоқ (мысалы, бұрын a оны көрсеткен, бірақ кейін a басқа нысанға көшті). Сондықтан ол қоқыс болып саналады да, GC оны босатады.

    class Uaqytsha {
    final int[] buf = new int[1000];
}

public class Qoqys {
    public static void main(String[] args) {
        Uaqytsha a = new Uaqytsha();
        a = new Uaqytsha();            // ескі нысанға сілтеме қалмады

        long sany = 0;
        for (int i = 0; i < 5_000_000; i++) {
            Uaqytsha t = new Uaqytsha();   // әр айналымда ~4 КБ, бірақ ешкім сақтамайды
            sany += t.buf.length;
        }
        System.out.println("Бағдарлама жад таусылмай аяқталды: " + sany);

        a = null;                       // соңғы нысан да қолжетімсіз
    }
}

    GC туралы нақтылау

    GC қашан жұмыс істейтінін біз басқармаймыз. System.gc() тек «жинағаның жөн болар еді» деген ұсыныс, кепіл емес. Сондықтан нысан жойылған кезде код орындалады деп сенуге болмайды. Жад үшін алаңдау азаяды, бірақ жад ағып кетуі әлі де мүмкін: егер нысанды тізімде ұстап, ешқашан өшірмесек, ол қолжетімді қалады да, GC оны өшірмейді. Файлдар, желі байланыстары сияқты жадтан тыс ресурстарды GC емес, біз өзіміз жабамыз (оны кейін көреміз).

    Нысандар тізімі

    Енді өткен аптадағы мәселеге оралайық. Нысандарымызды ArrayList-ке саламыз және онымен жұмыс істейміз. Сұрыптау үшін Java-ның Comparator құралын қолданамыз: Comparator.comparingDouble(Kitap::getBaga) - «кітаптарды getBaga нәтижесі бойынша салыстыр» (Kitap::getBaga - әдіске сілтеме, лямбданың қысқа жазылуы).

    import java.util.ArrayList;
import java.util.Comparator;

class Kitap {
    private final String atau;
    private final double baga;
    private int sany;

    Kitap(String atau, double baga, int sany) {
        this.atau = atau;
        this.baga = baga;
        this.sany = sany;
    }

    String getAtau() { return atau; }
    double getBaga() { return baga; }
    int getSany() { return sany; }

    boolean sat(int k) {
        if (k <= 0 || k > sany) {
            return false;
        }
        sany -= k;
        return true;
    }

    @Override
    public String toString() {
        return String.format("%-18s %7.1f тг  (%d дана)", atau, baga, sany);
    }
}

public class Katalog {
    public static void main(String[] args) {
        ArrayList<Kitap> kitaptar = new ArrayList<>();
        kitaptar.add(new Kitap("Абай жолы", 3200, 5));
        kitaptar.add(new Kitap("Көшпенділер", 4100, 2));
        kitaptar.add(new Kitap("Қазақ ертегілері", 1500, 10));
        kitaptar.add(new Kitap("Алгоритмдер", 8900, 1));

        kitaptar.sort(Comparator.comparingDouble(Kitap::getBaga));
        System.out.println("Бағасы бойынша:");
        for (Kitap k : kitaptar) {
            System.out.println("  " + k);
        }

        System.out.println(kitaptar.get(3).sat(1));   // соңғы кітап сатылды
        System.out.println(kitaptar.get(3).sat(1));   // енді жоқ

        double qor = 0;
        for (Kitap k : kitaptar) {
            qor += k.getBaga() * k.getSany();
        }
        System.out.printf("Қоймадағы құн: %.1f тг%n", qor);
    }
}

    Класты қалай жобалаймыз?

    Жаңа бағдарлама жазғанда «қандай класс керек?» деген сұрақ жиі қиын көрінеді. Қарапайым әдіс бар: есептің сипаттамасын оқып, зат есімдерге (кітап, оқушы, әмиян, қала) және етістіктерге (сатады, салады, алады, кемітеді) қараңыз. Зат есімдер - сыбайлас кластар мен өрістер; етістіктер - әдістер. Мысалы: «Кітапхана кітаптарды оқушыларға береді және қайтарып алады». Үш зат есім: Kitaphana, Kitap, Oqushy. Екі етістік: beru, qaytaryp aluy, олар Kitaphana класының әдістері болады.

    Әр класқа бір ғана жауапкершілік беріңіз (single responsibility). Егер класс сипаттамасында «және» сөзі көп кездессе (мысалы, «кітапты сақтайды және экранға шығарады және файлға жазады»), оны бөлу керек. Өрістерді мүмкіндігінше final жасаңыз: өзгермейтін нысанмен жұмыс істеу оңай, олар кездейсоқ бұзылмайды және оларды қауіпсіз бөлісуге болады. Конструктор нысанды әрқашан дұрыс күйде қалдыруы тиіс: жарамсыз деректі қабылдамай, IllegalArgumentException лақтырыңыз.

    Бір сұрақты өзіңізге қойыңыз: «Класты қолданған адам ішкі құрылымды білуі керек пе?» Жауап «жоқ» болса, инкапсуляция дұрыс. Мысалы, Hamyan ішінде қалдық long ретінде сақталады, ертең оны BigDecimal ауыстырсақ, сыртқы код (тек salu, aluy, getQaldyq қолданатын) өзгермей жұмыс істей береді. Нысандық бағдарламалаудың негізгі байлығы осы: ішкі шешімді еркін өзгерту мүмкіндігі.

    Өз компьютеріңде іске қос

    1. Бір файлда бірнеше класс болса, тек біреуі public және файл аты сол класс атымен бірдей (Katalog.java).
    2. Пакеті бар жоба: қалталар құрылымын жасаңыз (kz/dukan/), содан кейін түбір қалтадан javac kz/dukan/*.java Main.java және java Main.
    3. Класс жазып болған соң, оған toString қосуды әдетке айналдырыңыз: шығарғанда да, жөндегенде де өте ыңғайлы.

    Жиі қателер

    1. Нысанды new-сіз қолдану. Kitap k; k.atau = "x"; - k әлі ешнәрсеге көрсетпейді (компилятор «not initialized» дейді). Класс өрісі болса, null болып қалады да, NullPointerException шығады.
    2. Конструктордың алдына void жазу. void Kitap(...) - конструктор емес, жай әдіс!
    3. this-ті ұмыту. Конструктордың atau = atau; жолы параметрді өзіне меншіктейді де, өріс өзгермей қалады.
    4. Өрістерді public қалдыру. Деректі қорғау үшін private жасаңыз.
    5. static өріс пен нысан өрісін шатастыру. static ортақ, көшірмесі біреу.
    6. == арқылы нысанды салыстыру. == сілтемені салыстырады; мазмұн үшін equals керек.
    7. equals жазып, hashCode-ті ұмыту. HashSet пен HashMap қате жұмыс істейді.
    8. equals(Object) орнына equals(Kitap) жазу. Бұл қайта анықтау емес, қайта жүктеу; сондықтан @Override жазыңыз: компилятор ұстайды.
    9. null сілтемеге әдіс шақыру. NullPointerException: шақырар алдында тексеріңіз.
    10. Record өрісін өзгертуге тырысу. Record өзгермейді; өзгерту үшін жаңа record жасаңыз.

    Қорытынды

    • Класс - сызба (өрістер + әдістер), нысан - new арқылы жасалған дана;
    • Конструктор нысанды дайындайды; this - «осы нысан»; this(...) басқа конструкторды шақырады;
    • Инкапсуляция: өріс private, қол жеткізу getter/setter арқылы, ережені әдіс тексереді;
    • static мүшелер класқа тиесілі: ортақ санауыш, тұрақты, күйсіз көмекші әдіс;
    • toString, equals, hashCode - Object-тен келеді, көбіне қайта анықтау керек; equals пен hashCode әрқашан жұп;
    • record - өзгермейтін деректер класының қысқа жазылуы;
    • Пакет кластарды топтайды, import оларды көрсетеді, public пакеттен тыс жету үшін;
    • Нысан үймеде, айнымалыда сілтеме ғана; бірнеше сілтеме бір нысанды көрсете алады; null - нысансыз сілтеме;
    • GC қолжетімсіз нысандарды автоматты тазалайды.

    Келесі аптада кластар арасындағы қатынастарды үйренеміз: бір класс екіншісінің қасиеттерін мұра етіп алады, ортақ келісім-шарт интерфейс арқылы беріледі, ал бір сілтеме әртүрлі нысанды көрсете алады (полиморфизм).

    Өзіңізді тексеру тізімі

    • Өрістері, конструкторы және әдістері бар класс жаза аламын
    • this не үшін керек екенін және конструктор тізбегін түсіндіре аламын
    • Өрісті private етіп, тексеретін setter жаза аламын
    • static пен нысан мүшелерінің айырмашылығын білемін
    • toString, equals, hashCode жаза аламын және оларды бірге жазу керегін түсінемін
    • Стек/үйме диаграммасын сызып, сілтеме мен нысан айырмасын түсіндіре аламын
    • record қашан ыңғайлы екенін білемін

    Өзіңізді тексеріңіз

    1. Қай тұжырым класс пен нысан қатынасын дұрыс сипаттайды?

    Класс өрістер мен әдістерді сипаттайды, ал new оператормен жасалған нысанның өз өріс мәндері болады. Бір класстан қанша болса да нысан жасауға болады.

    2. Мына код не шығарады?

    class Sanau {
    static int jalpy = 0;
    int ozim = 0;

    Sanau() {
        jalpy++;
        ozim++;
    }
}

public class Q2 {
    public static void main(String[] args) {
        Sanau a = new Sanau();
        Sanau b = new Sanau();
        Sanau c = new Sanau();
        System.out.println(Sanau.jalpy + " " + c.ozim);
    }
}

    jalpy - static, барлық нысанға ортақ, үш конструктор оны 3-ке жеткізді. ozim - нысан өрісі, әр нысанның өзінде жеке, сондықтан c.ozim = 1. Нақты нәтиже: 3 1.

    3. Мына код не шығарады?

    class Nokta {
    private int x, y;
    Nokta(int x, int y) { this.x = x; this.y = y; }

    @Override
    public String toString() {
        return "(" + x + "; " + y + ")";
    }
}

public class Q3 {
    public static void main(String[] args) {
        Nokta p = new Nokta(3, 4);
        System.out.println("P = " + p);
    }
}

    Мәтінге нысанды жалғағанда Java toString()-ті шақырады. Біз оны қайта анықтағандықтан, нәтиже: P = (3; 4).

    4. Төмендегі кодта қате қайсы?
    class A { private int x = 1; }
    class B { void f() { A a = new A(); System.out.println(a.x); } }

    private мүше тек өз класының ішінде көрінеді. Компилятор «x has private access in A» хабарын береді. Шешімі - getter қосу: a.getX().

    5. Мына код не шығарады?

    class Qala {
    private int halyq;
    Qala(int halyq) { this.halyq = halyq; }
    int getHalyq() { return halyq; }
    void setHalyq(int h) { halyq = h; }
}

public class Q5 {
    public static void main(String[] args) {
        Qala a = new Qala(100);
        Qala b = a;
        b.setHalyq(250);
        System.out.println(a.getHalyq());
    }
}

    Qala b = a нысанды көшірмейді, тек сілтемені көшіреді. a мен b бір нысанды көрсетеді, сондықтан b арқылы жасалған өзгеріс a-дан да көрінеді. Нақты нәтиже: 250.

    6. Мына record үшін нәтиже қандай?

    record Nokta(int x, int y) { }

public class Q6 {
    public static void main(String[] args) {
        Nokta p = new Nokta(1, 2);
        Nokta q = new Nokta(1, 2);
        System.out.println(p.equals(q) + " " + (p == q));
    }
}

    Record equals-ті барлық өріс бойынша автоматты жасайды: екі нысан мазмұны бойынша тең (true). Бірақ == сілтемені салыстырады, ал олар әртүрлі нысандар (false). Нақты нәтиже: true false.

    7. Неге static әдіс ішінде this қолдануға болмайды?

    static әдіс нысансыз-ақ шақырылады (Math.sqrt(4)), сондықтан ол нысанның өрістеріне де, this-ке де тікелей жете алмайды. Ол тек static өрістермен жұмыс істей алады.

    8. Қай жағдайда нысан қоқыс жинаушы үшін босатуға үміткер болады?

    Java-да нысандарды қолмен өшірмейміз. Егер нысанға стектегі айнымалылардан немесе басқа қолжетімді нысандардан жету мүмкін болмаса (сілтемелер null болды не басқа нысанға ауысты), ол қолжетімсіз және GC оны босата алады.

    Жаттығулар

    Алты жаттығу: екі оңай, екі орташа, екі қиын. Шешімдерін өз компьютеріңде жазып, тексеріңіз.

    Оңай

    Санауыш

    Мына бағдарлама не шығарады? Жауабыңызды «a b» түрінде (екі сан, бос орынмен бөлініп) жазыңыз.

    class Oqushy {
    static int sany = 0;
    int nomer;

    Oqushy() {
        sany++;
        nomer = sany;
    }
}

public class Jat1 {
    public static void main(String[] args) {
        Oqushy a = new Oqushy();
        Oqushy b = new Oqushy();
        Oqushy c = new Oqushy();
        System.out.println(c.nomer + " " + Oqushy.sany);
    }
}
    Кеңес

    sany - static, nomer - әр нысанның өз өрісі. Үшінші нысан жасалғанда sany нешеге жетеді?

    Шешімі

    Үшінші нысанда sany = 3, ол nomer-ге де 3 болып көшеді. Сондықтан c.nomer = 3 және Oqushy.sany = 3.

    $ java Jat1

    Оңай

    Оқушы класы

    Oqushy классын жазыңыз: private final өрістері - аты-жөні (String), жасы (int), сыныбы (String); конструктор; toString. main-де үш оқушыдан массив жасап, оларды шығарыңыз.

    Кеңес

    Конструкторда this.ataui = ataui; түрінде жазыңыз. toString-ке @Override және public қосуды ұмытпаңыз.

    Шешімі

    Мысал шешім:

    class Oqushy {
    private final String ataui;
    private final int jas;

    Oqushy(String ataui, int jas, String synyp) {

    Орташа

    Қала халқы: сілтеме

    Мына бағдарлама не шығарады?

    class Qala {
    private String ataui;
    private int halyq;
    Qala(String ataui, int halyq) { this.ataui = ataui; this.halyq = halyq; }
    int getHalyq() { return halyq; }
    void setHalyq(int h) { halyq = h; }
}

public class Jat3 {
    public static void main(String[] args) {
        Qala q1 = new Qala("Астана", 1350000);
        Qala q2 = q1;
        q2.setHalyq(q2.getHalyq() + 50000);
        System.out.println(q1.getHalyq());

    Кеңес

    Qala q2 = q1; жолы көшіре ме, әлде екінші сілтеме жасай ма? Үймеде неше Qala нысаны бар?

    Шешімі

    Үймеде бір ғана нысан бар, q1 мен q2 екеуі де соны көрсетеді. q2 арқылы халық 1350000 + 50000 = 1400000 болды, q1 да сол нысанды көреді.

    $ java Jat3

    Орташа

    Аспап: equals

    Aspap классын жазыңыз: ataui (String) және baga (int) private final өрістері, баға теріс болса IllegalArgumentException лақтыратын конструктор, getter-лер, equals және hashCode. Сосын екі бірдей ("Қобыз", 78000) нысан жасап, a.equals(b) + " " + (a == b) шығарыңыз. Нәтиже қандай? (Жауап: екі сөз, бос орынмен.)

    Кеңес

    equals-те o instanceof Aspap a тексеріп, екі өрісті де салыстырыңыз. hashCode үшін Objects.hash(ataui, baga).

    Шешімі

    Мазмұны бірдей, бірақ екеуі new арқылы бөлек жасалды: equals - true, == - false.

    import java.util.Objects;

class Aspap {
    private final String ataui;
    private final int baga;

    Aspap(String ataui, int baga) {
        if (baga < 0) {
            throw new IllegalArgumentException("Баға теріс болмайды");
        }
        this.ataui = ataui;
        this.baga = baga;
    }

    String getAtaui() { return ataui; }
    int getBaga() { return baga; }

    @Override
    public boolean equals(Object o) {
        return o instanceof Aspap a && baga == a.baga && Objects.equals(ataui, a.ataui);
    }

    @Override
    public int hashCode() {
        return Objects.hash(ataui, baga);
    }
}

public class Jat4 {
    public static void main(String[] args) {
        Aspap a = new Aspap("Қобыз", 78000);
        Aspap b = new Aspap("Қобыз", 78000);
        System.out.println(a.equals(b) + " " + (a == b));
    }
}
    $ java Jat4
true false
    Өзін тексеру
    • equals екі өрісті де салыстырады
    • hashCode дәл сол өрістерді пайдаланады
    • Теріс баға IllegalArgumentException береді

    Қиын

    Әмиян амалдары

    Әмиянның басында 10 000 тг. Төмендегі әрекеттер ретімен орындалады: 1) 5 000 салу; 2) 20 000 алу; 3) 3 500 алу; 4) 1 200 салу. Әмиян қарыз берілмейді (қалдықтан артық алуға болмайды, теріс не нөл сома қабылданбайды). Соңында қалдық қанша? Содан кейін Hamyan классын жазып тексеріңіз.

    Кеңес

    Қадамдап жүріңіз: 10000 → 15000 → (20000 алу бас тартылды, 15000 қалады) → 11500 → ?

    Шешімі

    10 000 + 5 000 = 15 000. 20 000 алу мүмкін емес (15 000-нан артық): қалдық өзгермейді. 15 000 − 3 500 = 11 500. 11 500 + 1 200 = 12 700.

    class Hamyan {
    private long qaldyq;

    Hamyan(long bastapqy) {
        this.qaldyq = bastapqy;
    }

    boolean salu(long soma) {
        if (soma <= 0) return false;
        qaldyq += soma;
        return true;
    }

    boolean aluy(long soma) {
        if (soma <= 0 || soma > qaldyq) return false;
        qaldyq -= soma;
        return true;
    }

    long getQaldyq() { return qaldyq; }
}

public class HamyanOpe {
    public static void main(String[] args) {
        Hamyan h = new Hamyan(10000);
        h.salu(5000);
        h.aluy(20000);
        h.aluy(3500);
        h.salu(1200);
        System.out.println(h.getQaldyq());
    }
}
    $ java HamyanOpe
12700
    Өзін тексеру
    • Бас тартылған операция қалдықты өзгертпейді
    • Метод boolean қайтарады
    • Өріс private

    Кему ретімен: Алматы (2200000), Астана (1350000), Шымкент (1200000), Ақтөбе, Қарағанды. Үшінші - Шымкент.
