    5-апта

    Collections және generics

    Бір ғана айнымалы көп деректі сақтай алмайды. Бұл аптада Java-ның дайын жинақтарымен танысамыз: тізім, жиын, сөздік және кезек. HashMap-тың іші қалай жұмыс істейтінін көреміз, generics арқылы кодты қауіпсіз етеміз, ал Big-O кестесі арқылы қай жинақты қашан таңдау керегін үйренеміз.

    Бір ғана айнымалы жеткіліксіз

    Қазірге дейін біз бір сан, бір жол, бір нысан сақтайтын айнымалылармен жұмыс істедік. Массив (int[]) бірнеше мәнді сақтай алады, бірақ оның өлшемі өмір бойы өзгермейді. Ал нақты өмірде деректер саны күнде өзгеріп отырады: сыныпқа жаңа оқушы келеді, дүкен қоймасына тауар қосылады, ойынға жаңа ойыншы кіреді. Мұндай жағдайға Java-ның Collections Framework (collections framework, жинақтар жүйесі) дайын: нысандар тобын сақтаудың, іздеудің және сұрыптаудың дайын, жақсы жазылған құралдары.

    Аналогия: үй жиһазын қарастырыңыз. Шкаф - бұл «тізім»: заттар реті бойынша, әрқайсысының нөмірі бар. Қапшық - «жиын»: ішінде дәл қайталанатын зат болмайды. Мектептегі телефон кітапшасы - «сөздік»: аты бойынша нөмірін табасыз. Банктегі талон кезегі - «кезек»: бірінші келген бірінші қызмет алады. Java-да осы төрт ұғымның әрқайсысына интерфейс және бірнеше іске асыру бар.

    Бір қарағанда терминдер көп сияқты, бірақ ұстаным қарапайым: интерфейс не істей алатынын (List, Set, Map, Queue), ал класс қалай істейтінін (ArrayList, HashSet, TreeMap...) көрсетеді. Төмендегі карта осы жүйені көрсетеді:

    Мәтіндік балама: жоғарғы жағында Collection интерфейсі, одан List, Set және Queue тармақталады. List үшін ArrayList және LinkedList, Set үшін HashSet, LinkedHashSet, TreeSet, Queue үшін ArrayDeque, PriorityQueue, LinkedList қолданылады. Map интерфейсі Collection-нан мұрагерленбейді, бөлек тұрады, оның іске асырулары: HashMap, LinkedHashMap, TreeMap.

    Бұл апта үш үлкен бөліктен тұрады: алдымен жинақтарды қолдануды үйренеміз (List, Set, Map, Queue), содан кейін generics арқылы олардың қалай қауіпсіз жұмыс істейтінін көреміз, ал соңында қай жинақ қашан жылдам екенін Big-O кестесімен салыстырамыз.

    Импорт

    Жинақ кластары java.util пакетінде тұр. Файлдың басына import java.util.List; сияқты жолдар жазу керек, не import java.util.*; деп бәрін бірден алуға болады. Бұл лекциядағы мысалдар нақты импортпен жазылған, бұл оқуға ыңғайлы.

    List: ArrayList және LinkedList

    List (list, тізім) - реттелген жинақ: әр элементтің индексі бар (0-ден басталады), қайталанатын элементтерге рұқсат. Ең жиі қолданылатын жүзеге асыруы - ArrayList: ол ішінде массив ұстайды және толса, өзі үлкенірек массив жасап, көшіріп алады.

    import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> qalalar = new ArrayList<>();
        qalalar.add("Алматы");
        qalalar.add("Астана");
        qalalar.add("Шымкент");
        qalalar.add(1, "Қарағанды");           // индекс бойынша кірістіру

        System.out.println(qalalar);
        System.out.println("Өлшемі: " + qalalar.size());
        System.out.println("0-элемент: " + qalalar.get(0));

        qalalar.set(0, "Алматы (Верный)");
        qalalar.remove("Шымкент");              // мән бойынша жою
        qalalar.remove(0);                      // индекс бойынша жою

        System.out.println(qalalar);
        System.out.println("Астана бар ма? " + qalalar.contains("Астана"));
        System.out.println("Астананың индексі: " + qalalar.indexOf("Астана"));

        for (String q : qalalar) {
            System.out.println("- " + q);
        }
    }
}

    Мұнда бірнеше үлгі бар:

    • List<String> жазбасындағы <String> - бұл тізімге тек жол салуға болады деген мағына (generics, мұны төменде көреміз).
    • Айнымалының типін интерфейс (List) етіп, нысанды іске асыру (new ArrayList<>()) етіп жазамыз. Сонда кейін ArrayList орнына басқа тізімді қойсақ, қалған код өзгермейді. Бұл төртінші аптадағы полиморфизм.
    • remove("Шымкент") мәнді іздеп жояды, ал remove(0) индекс бойынша жояды. Екеуі де бір сөзбен жазылғанымен, нәтижесі әртүрлі. Төмендегі «Жиі қателер» бөлімінде List<Integer> үшін бұл қауіпті тұзақ екенін көреміз.
    • <> («алмаз операторы») компиляторға оң жақтағы типті сол жақтан шығарып алуды айтады.

    LinkedList басқа жолмен жұмыс істейді: ол массив емес, бір-бірімен сілтемемен байланысқан түйіндер тізбегі. Әр түйін алдыңғысы мен келесісін біледі. Аналогия: ArrayList - кинотеатрдағы нөмірленген қатар орындар (6-орынға бірден барасыз), ал LinkedList - бір-бірінің қолынан ұстаған балалар тізбегі (6-баланы табу үшін бірінші баладан санау керек).

    import java.util.LinkedList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        // тип - List, іске асыру - LinkedList: API бірдей
        List<String> kezek = new LinkedList<>();
        kezek.add("Айгерім");
        kezek.add("Бауыржан");
        kezek.add("Дана");
        System.out.println(kezek + " " + kezek.get(1));

        // LinkedList-ке тән әдістер үшін нақты тип керек
        LinkedList<String> ll = new LinkedList<>(kezek);
        ll.addFirst("Асылбек");
        ll.addLast("Ернар");
        System.out.println(ll);
        System.out.println(ll.removeFirst() + " және " + ll.removeLast() + " шығарылды");
        System.out.println(ll);
    }
}

    Set: қайталанбайтын жинақ

    Set (set, жиын) - қайталанатын элементті қабылдамайтын жинақ. Сурет салып қарасақ: бұл математикадағы жиын, мысалы, «сыныптағы қолданылған әріптер». Бір әріп бір рет қана болады. Жиында индекс жоқ, get(i) әдісі де жоқ: тек «бар ма?» (contains) деп сұраймыз.

    Үш негізгі жүзеге асыру бар, олардың айырмашылығы тек элементтердің реті:

    • HashSet - ең жылдам, бірақ ретіне кепілдік жоқ.
    • LinkedHashSet - қосылу ретін сақтайды.
    • TreeSet - әрқашан сұрыпталған күйде (өсу ретімен) ұстайды.
    import java.util.HashSet;
import java.util.LinkedHashSet;
import java.util.Set;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        String[] sozder = {"қалам", "дәптер", "қалам", "кітап", "дәптер", "сызғыш"};

        Set<String> hash = new HashSet<>();
        Set<String> linked = new LinkedHashSet<>();
        Set<String> tree = new TreeSet<>();
        for (String s : sozder) {
            hash.add(s);
            linked.add(s);
            tree.add(s);
        }
        System.out.println("Бастапқы: " + sozder.length + " сөз");
        System.out.println("HashSet:       " + hash.size() + " " + hash);
        System.out.println("LinkedHashSet: " + linked.size() + " " + linked);
        System.out.println("TreeSet:       " + tree.size() + " " + tree);

        System.out.println(tree.add("қалам"));     // қайталанса false
        System.out.println(tree.contains("кітап"));
    }
}

    Сұрыптау қазақ әліпбиі бойынша емес

    TreeSet, TreeMap және Collections.sort жолдарды Unicode коды бойынша салыстырады: бас әріптер кіші әріптерден бұрын келеді, ал ә, ө, ү, қ сияқты қазақ әріптері кейбір орыс әріптерінен кейін тұрады. Сондықтан өзен сөзі қала сөзінен кейін шығады, ал Алматы алма сөзінен бұрын тұрады. Шынайы қазақ әліпбиі бойынша сұрыптау керек болса, java.text.Collator кластын қарастырыңыз. Біздің мысалдарда нәтижелерді осы ескертумен оқыңыз.

    Map: кілт және мән

    Map (map, сөздік, карта) мәндерді кілт бойынша сақтайды: «кілт → мән» жұптары. Бұл ең пайдалы құрылым: оқушы аты → бағасы, қала → халық саны, сөз → қайталану саны. Кілттер бірегей болады, ал мәндер қайталана алады.

    Мәтіндегі сөздердің қанша рет кездескенін санайтын классикалық мысалды алайық (өте жиі кездесетін үлгі):

    import java.util.HashMap;
import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        String maqal = "жеті рет өлшеп бір рет кес жеті рет";
        Map<String, Integer> sanaq = new HashMap<>();
        for (String s : maqal.split(" ")) {
            sanaq.put(s, sanaq.getOrDefault(s, 0) + 1);
        }
        System.out.println("жеті: " + sanaq.get("жеті"));
        System.out.println("жоқ сөз: " + sanaq.get("қала"));
        System.out.println("кілт саны: " + sanaq.size());

        // TreeMap: кілттер әліпби ретімен
        Map<String, Integer> tree = new TreeMap<>(sanaq);
        for (Map.Entry<String, Integer> e : tree.entrySet()) {
            System.out.println(e.getKey() + " -> " + e.getValue());
        }

        // merge: қысқа жазу
        Map<String, Integer> m2 = new TreeMap<>();
        for (String s : maqal.split(" ")) {
            m2.merge(s, 1, Integer::sum);
        }
        System.out.println(m2);
    }
}

    Қадамдап оқимыз:

    • sanaq.put(s, sanaq.getOrDefault(s, 0) + 1): «осы сөздің қазіргі санын ал (жоқ болса 0), 1 қос да қайта жаз».
    • sanaq.get("қала") жоқ кілтті сұрағанда null қайтарады. int айнымалыға салмаңыз, әйтпесе NullPointerException шығады.
    • TreeMap кілттерді сұрыптап ұстайды; біз оны бар HashMap-тан көшіріп жасадық. «өлшеп» соңында тұр: Unicode реті.
    • merge(кілт, 1, Integer::sum) - сол есептеуді қысқа жазудың заманауи жолы: «кілт жоқ болса 1 қой, бар болса, бұрынғы мәнмен 1-ді қос».
    • Map.Entry - бір «кілт-мән» жұбы; entrySet() арқылы екеуін бірге аралаймыз.

    Map-тың да үш негізгі нұсқасы бар (HashMap, LinkedHashMap, TreeMap), олардың айырмашылығы Set-тегідей: жылдамдық пен тәртіп.

    HashMap іштей қалай жұмыс істейді

    HashMap-тың керемет жылдамдығы қайдан келеді? Телефон кітапшасынан «Сәлімді» іздеп отырсақ, әр беттен өтіп шығу керек. Ал егер кітапшаның әр әріпке бөлек қапшығы болса, «С» қапшығын ашып, оның ішінен ғана іздер едік. Бұл хеш-кесте (hash table) идеясы.

    Іште HashMap «қораптар» (buckets) массивін ұстайды (бастапқыда 16 қорап). Кілт қосқанда:

    1. Кілттің hashCode() әдісі шақырылып, бүтін сан (hash) алынады.
    2. Осы саннан қорап нөмірі есептеледі: h & (n - 1) (мұнда n - қорап саны).
    3. Түйін сол қорапқа қойылады. Егер қорапта басқа кілт тұрса (соқтығыс, collision), түйіндер тізбекке жалғанады.
    4. Іздегенде де сол жол: хешті есептейді, қорапты табады, ішіндегі бірнеше түйінді equals арқылы салыстырады.

    Нақты сандармен көрейік. Мына код біздің қала аттарының қорап нөмірін есептейді (Java HashMap ішінде дәл осылай жасайды):

    public class Main {
    // HashMap-тің ішіндегі қорап нөмірін есептеу тәсілі (кесте өлшемі n = 16)
    static int qorap(String kilt, int n) {
        int h = kilt.hashCode();
        h = h ^ (h >>> 16);          // HashMap биттерді "араластырады"
        return h & (n - 1);
    }

    public static void main(String[] args) {
        String[] kilter = {"Алматы", "Астана", "Шымкент", "Атырау", "Aa", "BB"};
        for (String k : kilter) {
            System.out.printf("%-8s hashCode=%11d  қорап(16)=%2d%n", k, k.hashCode(), qorap(k, 16));
        }
    }
}

    Мәтіндік балама: 16 қорапты кесте. 0-қорапта Aa және BB тізбегі, 2-қорапта Алматы және Шымкент, 3-қорапта Астана, 14-қорапта Атырау; қалған қораптар бос.

    Назар аударыңыз: «Алматы» мен «Шымкент» бір қорапқа (2) түсті, бұл соқтығыс. Бірақ ештеңе бұзылған жоқ: екеуі де тізбекте тұр, іздеу сәтті болады. Aa және BB жолдарының hashCode() мәні дәл бірдей (2112) болатыны бұрыннан белгілі «қызық»: бірдей хеш не бірдей кілт дегенді білдірмейді. Сондықтан equals әрқашан соңғы төреші.

    Бұдан екі маңызды қорытынды шығады:

    • Соқтығыс аз болса, іздеу дерлік бірден болады: O(1). Тізбек ұзарса, баяулайды. Java өте ұзын тізбекті теңестірілген ағашқа айналдырады, ал қораптар тым толса, кестені екі есе үлкейтіп, бәрін қайта таратады.
    • Өз класыңызды HashMap/HashSet кілті етіп қолдансаңыз, equals пен hashCode-ты бірге жазуыңыз керек (4-аптадағы Object әдістері). Мұны келесі мысалда көреміз:
    import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Set;

class Nokat {
    final int x, y;
    Nokat(int x, int y) { this.x = x; this.y = y; }
}

class NokatH {
    final int x, y;
    NokatH(int x, int y) { this.x = x; this.y = y; }
    @Override public boolean equals(Object o) {
        return o instanceof NokatH p && p.x == x && p.y == y;
    }
    @Override public int hashCode() { return 31 * x + y; }
}

public class Main {
    public static void main(String[] args) {
        Map<Nokat, String> a = new HashMap<>();
        a.put(new Nokat(1, 2), "Алматы");
        System.out.println("equals/hashCode жоқ: " + a.get(new Nokat(1, 2)));

        Map<NokatH, String> b = new HashMap<>();
        b.put(new NokatH(1, 2), "Алматы");
        System.out.println("equals/hashCode бар: " + b.get(new NokatH(1, 2)));

        Set<String> s = new HashSet<>();
        s.add("Aa");
        s.add("BB");        // hashCode бірдей, бірақ мәндері басқа
        System.out.println(s.size() + " " + s.contains("Aa") + " " + s.contains("BB"));
    }
}

    Nokat класында екі әдіс те жоқ: сондықтан екінші new Nokat(1, 2) басқа нысан, хеші де басқа, және HashMap оны таппай null қайтарды. Ал NokatH-та equals пен hashCode дұрыс жазылғандықтан кілт табылды. Соңғы жолда Aa мен BB бір қорапта тұрса да, жиын екеуін де бөлек сақтады (өлшемі 2).

    Кілт ретінде өзгермейтін нысан қолданыңыз

    Кілттің hashCode() нәтижесі кілтті қосқаннан кейін өзгермеуі керек. Сондықтан кілт ретінде String, Integer, record сияқты өзгермейтін (immutable) нысандарды алыңыз. record equals пен hashCode-ты автоматты жасап береді, сондықтан ол өте жақсы кілт.

    Итератор

    Жинақты аралаудың біз білетін жолы - for (T x : жинақ). Бұл жол ішінде итераторды (iterator) қолданады. Итератор - жинақтың «меңзері» (бетбелгі сияқты): hasNext() әрі қарай элемент бар ма деп сұрайды, next() келесісін береді, ал remove() соңғы берген элементті жинақтан алып тастайды.

    Неге оны қолмен қолданамыз? Себебі аралап жүргенде жинақтан элемент жоюдың қауіпсіз жолы бір ғана: итератордың өзінің remove() әдісі.

    import java.util.ArrayList;
import java.util.Iterator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> baldar = new ArrayList<>(List.of(45, 62, 38, 90, 55, 71));

        // Iterator арқылы қауіпсіз жою
        Iterator<Integer> it = baldar.iterator();
        while (it.hasNext()) {
            int b = it.next();
            if (b < 50) {
                it.remove();
            }
        }
        System.out.println("50-ден жоғары: " + baldar);

        // for-each ішінде жоюға тырысу
        try {
            for (Integer b : baldar) {
                if (b == 62) {
                    baldar.remove(b);
                }
            }
        } catch (java.util.ConcurrentModificationException e) {
            System.out.println("ConcurrentModificationException ұсталды");
        }

        // removeIf - ең қысқа жол
        baldar.removeIf(b -> b > 80);
        System.out.println(baldar);
    }
}
    $ javac Main.java && java Main
50-ден жоғары: [62, 90, 55, 71]
ConcurrentModificationException ұсталды
[55, 71]
    • Бірінші цикл итератор арқылы 50-ден төмен баллдарды жойды. Бәрі дұрыс.
    • Екіншісінде for-each ішінде baldar.remove(b) шақырып едік, Java ConcurrentModificationException лақтырды. Бұл «аралап жүргенде жинақты басқа жолмен өзгерттіңіз» деген қорғаныс. Қателіктің атауын есте сақтаңыз: ол көп ағынды бағдарламамен байланысты емес, қарапайым цикл ішінде де шығады.
    • Үшінші жол - ең заманауи: removeIf(шарт) бір жолмен шартқа сәйкес барлығын жояды. (b -> b > 80 - lambda өрнегі, оны келесі лекцияда толық үйренеміз.)
    Жасырын тұзақ

    Тізімнің соңғысынан бір бұрынғы элементін for-each ішінде жойсаңыз, қате шықпай қалуы мүмкін (бұл итератордың ішкі есептеуінен). Бұл тағы да үнсіз қате: цикл соңғы элементті өткізіп жібереді. Сондықтан ереже өзгермейді: аралап жүргенде жойғыңыз келсе, итераторды не removeIf-ті қолданыңыз.

    Generics: қауіпсіз «жалпы» типтер

    List<String> жазбасындағы <String> не береді? Ол болмаған кезде (Java 5-тен бұрын) тізім Object нысандарын сақтайтын, оған жол да, сан да салуға болатын, ал алып жатқанда қолмен түрлендіру керек болатын. Қателік тек орындау кезінде білінетін. Generics (generics, жалпыланған типтер) қателікті компиляция кезіне көшіреді: компилятор List<String> ішіне санды салуға рұқсат етпейді.

    Аналогия: «шай ыдысы» мен «қант ыдысы» - сыртқы пішіні бірдей, бірақ жазуы басқа. Ыдысқа «қант» деп жазылса, оған тұз салып қоймайсыз. <T> дегеніміз - «ыдыстағы заттың түрі әзірге белгісіз, оны қолданғанда айтамыз» деген толтырғыш, type parameter деп аталады.

    Өз generic класымызды жазайық:

    import java.util.List;

class Quty<T> {
    private T mazmun;

    Quty(T mazmun) { this.mazmun = mazmun; }

    T al() { return mazmun; }
    void sal(T jana) { this.mazmun = jana; }
}

class Jup<K, V> {
    final K kilt;
    final V man;
    Jup(K kilt, V man) { this.kilt = kilt; this.man = man; }
    @Override public String toString() { return "(" + kilt + ", " + man + ")"; }
}

public class Main {
    // шектелген generic әдіс: T салыстырыла алатын болуы керек
    static <T extends Comparable<T>> T maks(List<T> tizim) {
        T eng = tizim.get(0);
        for (T x : tizim) {
            if (x.compareTo(eng) > 0) {
                eng = x;
            }
        }
        return eng;
    }

    public static void main(String[] args) {
        Quty<String> a = new Quty<>("домбыра");
        Quty<Integer> b = new Quty<>(2024);
        String s = a.al();           // түрлендіру керек емес
        int n = b.al() + 1;
        System.out.println(s + " " + n);

        // a.sal(5);   // компиляция қатесі: String күтілді

        System.out.println(maks(List.of(3, 17, 9)));
        System.out.println(maks(List.of("Алматы", "Қостанай", "Атырау")));
        System.out.println(new Jup<>("Алматы", 2_000_000));
    }
}

17
Қостанай

    Не болып жатыр:

    • class Quty<T> - T типті құрастыратын класс. Quty<String> дегенде T орнына String қойылады. String s = a.al(); жолында түрлендіру қажет емес, компилятор типті біледі.
    • Jup<K, V> - екі типті параметрі бар класс (кілт және мән), Map<K,V>-ке ұқсас.
    • a.sal(5) деген жол (комментарийде) компиляцияда қате берер еді, себебі Quty<String>-ке сан салуға болмайды.
    • <T extends Comparable<T>> T maks(List<T> tizim) - generic әдіс. extends Comparable<T> деген шектеу «T салыстырыла алатын болуы керек» дегенді білдіреді. Сондықтан бұл әдіс Integer үшін де, String үшін де жұмыс істейді, бірақ compareTo жоқ кластарға берсек, компилятор қате береді. Жолдар үшін ең үлкені Unicode ретімен «Қостанай» болды.

    Generics-тің екі шектеуі бар, олар бастаушыларды таң қалдырады:

    • List<int> деп жазуға болмайды: тип параметрі тек сілтеме типі бола алады. Дұрысы: List<Integer>. Java int ↔ Integer арасында автоматты түрлендіреді (autoboxing).
    • List<Integer> типі List<Number> типіне жатпайды, ол ұрпақ болса да. Сондықтан жалпы ереже керек, ол келесі бөлімде.

    Wildcard: ? белгісі

    Бізге кез келген сан тізімінің қосындысын алатын әдіс керек делік. List<Number> параметрін алатын әдіс List<Integer>-ті қабылдамайды. Аналогия: қой қорасы «жалпы жануарлар қорасы» емес, оған жылқыны кіргізіп жіберуге болмайды. Компилятор да дәл солай: List<Integer> мен List<Number> бір-бірінің орнына жүрмейді. Мұны wildcard (?) шешеді.

    • List<? extends Number> - «Number-дің кез келген ұрпағының тізімі». Одан оқуға болады (кез келген элемент - Number), бірақ қосуға болмайды, себебі нақты тип белгісіз (тізім List<Double> болуы мүмкін, ал біз оған Integer қоссақ, бұзылады).
    • List<? super Integer> - «Integer-дің кез келген ата-типінің тізімі» (Integer, Number, Object). Оған Integer қосуға болады, бірақ одан оқығанда тек Object аламыз.

    Бұл «оқу үшін extends, жазу үшін super» ережесі деп аталады (PECS: producer extends, consumer super).

    import java.util.ArrayList;
import java.util.List;

public class Main {
    // ? extends Number: Number-дің кез келген ұрпағының тізімін ОҚИМЫЗ
    static double jiny(List<? extends Number> san) {
        double s = 0;
        for (Number n : san) {
            s += n.doubleValue();
        }
        return s;
    }

    // ? super Integer: Integer қоса алатын тізімге ЖАЗАМЫЗ
    static void toltyr(List<? super Integer> tizim) {
        for (int i = 1; i <= 3; i++) {
            tizim.add(i * 10);
        }
    }

    public static void main(String[] args) {
        List<Integer> a = List.of(1, 2, 3);
        List<Double> b = List.of(1.5, 2.5);
        System.out.println(jiny(a) + " " + jiny(b));

        List<Number> sandar = new ArrayList<>();
        List<Object> nysandar = new ArrayList<>();
        toltyr(sandar);
        toltyr(nysandar);
        System.out.println(sandar + " " + nysandar);
    }
}
    $ javac Main.java && java Main
6.0 4.0
[10, 20, 30] [10, 20, 30]

    jiny әдісі List<Integer> пен List<Double>-ді де қабылдады: екеуіне де ? extends Number сәйкес. Ал toltyr әдісі Integer қосу үшін List<Number> пен List<Object> тізімдерін де қабылдады. Wildcard-ты қазір терең меңгерудің қажеті жоқ: оның идеясын білсеңіз жеткілікті, ал көбіне List<? extends T> жазбасын тек кітапхана әдістерінің қолтаңбасынан оқисыз.

    Comparable және Comparator

    Сандар мен жолдарды Java өзі салыстыра алады. Ал сіздің Oqushy класыңыздың нысандарын қалай сұрыптаймыз: баға бойынша ма, ат бойынша ма? Java-да екі құрал бар:

    • Comparable (Comparable): класстың «табиғи реттілігі». Класс өзі compareTo әдісін жазады. Бір ғана реттілік болады.
    • Comparator (Comparator): сырттан берілетін қосымша реттілік. Қалағанша жасауға болады.

    compareTo(o) мәні теріс (бұл нысан бұрын келеді), нөл (тең) немесе оң (бұл нысан кейін келеді) болып келеді.

    import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

class Oqushy implements Comparable<Oqushy> {
    final String aty;
    final int bal;

    Oqushy(String aty, int bal) {
        this.aty = aty;
        this.bal = bal;
    }

    // табиғи реттілік: балы жоғарылар алда
    @Override
    public int compareTo(Oqushy o) {
        return Integer.compare(o.bal, this.bal);
    }

    @Override
    public String toString() {
        return aty + ":" + bal;
    }
}

public class Main {
    public static void main(String[] args) {
        List<Oqushy> sinip = new ArrayList<>(List.of(
            new Oqushy("Дана", 85), new Oqushy("Ерлан", 92),
            new Oqushy("Айдана", 85), new Oqushy("Нұрлан", 70)));

        sinip.sort(null);                               // Comparable қолданылады
        System.out.println("Бал бойынша: " + sinip);

        sinip.sort(Comparator.comparing(o -> o.aty));   // ат бойынша
        System.out.println("Ат бойынша:  " + sinip);

        sinip.sort(Comparator.comparingInt((Oqushy o) -> o.bal)
                              .reversed()
                              .thenComparing(o -> o.aty));
        System.out.println("Бал↓, ат↑:   " + sinip);
    }
}

Ат бойынша:  [Айдана:85, Дана:85, Ерлан:92, Нұрлан:70]
Бал↓, ат↑:   [Ерлан:92, Айдана:85, Дана:85, Нұрлан:70]

    Назар аударатын жайттар:

    • compareTo ішінде Integer.compare(o.bal, this.bal) жаздық, яғни аргументтерді кері бердік: сонда үлкен балл алда тұрады (кему реті).
    • sinip.sort(null) - «табиғи реттілікті қолдан» дегенді білдіреді.
    • Comparator.comparing(o -> o.aty) атының бойынша салыстырады; .reversed() кері бұрады; .thenComparing(...) теңдік болғанда келесі шартқа өтеді.
    • Дана мен Айдана екеуінің де балы 85. Бірінші сұрыптауда олардың реті бастапқы тізімдегідей қалды: Java тізім сұрыптауы тұрақты (stable), яғни тең элементтердің өзара тәртібін бұзбайды.

    Мұндағы lambda жазбасына (o -> o.aty) қазір тереңдеп кірмейміз. Оқылуы: «o берілсе, o.aty қайтар». Келесі лекцияда толық түсіндіріледі.

    Collections утилиталары

    Collections (соңында s!) - жинақтармен жұмыс істейтін дайын статик әдістер жиынтығы. Ең пайдалылары:

    import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.Random;

public class Main {
    public static void main(String[] args) {
        List<Integer> san = new ArrayList<>(List.of(40, 15, 90, 15, 62));

        Collections.sort(san);
        System.out.println("sort:      " + san);
        Collections.reverse(san);
        System.out.println("reverse:   " + san);
        Collections.shuffle(san, new Random(7));    // seed бекітілген: нәтиже әр жолы бірдей
        System.out.println("shuffle:   " + san);
        System.out.println("max / min: " + Collections.max(san) + " / " + Collections.min(san));
        System.out.println("frequency(15): " + Collections.frequency(san, 15));

        List<Integer> oqu = Collections.unmodifiableList(san);
        try {
            oqu.add(1);
        } catch (UnsupportedOperationException e) {
            System.out.println("unmodifiableList өзгертілмейді");
        }

        List<String> qaz = List.of("а", "ә");
        try {
            qaz.add("б");
        } catch (UnsupportedOperationException e) {
            System.out.println("List.of өзгертілмейді");
        }
        System.out.println(Collections.binarySearch(List.of(10, 20, 30, 40), 30));
    }
}

    • sort, reverse, shuffle - тізімнің өзін өзгертеді. shuffle-ға Random(7) бердік (7 - «seed»), сондықтан нәтиже әр жолы бірдей: тест жазғанда бұл өте ыңғайлы.
    • max, min, frequency - есептеу.
    • Collections.unmodifiableList(...) пен List.of(...) - өзгертілмейтін тізім қайтарады. Оларға add шақырсаңыз, UnsupportedOperationException шығады. Жақсы бағдарламалауда бір жерден жасалған тізімді басқаға «тек оқу» үшін беру әдеті бар.
    • binarySearch - сұрыпталған тізімнен жылдам іздеу (жауап - индекс, біздегі 30 екінші индексте). Тізім сұрыпталмаған болса, нәтиже дұрыс болмайды.

    Сондай-ақ Arrays классы да бар: Arrays.sort(massiv), Arrays.asList(...), Arrays.toString(massiv). Массивті жинаққа не кері аударуда бұл өте пайдалы.

    Queue, Deque және PriorityQueue

    Кейде реттің мәні элементтердің қосылу ретімен анықталады. Queue (queue, кезек) - FIFO (first in, first out): бірінші келген бірінші шығады. Банктегі талон кезегі дәл осындай.

    Deque (double-ended queue, екі жақты кезек, «дек» деп оқылады) екі шетінен де қосып-алуға мүмкіндік береді; сол себепті оны стек (stack, LIFO: соңғы келген бірінші шығады) ретінде де қолданамыз. Браузердегі «Артқа» батырмасы - стек: ең соңғы ашылған бет бірінші жабылады.

    PriorityQueue (priority queue, басымдықты кезек) бұдан да ақылды: элементтер қосылу ретімен емес, басымдық бойынша шығады. Жедел жәрдемдегі науқастарды елестетіңіз: ауыр жағдайдағы науқас бірінші, ол кеш келсе де.

    import java.util.ArrayDeque;
import java.util.Deque;
import java.util.PriorityQueue;
import java.util.Queue;

public class Main {
    record Tapsyrma(String atau, int mangyzdylyq) {}

    public static void main(String[] args) {
        // Queue: FIFO - банктегі кезек
        Queue<String> kezek = new ArrayDeque<>();
        kezek.offer("Айгүл");
        kezek.offer("Бекзат");
        kezek.offer("Сая");
        System.out.println("Алдыңғы: " + kezek.peek());
        System.out.println("Қызмет көрсетілді: " + kezek.poll());
        System.out.println("Кезекте қалды: " + kezek);

        // Deque екі жақтан да жұмыс істейді; стек ретінде қолдануға болады
        Deque<String> qapt = new ArrayDeque<>();
        qapt.push("1-бет");
        qapt.push("2-бет");
        qapt.push("3-бет");
        System.out.println("Артқа: " + qapt.pop() + ", " + qapt.pop());

        // PriorityQueue: ең кіші (немесе компаратор бойынша ең маңызды) бірінші шығады
        PriorityQueue<Tapsyrma> pq = new PriorityQueue<>(
            (x, y) -> Integer.compare(y.mangyzdylyq(), x.mangyzdylyq()));
        pq.add(new Tapsyrma("Үй жинау", 2));
        pq.add(new Tapsyrma("Емтиханға дайындық", 9));
        pq.add(new Tapsyrma("Футбол", 4));
        while (!pq.isEmpty()) {
            Tapsyrma t = pq.poll();
            System.out.println(t.mangyzdylyq() + " - " + t.atau());
        }
    }
}

    PriorityQueue-ды басып шығарса, сұрыпталған болмайды

    PriorityQueue ішінде «үйме» (heap) құрылымын ұстайды: ең басты элемент бірінші тұрады, ал қалғаны толық сұрыпталмаған. Тек poll() арқылы алғанда ғана реті дұрыс шығады. System.out.println(pq) реттелген тізімді көрсетеді деп күтпеңіз.

    Операциялар күрделілігі (Big-O)

    Қай жинақты таңдау керек? Жауап: ол қандай операция жиі болатынына байланысты. Операцияның қаншалықты жылдам екенін көрсету үшін Big-O белгілеуі (Big-O notation) қолданылады. Ол «деректер n есе көбейсе, жұмыс уақыты қалай өседі?» деген сұраққа жауап береді.

    • O(1) - тұрақты: деректер қанша болса да, бір қадам. Мысалы, массивтен индекспен элемент алу. Ұқсастығы: кітапхананың дәл нөмірі белгілі сөресінен кітап алу.
    • O(log n) - логарифмдік: әр қадам мәселенің жартысын шешеді. 1 000 000 элементте бар болғаны шамамен 20 қадам. Ұқсастығы: сөздіктен сөз іздеу, ортасынан ашып, жартысын тастап отырасыз.
    • O(n) - сызықтық: әр элементті қарап шығу. 1 000 000 элемент - 1 000 000 қадам. Ұқсастығы: бүкіл кітапхананы бір-бірлеп қарап шығу.

    Кестеден шығатын практикалық ережелер:

    • Көп «бар ма?» сұрау керек болса, List.contains емес, HashSet қолданыңыз: 1 000 000 элементте O(n) мен O(1) арасындағы айырма миллион есе болуы мүмкін.
    • Индекспен көп оқитын болсаңыз, ArrayList ең жақсы.
    • Кілт бойынша іздеу керек болса, HashMap; сұрыпталған күйде керек болса, TreeMap.
    • Тізімді сұрыптау O(n log n).

    Жиі қателер

    1. List<Integer> ішінде remove(int) пен remove(Object) шатасуы

    list.remove(1) - индекс 1-дегі элементті жояды. Мәні 1 болатын элементті жою үшін list.remove(Integer.valueOf(1)) жазыңыз. Бұл 1-жаттығуда кездеседі.

    2. Аралап жүргенде жинақты өзгерту

    for-each ішінде list.remove(x) не list.add(x) - ConcurrentModificationException. Итераторды не removeIf-ті қолданыңыз.

    3. equals/hashCode жазбау

    Өз класыңызды HashMap кілті етіп, equals пен hashCode-сыз қолдансаңыз, get әрқашан null қайтарады, өйткені екі «бірдей» нысан жад бойынша әртүрлі.

    4. null-ға түрлендіру

    int x = map.get("жоқ кілт"); - NullPointerException: get null қайтарады, ал null int бола алмайды. getOrDefault не containsKey қолданыңыз.

    5. HashSet/HashMap ретіне сену

    Хеш-жинақтардың ретіне кепілдік жоқ. Ретті керек етсеңіз, LinkedHash... не Tree... таңдаңыз.

    6. List.of ішіне элемент қосу

    List.of, Set.of, Map.of өзгертілмейтін жинақ қайтарады, add шақырсаңыз, UnsupportedOperationException. Өзгертетін көшірме керек болса: new ArrayList<>(List.of(...)).

    Бүгін біз Java-ның дерек құрылымдарымен таныстық:

    • List - реттелген, қайталануға рұқсат; ArrayList (әдетте таңдау) және LinkedList;
    • Set - қайталанбайды; HashSet (жылдам), LinkedHashSet (қосылу реті), TreeSet (сұрыпталған);
    • Map - кілт → мән; HashMap, LinkedHashMap, TreeMap; getOrDefault, merge, computeIfAbsent;
    • HashMap кілт хешінен қорап нөмірін есептейді; өз кілт класына equals пен hashCode қажет;
    • Iterator - жинақты аралап, қауіпсіз жоюға мүмкіндік береді; removeIf қысқа жол;
    • generics - <T> арқылы типті қауіпсіз ету; <T extends Comparable<T>> шектеуі; wildcard: ? extends оқуға, ? super жазуға;
    • Comparable - табиғи реттілік, Comparator - сырттан берілетін реттілік;
    • Collections утилиталары: sort, reverse, shuffle, max, min, frequency, unmodifiableList;
    • Queue (FIFO), Deque (екі жақты, стек), PriorityQueue (басымдық);
    • Big-O: O(1), O(log n), O(n) - жинақты операцияға қарай таңдаймыз.
    • Мен List, Set, Map арасындағы айырмашылықты түсіндіре аламын.
    • Мен өз тапсырмама қажетті жинақты (мысалы, сөз санау үшін Map) таңдай аламын.
    • Мен HashMap-тың қорап жүйесін өз сөзіммен айта аламын.
    • Мен өз кілт класыма equals және hashCode жаза аламын (не record қолдана аламын).
    • Мен generic класс пен generic әдіс жаза аламын.
    • Мен Comparable мен Comparator-дың айырмашылығын білемін және екеуін қолдана аламын.
    • Мен кестеден ArrayList.contains мен HashSet.contains-тің қайсысы жылдам екенін айта аламын.

    Өзіңізді тексеріңіз

    1. Мына әрекеттердің қайсысы ArrayList-те O(1) (тұрақты уақыт) болады?

    ArrayList ішінде массив бар, сондықтан индекс бойынша алу бірден орындалады: O(1). Басына қосу мен ортасынан жою элементтерді жылжытуды қажет етеді (O(n)), ал contains бәрін қарап шығады (O(n)).

    2. Мына бағдарлама не шығарады?

    import java.util.List;
import java.util.Set;
import java.util.TreeSet;

public class Main {
    public static void main(String[] args) {
        Set<Integer> s = new TreeSet<>(List.of(5, 3, 1));
        s.add(5);
        s.add(3);
        s.add(4);
        System.out.println(s + " " + s.size());
    }
}

    Set қайталанатын 5 пен 3-ті қабылдамайды, ал TreeSet элементтерді өсу ретімен сұрыптап ұстайды. Бірегей мәндер: 1, 3, 4, 5, яғни өлшемі 4.

    3. Мына жолда не қате? List<int> san = new ArrayList<>();

    List<int> компиляция қатесін береді: unexpected type; required: reference, found: int. Дұрысы List<Integer>; int ↔ Integer түрлендіруді Java автоматты жасайды (autoboxing).

    4. Мына бағдарлама не шығарады?

    import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> m = new HashMap<>();
        m.put("а", 1);
        Integer ber = m.put("а", 2);
        System.out.println(ber + " " + m.size() + " " + m.get("а"));
    }
}

    put кілт бұрыннан болған болса, ескі мәнді қайтарады (1) және оны жаңасымен (2) ауыстырады. Кілт бірегей, сондықтан size() әлі 1. Соңғы get жаңа мәнді береді: 2.

    5. Мына кодта қай жол компиляция қатесін береді?

    import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<? extends Number> l = new ArrayList<Integer>();
        Number n = l.get(0);
        l.add(5);
    }
}

    ? extends Number тізімінен оқуға болады (элемент Number-дің ұрпағы), бірақ оған қосуға болмайды: компилятор тізімнің нақты типін (Integer па, Double па) білмейді. Тек null қосуға болады.

    6. Мына бағдарлама не шығарады?

    import java.util.ArrayList;
import java.util.Comparator;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> s = new ArrayList<>(List.of("ай", "күн", "жер", "су"));
        s.sort(Comparator.comparingInt(String::length));
        System.out.println(s);
    }
}

    Жолдар ұзындығы бойынша сұрыпталады: екі әріптілер (ай, су), сосын үш әріптілер (күн, жер). Сұрыптау тұрақты, сондықтан ұзындығы бірдей элементтер бастапқы ретін сақтайды: ай су-дан бұрын, күн жер-ден бұрын.

    7. Мына бағдарлама не шығарады?

    import java.util.PriorityQueue;

public class Main {
    public static void main(String[] args) {
        PriorityQueue<Integer> pq = new PriorityQueue<>();
        pq.add(5);
        pq.add(1);
        pq.add(4);
        System.out.println(pq.peek() + " " + pq.size());
        System.out.println(pq.poll() + " " + pq.poll() + " " + pq.poll());

}

    PriorityQueue табиғи реттілікте ең кішісін бірінші ұстайды: peek() = 1, өлшемі 3. poll() үш рет шақырылғанда мәндер өсу ретімен шығады: 1, 4, 5.

    8. equals және hashCode туралы қай сөйлем дұрыс?

    Келісім: a.equals(b) ақиқат болса, a.hashCode() == b.hashCode() болуы шарт. Керісінше міндетті емес (Aa және BB хештері бірдей, бірақ жолдар әртүрлі). HashMap алдымен хешпен қорапты табады, содан кейін equals арқылы нақтылайды, сондықтан екеуі де керек. Тек record екеуін де автоматты жасайды.

    Жаттығуларды алдымен қағазда не ойша орындап көріңіз, содан кейін өз компьютеріңізде тексеріңіз. Дайын шешімдердің бәрі компилятормен тексерілген.

    Оңай

    remove: индекс пе, мән бе?

    Мына код орындалғанда соңғы шығатын тізім қандай болады? Жауабыңызды дәл шыққандай жазыңыз (мысалы, [1, 2, 3]).

    List<Integer> a = new ArrayList<>(List.of(10, 20, 30, 1, 2));
a.remove(1);
a.remove(Integer.valueOf(1));
System.out.println(a);
    Кеңес

    remove(1) мұнда int аргументі, яғни ИНДЕКС. Integer.valueOf(1) болса, Object нұсқасы: ол МӘНДІ іздеп жояды. Екеуін кезекпен орындаңыз: бірінші қадамнан кейін тізім қандай болады?

    Шешімі

    Бастапқы тізім: [10, 20, 30, 1, 2]. remove(1) индекс 1-дегі 20-ны жояды: [10, 30, 1, 2]. remove(Integer.valueOf(1)) мәні 1 болатынды жояды: [10, 30, 2].

    import java.util.ArrayList;
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<Integer> a = new ArrayList<>(List.of(10, 20, 30, 1, 2));
        a.remove(1);                       // int -> ИНДЕКС: 20 жойылады
        a.remove(Integer.valueOf(1));      // Integer -> МӘН: 1 жойылады
        System.out.println(a);
    }
}

    Шешімі

    Бірегей элементтер: «Алматы», «Астана», «алма», «кіші», барлығы 4. Бас әріпті жолдар кіші әріптілерден бұрын келеді, ал «Алматы» мен «Астана» арасында л < с, сондықтан «Алматы» бірінші.

    import java.util.Set;

    Орташа

    Мақалдағы сөздер санағы

    Мына мақалдағы әр сөздің қанша рет кездесетінін есептеп, TreeMap арқылы шығаратын бағдарлама жазыңыз: «Білекті бірді жығады, білімді мыңды жығады». Сөздерді кіші әріпке түсіріңіз және үтірді алып тастаңыз.

    Кеңес

    String.toLowerCase(), replace(",", "") және split(" ") әдістерін қолданыңыз. Санауды map.merge(сөз, 1, Integer::sum) деп жазсаңыз, цикл бір жол болады.

    Шешімі
    import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        String matin = "Білекті бірді жығады, білімді мыңды жығады";
        Map<String, Integer> sanaq = new TreeMap<>();
        for (String soz : matin.toLowerCase().replace(",", "").split(" ")) {
            sanaq.merge(soz, 1, Integer::sum);
        }
        for (Map.Entry<String, Integer> e : sanaq.entrySet()) {
            System.out.println(e.getKey() + ": " + e.getValue());
        }
    }
}

    Кілттер Unicode ретімен шықты (білекті < білімді < бірді): л әрпі р-дан бұрын тұр.

    Өзіңізді тексеріңіз
    • «жығады» сөзі 2 рет саналған, қалғандары 1 рет.
    • Нәтижеде үтір жоқ, барлық сөз кіші әріппен жазылған.
    • TreeMap қолданылған, кілттер сұрыпталған күйде шығады.
    • Бағдарлама компиляцияланады және қатесіз жұмыс істейді.

    Салыстырғыш тізбегі

    Төмендегі тізім ұзындығы бойынша өсу ретімен, ал ұзындығы бірдей болса, табиғи (Unicode) ретімен сұрыпталады. Тізімнің соңғы элементі қандай?

    List<String> sozder = new ArrayList<>(List.of("қала", "ауыл", "өзен", "көл", "дала"));
sozder.sort(Comparator.comparingInt(String::length)

    Қиын

    Үздік k оқушы

    Generic әдіс static <T extends Comparable<T>> List<T> top(List<T> tizim, int k) жазыңыз: ол тізімнен ең үлкен k элементті (кему ретімен) қайтарсын. Әдісті PriorityQueue арқылы жазыңыз: кезек өлшемі k-дан асқанда ең кішісін шығарып отырыңыз. Балдар тізімі: List.of(45, 90, 72, 88, 91, 60, 85), k = 3. Қандай тізім шығады?

    Кеңес

    Әдепкі PriorityQueue ең кішісін бірінші ұстайды. Әр элементті қосқаннан кейін size() > k болса, poll() ең кішісін алып тастайды. Соңында кезекте k ең үлкен қалады. Оларды new ArrayList<>(pq) арқылы тізімге көшіріп, Collections.sort(тізім, Collections.reverseOrder()) арқылы кему ретімен орналастырыңыз.

    Шешімі
    import java.util.ArrayList;
import java.util.Collections;
import java.util.List;
import java.util.PriorityQueue;

public class Main {
    // k ең үлкен элементті (кему ретімен) қайтарады
    static <T extends Comparable<T>> List<T> top(List<T> tizim, int k) {
        PriorityQueue<T> pq = new PriorityQueue<>();     // кіші мән алда
        for (T x : tizim) {
            pq.add(x);
            if (pq.size() > k) {
                pq.poll();                               // ең кішісін шығарамыз
            }
        }
        List<T> natije = new ArrayList<>(pq);
        Collections.sort(natije, Collections.reverseOrder());
        return natije;
    }

    public static void main(String[] args) {
        System.out.println(top(List.of(45, 90, 72, 88, 91, 60, 85), 3));
        System.out.println(top(List.of("ә", "а", "б"), 2));
    }
}
    $ javac Main.java && java Main
[91, 90, 88]
[ә, б]

    Бұл тәсіл тізімнің бәрін сұрыптаудан жылдамырақ: кезек өлшемі k-мен шектеулі, әр қосу O(log k).

    Қиын

    Сыныптар бойынша топтау

    Оқушылар "7А:Айдос" пішімінде берілген (сынып:аты). Тізім: "7А:Айдос", "7Ә:Мадина", "7А:Дана", "7Б:Ернар", "7Ә:Аружан", "7А:Сая". Map<String, List<String>> (кілт - сынып, мән - оқушылар тізімі) жасап, оны шығарыңыз, содан кейін әр сынып үшін оқушы санын шығарыңыз. Кілттерді сұрыптау үшін TreeMap қолданыңыз.

    Кеңес

    Тізімі жоқ кілт үшін жаңа тізім жасау үшін computeIfAbsent(кілт, k -> new ArrayList<>()) дұрыс таңдау: ол тізімді қайтарады, оған бірден .add(...) жасауға болады. Жолды бөлу: j.split(":").

    Шешімі
    import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;

public class Main {
    public static void main(String[] args) {
        String[] jazbalar = {"7А:Айдос", "7Ә:Мадина", "7А:Дана", "7Б:Ернар", "7Ә:Аружан", "7А:Сая"};
        Map<String, List<String>> sinipter = new TreeMap<>();
        for (String j : jazbalar) {
            String[] bolik = j.split(":");
            sinipter.computeIfAbsent(bolik[0], k -> new ArrayList<>()).add(bolik[1]);
        }
        System.out.println(sinipter);
        for (Map.Entry<String, List<String>> e : sinipter.entrySet()) {
            System.out.println(e.getKey() + " сыныбы: " + e.getValue().size() + " оқушы");
        }
    }
}

7А сыныбы: 3 оқушы

7Ә сыныбы: 2 оқушы
    Өзіңізді тексеріңіз
    • 7А сыныбында 3 оқушы, 7Б-да 1, 7Ә-де 2 оқушы шығады.
    • Map<String, List<String>> және computeIfAbsent қолданылған.
    • Кілттер сұрыпталып шығады (TreeMap).
    • Жолды split(":") арқылы бөлдіңіз.
