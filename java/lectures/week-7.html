    Көп ағын, құралдар және қорытынды жоба

    Соңғы аптада Java бағдарламасы бірнеше жұмысты бір мезгілде орындай алатынын көреміз: ағындар, олардың қауіпті тұстары (race condition) және қауіпсіз құралдары. Содан кейін нақты жоба құрылымын (Maven, Gradle) және тест жазу идеясын (JUnit) үйреніп, бүкіл курсты біріктіретін қорытынды жобаны - консольдік «Оқушы журналын» жасауға кірісеміз.

    Бір мезгілде бірнеше жұмыс

    Үйде қонақ күтіп жатқан әжені елестетіңіз. Ол шәйнекті қайнатуға қойып, сол арада қамырды илейді, одан кейін табаққа нан жайып қояды. Егер әже шәйнек қайнағанша ештеңе істемей, түк қимылдамай күтсе, қонақтар аш қалар еді. Ол бірнеше жұмысты араластырып жүргізеді. Бағдарламада да солай: бір жұмыс аяқталғанша күтіп тұрудың орнына, бірнеше жұмысты қатар жүргізуге болады.

    Java-да мұны ағындар (threads) арқылы істейміз. Ағын - бағдарламаның ішіндегі жеке орындалатын «жол». Қазіргі процессорларда бірнеше ядро бар, сондықтан бірнеше ағын шын мәнінде бір мезгілде жұмыс істей алады. Мұның пайдасы:

    • Жылдамдық: үлкен есепті бөліктерге бөліп, әр ядроға бір бөліктен беруге болады.
    • Жауап беру: бір ағын файл жүктеп жатқанда, басқасы қолданушының батырмасына жауап береді.

    Бірақ ағындардың бағасы бар. Олар бір ортақ жадпен жұмыс істейді, ал бұл тек «қауіпті» жол: екі ағын бір айнымалыны бір мезгілде өзгертсе, нәтиже күтпеген болады. Бұл апта осы тұзақ пен одан қорғану құралдарын көрсетеді.

    Көп ағынды бағдарламаның нәтижесі кейде әр жолы басқаша

    Ағындардың орындалу ретін операциялық жүйе шешеді, ал ол әр жолы әртүрлі болуы мүмкін. Сондықтан көп ағынды мысалдардың кейбіреуі детерминді (нәтижесі әрдайым бірдей: біз оларды join() не Future арқылы дұрыс күттік), ал кейбірі әдейі детермінді емес (race condition көрсететін мысал). Әр мысалдың қайсысы екені мәтінде анық айтылады. Детермінді емес мысалдың нәтижесі сіздің компьютеріңізде басқа сан болады: бұл қалыпты жағдай.

    Thread және Runnable

    Ағын жасаудың негізгі жолы: орындалатын жұмысты Runnable интерфейсі ретінде (бір ғана void run() әдісі бар, ол функционалды интерфейс, сондықтан lambda жазуға болады) жазып, Thread нысанына беру және start() шақыру.

    public class Main {
    public static void main(String[] args) throws InterruptedException {
        Runnable is = () -> System.out.println("Жұмыс істеп тұрған ағын: " + Thread.currentThread().getName());

        is.run();                                   // кәдімгі шақыру: main ағынында

        Thread t1 = new Thread(is, "ағын-1");
        t1.start();                                 // жаңа ағын ашады
        t1.join();                                  // main t1 біткенше күтеді

        Thread t2 = new Thread(is, "ағын-2");
        t2.start();
        t2.join();

        System.out.println("Бәрі аяқталды");
    }
}

    Бұл мысал детерминді, себебі әр start() кейін біз join() арқылы ағынның аяқталуын күттік. Қадамдап оқимыз:

    • is.run() - кәдімгі әдіс шақыру: жұмыс main ағынында орындалды (атауы main). Жаңа ағын ашылған жоқ!
    • new Thread(is, "ағын-1") ағынды дайындайды (әлі жұмыс істемейді), start() оны іске қосады. Енді run() жаңа ағында орындалады.
    • t1.join() - «ағын-1 біткенше мен күтемін». Онсыз main әрі қарай жүріп, соңғы жолды ертерек шығаруы мүмкін еді.

    Негізгі қателік: ағынды іске қосу үшін start() шақыру керек, run() емес. run() - тек кәдімгі әдіс, жаңа ағын ашпайды.

    Ағынды жасаудың екінші, ескірек жолы - Thread класын кеңейту (class MyThread extends Thread { public void run() {...} }). Әдетте Runnable жақсырақ: жұмыс пен оны орындайтын механизм бөлек болады, ал бір мезгілде басқа класты да мұрагерлей аласыз.

    Мәтіндік балама: уақыт сызығында main екі ағынды start() арқылы іске қосады, одан кейін join() шақырып күтеді. ағын-1 және ағын-2 бір мезгілде жұмыс істейді; екеуі де біткен соң main қорытындыны шығарады.

    Енді шынайы пайдасын көрейік: бір есепті екі ағынға бөлеміз. 1-ден 1 000 000-ға дейінгі сандарды қосамыз: бір ағын алғашқы жартысын, екіншісі қалғанын.

    public class Main {
    static long qosyndy(int bastau, int sony) {
        long s = 0;
        for (int i = bastau; i <= sony; i++) {
            s += i;
        }
        return s;
    }

    public static void main(String[] args) throws InterruptedException {
        int n = 1_000_000;
        long[] bolik = new long[2];

        Thread a = new Thread(() -> bolik[0] = qosyndy(1, n / 2));
        Thread b = new Thread(() -> bolik[1] = qosyndy(n / 2 + 1, n));

        a.start();
        b.start();
        a.join();
        b.join();

        System.out.println("1-жарты: " + bolik[0]);
        System.out.println("2-жарты: " + bolik[1]);
        System.out.println("Қосынды: " + (bolik[0] + bolik[1]));
        System.out.println("Формула: " + (long) n * (n + 1) / 2);
    }
}

    Бұл да детерминді: екі ағынның әрқайсысы өз bolik[i] ұясына жазады (бір-бірінің ұясына тимейді), ал main join()-нен кейін ғана оқиды. Нәтиже Гаусс формуласымен (n(n+1)/2) сәйкес келді. Негізгі идея: ортақ деректі бөлісудің орнына, ағындар бөлек бөліктермен жұмыс істесін, сонда мәселе болмайды.

    Ағындардың күйлері де бар: NEW (жасалды), RUNNABLE (жұмыс істеп жатыр), WAITING/TIMED_WAITING (күтіп тұр, мысалы sleep кезінде), TERMINATED (аяқталды). Мына мысалда үзу (interrupt) де көрсетілген:

    public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> {
            try {
                for (int i = 1; i <= 3; i++) {
                    System.out.println("Жұмыс " + i);
                    Thread.sleep(100);
                }
            } catch (InterruptedException e) {
                System.out.println("Үзілді");
            }
        });
        t.start();
        t.join();
        System.out.println("Күй: " + t.getState() + ", тірі ме: " + t.isAlive());

        Thread uzu = new Thread(() -> {
            try {
                Thread.sleep(10_000);
                System.out.println("Бұл жол шықпайды");
            } catch (InterruptedException e) {
                System.out.println("Ұйқыдан оянды (interrupt)");
            }
        });
        uzu.start();
        uzu.interrupt();
        uzu.join();
    }
}

Ағын ұйықтап жатқанда interrupt() шақырсаңыз, ол InterruptedException лақтырып оянады, сондықтан sleep пен join әрқашан try/catch не throws InterruptedException талап етеді (өткен аптадағы checked қате). Бұл - ағынға «жұмысты тоқтат» дейтін жалпы тәсіл.

    Race condition: ортақ айнымалының қауіпі

    Енді бүгінгі ең маңызды ескертуге келдік. Екі ағын ортақ айнымалыны өзгертсе не болады?

    public class Main {
    static int sanagysh = 0;                       // ортақ айнымалы

    static void arttyr() {
        for (int i = 0; i < 100_000; i++) {
            sanagysh++;                            // oqu -> +1 -> jazu: 3 қадам!
        }
    }

    static int synama() throws InterruptedException {
        sanagysh = 0;
        Thread a = new Thread(Main::arttyr);
        Thread b = new Thread(Main::arttyr);
        a.start();
        b.start();
        a.join();
        b.join();
        return sanagysh;
    }

    public static void main(String[] args) throws InterruptedException {
        System.out.println("Күтілген нәтиже: 200000");
        for (int i = 1; i <= 5; i++) {
            System.out.println(i + "-сынама: " + synama());
        }
    }
}

Сіздің компьютеріңізде басқа сандар болады, бәлкім барлығы дұрыс шығып қалар (бұл қауіпті: қате жоқ болғаннан емес, жай «бүгін» көрінбегендіктен). Бұл құбылыс race condition (race condition, «жарыс жағдайы») деп аталады: нәтиже ағындардың орындалу ретіне байланысты болады.

    Неге? sanagysh++ бір қадам сияқты көрінгенімен, процессор үшін үш қадам: (1) айнымалының мәнін оқу, (2) оған 1 қосу, (3) нәтижені жазу. Екі ағын осы қадамдарды араластырып жіберсе, мына жағдай болады:

    Мәтіндік балама: sanagysh 5-ке тең. A ағыны 5-ті оқиды, B ағыны да 5-ті оқиды. Екеуі де 5+1=6 есептейді. A 6 жазады, B да 6 жазады. Екі арттыру жасалды, бірақ сан бір-ақ рет өсті (7 орнына 6): бір арттыру «жоғалды».

    Аналогия: екі кассир бір дәптерге бір мезгілде жазып отыр. Екеуі де дәптерде «5» деген санды көріп, әрқайсысы «6» деп өшіріп жаза салады. Нәтижесінде екі сатылым бір ғана рет есепке алынды. Бұл қате ең жиі кездесетін және табуға ең қиын қателердің бірі, себебі ол әр жолы шықпайды.

    Қадамдап көрейік. counter++ үш майда әрекеттен тұрады. Төмендегі визуализатор екі ағынның әрекетін уақыт сызығында көрсетеді: қай кезекте жауап дұрыс, қай кезекте біреуі жоғалады және synchronized мұны қалай түзетеді.

    synchronized және атомдық айнымалылар

    Мәселені шешу идеясы: бір мезгілде тек бір ағын ғана «қауіпті» код бөлігін орындасын. Банктегі бір терезеге бір клиент кіргендей. Java-да мұны монитор құлыпы (lock) жасайды, ал оны synchronized кілт сөзі басқарады.

    import java.util.concurrent.atomic.AtomicInteger;

public class Main {
    static int a = 0;                              // synchronized арқылы қорғалған
    static final Object qulyp = new Object();
    static final AtomicInteger b = new AtomicInteger();   // атомдық санауыш

    static synchronized void artyrA() {            // әдісті бір мезгілде тек бір ағын орындайды
        a++;
    }

    static void artyrB() {
        b.incrementAndGet();
    }

    static int c = 0;
    static void artyrC() {
        synchronized (qulyp) {                     // тек қажетті блокты құлыптау
            c++;
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Runnable is = () -> {
            for (int i = 0; i < 100_000; i++) {
                artyrA();
                artyrB();
                artyrC();
            }
        };
        Thread t1 = new Thread(is);
        Thread t2 = new Thread(is);
        t1.start(); t2.start();
        t1.join(); t2.join();
        System.out.println("synchronized әдіс: " + a);
        System.out.println("AtomicInteger:     " + b.get());
        System.out.println("synchronized блок: " + c);
    }
}

    Бұл мысал детерминді: үш тәсіл де әрдайым 200 000 береді. Үш тәсілдің айырмашылығы:

    • static synchronized void artyrA() - әдіс деңгейіндегі құлып. Бір мезгілде бір ағын ғана бұл әдісті орындай алады (құлып класқа тиесілі).
    • synchronized (qulyp) { c++; } - блок деңгейіндегі құлып: тек қауіпті жолды ғана қорғаймыз, ал тиісті құлып нысанын өзіміз таңдаймыз. Бұл дәлірек және көбіне жылдамырақ.
    • AtomicInteger - атомдық (бөлінбейтін) операциялары бар класс. incrementAndGet() оқу-қосу-жазуды бір бөлінбейтін қадам ретінде орындайды, құлыпсыз-ақ қауіпсіз. Сан санау сияқты қарапайым жағдайларда ең жақсы таңдау.

    synchronized пайдалы, бірақ абайлау керек: екі ағын бір-бірінің құлпын күтіп мәңгі тұрып қалса, deadlock (deadlock, өзара құлыптану) болады. Мысалы, A ағыны 1-құлыпты алып, 2-құлыпты күтеді, ал B ағыны 2-құлыпты алып, 1-құлыпты күтеді. Екеуі де қозғалмайды. Қарапайым ереже: бірнеше құлып қажет болса, оларды әрдайым бірдей ретпен алыңыз.

    Ортақ күйден аулақ жүріңіз

    Көп ағынды кодты ең жақсы жазу жолы - ортақ өзгермелі күйді мүлде қолданбау. Өзгермейтін (immutable) нысандар (String, record) бірнеше ағынға қауіпсіз. Жоғарыдағы жарты-жартылай қосу мысалындағыдай әр ағынға өз бөлігін бергенде де мәселе жоқ.

    ExecutorService: ағындарды басқару

    Әр тапсырма үшін қолмен new Thread(...) жасау ыңғайсыз: ағынды жасау қымбат, ал 10 000 тапсырма үшін 10 000 ағын ашу бағдарламаны құлатады. Орнына ағындар пулы (thread pool) қолданамыз: бірнеше дайын ағын тапсырма кезегінен жұмыс алып орындайды. Мұны ExecutorService интерфейсі басқарады. Аналогия: шеберханада 4 шебер бар, тапсырыстар кезекке тұрады, бос шебер келесі тапсырысты алады.

    Тапсырма екі түрлі: нәтиже қайтармайтын Runnable және нәтиже қайтаратын Callable<T>. Нәтижені Future<T> («болашақтағы нәтиже» квитанциясы) арқылы аламыз: future.get() нәтиже дайын болғанша күтеді.

    import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.TimeUnit;

public class Main {
    public static void main(String[] args) throws InterruptedException, ExecutionException {
        ExecutorService pul = Executors.newFixedThreadPool(4);

        // әр тапсырма: сыныптың бір бөлігінің балдарын қосады
        List<Future<Integer>> keler = new ArrayList<>();
        int[][] sinipter = { {90, 85, 70}, {60, 75}, {100, 95, 88, 92}, {50} };
        for (int[] bal : sinipter) {
            Callable<Integer> tapsyrma = () -> {
                int s = 0;
                for (int x : bal) s += x;
                return s;
            };
            keler.add(pul.submit(tapsyrma));
        }

        int jiny = 0;
        for (int i = 0; i < keler.size(); i++) {
            int bolik = keler.get(i).get();          // нәтиже дайын болғанша күтеді
            System.out.println((i + 1) + "-тапсырма: " + bolik);
            jiny += bolik;
        }
        System.out.println("Жалпы қосынды: " + jiny);

        pul.shutdown();                              // жаңа тапсырма қабылдамайды
        System.out.println("Пул жабылды: " + pul.awaitTermination(5, TimeUnit.SECONDS));
    }
}

    Негізгі қадамдар:

    1. Executors.newFixedThreadPool(4) - 4 ағынды пул жасайды.
    2. pul.submit(...) - тапсырма жібереді, Future қайтарады.
    3. future.get() - нәтижені алады (қате болса, ExecutionException).
    4. pul.shutdown() - «жаңа тапсырма қабылдамаймын, барлығы біткен соң жабылам». Мұны ұмытпаңыз, әйтпесе бағдарлама аяқталмай қалуы мүмкін (пулдың ағындары тірі).
    5. awaitTermination(...) - жабылуын күтеді; өлшемі бар уақыт шектеуі қойылады.

    Тағы бір мысал: бірнеше тапсырма бір ортақ картаға жазады. Бұл жолы қауіпсіз құрылым - ConcurrentHashMap қолданамыз, әдеттегі HashMap емес (ол көп ағында қауіпсіз емес). Мақал сөздерін төрт тапсырмамен санаймыз:

    import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        List<String> mataldar = List.of(
            "жақсы сөз жарым ырыс",
            "бірлік бар жерде тірлік бар",
            "жақсы сөз жылы ұя",
            "бірлік жоқ жерде тірлік жоқ");

        Map<String, Integer> sanaq = new ConcurrentHashMap<>();
        ExecutorService pul = Executors.newFixedThreadPool(3);
        for (String m : mataldar) {
            pul.submit(() -> {
                for (String soz : m.split(" ")) {
                    sanaq.merge(soz, 1, Integer::sum);      // қауіпсіз біріктіру
                }
            });
        }
        pul.shutdown();
        pul.awaitTermination(5, TimeUnit.SECONDS);

        System.out.println(new TreeMap<>(sanaq));
    }
}

    Жоба құралдары: Maven және Gradle

    Біз қазірге дейін бір Main.java файлын javac арқылы компиляциялап келдік. Шынайы жоба бірнеше жүз файлдан, сыртқы кітапханалардан (мысалы, JUnit) және тесттерден тұрады.     • жобаның стандартты құрылымын анықтайды (барлығы қайда тұратыны белгілі);
    • тәуелділіктерді (dependencies) өзі жүктейді: «менің жобаға JUnit 5.10.2 керек» дейміз, ал құрал оны интернеттегі орталық қоймадан (Maven Central) алады;

    Тест жазу: JUnit идеясы

    Бағдарлама жазып, оны қолмен іске қосып, «дұрыс сияқты» деп қарау - бастаушының жолы. Жоба өскен сайын бұл жетпейді: бір жерді түзетсеңіз, басқа жер бұзылуы мүмкін, ал оны қолмен тексеруге уақыт жетпейді. Шешімі - автоматты тесттер: кішкентай бағдарламалар, олар сіздің кодты шақырып, нәтижесін күткенмен салыстырады. Тест жасыл болса (өтті), код дұрыс; қызыл болса (құлады), бір нәрсе бұзылған.

    Java-ның стандартты тест кітапханасы - JUnit (бұл курста 5-нұсқа). Негізгі ұғымдар:

    • @Test - бұл әдіс тест екенін білдіреді.
    • assertEquals(күтілген, нақты) - екі мән тең болуы керек. Нақты сандар (double) үшін үшінші параметр - қателік шегі (0.0001).
    • assertTrue, assertFalse, assertThrows(Қате.class, () -> ...) - шарт не қате күту.
    • @BeforeEach - әр тесттен бұрын орындалатын дайындық (таза нысан жасау).
    • @Disabled - тестті уақытша өшіреді.

mvn test               # тесттерді іске қосу

    Maven орнатылмаған болса, mvn -v команда табылмады деп жауап береді. Онда Maven-ді maven.apache.org сайтынан жүктеп орнатыңыз не VS Code пен IntelliJ IDEA ішіндегі Java жоба құралдарын қолданыңыз (олар Maven жобаларын өздері ашады). Gradle қолданғыңыз келсе, gradle test пен gradle run.

    Жиі қателер

    1. start() орнына run()

    t.run() жаңа ағын ашпайды, жұмыс шақырған ағында (көбіне main) орындалады. Ағынды іске қосу үшін әрқашан t.start().

    2. join() ұмыту

    join() қоймасаңыз, main ағыны жұмыс аяқталмай жатып нәтижені оқып, нөл не жартылай нәтиже көруі мүмкін. Ағындарды күтіңіз (join, Future.get, awaitTermination).

    3. Ортақ айнымалыны қорғамау

    count++, list.add(...), HashMap.put(...) бірнеше ағыннан қорғаусыз шақырылса, нәтиже әр жолы басқаша болады. synchronized, AtomicInteger, ConcurrentHashMap қолданыңыз.

    4. shutdown() ұмыту

    ExecutorService-ті shutdown() қылмасаңыз, пулдың ағындары тірі қалып, бағдарлама аяқталмайды.

    5. Әртүрлі құлып нысандарын қолдану

    Екі ағын synchronized (new Object()) деп әрқайсысы өз құлпын алса, олар бір-бірін күтпейді, ешқандай қорғаныс жоқ. Құлып нысаны ортақ болуы керек.

    6. Тестсіз «жұмыс істейді» деп сену

    Қолмен бір рет іске қосып, «дұрыс» деу жеткіліксіз. Шеткі жағдайларды (бос тізім, жоқ оқушы, 6-баға) тестпен тексеріңіз.

    Қорытынды

    Бүгін біз:

    • ағын - бағдарламаның ішіндегі жеке орындалатын жол екенін, ал start() ағын ашып, run() ашпайтынын көрдік; join() ағынның аяқталуын күтеді;
    • race condition не екенін, неге count++ қауіпті екенін және нәтиже әр жолы басқаша болатынын көрдік;
    • synchronized (әдіс және блок), AtomicInteger арқылы қорғанудың жолдарын үйрендік, deadlock туралы естідік;
    • ExecutorService, Callable, Future арқылы ағындарды басқарып, shutdown() жасауды біліп алдық;
    • Maven мен Gradle - жобаны құрастыру, тәуелділіктерді жүктеу құралдары екенін; pom.xml мен build.gradle оқуды;
    • JUnit арқылы автоматты тест жазу идеясын (@Test, assertEquals, assertThrows, @BeforeEach) және TDD «қызыл - жасыл» циклін меңгердік;
    • қорытынды жоба «Оқушы журналы»: талаптар, қаңқа, қабылдау критерийлері, рубрика және кеңестер.
    • Мен start() пен run() айырмашылығын және join() не істейтінін айта аламын.
    • Мен race condition қалай пайда болатынын диаграммамен түсіндіре аламын.
    • Мен synchronized не AtomicInteger қолданып, қауіпсіз санауыш жаза аламын.
    • Мен ExecutorService + Future арқылы нәтиже қайтаратын тапсырма жібере аламын.
    • Мен Maven жобасының құрылымы мен pom.xml мазмұнын түсіндіре аламын.
    • Мен JUnit тесті жаза аламын (@Test, assertEquals, assertThrows).
    • Мен қорытынды жобаның талаптары мен рубрикасын түсіндім және жұмысты бастай аламын.

    Сіз Java-ның негізінен бастап көп ағынға, құралдарға және тестке дейін өтіп шықтыңыз. Қорытынды жоба - жүрек: оны өз қолыңызбен аяқтаған соң сіз шын мәнінде бағдарламалаушысыз. Сәттілік!

    Өзіңізді тексеріңіз

    1. Мына бағдарлама не шығарады?

    public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread t = new Thread(() -> System.out.println(Thread.currentThread().getName()), "A");
        t.run();
        t.start();
        t.join();
    }
}

    t.run() жаңа ағын ашпайды, кәдімгі әдіс сияқты main ағынында орындалады, сондықтан main шығады. t.start() жаңа ағынды іске қосады, оның аты A. join() оның біткенін күтеді, сондықтан екінші жол A.

    2. Race condition деген не?

    Race condition - ортақ айнымалыны бірнеше ағын қорғаусыз өзгерткенде нәтиженің ағындардың араласу ретіне байланысты болуы. Бірінші нұсқа - deadlock.

    3. synchronized (qulyp) { ... } не кепілдік береді?

    synchronized өзара шеттету (mutual exclusion) береді: бір құлыппен қорғалған код бөлігін бір мезгілде бір ағын ғана орындайды. Қалғандары күтеді. Ол жылдамдық не қателерден қорғау кепілдігін бермейді.

    4. Мына бағдарлама не шығарады?

    import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService pul = Executors.newSingleThreadExecutor();
        Future<Integer> f = pul.submit(() -> 6 * 7);
        System.out.println(f.get());
        pul.shutdown();
        System.out.println(pul.isShutdown());
    }
}

    submit(() -> 6 * 7) нәтиже қайтаратын Callable жібереді; f.get() нәтиже (42) дайын болғанша күтеді. shutdown() шақырылғаннан кейін isShutdown() - true.

    5. t.join() шақыру нені білдіреді?

    join() - шақырған ағынды t біткенше «тоқтатып» қояды. Іске қосу - start(), ал тоқтатуды interrupt() ұсынады (мәжбүрлеп тоқтату жоқ).

    6. Maven жобасында JUnit тесттері әдетте қай қалтада тұрады?

    Стандартты Maven құрылымы: негізгі код - src/main/java, тесттер - src/test/java. target - жиналған нәтиже қалтасы, оған қолмен код жазбайды.

    7. JUnit 5-те әр тесттің алдында орындалатын дайындық әдісін қай аннотация белгілейді?

    @BeforeEach әдісі әр @Test алдында орындалады (мысалы, таза Zhurnal нысанын жасау үшін). @AfterAll барлық тесттен кейін бір рет орындалады, ал @Setup JUnit-те жоқ.

    8. Мына бағдарлама не шығарады?

    import java.util.concurrent.atomic.AtomicInteger;

public class Main {
    public static void main(String[] args) {
        AtomicInteger a = new AtomicInteger(5);
        int x = a.incrementAndGet();
        int y = a.getAndIncrement();
        System.out.println(x + " " + y + " " + a.get());
    }
}

    incrementAndGet() алдымен 1 қосып, жаңа мәнді (6) қайтарады. getAndIncrement() алдымен ескі мәнді (6) қайтарып, содан кейін 1 қосады (мән 7 болады). Соңында a.get() = 7.

public class Main {

        System.out.println(sanagysh.get());

}

    Callable және invokeAll

    Үш Callable<Integer> тапсырмасын ExecutorService-ке жіберіңіз: 5! (факториал), 2^10 және 1+2+...+100. Олардың нәтижелерінің қосындысы неге тең?

    Кеңес

    5! = 120, 2^10 = 1024, 1+...+100 = 5050. Қосыңыз. Кодпен тексеру үшін pul.invokeAll(List.of(...)) барлық Future-ді қайтарады, олардан get() алыңыз.

    Шешімі

    120 + 1024 + 5050 = 6194.

    import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService pul = Executors.newFixedThreadPool(3);

        Callable<Integer> faktorial = () -> {
            int p = 1;
            for (int i = 2; i <= 5; i++) p *= i;
            return p;                                  // 5! = 120
        };
        Callable<Integer> eki = () -> 1 << 10;         // 2^10 = 1024
        Callable<Integer> qosu = () -> {
            int s = 0;
            for (int i = 1; i <= 100; i++) s += i;
            return s;                                  // 5050
        };

        List<Future<Integer>> natijeler = pul.invokeAll(List.of(faktorial, eki, qosu));
        int jiny = 0;
        for (Future<Integer> f : natijeler) {
            jiny += f.get();
        }
        System.out.println(jiny);
        pul.shutdown();
    }
}
    $ javac Main.java && java Main
6194

    Параллель санау

    Мына төрт жолда «ай» сөзі барлығы неше рет кездеседі? Жолдар: "ай мен күн", "ай туды", "күн мен ай бірге", "ай-ай". Жолдар сөздерге бос орын мен сызықша бойынша бөлінеді (split("[ -]")). Әр жолды бөлек тапсырма ретінде екі ағынды пулға жіберіп, ортақ AtomicInteger-ге санаңыз.

    Кеңес

    Қолмен санаңыз: 1-жол 1, 2-жол 1, 3-жол 1, 4-жол ай-ай екі сөзге бөлінеді (ай, ай), демек 2. AtomicInteger.incrementAndGet() қолданыңыз, соңында shutdown() және awaitTermination(...).

    Шешімі

    1 + 1 + 1 + 2 = 5. Ағындардың реті әр жолы басқаша болуы мүмкін, бірақ қосынды әрдайым бірдей.

    import java.util.List;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.atomic.AtomicInteger;

public class Main {
    public static void main(String[] args) throws InterruptedException {
        List<String> joldar = List.of(
            "ай мен күн", "ай туды", "күн мен ай бірге", "ай-ай");
        AtomicInteger sany = new AtomicInteger();

        ExecutorService pul = Executors.newFixedThreadPool(2);
        for (String j : joldar) {
            pul.submit(() -> {
                for (String soz : j.split("[ -]")) {
                    if (soz.equals("ай")) {
                        sany.incrementAndGet();
                    }
                }
            });
        }
        pul.shutdown();
        pul.awaitTermination(5, TimeUnit.SECONDS);
        System.out.println(sany.get());
    }
}
    $ javac Main.java && java Main
5

    Төмендегі шешім жобаға қойылып, 8 тестің бәрі (@Disabled алынған) mvn test арқылы өтті:

public void oqushyJoyu(String aty) {
    if (oqushylar.remove(aty.trim()) == null) {

public java.util.OptionalDouble sinipOrtasy(String sinip) {
    return oqushylar.values().stream()
            .filter(o -> o.getSinip().equals(sinip))
            .flatMap(o -> o.getBagalar().stream())
            .mapToInt(Baga::baga)
            .average();
}

// ZhurnalSaqtau.java ішіне:
public static Zhurnal zhukteu(Path jol) throws IOException {
    Zhurnal zhurnal = new Zhurnal();
    for (String joly : Files.readAllLines(jol)) {
        String[] bolik = joly.split(";", -1);
        Oqushy o = zhurnal.oqushyQosu(bolik[0], bolik[1]);
        if (!bolik[2].isEmpty()) {
            for (String jup : bolik[2].split(",")) {
                String[] pb = jup.split(":");
                o.bagaQosu(new Baga(Pan.valueOf(pb[0]), Integer.parseInt(pb[1])));
            }
        }
    }
    return zhurnal;
}
