Лекциялар Жаттығу Ойындар Сынақ алаңы Сөздік

Мазмұны

    C1 · 3-сабақ

    Күрделі мәтінді оқу

    Бұл сабақта күрделі академиялық және техникалық мәтінді тез әрі терең оқуды үйренеміз: оқу стратегиялары, күрделі зат есімді топтар, зат есімдену (nominalisation), есімше айналымдары, мәтіннің байланысы (cohesion) және спецификация тілі (MUST / SHOULD / MAY). Сонымен қатар осындай стильде өзіміз жазамыз.

    СабақтарДағдыларСөздікГрамматикаIT-фразаларДеңгей тесті
    Деңгей туралы

    C1 - жоғары деңгей, ол CEFR шкаласына шамамен сәйкес келеді. Бұл ресми деңгей емес, тек оқу жолындағы бағдар. Мазмұн жасанды интеллект көмегімен дайындалған, сондықтан мұғаліммен тексерген жөн.

    Сабақ мақсаттары

    Осы сабақтың соңында сіз мыналарды істей аласыз:

    • мәтінді мақсатына қарай шолып (skim), іздеп (scan) және терең (intensive) оқу стратегияларын таңдайсыз;
    • күрделі зат есімді топты бөліп, ішінен басты сөзін табасыз (unpacking);
    • етістікті зат есімге айналдырып (decide -> decision) ресми әрі тығыз сөйлем құрастырасыз;
    • есімше айналымдарын (Having tested ..., Written in Rust, ...) дұрыс қолданасыз;
    • мәтін байланысын (this, such, the former, the latter, thereby, whereby) көрсететін сөздерді табасыз және қолданасыз;
    • спецификацияның MUST, SHOULD, MAY тілін түсініп, өз талаптарыңызды дәл жазасыз;
    • күрделі мәтіннің қысқаша мазмұнын (abstract, summary) жазасыз.

    Уақыты: 45-60 минут. Әр жаттығу автоматты тексеріледі, ал жазба жаттығуын өз критерийлеріңізбен өзіңіз бағалайсыз.

    Оқу стратегиялары: тез және терең

    Күрделі мәтінді сөзбе-сөз бастан аяқ оқу - ең баяу әрі тиімсіз тәсіл. Мақсатыңызға қарай әдісті таңдаңыз:

    • Skimming (шолу): негізгі ойды 1-2 минутта түсіну. Тақырып, аннотация, әр абзацтың бірінші және соңғы сөйлемі, қорытынды.
    • Scanning (іздеу): нақты ақпаратты (сан, термин, кодтың аты) көзбен іздеу. Мәтіннің бәрін оқымайсыз.
    • Intensive reading (терең оқу): күрделі бөлімді ойланып, абзацтап оқу.
    • Critical reading (сыни оқу): автордың дәлелі қандай, нақты дерек бар ма, қандай болжам жасалған?

    Нақты жоспар:

    1. Алдын ала қарау: тақырып, құрылым, суреттер, қорытынды. Мәтін не туралы деп болжаңыз.
    2. Сұрақ қою: «Мен бұл мәтіннен не білгім келеді?»
    3. Оқу: абзацтың topic sentence (негізгі сөйлемі) қайда екенін табыңыз, жиектерге белгі қойыңыз (annotate).
    4. Өз сөзіңізбен қайталау (paraphrase): әр бөлімнен кейін бір сөйлеммен.
    5. Қайталау: мәтін соңында қысқаша мазмұнды (summary) жазыңыз.

    Белгісіз сөзге тоқтап қалмаңыз: ойдан шығару үшін құрамына (re- қайта, un- теріс, -able мүмкін болатын), басқа сөйлемдердегі мағынасына, сөйлемдегі қызметіне (зат есім ме, етістік пе) қараңыз. Тек мағына кілт болса ғана сөздікке жүгініңіз.

    Қазақшамен салыстыру

    Қазақшада күрделі мәтінде сөйлем көбіне ұзақ, етістік соңында тұрады: оқырман сөйлем соңына дейін күтеді. Ағылшынша керісінше: бастауыш пен етістік алдында, ал ұзын анықтауыштар зат есімнің алдында немесе артында тұрады. Сондықтан ағылшын мәтінінде алдымен бастауыш пен етістікті табу, содан кейін қосымша бөліктерді қосу пайдалы.

    Күрделі зат есімді топтар және зат есімдену

    Академиялық және техникалық ағылшынның ерекшелігі - ақпарат етістікте емес, зат есімді топта шоғырланады. Бір зат есімнің алдында және артында көптеген анықтауыш тұра алады:

    the recent failure of the distributed payment processing system that handles international transactions

    Мұндай топты бөлу үшін (unpacking) басты зат есімді табыңыз - бұл мысалда failure. Қалғаны оны сипаттайды: recent (алдында), of the ... system (артында), that handles ... (анықтауыш сөйлем). Сосын сұрақ қойыңыз: «Не істелді? Кім? Қашан?»

    Зат есімдену (nominalisation) - етістікті не сын есімді зат есімге айналдыру. Нәтижесінде сөйлем тығыздалып, ресмирек болады:

    • decide -> decision, fail -> failure, analyse -> analysis, reduce -> reduction, implement -> implementation, available -> availability.
    • Because the system failed, users lost data. -> The failure of the system led to data loss for users.
    • We analysed the logs carefully, and this showed ... -> Careful analysis of the logs showed ...

    Артық зат есімдену мәтінді ауыр етеді. Егер сөйлемді түсіну қиын болса, оны етістікке қайтарыңыз: The implementation of the migration of the legacy database -> We migrated the legacy database. Академиялық стильде ақпарат тығыз болғаны жөн, бірақ оқуға ыңғайлы болуы маңыздырақ.

    Есімше айналымдары (participle clauses) да ақпаратты тығыздайды:

    • Having tested the code, we released it. (Кодты сынап болған соң, оны шығардық.)
    • Written in Rust, the tool is extremely fast. (Rust тілінде жазылған құрал өте жылдам.)
    • Not knowing the cause, we restarted the server.
    • Анықтауыш сөйлемнің қысқасы: the report written by Aida (= which was written), a function returning a list (= that returns).

    Ереже: есімше айналымының бастауышы басты сөйлемнің бастауышымен бірдей болуы керек. Opening the file, an error appeared. - қате (файлды ашқан - қате емес, адам). Дұрысы: When I opened the file, an error appeared.

    Қосымша: nominalisation, күрделі зат есімді топ, есімше айналымдары.

    Мәтіннің байланысы (cohesion)

    Жақсы мәтінде сөйлемдер бір-бірімен «желімделген». Мұндай байланысты құралдар:

    • Сілтеме (reference): this, that, these, such, the above, the former, the latter. We compared a monolith and microservices. The former is easier to deploy, whereas the latter scales better.
    • Ауыстыру мен қысқарту: do so, one, ones: Users who wish to do so can disable the feature.
    • Байланыстырғыштар: moreover, nevertheless, thereby, whereby, albeit, notwithstanding. The cache reduces load, thereby improving speed. / We use a process whereby every change is reviewed. / The solution works, albeit slowly.
    • Лексикалық жіп: бір тақырыптағы сөздердің қайталануы және синонимі: failure, outage, incident.
    • Белгілеу (signposting): This section explains ..., In the next section, ..., To summarise, ...

    Назар аударыңыз: this жалғыз өзі қабатталған сілтеме болса шатасуға әкеледі. Нақтылау үшін this + зат есім дұрыс: This approach, this failure. Академиялық мәтінде көбіне жаңа ақпарат сөйлемнің соңында беріледі.

    Мәтін үлгілері: problem - solution (Мәселе - Шешім), cause - effect, comparison, chronological. Үлгіні таныса, мәтіннің қай жерде не болатыны алдын ала белгілі.

    Спецификация мен RFC тілі

    Техникалық стандарттар мен спецификацияларда сөздер нақты мағынада қолданылады. Көптеген спецификация басында ескертеді: бас әріппен жазылған MUST, SHOULD, MAY (және олардың болымсыз түрлері) күнделікті сөздер емес, талап дәрежесін көрсететін терминдер. Олардың негізгі мағынасы:

    • MUST - міндетті талап (орындамаса, жүйе талапқа сай емес).
    • MUST NOT - қатаң тыйым.
    • SHOULD - күшті ұсыныс: дәлелді себеп болғанда ғана оны орындамауға болады.
    • MAY - міндетті емес, қалау бойынша.

    Басқа ерекшеліктер: normative (міндетті ережелер) пен informative (түсіндіру) бөлімдері бөлек; rationale (негіздеме) неге бұлай екенін түсіндіреді; сөйлемдер ұзын, бірақ нақты, ал ресми сөздер (whereby, thereby, notwithstanding, albeit) жиі кездеседі. Оқу тәртібі: алдымен терминдер мен ескертпені (қандай сөздер қалай түсініледі), сосын талаптарды, соңында негіздемені оқыңыз.

    Өз спецификацияңызды жазғанда: бір сөйлемге бір талап, бастауышты нақты атаңыз (The server MUST ...), «ол», «бұл» деген сілтемелерден аулақ болыңыз, сандар мен шектеулерді нақты көрсетіңіз.

    Сөздік: мәтін және академиялық жазу

    Әр сөздің жанындағы «жаттадым» белгісі сөздік бетімен ортақ.

    • ambiguity noun екіұштылық Оқылуы: эмбигьюити The specification contains some ambiguity. Техникалық тапсырмада кейбір екіұштылық бар.
    • nuance noun реңк, нәзік айырма Оқылуы: нюанс The translation loses some nuance. Аударма реңктің бір бөлігін жоғалтады.
    • implication noun астар, салдар Оқылуы: имплакейшн The implications of this change are far-reaching. Бұл өзгерістің салдары кең ауқымды.
    • coherent adj өзара сабақтас, түсінікті Оқылуы: коухиәрәнт The report is clear and coherent. Есеп анық әрі өзара сабақтас.
    • concise adj қысқа әрі нақты Оқылуы: кәнсайс Keep the summary concise. Қорытындыны қысқа әрі нақты жазыңыз.
    • verbose adj шұбалаңқы, сөзді көп Оқылуы: вәбоус The documentation is too verbose. Құжаттама тым шұбалаңқы.
    • jargon noun кәсіби жаргон Оқылуы: джагән Avoid jargon when you write for new users. Жаңа пайдаланушыларға жазғанда жаргоннан аулақ болыңыз.
    • terminology noun терминология Оқылуы: тәминолоджи Use consistent terminology throughout the document. Құжат бойы бірізді терминологияны қолданыңыз.
    • albeit conj ал дегенмен, бірақ та Оқылуы: олбиит The solution works, albeit slowly. Шешім жұмыс істейді, бірақ баяу.
    • whereby adv соның арқылы, сол бойынша Оқылуы: уеәбай We use a process whereby every change is reviewed. Біз әр өзгеріс қаралатын процесті қолданамыз.
    • notwithstanding prep ...ға қарамастан (ресми) Оқылуы: нотуиезстэндин Notwithstanding these risks, we recommend proceeding. Осы тәуекелдерге қарамастан, жалғастыруды ұсынамыз.
    • thereby adv осылайша, соның нәтижесінде Оқылуы: зеәбай The cache reduces load, thereby improving speed. Кэш жүктемені азайтады, осылайша жылдамдықты арттырады.
    • discern verb айыра білу, байқау Оқылуы: дисән It is hard to discern the author's real intention. Автордың нақты ниетін айыру қиын.

    Оқу мәтіндері

    Екі мәтін де оқу мақсатында жазылған: олар нақты зерттеуге не стандартқа сілтеме емес. Бірінші мәтінді алдымен skim (1-2 минут), содан кейін мұқият оқыңыз.

    Мәтін 1. Академиялық стильдегі абзац

    The widespread adoption of microservice architectures has, in many organisations, led to a marked increase in operational complexity. While the separation of services allows individual teams to release changes independently, the resulting network of dependencies is considerably harder to understand than a single application. Failures, moreover, rarely remain local: a delay in one service can spread through the whole system, thereby affecting users who never used the failing component. Having analysed incident reports from several projects, the authors of this fictional report conclude that the main difficulty lies not in the technology itself but in the lack of shared knowledge about how the parts interact. They therefore recommend that teams invest in clear documentation and regular joint reviews before splitting a system further.

    Мәтін 2. Спецификация үзіндісі

    Section 4. Request handling
    4.1 A client MUST include a unique request identifier in every request.
    4.2 The server SHOULD reject a request that contains an identifier it has already processed; however, it MAY accept the request if the earlier one failed.
    4.3 Servers MUST NOT store an identifier for longer than 24 hours.
    Rationale: Unique identifiers allow a server to detect duplicates, whereby a retried request does not cause the same action twice. A limited storage period reduces the amount of data a server has to keep, albeit at the cost of rare duplicates after a very long delay.
    Note: In this document, the words MUST, SHOULD and MAY indicate a mandatory rule, a strong recommendation and optional behaviour, respectively.

    Қазақ тілді оқушылардың жиі қателері

    • Сипаттауышты басты сөз деп қабылдау. In 'the recent failure of the system', the main word is 'recent'. емес, In 'the recent failure of the system', the main word is 'failure'. Алдымен басты зат есімді табыңыз, қалғаны оны сипаттайды.
    • Есімше айналымының бастауышы басты сөйлемнен бөлек. Opening the file, an error appeared. емес, When I opened the file, an error appeared. Есімше мен басты сөйлемнің бастауышы бірдей болуы керек.
    • this сілтемесі түсініксіз. This is a problem. емес, This inconsistency is a problem. this-тен кейін зат есім қосып нақтылаңыз.
    • whereas пен whereby шатасуы. A process whereas every change is reviewed. емес, A process whereby every change is reviewed. whereby = соның арқылы; whereas = ал (салыстыру).
    • albeit-тен кейін толық сөйлем қою (табиғи емес). The solution works, albeit it is slow. емес, The solution works, albeit slowly. albeit кейін жиі сын есім / үстеу / қысқа тіркес.
    • Зат есімденуді шектен тыс қолдану. The implementation of the migration of the database was performed. емес, We migrated the database. Түсінікті болу ең басты. Тым ауыр мәтін оқырманды шаршатады.
    • Міндетті ережеге SHOULD қолдану. Clients SHOULD include an identifier. (ереже міндетті) емес, Clients MUST include an identifier. Спецификацияда SHOULD = ұсыныс, MUST = міндет.
    • Академиялық мәтінде ауызекі сөздер мен қысқартулар. It's kind of a big deal. емес, It is a significant issue. Жазбаша ресми мәтінде нақты және бейтарап сөздер.

    IT-ағылшын: спецификация, құжаттама және RFC

    Бағдарламашы күн сайын құжаттама, спецификация және стандарт оқиды. Мақсат - барлығын түсіну емес, керек ақпаратты тез табу. Алдымен мазмұнды қарап, сілтеме жасаңыз; код мысалдарын оқыңыз; талаптарды (MUST) белгілеңіз; кері үйлесімділік пен ескірген (deprecated) бөлімдерге назар аударыңыз.

    • specification noun техникалық сипаттама, спецификация (specification) Оқылуы: спэсификейшн The specification defines the message format. Спецификация хабарламаның пішімін анықтайды.
    • normative adj міндетті сипаттағы (стандарттағы) Оқылуы: номәтив The normative sections must be followed exactly. Міндетті бөлімдерді дәл сақтау керек.
    • compliant adj талаптарға сай Оқылуы: кәмплайәнт Your server is not compliant with the standard. Сіздің серверіңіз стандартқа сай емес.
    • deprecate verb ескірген деп жариялау (қолданудан шығару) Оқылуы: депрәкейт The team deprecated the old endpoint. Команда ескі endpoint-ті ескірген деп жариялады.
    • obsolete adj ескірген, қолданыстан шыққан Оқылуы: обсәлит This library is obsolete. Бұл кітапхана ескірген.
    • interoperability noun жүйелердің бір-бірімен үйлесімді жұмысы (interoperability) Оқылуы: интәропәрәбилити The goal is interoperability between vendors. Мақсат - жеткізушілер арасындағы үйлесімді жұмыс.
    • rationale noun негіздеме (rationale) Оқылуы: рэшәнал The document explains the rationale for the change. Құжат өзгерістің негіздемесін түсіндіреді.
    • abstraction noun абстракция (күрделілікті жасыру) (abstraction) Оқылуы: абстрэкшн Good abstraction hides unnecessary details. Жақсы абстракция қажетсіз бөлшектерді жасырады.
    • invariant noun өзгермейтін шарт (invariant) Оқылуы: инвеәриәнт The function must preserve this invariant. Функция осы өзгермейтін шартты сақтауы тиіс.
    • mandatory field noun міндетті өріс (mandatory field) Оқылуы: мэндәтри филд The user name is a mandatory field. Пайдаланушы аты - міндетті өріс.

    Мысал: құжаттаманың талап пен ескертпе бөлімі.

    parse(input, options)

Parses the given input and returns a normalised object.

options.strict   (boolean, optional)
  If true, the parser MUST reject unknown fields.
  Default: false.

Deprecated: the "legacy" option is obsolete and will be
removed in version 3.0. New code SHOULD NOT use it.

    Бұл мәтінді мұқият оқу: MUST reject - міндетті, optional - қосымша, Default: false - әдепкі мән, obsolete және SHOULD NOT use - қолданбау керек. Өз құжаттамаңызды жазғанда да осы құрылымды қолданыңыз: қысқа сипаттама, параметрлер, әдепкі мән, ескертпе, мысал.

    25. Мини-жоба: шағын спецификация

    Мини-жоба: күрделі мәтінді оқу және жазу

    Бұл жоба 45 минут алады.

    1. Мәтінді таңдаңыз: өзіңізге қызықты ағылшынша техникалық мақала, құжаттама бөлімі не спецификация үзіндісі (бір не екі бет).
    2. Skim (2 минут): негізгі ойды бір сөйлеммен жазыңыз. Scan: бір нақты ақпаратты (сан, термин) табыңыз.
    3. Терең оқу: ең күрделі 3 сөйлемді таңдап, басты зат есімдерін табыңыз және сөйлемді қарапайым етістікпен қайта жазыңыз (nominalisation-ды кері бұрыңыз).
    4. Қорытынды (abstract): 4-5 сөйлеммен: Context, Problem, Method, Result, Implication. Кемінде бір есімше айналымы мен бір байланыс сөзі.
    5. Лексика: 8-10 жаңа сөзді өз сөзіңізбен мысалдап жазыңыз.

    Нәтижені бір аптадан кейін қайта оқып көріңіз: түсінікті ме?

    Қайталау тізімі

    • Стратегиялар: skim, scan, intensive, critical; annotate, paraphrase, summarise.
    • Күрделі зат есімді топ: басты сөзді тауып (unpacking), қалғанын сипаттауышқа бөлу.
    • Nominalisation: decide -> decision, fail -> failure, analyse -> analysis; артық болса, етістікке қайтару.
    • Есімше айналымдары: Having tested ..., Written in ..., Not knowing ...; бастауыш бірдей.
    • Cohesion: this + зат есім, the former / the latter, do so, thereby, whereby, albeit, notwithstanding.
    • Спецификация: MUST, MUST NOT, SHOULD, MAY; normative, rationale, deprecated, obsolete.

    Осы сабақтың сөздерін сөздік бетіндегі карточкалармен қайталаңыз.

    Қорытынды

    Бүгін мынаны қарастырдық:

    • Оқу стратегиясы: мақсатқа қарай skim, scan, intensive, critical; annotate және summarise.
    • Зат есімді топ: басты сөзді табу; nominalisation: етістік -> зат есім.
    • Есімше айналымдары: Having tested ..., Written in ...; бастауыш сәйкес болуы тиіс.
    • Cohesion: this, the former / the latter, do so, thereby, whereby, albeit.
    • Спецификация: MUST - міндет, SHOULD - күшті ұсыныс, MAY - қосымша; rationale - негіздеме.
    • Жазу: нақты, бейтарап, бір сөйлемде бір ой; summary өз сөзіңізбен.

    Келесі, соңғы сабақта (C1 · 4-сабақ) идиомаларды, коллокацияларды, келіссөзді және презентация мен демо тілін қарастырамыз.

    Өзіңізді тексеріп көріңіз:

    • Мақсатқа қарай оқу стратегиясын таңдай аламын (skim, scan, intensive).
    • Күрделі зат есімді топтың басты сөзін таба аламын.
    • Етістікті зат есімге айналдырып, ресми сөйлем құра аламын.
    • Есімше айналымдарын дұрыс қолданамын.
    • MUST, SHOULD, MAY сөздерін спецификацияда дұрыс түсінемін және қолданамын.

    Қорытынды тест

    1. Ұзақ құжаттан нақты нөмірді іздеу үшін қай стратегия ең тиімді?

    Нақты ақпаратты іздеу - scanning.

    2. The solution works, ___ slowly.

    albeit slowly - бірақ баяу.

    3. Қай сөйлем дұрыс?

    Есімшенің бастауышы басты сөйлемнің бастауышымен бірдей болуы керек.

    4. decide сөзінің зат есімі қандай?

    decide -> decision.

    5. Спецификацияда The server MUST NOT store ... нені білдіреді?

    MUST NOT - тыйым.

    6. We compared A and B. ___ is cheaper; ___ is faster. (A мен B ретімен)

    The former - алғашқы, the latter - соңғы.

    7. We use a process ___ every change is reviewed.

    whereby = соның арқылы.

    8. Қай стратегия мәтіннің жалпы идеясын 1-2 минутта түсінуге көмектеседі?

    Skimming - шолу.
