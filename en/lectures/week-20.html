Мазмұны

    C1 · 1-сабақ

    Болжам, инверсия және ерекше құрылымдар

    Бұл сабақта бір нәрсенің болғанына сенімділік дәрежесін білдіретін құрылымдарды (must have been, can't have, might have), екпін беретін инверсияны (Never have I ..., Not only does ...), ресми жазбадағы субъюнктивті (It is essential that ... be ...) және архитектура талқылауындағы дәлелдеу тіркестерін меңгереміз.

    СабақтарДағдыларСөздікГрамматикаIT-фразаларДеңгей тесті
    Деңгей туралы

    C1 - жоғары деңгей, ол CEFR шкаласына шамамен сәйкес келеді. Бұл ресми деңгей емес, тек оқу жолындағы бағдар. Мазмұн жасанды интеллект көмегімен дайындалған, сондықтан мұғаліммен тексерген жөн.

    Сабақ мақсаттары

    Осы сабақтың соңында сіз мыналарды істей аласыз:

    • must have / can't have / might have + V3 арқылы өткен оқиғаға сенімділік дәрежесін дәл білдіресіз;
    • теріс мағыналы сөздермен (Never, Rarely, Hardly, No sooner, Not only, Under no circumstances) басталатын инверсиялы сөйлем құрастырасыз;
    • Only after, Not until, Little did және So ... that инверсиясын қолданасыз;
    • It is essential that ... be ... типті субъюнктивті ресми мәтінде дұрыс қолданасыз;
    • архитектура шешімін trade-off тілімен дәлелдейсіз;
    • бір шешімнің артықшылығы мен кемшілігін қысқа дизайн-жазбасында жазасыз.

    Уақыты: 45-60 минут. Әр жаттығу автоматты тексеріледі, ал жазба жаттығуын өз критерийлеріңізбен өзіңіз бағалайсыз.

    Өткен оқиғаға болжам: must have, can't have, might have

    Біз өткенде не болғанын көбіне көрмейміз, тек қорытынды жасаймыз. Ағылшын тілінде болжамның сенімділік дәрежесін модаль етістік + have + V3 құрылымы береді:

    • must have + V3 - сенімдімін, ол болған (шамамен 95%): The build failed, so someone must have changed the config. (Жинау сәтсіз болды, демек біреу конфигті өзгерткен.)
    • can't / couldn't have + V3 - сенімдімін, ол болмаған: She can't have deployed it; she was on holiday. (Ол деплой жасай алмайды, ол демалыста еді.)
    • may / might / could have + V3 - болуы да, болмауы да мүмкін: The file might have been deleted by the cleanup script.
    • should / ought to have + V3 - күтілген, дегенмен нақты білмейміз: They should have arrived by now. (Олар қазір жеткен болуы керек.)

    Әрекеттің барысын айту үшін: must have been + -ing: He must have been working all night. Ырықсыз етіс: must have been + V3: The logs must have been overwritten.

    Қазіргі уақытқа болжам үшін: must be (демек, солай), can't be (мүмкін емес), might be: The light is on, so he must be in the office.

    Модальға қосымша ықтималдық сөздері: presumably (болжай келгенде), evidently (көрінгендей), apparently (айтылуынша), conceivably (ойға келеді). Мысалы: Presumably, the cache was cleared during the deploy.

    Қазақшамен салыстыру

    Қазақшада болжам «-ған шығар», «-ған болуы керек», «-ған болуы мүмкін», «-ған емес» арқылы беріледі: «Біреу конфигті өзгерткен болуы керек». Ағылшынша дәреже модальды таңдаумен беріледі, оның ішінде қазақ тілді оқушылар көбіне must пен should-ды шатастырады: must have - қорытынды (сенімділік), ал should have - орындалмаған міндет не күтілген іс. Тағы бір қате: can't have орнына mustn't have қолдану. Mustn't have болжамда қолданылмайды.

    Қосымша: болжам құрылымдары.

    Инверсия: сөз ретін екпін үшін өзгерту

    Кәдімгі ағылшын сөйлемінде бастауыш етістіктің алдында тұрады. Бірақ сөйлем теріс не шектеуші мағыналы сөзбен басталса, көмекші етістік бастауыштың алдына шығады, ал көмекші етістік жоқ жерде do / does / did қосылады. Бұл стиль екпін береді және ресми, жазбаша, шешендік мәтінде кездеседі.

    • Never / Rarely / Seldom: Never have I seen such a clean design. / Rarely does this module need changes.
    • Hardly ... when / Scarcely ... when / No sooner ... than: Hardly had we deployed when the alerts started. / No sooner had we fixed one bug than another appeared.
    • Not only ... but (also): Not only does the cache speed things up, but it also saves money.
    • Under no circumstances / At no point / On no account: Under no circumstances should you share your password.
    • Only after / Only when / Not until: Only after we read the logs did we understand the problem. / Not until the release did we notice the error.
    • Little did: Little did we know that the problem was in the config.
    • So + сын есім ... that / Such ... that: So slow was the server that users left. / Such was the demand that the site crashed.

    Үлгі: Қарапайым сөйлем -> We had never seen such a clean design. -> Инверсия: Never had we seen such a clean design. Көмекші етістік (had) бастауыштың (we) алдына шықты.

    Шарттағы инверсия (B2-де таныстық): Had we tested it, ..., Were I you, ..., Should you need help, ...

    Пайдалану кеңесі

    Инверсияны үнемдеп қолданыңыз. Күнделікті сөйлеуде ол өте ресми естіледі. Презентацияда, баяндамада, ресми хатта, дәлелдеме мәтінде бір-екі инверсия ойға ерекше екпін береді. Бір абзацта үштен көп қоспаңыз.

    Қазақшамен салыстыру

    Қазақшада сөз реті еркін, ал екпін интонация, «тіпті», «ешқашан», «ол ғана емес, сонымен қатар» сөздері арқылы беріледі: «Ешқашан мұндай таза дизайнды көрген емеспін». Ағылшынша екпін үшін сөз реті өзгереді, және қазақ тілді оқушылар көмекшіні қоюды ұмытады: Never I have seen it емес, Never have I seen it. Тағы бір жиі қате: Not only it works емес, Not only does it work.

    Қосымша: инверсия ережесі.

    Субъюнктив: ресми талап пен ұсыныс

    Ресми мәтінде талап, ұсыныс, шарт білдірген кезде that-сөйлемде етістіктің негізгі түрі (to-сыз) қолданылады. Бұл subjunctive (құрылымдық, талап райы) деп аталады. Ол үшінші жақта -s жалғауын алмайды және be етістігі is/are/was болмайды, be болады.

    Құрылым: (сын есім / етістік) + that + бастауыш + негізгі форма.

    • сын есімдер: essential, vital, imperative, important, necessary - It is essential that every request be logged.
    • етістіктер: demand, insist, recommend, suggest, propose, require, stipulate - The contract stipulates that payment be made in advance. / I recommend that she submit the report today.
    • болымсыз: not + негізгі форма - We insist that the file not be changed.

    Британдық ағылшында көбіне should қосылады: It is essential that every request should be logged. Екеуі де дұрыс. Ауызекі сөйлеуде жиі қарапайым форма да қолданылады, бірақ ресми құжатта (талап, шарт, ереже) субъюнктив ресми көрінеді.

    Тағы бір субъюнктив түрі: If I were you, ..., I wish it were easier, as if it were true - онда were барлық жаққа қолданылады.

    Қазақшамен салыстыру

    Қазақшада талап пен ұсыныс бұйрық не қалау райымен («болсын», «жасалсын») айтылады: «Әр сұраныс тіркелсін». Ағылшынша мұндай ресми «болсын» формасы - негізгі түрдегі етістік (be logged). Қазақ тілді оқушылар көбіне is logged немесе will be logged деп қояды, ал бұл талап емес, жай факт болып естіледі.

    Қосымша: субъюнктив ережесі.

    Архитектураны талқылау: дәлелдеу тілі

    Архитектура туралы пікірталаста «мынау жақсы, мынау жаман» деу жеткіліксіз: әр шешімнің артықшылығы мен бағасы (trade-off) көрсетіледі. Төмендегі тіркестер ойды құрылымдайды:

    • Артықшылық: The main advantage of this approach is that ... / It allows us to ...
    • Баға: This comes at the cost of ... / The downside is that ... / The price we pay is ...
    • Салыстыру: On the one hand, ... On the other hand, ... / Compared with ..., ...
    • Негіздеме: Given that ... / In light of ... / Considering that ...
    • Тәжірибе: In my experience, ... / From what I have seen, ...
    • Қорытынды: On balance, ... / Weighing the trade-offs, I would recommend ...
    • Келіспеу (жұмсақ): I see your point, but I am not convinced that ...

    Бір абзацта бір ой болсын: мәселе -> нұсқалар -> салыстыру -> ұсыныс.

    Сөздік: болжам және инверсия

    Әр сөздің жанындағы «жаттадым» белгісі сөздік бетімен ортақ.

    • presumably adv болжай келгенде, сірә Оқылуы: призьюмәбли Presumably, the cache was cleared during the deploy. Сірә, кэш деплой кезінде тазаланған.
    • evidently adv анық, көрініп тұрғандай Оқылуы: эвидәнтли Evidently, nobody had tested the migration. Көрініп тұрғандай, миграцияны ешкім тексермеген.
    • plausible adj шындыққа жанасатын, сенімді Оқылуы: плозәбл That is a plausible explanation for the delay. Бұл кешігудің шындыққа жанасатын түсіндірмесі.
    • inevitable adj сөзсіз, болмай қоймайтын Оқылуы: инэвитәбл Some technical debt is inevitable. Біршама техникалық берешек болмай қоймайды.
    • conceivable adj ойға келетін, мүмкін болатын Оқылуы: кәнсивәбл It is conceivable that two requests arrived at once. Екі сұраныс бірден келуі де мүмкін.
    • scarcely adv әрең, дерлік ... емес Оқылуы: скеәсли Scarcely had we deployed when the alerts started. Біз деплой жасап үлгергенше болмай, ескертулер басталды.
    • seldom adv сирек Оқылуы: сэлдәм Seldom does this module need changes. Бұл модульді сирек өзгертуге тура келеді.
    • hardly adv әрең, дерлік ... емес Оқылуы: хадли Hardly had I opened the file when the editor froze. Файлды ашқаным сол еді, редактор қатып қалды.
    • no sooner phrase ...болғаны сол еді (...than) Оқылуы: ноу сунә No sooner had we fixed it than a new bug appeared. Түзетіп болғанымыз сол еді, жаңа қате шықты.
    • under no circumstances phrase ешбір жағдайда Оқылуы: андә ноу сәкемстәнсиз Under no circumstances should you share your key. Ешбір жағдайда кілтіңізді ешкімге бермеңіз.
    • not until phrase ...ғанға дейін ғана емес, тек ... кейін Оқылуы: нот антил Not until we read the logs did we see the problem. Журналды оқығаннан кейін ғана мәселені көрдік.
    • imperative adj міндетті, аса қажетті Оқылуы: импэрәтив It is imperative that the data be encrypted. Деректің шифрлануы аса қажет.

    Оқу мәтіндері

    Бірінші мәтінде оқиға себебін іздеу, екіншісінде архитектуралық ұсыныс. Модаль болжамдарды, инверсияны және субъюнктивті белгілеп шығыңыз.

    Мәтін 1. Жоғалған есеп

    On Monday morning, the nightly report was missing, and nobody knew why. The logs showed that the job had started at midnight but never finished. "It must have run out of memory," Dan said, "because the data was twice as large as usual." Aida disagreed. "It can't have been the memory," she said. "The monitoring shows that only half of it was used." Then they noticed something strange: the database backup had also started at midnight. "The two jobs might have been competing for the same table," Aida suggested. "That would explain why the report stopped without any error message." They tested the idea on a copy of the system. Hardly had they started both jobs when the report froze again. "We should have checked the schedule weeks ago," said Dan. It is essential that the two jobs be moved to different times, and the team agreed to do it that day.

    Мәтін 2. Архитектуралық ұсыныс

    Subject: Proposal: splitting the billing module
    Hi team,
    I would like to propose that the billing module be separated from the main application. Rarely has a single module caused so many deployment delays: over the last quarter, eleven of our fourteen delayed releases were related to billing. Not only does this slow us down, but it also makes it harder to test changes safely. On the other hand, a separate service would add network calls, which means higher latency and a new point of failure. Were we to ignore this risk, we could end up with a system that is harder to run than the current one. Therefore, I recommend that we start with a small, well-defined part, measure the results, and only then decide whether to go further. Under no circumstances should we split everything at once. I would appreciate your comments before Friday.
    Best regards,
    Sam

    Қазақ тілді оқушылардың жиі қателері

    • Болжамда mustn't have қолдану. He mustn't have deployed it. емес, He can't have deployed it. mustn't болжамда емес, тыйым үшін.
    • must have пен should have-ты шатастыру. The build failed, so someone should have changed it. емес, The build failed, so someone must have changed it. must have - қорытынды; should have - орындалмаған міндет.
    • Инверсияда көмекші етістік ұмытылады. Never I have seen such a design. емес, Never have I seen such a design. Теріс сөзден кейін көмекші етістік бастауыштың алдына шығады.
    • Not only-дан кейін бастауыш бірінші. Not only it works, but it is fast. емес, Not only does it work, but it is also fast. do/does/did қосылады.
    • Инверсиядан кейін негізгі етістікке -s жалғау. Rarely does this module needs changes. емес, Rarely does this module need changes. does бар болса, негізгі етістік жалаң түрде.
    • Субъюнктивте is / will be қолдану. It is essential that every request is logged. емес, It is essential that every request be logged. Талап үшін негізгі форма (be) не should be.
    • Субъюнктивте 3-жақ -s. I recommend that she submits the report. емес, I recommend that she submit the report. Субъюнктивте -s жалғауы жоқ.
    • Hardly ... than. Hardly had we started than it froze. емес, Hardly had we started when it froze. Hardly / Scarcely ... when, No sooner ... than.

    IT-ағылшын: архитектура талқылауы және шешім жазбасы

    Архитектура туралы пікірталас әріптестерді сендіруге негізделген. Мұндай талқылауда «ең жақсы шешім» болмайды, ал «берілген шектеулерге ең лайықты ымыра» бар. Төмендегі сөздер мен құрылымдар осыны айту үшін.

    • trade-off noun артықшылық пен кемшіліктің арасындағы таңдау (trade-off) Оқылуы: трейд-оф Every design decision involves a trade-off. Әр дизайн шешімі белгілі бір ымыраны талап етеді.
    • scalability noun масштабталу мүмкіндігі (scalability) Оқылуы: скейләбилити Scalability was the main concern of the design. Дизайнның басты алаңдаушылығы масштабталу болды.
    • latency noun кідіріс, жауап беру уақыты (latency) Оқылуы: лейтәнси High latency hurts the user experience. Жоғары кідіріс пайдаланушы тәжірибесін нашарлатады.
    • throughput noun өткізу қабілеті (throughput) Оқылуы: срупут We doubled the throughput of the pipeline. Біз конвейердің өткізу қабілетін екі есе арттырдық.
    • bottleneck noun тар жер, жүйенің баяулататын буыны (bottleneck) Оқылуы: ботлнек The database is the main bottleneck. Дерекқор - негізгі тар жер.
    • redundancy noun резервтеу, қосымша көшірмелік қуат (redundancy) Оқылуы: ридандәнси Redundancy keeps the service running during failures. Резервтеу ақау кезінде қызметті жұмыс істетіп тұрады.
    • coupling noun модульдердің өзара байланыстылығы (coupling) Оқылуы: капліңг Tight coupling makes changes risky. Тығыз байланыстылық өзгерістерді қауіпті етеді.
    • monolith noun монолит (біртұтас қолданба) (monolith) Оқылуы: монолит We started as a monolith and split it later. Біз монолит ретінде бастап, кейін бөлдік.
    • fault tolerance noun ақауға төзімділік (fault tolerance) Оқылуы: фолт толәрәнс Fault tolerance is a key design goal. Ақауға төзімділік - дизайнның негізгі мақсаты.
    • single point of failure noun жалғыз осал нүкте (ол істен шықса, жүйе тоқтайды) (single point of failure) Оқылуы: сингл пойнт ов фейлә One server is a single point of failure. Бір сервер - жалғыз осал нүкте.

    Шешім жазбасының (architecture decision record) қысқа мысалы:

    Decision: Use a message queue between the order service
and the e-mail service.

Context: E-mail delivery is slow and sometimes fails.
Orders must not be blocked by it.

Consequences:
  + Orders are no longer affected by e-mail problems.
  + The system scales more easily.
  - We must monitor the queue and handle duplicate messages.
  - Debugging becomes harder because the flow is asynchronous.

Alternatives considered: calling the e-mail service directly.
Rejected, because the order service would depend on it.

    Пікірталаста ойды бекітіп немесе қарсы айту үшін:

    • Not only does a queue improve reliability, but it also makes scaling easier.
    • It is essential that no order be lost, so the queue must be persistent.
    • The bottleneck can't have been the network; the latency graphs are flat.
    • Rarely do we need real-time delivery for e-mails.

    Жаттығулар

    Қиын

    25. Мини-жоба: шешім жазбасы

    Мини-жоба: архитектура туралы пікірталас және шешім жазбасы

    Бұл жоба 40 минут алады.

    1. Мәселені таңдаңыз: өз жобаңыздағы (не ойдан шығарылған) нақты шешім: кэш қосу, сервисті бөлу, дерекқорды ауыстыру, тесттер жазу.
    2. Пікірталас хаты (8-10 сөйлем): ұсыныс, артықшылық, баға (at the cost of), қарсы жағы (On the other hand), қорытынды (On balance). Кемінде екі инверсия мен бір субъюнктив қолданыңыз.
    3. Шешім жазбасы: Decision, Context, Consequences, Alternatives considered.
    4. Өзіңізді тексеріңіз: әр инверсияда көмекші етістік бастауыштың алдында ма? Субъюнктивте етістік жалаң түрде ме? must have / can't have орынды қолданылды ма?

    Нәтижені тәжірибелі әріптеске не мұғалімге көрсетіп, пікір сұраңыз.

    Қайталау тізімі

    • Болжам: must have + V3 (сенімді, болған), can't have + V3 (сенімді, болмаған), might / may / could have (мүмкін), should have (күтілген / міндет).
    • Инверсия: Never, Rarely, Seldom, Hardly ... when, No sooner ... than, Not only ... but also, Under no circumstances, Only after, Not until, Little did.
    • Көмекші етістік бастауыштың алдына шығады; жоқ болса do / does / did.
    • Шарттағы инверсия: Had we ..., Were I ..., Should you ...
    • Субъюнктив: It is essential / vital / imperative that ... be / + негізгі форма; recommend / insist / demand / suggest that ...
    • Дәлелдеу тіркестері: The main advantage is that ..., at the cost of ..., Given that ..., On balance, ...

    Осы сабақтың сөздерін сөздік бетіндегі карточкалармен қайталаңыз.

    Қорытынды

    Бүгін мынаны қарастырдық:

    • Болжам: must have (болған), can't have (болмаған), might have (мүмкін), should have (күтілген).
    • Инверсия: теріс не шектеуші сөзден кейін көмекші етістік бастауыштың алдына шығады.
    • Not only does ..., Hardly had ... when, Under no circumstances should ... ресми екпін үшін.
    • Субъюнктив: It is essential that ... be / негізгі форма (-s жоқ).
    • Архитектура: артықшылық, баға (trade-off), негіздеме, қорытынды ұсыныс.
    • Шешім жазбасы: Decision, Context, Consequences, Alternatives.

    Келесі сабақта (C1 · 2-сабақ) жұмсақ және нақты ой білдіруді (hedging), нәзік сынды, дизайн-құжат жазуды және cleft құрылымдарын қарастырамыз.

    Өзіңізді тексеріп көріңіз:

    • must have, can't have, might have арқылы сенімділік дәрежесін айыра аламын.
    • Негізгі инверсиялы құрылымдарды (Never have I, Not only does, Hardly had) құра аламын.
    • Субъюнктивті ресми талап пен ұсынысқа дұрыс қолданамын.
    • Архитектуралық шешімді артықшылығы мен бағасымен дәлелдей аламын.
    • Қысқа шешім жазбасын ағылшынша жаза аламын.

    Қорытынды тест

    1. Бос орынға не келеді? The build failed, so someone ___ the config.

    Қорытынды: must have + V3.

    2. Қай сөйлем дұрыс?

    Теріс сөзден кейін көмекші етістік бастауыштың алдына шығады.

    3. Not only ___ it work, but it is also fast.

    Not only does it work.

    4. It is essential that every request ___ logged.

    Субъюнктив: be.

    5. She can't have deployed it нені білдіреді?

    can't have + V3 - болмағанына сенімділік.

    6. Hardly had we started ___ it froze.

    Hardly ... when.

    7. Қай тіркес trade-off-ты көрсетеді?

    at the cost of - баға.

    8. I recommend that she ___ the report.

    Субъюнктив: -s жоқ.
