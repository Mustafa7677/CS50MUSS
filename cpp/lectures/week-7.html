    Шаблондар, ерекше жағдайлар, файлдар және қорытынды жоба

    Соңғы аптада үлкен бағдарламаға қажет құралдарды жинаймыз: кез келген типпен жұмыс істейтін шаблондар, қателерді өңдеу, файлмен жұмыс, көп файлға бөлу. Содан кейін бәрін біріктіріп, қорытынды жоба - «Кітапхана басқару жүйесі» - жазамыз.

    Соңғы апта: үлкен бағдарламаға қажет құралдар

    Алдыңғы апталарда біз тілдің негізін қалап, класстар, мұрагерлік және STL-мен танысып шықтық. Бірақ нағыз бағдарлама тек есептеумен шектелмейді: ол әртүрлі деректер типімен жұмыс істеуі керек, қателер болса, құламай тұруы керек, деректерді файлға сақтауы керек және жүздеген жолдан тұратын кодты ыңғайлы файлдарға бөле алуы керек. Дәл осыларды бүгін үйренеміз:

    1. шаблондар: бір кодты кез келген типке қолдану;
    2. ерекше жағдайлар: қатені тәртіппен өңдеу;
    3. RAII: ресурсты қауіпсіз басқару;
    4. файлдар: деректерді сақтау және оқу;
    5. namespace: атаулардың шатасуын болдырмау;
    6. көп файлды жоба: header, source, Makefile;
    7. қорытынды жоба: бәрін біріктіріп, «Кітапхана басқару жүйесін» жазу.

    Шаблондар

    Екі санның үлкенін табатын функцияны int үшін жазсақ, double үшін тағы бір рет көшіруге тура келеді, string үшін тағы бір рет. Логика бірдей, тек тип басқа. Мұндай қайталануды болдырмау үшін шаблон (template) бар: ол «тип орнына тұратын айнымалысы бар» функция не класс.

    #include <iostream>
#include <string>

template <typename T>
T maxOf(T a, T b) {
    return (a < b) ? b : a;
}

template <typename T>
void swapValues(T& a, T& b) {
    T tmp = a;
    a = b;
    b = tmp;
}

int main() {
    std::cout << maxOf(3, 7) << "\n";                       // T = int
    std::cout << maxOf(2.5, 1.5) << "\n";                   // T = double
    std::cout << maxOf(std::string("Алматы"), std::string("Астана")) << "\n";   // T = string
    std::cout << maxOf<double>(3, 7.5) << "\n";             // T-ны өзіміз көрсеттік

    std::string a = "бірінші", b = "екінші";
    swapValues(a, b);
    std::cout << a << " " << b << "\n";
}

екінші бірінші

    Негізгі жазу: template <typename T>. Мұндағы T - тип параметрі («қандай да бір тип»). Компилятор шақыруды көргенде, T орнына нақты типті қойып, кодтың сәйкес нұсқасын өзі жасайды. Мұны инстанцирлеу (template instantiation) дейді. Типті компилятор аргументтерден анықтайды (maxOf(3, 7) → T = int), не біз өзіміз maxOf<double>(3, 7.5) деп көрсетеміз.

    Шаблон «ақылды» көшіру-қою сияқты, сондықтан оның қолданатын операциялары нақты типте болуы керек. maxOf ішінде a < b бар, демек, тип < операторын білуі керек. Тағы бір ереже: екі параметр де бірдей T, сондықтан int мен double араластырсақ, компилятор шатасады:

    #include <iostream>

template <typename T>
T maxOf(T a, T b) {
    return (a < b) ? b : a;
}

struct Point { int x, y; };

int main() {
    std::cout << maxOf(3, 4.5) << "\n";
    Point p{1, 2}, q{3, 4};
    maxOf(p, q);
}

    Класс шаблондары

    Шаблон тек функция емес, класс та бола алады. STL-дегі vector<int>, map<K, V> дәл осылай жазылған. Өз стегімізді жазып көрейік, ол кез келген типті сақтай алады:

    #include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

template <typename T>
class Stack {
public:
    void push(const T& x) { items_.push_back(x); }
    T pop() {
        if (items_.empty()) throw std::out_of_range("стек бос");
        T top = items_.back();
        items_.pop_back();
        return top;
    }
    bool empty() const { return items_.empty(); }
    std::size_t size() const { return items_.size(); }

private:
    std::vector<T> items_;
};

template <typename A, typename B>
struct Pair {
    A first;
    B second;
};

int main() {
    Stack<int> s;
    s.push(10);
    s.push(20);
    s.push(30);
    std::cout << s.pop() << " " << s.pop() << " (қалды: " << s.size() << ")\n";

    Stack<std::string> names;
    names.push("Қобыланды");
    names.push("Алпамыс");
    std::cout << names.pop() << "\n";

    Pair<std::string, double> p{"шай", 350.5};
    std::cout << p.first << " = " << p.second << " тг\n";
}

    Тип қана емес, тұрақты мәнді де шаблон параметрі етуге болады. Мысалы, өлшемі компиляция кезінде белгілі жиым:

    #include <iostream>

template <typename T, int N>
class FixedArray {
public:
    constexpr int size() const { return N; }
    T& operator[](int i) { return data_[i]; }
    T sum() const {
        T s = T();
        for (int i = 0; i < N; ++i) s += data_[i];
        return s;
    }

private:
    T data_[N] = {};
};

int main() {
    FixedArray<int, 5> a;
    for (int i = 0; i < a.size(); ++i) a[i] = (i + 1) * 10;
    std::cout << "өлшемі " << a.size() << ", қосындысы " << a.sum() << "\n";

    FixedArray<double, 3> d;
    d[0] = 0.5; d[1] = 1.5; d[2] = 2.0;
    std::cout << "double қосындысы " << d.sum() << "\n";
}

    Ерекше жағдайлар: try, catch, throw

    Қате жағдайды қалай хабарлаймыз? Функция қайтарған мәнмен (-1, false)? Бұл жұмыс істейді, бірақ қайтарым кодын тексеруді ұмытуға болады, ал тексермесек, бағдарлама үнсіз қате нәтижемен жалғасады. C++ басқа жолды ұсынады: ерекше жағдай (exception). Үш кілт сөз:

    • throw - ерекше жағдайды «лақтырады» (қате болғанын жариялайды);
    • try - қате болуы мүмкін кодты қамтиды;
    • catch - лақтырылған қатені ұстап, өңдейді.
    #include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) throw std::invalid_argument("нөлге бөлуге болмайды");
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 4) << "\n";
        std::cout << divide(5, 0) << "\n";       // осы жерде лақтырылады
        std::cout << "бұл жол орындалмайды\n";
    } catch (const std::invalid_argument& e) {
        std::cout << "Қате: " << e.what() << "\n";
    }
    std::cout << "бағдарлама жалғасты\n";
}

    Мұнда divide(5, 0) ерекше жағдай лақтырды. Бағдарлама сол сәтте try блогының қалған бөлігін өткізіп жібереді (сондықтан «бұл жол орындалмайды» шықпады), нақты catch-ке секіреді, ал содан кейін қалыпты жалғасады. Ерекше жағдай көп функцияны артқа қарай «жоғары көтеріледі», ұстайтын catch табылғанша.

    std::exception иерархиясы

    Стандартты кітапхананың ерекше жағдайлары мұрагерлік иерархиясына құрылған (өткен апта!). Ең жоғарыда std::exception тұр, оның what() әдісі қатенің сипаттамасын қайтарады.

    Иерархияның пайдасы: catch (const std::exception&) барлық стандартты қатені ұстайды, ал нақтырақ catch нақты түрін ұстайды. Өз қатемізді де осы иерархияға қосуға болады: std::runtime_error-дан мұрагерлендіреміз. Банк мысалына қайта оралайық:

    #include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

class InsufficientFunds : public std::runtime_error {
public:
    InsufficientFunds(double need, double have)
        : std::runtime_error("қаражат жеткіліксіз: керек " + std::to_string(static_cast<int>(need)) +
                             ", бар " + std::to_string(static_cast<int>(have))) {}
};

void withdraw(double balance, double amount) {
    if (amount <= 0) throw std::invalid_argument("сома оң болуы керек");
    if (amount > balance) throw InsufficientFunds(amount, balance);
    std::cout << "алынды: " << amount << "\n";
}

int main() {
    double amounts[] = {5000, -1, 90000};
    for (double a : amounts) {
        try {
            withdraw(20000, a);
        } catch (const InsufficientFunds& e) {
            std::cout << "InsufficientFunds: " << e.what() << "\n";
        } catch (const std::invalid_argument& e) {
            std::cout << "invalid_argument: " << e.what() << "\n";
        }
    }

    try {
        std::vector<int> v(3);
        v.at(10) = 1;
    } catch (const std::exception& e) {          // барлық стандартты қателер үшін ортақ база
        std::cout << "std::exception ұстады\n";
    }
}

    RAII және ерекше жағдайлар

    Ерекше жағдай функцияны кез келген жерінен үзе алады. Сонда функцияның соңындағы delete орындалмай қалуы мүмкін. Алдымен бағдарлама ерекше жағдай лақтырылғанда локалды нысандардың деструкторлары қалай жұмыс істейтінін көрейік. Бұл процесс стекті тарқату (stack unwinding) деп аталады:

    #include <iostream>
#include <stdexcept>
#include <string>

struct Guard {
    std::string name;
    Guard(std::string n) : name(n) { std::cout << "+" << name << " "; }
    ~Guard() { std::cout << "-" << name << " "; }
};

void inner() {
    Guard a("a");
    Guard b("b");
    throw std::runtime_error("қате");
    Guard c("c");              // бұған жетпейді
}

int main() {
    try {
        inner();
    } catch (const std::exception&) {
        std::cout << "| ұсталды ";
    }
    std::cout << "| соңы\n";
}
    $ ./a08_unwind

    inner() ішінде a мен b жасалып, throw болғанда стек артқа қарай тарқатылды: b, содан кейін a жойылды (деструкторлар жұмыс істеді), сосын catch орындалды. c жасалуға жеткен жоқ. Осы үшін деструкторлар ерекше жағдай кезінде де кепілді жұмыс істейді. Енді қолмен жадты басқарғанда не болатынын көрейік:

    #include <iostream>
#include <stdexcept>

void process(bool fail) {
    int* data = new int[1000];       // қолмен бөлінген жад
    if (fail) throw std::runtime_error("ортасында қате");
    delete[] data;                   // fail болса, мұнда жетпейді!
}

int main() {
    try {
        process(true);
    } catch (const std::exception& e) {
        std::cout << "ұсталды: " << e.what() << std::endl;
    }
}

    Namespace: атаулар кеңістігі

    Жоба өскен сайын атаулар қайталана бастайды: кітапханада Book бар, кітап дүкенінде де Book бар. Олар бірдей аталса, не болады? Мұндай соқтығысты атау кеңістігі (namespace) шешеді: ол атауларды «аудандарға» бөледі, сондықтан library::Book мен shop::Book бір-біріне кедергі жасамайды. Біз std:: префиксін қолданып келе жатқанымыз да осы: std - стандартты кітапхананың namespace-і.

    #include <iostream>
#include <string>

namespace library {
    struct Book { std::string title; };
    void print(const Book& b) { std::cout << "Кітапхана кітабы: " << b.title << "\n"; }
}

namespace shop {
    struct Book { std::string title; int price; };
    void print(const Book& b) { std::cout << "Дүкен тауары: " << b.title << ", " << b.price << " тг\n"; }

    namespace discount {
        int apply(int price) { return price * 90 / 100; }
    }
}

namespace {                                    // атаусыз: тек осы файлда көрінеді
    int secret() { return 42; }
}

int main() {
    library::Book a{"Абай жолы"};
    shop::Book b{"Абай жолы", 4000};
    library::print(a);
    shop::print(b);
    std::cout << "Жеңілдікпен: " << shop::discount::apply(b.price) << " тг\n";

    using shop::print;                         // тек бір атауды әкелу
    print(b);
    std::cout << secret() << "\n";
}

    Header-де жазылған using namespace std; бұл header-ді қосатын әр файлға тарайды және соқтығысу қаупін көбейтеді. Header-де әрқашан толық атауды (std::string) жазыңыз. .cpp файлдарында да мүмкіндігінше жеке атауларды әкеліңіз.

    Көп файлды жоба: header, source, Makefile

    Бағдарлама мың жолға жеткенде бір файлда жұмыс істеу мүмкін емес. C++ жобасы әдетте мына түрде бөлінеді:

    • header (.h/.hpp): жариялаулар - класс анықтамалары, функция қолтаңбалары. Бұл «мазмұн» немесе «шарттар парағы»;
    • source (.cpp): анықтаулар - функциялардың нақты денесі;
    • main.cpp: бағдарламаның кіру нүктесі.

    Шағын мысал: геометриялық есептеулер. Header-де не бар, сол кітапты «қолданушы» (main) біледі:

    #ifndef GEOMETRY_H
#define GEOMETRY_H

namespace geo {

constexpr double PI = 3.14159265;

double circleArea(double r);            // жариялау (declaration)
double rectArea(double w, double h);

}  // namespace geo

#endif  // GEOMETRY_H
    #include "geometry.h"

namespace geo {

double circleArea(double r) {           // анықтау (definition)
    return PI * r * r;
}

double rectArea(double w, double h) {
    return w * h;
}

    #include <iostream>
#include "geometry.h"

int main() {

    Құрастыру қалай жүреді?

    Көп файлды жобада g++ main.cpp geometry.cpp -o app деп бәрін бірден құрастыруға болады, бірақ іс жүзінде екі қадам бөлек жасалады:

    1) Компиляция (g++ -c) әр .cpp файлын бөлек объектілік файлға (.o) айналдырады. Бұл кезде #include header-лердің мәтінін ішке қосады. 2) Линкер (linker) барлық .o файлды бір орындалатын файлға біріктіреді және функцияны шақыру мен оның анықтамасын байланыстырады.     Makefile

    Әр жолы үш-бес командасын қолмен тергеннен, make құралын қолданған жақсы. Ол Makefile файлындағы ережелерді оқиды: «мақсат: тәуелділіктер» және оның астында (міндетті түрде табуляциямен басталатын) команда. Make файлдардың өзгеру уақытына қарап, тек өзгергенін ғана қайта құрастырады:

    CXX = g++
CXXFLAGS = -std=c++17 -Wall -Wextra -g
OBJS = main.o geometry.o

app: $(OBJS)
	$(CXX) $(CXXFLAGS) -o app $(OBJS)

%.o: %.cpp geometry.h
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) app

.PHONY: clean

    Ережелер: app мақсаты main.o мен geometry.o файлдарына тәуелді. %.o: %.cpp geometry.h - кез келген .o файлы өзінің .cpp мен header-інен жасалады ($< - бірінші тәуелділік, $@ - мақсат). clean құрастыру нәтижелерін өшіреді. .PHONY «clean файл емес, команда аты» дегенді білдіреді. Іске қосайық:

Makefile-да табуляция (Tab) міндетті, бос орындар жұмыс істемейді: бұл ескі, бірақ қатал ереже. Қолмен жазу ыңғайсыз болса, CMake сияқты құралдар бар, бірақ бастаушы үшін қарапайым Makefile жеткілікті.

    Функционалдық талаптар (бағдарлама не істей алуы керек):

    1. F1. Кітаптар. Кітапта id (бағдарлама өзі береді), атауы, авторы, шыққан жылы және күйі (бос/берілген) болады. Кітап қосу және жою мүмкін.
    2. F2. Оқырмандар. Оқырманның id, аты бар. Оқырман түрі екеу: Student (бір мезгілде ең көбі 3 кітап) және Teacher (ең көбі 5 кітап). Лимит virtual int maxBooks() const арқылы анықталады.
    3. F3. Іздеу. Кітапты атауының не автордың бөлігі бойынша, регистрді ескермей табу (мысалы, «абай» → «Абай жолы» және «Абай Құнанбайұлы» кітаптары).
    4. F4. Беру. Кітапты оқырманға беру. Кітап бос емес не оқырман лимитіне жеткен болса, ерекше жағдай лақтырылады.
    5. F5. Қайтару. Кітапты қайтару; оқырманның кітап тізімінен алынады, кітап қайтадан «бос» болады.
    6. F6. Тізімдер мен сұрыптау. Барлық кітап, бос кітаптар, берілген кітаптар (кімде екенін көрсетіп). Атауы, авторы не жылы бойынша сұрыптау (std::sort + lambda).
    7. F7. Статистика. Барлық кітап саны, берілгені, бос саны; кітап саны ең көп автор (std::map).
    8. F8. Сақтау және жүктеу. Деректер мәтін файлдарына сақталады (мысалы, data/books.txt, data/members.txt, data/loans.txt) және бағдарлама басталғанда автоматты жүктеледі. Файл жоқ болса, бағдарлама құламайды.
    9. F9. Консольдік мәзір. Нөмір бойынша таңдау. Қате енгізуде (әріп, шектен тыс нөмір) бағдарлама құламай, қайта сұрайды.
    10. F10. Көп файлды құрылым. Кемінде 5 файл (header + source), make, make run, make clean жұмыс істейді.

    Техникалық талаптар (қалай жазылуы керек):

    • Кемінде 4 класс; инкапсуляция сақталған (өрістер private); қажет жерде const әдістер.
    • Кемінде бір мұрагерлік иерархиясы және виртуалды функциялар (Member → Student/Teacher), виртуалды деструктор.
    • Кемінде бір шаблон (мысалы, жалпы Repository<T> не findBy көмекші функциясы).
    • STL: vector, map (не unordered_map), <algorithm>, lambda.
    • Қателер ерекше жағдайлар арқылы (std::runtime_error-дан тараған өз класыңыз), ұсталуы main-де.
    • Қолмен new/delete жоқ: vector, std::unique_ptr, fstream (RAII).
    • Өз кодыңыз үшін namespace (мысалы, library).
    • -std=c++17 -Wall -Wextra ескертусіз өтеді; -fsanitize=address,undefined қателерді көрсетпейді.

    • Сұрыптау үш өлшем бойынша жұмыс істейді (атауы, авторы, жылы).
    • Статистика дұрыс: жалпы, берілген, бос; кітабы ең көп автор.
    • Бағдарламаны жауып, қайта ашқанда деректер жоғалмайды (файлдан жүктеледі).

    7. Git қолдан. Әр жұмыс істейтін қадамнан кейін коммит жаса. Бір нәрсе бұзылса, бұрынғы жұмыс істеген нұсқаға оралу оңай.
    8. Оқылымдылық. Функция бір экранға сыйсын, атаулар түсінікті болсын (borrowBook, x1 емес), комментарий «неге» деген сұраққа жауап берсін.
    9. Қатты тұрып қалсаң, мәселені кішірейт: бұзылатын ең кішкентай мысалды бөлек файлда жаса. Көбіне мәселені жазғанда-ақ шешімін табасың.

    Жиі қателер

    1. Шаблонды .cpp-ға шығару. Шаблонның денесі header-де болуы керек, әйтпесе линкер undefined reference береді.
    2. Жалпы catch-ті бірінші жазу. catch (const std::exception&) алда тұрса, нақтырақтары ешқашан жұмыс істемейді.
    3. Қатені мәнмен ұстау. catch (std::exception e) slicing жасайды; const std::exception& жазыңыз.
    4. Файлдың ашылғанын тексермеу. if (!in) жоқ болса, бағдарлама үнсіз жалғасады, тек бос деректермен.
    5. ofstream файлды өшіреді. Қосу керек болса, std::ios::app.
    6. Header-де анықтау. Функция денесін (шаблон емес) header-ге жазсаңыз және ол бірнеше .cpp-ға қосылса, линкер «multiple definition» қатесін береді.
    7. Include guard-ты ұмыту не екі header-де бірдей guard атын қолдану.
    8. Makefile-да бос орынның орнына табуляция қоймау (missing separator).
    9. Header-де using namespace std;. Оны қосқан әр файлға тарайды.
    10. Деструктор ішінде exception лақтыру. Деструктор ерекше жағдай лақтырмауы керек, әйтпесе стек тарқатылғанда бағдарлама тоқтайды.

    Қорытынды

    • Шаблон (template <typename T>) бір кодты кез келген типке қолдануға мүмкіндік береді; компилятор әр тип үшін нұсқасын жасайды; шаблон коды header-де тұрады.
    • Ерекше жағдай: throw лақтырады, try/catch ұстайды; нақты түрлер бірінші, const& арқылы ұсталады. Өз қателеріңізді std::runtime_error-дан тарату ыңғайлы. Ұсталмаса, std::terminate.
    • RAII: ресурс конструкторда алынып, деструкторда қайтарылады; ерекше жағдай болса да, стек тарқатылғанда деструкторлар жұмыс істейді. vector, string, unique_ptr, fstream - дайын RAII.
    • fstream: ofstream (жазу), ifstream (оқу); әрқашан ашылғанын тексеріңіз; getline арқылы жолдап оқыңыз.
    • namespace атау соқтығысын болдырмайды; header-де using namespace жазбаңыз.
    • Көп файлды жоба: header (жариялау) + source (анықтау), include guard, компиляция + линкер, Makefile.
    • Қорытынды жоба: класстар, мұрагерлік, STL, exception, файл және Makefile бірге жұмыс істейтін толық бағдарлама.

    Курсты аяқтағаныңызбен құттықтаймыз! Енді сіз C++-та өз бетіңізше жобалар жасай аласыз. Келесі қадамдар: стандартты кітапханаға тереңірек үңілу (<chrono>, <optional>, <variant>), CMake, бірлік тесттер (Catch2/GoogleTest) және өз қызығушылығыңыз бойынша жоба: ойын, деректер өңдеу, жүйелік құрал.

    Өзіңді тексеру тізімі

    • Функция мен класс шаблонын жаза аламын, шаблон қатесінің алғашқы жолын оқи аламын.
    • try/catch/throw ағынын болжай аламын, өз exception класын жаза аламын.
    • RAII деген не екенін және неге new/delete қауіпті екенін түсіндіре аламын.
    • Мәтін файлға жазып, қайта оқып, жолды бөліп өңдей аламын.
    • Header мен source айырмасын, include guard мақсатын білемін.
    • Қарапайым Makefile жаза аламын және undefined reference қатесін түсінемін.

    Өзіңізді тексеріңіз

    1. Мына код не береді?

    template <typename T>
T maxOf(T a, T b) { return a < b ? b : a; }

std::cout << maxOf(3, 4.5);

    Екі аргументтің типі әртүрлі (int және double), ал шаблонда екеуі де T. Компилятор deduced conflicting types қатесін береді. Түзету: maxOf<double>(3, 4.5).

    2. Ерекше жағдай лақтырылды, бірақ ешбір catch оны ұстамады. Не болады?

    Ұсталмаған ерекше жағдай main-нен де шығып кетсе, std::terminate шақырылады. Нәтижесі: «terminate called after throwing an instance of ...».

    3. RAII принципі нені білдіреді?

    RAII ресурс өмірін нысан өміріне байлайды. Ерекше жағдай болса да, деструкторлар шақырылады, сондықтан ресурс ағып кетпейді.

    4. Бағдарлама не шығарады?

    struct Guard {
    std::string name;
    Guard(std::string n) : name(n) { std::cout << "+" << name << " "; }
    ~Guard() { std::cout << "-" << name << " "; }
};

void inner() {
    Guard a("a");
    Guard b("b");
    throw std::runtime_error("қате");
    Guard c("c");
}
// main-де: try { inner(); } catch (const std::exception&) { std::cout << "| ұсталды "; }
//          std::cout << "| соңы\n";

    c жасалмайды, себебі throw одан бұрын. Стек тарқатылғанда локалды нысандар жасалуға кері ретпен жойылады: алдымен b, содан кейін a, сосын catch жұмыс істейді.

    5. Жоқ файлды std::ifstream f("joq_file.txt"); деп аштық. Әдепкі баптауда не болады?

    Fstream әдепкіде exception лақтырмайды, сондықтан ашылғанын өзіміз тексереміз (if (!f)). Орындаған нәтиже: 0 fail.

    6. Екі namespace-те де f() бар, екеуі де using namespace арқылы әкелінген. f() шақырылса, не болады?

    Компилятор қайсысын таңдау керегін білмейді: call of overloaded 'f()' is ambiguous. Шешім: толық атау a::f().

    7. Include guard (#ifndef/#define/#endif) не үшін керек?

    Guard болмаса, struct Point екі рет анықталып, redefinition of 'struct Point' қатесі шығады (біз бұны нақты көрдік).

    8. g++ main.cpp -o app командасын орындадық, бірақ geometry.cpp қосылмады. Қате қай кезеңде шығады?

    Header функцияны жариялайды, сондықтан компиляция өтеді. Бірақ денесі жоқ, сондықтан линкер undefined reference to 'geo::circleArea(double)' қатесін береді.

    Жаттығулар

    Оңай

    Басып шығару ретін болжа

    Мына бағдарлама экранға қандай сандарды (бос орынмен бөліп, жол ретімен) шығарады?

    #include <iostream>
#include <stdexcept>

void f() { throw std::runtime_error("x"); }

int main() {
    try {
        std::cout << "1\n";
        f();
        std::cout << "2\n";
    } catch (...) {
        std::cout << "3\n";
    }
    std::cout << "4\n";
}
    Кеңес

    f() шақырылғаннан кейін try блогының қалған бөлігі орындала ма? catch-тен кейін не болады?

    Шешімі

    Жауап: 1 3 4 (үш жол). 1 шығады, f() лақтырады, «2» өткізіледі, catch (...) «3» шығарады, содан кейін бағдарлама жалғасып «4» шығады. Нақты нәтиже:

    $ ./t01_flow

3
4
    Оңай

    Файл header-і

    Файлға жазу үшін std::ofstream қолданылады. Қай header файлын қосу керек? (мысалы, iostream түрінде, бұрыштық жақшасыз)

    Кеңес

    Оқу (ifstream), жазу (ofstream) және екеуі де (fstream) класы бір header-де. Оның атауы класс атауына ұқсас.

    Шешімі

    Жауап: fstream, яғни #include <fstream>.

    Орташа

    Қай catch жұмыс істейді?

    Мына бағдарлама экранға A әлде B шығарады?

    #include <iostream>
#include <stdexcept>

int main() {
    try {
        throw std::invalid_argument("x");
    } catch (const std::exception&) {
        std::cout << "A\n";
    } catch (const std::invalid_argument&) {
        std::cout << "B\n";
    }
}
    Кеңес

    invalid_argument класы std::exception-нан мұрагерленген. catch блоктары жоғарыдан төмен қарай тексеріледі.

    Шешімі

    Жауап: A. invalid_argument - exception-ның туындысы, сондықтан бірінші catch оны ұстайды. Екіншісіне ешқашан жетпейді. Компилятор мұны ескертеді (-Wexceptions). Дұрыс тәртіп: алдымен нақты түр, содан кейін жалпы.

    Орташа

    Шаблондар

    (1) Кез келген салыстырмалы типке жұмыс істейтін clampTo(x, lo, hi) функция шаблонын жаз: x аралықтан тыс болса, ең жақын шекті қайтарады. (2) Box<T> класс шаблонын жаз: add, largest() (ең үлкен элемент), size(). int және std::string үшін тексер.

    Кеңес

    Екеуі де operator<-ке сүйенеді. Box ішінде std::vector<T> қолдан. Бос қорапта largest() не істейтінін ойлан (нұсқа: ерекше жағдай лақтыруға болады).

    Шешімі
    #include <iostream>
#include <string>
#include <vector>

template <typename T>
T clampTo(T x, T lo, T hi) {
    if (x < lo) return lo;
    if (x > hi) return hi;
    return x;
}

template <typename T>
class Box {
public:
    void add(const T& x) { items_.push_back(x); }
    T largest() const {
        T best = items_.front();
        for (const T& x : items_) if (best < x) best = x;
        return best;
    }
    std::size_t size() const { return items_.size(); }

private:
    std::vector<T> items_;
};

int main() {
    std::cout << clampTo(15, 0, 10) << " " << clampTo(-3, 0, 10) << " " << clampTo(7, 0, 10) << "\n";
    std::cout << clampTo(0.75, 0.0, 0.5) << "\n";

    Box<int> ints;
    ints.add(4); ints.add(19); ints.add(7);
    Box<std::string> names;
    names.add("Алма"); names.add("Нұр"); names.add("Бота");
    std::cout << ints.largest() << " " << names.largest() << " (" << names.size() << " элемент)\n";
}

    Тексеру
    • clampTo(15, 0, 10) = 10, clampTo(-3, 0, 10) = 0.
    • Box<int> және Box<std::string> екеуі де жұмыс істейді.
    • Шаблондар header-де емес болса да (бір файлда), бәрі құрастырылады, ескертусіз.

    Қиын

    Кітаптарды файлға сақтау

    Book құрылымы (атауы, авторы, жылы) үшін saveBooks(path, books) және loadBooks(path) функцияларын жаз. Файлда бір жол - бір кітап, бөлгіш ;. Файл ашылмаса, std::runtime_error лақтыр. main-де екі кітапты сақта, қайта оқы, шығар; содан кейін жоқ жолдағы файлды оқып көріп, қатені ұста.

    Кеңес

    Жазуда std::ofstream, оқуда std::ifstream және std::getline(ss, field, ';'). Жылды std::stoi арқылы санға айналдыр. Әр функцияда алдымен if (!stream) тексер.

    Шешімі
    #include <cstdio>
#include <fstream>
#include <iostream>
#include <sstream>
#include <stdexcept>
#include <string>
#include <vector>

struct Book {
    std::string title;
    std::string author;
    int year;
};

void saveBooks(const std::string& path, const std::vector<Book>& books) {
    std::ofstream out(path);
    if (!out) throw std::runtime_error("жазуға ашылмады: " + path);
    for (const Book& b : books) {
        out << b.title << ';' << b.author << ';' << b.year << '\n';
    }
}

std::vector<Book> loadBooks(const std::string& path) {
    std::ifstream in(path);
    if (!in) throw std::runtime_error("оқуға ашылмады: " + path);
    std::vector<Book> books;
    std::string line;
    while (std::getline(in, line)) {
        std::istringstream ss(line);
        Book b;
        std::string year;
        if (std::getline(ss, b.title, ';') && std::getline(ss, b.author, ';') && std::getline(ss, year)) {
            b.year = std::stoi(year);
            books.push_back(b);
        }
    }
    return books;
}

int main() {
    std::vector<Book> shelf{{"Қара сөздер", "Абай Құнанбайұлы", 1904}, {"Ақбілек", "Ілияс Жансүгіров", 1927}};
    try {
        saveBooks("shelf_tmp.txt", shelf);
        std::vector<Book> back = loadBooks("shelf_tmp.txt");
        std::cout << "Оқылды: " << back.size() << " кітап\n";
        for (const Book& b : back) std::cout << " - " << b.title << " (" << b.year << ")\n";
        loadBooks("/жоқ/жол/файл.txt");
    } catch (const std::exception& e) {
        std::cout << "Қате: " << e.what() << "\n";
    }
    std::remove("shelf_tmp.txt");
}

Қате: оқуға ашылмады: /жоқ/жол/файл.txt
    Тексеру
    • Сақталған кітаптар дәл сол күйінде қайта оқылады.
    • Жоқ файл бағдарламаны құлатпай, түсінікті хабар береді.
    • Файл нысандары RAII-мен жабылады (қолмен close() міндетті емес).
    • -fsanitize=address,undefined таза.

    Мына бағдарламада catch жазуы шығардан бұрын неше деструктор жұмыс істейді? (сан)

    #include <iostream>
#include <stdexcept>
#include <string>

struct G {
    std::string n;

void f() {
    G a("a");

    throw std::runtime_error("x");

}

int main() {
