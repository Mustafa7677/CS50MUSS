    4-апта

    Класстар және нысандар

    Осы уақытқа дейін деректер бір жерде, функциялар басқа жерде жүрді. Бұл аптада оларды бір «қорапқа» жинаймыз: банк шоты өз қалдығын өзі қорғайды, кітап өз мәліметін өзі шығарады. Бұл - нысанға бағытталған бағдарламалаудың (OOP) бастауы.

    Неге класс керек?

    Алдыңғы апталарда біз айнымалылар мен функцияларды бөлек-бөлек жазып келдік. Банк шотын елестетіңіз: оның иесінің аты, қалдығы бар, ал оған ақша салатын, ақша алатын функциялар бөлек тұр. Бағдарлама кішкентай болса, бұл жарайды. Бірақ жүз шот, он мың тапсырыс болғанда не болады? Біреу қалдықты кездейсоқ теріс санға өзгертіп жіберсе, оны кім тоқтатады? Деректер мен оларды өңдейтін функциялар бір-бірінен алыс жатса, қате іздеу қиынға соғады.

    Шешім: деректер мен функцияларды бір «қорапқа» салу. Мұндай қорапты класс (class) дейді, ал сол қораптың негізінде жасалған нақты затты нысан (object) деп атаймыз. Аналогия: класс - бұл үйдің сызбасы (чертеж), ал нысан - сол сызба бойынша салынған нақты үй. Сызба біреу, ал үй қанша керек болса, сонша салуға болады. Әр үйдің өз мекенжайы, өз терезесі бар, бірақ олардың бәрі бір сызбаға сай.

    Бұл апта бойы бір ойды басшылыққа аламыз: нысан өзінің деректерін өзі қорғайды және өзі басқарады. Банк шоты қалдығын сырттан кез келген адам өзгертуге жібермейді, тек «салу» және «алу» әдістері арқылы ғана өзгертеді. Бұл идеяны инкапсуляция (encapsulation) деп атайды, оған бөлек тоқталамыз.

    Өз компьютеріңде іске қос

    Бұл лекциядағы барлық мысалды өзің теріп көр, көшіру жеткіліксіз: саусақ код жазуды есте сақтайды. Файлды main.cpp деп сақтап, терминалда мынаны орында:

    g++ -std=c++17 -Wall -Wextra -fsanitize=address,undefined main.cpp -o main
./main

    -Wall -Wextra компилятордан көбірек ескерту сұрайды, ал -fsanitize=address,undefined жад пен анықталмаған әрекеттегі қателерді орындау кезінде ұстайды. Біз осы лекцияның бүкіл кодын дәл осылай тексердік.

    Мысалдарда using namespace std; жазбаймыз, барлық стандартты атауды std:: префиксімен жазамыз (std::string, std::cout). Бұл ұзағырақ, бірақ қай атау қайдан келгені көрініп тұрады, ал үлкен жобада атаулардың шатасуына жол бермейді.

    struct пен class, қолжетімділік

    C++-та нысан жасаудың екі жолы бар: struct және class. Алдымен құрылым (struct) арқылы қарапайым мысал көрейік. Бір кітап туралы мәліметті бір жерге жинаймыз:

    #include <iostream>
#include <string>

struct Book {
    std::string title;
    std::string author;
    int pages;
};

int main() {
    Book b;
    b.title = "Қобыланды батыр";
    b.author = "халық эпосы";
    b.pages = 120;

    Book c = {"Абай жолы", "Мұхтар Әуезов", 640};

    std::cout << b.title << " (" << b.author << "), " << b.pages << " бет\n";
    std::cout << c.title << " (" << c.author << "), " << c.pages << " бет\n";
}
    $ ./a01_struct
Қобыланды батыр (халық эпосы), 120 бет
Абай жолы (Мұхтар Әуезов), 640 бет

    Мұнда Book - біздің өз типіміз. Оның ішінде үш өріс (member variable, мүше айнымалы) бар: title, author, pages. Өріске нүкте арқылы қол жеткіземіз: b.title. Екінші кітапты (c) жақшамен бірден толтырдық. Бұл ыңғайлы, бірақ бір кемшілігі бар: кез келген жерден кез келген адам b.pages = -5; деп жаза алады, ал кітаптың беті теріс бола ма?

    Енді қолжетімділік (access specifier) ұғымын енгізейік. Үш кілт сөз бар:

    • public (ашық): класстың сыртынан да кез келген адам қолдана алады;
    • private (жабық): тек класстың өз әдістері ғана қолдана алады;
    • protected (қорғалған): жабық сияқты, бірақ мұрагерлерге де рұқсат. Оны келесі аптада қараймыз.

    struct пен class арасындағы бірден-бір маңызды айырмашылық - әдепкі қолжетімділік: struct-та бәрі әдепкіде public, ал class-та бәрі әдепкіде private. Басқа ешқандай үлкен айырмасы жоқ. Дәстүр бойынша қарапайым деректер жиынына (екі-үш өріс, ешқандай ереже жоқ) struct қолданылады, ал өз ережесі бар, деректерін қорғайтын нысандарға class жазылады.

    Классты қорғау қалай жұмыс істейтінін көрейік. Банк шотының қалдығын жабық етіп, сыртынан өзгертіп көрейік:

    #include <iostream>

class Account {
    double balance;
};

int main() {
    Account acc;
    acc.balance = 1000000;
    std::cout << acc.balance << "\n";
}

    Өріс атының соңындағы төменгі сызық

    Мысалдарда жабық өрістерді title_, balance_ деп жазамыз: соңына _ қосу - кең тараған әдет. Сонда title() әдісі мен title_ өрісі шатаспайды, ал конструктор параметрінің аты title бола алады. Бұл тіл ережесі емес, тек келісім.

    Конструктор және инициализация тізімі

    Нысан дүниеге келген кезде оның өрістері дұрыс мәнмен толуы керек. Мұны жасайтын арнайы әдіс бар: конструктор (constructor). Оның аты класстың атымен бірдей, қайтарым типі жоқ (void та жазбаймыз). Нысан жасалған сәтте компилятор оны өзі шақырады.

    #include <iostream>
#include <string>

class Book {
public:
    Book(std::string title, std::string author, int pages)
        : title_(title), author_(author), pages_(pages) {
        std::cout << "Кітап жасалды: " << title_ << "\n";
    }

    std::string title() const { return title_; }
    std::string author() const { return author_; }
    int pages() const { return pages_; }

private:
    std::string title_;
    std::string author_;
    int pages_;
};

int main() {
    Book b("Көшпенділер", "Ілияс Есенберлин", 560);
    std::cout << b.title() << " - " << b.author() << ", " << b.pages() << " бет\n";
}
    $ ./a03_book_ctor
Кітап жасалды: Көшпенділер
Көшпенділер - Ілияс Есенберлин, 560 бет

    Конструктордың тақырыбына назар аударыңыз:

    Book(std::string title, std::string author, int pages)
    : title_(title), author_(author), pages_(pages) { ... }

    Қос нүктеден кейінгі бөлікті инициализация тізімі (member initializer list) дейді. Ол өрістерге мәнді конструктордың денесі басталмай тұрып береді. Неге денесінде title_ = title; деп жазбаймыз? Себебі бұл екі әрекет бірдей емес: тізім өрісті бірден дұрыс мәнмен жасайды, ал денесіндегі меншіктеу алдымен өрісті бос жасап, содан кейін мәнді қайта жазады. std::string үшін бұл артық жұмыс, ал кейбір өрістер (const пен сілтеме түріндегілер) үшін тізім - жалғыз мүмкін жол.

    Бір класста бірнеше конструктор болуы мүмкін, бұл жүктеу (overloading) деп аталады. Аргументсіз шақырылатын конструкторды әдепкі конструктор (default constructor) дейді:

    #include <iostream>
#include <string>

class Student {
public:
    Student() : name_("белгісіз"), grade_(0) {}
    Student(std::string name) : name_(name), grade_(0) {}
    Student(std::string name, int grade) : name_(name), grade_(grade) {}

    void print() const { std::cout << name_ << ", бағасы: " << grade_ << "\n"; }

private:
    std::string name_;
    int grade_;
};

int main() {
    Student a;
    Student b("Нұрлан");
    Student c("Дана", 5);
    a.print();
    b.print();
    c.print();
}

    Инициализация реті

    Тағы бір нәзік жер: өрістер инициализация тізімінде жазылған ретпен емес, класта жарияланған ретпен жасалады. Компилятор мұны байқап, ескерту береді:

    #include <iostream>

class Point {
public:
    Point(int x, int y) : y_(y), x_(x) {}
    void show() const { std::cout << x_ << ", " << y_ << "\n"; }

private:
    int x_;
    int y_;
};

int main() {
    Point p(3, 4);
    p.show();
}

Қарапайым бүтін сандарда бұл зиян келтірмейді, ал бір өріс екіншісінің мәніне сүйенсе, нағыз қате болады. Ереже: тізімді өрістердің жариялану тәртібімен жазыңыз, сонда ескерту де шықпайды.

    Қарапайым типтердің (int, double) өрісін конструкторда мәнсіз қалдырсаңыз, онда кездейсоқ «қоқыс» мән тұрады. Оны болдырмау үшін өрістің өзінде әдепкі мән беруге болады:

    #include <iostream>

class Counter {
public:
    void inc() { n_++; }
    int value() const { return n_; }

private:
    int n_ = 0;   // әдепкі мән: ұмытуға жол жоқ
};

int main() {
    Counter c;
    c.inc();
    c.inc();
    std::cout << c.value() << "\n";
}

    Мұндағы int n_ = 0; жазуы кез келген конструктор өрістің мәнін көрсетпесе, 0 болатынын кепілдейді.

    Нысан жасаудың жолдары

    Нысанды бірнеше жазумен жасауға болады, олардың бәрі бір конструкторды шақырады. Дөңгелек жақша ескі әдіс, ал фигуралы жақша (brace initialization) C++11-ден бері бар. Фигуралы жақшаның артықшылығы: ол деректі «тарылтып» жібермейді, мысалы int x{3.7}; компиляторда қате (не ескерту) береді, ал int x(3.7); үнсіз ғана 3 етіп кесіп тастайды. Класстар үшін екі нұсқа да бірдей жұмыс істейді:

    #include <iostream>
#include <string>

class Guest {
public:
    Guest(std::string name, int age) : name_(name), age_(age) {}
    void greet() const {
        std::cout << "Қош келдіңіз, " << name_ << " (" << age_ << ")!\n";
    }

private:
    std::string name_;
    int age_;
};

int main() {
    Guest a("Сәуле", 31);      // дөңгелек жақша
    Guest b{"Мұрат", 45};      // фигуралы жақша (C++11)
    Guest c = Guest("Гүлнәр", 27);
    a.greet();
    b.greet();
    c.greet();
}

    Деструктор

    Нысан жасалады, жұмыс істейді, сосын жойылады. Жойылар алдында ол артынан жинау жұмыстарын жасай алады: файлды жабу, жадты босату, желі байланысын үзу. Мұны деструктор (destructor) атқарады. Оның аты - класс аты, алдына ~ белгісі қойылады, параметрі де, қайтарым типі де жоқ. Деструкторды компилятор нысан көрінетін аймақтан (scope) шыққанда автоматты шақырады.

    Шай үйіндегі кесемен салыстырайық: қонақ келгенде кесе дайындалады (конструктор), қонақ кеткенде кесе жуылады (деструктор). Нысандар жойылғанда ретті бақылап көрейік:

    #include <iostream>
#include <string>

class Cup {
public:
    Cup(std::string who) : who_(who) {
        std::cout << "  кесе дайын: " << who_ << "\n";
    }
    ~Cup() {
        std::cout << "  кесе жуылды: " << who_ << "\n";
    }

private:
    std::string who_;
};

int main() {
    std::cout << "Шай үйі ашылды\n";
    Cup a("Айгүл");
    {
        std::cout << "Жаңа қонақ келді\n";
        Cup b("Ерлан");
        Cup c("Дана");
        std::cout << "Қонақтар шай ішіп жатыр\n";
    }
    std::cout << "Шай үйі жабылды\n";
}

    1. Ішкі { ... } жақшасы аяқталғанда b мен c жойылды, main аяқталмай жатып.
    2. Жойылу реті жасалу ретіне кері: бірінші Дана (соңғы жасалған), содан кейін Ерлан. Бұл әдеттегі дүниедегі сияқты: соңғы киген аяқ киімді бірінші шешесіз.

    Деструктор C++-тың ең күшті идеяларының біріне - RAII (Resource Acquisition Is Initialization, «ресурс алу - инициализация») - негіз болады. Оны 7-аптада кеңірек қараймыз; қысқасы: ресурсты конструкторда аламыз, деструкторда қайтарамыз, сонда ұмыту мүмкін емес.

    Инкапсуляция: Банк шоты

    Енді басты идеяға келдік. Инкапсуляция (encapsulation) - деректерді жасырып (private), оларға тек ойластырылған ашық әдістер (public) арқылы жол ашу. Сыртқы әлем «қалдық неше?» деп сұрай алады, бірақ «қалдықты мынаған теңе» деп бұйыра алмайды. Банкоматтан ақша алғанда сіз қоймаға кірмейсіз, терезедегі кассир қабылдайды.

    #include <iostream>
#include <string>

class Account {
public:
    Account(std::string owner, double balance) : owner_(owner), balance_(balance) {}

    bool deposit(double amount) {
        if (amount <= 0) return false;
        balance_ += amount;
        return true;
    }

    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance_) return false;
        balance_ -= amount;
        return true;
    }

    double balance() const { return balance_; }
    std::string owner() const { return owner_; }

private:
    std::string owner_;
    double balance_;
};

int main() {
    Account acc("Айдос", 50000);
    std::cout << acc.owner() << ": " << acc.balance() << " тг\n";

    acc.deposit(15000);
    std::cout << "Салғаннан кейін: " << acc.balance() << " тг\n";

    if (!acc.withdraw(100000)) {
        std::cout << "Қаражат жеткіліксіз!\n";
    }
    if (!acc.deposit(-500)) {
        std::cout << "Теріс сома салуға болмайды!\n";
    }
    acc.withdraw(20000);
    std::cout << "Соңғы қалдық: " << acc.balance() << " тг\n";
}

Қалдық private болғандықтан, оны бұзуға тек бір ғана жол бар - класстың өз әдістері арқылы, ал ол әдістер ережені тексереді.

    Тағы бір мысал: температура. Абсолюттік нөлден төмен температура болмайды, сондықтан орнату әдісі мұны тексереді:

    #include <iostream>

class Temperature {
public:
    bool setCelsius(double c) {
        if (c < -273.15) return false;
        c_ = c;
        return true;
    }
    double celsius() const { return c_; }
    double kelvin() const { return c_ + 273.15; }

private:
    double c_ = 0;
};

int main() {
    Temperature t;
    t.setCelsius(-12.5);
    std::cout << "Астанада қаңтарда: " << t.celsius() << " C = " << t.kelvin() << " K\n";
    if (!t.setCelsius(-300)) {
        std::cout << "-300 C мүмкін емес, мән өзгерген жоқ: " << t.celsius() << "\n";
    }
}

    Геттер мен сеттер: қашан керек?

    Өрісті оқитын әдісті геттер (getter), өзгертетінін сеттер (setter) дейді. Жаңа бастаушылар көбіне әр өріске геттер мен сеттер жазады да, «инкапсуляцияны орындадым» деп ойлайды. Бұл жартылай ғана дұрыс. Егер сеттер ешқандай тексерусіз өрістің мәнін жай ғана өзгертсе, өрісті public етіп қою мен арасында айтарлықтай айырма жоқ. Нағыз инкапсуляция мынаны сұрайды: «Нысан қандай әрекеттер жасай алады?», «қандай деректер бар?» емес.

    Сондықтан банк шотына setBalance(double) жазбаймыз, оның орнына мағыналы deposit, withdraw, transferTo береміз. Сыртқы код «қалдықты 0 ет» деп бұйырмайды, «осы сомада ақша ал» деп сұрайды, ал шот ережеге сай орындайды немесе бас тартады. Кітапта да солай: кітаптың атын қайта-қайта өзгерту қажет емес, сондықтан геттер жеткілікті, сеттер мүлде жоқ. Қағида: геттерді қажет болғанда, сеттерді одан да сирек қосыңыз.

    const әдістер және const сілтеме

    Кейбір әдіс нысанды өзгертпейді, тек оқиды: balance(), title(). Мұны компиляторға да, оқырманға да айту үшін әдістің жақшасынан кейін const жазамыз: const әдіс (const member function). Бұл «уәде»: әдіс ішінде бірде-бір өрісті өзгертпеймін. Компилятор уәдені тексереді.

    Неге бұл маңызды? Себебі функцияларға нысанды көбіне const сілтеме арқылы береміз (көшірмені болдырмау үшін), ал const нысанның тек const әдістерін ғана шақыруға болады. Бір ұмытсақ не болады:

    #include <iostream>

class Account {
public:
    Account(double b) : balance_(b) {}
    void deposit(double a) { balance_ += a; }
    double balance() { return balance_; }

private:
    double balance_;
};

void show(const Account& acc) {
    std::cout << acc.balance() << "\n";
}

int main() {
    Account a(1000);
    show(a);
}

    this көрсеткіші және нысан жадта

    Бір класстан он нысан жасалса, deposit әдісінің коды он рет көшіріле ме? Жоқ. Әдістің коды бір ғана рет сақталады, ал әр нысан тек өз өрістерін ғана ұстайды. Сонда acc1.deposit(100) мен acc2.deposit(100) қалай айырады, қайсысының қалдығын арттыру керек? Жауабы: әр әдіске жасырын параметр беріледі - ол this, яғни «қазір әдіс шақырылып жатқан нысанға көрсеткіш».

    Суретте екі нысанның өз өрістері бар, ал әдіс бір дана. Әдіс шақырылғанда сол нысанның мекенжайы this ретінде беріледі. Біз өріс атын жай жазғанда (balance_) компилятор оны өзі this->balance_ деп түсінеді. Қолмен this-> жазу қажет болатын екі жағдай бар:

    • параметр аты өріс атымен бірдей болғанда (this->table_ = table;);
    • әдіс өз нысанының өзін қайтарғанда: return *this;.

    Екінші жағдай тізбектеп шақыру (method chaining) үшін қажет. Шай үйінің тапсырысын тізбектеп толтырайық:

    #include <iostream>
#include <string>

class Order {
public:
    Order(std::string table) : table_(table) {}

    Order& add(std::string item, int price) {
        total_ += price;
        std::cout << "  + " << item << " (" << price << " тг)\n";
        return *this;
    }

    void setTable(std::string table) {
        this->table_ = table;
    }

    void print() const {
        std::cout << "Үстел " << table_ << ", жалпы: " << total_ << " тг\n";
    }

private:
    std::string table_;
    int total_ = 0;
};

int main() {
    Order o("5");
    o.add("қара шай", 400).add("баурсақ", 600).add("қазы", 2500);
    o.print();
}

    static мүшелер

    Кейде деректі нысанға емес, бүкіл класқа ортақ ету керек. Мысалы, Алматы - Астана рейсіне берілген билеттердің жалпы санын бақылау: әр билет өз нөмірін біледі, ал санауыш бір ғана. Мұндай мүше static деп жарияланады. Ол барлық нысанға ортақ, жадта бір ғана дана болып тұрады және нысансыз да бар.

    #include <iostream>
#include <string>

class Ticket {
public:
    Ticket(std::string route) : route_(route), number_(++counter_) {}

    static int issued() { return counter_; }
    int number() const { return number_; }
    std::string route() const { return route_; }

private:
    std::string route_;
    int number_;
    inline static int counter_ = 0;
};

int main() {
    std::cout << "Басында: " << Ticket::issued() << "\n";
    Ticket t1("Алматы - Астана");
    Ticket t2("Астана - Алматы");
    Ticket t3("Алматы - Шымкент");
    std::cout << "Билет №" << t1.number() << ": " << t1.route() << "\n";
    std::cout << "Билет №" << t3.number() << ": " << t3.route() << "\n";
    std::cout << "Барлығы берілді: " << Ticket::issued() << "\n";
    (void)t2;
}

    Мұнда екі static мүше бар: counter_ (ортақ санауыш) және issued() (static әдіс, ол this-сіз жұмыс істейді, сондықтан тек static мүшелерді ғана көреді). Оны нысансыз, Класс::әдіс() түрінде шақырамыз: Ticket::issued(). Конструкторда ++counter_ әр жаңа билетке келесі нөмір береді.

    C++17-де static өрісті класстың ішінде inline static int counter_ = 0; деп бірден мәнімен жариялауға болады. Ескі C++ стандарттарында оны класстан тыс бөлек жариялау керек еді: int Ticket::counter_ = 0;. Екі жазуды да кездестіресіз.

    Оператор << жүктеу

    Біз std::cout << 5 деп жаза аламыз, бірақ std::cout << book деп жазсақ, компилятор кітапты қалай шығару керегін білмейді. Біз оған үйрете аламыз: бұл операторды жүктеу (operator overloading). << операторы үшін ол жеке функция түрінде жазылады:

    #include <iostream>
#include <string>

class Book {
public:
    Book(std::string title, std::string author, int year)
        : title_(title), author_(author), year_(year) {}

    const std::string& title() const { return title_; }
    const std::string& author() const { return author_; }
    int year() const { return year_; }

private:
    std::string title_;
    std::string author_;
    int year_;
};

std::ostream& operator<<(std::ostream& out, const Book& b) {
    out << "«" << b.title() << "», " << b.author() << ", " << b.year();
    return out;
}

int main() {
    Book b("Қан мен тер", "Әбдіжәміл Нұрпейісов", 1970);
    Book c("Ақбілек", "Ілияс Жансүгіров", 1927);
    std::cout << b << "\n" << c << "\n";
    std::cout << "Екі кітап: " << b << " | " << c << "\n";
}

    Қолтаңбаны бөлшектеп көрейік: std::ostream& operator<<(std::ostream& out, const Book& b).

    • Бірінші параметр - шығыс ағыны (std::cout соның нысаны). Оны сілтеме арқылы аламыз, себебі ағынды көшіруге болмайды.
    • Екінші параметр - шығарылатын нысан. const& арқылы көшірмесіз және өзгертпей аламыз.
    • Қайтарым типі - сол std::ostream&. Осының арқасында std::cout << b << "\n" << c деп тізбектеп жаза аламыз: әр << ағынды келесіге береді.

    Функция класстан тыс тұрғандықтан жабық өрістерді көре алмайды, сондықтан біз ашық title(), author() әдістерін қолдандық. Басқа жол - функцияны класс ішінде friend («дос») деп жариялау, сонда ол жабық мүшелерге қол жеткізеді. Бірақ мүмкін болса, ашық әдістер арқылы жұмыс істеген таза.

    Композиция және класс диаграммасы

    Нағыз бағдарламада класстар бір-бірінен тұрады. Кітапханада кітаптар бар, кітаптың авторы бар. Бір класстың өрісі екінші класстың нысаны болса, бұл композиция (composition) деп аталады, ал қатынас «бар» (has-a) деп оқылады: «Кітапта автор бар», «Кітапханада кітаптар бар». Мұрагерліктегі «болып табылады» (is-a) қатынасынан бұл өзгеше, оны келесі аптада көреміз.

    #include <iostream>
#include <string>
#include <vector>

class Author {
public:
    Author(std::string name, int born) : name_(name), born_(born) {}
    std::string name() const { return name_; }
    int born() const { return born_; }

private:
    std::string name_;
    int born_;
};

class Book {
public:
    Book(std::string title, Author author) : title_(title), author_(author) {}
    void print() const {
        std::cout << title_ << " - " << author_.name() << " (" << author_.born() << ")\n";
    }

private:
    std::string title_;
    Author author_;   // композиция: Book-тың ішінде Author бар
};

class Library {
public:
    Library(std::string name) : name_(name) {}
    void add(const Book& b) { books_.push_back(b); }
    void print() const {
        std::cout << name_ << " (" << books_.size() << " кітап):\n";
        for (const Book& b : books_) {
            std::cout << "  ";
            b.print();
        }
    }

private:
    std::string name_;
    std::vector<Book> books_;
};

int main() {
    Library lib("Абай атындағы кітапхана");
    lib.add(Book("Абай жолы", Author("Мұхтар Әуезов", 1897)));
    lib.add(Book("Қара сөздер", Author("Абай Құнанбайұлы", 1845)));
    lib.print();
}

  Қара сөздер - Абай Құнанбайұлы (1845)

    Кітап пен автор арасындағы байланысты көрнекі етіп сызу үшін класс диаграммасы (class diagram) қолданылады. Әр класс үш қабаттан тұрады: аты, өрістер, әдістер. Ромб (◆) «тұтас - бөлік» байланысын, яғни композицияны көрсетеді: ромб тұрған жақ - иесі.

    Диаграммадан мынаны оқимыз: кітапханада нөл немесе одан көп кітап (0..*) бар, әр кітапта нақты бір автор (1) бар. Бағдарламаны жазбай тұрып-ақ, осындай сызба жобаны түсінуге көп көмектеседі. Қағазға қарындашпен сызудың өзі жеткілікті.

    Композицияда ішкі нысан иесімен бірге жасалып, бірге жойылады. Book жойылса, ішіндегі Author көшірмесі де жойылады. Сондықтан деструкторларды қолмен жазу қажет болмайды: компилятор өзі дұрыс ретпен шақырады. Қысқа тәжірибе жасап көрейік. Үйдің құрамында қабырға мен төбе бар, конструкторда әдейі кері ретпен жаздық:

    #include <iostream>
#include <string>

class Part {
public:
    Part(std::string name) : name_(name) { std::cout << name_ << " жасалды\n"; }
    ~Part() { std::cout << name_ << " жойылды\n"; }

private:
    std::string name_;
};

class House {
public:
    House() : roof_("төбе"), wall_("қабырға") { std::cout << "Үй дайын\n"; }
    ~House() { std::cout << "Үй құлады\n"; }

private:
    Part wall_;
    Part roof_;
};

int main() {
    House h;
}

    Толық мысал: Банк шоттары

    Енді барлығын біріктірейік. Банк шоты: иесі, қалдығы, автоматты нөмірі (static санауыштан), салу, алу, бір шоттан екіншісіне аудару (Account& арқылы), және << оператор:

    #include <iostream>
#include <string>

class Account {
public:
    Account(std::string owner, double balance = 0)
        : owner_(owner), balance_(balance), id_(++count_) {}

    bool deposit(double amount) {
        if (amount <= 0) return false;
        balance_ += amount;
        return true;
    }

    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance_) return false;
        balance_ -= amount;
        return true;
    }

    bool transferTo(Account& other, double amount) {
        if (!withdraw(amount)) return false;
        other.deposit(amount);
        return true;
    }

    double balance() const { return balance_; }
    const std::string& owner() const { return owner_; }
    int id() const { return id_; }
    static int count() { return count_; }

private:
    std::string owner_;
    double balance_;
    int id_;
    inline static int count_ = 0;
};

std::ostream& operator<<(std::ostream& out, const Account& a) {
    return out << "Шот №" << a.id() << " [" << a.owner() << "]: " << a.balance() << " тг";
}

int main() {
    Account aigerim("Әйгерім", 120000);
    Account bauyrzhan("Бауыржан");

    std::cout << aigerim << "\n" << bauyrzhan << "\n";

    if (aigerim.transferTo(bauyrzhan, 45000)) {
        std::cout << "Аударым сәтті өтті\n";
    }
    if (!bauyrzhan.transferTo(aigerim, 100000)) {
        std::cout << "Аударым қабылданбады: қаражат жеткіліксіз\n";
    }

    std::cout << aigerim << "\n" << bauyrzhan << "\n";
    std::cout << "Барлық шот саны: " << Account::count() << "\n";
}

    Мұнда не болып жатыр:

    • id_(++count_) әр жаңа шотқа келесі нөмірді береді;
    • transferTo(Account& other, ...) екінші шотты сілтеме арқылы алады, сондықтан шын шот өзгереді (көшірме емес);
    • аудару алдымен withdraw арқылы ережені тексереді: қаражат жетпесе, other мүлде өзгермейді.

    Бағдарламаның ешбір жерінде balance_-ты тікелей өзгертетін код жоқ, ол тек класс ішінде. Сондықтан аудару кезінде ақша «жоғалып» немесе «пайда болып» кетуі мүмкін емес. Бұл инкапсуляцияның нақты пайдасы.

    Класты қалай жобалайды?

    Бастаушылар үшін ең қиыны - код жазу емес, қандай класс керек екенін шешу. Қарапайым әдіс бар: мәселенің сипаттамасын жазып, ондағы зат есімдер мен етістіктерді іздеңіз. Зат есімдер - класстар мен өрістер, етістіктер - әдістер. Мысалы: «Кітапханада оқырман кітап алады, кітап қайтарады. Кітапта атауы мен авторы бар».

    • Зат есімдер: кітапхана, оқырман, кітап, атауы, автор. Класс үміткерлері: Library, Reader, Book. Ал «атауы» мен «авторы» - Book-тың өрістері.
    • Етістіктер: алады, қайтарады. Әдіс үміткерлері: borrow(book), giveBack(book).

    Содан кейін әр класқа үш сұрақ қойыңыз: (1) Ол нені біледі? (өрістер). (2) Ол не істей алады? (әдістер). (3) Ол қандай ережені қорғайды? (инвариант). Мысалы, банк шоты қалдықты біледі, салып-ала алады, ал оның ережесі: «қалдық теріс болмайды».

    Тағы бір жақсы белгі - «бір класс - бір жауапкершілік». Егер классты бір сөйлеммен сипаттай алмасаңыз (мысалы, «шотты да, принтерді де, файлды да басқарады»), ол көбіне бірнеше класқа бөлінуі керек. Класс диаграммасын алдымен қағазға қарындашпен салыңыз: төрт-бес қорап пен олардың арасындағы сызықтар көбіне код жазудан бұрын көп қате жібермеуге көмектеседі. Әрине, алғашқы жоба мінсіз болмайды, ол қалыпты: код өскен сайын класстарды жақсартып отырасыз.

    Соңында қарапайым тексеру: кластың public бөлігін оқып шығыңыз. Егер онда класты қолданушыға керек емес ішкі «құрылыс» бөлшектері көрінсе, олар private болуы керек. Қолданушы «не істей аламын?» деген сұраққа ғана жауап көруі тиіс, «ішінде не жатыр?» дегенге емес.

    Жиі қателер

    1. Классты ;-сіз жабу. class A { ... }; соңындағы нүктелі үтір міндетті. Ұмытсаңыз, компилятор келесі жолдан қате көрсетеді, соның салдарынан таңқалып қаласыз.
    2. Өрісті private етпей, әдісті public қалдыру. Класта public: жазбасаңыз, бәрі жабық болып, main-нен конструкторды да шақыра алмайсыз.
    3. Нысанды жақшамен жасау тұзағы. Student a(); нысан жасамайды, ол «Student қайтаратын a функциясы» деген жариялау. Әдепкі конструктор үшін жай Student a; жазыңыз.
    4. const әдісті ұмыту. Жоғарыда көрдік: const нысанмен жұмыс істемей қалады.
    5. Инициализация тізімінің реті. Тізім емес, класта жарияланған рет басым. -Wall ескертуін оқыңыз.
    6. Артық көшіру. Функцияға Book b түрінде қабылдасаңыз, әр шақыруда көшірме жасалады. Үлкен нысанды const Book& b түрінде беріңіз.
    7. Static өрісті шақыру кезінде this іздеу. Static әдіс ішінде қарапайым өрісті қолдана алмайсыз, себебі қай нысан екені белгісіз.
    8. Өрісте мәнсіз қалдыру. int n_; кездейсоқ мән алады. Әрқашан int n_ = 0; немесе тізімде инициализациялаңыз.

    Қорытынды

    Бұл аптада біз деректер мен оларды өңдейтін функцияларды бір бүтінге біріктірдік:

    • struct пен class тек әдепкі қолжетімділікпен ерекшеленеді: struct - public, class - private;
    • конструктор нысанды дұрыс күйде жасайды, инициализация тізімі өрістерді класта жарияланған ретпен толтырады;
    • деструктор нысан аймақтан шыққанда, жасалуға кері ретпен шақырылады;
    • инкапсуляция: деректі private жасап, ережені public әдісте тексереміз;
    • const әдіс нысанды өзгертпейтініне уәде береді; const& параметр көшірмені болдырмайды;
    • this - әдіс шақырылған нысанға көрсеткіш; return *this тізбектеп шақыруға мүмкіндік береді (қайтарым типі T& болуы шарт);
    • static мүше барлық нысанға ортақ; static әдіс this-сіз жұмыс істейді;
    • operator<< нысанды std::cout арқылы шығаруға мүмкіндік береді және std::ostream& қайтарады;
    • композиция («бар» қатынасы): бір класс екіншісінің нысанын өрісте ұстайды; класс диаграммасы мұны ромбпен көрсетеді.

    Өзіңді тексеру тізімі

    • Класс пен нысанның айырмашылығын «сызба мен үй» арқылы түсіндіре аламын.
    • Конструкторды инициализация тізімімен жаза аламын және жариялау реті мен тізім ретінің айырмасын білемін.
    • Деструктор қашан және қандай ретпен шақырылатынын болжай аламын.
    • Өрістерді private етіп, ережені public әдісте тексере аламын.
    • Қай әдіс const болуы керегін айта аламын.
    • operator<< жаза аламын және оның қайтарым типінің себебін білемін.

    Өзіңізді тексеріңіз

    1. Мына код нені береді?

    class C { int x = 7; };

int main() {
    C c;
    std::cout << c.x;
}

    class-та әдепкі қолжетімділік private. main класстың мүшесі емес, сондықтан c.x-ке қол жеткізе алмайды. Егер struct C болса, 7 шығар еді.

    2. Мына бағдарлама экранға не шығарады?

    struct Loud { Loud(const char* s) { std::cout << s; } };

class P {
public:
    P() : a_("A"), b_("B") {}
private:
    Loud b_;
    Loud a_;
};
// main-де: P p;

    Өрістер тізімдегі ретпен емес, класта жарияланған ретпен жасалады: b_ бірінші, содан кейін a_. Нәтиже BA. Компилятор тек -Wreorder ескертуін береді.

    3. show(const Account& acc) функциясы ішінде acc.balance() шақырылады. Қатесіз жұмыс істеуі үшін не қажет?

    const нысанмен тек const әдістерді шақыруға болады. Дұрыс жол - әдіске const қосу, өйткені ол нысанды өзгертпейді. Тек & алып тастау көмектеспейді: const Account acc көшірмесі де const болып қала береді.

    4. Нәтиже қандай?

    class A {
public:
    A() { ++k; }
    static int k;
};
int A::k = 10;

int main() {
    A x, y, z;
    std::cout << A::k << " " << x.k;
}

    k - static, барлық нысанға ортақ бір ғана айнымалы. Үш нысан жасалғанда ол үш рет артады: 10 + 3 = 13. x.k пен A::k - бір нәрсе.

    5. Деструктор қашан шақырылады?

    Қарапайым (автоматты) нысан үшін деструкторды компилятор нысанның аймағы аяқталғанда өзі шақырады, жасалуға кері ретпен.

    6. std::cout << b << "\n" << c; деп тізбектеп жазу үшін operator<< қандай типті қайтаруы керек?

    Әр << келесі <<-ге ағынды беруі керек, ол үшін ағынға сілтеме қайтарылады. void қайтарса, тізбектеу жұмыс істемейді.

    7. Мына класта inc нысанды көшірме етіп қайтарады. Нәтиже қандай?

    class Counter {
public:
    Counter inc() { n_++; return *this; }   // сілтемесіз!
    int value() const { return n_; }
private:
    int n_ = 0;
};
// main-де:
Counter c;
c.inc().inc().inc();
std::cout << c.value();

    Бірінші inc() түпнұсқа c-ны 1-ге арттырады да, көшірме қайтарады. Келесі екі inc() сол көшірмеге қолданылады. Түпнұсқа c.value() = 1. Counter& қайтарсақ, нәтиже 3 болар еді. Екеуін де орындап тексердік.

    8. Library класының ішінде std::vector<Book> books_; өрісі бар. Бұл қандай қатынас?

    Кітапхана кітап емес, оның құрамында кітаптар бар. Бұл «бар» қатынасы, яғни композиция. Мұрагерлікті «болып табылады» қатынасында қолданамыз.

    Жаттығулар

    Әр тапсырмада «Кеңес» пен «Шешімі» бар. Алдымен өзің жазып көр, содан кейін ғана шешімге қара. Жауапты енгізу өрісімен тексеруге болатын тапсырмалар бөлек белгіленген.

    Қойлар саны

    ~Sheep() { --n_; }
    static int count() { return n_; }

    Sheep b;

    Жауап: 14. Класта тек бір аргументті конструктор бар, аргументсіз жазылған Tea t; оған сәйкес келмейді. Түзету: Tea t("қара шай");. Нақты компилятор қатесі лекцияның конструктор бөлімінде көрсетілген (t03_tea_err.cpp:14:9).

    Орташа

    Шай үйі класы

    TeaHouse класын жаз: аты (name_), жалпы құн мен тағам санын сақтайды. Конструктор тек атты алады. addDish(dish, price) тағамды қосып, оның жолын шығарады. total(), dishes(), name() - const әдістер. static санауыш қанша шай үйі жасалғанын санайды. operator<< «Аты: N тағам, барлығы M тг» түрінде шығарады.

    Кеңес

    Лекциядағы Account пен Ticket мысалдарын біріктір. total_ мен dishes_ өрістеріне әдепкі мән = 0 бер, санауышты inline static ет.

    Шешімі
    #include <iostream>
#include <string>

class TeaHouse {
public:
    TeaHouse(std::string name) : name_(name) { ++houses_; }

    void addDish(const std::string& dish, int price) {
        total_ += price;
        ++dishes_;
        std::cout << "  " << dish << ": " << price << " тг\n";
    }

    int total() const { return total_; }
    int dishes() const { return dishes_; }
    const std::string& name() const { return name_; }
    static int houses() { return houses_; }

private:
    std::string name_;
    int total_ = 0;
    int dishes_ = 0;
    inline static int houses_ = 0;
};

std::ostream& operator<<(std::ostream& out, const TeaHouse& h) {
    return out << h.name() << ": " << h.dishes() << " тағам, барлығы " << h.total() << " тг";
}

int main() {
    TeaHouse a("Дастархан");
    std::cout << a.name() << " шай үйінің чегі:\n";
    a.addDish("көк шай", 350);
    a.addDish("самса", 700);
    a.addDish("баурсақ", 500);
    std::cout << a << "\n";
    TeaHouse b("Ақ жол");
    std::cout << "Шай үйлері: " << TeaHouse::houses() << "\n";
}

    Алматы - Астана рейсі

    Flight класын жаз: рейс нөмірі, қайдан, қайда, орын саны. book(n) әдісі n орын бос болса, оларды брондап true қайтарады, әйтпесе (және n <= 0 болса) false, ал бос орын саны өзгермейді. available() бос орынды қайтарады. operator<< мына түрде шығарады: KC-101 Алматы -> Астана (бос орын: 5/5). Барлық рейстерді санайтын static санауыш қос. main-де 5 орынды рейске 3, содан кейін 4 орын брондап көр.

    Кеңес

    Екі сан сақта: жалпы орын (seats_) және бос орын (free_). Инвариант: 0 <= free_ <= seats_. book ішінде алдымен шартты тексер, содан кейін ғана free_-ті азайт. Инициализация тізімін өрістердің жариялану тәртібімен жаз.

    Шешімі
    #include <iostream>
#include <string>

class Flight {
public:
    Flight(std::string number, std::string from, std::string to, int seats)
        : number_(number), from_(from), to_(to), seats_(seats), free_(seats) {
        ++flights_;
    }

    bool book(int n) {
        if (n <= 0 || n > free_) return false;
        free_ -= n;
        return true;
    }

    int available() const { return free_; }
    const std::string& number() const { return number_; }
    const std::string& from() const { return from_; }
    const std::string& to() const { return to_; }
    int seats() const { return seats_; }
    static int flights() { return flights_; }

private:
    std::string number_;
    std::string from_;
    std::string to_;
    int seats_;
    int free_;
    inline static int flights_ = 0;
};

std::ostream& operator<<(std::ostream& out, const Flight& f) {
    return out << f.number() << " " << f.from() << " -> " << f.to()
               << " (бос орын: " << f.available() << "/" << f.seats() << ")";
}

int main() {
    Flight f("KC-101", "Алматы", "Астана", 5);
    std::cout << f << "\n";
    std::cout << "3 орын: " << (f.book(3) ? "брондалды" : "бос орын жоқ") << "\n";
    std::cout << "4 орын: " << (f.book(4) ? "брондалды" : "бос орын жоқ") << "\n";
    std::cout << f << "\n";
    Flight g("KC-102", "Астана", "Алматы", 120);
    std::cout << "Рейс саны: " << Flight::flights() << "\n";
    (void)g;
}

    • book(0) және book(-2) false қайтарады.
    • Өрістер private, ескертусіз құрастырылады.
