    5-апта

    Мұрагерлік және полиморфизм

    Бір класс екіншісінің қасиетін алып, оны өзгерте алады: «көлік» дегеннен «жеңіл көлік» пен «автобус» шығады. Бұл аптада мұрагерлікті, virtual функцияларды және бір көрсеткіш арқылы әртүрлі нысанмен жұмыс істеуді (полиморфизм) үйренеміз.

    Мұрагерлік: «болып табылады» қатынасы

    Өткен аптада композицияны көрдік: кітапханада кітаптар бар. Енді басқа түрлі қатынасты қарастырайық: жүк көлігі - бұл көлік, автобус - бұл көлік. Бұл «болып табылады» (is-a) қатынасы. Қазақ тілінде мұны «тектен тарау» дейміз: бала әке-шешенің қасиетін алады. Бағдарламалауда мұны мұрагерлік (inheritance) деп атайды.

    Мұрагерлік не үшін керек? Көліктің барлығында атау мен дөңгелек саны бар. Автобус пен жеңіл көліктің әрқайсысында бұл өрістерді қайта жазбау үшін, жалпы бөлікті бір рет базалық класта (base class) жазамыз, ал ерекшеліктерін туынды класта (derived class) жазамыз. Туынды класс базалық кластың бәрін «мұра етіп» алады және өз мүшелерін қосады.

    #include <iostream>
#include <string>

class Vehicle {
public:
    Vehicle(std::string name, int wheels) : name_(name), wheels_(wheels) {
        std::cout << "  Vehicle(" << name_ << ")\n";
    }
    ~Vehicle() { std::cout << "  ~Vehicle(" << name_ << ")\n"; }

    void info() const {
        std::cout << name_ << ": дөңгелек саны " << wheels_ << "\n";
    }

protected:
    std::string name_;

private:
    int wheels_;
};

class Bus : public Vehicle {
public:
    Bus(std::string name, int seats) : Vehicle(name, 6), seats_(seats) {
        std::cout << "  Bus(" << name_ << ")\n";
    }
    ~Bus() { std::cout << "  ~Bus(" << name_ << ")\n"; }

    void seatsInfo() const {
        std::cout << name_ << ": " << seats_ << " орын\n";
    }

private:
    int seats_;
};

int main() {
    Bus b("Алматы-12", 45);
    b.info();         // Vehicle-дан мұраланған
    b.seatsInfo();    // Bus-тың өзінікі
}

    Суретте үш жануар бір Animal класына қарай «жоғары» бағытталған: әрқайсысы - жануар. Бұл иерархияны төменде нақты бағдарламамен («ферма» мысалы) толтырамыз.

    Өз компьютеріңде іске қос

    Әр мысалды main.cpp файлына жазып, терминалда құрастыр да іске қос:

    g++ -std=c++17 -Wall -Wextra -fsanitize=address,undefined main.cpp -o main && ./main

    Бұл апта үшін -Wall -Wextra ерекше маңызды: компилятор ұмытылған override, дұрыс емес инициализация реті сияқты қателерді ескерту ретінде көрсетеді. -fsanitize=address жадпен байланысты қателерді (қос босату, босатылған жадты оқу) орындау кезінде ұстайды.

    protected және мұрагерліктегі қолжетімділік

    4-аптада public пен private көрдік. Мұрагерлікте тағы бір деңгей керек болады. Егер базалық кластың өрісін private қылсақ, туынды класс оны көре алмайды (ол «ата-ананың жеке күнделігі» сияқты). Ал public қылсақ, бүкіл әлем көреді. Ортасы - protected: тек класстың өзі мен оның мұрагерлері көре алады, сырттан кірген main көре алмайды.

    Кім қолдана алады?publicprotectedprivate
    Класстың өз әдісіиәиәиә
    Туынды класс әдісіиәиәжоқ
    Сырттан (main, басқа функция)иәжоқжоқ

    Мысалы, жылқы өз атын айта алады (protected өрісті қолданады), бірақ main оған тікелей қол сұқса, компилятор тоқтатады:

    #include <iostream>
#include <string>

class Animal {
public:
    Animal(std::string n) : name_(n) {}

protected:
    std::string name_;
};

class Horse : public Animal {
public:
    Horse(std::string n) : Animal(n) {}
    void say() const { std::cout << name_ << " кісінеді\n"; }   // protected - рұқсат
};

int main() {
    Horse h("Тұлпар");
    h.say();
    std::cout << h.name_ << "\n";   // сырттан - қате
}

    protected-ті үнемді қолданыңыз

    Өрісті protected қылу - инкапсуляцияны босаңсыту, себебі кез келген мұрагер оны өзгерте алады. Тәжірибелі бағдарламашылар өрісті private қалдырып, мұрагерлерге арнап protected әдіс береді. Оқу мысалдарында қарапайымдылық үшін protected өріс жазылады, бірақ нағыз жобада бұл ереже жақсырақ.

    Конструктор мен деструктор реті

    Туынды нысан жасалғанда алдымен оның базалық бөлігі жасалуы керек, себебі туынды бөлік базалыққа сүйенеді. Үйдің іргетасынан бастап салатыны сияқты. Сондықтан конструкторлар жоғарыдан төмен шақырылады, ал деструкторлар кері ретпен: төбеден бастап бұзылады. 1-мысалдың нәтижесінде осыны көрдік: Vehicle → Bus, содан кейін ~Bus → ~Vehicle.

    Базалық конструкторға аргумент беру үшін туынды конструкторда инициализация тізімін қолданамыз: Bus(...) : Vehicle(name, 6), seats_(seats). Егер оны жазбасақ, базалық классты әдепкі конструктормен жасауға тырысады, ал ондай конструктор жоқ болса, қате шығады.

    Тізбек ұзарса да, ереже өзгермейді. Үш деңгейлі мысал:

    #include <iostream>

struct A { A() { std::cout << "A "; } ~A() { std::cout << "~A "; } };
struct B : A { B() { std::cout << "B "; } ~B() { std::cout << "~B "; } };
struct C : B { C() { std::cout << "C "; } ~C() { std::cout << "~C "; } };

int main() {
    C c;
    std::cout << "| ";
}

    Конструкторлар A B C ретімен, деструкторлар ~C ~B ~A ретімен жұмыс істеді. Егер туынды класстың өрісі де болса, ол базалық бөліктен кейін, бірақ туынды конструктордың денесінен бұрын жасалады:

    #include <iostream>

struct Tail { Tail() { std::cout << "Tail "; } };

struct Animal {
    Animal() { std::cout << "Animal "; }
};

struct Fox : Animal {
    Tail tail_;

};

int main() {
    Fox f;
    std::cout << "\n";
}

    virtual және override

    Енді мұрагерліктің ең қызықты бөлігіне келдік. Кез келген Circle - бұл Shape, сондықтан Shape-ке көрсеткіш Circle-ды ұстай алады. Бір сұрақ: ол көрсеткіш арқылы area() шақырсақ, қай нұсқа орындалады - Shape-тікі ме, әлде Circle-дікі ме? Көрейік:

    #include <iostream>

class Shape {
public:
    double area() const { return 0; }
};

class Circle : public Shape {
public:
    Circle(double r) : r_(r) {}
    double area() const { return 3.14159 * r_ * r_; }

private:
    double r_;
};

int main() {
    Circle c(2);
    Shape* p = &c;
    std::cout << "Circle арқылы: " << c.area() << "\n";
    std::cout << "Shape* арқылы: " << p->area() << "\n";
}
    $ ./a03_nonvirtual
Circle арқылы: 12.5664
Shape* арқылы: 0

    Күтпеген нәтиже: көрсеткіш арқылы 0 шықты, шеңбердің ауданы емес. Әдепкіде C++ қай нұсқаны шақыруды көрсеткіштің типіне қарап, компиляция кезінде шешеді. p типі - Shape*, сондықтан Shape::area шақырылды. Мұны статикалық байланыстыру (static binding) дейді.

    Біз нысанның нақты типіне қарап шешім қабылдаған қалаймыз. Ол үшін базалық класта функцияны virtual деп белгілейміз:

    #include <iostream>

class Shape {
public:
    virtual double area() const { return 0; }
    virtual ~Shape() = default;
};

class Circle : public Shape {
public:
    Circle(double r) : r_(r) {}
    double area() const override { return 3.14159 * r_ * r_; }

private:
    double r_;
};

int main() {
    Circle c(2);
    Shape* p = &c;
    std::cout << "Circle арқылы: " << c.area() << "\n";
    std::cout << "Shape* арқылы: " << p->area() << "\n";
}
    $ ./a04_virtual
Circle арқылы: 12.5664
Shape* арқылы: 12.5664

    Енді Shape* арқылы да Circle нұсқасы шақырылды. Бұл динамикалық байланыстыру (dynamic binding) немесе полиморфизм (polymorphism, грекше «көп пішінділік»): бір ғана p->area() жазуы нысанға қарай әртүрлі код орындайды.

    Туынды класта override кілт сөзін жазғанымызға назар аударыңыз. Ол міндетті емес, бірақ өте пайдалы: «мен базалық кластың виртуалды функциясын қайта анықтап жатырмын» деп компиляторға айтады, ал сәйкес функция жоқ болса, компилятор қате береді. Қателесу өте оңай. Мысалы, const ұмыту:

    #include <iostream>

class Animal {
public:
    virtual void speak() const { std::cout << "...\n"; }
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void speak() override { std::cout << "Hau!\n"; }   // const ұмытылды
};

int main() {
    Dog d;
    d.speak();
}

Компилятор тек -Woverloaded-virtual ескертуін берді, оған көңіл бөлмесең, бағдарлама үнсіз қате істейді. Ереже: әр қайта анықталған виртуалды функцияға override жазыңыз.

    final

    final кілт сөзі «бұдан әрі өзгертуге болмайды» деген мағына береді. Оны екі жерде қолданамыз: виртуалды функцияға (мұрагерлер оны қайта анықтай алмайды) және бүкіл класқа (одан мұрагерлену мүмкін емес). Мысалы, студенттік билеттің тарифін ешкім қайта анықтамасын десек:

    #include <iostream>

class Ticket {
public:
    virtual ~Ticket() = default;
    virtual int price() const { return 5000; }
    virtual const char* kind() const { return "жалпы"; }
};

class StudentTicket final : public Ticket {   // final: мұрагер болмайды
public:
    int price() const override { return 2500; }
    const char* kind() const final { return "студент"; }
};

int main() {
    StudentTicket t;
    const Ticket& r = t;
    std::cout << r.kind() << " билеті: " << r.price() << " тг\n";
}

    Абстрактілі класс және таза virtual

    «Фигура» деген нысанды елестетіп көріңіз. Фигураның ауданы неше? Айту мүмкін емес: ол шеңбер ме, төртбұрыш па? Жалпы «фигураның» ауданын есептейтін формула жоқ. Осындай жағдайда функцияны таза виртуалды (pure virtual) етіп жариялаймыз: денесі жоқ, соңында = 0 тұрады. Кем дегенде бір таза виртуалды функциясы бар класс абстрактілі класс (abstract class) деп аталады. Одан нысан жасауға болмайды:

    #include <iostream>

class Shape {
public:
    virtual double area() const = 0;
};

int main() {
    Shape s;
    std::cout << s.area() << "\n";
}

    Абстрактілі класс - «келісімшарт» сияқты: ол «барлық мұрагер мына әрекеттерді орындай алуы керек» дейді, ал қалай орындалатыны мұрагерге байланысты. Енді нағыз мысал: дәстүрлі музыкалық аспаптар. Әр аспап атын айтып, ойналуын көрсетуі керек, ал таныстыру жолы ортақ:

    #include <iostream>
#include <string>
#include <vector>
#include <memory>

class Instrument {
public:
    virtual ~Instrument() = default;
    virtual std::string name() const = 0;       // таза virtual
    virtual void play() const = 0;
    void introduce() const {                    // жалпы әдіс
        std::cout << name() << " -> ";
        play();
    }
};

class Dombyra : public Instrument {
public:
    std::string name() const override { return "Домбыра"; }
    void play() const override { std::cout << "күй тартылды (2 ішек)\n"; }
};

class Kobyz : public Instrument {
public:
    std::string name() const override { return "Қобыз"; }
    void play() const override { std::cout << "бақсы күйі естілді\n"; }
};

int main() {
    std::vector<std::unique_ptr<Instrument>> orchestra;
    orchestra.push_back(std::make_unique<Dombyra>());
    orchestra.push_back(std::make_unique<Kobyz>());
    for (const auto& i : orchestra) {
        i->introduce();
    }
}

Қобыз -> бақсы күйі естілді

    Мұнда не бар:

    • Instrument - абстрактілі. name() мен play() таза виртуалды, ал introduce() - жалпы әдіс, ол соларды шақырады.
    • Dombyra мен Kobyz екі функцияны да override етті. Біреуін ұмытса, олар да абстрактілі болып қалар еді.
    • Оркестр - Instrument-ке көрсеткіштер тізімі. Ішінде әртүрлі аспап бар, бірақ біз бәрімен бірдей жұмыс істейміз.
    std::unique_ptr деген не?

    std::unique_ptr<T> - «ақылды көрсеткіш» (smart pointer). Ол өзі меңгерген нысанды жойылғанда автоматты түрде delete жасайды, сондықтан біз қолмен жадты босатуды ұмытпаймыз. std::make_unique<Dombyra>() нысанды жасап, оған unique_ptr береді. Ақылды көрсеткіштерді 7-аптадағы RAII бөлімінде тереңірек қараймыз. Қазірше оны «өзі жинап алатын көрсеткіш» ретінде қабылдаңыз.

    vtable: бұл қалай жұмыс істейді?

    Компилятор қай функцияны шақыру керегін орындау кезінде қалай біледі? Көптеген компиляторлар бір және сол әдісті қолданады (стандартта талап етілмейді, бірақ іс жүзінде солай). Әр виртуалды функциясы бар класс үшін виртуалды функциялар кестесі (vtable) жасалады: онда әр виртуалды функцияның нақты нұсқасының мекенжайы тұрады. Ал әр нысанның ішінде жасырын көрсеткіш (vptr) болады, ол өз класының кестесіне нұсқайды.

    Схема бойынша: i->play() шақырылғанда бағдарлама нысанның vptr-ін оқиды, кестеге барады, play жолындағы мекенжайды алып, сол кодқа секіреді. Нысан Dombyra болса, Dombyra::play, Kobyz болса, Kobyz::play. Біз Instrument* типінің артында қандай нысан тұрғанын білмейміз, бірақ нысанның өзі біледі.

    Бұдан екі практикалық қорытынды шығады:

    • виртуалды функция сәл қымбатырақ (бір қосымша көрсеткіш оқу), бірақ көп жағдайда бұл елеусіз;
    • виртуалды функциясы бар нысан бір көрсеткішке (8 байтқа) ауырлайды. Конструктор мен деструктор сәтінде кесте де орнатылады, сондықтан конструктор ішінде виртуалды шақыру туынды нұсқаны емес, ағымдағы класстың нұсқасын шақырады.

    Статикалық және динамикалық тип

    Бір көрсеткіштің екі типі болады. Статикалық тип - код жазғанда көрсетілген тип: Shape* p үшін ол Shape*. Динамикалық тип - көрсеткіштің қазір нұсқап тұрған нысанның нақты типі: ол Circle болуы мүмкін. Бағдарлама жұмыс істеп тұрғанда динамикалық тип өзгеруі мүмкін, ал статикалық тип ешқашан өзгермейді. Виртуалды емес функция статикалық типке қарап, ал виртуалды функция динамикалық типке қарап таңдалады. Осы екі сөзді есте сақтасаңыз, мұрагерлікке қатысты ойлау әлдеқайда жеңілдейді.

    Қадамдап көрейік. Aspap* p = new Dombyra; болғанда p->daus() дұрыс функцияны қалай табады? Төмендегі визуализаторда нысан → vptr → vtable → функция тізбегін қадамдап көріңіз, содан кейін virtual жоқ жағдаймен және slicing-пен салыстырыңыз.

    Көрсеткіш не сілтеме арқылы полиморфизм

    Полиморфизмнің негізгі пайдасы - бір кодпен әртүрлі нысанды өңдеу. Ферма мысалын қарайық: түйе, бүркіт, қой. Барлығы - жануар, бәрінің дауысы мен аяқ саны бар, бірақ олар әртүрлі:

    Полиморфизм жұмыс істеуі үшін үш шарт қатар орындалуы керек:

    1. функция базалық класта virtual деп жарияланған;
    2. нысанға көрсеткіш не сілтеме арқылы қол жеткізіледі;

    Slicing: нысанды кесіп алу қатесі

    Нысанды базалық типке мәнмен берсек, не болады? Туынды бөлік жай ғана «кесіліп» тасталады, тек базалық бөлік көшіріледі. Бұл құбылыс slicing (object slicing, «кесіп алу») деп аталады.

    #include <iostream>
#include <string>

    std::string name_;

class Manager : public Employee {
public:

void byValue(Employee e) {

}

void byRef(const Employee& e) {

}

int main() {

    byValue(m);
    byRef(m);
}

    Rule of Three және Rule of Five кіріспесі

    Деструкторға байланысты бір маңызды ереже бар. Егер класыңыз өзі ресурс (мысалы, new арқылы алынған жад) иеленсе, оның деструкторын жазасыз. Бірақ компилятор нысанды көшіргенде (Name b = a;) әдепкіде көрсеткішті «байт-байтымен» көшіреді. Нәтижесінде екі нысан бір жадқа нұсқайды, ал екеуі де жойылғанда сол жад екі рет босатылады. Көрейік:

    #include <cstring>
#include <iostream>

public:
    Name(const char* s) : data_(new char[std::strlen(s) + 1]) {

    ~Name() { delete[] data_; }

private:

    }                   // b жойылды -> a.data_ да босатылды
    std::cout << a.c_str() << "\n";   // қолданылған жад!

    Көшіру конструкторы мен көшіру меншіктеуінің айырмасы жиі шатастырылады. Нысан әлі жоқ болып, басқасынан жасалса, көшіру конструкторы шақырылады (Name b = a;, Name b(a);, нысанды мәнмен функцияға беру). Нысан бар болып, оған жаңа мән берілсе, меншіктеу операторы жұмыс істейді (c = a;). Бір жолда «=» белгісі тұрғанына қарамастан, Name b = a; меншіктеу емес, конструктор. Мысалдағы нәтижеде «көшірілді» жазуы тек бір рет (b үшін) шықты, ал c = a үнсіз орындалды, себебі меншіктеу операторында ештеңе шығармадық.

    C++11-ден бері көшіру конструкторы мен деструкторды жазбай-ақ, компилятор өзі жасаған нұсқаларды қолдануды = default, ал тыйым салуды = delete арқылы анық жазуға болады. Мысалы, Name(const Name&) = delete; нысанды көшіруге мүлде тыйым салады: көшіруге тиіс емес нәрсені (файл дескрипторы, желі байланысы) қорғаудың ең оңай жолы.

    C++11-ден бері көшіруден бөлек жылжыту (move) ұғымы бар. Егер нысан уақытша болса (мысалы, функция қайтарған), оның ресурсын көшірудің қажеті жоқ, оны жай ғана «тартып алуға» болады. Осыдан Rule of Five шығады: үшеуіне қосымша жылжыту конструкторы мен жылжыту меншіктеуі.

    #include <iostream>
#include <utility>
#include <string>

class Buffer {
public:
    explicit Buffer(std::size_t n) : n_(n), data_(new int[n]()) {
        std::cout << "жасалды (" << n_ << ")\n";
    }
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& o) : n_(o.n_), data_(new int[o.n_]) {
        for (std::size_t i = 0; i < n_; ++i) data_[i] = o.data_[i];
        std::cout << "көшірілді\n";
    }
    Buffer& operator=(const Buffer& o) {
        if (this != &o) {
            Buffer tmp(o);
            std::swap(n_, tmp.n_);
            std::swap(data_, tmp.data_);
        }
        return *this;
    }
    Buffer(Buffer&& o) noexcept : n_(o.n_), data_(o.data_) {
        o.n_ = 0;
        o.data_ = nullptr;
        std::cout << "көшірілмей, жылжытылды\n";
    }
    Buffer& operator=(Buffer&& o) noexcept {
        if (this != &o) {
            delete[] data_;
            n_ = o.n_;
            data_ = o.data_;
            o.n_ = 0;
            o.data_ = nullptr;
        }
        return *this;
    }
    std::size_t size() const { return n_; }

private:
    std::size_t n_;
    int* data_;
};

Buffer make() { return Buffer(1000); }

int main() {
    Buffer a(10);
    Buffer b = a;                 // көшіру
    Buffer c = std::move(a);      // жылжыту
    std::cout << "a: " << a.size() << ", b: " << b.size() << ", c: " << c.size() << "\n";
    Buffer d = make();
    std::cout << "d: " << d.size() << "\n";
}

    Rule of Zero: ең жақсы ереже

    Ең жақсы жағдай - бесеуін де жазбау. Егер сіз жадты қолмен басқармай, std::string, std::vector, std::unique_ptr сияқты дайын кластарды өрістер ретінде қолдансаңыз, компилятор жасаған әдепкі көшіру, жылжыту және деструктор өздері дұрыс жұмыс істейді. Мұны Rule of Zero («нөл ереже») дейді. Бұл апта үшін Rule of Three/Five кіріспе ғана; шын жобада алдымен дайын контейнерлерге жүгініңіз.

    Дизайн мысалы: билет жүйесі

    Мұрагерлікті практикада қалай ойластырамыз? Аэропорт кассасында билеттер бар делік: ересектер билеті, балалар билеті, студенттер билеті. Үшеуінің де нөмірі, бағыты мен бағасы бар, бірақ баға әртүрлі есептеледі. Дизайн қадамдары:

    1. Ортақ бөлікті табу. Нөмір, бағыт, негізгі баға - базалық Ticket класына.
    2. Өзгеретін мінез-құлықты анықтау. Бағаны есептеу әдісі әр түрде басқа. Оны virtual int price() const етеміз.
    3. Базалық класс нысаны керек пе? «Жалпы билет» деген нәрсе жоқ, сондықтан price() таза виртуалды, Ticket абстрактілі.
    4. Мұрагерлерді жазу. AdultTicket толық бағаны, ChildTicket 50%, StudentTicket 25% жеңілдікті қайтарады. Кассаның қалған коды тек Ticket& не Ticket* арқылы жұмыс істейді, сондықтан жаңа билет түрі қосылса, ол өзгермейді.
    5. Жад пен деструктор. Билеттер контейнерде ұсталса, олар unique_ptr<Ticket> арқылы сақталады, ал Ticket виртуалды деструкторы бар.

    Осы ойлау реті кез келген мұрагерлік мәселесіне қолданылады: ортақты жоғары шығар, өзгеретінді virtual ет, нысан жасалмайтын жалпы ұғымды абстрактілі ет. Лекцияның соңындағы «Төлем әдістері» жаттығуы дәл осы құрылымды қайталайды.

    Мұрагерлік пе, композиция ма?

    Мұрагерлікті үйренген бастаушылар оны барлық жерде қолданғысы келеді. Бұл үйреншікті қателік. Мұрагерлік - өте тығыз байланыс: базалық класты өзгертсеңіз, барлық мұрагер әсер етеді. Сондықтан дұрыс таңдау үшін екі сұрақ қойыңыз:

    1. «Туынды нысанды базалық нысанның орнына барлық жерде қоя аламын ба?» Бұл Барбара Лисковтың алмастыру қағидасы. Егер функция Bird күтсе, оған Penguin берсеңіз, ол «ұшу» әрекетін орындай ала ма? Пингвин ұша алмаса, Penguin класын Bird-тен «ұша алатын құс» мағынасында мұрагерлеуге болмайды. Шаршы мен тіктөртбұрыш мысалы да осыған ұқсас: тіктөртбұрыштың енін жеке өзгертуге болады, шаршының болмайды.
    2. «Бұл «болып табылады» ма, әлде «бар» ма?» Автобус - көлік (мұрагерлік). Автобуста қозғалтқыш бар (композиция). Қозғалтқыштан мұрагерлену дұрыс емес, себебі автобус қозғалтқыш емес.

    Қосымша ереже: мұрагерлікті интерфейс (келісімшарт) үшін қолданыңыз, ал кодты қайта қолдану үшін композицияны таңдаңыз. Интерфейс деп C++-та көбіне тек таза виртуалды функциялардан тұратын абстрактілі класты айтады (біздің Instrument сияқты). Мұндай класс «не істеуге болады» дегенді ғана сипаттайды, ал «қалай істеледі» мұрагерге қалдырылады. Нәтижесінде бағдарламаның бөліктері бір-біріне тікелей тәуелді емес, олар тек келісімшартты біледі. Бұл - үлкен жобаны оңай өзгертуге мүмкіндік беретін ең пайдалы идеялардың бірі.

    Интерфейс идеясын нақты мысалмен көрейік. Кітаптың сипаттамасы бар (Describable) және бағасы бар (Priced). Музей қоры сипатталады, бірақ сатылмайды. Екі интерфейс бөлек, ал Book екеуін де орындайды:

    #include <iostream>
#include <string>
#include <vector>

class Describable {                       // интерфейс: тек таза виртуалды функциялар
public:
    virtual ~Describable() = default;
    virtual std::string describe() const = 0;
};

class Priced {
public:
    virtual ~Priced() = default;
    virtual int price() const = 0;
};

class Book : public Describable, public Priced {
public:
    Book(std::string t, int p) : title_(t), price_(p) {}
    std::string describe() const override { return "Кітап «" + title_ + "»"; }
    int price() const override { return price_; }

private:
    std::string title_;
    int price_;
};

class Museum : public Describable {
public:
    std::string describe() const override { return "Музей қоры (сатылмайды)"; }
};

void printAll(const std::vector<const Describable*>& items) {
    for (const Describable* d : items) {
        std::cout << " - " << d->describe() << "\n";
    }
}

int main() {
    Book b1("Қара сөздер", 2500);
    Book b2("Көшпенділер", 4200);
    Museum m;
    printAll({&b1, &b2, &m});

    const Priced* p = &b2;               // сол нысанға басқа интерфейс арқылы қарау
    std::cout << "Баға: " << p->price() << " тг\n";
}

    Мұнда printAll функциясы кітап пен музей қорының айырмасын білмейді, ол тек Describable келісімшартын біледі. Ертең сипатталатын жаңа зат (мысалы, мұражай билеті) пайда болса, printAll өзгермейді. Сол b2 нысанына екінші интерфейс (Priced) арқылы да қарадық. Мұндай бірнеше интерфейстен мұрагерлену C++-та қауіпсіз, өйткені интерфейстерде өріс жоқ және шатасатын ештеңе жоқ. Екі интерфейс-емес кластан бірден мұрагерлену күрделі, ол жағдайды әдетте композициямен ауыстыру жақсы.

    Қайта анықтау мен жасыру

    Тапсырма 2-дегі g() мысалына оралайық. Виртуалды емес функцияны туындыда қайта жазсақ, ол базалық нұсқаны қайта анықтамайды, тек жасырады (name hiding). Туынды нысанмен тікелей жұмыс істегенде жаңа нұсқа көрінеді, ал базалық көрсеткіш арқылы ескі нұсқа шақырылады. Нәтижесі: бір нысан, екі түрлі жауап. Мұндай жағдай бағдарламаны түсініксіз етеді, сондықтан ереже қарапайым: базалық класта виртуалды емес функцияны туындыда қайта жазбаңыз. Егер мінез-құлық өзгеруі керек болса, оны virtual жасаңыз.

    Тағы бір нәзік жағдай: туынды класс базалық функцияның аты бірдей, бірақ параметрлері басқа нұсқасын жазса, базалық барлық нұсқалар жасырылады. Бұл жөнінде компилятор -Woverloaded-virtual ескертуін берді (a05 және a06 мысалдарында көрдік). Ескертулерге мән беріңіз: олар көбіне ойластырылмаған қатені көрсетеді.

    Жиі қателер

    1. Деструкторды виртуалды етпеу. Базалық көрсеткіш арқылы delete істесеңіз, туынды бөлік жойылмайды. Базада virtual ~Base() = default;.
    2. override жазбау. const не параметр типі сәйкес келмесе, функция қайта анықталмай, жаңасы жасалады. Компилятор ұстау үшін әрқашан override жазыңыз.
    3. Нысанды мәнмен беру (slicing). void f(Base b) орнына void f(const Base& b).
    4. Абстрактілі классты жасауға тырысу. Таза виртуалды функциясы бар кластан нысан алынбайды; туындыда барлық таза виртуалды функцияны қайта анықтау керек.
    5. Конструктор ішінде виртуалды шақыру. Конструктор кезінде нысанның түрі әлі ағымдағы класс, сондықтан туынды нұсқа орындалмайды.
    6. public-ті ұмыту. class B : A жазсаңыз, class үшін әдепкі мұрагерлік private, ал struct үшін public. Әрқашан : public A деп жазыңыз.
    7. Мұрагерлікті артық қолдану. «Болып табылады» қатынасы жоқ жерде композицияны таңдаңыз. «Автобус - көлік», бірақ «кітапхана - кітап» емес.
    8. Көшіруді ұмыту. Жадты иеленетін класта Rule of Three/Five орындалмаса, ерте-кеш «қос босату» қатесі шығады.

    Қорытынды

    • Мұрагерлік (class D : public B) «болып табылады» қатынасын білдіреді; туынды класс базалық мүшелерді алады.
    • protected мүше тек класта және мұрагерлерде көрінеді; бірақ өрісті мүмкіндігінше private қалдырыңыз.
    • Конструкторлар жоғарыдан төмен (база → туынды), деструкторлар төменнен жоғары.
    • virtual функция динамикалық байланыстыруды қосады, override қателерді компиляция кезінде ұстайды, final одан әрі өзгертуді тыйады.
    • Таза виртуалды функция (= 0) классты абстрактілі етеді; одан тек мұрагерлер арқылы нысан жасалады.
    • vtable идеясы: әр нысанда vptr бар, ол кластың функциялар кестесіне нұсқайды.
    • Полиморфизм көрсеткіш не сілтеме арқылы жұмыс істейді; мәнмен берсек, slicing болады.
    • Полиморфты базада деструктор virtual болуы керек.
    • Ресурс иеленетін класта Rule of Three/Five; мүмкін болса, Rule of Zero.

    Өзіңді тексеру тізімі

    • «Болып табылады» мен «бар» қатынасының айырмасын мысалмен түсіндіре аламын.
    • Базалық және туынды конструктор/деструктор ретін болжай аламын.
    • virtual болмаса не болатынын, override не беретінін түсіндіре аламын.
    • Абстрактілі класс жазып, одан бірнеше мұрагер жасай аламын.
    • Slicing қатесін танып, түзете аламын.
    • Виртуалды деструктор неге керегін айта аламын.
    • Rule of Three-дегі үш мүшені атай аламын.

    Өзіңізді тексеріңіз

    1. Мына бағдарлама не шығарады?

    struct Base {
    virtual const char* who() const { return "Base"; }
};
struct Derived : Base {
    const char* who() const override { return "Derived"; }
};

void show(Base b) { std::cout << b.who() << "\n"; }

// main-де:
Derived d;
show(d);
Base& r = d;
std::cout << r.who() << "\n";

    show нысанды мәнмен алады, сондықтан Derived бөлігі кесіліп (slicing), тек Base қалады. Сілтеме арқылы нысанның өзі сақталады, сондықтан Derived шығады. Компилятормен тексердік.

    2. Қай жағдайда виртуалды деструктор міндетті?

    Деструктор виртуалды болмаса, базалық көрсеткіш арқылы delete тек базалық деструкторды шақыруы мүмкін, ал бұл анықталмаған әрекет және жад ағуы.

    3. Таза виртуалды функциясы бар класс туралы қай пікір дұрыс?

    Абстрактілі класс тек базалық түрде қолданылады. Мұрагер таза виртуалды функцияларды қайта анықтағанда ғана нысан жасауға болады.

    4. Туынды класта void speak() override жазылған, ал базада virtual void speak() const. Не болады?

    Қолтаңба сәйкес емес (const жоқ), сондықтан функция базаны қайта анықтамайды. override дәл осындай қателерді құрастыру кезінде ұстау үшін бар.

    5. Мына нысан жасалғанда экранға не шығады?

    struct Tail   { Tail()   { std::cout << "Tail ";   } };
struct Animal { Animal() { std::cout << "Animal "; } };
struct Fox : Animal {
    Tail tail_;
    Fox() { std::cout << "Fox "; }
};
// main-де: Fox f;

    Алдымен базалық бөлік (Animal), содан кейін туынды класстың өрістері (Tail), ең соңында туынды конструктордың денесі (Fox).

    6. Rule of Three бойынша қай үштік бірге жазылуы керек?

    Ресурс иеленетін класта осы үшеуі бірге анықталады. Жылжыту конструкторы мен жылжыту меншіктеуі қосылса, Rule of Five болады.

    7. protected өріске кім қол жеткізе алады?

    protected - private пен public арасындағы деңгей: мұрагерлер көреді, сырттағы код көрмейді.

    8. Мына код компиляцияланады ма?

    class A final {};
class B : public A {};

    Компилятор cannot derive from 'final' base 'A' деген қате береді. Мұны нақты тексердік.

    Деструкторлар реті

    Мына бағдарлама A B C | ~C ~B ~A шығарады (лекциядағы t01_vehicle_order). Құрылымы: struct B : A, struct C : B, main-де C c;. Шыққан нәтижедегі бірінші «~» белгісімен басталатын жазуды ашып жаз (мысалы, ~X түрінде).

    Кеңес

    Конструкторлар базадан туындыға қарай жұмыс істейді. Деструкторлар қалай?

    Шешімі

    Жауап: ~C. Деструкторлар конструкторларға кері ретпен шақырылады: ең соңғы жасалған C бірінші жойылады. Нақты нәтиже лекцияда көрсетілген.

    Оңай

    Қай g()?

    Мына кодта f() виртуалды, ал g() виртуалды емес. Base* p = &d; болғанда, p->g() қай жолды шығарады: Base-g әлде Derived-g?

    #include <iostream>

struct Base {
    virtual void f() const { std::cout << "Base "; }
    void g() const { std::cout << "Base-g "; }
};
struct Derived : Base {
    void f() const override { std::cout << "Derived "; }
    void g() const { std::cout << "Derived-g "; }
};

int main() {
    Derived d;
    Base* p = &d;
    p->f();
    p->g();
    d.g();
    std::cout << "\n";
}
    Кеңес

    Функция виртуалды болмаса, шақырылатын нұсқа көрсеткіштің типіне қарап таңдалады.

    Шешімі

    Жауап: Base-g. Нәтиже:

    $ ./t02_override
Derived Base-g Derived-g
    Орташа

    Ұмытылған сөз

    Мына класс override қатесін береді. Базада: virtual void speak() const. Туындыда: void speak() override. Қатені түзету үшін override-тан алдын қай кілт сөзді қосу керек? (бір сөз)

    Кеңес

    Сәйкес келмейтін нәрсе: қолтаңба. Базадағы функцияның жақшасынан кейін не тұр?

    Шешімі

    Жауап: const: void speak() const override. Компиляторға берілген қате: marked 'override', but does not override.

    Орташа

    Төлем әдістері

    Абстрактілі Payment класын жаз: таза виртуалды fee(double amount) (комиссия) және name(), виртуалды деструктор. Үш мұрагер жаз: CardPayment (1%), CashPayment (0%), QrPayment (0.5%). main-де std::vector<std::unique_ptr<Payment>> құрып, 20000 тг-ге комиссияны шығар.

    Кеңес

    Әр мұрагерде екі функцияны да override ет. Қолма-қол төлемде параметр керек емес, сондықтан double атаусыз қалдыруға болады (ескерту шықпайды).

    Шешімі
    #include <iostream>
#include <memory>
#include <string>
#include <vector>

class Payment {
public:
    virtual ~Payment() = default;
    virtual double fee(double amount) const = 0;     // комиссия
    virtual std::string name() const = 0;
};

class CardPayment : public Payment {
public:
    double fee(double amount) const override { return amount * 0.01; }
    std::string name() const override { return "Карта"; }
};

class CashPayment : public Payment {
public:
    double fee(double) const override { return 0; }
    std::string name() const override { return "Қолма-қол"; }
};

class QrPayment : public Payment {
public:
    double fee(double amount) const override { return amount * 0.005; }
    std::string name() const override { return "QR"; }
};

int main() {
    std::vector<std::unique_ptr<Payment>> methods;
    methods.push_back(std::make_unique<CardPayment>());
    methods.push_back(std::make_unique<CashPayment>());
    methods.push_back(std::make_unique<QrPayment>());

    double amount = 20000;
    for (const auto& m : methods) {
        std::cout << m->name() << ": комиссия " << m->fee(amount) << " тг\n";
    }
}
    $ ./t04_payment
Карта: комиссия 200 тг
Қолма-қол: комиссия 0 тг
QR: комиссия 100 тг
    Тексеру
    • Payment-тен нысан жасауға болмайды (абстрактілі).
    • Барлық мұрагерде override жазылған.
    • Базада virtual ~Payment() = default; бар.
    • Комиссиялар 200, 0, 100 тг шығады.

    Қиын

    Фигуралар иерархиясы

    Shape (абстрактілі: area(), name()), Rect, Circle кластарын жаз, Square-ды Rect-тен final мұрагер ет (Square(5) шаршысы). Бәрін бір векторда ұста, әрқайсысының ауданын және жалпы ауданды шығар. Мұрагерліктің дұрыс-бұрыстығы туралы ойлан: шаршы шынымен тіктөртбұрыш па?

    Кеңес

    Square конструкторы Rect(s, s) шақырады. name() ғана қайта анықталады, area() мұраланады. Нысандарды std::make_unique арқылы жаса.

    Шешімі
    #include <iostream>
#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual const char* name() const = 0;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
    const char* name() const override { return "тік төртбұрыш"; }

private:
    double w_, h_;
};

class Circle : public Shape {
public:
    Circle(double r) : r_(r) {}
    double area() const override { return 3.14159 * r_ * r_; }
    const char* name() const override { return "шеңбер"; }

private:
    double r_;
};

class Square final : public Rect {
public:
    Square(double s) : Rect(s, s) {}
    const char* name() const override { return "шаршы"; }
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Rect>(3, 4));
    shapes.push_back(std::make_unique<Circle>(1));
    shapes.push_back(std::make_unique<Square>(5));

    double total = 0;
    for (const auto& s : shapes) {
        std::cout << s->name() << ": " << s->area() << "\n";
        total += s->area();
    }
    std::cout << "Жалпы ауданы: " << total << "\n";
}
    $ ./t05_shapes
тік төртбұрыш: 12
шеңбер: 3.14159
шаршы: 25
Жалпы ауданы: 40.1416
    Тексеру
    • 12, 3.14159, 25 және жалпы 40.1416 шығады.
    • class X : public Square жазып көр: компилятор қате береді.
    • -fsanitize=address,undefined қатесіз өтеді (жад ағуы жоқ).

    Қиын

    Қай қате?

    Лекциядағы a16_rule3_bad бағдарламасын AddressSanitizer-мен орындағанда қандай қате түрі шықты? (бір атау, дефис арқылы: heap-...)

    #include <cstring>
#include <iostream>

class Name {
public:
    Name(const char* s) : data_(new char[std::strlen(s) + 1]) {
        std::strcpy(data_, s);
    }
    ~Name() { delete[] data_; }
    const char* c_str() const { return data_; }

private:
    char* data_;
};

int main() {
    Name a("Айгерім");
    {
        Name b = a;     // әдепкі көшіру: көрсеткіш көшіріледі, мәтін емес!
        std::cout << b.c_str() << "\n";
    }                   // b жойылды -> a.data_ да босатылды
    std::cout << a.c_str() << "\n";   // қолданылған жад!
}
    Кеңес

    Ішкі жақша аяқталғанда b жойылады. Ол жадты босатады. Содан кейін a сол жадты оқиды. Босатылған жадты қолдану қалай аталады?

    Шешімі

    Жауап: heap-use-after-free. Әдепкі көшіру конструкторы көрсеткішті көшірді, мәтінді емес, сондықтан a мен b бір жадқа нұсқады. Түзету: көшіру конструкторы мен меншіктеуін жазу (a15_rule3) не std::string қолдану (Rule of Zero).
