    Оңтайландыру

    Мүмкін болатын нұсқалардың ішінен ең жақсысын қалай табамыз? Жергілікті іздеуді (төбеге өрмелеу, күйдіру), сызықтық бағдарламалауды және шектеулерді қанағаттандыру есептерін (AC-3, кері іздеу, эвристикалар) үйренеміз.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)
    Бұл апта не туралы

    Минимаксте біз ойынның ең жақсы жүрісін іздедік. Бүгін сол «ең жақсыны табу» идеясын кең ауқымда қарастырамыз: аурухана орнын таңдау, жеткізу маршруты, емтихан кестесі, кроссворд. Апта соңындағы тапсырмада кроссвордты автоматты құрастыратын ЖИ жазасыз, ал браузердегі автотексеруші сіздің функцияларыңызды шағын торларда тексереді.

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен кодтың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Оңтайландыру

    Бүгін біз жасанды интеллекттің тағы бір үлкен тақырыбына келдік: оңтайландыру (optimization). Қарапайым тілмен айтқанда, бұл - мүмкін болатын нұсқалардың ішінен ең жақсысын таңдау. Мұндай мәселеге біз бұрын да тап болғанбыз: минимакс алгоритмі де ойынның ішінен ең жақсы жүрісті іздейтін. Ал бүгін одан да кең ауқымды есептерді шешетін құралдармен танысамыз.

    Үш үлкен идея көреміз: жергілікті іздеу, сызықтық бағдарламалау және шектеулерді қанағаттандыру. Үшеуі де «ең жақсы жауапты қалай табамыз?» деген сұраққа үш түрлі жолмен жауап береді.

    Жергілікті іздеу

    Жергілікті іздеу (local search) - бір ғана түйінді (күйді) есте ұстап, іздеуді сол күйден көршісіне көшу арқылы жүргізетін алгоритм. Бұрынғы іздеу түрлерінен айырмашылығы бар. Лабиринт шешкенде бізге мақсатқа апаратын ең қысқа жол керек болды. Ал жергілікті іздеуге жол емес, сұраққа ең жақсы жауап маңызды. Көбіне ол «ең оңтайлы» жауапты емес, «жеткілікті жақсы» жауапты береді, бірақ есептеу қуатын үнемдейді.

    Мысал келтірейік. Қалада төрт үй бар, олардың орны белгілі. Екі аурухана салуымыз керек, және әр үйден ең жақын ауруханаға дейінгі қашықтықтың қосындысы мүмкіндігінше аз болсын. (Дәл осылай екі кеңсені, екі дүкенді немесе екі жеткізу пунктін орналастыруға болады: тапсырыс берушілер қайда тұрса да, оларға жақынырақ болғымыз келеді.)

    Суретте үш түрлі орналасу көрсетілген. Қашықтықты Манхэттен арақашықтығымен өлшейміз: жоғары, төмен, оңға, солға қанша қадам жасау керек екенін санаймыз (мұны 0-апталарда көргенбіз). Әр үйден ең жақын ауруханаға дейінгі қадамдарды қоссақ, шығын (cost) шығады: мұнда 15, 13 және 9. Біз осыны азайтқымыз келеді. Ал күй (state) деп үйлер мен ауруханалардың кез келген бір орналасуын айтамыз.

    Енді мұны жалпылайық. Әр күйдің бір мәні бар (біздегі шығын). Барлық күйді қатар тізіп, әрқайсысына баған сызсақ, күй кеңістігінің ландшафты (state-space landscape) шығады: таулар мен аңғарлар.

    Осы суретке сүйеніп, бірнеше терминді келісіп алайық:

    • мақсат функциясы (objective function) - шешімнің мәнін көбейтуге қолданатын функция;
    • шығын функциясы (cost function) - шешімнің шығынын азайтуға қолданатын функция. Үйлер мен ауруханалар мысалында дәл осы керек: қашықтықты азайтамыз;
    • ағымдағы күй (current state) - функция дәл қазір қарап отырған күй;
    • көрші күй (neighbor state) - ағымдағы күйден көшуге болатын күй. Бір өлшемді ландшафтта ол - екі жағындағы баған. Біздің мысалда - бір аурухананы бір қадам кез келген бағытқа жылжытқандағы күй. Көрші күйлер әдетте ағымдағыға ұқсас, сондықтан мәндері де жақын болады.

    Бір нәрсені ескеріңіз: жергілікті іздеу бір ғана күйді ұстап, оны көршісімен ауыстырады. Минимакстегідей барлық күйді рекурсивті аралап шықпайды. Сондықтан ол жылдам.

    Төбеге өрмелеу

    Төбеге өрмелеу (hill climbing) - жергілікті іздеудің ең қарапайым түрі. Идеясы былай: көрші күйлерді ағымдағымен салыстырамыз, егер біреуі жақсырақ болса, соған көшеміз. «Жақсырақ» дегеніміз - мақсат функциясын қолдансақ, мәні үлкенірек; шығын функциясын қолдансақ, мәні кішірек.

    function Hill-Climb(problem):
    current = initial state of problem
    repeat:
        neighbor = best valued neighbor of current
        if neighbor not better than current:
            return current
        current = neighbor

    Қадамдарын оқып шығайық. Алдымен бастапқы күйден бастаймыз. Кейбір есепте ол белгілі, кейбірінде кездейсоқ таңдаймыз. Сосын қайталаймыз: көршілердің мәнін есептеп, ішінен ең жақсысын аламыз. Оны ағымдағымен салыстырамыз. Көрші жақсы болса, соған көшіп, процесті қайта бастаймыз. Ал ең жақсы көрші де ағымдағыдан жақсы болмай шықса, тоқтаймыз да, ағымдағы күйді қайтарамыз.

    Мұны ауруханалар мысалында өзіміз жазып көрейік. Төмендегі кодта ауруханалардың бастапқы орны берілген, ал hill_climb әр қадамда ең арзан көршіге көшеді. (Бұл біздің өз мысалымыз, түпнұсқадағы суретті қайталамайды, бірақ ойы сол.) Іске қосып көріңіз:

    import random

HEIGHT, WIDTH = 5, 9
HOUSES = [(0, 1), (1, 7), (3, 0), (4, 5)]


def cost(hospitals):
    """Әр үйден ең жақын ауруханаға дейінгі Манхэттен қашықтығы, барлығының қосындысы."""
    return sum(
        min(abs(hi - ri) + abs(hj - rj) for ri, rj in hospitals)
        for hi, hj in HOUSES
    )


def neighbors(hospitals):
    """Бір ауруханаға бір қадам жасатқанда шығатын барлық көрші күйлер."""
    result = []
    for n, (i, j) in enumerate(hospitals):
        for di, dj in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            ni, nj = i + di, j + dj
            if 0 <= ni < HEIGHT and 0 <= nj < WIDTH and (ni, nj) not in hospitals:
                result.append(hospitals[:n] + [(ni, nj)] + hospitals[n + 1:])
    return result


def hill_climb(hospitals):
    current = hospitals
    while True:
        best = min(neighbors(current), key=cost)
        if cost(best) >= cost(current):
            return current
        current = best


def show(hospitals):
    for i in range(HEIGHT):
        row = ""
        for j in range(WIDTH):
            if (i, j) in hospitals:
                row += "H"
            elif (i, j) in HOUSES:
                row += "D"
            else:
                row += "."
        print(row)


start = [(1, 5), (2, 5)]
print("Бастапқы күй, шығын:", cost(start))
show(start)

result = hill_climb(start)
print("Төбеге өрмелеу тоқтаған күй, шығын:", cost(result))
show(result)

    Шығын 15-тен 13-ке түсті. Бірақ 13 - ең жақсы нәтиже емес! Оны келесі суреттен де көрдіңіз: ең жақсы күйде шығын 9. Неге алгоритм сол жерге жетпеді? Себебі 13-ші күйдің барлық көршісі одан жақсы емес (тең немесе қымбатырақ). Төбеге өрмелеу жақыннан ғана көреді, сондықтан «осыдан жақсысы көрінбейді» деп тоқтап қалады. Бұл - алгоритмнің көзі жақын екенінің белгісі.

    Жергілікті және жаһандық максимум пен минимум

    Жоғарыда айттық: төбеге өрмелеу жергілікті максимум немесе минимумға тұрып қалады. Жергілікті максимум (local maximum) - мәні көрші күйлерден жоғары күй. Ал жаһандық максимум (global maximum) - барлық күйдің ішіндегі ең жоғары мәнді күй. Дәл солай жергілікті минимум (local minimum) - көршілерінен төмен күй, ал жаһандық минимум (global minimum) - бүкіл кеңістіктегі ең төмені.

    Алгоритм көршілерінің бәрі өзінен нашар күйге жеткенде тоқтайды. Сондықтан ол жергілікті максимумда (минимумда) қалып қоюы мүмкін. Тағы екі қиын жағдай бар:

    • жазық жергілікті максимум/минимум (flat local maximum/minimum) - мәні бірдей бірнеше көрші күй қатар тұрып, алаң жасайды, ал алаңның айналасы нашар;
    • иық (shoulder) - мәні бірдей күйлер қатар тұрады, бірақ алаңның бір жағында жақсырақ күйлер де бар.

    Алаңның ортасынан бастасақ, алгоритм ешбір бағытта алға жылжи алмайды: көршілердің бәрі дәл өзіндей.

    Ойланып көріңіз: тұрып қалған күйден қалай құтыламыз?

    Бір ой: егер әр жолы басқа жерден бастасақ ше? Бір бастау жергілікті минимумға әкелсе, екіншісі тереңірек аңғарға әкелуі мүмкін. Дәл осыны төменде «кездейсоқ қайта бастау» деп көреміз.

    Төбеге өрмелеудің түрлері

    Төбеге өрмелеудің кемшілігін жеңу үшін бірнеше нұсқа ойлап табылған. Бәріне ортақ нәрсе: қай стратегияны таңдасақ та, жергілікті максимум/минимумға тұрып қалу қаупі сақталады. Төмендегі сипаттамалар «үлкенірек жақсы» деген тұрғыда айтылған, бірақ шығын функциясына да дәл солай қолданылады.

    • ең тік өрлеу (steepest-ascent): мәні ең жоғары көршіні таңдаймыз. Бұл - жоғарыда көрген стандартты нұсқа.
    • стохастикалық (stochastic): мәні жоғары көршілердің арасынан кездейсоқ біреуін аламыз. Яғни мәнді жақсартатын кез келген бағытқа жүре аламыз. Бұл ең биік көрші жергілікті максимумға апарып, ал басқа көрші жаһандық максимумға апаратын жағдайда пайдалы.
    • бірінші таңдау (first-choice): мәні жоғары бірінші кездескен көршіні аламыз.
    • кездейсоқ қайта бастау (random-restart): төбеге өрмелеуді бірнеше рет жүргіземіз, әр жолы кездейсоқ күйден бастаймыз. Барлық нәтиженің ішінен ең жақсысын аламыз.
    • локалды сәуле іздеуі (local beam search): бір емес, k ең жақсы көршіні таңдаймыз. Көптеген жергілікті іздеу алгоритмдерінен айырмашылығы - бірнеше түйінді қатар ұстайды.

    Кездейсоқ қайта бастауды ауруханалар есебінде тексеріп көрелік. Төмендегі кодта бастапқы күйлер кездейсоқ таңдалады (random.seed(8) нәтижені қайталанатын етеді). Бір рет бастағанда тұрып қалуымыз мүмкін, ал қайталай берсек, 9-ға жетеміз:

    import random

HEIGHT, WIDTH = 5, 9
HOUSES = [(0, 1), (1, 7), (3, 0), (4, 5)]


def cost(hospitals):
    return sum(
        min(abs(hi - ri) + abs(hj - rj) for ri, rj in hospitals)
        for hi, hj in HOUSES
    )


def neighbors(hospitals):
    result = []
    for n, (i, j) in enumerate(hospitals):
        for di, dj in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
            ni, nj = i + di, j + dj
            if 0 <= ni < HEIGHT and 0 <= nj < WIDTH and (ni, nj) not in hospitals:
                result.append(hospitals[:n] + [(ni, nj)] + hospitals[n + 1:])
    return result


def hill_climb(hospitals):
    current = hospitals
    while True:
        best = min(neighbors(current), key=cost)
        if cost(best) >= cost(current):
            return current
        current = best


def random_state():
    cells = [(i, j) for i in range(HEIGHT) for j in range(WIDTH)]
    return random.sample(cells, 2)


def random_restart(times):
    best = hill_climb(random_state())
    for _ in range(times - 1):
        candidate = hill_climb(random_state())
        if cost(candidate) < cost(best):
            best = candidate
    return best


random.seed(8)
for times in [1, 5, 20]:
    best = random_restart(times)
    print(f"{times} рет бастау -> ең жақсы шығын {cost(best)}, ауруханалар {best}")

    Жергілікті іздеу әрдайым ең жақсы шешімді бермейді. Бірақ барлық күйді қарап шығу есептеуге келмейтін жағдайда, ол жиі «жеткілікті жақсы» шешімді береді. Қаланың аудандары көбейген сайын барлық орналасуды санап шығу мүмкін болмайды, ал төбеге өрмелеу шапшаң жұмыс істей береді.

    Күйдіру имитациясы

    Төбеге өрмелеудің барлық түрінде ортақ кемшілік бар: жергілікті максимумға жетсе, тоқтап қалады. Ал күйдіру имитациясы (simulated annealing) алгоритмге тұрып қалған жерден «шығып кетуге» мүмкіндік береді.

    Атауы металлургиядан алынған. Annealing - металды қыздырып, содан кейін баяу суыту. Ол металды қатайтады. Алгоритм осы құбылысқа ұқсайды: басында «температура» жоғары, ол кездейсоқ шешімдерге көбірек бейім. Температура төмендеген сайын ол «қатая» бастайды, кездейсоқтық азаяды. Осы тетік арқылы алгоритм ағымдағыдан нашар көршіге де көше алады, жергілікті максимумнан шығу жолы дәл осында.

    function Simulated-Annealing(problem, max):
    current = initial state of problem
    for t = 1 to max:
        T = Temperature(t)
        neighbor = random neighbor of current
        ΔE = how much better neighbor is than current
        if ΔE > 0:
            current = neighbor
        with probability e^(ΔE/T) set current = neighbor
    return current

    Кірісі - есеп пен max, яғни қанша рет қайталау керек. Әр қадамда Temperature функциясы T мәнін береді: ерте қадамда (t аз) жоғары, кейінгі қадамда (t көп) төмен. Содан кейін кездейсоқ көрші алып, ΔE есептейміз, яғни көрші ағымдағыдан қаншалықты жақсы екенін. Егер көрші жақсы болса (ΔE > 0), бұрынғыдай оған көшеміз. Ал көрші нашар болса (ΔE < 0), оған ықтималдықпен eΔE/T көшуіміз мүмкін.

    Бұл формуланы түсінейік. e - тұрақты шама (шамамен 2,72), ал ΔE теріс. ΔE неғұрлым теріс болса (көрші нашар), нәтиже 0-ге жақындайды, яғни көшу ықтималдығы аз. Температура T неғұрлым жоғары болса, ΔE/T 0-ге жақындайды, сонда ықтималдық 1-ге жақындайды. Қорытындысы: көрші нашар болған сайын, оны таңдау ықтималдығы азаяды; алгоритм ерте кезеңде болған сайын, нашар көршіге көшу ықтималдығы жоғары. Сандарға қарап көрейік:

    import math

print("  dE      T    ықтималдық e^(dE/T)")
for delta in [-1, -3, -10]:
    for T in [10, 1, 0.1]:
        print(f"{delta:4}  {T:5}    {math.exp(delta / T):.4f}")

    Байқадыңыз ба? ΔE = -1 және T = 10 болғанда ықтималдық 90%-дан асады, яғни «ыстық» кезде алгоритм бәріне көне береді. T = 0,1 болғанда нашар көршіге көшу мүлде жоқ: алгоритм «қатты» төбеге өрмелеуге айналды. Енді осыны ауруханалар есебіне қолданайық. Төбеге өрмелеу 13-те тұрып қалған бастапқы күйден бастаймыз:

    import math
import random

HEIGHT, WIDTH = 5, 9
HOUSES = [(0, 1), (1, 7), (3, 0), (4, 5)]


def cost(hospitals):
    return sum(
        min(abs(hi - ri) + abs(hj - rj) for ri, rj in hospitals)
        for hi, hj in HOUSES
    )


def random_neighbor(hospitals):
    while True:
        n = random.randrange(len(hospitals))
        i, j = hospitals[n]
        di, dj = random.choice([(-1, 0), (1, 0), (0, -1), (0, 1)])
        ni, nj = i + di, j + dj
        if 0 <= ni < HEIGHT and 0 <= nj < WIDTH and (ni, nj) not in hospitals:
            return hospitals[:n] + [(ni, nj)] + hospitals[n + 1:]


def temperature(t, max_steps):
    # Басында ыстық (10), соңында суық (0-ге жақын)
    return 10 * (1 - t / max_steps) + 0.01


def simulated_annealing(hospitals, max_steps):
    current = hospitals
    for t in range(1, max_steps + 1):
        T = temperature(t, max_steps)
        neighbor = random_neighbor(current)
        delta = cost(current) - cost(neighbor)   # оң болса, көрші жақсырақ (шығын аз)
        if delta > 0 or random.random() < math.exp(delta / T):
            current = neighbor
    return current


random.seed(1)
start = [(1, 5), (2, 5)]        # төбеге өрмелеу тұрып қалған бастапқы күй
result = simulated_annealing(start, 2000)
print("Күйдіру нәтижесі:", result, "шығын:", cost(result))
    Ойланып көріңіз: егер температура әрдайым жоғары болса не болады?

    Онда ықтималдық әрдайым 1-ге жақын, алгоритм жақсы-нашарды айырмай, кездейсоқ қыдыра береді. Ал егер температура басынан нөлге жақын болса, ол кәдімгі төбеге өрмелеуге айналады. Күйдірудің күші - екеуінің арасында: алдымен ақылмен «шолу», сосын біртіндеп «шешім қабылдау».

    Коммивояжер есебі

    Күйдіру имитациясының классикалық мысалы - коммивояжер есебі (traveling salesman problem). Мақсат: барлық нүктені қосатын ең қысқа маршрутты табу. Жеткізу компанияларына дәл осы керек: дүкеннен шығып, барлық тапсырыс берушінің үйіне соғып, дүкенге қайта оралатын ең қысқа жолды табу.

    Бұл есепте көрші күйді былай анықтауға болады: маршруттағы екі кесіндінің орнын ауыстырамыз. Барлық нұсқаны санау өте ауыр: небәрі 10 нүктенің өзінде 10! = 3 628 800 маршрут бар. Ал күйдіру имитациясы салыстырмалы түрде аз есептеумен жақсы маршрутты табады.

    Сызықтық бағдарламалау

    Сызықтық бағдарламалау (linear programming) - сызықтық теңдеуді (y = ax₁ + bx₂ + … түріндегі) оңтайландыратын есептер тобы. Оның құрамында үш бөлік бар:

    • азайтқымыз келетін шығын функциясы: c₁x₁ + c₂x₂ + … + cₙxₙ. Мұнда әр xᵢ - айнымалы, оның өз шығыны cᵢ бар;
    • шектеу: айнымалылардың қосындысы бір мәннен аз не тең (a₁x₁ + a₂x₂ + … + aₙxₙ ≤ b) немесе дәл тең (… = b). Мұнда aᵢ - айнымалыға жұмсалатын ресурс, ал b - есепке бөле алатын ресурстың жалпы мөлшері;
    • айнымалыларға жеке шектеу, мысалы, айнымалы теріс бола алмайды: lᵢ ≤ xᵢ ≤ uᵢ.

    Мысал қарастырайық. Екі станок бар: X₁ және X₂.

    • X₁ жұмысы сағатына $50 тұрады, X₂ - сағатына $80. Мақсат - шығынды азайту. Шығын функциясы: 50x₁ + 80x₂.
    • X₁ сағатына 5 бірлік еңбек қажет етеді, X₂ - 2 бірлік. Барлығы 20 бірлік еңбек бар. Шектеу: 5x₁ + 2x₂ ≤ 20.
    • X₁ сағатына 10 бірлік өнім шығарады, X₂ - 12 бірлік. Компанияға 90 бірлік өнім керек. Бұл да шектеу: 10x₁ + 12x₂ ≥ 90. Бірақ шектеулер «≤» не «=» түрінде болуы тиіс. Сондықтан екі жағын (-1)-ге көбейтеміз: (-10x₁) + (-12x₂) ≤ -90.

    Суретте екі шектеу сызығы мен олар қиятын аймақ көрсетілген. Ең арзан шешім - осы аймақтың бір бұрышында. Мұндай есепті шешетін алгоритм геометрия мен сызықтық алгебра біліміне сүйенеді, оларды біз бұл жерде талап етпейміз. Орнына дайын алгоритмдерді қолданамыз, мысалы, симплекс (Simplex) және ішкі нүктелер (Interior-Point) әдістерін.

    Төменде Python-дағы scipy кітапханасымен шешілген мысал. (scipy браузерде жоқ, сондықтан бұл кодты сайтта іске қосу мүмкін емес, өз компьютеріңізде көріңіз.)

    import scipy.optimize

# Objective Function: 50x_1 + 80x_2
# Constraint 1: 5x_1 + 2x_2 <= 20
# Constraint 2: -10x_1 + -12x_2 <= -90

result = scipy.optimize.linprog(
    [50, 80],  # Cost function: 50x_1 + 80x_2
    A_ub=[[5, 2], [-10, -12]],  # Coefficients for inequalities
    b_ub=[20, -90],  # Constraints for inequalities: 20 and -90
)

if result.success:
    print(f"X1: {round(result.x[0], 2)} hours")
    print(f"X2: {round(result.x[1], 2)} hours")
else:
    print("No solution")

    linprog бірінші аргументке шығын функциясының коэффициенттерін алады ([50, 80]), A_ub - теңсіздіктердің коэффициенттері, b_ub - олардың оң жағы. Нәтиже: X1: 1.5 hours, X2: 6.25 hours, дәл суреттегі бұрыш нүктесі (жалпы шығын $575).

    Қағаздағы тексеру

    Екі шектеуді теңдік ретінде алсақ: 5x₁ + 2x₂ = 20 және 10x₁ + 12x₂ = 90. Бірінші теңдеуден x₂ = 10 - 2,5x₁. Екіншіге қойсақ, 10x₁ + 120 - 30x₁ = 90, яғни x₁ = 1,5, x₂ = 6,25. Шығын 50 · 1,5 + 80 · 6,25 = 575. Басқа бұрыштар (0; 7,5) шығыны 600, (0; 10) шығыны 800: қымбатырақ.

    Шектеулерді қанағаттандыру

    Шектеулерді қанағаттандыру есептері (constraint satisfaction problems, CSP) - айнымалыларға мәндер беру керек, бірақ белгілі шарттар сақталуы тиіс есептер. Олардың үш құрамдас бөлігі бар:

    • айнымалылар жиыны (x₁, x₂, …, xₙ);
    • әр айнымалының домені (domain), яғни қабылдай алатын мәндер жиыны {D₁, D₂, …, Dₙ};
    • шектеулер жиыны C.

    Судоку - дәл осындай есеп. Әр бос шаршы - айнымалы, домен - 1-ден 9-ға дейінгі сандар, ал шектеу - белгілі шаршылардағы сандар бір-біріне тең болмауы керек.

    Тағы бір мысал. Төрт студент бар (1-ден 4-ке дейін), әрқайсысы A, B, …, G пәндерінің ішінен үшеуін оқиды. Әр пәннен емтихан болады, ал емтихан күндері - дүйсенбі, сейсенбі, сәрсенбі. Бір студенттің екі емтиханы бір күнге түспеуі керек. Мұнда айнымалылар - пәндер, домен - күндер, шектеулер - бір студент оқитын пәндер бір күнге қойылмайды.

    Мұндай есепті граф түрінде көрсету ыңғайлы: түйін - пән, ал екі пәнді қабырғамен қосамыз, егер оларды бір күнге қоюға болмаса.

    Тағы бірнеше термин:

    • қатаң шектеу (hard constraint) - дұрыс шешімде міндетті түрде орындалуы тиіс шектеу;
    • жұмсақ шектеу (soft constraint) - қай шешімнің басқасынан артық екенін көрсететін шектеу (орындалмаса да болады, бірақ орындалғаны жақсы);
    • унарлы шектеу (unary constraint) - тек бір айнымалыға қатысты шектеу. Біздің мысалда: «A пәнінің емтиханы дүйсенбіде болмайды», {A ≠ Mon};
    • бинарлы шектеу (binary constraint) - екі айнымалыны байланыстыратын шектеу. Жоғарыдағы мысалдағыдай: екі пән бірдей күн ала алмайды, {A ≠ B}.

    Түйін келісімі

    Түйін келісімі (node consistency) - айнымалының доменіндегі барлық мән оның унарлы шектеулерін қанағаттандыратын жағдай.

    Екі пәнді алайық: A және B. Екеуінің де домені - {Mon, Tue, Wed}, шектеулер - {A ≠ Mon, B ≠ Tue, B ≠ Mon, A ≠ B}. Қазір А да, B де түйін-келісімді емес: шектеулер әрқайсысына доменіндегі кейбір мәнді алуға тыйым салады. Бірақ A-ның доменінен Mon-ды алып тастасақ, A түйін-келісімді болады. B-ны келісімді ету үшін одан Mon мен Tue екеуін де алып тастау керек. Төмендегі кодпен тексеріп көріңіз (кодтың соңында келесі бөлімнің алдын ала көрінісі де бар):

    DAYS = {"Mon", "Tue", "Wed"}

# Екі пән: A және B. Екеуінің домені - үш күн.
domains = {"A": set(DAYS), "B": set(DAYS)}

# Унарлы шектеулер: A != Mon, B != Tue, B != Mon
unary = {"A": {"Mon"}, "B": {"Tue", "Mon"}}

# 1) Түйін келісімі
for var, banned in unary.items():
    domains[var] -= banned
print("Түйін келісімінен кейін:", domains)

# 2) Доға келісімі: A != B
def revise(domains, x, y):
    revised = False
    for vx in set(domains[x]):
        if not any(vx != vy for vy in domains[y]):
            domains[x].remove(vx)
            revised = True
    return revised

print("revise(A, B):", revise(domains, "A", "B"), domains)
print("revise(B, A):", revise(domains, "B", "A"), domains)

    Доға келісімі

    Доға келісімі (arc consistency) - айнымалының доменіндегі әр мән оның бинарлы шектеулерін қанағаттандыратын жағдай. (Енді «қабырға» дегенді «доға» (arc) деп атаймыз.) Басқаша айтқанда, X айнымалысын Y-ке қатысты доға-келісімді ету үшін X-тің доменінен мәндерді алып тастаймыз, сонда X-тің әр таңдауына Y-тен сәйкес таңдау табылады.

    Алдыңғы мысалды жаңартылған домендермен алайық: A: {Tue, Wed}, B: {Wed}.

    A, B-ге қатысты доға-келісімді ме? A қандай күн алса да (өз доменінен), B-ге бір күн қалуы керек. Егер A = Tue болса, B = Wed ала алады. Бірақ A = Wed болса, B-ге ештеңе қалмайды (шектеулердің бірі A ≠ B екенін ұмытпаңыз). Демек, A, B-ге қатысты доға-келісімді емес. Түзету үшін A-ның доменінен Wed-ті алып тастаймыз. Сонда A қандай мән алса да (тек Tue қалды), B-ге мән қалады (Wed). Енді A доға-келісімді.

    Мұны істейтін алгоритм:

    function Revise(csp, X, Y):
    revised = false
    for x in X.domain:
        if no y in Y.domain satisfies constraint for (X, Y):
            delete x from X.domain
            revised = true
    return revised

    Алгоритм алдымен X-тің доменінде өзгеріс болды ма, соны revised айнымалысымен бақылайды (бұл келесі алгоритмге керек). Сосын X-тің әр мәні үшін Y-те шектеуді қанағаттандыратын мән бар-жоғын қарайды. Бар болса, ештеңе істемейді; жоқ болса, мәнді X-тің доменінен алып тастайды. Python-дағы revise функциясын сіз жоғарыдағы кодта көрдіңіз.

    Көбіне бір айнымалыны емес, бүкіл есепті доға-келісімді еткіміз келеді. Ол үшін Revise-ті қолданатын AC-3 алгоритмі бар:

    function AC-3(csp):
    queue = all arcs in csp
    while queue non-empty:
        (X, Y) = Dequeue(queue)
        if Revise(csp, X, Y):
            if size of X.domain == 0:
                return false
            for each Z in X.neighbors - {Y}:
                Enqueue(queue, (Z, X))
    return true

    Алгоритм есептегі барлық доғаны кезекке (queue) салады. Әр доғаны қарағанда, оны кезектен алып тастап, Revise шақырады. Егер өзгеріс болса, қосымша әрекет керек. Егер X-тің домені бос қалса, есептің шешімі жоқ (X қандай мән алса да, Y-ке мән қалмайды). Ал домен бос қалмаса, X-тің домені өзгергендіктен, X-ке қатысты барлық доға әлі келісімді ме, соны тексеру керек. Сондықтан X-тің Y-тен басқа барлық көршісін алып, олардың X-пен доғаларын кезекке қосамыз. Revise false қайтарса (домен өзгермесе), келесі доғаға өтеміз. Сынап көріңіз: A-ның домені {Mon} болғанда, AC-3 оның көршілері B мен C-дан Mon-ды алып тастайды.

    from collections import deque

EDGES = {("A", "B"), ("A", "C"), ("B", "C"), ("B", "D"), ("B", "E"),
         ("C", "E"), ("C", "F"), ("D", "E"), ("E", "F"), ("F", "G")}


def neighbors(x):
    return {b if a == x else a for a, b in EDGES if x in (a, b)}


def revise(domains, x, y):
    """x-ті y-ке қатысты доға-келісімді ету: A != B түріндегі шектеу."""
    revised = False
    for vx in set(domains[x]):
        if not any(vx != vy for vy in domains[y]):
            domains[x].remove(vx)
            revised = True
    return revised


def ac3(domains):
    queue = deque((x, y) for x in domains for y in neighbors(x))
    while queue:
        x, y = queue.popleft()
        if revise(domains, x, y):
            if not domains[x]:
                return False
            for z in neighbors(x) - {y}:
                queue.append((z, x))
    return True


# A-ның домені {Mon}, B-нің домені {Mon, Tue}: AC-3 B-ден Mon-ды алып тастайды
domains = {v: {"Mon", "Tue", "Wed"} for v in "ABCDEFG"}
domains["A"] = {"Mon"}
print(ac3(domains))
for v in sorted(domains):
    print(v, sorted(domains[v]))

    Доға келісімі есепті жеңілдетуі мүмкін, бірақ міндетті түрде шешпейді: ол тек бинарлы шектеулерді қарайды, көп түйіннің өзара байланысын ескермейді. Мысалы, төрт студент пен жеті пәннің алдыңғы есебіне AC-3 жүргізсек, ештеңе өзгермейді.

    Бірінші лекциядағы іздеу есептерін еске түсірейік. Шектеулерді қанағаттандыру есебін іздеу есебі ретінде де жазуға болады:

    • бастапқы күй: бос меншіктеу (ешбір айнымалыға мән берілмеген);
    • әрекеттер: меншіктеуге {айнымалы = мән} қосу, яғни бір айнымалыға мән беру;
    • ауысу моделі: соңғы әрекеттен кейінгі меншіктеуді қайтарады, мұнда терең ештеңе жоқ;
    • мақсат тексерісі: барлық айнымалыға мән берілген және барлық шектеу орындалған;
    • жол құны: барлық жолдың құны бірдей. Жоғарыда айтқанымыздай, оңтайландыру есептері жолды емес, шешімді қызықтырады.

    Бірақ есепті қарапайым іздеу ретінде «аңқау» шешу өте тиімсіз. Оның орнына CSP құрылымын пайдаланып, тиімдірек шешеміз.

    Кері іздеу

    Кері іздеу (backtracking search) - CSP құрылымын ескеретін іздеу алгоритмі. Ол рекурсивті функция: шектеулер сақталып тұрғанда мән беруді жалғастырады, ал шектеу бұзылса, басқа мәнді сынайды. Псевдокод:

    function Backtrack(assignment, csp):
    if assignment complete:
        return assignment
    var = Select-Unassigned-Var(assignment, csp)
    for value in Domain-Values(var, assignment, csp):
        if value consistent with assignment:
            add {var = value} to assignment
            result = Backtrack(assignment, csp)
            if result ≠ failure:
                return result
            remove {var = value} from assignment
    return failure

    Сөзбен айтқанда: меншіктеу толық болса, оны қайтарамыз, жұмыс біткен. Толық болмаса, мәні жоқ айнымалылардың бірін таңдаймыз. Оған мән беріп көреміз және алынған меншіктеумен Backtrack-ті қайта шақырамыз (рекурсия). Нәтиже failure болмаса, меншіктеу сәтті болды, оны қайтарамыз. Нәтиже failure болса, соңғы меншіктеуді қайтарып алып, келесі мәнді сынаймыз. Егер доменнің барлық мәні сәтсіз болса, кері қайту керек: мәселе бұрынғы меншіктеулердің бірінде. Ал мұндай жағдай ең бірінші айнымалыда болса, демек шектеулерді қанағаттандыратын шешім жоқ.

    Суретті қадамдап оқиық. Бос меншіктеуден бастаймыз (1). A-ны таңдап, Mon береміз (2). Енді B-ге өтіп, оған да Mon береміз (3): бұл қате, себебі A мен B қабырғамен байланысқан. Сондықтан C-ға өтпей, B-ге басқа мән береміз, Tue (4): енді шектеулер сақталады, келесі айнымалыға өтеміз. Егер B-ге Tue мен Wed те қате берсе, A-ға оралып, оған Tue береміз. Ал A-ның да барлық мәні сәтсіз болса, барлық меншіктеуді тексеріп болдық, есептің шешімі жоқ.

    Мұны емтихан кестесінің барлық жеті пәніне жазып көрелік. Төмендегі кодта айнымалыларды алфавит ретімен аламыз, ал әр сынаған мәнді санаймыз:

    EDGES = {("A", "B"), ("A", "C"), ("B", "C"), ("B", "D"), ("B", "E"),
         ("C", "E"), ("C", "F"), ("D", "E"), ("E", "F"), ("F", "G")}
DAYS = ["Mon", "Tue", "Wed"]
VARIABLES = list("ABCDEFG")


def neighbors(x):
    return {b if a == x else a for a, b in EDGES if x in (a, b)}


def consistent(assignment, var, value):
    return all(assignment.get(n) != value for n in neighbors(var))


steps = 0


def backtrack(assignment):
    global steps
    if len(assignment) == len(VARIABLES):
        return assignment
    var = next(v for v in VARIABLES if v not in assignment)
    for value in DAYS:
        steps += 1
        if consistent(assignment, var, value):
            assignment[var] = value
            result = backtrack(assignment)
            if result is not None:
                return result
            del assignment[var]
    return None


solution = backtrack({})
print(solution)
print("Тексерілген меншіктеулер саны:", steps)

    Бұл алгоритм кең қолданылады, сондықтан көптеген кітапханада дайын нұсқасы бар.

    Қорытынды шығару

    Кері іздеу қарапайым іздеуден тиімдірек, бірақ әлі де көп есептеу алады. Ал доға келісімін қамтамасыз ету одан арзанырақ. Кері іздеуді қорытынды шығарумен (inference) араластырсақ, яғни әр жаңа меншіктеуден кейін доға келісімін орнатсақ, алгоритм тиімдірек болады. Оны доға келісімін сақтау (Maintaining Arc-Consistency) алгоритмі дейді. Нақтырақ айтқанда, X-ке жаңа мән бергенде, AC-3 алгоритмін шақырамыз, бірақ кезекке бүкіл есептің доғаларын емес, тек (Y, X) доғаларын саламыз (Y - X-тің көршісі). Төменде өзгертілген Backtrack: жаңа жолдар (жаңа) деп белгіленген:

    function Backtrack(assignment, csp):
    if assignment complete:
        return assignment
    var = Select-Unassigned-Var(assignment, csp)
    for value in Domain-Values(var, assignment, csp):
        if value consistent with assignment:
            add {var = value} to assignment                 # (жаңа)
            inferences = Inference(assignment, csp)         # (жаңа)
            if inferences ≠ failure:
                add inferences to assignment                # (жаңа)
            result = Backtrack(assignment, csp)
            if result ≠ failure:
                return result
            remove {var = value} and inferences from assignment # (жаңа)
    return failure

    Бұл жерде Inference функциясы AC-3-ті жүргізеді. Оның нәтижесі - доға келісімін орнатудан шығатын барлық қорытынды, яғни алдыңғы меншіктеулер мен есептің құрылымынан шығарылатын жаңа меншіктеулер.

    Эвристикалар

    Алгоритмді тағы тиімді ету жолдары бар. Осы уақытқа дейін мәні жоқ айнымалыны кездейсоқ таңдадық. Бірақ кейбір таңдау шешімге тезірек апарады. Ол үшін эвристика (heuristic) қажет. Эвристика - ережені «көбіне» жақсы нәтиже беретін, бірақ кепілдік бермейтін практикалық қағида.

    Ең аз қалған мәндер (Minimum Remaining Values, MRV) - солардың бірі. Идея мынау: егер қорытынды шығару айнымалының доменін тарылтып, оның бір ғана мәні (немесе екі мәні) қалса, сол меншіктеуді қазір жасасақ, кейін кері қайту қажеттілігі азаяды. Ол меншіктеуді ертеме-кеш жасауға тура келеді (қорытынды солай шығарады). Егер ол сәтсіз болса, бұл жайында мүмкіндігінше ертерек білген жөн, кейін кері қайтқаннан гөрі.

    Мысалы, ағымдағы меншіктеуге қарай домендерді тарылтқаннан кейін MRV бойынша келесі айнымалы ретінде C-ны таңдап, оған Wed береміз.

    Дәреже эвристикасы (Degree heuristic) айнымалылардың дәрежесіне сүйенеді. Дәреже - айнымалыны басқа айнымалылармен байланыстыратын доғалардың саны. Дәрежесі ең жоғары айнымалыны таңдасақ, бір меншіктеумен көп басқа айнымалыны шектейміз, алгоритм тез жүреді.

    Мысалы, жоғарыдағы барлық айнымалының домені бірдей үлкен. Сондықтан дәрежесі ең жоғарыны, яғни E-ні таңдаймыз.

    Екі эвристика да әрдайым қолданыла бермейді: мысалы, бірнеше айнымалының домені бірдей аз болғанда немесе бірнеше айнымалының дәрежесі бірдей жоғары болғанда. Сондықтан тең түскенде бірін екіншісімен толықтырамыз (алдымен MRV, тең болса дәреже).

    Алгоритмді тиімді етудің тағы бір жолы - айнымалының доменінен мән таңдағанда да эвристика қолдану. Бұл - ең аз шектейтін мән (Least Constraining Values, LCV) эвристикасы: басқа айнымалылардың ең аз санын шектейтін мәнді таңдаймыз. Дәреже эвристикасында ең көп шектейтін айнымалыны іздедік, ал мұнда сол айнымалыны мүмкіндігінше қолайсыздау етеміз. Яғни ең үлкен ықтимал қиындық көзін (дәрежесі ең жоғары айнымалыны) тауып алып, оны ең аз қиындық тудыратын мәнмен толтырамыз.

    Мысалы, C айнымалысын қарайық. Оған Tue берсек, B, E және F шектеледі. Ал Wed берсек, тек B мен E шектеледі. Демек, Wed таңдаған жөн.

    Ойланып көріңіз: MRV мен LCV неге қарама-қарсы сияқты көрінеді?

    MRV (және дәреже) айнымалыны таңдайды: ең қиын айнымалыны алдымен аламыз, себебі сәтсіздік болса, ертерек білеміз («қиынды бірінші»). LCV мәнді таңдайды: оған мән бергенде көрші айнымалыларға мүмкіндік көбірек қалдырамыз («жеңілді таңда»). Біз алдымен қиын орынға барамыз, бірақ оны ең жайлы мәнмен толтырамыз. Айнымалы үшін «қиынды бірінші», мән үшін «жеңілді бірінші»: бұл екі қағида бір-біріне қайшы емес.

    Осы эвристикаларды біріктіріп, барлық жеті пәннің емтихан кестесін қайта шешейік. Бұл жолы айнымалыны MRV мен дәреже арқылы, мәнді LCV арқылы таңдаймыз, ал әр меншіктеуден кейін көршілердің доменінен сол күнді алып тастаймыз (қарапайым қорытынды шығару):

    EDGES = {("A", "B"), ("A", "C"), ("B", "C"), ("B", "D"), ("B", "E"),
         ("C", "E"), ("C", "F"), ("D", "E"), ("E", "F"), ("F", "G")}
DAYS = ["Mon", "Tue", "Wed"]
VARIABLES = list("ABCDEFG")


def neighbors(x):
    return {b if a == x else a for a, b in EDGES if x in (a, b)}


def select_unassigned_variable(assignment, domains):
    unassigned = [v for v in VARIABLES if v not in assignment]
    # MRV: ең аз мәні қалған; тең болса - степені (бос көршілер саны) жоғары
    return min(unassigned, key=lambda v: (
        len(domains[v]),
        -len([n for n in neighbors(v) if n not in assignment])))


def order_domain_values(var, assignment, domains):
    # LCV: көршілердің көбірек мәнін өшірмейтін күннен бастаймыз
    def ruled_out(value):
        return sum(value in domains[n] for n in neighbors(var) if n not in assignment)
    return sorted(domains[var], key=ruled_out)


def inference(var, value, domains):
    """Меншіктеуден кейін көршілерден осы күнді алып тастаймыз (доға келісімі)."""
    new = {v: set(d) for v, d in domains.items()}
    new[var] = {value}
    for n in neighbors(var):
        new[n].discard(value)
        if not new[n]:
            return None
    return new


steps = 0


def backtrack(assignment, domains):
    global steps
    if len(assignment) == len(VARIABLES):
        return assignment
    var = select_unassigned_variable(assignment, domains)
    for value in order_domain_values(var, assignment, domains):
        steps += 1
        new_domains = inference(var, value, domains)
        if new_domains is not None:
            assignment[var] = value
            result = backtrack(assignment, new_domains)
            if result is not None:
                return result
            del assignment[var]
    return None


domains = {v: set(DAYS) for v in VARIABLES}
print(backtrack({}, domains))
print("Тексерілген меншіктеулер саны:", steps)

    Қорытынды

    Оңтайландыру есептерін бірнеше түрлі тәсілмен қоюға болады. Бүгін үшеуін көрдік:

    • жергілікті іздеу: бір күйді ұстап, көршісіне көшеміз; төбеге өрмелеу (түрлері: ең тік өрлеу, стохастикалық, бірінші таңдау, кездейсоқ қайта бастау, локалды сәуле іздеуі) жергілікті максимум/минимум, жазық алаң және иыққа тұрып қалуы мүмкін;
    • күйдіру имитациясы: температураға байланысты нашар көршіге де ықтималдықпен eΔE/T көшеміз, сондықтан тұрып қалудан шыға аламыз; коммивояжер есебінде қолданылады;
    • сызықтық бағдарламалау: сызықтық шығынды сызықтық шектеулер астында азайту; дайын алгоритмдер - симплекс және ішкі нүктелер (scipy.optimize.linprog);
    • шектеулерді қанағаттандыру (CSP): айнымалылар, домендер, шектеулер; қатаң/жұмсақ, унарлы/бинарлы шектеулер;
    • түйін келісімі (унарлы) және доға келісімі (бинарлы), Revise және AC-3 алгоритмдері;
    • кері іздеу және оны қорытынды шығарумен (доға келісімін сақтау) толықтыру;
    • эвристикалар: айнымалы таңдауда MRV және дәреже, мән таңдауда LCV.

    Өзіңізді тексеріңіз

    1. Төбеге өрмелеу алгоритмі қай кезде тоқтайды?

    Төбеге өрмелеу тек көршілерді қарайды. Ешбір көрші жақсырақ болмаса, ағымдағы күйді қайтарады, бұл жергілікті максимум/минимум болуы мүмкін.

    2. Күйдіру имитациясында температура T жоғары, ал көрші нашар (ΔE < 0). Нашар көршіге көшу ықтималдығы eΔE/T туралы не айтуға болады?

    T үлкен болса, ΔE/T 0-ге жақындайды, ал e0 = 1. Температура төмендеген сайын ықтималдық азаяды.

    3. Мына шектеулердің қайсысы унарлы?

    Унарлы шектеу тек бір айнымалыға қатысты ({A ≠ Mon}). A ≠ B екі айнымалыны байланыстырады, сондықтан ол бинарлы.

    4. A: {Tue, Wed}, B: {Wed}, шектеу A ≠ B. A-ны B-ге қатысты доға-келісімді ету үшін не істейміз?

    A = Wed болса, B-ге мән қалмайды. Сондықтан Wed-ті A-дан алып тастаймыз. Revise тек бірінші айнымалының (X) доменін өзгертеді.

    5. AC-3-те X-тің домені өзгерген соң, кезекке қандай доғалар қосылады?

    X-тің мәндері азайғандықтан, оның көршілері X-ке сүйеніп тұрған мәндерін жоғалтуы мүмкін. Сондықтан (Z, X) доғаларын қайта тексереміз.

    6. Кері іздеуде барлық айнымалыға мән берілмей, ең бірінші айнымалының барлық мәні сәтсіз болса, бұл нені білдіреді?

    Кері қайту ең бірінші айнымалыға дейін жетіп, барлық мән сынап болса, барлық мүмкін меншіктеу тексерілген: шешім жоқ, функция failure қайтарады.

    7. Домендері бірдей үлкен айнымалылардың ішінде E-нің түйіндері басқаларынан көп (дәрежесі жоғары). Қай эвристика E-ні таңдайды?

    MRV доменнің өлшеміне қарайды, ал домендер тең. Тең түскенде дәреже эвристикасы көршісі ең көп айнымалыны таңдайды. LCV айнымалыны емес, мәнді таңдайды.

    8. C айнымалысына Tue берсек B, E және F-тің мәндері азаяды, ал Wed берсек тек B мен E-нікі азаяды. LCV қайсысын таңдайды?

    LCV (ең аз шектейтін мән) көрші айнымалыларға мүмкіндікті көбірек қалдыратын мәнді таңдайды.

    Алғышарт

    Кроссвордты қалай құрастыруға болады? Кроссвордтың құрылымы (қай шаршыларға әріп жазылады) мен қолданылатын сөздер тізімі берілсін. Сонда есеп мынаған келеді: әр тік немесе көлденең шаршылар тізбегіне қай сөзді қою керек? Мұны шектеулерді қанағаттандыру есебі ретінде модельдеуге болады. Әр шаршылар тізбегі - бір айнымалы, оның мәні - домендегі мүмкін сөздердің бірі.

    Мысалы, төрт сөзден тұратын кроссвордта төрт айнымалы болады. Әр айнымалы төрт мәнмен анықталады: басталатын қатары (i), басталатын бағаны (j), бағыты (көлденең across немесе тік down) және ұзындығы. Мысалы, 1-айнымалы: қатары 1 (жоғарыдан санағанда, 0-ден бастап), бағаны 1 (солдан санағанда), бағыты across, ұзындығы 4.

    Көптеген CSP сияқты, мұнда унарлы және бинарлы шектеулер бар. Унарлы шектеуді айнымалының ұзындығы береді: 1-айнымалы үшін BYTE сөзі дұрыс, ал BIT дұрыс емес (әріп саны сәйкес емес). Унарлы шектеуді қанағаттандырмайтын мәндерді доменнен бірден алып тастауға болады.

    Бинарлы шектеулерді көрші айнымалылармен қиылысу береді. Әр көрші жұп бір ортақ шаршыны бөліседі. Қиылысуды әр сөздегі сәйкес әріп нөмірінің жұбы ретінде жазамыз. Мысалы, 1 және 2 айнымалыларының қиылысы (1, 0) болса, 1-айнымалының 1-әрпі 2-айнымалының 0-әрпімен бірдей болуы керек (0-ден бастап санаймыз). 2 және 3 айнымалыларының қиылысы (3, 1) болуы мүмкін.

    Бұған қосымша шектеу: барлық сөз әртүрлі болуы керек (бір сөз кроссвордта екі рет қайталанбайды). Міндет: әр айнымалыға берілген сөздер тізімінен әртүрлі сөз беру, барлық унарлы және бинарлы шектеу орындалатындай.

    Үлгі кодты crossword.zip архивінен жүктеп, ашыңыз.

    Түсіну

    Жобада екі Python файлы бар: crossword.py және generate.py. Біріншісі толық дайын, екіншісінде бірнеше функцияны сіз жазасыз.

    crossword.py екі класты анықтайды: Variable (кроссворд айнымалысы) және Crossword (кроссвордтың өзі). Variable жасау үшін төрт мән беру керек: қатары i, бағаны j, бағыты (Variable.ACROSS немесе Variable.DOWN) және ұзындығы. Crossword екі мән алады: structure_file (құрылым файлы, мұнда _ бос шаршы, басқа таңба толтырылмайтын шаршы) және words_file (әр жолда бір сөз). data қалтасында үш үлгі бар, өзіңіз де жасай аласыз.

    crossword нысаны үшін мына мәндер бар:

    • crossword.height және crossword.width - кроссвордтың биіктігі мен ені;
    • crossword.structure - 2D тізім: crossword.structure[i][j] шаршы бос (әріп жазылады) болса True, әйтпесе False;
    • crossword.words - қолдануға болатын барлық сөздер жиыны;
    • crossword.variables - барлық айнымалылар жиыны (Variable нысандары);
    • crossword.overlaps - айнымалылар жұбын олардың қиылысына сәйкестендіретін сөздік. Екі түрлі v1, v2 үшін crossword.overlaps[v1, v2] қиылыспаса None, қиылысса бүтін сандар жұбы (i, j): v1 мәнінің i-ші әрпі v2 мәнінің j-ші әрпімен бірдей болуы керек.

    Crossword сондай-ақ neighbors әдісін қолдайды: crossword.neighbors(v1) - v1 айнымалысымен қиылысатын барлық айнымалы жиыны.

    generate.py ішінде кроссвордты шешетін CrosswordCreator класы бар. Нысан жасалғанда оның crossword қасиеті (жоғарыдағы барлық мәні бар Crossword нысаны) және domains қасиеті болады: айнымалыны мүмкін сөздер жиынына сәйкестендіретін сөздік. Басында домен - сөздіктегі барлық сөз, оны функцияларыңыз тарылтады. Тестілеуге көмектесетін дайын функциялар: print (меншіктеуді терминалға шығарады), save (сурет файлына сақтайды, pip3 install Pillow керек) және letter_grid (көмекші функция). Бұл жерде меншіктеу - айнымалыларды сөздерге сәйкестендіретін сөздік.

    Соңында solve функциясын қараңыз. Ол үш іс істейді: алдымен enforce_node_consistency шақырып, түйін келісімін орнатады; сосын ac3 арқылы доға келісімін орнатады; ақырында бос сөздікпен (dict()) backtrack шақырып, шешімді іздейді. Бірақ enforce_node_consistency, ac3, backtrack және басқа бірнеше функция әлі жазылмаған. Міне, осы жерде сіз керексіз.

    Талаптар

    generate.py ішіндегі enforce_node_consistency, revise, ac3, assignment_complete, consistent, order_domain_values, select_unassigned_variable және backtrack функцияларын аяқтаңыз, сонда ЖИ мүмкін болса, толық кроссворд құрастырады. (Ресми беттің бір жерінде соңғы атау опечаткамен selected_unassigned_variable деп жазылған, бірақ коддағы дұрыс аты - select_unassigned_variable.)

    • enforce_node_consistency self.domains жаңартуы тиіс, сонда әр айнымалы түйін-келісімді болады. Кроссвордта бұл әр доменнің әр сөзінің ұзындығы айнымалының ұзындығына тең болуы деген сөз. Мәнді алып тастау үшін self.domains[v].remove(x) шақыруға болады. Қайтарылатын мән жоқ.
    • revise x айнымалысын y айнымалысына қатысты доға-келісімді етеді. Екеуі де Variable нысаны. x доға-келісімді, егер x доменіндегі әр мәнге y доменінде қайшылық тудырмайтын мән табылса (кроссвордта қайшылық - екі айнымалының бір шаршыға әртүрлі әріп талап етуі). Сондықтан y-те сәйкес мәні жоқ мәндерді x доменінен алып тастаңыз. Қиылысты self.crossword.overlaps арқылы алыңыз. y домені өзгермей қалуы керек. x домені өзгерсе True, әйтпесе False қайтарыңыз.
    • ac3 AC-3 алгоритмімен есептің доға келісімін орнатады. Функция қосымша arcs аргументін алады - өңделетін доғалардың бастапқы тізімі. arcs мәні None болса, кезекті есептегі барлық доғадан бастаңыз. Әйтпесе тек arcs тізімінде тұрған доғалардан бастаңыз (әр доға - (x, y) кортежі, x және одан басқа y айнымалылары). Домен өзгергенде кезекке қосымша доғалар қосу қажет болуы мүмкін. Іске асыруда revise-ті пайдалануға болады. Егер процесте қандай да бір доменнен барлық мән өшіп қалса, False қайтарыңыз (шешім мүмкін емес). Әйтпесе True. Бұл функцияда сөздердің әртүрлілігін ескермесеңіз де болады (оны consistent тексереді).
    • assignment_complete берілген assignment толық ма, соны тексереді. Меншіктеу - айнымалылар (кілт) мен сөздер (мән) сөздігі. Кроссворд айнымалыларының бәріне мән берілсе, меншіктеу толық (мәннің қандай екені маңызды емес). Толық болса True, әйтпесе False.
    • consistent меншіктеудің үйлесімді екенін тексереді. Меншіктеу толық болмауы мүмкін. Меншіктеу үйлесімді, егер бұл шарттардың бәрі орындалса: барлық мән әртүрлі, әр мәннің ұзындығы дұрыс, көрші айнымалылар арасында қайшылық жоқ. Үйлесімді болса True, әйтпесе False.
    • order_domain_values var доменіндегі барлық мәннің тізімін қайтарады, ең аз шектейтін мән (LCV) эвристикасымен реттелген. var - Variable нысаны. LCV саны - мән көрші меншіктелмеген айнымалылардан қанша таңдауды жоятынын көрсетеді: егер мән n таңдауды жойса, нәтижені n өсу ретімен реттеңіз. assignment-те бар айнымалының мәні бұрыннан бар, оны n санағанда есепке алмаңыз. n тең мәндердің ретінің маңызы жоқ. Қиылысты self.crossword.overlaps арқылы алыңыз. Алдымен тізімді кез келген ретпен қайтарып, алгоритмді жұмыс істетіп алыңыз, кейін ретті дұрыстаңыз. Тізімді key бойынша sort ету көмектеседі.
    • select_unassigned_variable assignment-ке кірмейтін бір айнымалыны қайтарады: алдымен ең аз мәні қалған (MRV) айнымалыны, тең болса дәрежесі ең жоғарыны (көршісі ең көп). Екі жағдайда да тең болса, кез келгенін таңдаңыз. Меншіктеу толық емес деп есептей беріңіз. Алдымен кез келген меншіктелмеген айнымалыны қайтарып, кейін эвристиканы қосуға болады.
    • backtrack ішінара меншіктеу assignment алып, кері іздеумен толық үйлесімді меншіктеуді қайтарады (мүмкін болса). Шешім болмаса None қайтарыңыз. Қаласаңыз, іздеуді қорытынды шығарумен араластырсаңыз болады (әр жаңа меншіктеуден кейін доға келісімін сақтау): ac3-тің arcs аргументі дәл сол үшін қажет. Міндетті емес, бірақ нәтиже дұрыс болуы керек.

    generate.py ішінде спецификация сұрамаған ештеңені өзгертпеңіз; қосымша функция жазуға және Python стандартты кітапханасынан модуль импорттауға болады. numpy не pandas қолдануға болады, бірақ басқа сыртқы модуль болмайды. crossword.py-ды өзгертпеңіз.
