    Модульдік тесттер

    Кодты print арқылы көзбен тексерудің орнына, оны тексеретін кодты өзіміз жазамыз. assert, pytest және ерекше жағдайларды тексеруді үйренеміз.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)
    Бұл апта не туралы

    Осы уақытқа дейін кодыңыздың дұрыс-бұрыстығын print арқылы немесе CS50-дің тексерушісі арқылы біліп келдіңіз. Енді үшінші жолды үйренеміз: кодты тексеретін кодты өзіміз жазамыз. Апта соңындағы тапсырмаларда сіз бағдарламаны ғана емес, оның тесттерін де жазасыз, ал браузердегі автотексеруші сіздің тесттеріңіздің өзін тексереді.

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен кодтың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Модульдік тесттер

    Шынын айтайық: осы кезге дейін өз кодыңызды қалай тексеріп келдіңіз? Көбіміз print жазып, экранға қарап, «дұрыс сияқты» дейміз. Ал кейде тексеруді CS50-дің өзіне тапсырып, check50-нің жасыл күлкілерін күтеміз. Бірақ нақты өндірісте, компанияларда бәрі басқаша: бағдарламашылар өз кодын тексеру үшін арнайы код жазады. Яғни бағдарлама бір бөлек, оны тексеретін бағдарлама тағы бір бөлек.

    Мұны модульдік тест (unit test) дейді. «Модуль» немесе «бірлік» деп бағдарламаның бір шағын бөлігін, көбіне бір функцияны айтамыз. Бүкіл ғимаратты бірден тексерудің орнына, әр кірпіштің мықтылығын бөлек тексеру сияқты.

    Бастау үшін таныс калькуляторымызды алайық. Терминалға code calculator.py деп жазып, мынадай код жазамыз (өткен лекцияда жазған болуыңыз керек):

    def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))


def square(n):
    return n * n


if __name__ == "__main__":
    main()

    Бұл кодты өзіңіз-ақ тексере аласыз: іске қосып, 2 деп жазасыз, 4 шықты, жарайды. Бірақ ойланып көріңіз: неге бұған бөлек тест жазу керек? Себебі «2» деген бір ғана жағдай. Бағдарлама үлкейгенде қолмен тексеру қиындап, біреуін ұмытып кетеміз. Тестті бір рет жазып қойсақ, кодты өзгерткен сайын оны бір секундта қайта жүргізе аламыз.

    Дәстүр бойынша тест файлының аты test_ деп басталады. Жаңа файл ашайық: code test_calculator.py.

    from calculator import square


def main():
    test_square()


def test_square():
    if square(2) != 4:
        print("2 squared was not 4")
    if square(3) != 9:
        print("3 squared was not 9")


if __name__ == "__main__":
    main()

    Бірінші жолға назар аударыңыз: from calculator import square. Біз calculator.py файлынан тек square функциясын өз тест файлымызға әкеліп отырмыз. Міне, if __name__ == "__main__" тексерісінің пайдасы осында: калькулятор main-і біз импорттағанда өздігінен іске қосылып кетпейді.

    Енді терминалда python test_calculator.py деп жазайық. Не шықты? Ештеңе. Бос экран. Бұл жақсы ма? Мүмкін, бәрі дұрыс шығар. Ал мүмкін, біздің тестіміз қателікті ұстамай тұрған шығар: бағдарлама тек бізге белгілі екі жағдайды ғана тексерді, ал «шеткі жағдайлар» (corner cases) есімізден шығып кеткен болуы мүмкін.

    Тағы бір мәселе бар. Тексеретін жағдайымыз он болса, он if жазамыз ба? Тест кодымыз бағдарламаның өзінен ұзын болып кетеді. Қалай қысқартуға болады?

    assert

    Python-да бұған арнайы команда бар: assert, яғни «бекіту». Ол интерпретаторға былай дейді: «Мынау ақиқат екеніне сенімдімін. Егер олай болмай шықса, дереу қате бер». Тестімізді қайта жазайық:

    from calculator import square


def main():
    test_square()


def test_square():
    assert square(2) == 4
    assert square(3) == 9


if __name__ == "__main__":
    main()

    Көрдіңіз бе, төрт жол екіге түсті. Біз «square(2) міндетті түрде 4-ке тең» деп тікелей бекітіп отырмыз. Егер солай болса, ештеңе болмайды, бағдарлама үнсіз жалғаса береді. Егер болмаса, Python дабыл қағады.

    Дабылды көру үшін калькуляторымызды әдейі бұзып көрейін. * белгісін + етіп өзгертемін:

    def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))


def square(n):
    return n + n


if __name__ == "__main__":
    main()

    Байқадыңыз ба, қате өте қулықпен жасырылған. Өйткені 2 + 2 де 4, ал 2 * 2 де 4! Тек екі санымен тексерсеңіз, қатені ешқашан таппайсыз. Бірақ біздің тестіміз 3-ті де қосқан. Енді python test_calculator.py деп іске қосамыз да, AssertionError аламыз. Бұл интерпретатордың «сіз бекіткен шарттардың бірі орындалмады» дегені.

    Ойланып көріңіз: неге тест үшін 2 емес, 3 қажет болды?

    Себебі 2 үшін n + n мен n * n бірдей нәтиже береді (екеуі де 4). Қате тек басқа сан берген кезде ғана білінеді. Мұнан үлкен сабақ шығады: тесттегі мәндерді ойланып таңдау керек, бір «ыңғайлы» санға сүйенуге болмайды.

    Ал енді тағы бір қиындық. AssertionError шықты, бірақ қайсысы құлады? Өкінішке қарай, ол өте қысқа хабар береді. Қолданушыға түсінікті хабар шығарғымыз келсе, ойға бірінші келетін жол мынау:

    from calculator import square


def main():
    test_square()


def test_square():
    try:
        assert square(2) == 4
    except AssertionError:
        print("2 squared is not 4")
    try:
        assert square(3) == 9
    except AssertionError:
        print("3 squared is not 9")
    try:
        assert square(-2) == 4
    except AssertionError:
        print("-2 squared is not 4")
    try:
        assert square(-3) == 9
    except AssertionError:
        print("-3 squared is not 9")
    try:
        assert square(0) == 0
    except AssertionError:
        print("0 squared is not 0")


if __name__ == "__main__":
    main()

    Мұнда әр жағдайды try ішіне алып, қате шықса, түсінікті хабар жазамыз. Енді іске қосқанда бірнеше қате хабарын көреміз. Бірақ бәрін емес! Мысалы, 0 үшін 0 + 0 де 0 * 0 де нөл, сондықтан ол жағдай жасырын қалады. Бұл тағы бір дәлел: жағдайлардың көп болғаны жақсы, сонда қателердің ұсталу мүмкіндігі артады.

    Бірақ осы кодқа қараңызшы: бес жағдай үшін жиырмадан астам жол! Бұл дұрыс жол емес. Сұрақ қайта туады: тестті қалай жеңілдетуге болады, және қателерді әдемі етіп қалай көрсетуге болады?

    Қосымша: assert туралы Python құжаттамасында толығырақ оқи аласыз.

    pytest

    Жауап: біреу бұл мәселені біз үшін шешіп қойған. pytest - Python бағдарламаларын тексеруге арналған үшінші тарап кітапханасы (third-party library). Ол қателерді әдемі көрсетеді және тесттерді өзі тауып, іске қосады. Орнату үшін терминалда:

    $ pip install pytest

    Мұнда pip - Python пакеттерін орнататын құрал. Ол кітапхананы интернеттен тауып жүктеп береді.

    Ең алдымен тест кодымызды жеңілдетейік. Енді main-нің қажеті жоқ (кодта қалып қойса да, pytest оны шақырмайды), assert-тердің барлығын бір функцияға салып қоямыз (try та керек емес):

    from calculator import square


def main():
    test_square()


def test_square():
    assert square(2) == 4
    assert square(3) == 9
    assert square(-2) == 4
    assert square(-3) == 9
    assert square(0) == 0

    Қараңыз, біз тексергіміз келген бес шарттың бәрі таза жазылды. Енді python емес, pytest арқылы іске қосамыз:

    $ pytest test_calculator.py

    Бірден көп мәтін шығады. Жоғарыда қызыл F (fail, «құлады») әрпін көресіз: бірдеңе дұрыс емес. Одан төменде қызыл E жолдары қателіктің себебін көрсетеді, соның ішінде square(3) қандай нәтиже қайтарғанын да. Мысалы, 3-ті квадраттағанда 9 емес, 6 шыққанын көресіз. Міне, қызыл мәтін бізге дәл қайда іздеу керегін айтып тұр. Қатені түзетейік, + қайтадан * болсын:

    def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))


def square(n):
    return n * n


if __name__ == "__main__":
    main()

    Қайта pytest test_calculator.py жүргіземіз. Енді қате жоқ, жасыл түс. Құттықтаймын!

    Бірақ ыңғайсыз жағы бар: біздің тест бірінші құлаған assert-тен кейін тоқтап қалады. Қалған төрт жағдай тексерілмей қалады. Мұны өз көзімізбен көру үшін калькуляторды тағы бұзайық (* орнына +):

    def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))


def square(n):
    return n + n


if __name__ == "__main__":
    main()

    Шешім қарапайым: тесттерді тақырыбы бойынша бөлек функцияларға бөлеміз. pytest әр функцияны бөлек іске қосады және біреуі құласа да, қалғандарын жалғастыра береді:

    from calculator import square


def test_positive():
    assert square(2) == 4
    assert square(3) == 9


def test_negative():
    assert square(-2) == 4
    assert square(-3) == 9


def test_zero():
    assert square(0) == 0

    Сол бес тест, тек үш топқа бөлінген: оң сандар, теріс сандар және нөл. pytest-ті қайта жүргізсек, қателіктер әлдеқайда көп шығады және олар қай топта екенін көрсетеді. Қате туралы ақпарат неғұрлым көп болса, соғұрлым оны табу оңай. Ал енді калькуляторды қайтадан түзетеміз:

    def main():
    x = int(input("What's x? "))
    print("x squared is", square(x))


def square(n):
    return n * n


if __name__ == "__main__":
    main()

    pytest test_calculator.py тағы да жасыл: қате жоқ.

    Ерекше жағдайларды тексеру

    Тағы бір маңызды нәрсе. Кейде дұрыс бағдарлама қате беруі тиіс. Мысалы, square("cat") дегенде не болуы керек? «Мысықты» квадраттай алмаймыз ғой, сондықтан TypeError шығуы заңды. Бұл күтілген қате екенін тестте қалай жазамыз? pytest-тің өз құралы бар: raises. Оны қолдану үшін файлдың басына import pytest қосамыз:

    import pytest

from calculator import square


def test_positive():
    assert square(2) == 4
    assert square(3) == 9


def test_negative():
    assert square(-2) == 4
    assert square(-3) == 9


def test_zero():
    assert square(0) == 0


def test_str():
    with pytest.raises(TypeError):
        square("cat")

    Бұл жолы assert емес, pytest.raises қолдандық. Оқылуы былай: «with блогының ішінде TypeError шығуы тиіс». Қате шықса, тест өтті. Ал қате шықпаса, тест құлайды. Яғни біз қатенің болмауын емес, болуын күтіп отырмыз. Ол үшін pytest.raises-ке қандай қате күтетінімізді (TypeError) көрсетеміз.

    Тағы pytest test_calculator.py іске қосамыз: қате жоқ.

    Қорытындылайық: қанша және қандай жағдайларды тексеру - өзіңіздің шешіміңіз. Бағдарламашы ретінде қандай мән бағдарламаны құлата алатынын ойлап, соның бәрін тестке қосу сіздің міндетіңіз.

    Толығырақ оқу үшін: pytest құжаттамасы.

    Жолдарды тестілеу

    Енді «ескі уақытқа» оралайық. Нөлінші апталардағы hello.py бағдарламасын еске түсіріңіз:

    def main():
    name = input("What's your name? ")
    hello(name)


def hello(to="world"):
    print("hello,", to)


if __name__ == "__main__":
    main()

    Мұндағы hello функциясын тексергіміз келеді. Мынадай test_hello.py жазып көрелік:

    from hello import hello


def test_hello():
    assert hello("David") == "hello, David"
    assert hello() == "hello, world"
    Ойланып көріңіз: бұл тест жұмыс істей ме?

    Жоқ! Неге? Төменде түсіндіреміз: hello мәнді қайтармайды, тек экранға жазады, ал assert тек қайтарылған мәнмен жұмыс істейді.

    Сонымен, жауабы: жоқ! Неге? Себебі біздің hello функциясы ештеңе қайтармайды, ол тек экранға жазады (print). Ал assert функциядан қайтқан мәнді салыстырады. Экранға шыққан мәтінге оның қолы жетпейді. Нөлінші лекциядағы print мен return айырмашылығы міне, қайда керек болды: жазылған мәтінді тесттен ұстай алмаймыз, ал қайтарылған мәнді ұстай аламыз.

    Сондықтан hello-ны өзгертеміз: ол жолды return етсін, ал print-ті main орындасын:

    def main():
    name = input("What's your name? ")
    print(hello(name))


def hello(to="world"):
    return f"hello, {to}"


if __name__ == "__main__":
    main()

    Енді hello жол қайтарады, сондықтан pytest оны тексере алады. pytest test_hello.py деп жазсақ, барлық тест өтеді!

    Алдыңғы мысалдағыдай, тесттерді бөлек функцияларға бөлеміз, сонда біреуі құласа да, екіншісі жүре береді:

    from hello import hello


def test_default():
    assert hello() == "hello, world"


def test_argument():
    assert hello("David") == "hello, David"

    Тест екі функцияға бөлінді: бірі әдепкі мәнді, екіншісі берілген атты тексереді. Біреуі қате берсе де, екіншісі бәрібір орындалады.

    Тестілеуге ыңғайлы код жазу

    Функция print жасаса, оны тексеру қиын. Функция мән return етсе, тексеру оңай. Сондықтан кодты былай құрастырыңыз: есептеу функциялары нәтижені қайтарсын, ал print тек main-де болсын. Бұл CS50P-дің осы апталық тапсырмаларындағы да басты талап: «Only main should call print».

    Тесттерді қалталарға ұйымдастыру

    Нақты жобада тест файлдары көп болады. Оларды бір-бірден іске қоса бермей, бүкіл қалтаны бір командамен жүргізуге болады. Қалай дейсіз бе? Әуелі терминалда test деген қалта жасаймыз:

    $ mkdir test

    Содан кейін сол қалтаның ішінде тест файлын ашамыз. Жолдағы test/ терминалға «файлды test қалтасында жаса» дегенді білдіреді:

    $ code test/test_hello.py

    Файлға таныс тестімізді жазамыз:

    from hello import hello


def test_default():
    assert hello() == "hello, world"


def test_argument():
    assert hello("David") == "hello, David"

    Бәрі бұрынғыдай. Бірақ қалтада арнайы __init__ файлы болмаса, pytest қалтаны тұтастай іске қоспайды, тек осы бір файлмен (немесе бір топ файлмен) шектеледі. Оны жасайық:

    $ code test/__init__.py

    Қайтадан test/ қалтасын және init сөзінің екі жағындағы қос астыңғы сызықты (__) байқаңыз. Файлдың өзі бос қалса да болады. Оның болуының өзі pytest-ке «бұл қалтада орындалатын тесттер бар» деп хабарлайды. Енді бүкіл қалтаны бір командамен жүргізе аламыз:

    $ pytest test

    Қалтадағы барлық тест бірден орындалады. Жоба үлкейгенде мұндай тәсіл өте ыңғайлы: мыңдаған тестті бір қимылмен жүргізуге болады.

    Қосымша: pytest-тің импорт механизмдері туралы құжаттама.

    Қорытынды

    Кодты тексеру - бағдарламалау процесінің табиғи бөлігі. Модульдік тесттер кодыңыздың нақты бөліктерін тексеруге мүмкіндік береді. Тесттерді өзіңіз де жаза аласыз, ал pytest сияқты фреймворктер оларды сіз үшін іске қосып, нәтижесін әдемі көрсетеді. Бұл лекцияда сіз мыналарды үйрендіңіз:

    • модульдік тесттер (test_ деп басталатын функциялар) және неге олар қажет;
    • assert арқылы шарттарды бекіту және AssertionError;
    • шеткі жағдайларды ойлап, мәндерді ойланып таңдау;
    • pytest: орнату, pytest test_файл.py, F мен E белгілері;
    • тесттерді бөлек функцияларға бөлу (бірі құласа, қалғандары жүреді);
    • күтілетін қатені pytest.raises арқылы тексеру;
    • тестілеуге ыңғайлы код: print емес, return;
    • тесттерді қалтаға жинап, __init__.py қосып, pytest test арқылы іске қосу.

    Өзіңізді тексеріңіз

    1. Тест файлының атын неге test_calculator.py деп қоямыз?

    Атау дәстүрі қатаң болмаса да, pytest тесттерді дәл осы test_ префиксі арқылы тауып алады.

    2. square(n) функциясында қателесіп n * n орнына n + n жазылған. Қай тест қатені таппайды?

    2 + 2 және 2 * 2 екеуі де 4 болады, сондықтан бұл тест қатені байқамайды. Сондықтан бірнеше түрлі мәнмен тексеру керек.

    3. assert square(3) == 9 орындалмаса, Python не істейді?

    assert шарт ақиқат болмаса, AssertionError көтереді. Шарт ақиқат болса, үнсіз өтіп кетеді.

    4. Тесттерді test_positive, test_negative, test_zero деген бірнеше функцияға бөлудің басты артықшылығы қандай?

    Бір функцияның ішінде бірінші құлаған assert-тен кейін қалғандары орындалмайды. Бөлек функциялар бөлек іске қосылады.

    5. square("cat") шақырылғанда TypeError шығуын күтетін тест қалай жазылады?

    pytest.raises блоктағы код көрсетілген қатені көтерсе, тест өтеді; көтермесе, құлайды.

    6. Мына hello функциясын assert hello("David") == "hello, David" арқылы тексеруге бола ма?

    def hello(to="world"):
    print("hello,", to)

    Тестілеу үшін функция return жасауы керек. Сондықтан print тек main-де қалады.

    7. test қалтасындағы барлық тестті pytest test арқылы іске қосу үшін қалтаға не қосу керек?

    __init__.py болғанда, pytest бүкіл қалтада орындалатын тесттер бар екенін біледі.

    8. pytest шығысындағы қызыл F әрпі нені білдіреді?

    F - құлаған тест, ал қызыл E жолдары қатенің қайда екенін көрсететін кеңестер береді.

    Тапсырмалар жинағы 5

    (Problem Set 5) Ресми тапсырма беті: cs50.harvard.edu/python/psets/5. Бұл жолы ерекше: сіз өткен апталардағы төрт бағдарламаны қайта жазасыз (оларды тестілеуге ыңғайлы етіп), сосын олар үшін тест файлын жазасыз. Автотексеруші сіздің тестіңізді дұрыс бағдарламамен де, әдейі бұзылған бірнеше бағдарламамен де іске қосады: дұрысында барлығы өтуі, ал әр қате нұсқада кемінде бір тест құлауы керек. Ресми check50 да дәл осылай жұмыс істейді.

    Браузерде pytest жоқ

    Браузердегі автотексеруші нағыз pytest-ті іске қоса алмайды. Сондықтан онда тесттеріңізді кәдімгі assert арқылы жазыңыз; import pytest және with pytest.raises(...) да жұмыс істейді (шағын алмастырғыш бар), ал қалған pytest мүмкіндіктері жоқ. Компьютеріңізде нағыз pytest орнатып, ресми check50 командасын міндетті түрде іске қосыңыз. Әр тапсырмада екі автотексеруші бар: біріншісі сіздің тестіңізді, екіншісі қайта жазылған бағдарламаның өзін тексереді.

    Оңай

    Testing my twttr (twttr-ді тестілеу)

    twttr.py файлында 2-тапсырмалар жинағындағы «Setting up my twttr» бағдарламасын қайта жазыңыз. Енді код мына құрылымда болсын: shorten кіріс ретінде str алып, сол str-ді, бірақ барлық дауысты әріптерсіз (A, E, I, O, U; бас немесе кіші әріп болуына қарамастан) қайтарады.

    def main():
    ...


def shorten(word):
    ...


if __name__ == "__main__":
    main()

    Сосын test_twttr.py файлында shorten бағдарламаңызды жан-жақты тексеретін бір немесе бірнеше функция жазыңыз. Әр функцияның аты test_ деп басталсын, сонда оларды былай іске қосуға болады:

    $ pytest test_twttr.py
    Кеңес

    test_twttr.py файлының басына import twttr немесе from twttr import shorten қосыңыз, сонда тесттерде shorten-ді шақыра аласыз. shorten ішінде print емес, str return етіңіз: print-ті тек main шақырады. Қандай жағдайларды ұмытпауыңыз керек? Бас әріпті дауыстылар, цифрлар, тыныс белгілері.

    Қалай тексеру керек. Алдымен twttr.py-дың дұрыс нұсқасымен pytest test_twttr.py жүргізіңіз: барлығы өтуі керек. Сосын twttr.py-ға әдейі қате енгізіңіз (мысалы, тек кіші әріпті дауыстыларды өшіретін болсын) және тесттеріңіз кемінде біреуінде құлайтынын тексеріңіз.

    Тексеру
    • twttr.py-да shorten жолды return етеді, print тек main-де.
    • Тесттер бас және кіші дауыстыларды, цифрларды және тыныс белгілерін қамтиды.
    • check50 cs50/problems/2022/python/tests/twttr өтеді.

    Back to the Bank (Банкке оралу)

    bank.py файлында 1-тапсырмалар жинағындағы «Home Federal Savings Bank» бағдарламасын қайта жазыңыз. value кіріс ретінде str алады және int қайтарады: жол «hello» сөзімен басталса 0, «h» әрпімен басталса (бірақ «hello» емес) 20, әйтпесе 100. Жолды регистрге тәуелсіз қарастырыңыз. value-ге берілетін жолдың басында бос орын болмайды деп есептеуге болады. print-ті тек main шақырады.

    def main():
    ...


def value(greeting):
    ...


if __name__ == "__main__":
    main()

    Сосын test_bank.py файлында value-ны жан-жақты тексеретін үш немесе одан көп функция жазыңыз (аттары test_ деп басталсын):

    $ pytest test_bank.py
    Кеңес

    Файлдың басына import bank немесе from bank import value жазыңыз. value ішінде int return етіңіз, print емес. Үш функцияға бөлудің табиғи жолы: «hello» жағдайлары, «h» жағдайлары, қалғандары. Бас және кіші әріппен жазылған мысалдарды да қосыңыз.

    Қалай тексеру керек. Дұрыс bank.py-мен барлық тест өтуі тиіс. Содан кейін мәндерді әдейі өзгертіңіз (мысалы, «Hello»-ға 100, ал «What's up»-қа 0 берілсін): кемінде бір тест құлауы керек.

    Тексеру
    • value int қайтарады, регистрге тәуелсіз жұмыс істейді.
    • test_bank.py-да кемінде үш test_ функциясы бар.
    • check50 cs50/problems/2022/python/tests/bank өтеді.

    Орташа

    Re-requesting a Vanity Plate (Нөмір белгісін қайта сұрау)

    plates.py файлында 2-тапсырмалар жинағындағы «Vanity Plates» бағдарламасын қайта жазыңыз. is_valid бұрынғыдай str қабылдап, барлық талап орындалса True, әйтпесе False қайтарады. Бірақ енді main тек __name__ мәні "__main__" болғанда ғана шақырылады:

    def main():
    ...


def is_valid(s):
    ...


if __name__ == "__main__":
    main()

    Сосын test_plates.py файлында is_valid-ты жан-жақты тексеретін төрт немесе одан көп функция жазыңыз (аттары test_ деп басталсын):

    $ pytest test_plates.py

    Еске салайық, нөмір белгісінің талаптары: кемінде екі әріптен басталады; ұзындығы 2-ден 6 таңбаға дейін; цифрлар тек соңында болады және бірінші цифр 0 болмайды; нүкте, бос орын, тыныс белгілері болмайды.

    Кеңес

    Файлдың басында import plates немесе from plates import is_valid болсын. is_valid ішінде bool return етіңіз, print емес. Төрт функцияға бөлуге болатын топтар: дұрыс нөмірлер, ұзындық, басындағы әріптер, цифрлардың орны мен нөл, тыныс белгілері.

    Қалай тексеру керек. Дұрыс plates.py-мен тесттер өтуі керек. Сосын шектеулердің бірін алып тастаңыз (мысалы, кез келген ұзындыққа «Valid» берсін): тесттер кемінде біреуінде құлауы тиіс.

    Тексеру
    • is_valid bool қайтарады, main тек __name__ == "__main__" кезінде шақырылады.
    • Тесттер әрбір талапты (ұзындық, алғашқы әріптер, цифрлар, 0, тыныс белгілері) бөлек тексереді.
    • check50 cs50/problems/2022/python/tests/plates өтеді.

    Күрделі

    Refueling (Қайта жанармай құю)

    fuel.py файлында 3-тапсырмалар жинағындағы «Fuel Gauge» бағдарламасын қайта жазыңыз:

    • convert X/Y пішіміндегі str қабылдайды (X - теріс емес бүтін, Y - оң бүтін) және бөлшекті 0-ден 100-ге дейінгі (қоса алғанда) ең жақын int пайыз етіп қайтарады. X және/немесе Y бүтін сан болмаса немесе X саны Y-тен үлкен болса, convert ValueError көтеруі керек. Y нөл болса, ZeroDivisionError көтеруі керек.
    • gauge int қабылдайды және str қайтарады: сан 1-ден аз не тең болса "E", 99-дан көп не тең болса "F", қалған жағдайда "Z%" (мұнда Z - сол сан).
    def main():
    ...


def convert(fraction):
    ...


def gauge(percentage):
    ...


if __name__ == "__main__":
    main()

    Сосын test_fuel.py файлында convert пен gauge функцияларын жан-жақты тексеретін екі немесе одан көп функция жазыңыз (аттары test_ деп басталсын):

    $ pytest test_fuel.py
    Кеңес

    Файлдың басына import fuel немесе from fuel import convert, gauge жазыңыз. convert ішінде int, gauge ішінде str return етіңіз; print тек main-де. Ерекше жағдайды raise ValueError арқылы көтересіз, ал оны тестте with pytest.raises(ValueError): арқылы тексересіз (құжаттама). Шеткі мәндерді ұмытпаңыз: 0, 1, 99, 100.

    Қалай тексеру керек. Дұрыс fuel.py-мен тесттер өтуі керек. Содан кейін convert-тің қайтарған мәнін өзгертіңіз (мысалы, int орнына str қайтарсын) және gauge-ті бұзыңыз (мысалы, % белгісін ұмытсын). Әр жағдайда тесттің кемінде біреуі құлауы тиіс.

    Браузерде ерекше жағдайларды тексеру

    Браузерде нағыз pytest жоқ, бірақ with pytest.raises(ValueError): жұмыс істейді. Қаласаңыз, try/except арқылы да жаза аласыз: try: ішінде convert("3/2")-ді шақырып, except ValueError: pass деп, ал else: бөлігінде assert False деп жазыңыз. Қате шықпаса, тест құлайды. Автотексеруші екі тәсілді де қабылдайды.

    Тексеру
    • convert ValueError және ZeroDivisionError көтереді, gauge "E", "F" немесе "Z%" қайтарады.
    • Тесттер ерекше жағдайларды және шеткі мәндерді (0, 1, 99, 100) қамтиды.
    • check50 cs50/problems/2022/python/tests/fuel өтеді.
