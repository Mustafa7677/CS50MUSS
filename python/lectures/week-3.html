Мазмұны

    3-апта

    Ерекше жағдайлар

    Бағдарлама әрқашан біз ойлағандай жүре бермейді: қолданушы сан орнына «cat» деп жазады, біреу нөлге бөледі. Бұл аптада осындай ерекше жағдайларды try, except, else және pass арқылы ұстап, бағдарламаны құлатпай, сыпайы түрде қайта сұрауды үйренеміз.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен кодтың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Ерекше жағдайлар

    Осы уақытқа дейін біз бағдарламаларымыз дұрыс жұмыс істейтін жағдайларды көбірек қарадық. Бірақ шынайы өмірде бәрі бірдей жайлы бола бермейді. Бүгін соның екінші жағына, яғни бағдарлама жұмыс істеп тұрғанда бірдеңе дұрыс болмай қалатын сәттерге назар аударамыз. Мұндай мәселелерді Python-да ерекше жағдайлар (exceptions) деп атайды: кодымыздың ішінде, жоспардан тыс, бір нәрсе бұзылып кетеді.

    Бастау үшін әдейі қате жасап көрейін. Терминалға code hello.py деп жазып, жаңа файл ашамын да, бізге баяғыдан таныс жолды жазамын. Тек бұл жолы соңғы тырнақшаны қасақана ұмытып кетемін:

    print("hello, world)

    Тырнақша жабылмай қалғанын байқадыңыз ба? Енді python hello.py деп іске қосайық:

    $ python hello.py
  File "hello.py", line 1
    print("hello, world)
          ^
SyntaxError: unterminated string literal (detected at line 1)

    Python бірден наразылық білдірді. Бұл - синтаксистік қате (syntax error). Синтаксис дегеніміз - тілдің грамматикасы. Қазақ тілінде сөйлемнің соңына нүкте қоймасаңыз, оқырман бәрібір түсінер еді, ал Python олай кешірімді емес: тырнақша ашылды ма, міндетті түрде жабылуы керек. Синтаксистік қате шықса, әдетте бір ғана кеңес бар: кодыңызды қайта қарап, дұрыс тергеніңізге көз жеткізіңіз. Мұндай қатені Python бізге «ұстап» бере алмайды, оны өзіміз, қолмен түзетуіміз керек.

    Қателер мен ерекше жағдайлар туралы толығырақ Python құжаттамасында бар: Errors and Exceptions.

    Орындалу кезіндегі қателер

    Синтаксистік қателерді біз жазу кезінде жібереміз, сондықтан оларды түзету оңай. Ал мүлде басқа түрі бар: орындалу кезіндегі қателер (runtime errors). Код грамматикалық тұрғыдан мінсіз болуы мүмкін, бірақ бағдарлама жұмыс істеп жатқанда күтпеген бірдеңе болады да, бәрі құлайды. Мысалы, біз қолданушыдан сан күтеміз, ал ол әріп жазып жібереді.

    Көрсетейін. Терминалда code number.py деп жаңа файл ашып, мынаны жазамын:

    x = int(input("What's x? "))
print(f"x is {x}")

    Тырнақшаның алдындағы f әрпін ұмытқан жоқсыз ғой? Ол арқылы Python-ға фигуралы жақшаның ішіндегіні интерполяциялау (interpolate), яғни {x} деген жердің орнына x-тің мәнін қою керегін айтамыз.

    Бағдарламаны іске қосып, 50 енгізсек, бәрі керемет: x is 50. Бірақ енді өзіңізді қолданушының орнына қойыңыз. Ол сан орнына жол немесе бір әріп жазып жіберуі әбден мүмкін. Тіпті ештеңе жазбай, жай ғана Enter басып қалуы да ықтимал. Біз, бағдарламашылар, алдын ала қорғанып жазуымыз керек: қолданушының біз күткен нәрсені енгізгеніне көз жеткізуіміз қажет. Ендеше, әдейі «cat» деп жазып көрейік:

    $ python number.py
What's x? cat
Traceback (most recent call last):
  File "number.py", line 1, in <module>
    x = int(input("What's x? "))
ValueError: invalid literal for int() with base 10: 'cat'

    Міне, ValueError, яғни мән қатесі (value error). Хабарды сөзбе-сөз оқысақ: «int() үшін ондық санау жүйесіндегі жарамсыз литерал: 'cat'». Қарапайым тілмен айтқанда, int функциясы «cat» деген мәтінді санға айналдыра алмайды. Шынында да, мысықты санға қалай айналдырасыз?

    Ойланып көріңіз: қолданушы ештеңе жазбай, бірден Enter басса не болады?

    Тағы да ValueError шығады, тек бұл жолы соңында бос жол тұрады: invalid literal for int() with base 10: ''. input бос жол қайтарады, ал бос жолды да санға айналдыру мүмкін емес.

    Бағдарламаның қолданушы алдында осылай құлап, түсініксіз қызыл жазу шығаруы - жақсы емес. Мұны түзетудің тиімді жолы - қателерді өңдеу (error handling): қолданушы біз күткендей әрекет етпесе, бағдарлама оған дайын болып, өзін дұрыс ұстауы керек. Мұны қалай істейтінімізді қазір көреміз. Толығырақ: Errors and Exceptions.

    try және except

    Python-да бұл үшін екі кілт сөз бар: try («байқап көр») және except («егер ... болса, ұста»). Олардың мағынасы мынадай: «мына кодты орындап көр, ал егер белгілі бір ерекше жағдай туындаса, бағдарламаны құлатпай, оның орнына мынаны істе». Кодымызды өзгертейік:

    try:
    x = int(input("What's x?"))
    print(f"x is {x}")
except ValueError:
    print("x is not an integer")

    Іске қосып, 50 енгізсек, бәрі бұрынғыдай: x is 50. Ал cat деп жазсақ, бағдарлама құламайды, оның орнына қолданушыға енгізгенінің неге қабылданбағанын түсіндіретін хабар шығады:

    $ python number.py
What's x?cat
x is not an integer

    Айтпақшы, сұрақ мәтінінің соңында бос орын жоқ болғандықтан, жауап сұраққа жабысып тұрғанын байқадыңыз ба? Бұл ұсақ-түйек, оны лекцияның соңында түзетеміз. Одан да маңыздырақ нәрсе бар: except ValueError деп нақты қай ерекше жағдайды ұстайтынымызды атап жазғанымызға назар аударыңыз. Біз «кез келген қатені» емес, дәл осы, int лақтыруы мүмкін қатені күтіп отырмыз.

    Дегенмен бұл код әлі де мінсіз емес. Байқасаңыз, try-дың ішінде екі жол тұр. Жақсы әдет бойынша try-дың ішіне тек қате беруі мүмкін, біз алаңдайтын ең аз жолды ғана жазған жөн. print-тің қате беруінен біз қорықпаймыз ғой. Ендеше, оны сыртқа шығарайық:

    try:
    x = int(input("What's x?"))
except ValueError:
    print("x is not an integer")

print(f"x is {x}")
    Ойланып көріңіз: енді «cat» енгізсек, не болады?

    Алдымен x is not an integer шығады, бірақ сосын бағдарлама бәрібір құлайды, бұл жолы жаңа қатемен: NameError: name 'x' is not defined. Неге екенін төменде түсіндіремін.

    Мақсатымызға жеттік сияқты еді: try-да тек бір жол қалды. Бірақ енді жаңа қатеге тап болдық: атау қатесі (name error), NameError, яғни «x анықталмаған». Қалайша? Біз x = ... деп анық жаздық қой!

    Жауабын табу үшін x = int(input("What's x?")) жолының қалай орындалатынын еске түсірейік. Меншіктеуді оңнан солға қарай оқимыз: алдымен input орындалып, «cat» жолын қайтарады. Сосын int оны санға айналдырмақ болады да, сол сәтте ValueError лақтырады. Ал ең соңғы қадам, яғни нәтижені x қобдишасына салу, ешқашан орындалмайды, себебі оған жетпей-ақ бәрі үзілді. Бағдарлама бірден except блогына секіріп, хабар шығарады да, ары қарай жүре береді. Соңғы жолға жеткенде x атты қобдиша мүлде жасалмаған, сондықтан print оны таба алмайды.

    Басқа да ерекше жағдайлар

    ValueError мен NameError-дан басқа да ерекше жағдайлар көп. Мысалы, нөлге бөлсеңіз - ZeroDivisionError, сөздікте жоқ кілтті сұрасаңыз - KeyError, ал қолданушы control-d басып, енгізуді аяқтаса - input EOFError лақтырады. Бұлардың бәрі тапсырмалар жинағында кездеседі және бәрін дәл осылай try/except арқылы ұстауға болады. Толық тізімі: Built-in Exceptions.

    else

    Сонымен, бізге «егер қате болмаса ғана, мынаны істе» деп айтудың жолы керек. Шартты операторлардан таныс else сөзі try-мен де қолданылады екен. Кодымызды былай өзгертейік:

    try:
    x = int(input("What's x?"))
except ValueError:
    print("x is not an integer")
else:
    print(f"x is {x}")

    Логикасы өте қарапайым: try-дағы код ешқандай ерекше жағдайсыз орындалса, Python else блогын іске қосады. Ал қате болса, except орындалады да, else өткізіп жіберіледі. Екеуінің біреуі ғана, ешқашан екеуі бірге емес. python number.py деп іске қосып, 50 енгізсек, нәтиже шығады. Қайтадан іске қосып, cat енгізсек, бағдарлама қатені ұстап, ешқандай NameError-сыз әдемі аяқталады.

    Бірақ ойланып қарасаңыз, біз қолданушыға сәл дөрекі қарап отырмыз. Ол бір рет қателессе, бағдарламамыз «сан емес» деп, есікті тарс жауып кете барады. Банкоматты елестетіңіз: PIN-кодты бір рет қате тердіңіз екен деп, ол картаңызды жұтып қоймайды ғой, «қайта енгізіңіз» дейді. Біз де солай істейік: қолданушы дұрыс жауап бергенше, цикл арқылы қайта-қайта сұрайық:

    while True:
    try:
        x = int(input("What's x?"))
    except ValueError:
        print("x is not an integer")
    else:
        break

print(f"x is {x}")

    while True - бізге 2-аптадан таныс шексіз цикл (infinite loop): шарты әрқашан ақиқат болғандықтан, ол мәңгі айнала береді. Одан шығудың жалғыз жолы - break. Ал біз break-ті әдейі else-тің ішіне қойдық, яғни циклден тек қолданушы дұрыс сан енгізгенде ғана шығамыз. Сол сәтте x міндетті түрде анықталған, сондықтан соңғы print қауіпсіз:

    $ python number.py
What's x?cat
x is not an integer
What's x?dog
x is not an integer
What's x?50
x is 50

    Енді қате енгізген қолданушыдан бағдарлама жай ғана қайта сұрайды. Әлдеқайда сыпайы, солай емес пе?

    Бүтін сан алатын функция

    Қолданушыдан бүтін сан сұрау - бағдарламаларда үнемі кездесетін жұмыс. Әр жолы осы цикл мен try-ды көшіріп отырмай, оны бөлек функцияға шығарайық. 0-аптадан бері қолданып келе жатқан main үлгісі осында да көмектеседі:

    def main():
    x = get_int()
    print(f"x is {x}")


def get_int():
    while True:
        try:
            x = int(input("What's x?"))
        except ValueError:
            print("x is not an integer")
        else:
            break
    return x


main()

    Мұнда бірнеше жақсы қасиетті байқауға болады. Ең бастысы, біз бүтін сан алу қабілетін абстракциялап (abstraction) шығардық: санды қалай сұрайтынымыз, қатені қалай ұстайтынымыз, қайта сұрау - мұның бәрі get_int-тің ішіне жасырылды. Енді бүкіл бағдарламаның мәні алғашқы үш жолға сыйып кетті: «бүтін сан ал да, оны шығар». main-ді оқыған адам get_int-тің ішінде не болып жатқанын білмесе де, бағдарламаның не істейтінін бірден түсінеді.

    Дегенмен мұны да жақсартуға болады. Қараңызшы: циклден break арқылы шығамыз да, бірден return x жасаймыз. Екі қадам. Ал оны біреуіне айналдыруға бола ма?

    def main():
    x = get_int()
    print(f"x is {x}")


def get_int():
    while True:
        try:
            x = int(input("What's x?"))
        except ValueError:
            print("x is not an integer")
        else:
            return x


main()

    Болады! return тек мәнді қайтарып қана қоймайды, ол функциядан толығымен шығады, демек ішіндегі циклді де бірге үзеді. Сондықтан бұл жерде break керек емес: return екеуінің жұмысын бір өзі атқарады.

    Кейбіреулер тіпті одан әрі барып, былай жазуға болады дер еді:

    def main():
    x = get_int()
    print(f"x is {x}")


def get_int():
    while True:
        try:
            return int(input("What's x?"))
        except ValueError:
            print("x is not an integer")


main()
    Ойланып көріңіз: бұл нұсқа алдыңғысынан өзгеше жұмыс істей ме?

    Жоқ, дәл солай жұмыс істейді. int сәтті болса, return мәнді бірден қайтарып, функциядан шығады. Сәтсіз болса, return-ге жетпей-ақ ValueError лақтырылады, except хабар шығарады да, цикл жаңа айналымға кетеді. Айырмашылығы - жолдар саны азырақ, бар болғаны сол.

    Бұл нұсқа алдыңғысымен бірдей нәтиже береді, тек қысқарақ. Қайсысы жақсы? 0-аптадағы әңгімені еске алайық: маңыздысы - оқылуы. Екі нұсқа да түсінікті, сондықтан өзіңізге қайсысы айқынырақ көрінсе, соны таңдаңыз.

    pass

    Кейде қолданушыға «сан емес» деп әр жолы ескертудің қажеті жоқ, жай ғана сұрақты қайталасақ жеткілікті. Бірақ Python-да except-тің ішін бос қалдыруға болмайды: шегіністен кейін кемінде бір жол тұруы керек. Сол үшін арнайы pass кілт сөзі бар. Ол «ештеңе істеме» дегенді білдіреді, яғни грамматика үшін тұрған бос «толтырғыш»:

    def main():
    x = get_int()
    print(f"x is {x}")


def get_int():
    while True:
        try:
            return int(input("What's x?"))
        except ValueError:
            pass


main()

    Код бұрынғыдай жұмыс істейді, тек қолданушыға қатесі туралы қайта-қайта айтпайды: «cat» деп жазса, бағдарлама үнсіз ғана сұрақты қайталайды. Қай тәсіл дұрыс? Бұл жағдайға байланысты. Кейде қолданушыға не дұрыс болмағанын анық түсіндірген маңызды, ал кейде сұрақты қайта қою жеткілікті. Таңдау - бағдарламашы ретінде сіздің шешіміңіз.

    Ал енді соңғы бір жетілдіру. get_int функциясына тағы бір қарасаңыз, ішінде "What's x?" сұрағы қатаң жазылған (hard-coded) тұр. Яғни бұл функция тек x-ті сұрай алады. Ертең бізге y керек болса ше? Әр жолы жаңа функция жазамыз ба? Әрине, жоқ. Сұрақ мәтінін функцияға сырттан, параметр арқылы берейік:

    def main():
    x = get_int("What's x? ")
    print(f"x is {x}")


def get_int(prompt):
    while True:
        try:
            return int(input(prompt))
        except ValueError:
            pass


main()

    Енді get_int - нағыз әмбебап құрал: get_int("What's y? ") немесе get_int("Жасыңыз: ") деп кез келген сұрақпен шақыра аласыз. Сұрақтың соңына бос орын қосқанымызды да байқадыңыз ба? Әлгі жауаптың сұраққа жабысып тұратын кішкентай мәселесі де осымен шешілді:

    $ python number.py
What's x? cat
What's x? dog
What's x? 50
x is 50

    pass туралы толығырақ: Python құжаттамасындағы pass.

    Кеңес: try-ға неғұрлым аз код

    try блогына тек қате беруі мүмкін жолдарды ғана жазыңыз және except-ке нақты қай ерекше жағдайды күтетініңізді көрсетіңіз (except ValueError:). Сонда басқа, күтпеген қате пайда болса, ол үнсіз жұтылып кетпейді, сіз оны бірден көресіз.

    Қорытынды

    Қателер - бағдарламалаудың ажырамас бөлігі, олардан толық құтылу мүмкін емес. Бірақ бүгін үйренгеніңіздің арқасында оларды алдын ала болжап, бағдарламаңызды құлатпай, дұрыс өңдей аласыз. Бұл лекцияда біз мыналармен таныстық:

    • ерекше жағдайлар (exceptions) - бағдарлама жұмыс істеп тұрғанда туындайтын мәселелер;
    • синтаксистік қателер (SyntaxError) - оларды өзіміз түзетеміз;
    • орындалу кезіндегі қателер, соның ішінде ValueError және NameError;
    • try және except - қате беруі мүмкін кодты «байқап көру» және ерекше жағдайды ұстау;
    • else - қате болмаған жағдайда ғана орындалатын блок;
    • while True мен break (немесе return) арқылы қолданушыдан қайта сұрау;
    • бүтін сан алуды get_int(prompt) функциясына абстракциялау;
    • pass - «ештеңе істеме» дейтін кілт сөз.

    Өзіңізді тексеріңіз

    1. Қолданушы x = int(input("What's x? ")) жолына cat деп жауап берсе, қай ерекше жағдай туындайды?

    int «cat» мәтінін санға айналдыра алмайды, сондықтан ValueError лақтырады. Код грамматикалық тұрғыдан дұрыс, бұл орындалу кезіндегі қате.

    2. Мына бағдарламаға cat енгізілсе, не болады?

    try:
    x = int(input("What's x? "))
except ValueError:
    print("x is not an integer")

print(f"x is {x}")

    int қате бергендіктен, x-ке ешқашан мән меншіктелмейді. except хабарды шығарады, бірақ соңғы print анықталмаған x-ті таба алмай, NameError береді.

    3. try / except / else құрылымында else блогы қашан орындалады?

    else тек try сәтті аяқталғанда орындалады. Қате болса, except орындалып, else өткізіп жіберіледі.

    4. Қолданушы кезекпен cat, dog, 50 енгізеді. x is not an integer неше рет шығады?

    while True:
    try:
        x = int(input("What's x? "))
    except ValueError:
        print("x is not an integer")
    else:
        break

print(f"x is {x}")

    «cat» пен «dog» - екі қате, әрқайсысынан кейін хабар шығады. «50» сәтті болып, else ішіндегі break циклді тоқтатады да, x is 50 шығады.

    5. except ValueError: астындағы pass не істейді?

    pass - бос толтырғыш. Ерекше жағдай ұсталады, бірақ ешқандай хабар шықпайды; циклдің ішінде болса, сұрақ жай ғана қайталанады.

    6. get_int ішінде while True: циклінің ішіндегі return int(input(prompt)) сәтті орындалса, не болады?

    return функцияны толығымен аяқтайды, сондықтан ішіндегі цикл де бірге үзіледі. break қажет емес.

    7. Файлдың бірінші жолы print("hi"), ал екінші жолы print("hello, world) (тырнақша жабылмаған). Іске қоссақ, не болады?

    Python кодты орындамас бұрын бүкіл файлдың грамматикасын тексереді. Синтаксистік қате болса, бірде-бір жол орындалмайды. Сол себепті оны try арқылы ұстай алмаймыз, өзіміз түзетеміз.

    8. Мына мәндердің қайсысын int(...)-ке берсек, ValueError шығады?

    int бүтін санды білдіретін жолды ғана қабылдайды: теріс таңба мен шеттегі бос орындар рұқсат, ал ондық нүкте жоқ. "1.5" - ValueError. Бұл Fuel Gauge тапсырмасында керек болады!

Компьютерде жұмыс істесеңіз, cs50.dev-те әр тапсырма үшін бөлек папка ашып (мысалы, mkdir fuel, cd fuel, code fuel.py), ресми check50 командасын да қолданыңыз.

    Орташа

    Fuel Gauge (Жанармай көрсеткіші)

    Жанармай көрсеткіштері бакта қанша жанармай қалғанын көбіне бөлшекпен көрсетеді. Мысалы, 1/4 бактың 25%-ы, 1/2 - 50%-ы, ал 3/4 - 75%-ы толы екенін білдіреді.

    fuel.py файлында қолданушыдан X/Y пішіміндегі бөлшекті сұрайтын бағдарлама жазыңыз, мұндағы X - теріс емес бүтін сан, ал Y - оң бүтін сан. Сосын бакта қанша жанармай барын ең жақын бүтін санға дөңгелектелген пайызбен шығарыңыз (мысалы, 75%). Бірақ 1% не одан аз қалса, бактың іс жүзінде бос екенін білдіру үшін оның орнына E шығарыңыз. Ал 99% не одан көп болса, толы екенін білдіріп, F шығарыңыз.

    Егер X немесе Y бүтін сан болмаса, X Y-тен үлкен болса, немесе Y нөлге тең болса, қолданушыдан қайта сұраңыз. (Y міндетті түрде 4 болуы шарт емес.) ValueError немесе ZeroDivisionError сияқты ерекше жағдайларды міндетті түрде ұстаңыз.

    Өзіңізді тексеріңіз: 1/3 енгізілсе, не шығады?

    Кеңес

    Жолдардың көп әдісі бар, соның ішінде split: "3/4".split("/") → ["3", "4"]. Екі ерекше жағдайды бөлек ұстауға болады:

    try:
    ...
except ValueError:
    ...
except ZeroDivisionError:
    ...

    Немесе екеуін бірге:

    try:
    ...
except (ValueError, ZeroDivisionError):
    ...

    Есіңізде болсын: int("-3") қате бермейді, сондықтан теріс сандарды өзіңіз тексеруіңіз керек. Ал int("1.5") мен int("three") ValueError береді.

    Тексеру
    • 3/4 → 75%, 1/4 → 25%
    • 4/4 → F, 0/4 → E
    • 4/0, three/four, 1.5/3, -3/4, 5/4 → қайта сұрайды
    • check50 cs50/problems/2022/python/fuel өтеді.

    Орташа

    Felipe’s Taqueria (Фелипенің такериясы)

    Гарвард алаңындағы (Harvard Square) ең танымал тамақтанатын орындардың бірі - мексикалық Felipe’s Taqueria. Оның мәзірі төмендегі dict-те берілген, әр кілттің мәні - доллармен бағасы:

    {
    "Baja Taco": 4.25,
    "Burrito": 7.50,
    "Bowl": 8.50,
    "Nachos": 11.00,
    "Quesadilla": 8.50,
    "Super Burrito": 8.50,
    "Super Quesadilla": 9.50,
    "Taco": 3.00,
    "Tortilla Salad": 8.00
}

    taqueria.py файлында қолданушыға тапсырыс беруге мүмкіндік беретін бағдарлама жазыңыз: ол қолданушы control-d баспайынша (бұл бағдарламаға енгізуді аяқтаудың кең тараған тәсілі) тағамдарды бір жолдан бір-бірлеп сұрай береді. Әр енгізілген тағамнан кейін осы уақытқа дейінгі барлық тағамның жалпы құнын доллар белгісімен ($) және екі ондық таңбаға дейін пішімдеп шығарыңыз, мысалы Total: $6.00. Қолданушы енгізгенін регистрді ескермей өңдеңіз. Мәзірде жоқ кез келген енгізуді елемеңіз. Мәзірдегі әр тағам атауы title регистрінде (әр сөз бас әріппен) жазылған деп есептеңіз.

    Өзіңізді тексеріңіз: Baja Taco, сосын Tortilla Salad енгізілсе, соңғы жол қандай болады?

    Кеңес

    Қолданушы control-d басқанын EOFError ұстау арқылы білуге болады:

    try:
    item = input()
except EOFError:
    ...

    control-d басқанда Enter басу керек емес, сондықтан курсор сіздің сұрағыңыз тұрған жолда қалып қоюы мүмкін. Курсорды жаңа жолға көшіру үшін \n-ді өзіңіз шығарыңыз (мысалы, бос print()). Сөздіктің әдістері бар, соның ішінде get; сондай-ақ d[key] және if key in d: жазуларын қолдана аласыз. KeyError-дан сақтаныңыз немесе оны ұстаңыз.

    Тексеру
    • Taco, Taco → Total: $6.00, сосын control-d-ға дейін сұрай береді
    • Baja Taco, Tortilla Salad → Total: $12.25
    • Burger → елемей, қайта сұрайды; кіші/бас әріппен жазылған тағамдар да танылады
    • check50 cs50/problems/2022/python/taqueria өтеді.

    Оңай

    Grocery List (Азық-түлік тізімі)

    Дүкенге барар алдында не сатып алу керегін тізіп жазатын әдетіңіз бар делік.

    grocery.py файлында қолданушы control-d баспайынша тауарларды бір жолдан бір-бірлеп сұрайтын бағдарлама жазыңыз. Сосын қолданушының сатып алу тізімін бас әріптермен, тауар атауы бойынша әліпби ретімен сұрыптап шығарыңыз, әр жолдың басына сол тауардың неше рет енгізілгенін жазыңыз. Атауларды көпше түрге қоюдың қажеті жоқ. Қолданушы енгізгенін регистрді ескермей өңдеңіз (milk пен MILK - бір тауар).

    Мысалы, tortilla, sweet potato енгізіп, control-d басса, бағдарлама мынаны шығарады:

    1 SWEET POTATO
1 TORTILLA
    Кеңес

    control-d-ны EOFError ұстау арқылы анықтаңыз (Taqueria-дағыдай). Тізімді dict ретінде сақтаған ыңғайлы: кілт - тауар, мән - саны. Сөздіктің get әдісі мен if key in d: жазуы KeyError-дан сақтайды. Сөздікті sorted-ке берсеңіз, оның кілттері әліпби бойынша сұрыпталады.

    Тексеру
    • mango, strawberry, control-d → 1 MANGO, 1 STRAWBERRY
    • milk, milk, control-d → 2 MILK
    • tortilla, sweet potato, control-d → 1 SWEET POTATO, 1 TORTILLA

    Қиын

    Outdated (Ескі пішім)

    АҚШ-та күндер әдетте ай-күн-жыл ретімен (MM/DD/YYYY) жазылады. Мұны «ортадан басталатын» (middle-endian) рет дейді және оны сәтсіз дизайн деуге әбден болады. Мұндай күндерді оңай сұрыптау мүмкін емес, себебі жыл басында емес, соңында тұр: кез келген бағдарламада (мысалы, кестеде) 2/2/1800, 3/3/1900 және 1/1/2000-ды хронологиялық ретпен сұрыптап көріңізші. Оның үстіне, бұл пішім екіұшты: Гарвард 1636 жылы 8 қыркүйекте құрылған, бірақ 9/8/1636-ны 1636 жылғы 9 тамыз деп те оқуға болады!

    Бақытымызға орай, компьютерлер көбіне ISO 8601 халықаралық стандартын қолданады. Ол елге қарамастан күнді жыл-ай-күн (YYYY-MM-DD) ретімен жазуды талап етеді: жыл төрт цифрмен, ай екі цифрмен, күн екі цифрмен, қажет болса алдына нөл қосылады.

    outdated.py файлында қолданушыдан жаңа эрамыздағы күнді ай-күн-жыл ретімен сұрайтын бағдарлама жазыңыз. Күн 9/8/1636 немесе September 8, 1636 пішімінде беріледі, екінші пішімдегі ай атауы төмендегі list-тің кез келгені болуы мүмкін:

    [
    "January",
    "February",
    "March",
    "April",
    "May",
    "June",
    "July",
    "August",
    "September",
    "October",
    "November",
    "December"
]

    Сосын сол күнді YYYY-MM-DD пішімінде шығарыңыз. Егер енгізілген мән екі пішімнің ешқайсысында жарамды күн болмаса, қолданушыдан қайта сұраңыз. Әр айда 31-ден аспайтын күн бар деп есептеңіз: айдың 28, 29, 30 не 31 күндік екенін тексерудің қажеті жоқ.

    Өзіңізді тексеріңіз: October 9, 1701 енгізілсе, не шығады?

    Кеңес

    Жолдың split әдісі мен тізімнің index әдісін еске алыңыз: months.index("September") → 8 (санау нөлден басталады!). Бүтін санның алдына нөл қосу үшін f-жолды қолданыңыз: print(f"{n:02}") - n бір цифрлы болса, алдына бір 0 қосылады. Тексерушілер 23/6/1912 (23-ай жоқ), December 80, 1980 (80-күн жоқ) және үтірсіз September 8 1636 сияқты кірістерде қайта сұрауды күтеді.

    Тексеру
    • 9/8/1636 → 1636-09-08
    • September 8, 1636 → 1636-09-08
    • 23/6/1912 және December 80, 1980 → қайта сұрайды
    • check50 cs50/problems/2022/python/outdated өтеді.
