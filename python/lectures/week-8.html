    8-апта

    Объектіге бағытталған бағдарламалау

    Бағдарламалаудың жаңа тәсілімен танысамыз: өз деректер типімізді, яғни класты ойлап тауып, оған әдістер мен қасиеттер береміз. Сосын класс әдістерін, мұрагерлікті және операторларды қайта жүктеуді үйренеміз.

    ▶ Түпнұсқа бейнежазба мен материалдар (ағылшынша)

    Бұл бет сөзбе-сөз аударма емес. Лектор аудиторияда қалай түсіндірсе, біз де солай баяндаймыз: мағынасы мен кодтың бәрі түпнұсқадағыдай, тек әңгіме ана тілімізде жүреді.

    Объектіге бағытталған бағдарламалау

    Бағдарлама жазудың бір ғана жолы жоқ. Есепті шешудің әртүрлі көзқарастары, «мектептері» бар, оларды парадигмалар (paradigms) деп атайды. Басқа тілдерді үйренген сайын, сіз оларды бірден тани бастайсыз. Осы уақытқа дейін біз процедуралық (procedural) тәсілмен жұмыс істедік: бағдарлама жоғарыдан төменге қарай, қадам-қадаммен орындалады, ал кодты функцияларға бөлеміз. Бүгін бағдарламалаудағы көп мәселенің әдемі шешімі болып табылатын тағы бір парадигмамен танысамыз: объектіге бағытталған бағдарламалау (object-oriented programming, OOP).

    Қарапайымнан бастайық. Терминалға code student.py деп жазып, Хогвартс студенті туралы мәлімет сұрайтын бағдарлама жазамыз:

    name = input("Name: ")
house = input("House: ")
print(f"{name} from {house}")

    Бұл - таза процедуралық код: атын сұрадық, үйін (Хогвартстағы факультетін) сұрадық, шығардық. Курстың алдыңғы бөліктерінде дәл осылай жазып келдік. Ал өткен апталардағы тәжірибемізге сүйеніп, кодтың кейбір бөліктерін функцияларға шығарып, абстракциялауға (abstract away) болады:

    def main():
    name = get_name()
    house = get_house()
    print(f"{name} from {house}")


def get_name():
    return input("Name: ")


def get_house():
    return input("House: ")


if __name__ == "__main__":
    main()

    Енді main атты қалай, үйді қалай алатынымен әуре болмайды, бұл жұмысты get_name мен get_house атқарады. Ал соңғы екі жол, бұрыннан таныс, интерпретаторға «файл тікелей іске қосылса, main-ді шақыр» дейді.

    Кортеждер

    Бірақ ойланып қараңызшы: аты мен үйі - бір студенттің екі сипаты ғой. Оларды неге екі бөлек функция арқылы аламыз? Бір функция екеуін бірге қайтарса, қисындырақ болар еді. Python-да бұған кортеж (tuple) көмектеседі. Кортеж - мәндер тізбегі, тізімге ұқсас, бірақ бір үлкен айырмашылығы бар: оны өзгертуге болмайды. Мына кодта, мағынасы жағынан, біз екі мәнді бірге қайтарып тұрмыз:

    def main():
    name, house = get_student()
    print(f"{name} from {house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return name, house


if __name__ == "__main__":
    main()

    get_student соңындағы return name, house жолына қараңыз. Үтір арқылы жазылған екі мән Python үшін бір кортеж. Ал main-де оны name, house = ... деп бірден екі айнымалыға «тарқатып» алдық.

    Тарқатпай, кортежді бүтіндей бір айнымалыға, мысалы, student-ке «буып-түйіп» сақтауға да болады:

    def main():
    student = get_student()
    print(f"{student[0]} from {student[1]}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return (name, house)


if __name__ == "__main__":
    main()

    Бұл жолы return (name, house) деп жақшамен жаздық. Python үшін айырмашылық жоқ, бірақ кодты оқитын адамға «мен бір мәннің ішінде екі мән қайтарып тұрмын» деп анық көрсетеді. Ал кортеждің ішіндегі мәндерге тізімдегідей, индекс арқылы жетеміз: student[0] - аты, student[1] - үйі.

    Кортеж өзгермейтін (immutable) деп айттық. Бұл не береді? Бұл - қорғаныс бағдарламалауының (defensive programming) бір тәсілі: мән өзгермейтін болса, оны біреу байқамай бұзып алмайды. Тексеріп көрейік. Айталық, Падма деген студент қай үйді жазса да, біз оны Рейвенкло деп түзеткіміз келеді:

    def main():
    student = get_student()
    if student[0] == "Padma":
        student[1] = "Ravenclaw"
    print(f"{student[0]} from {student[1]}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return name, house


if __name__ == "__main__":
    main()
    Ойланып көріңіз: «Padma» мен «Gryffindor» енгізсек, не болады?

    Бағдарлама құлайды! Кортежді өзгертуге болмайды, сондықтан student[1] = "Ravenclaw" жолында Python қате береді:

    TypeError: 'tuple' object does not support item assignment

    Яғни «кортеж объектісі элементті қайта меншіктеуге рұқсат бермейді».

    Тізімдер: өзгертуге болатын нұсқа

    Ал әріптестерімізге осындай икемділік бергіміз келсе ше? Онда кортеждің орнына тізімді (list) қайтарамыз. Бар болғаны жақшаның түрін ауыстырамыз: [name, house]:

    def main():
    student = get_student()
    if student[0] == "Padma":
        student[1] = "Ravenclaw"
    print(f"{student[0]} from {student[1]}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return [name, house]


if __name__ == "__main__":
    main()

    Енді бәрі жұмыс істейді: Падма Рейвенклоға түседі. Себебі тізім өзгермелі (mutable): оның ішіндегі name мен house мәндерін бағдарламашы өзгерте алады. Кейде бұл дәл керек нәрсе. Бірақ есте сақтаңыз: икемділік үшін қауіпсіздіктің бір бөлігін құрбан етесіз. Мәндер өзгере алатын болса, сізбен бірге жұмыс істейтін бағдарламашылар кейін байқамай қате жіберуі мүмкін.

    Сөздіктер

    Тағы бір нұсқа - сөздік (dictionary, dict). Есіңізде болса, сөздік «кілт - мән» жұптарын сақтайды. student[0] дегеннен гөрі student["name"] әлдеқайда түсінікті емес пе?

    def main():
    student = get_student()
    print(f"{student['name']} from {student['house']}")


def get_student():
    student = {}
    student["name"] = input("Name: ")
    student["house"] = input("House: ")
    return student


if __name__ == "__main__":
    main()

    Мұнда get_student екі «кілт - мән» жұбы бар сөздік қайтарады. Ұтысы - енді мәндерге нөмір арқылы емес, кілттің аты арқылы жетеміз. f-жолдың ішінде кілттерді жалқы тырнақшаға ('name') алғанымызға назар аударыңыз: сыртқы тырнақша қос болғандықтан, ішінде басқа түрін қолдандық.

    Кодты сәл жинақтауға болады. student = {} деп бос сөздік жасап, оны бірте-бірте толтырудың қажеті жоқ, артық айнымалыдан құтыламыз:

    def main():
    student = get_student()
    print(f"{student['name']} from {student['house']}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return {"name": name, "house": house}


if __name__ == "__main__":
    main()

    return жолындағы фигуралы жақшалар сөздікті сол жерде жасап, бірден қайтарады. Ал Падманың ерекше жағдайын сөздік нұсқасына да қайтара аламыз, бұл жолы кілттің аты арқылы:

    def main():
    student = get_student()
    if student["name"] == "Padma":
        student["house"] = "Ravenclaw"
    print(f"{student['name']} from {student['house']}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return {"name": name, "house": house}


if __name__ == "__main__":
    main()

    Сөздік те өзгермелі, сондықтан бұл код жұмыс істейді. Сонымен, бір студентті сақтаудың үш жолын көрдік: кортеж, тізім, сөздік. Бірақ үшеуі де Python-ның дайын типтері. Ал «студент» деген өз типімізді жасай алсақ ше?

    Кластар

    Міне, объектіге бағытталған бағдарламалаудың өзегіне келдік. Класс (class) - өз деректер типімізді ойлап тауып, оған ат беру тәсілі. Оны сызба немесе қалып сияқты елестетіңіз: үй салар алдында сәулетші сызба жасайды, сол бір сызбамен ондаған үй салуға болады. Немесе бауырсақ кесетін қалыпты алайық: қалып біреу, ал ол арқылы кесілген бауырсақ көп. Класс - сол қалып.

    Өз Student класымызды жасайық:

    class Student:
    ...


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")


def get_student():
    student = Student()
    student.name = input("Name: ")
    student.house = input("House: ")
    return student


if __name__ == "__main__":
    main()

    Бірнеше нәрсеге назар аударайық. Біріншіден, келісім бойынша класс аты бас әріппен жазылады: Student. Екіншіден, ... (көп нүкте) «бұл бөлікке кейін ораламыз» дегенді білдіреді, әзірге класс бос. Үшіншіден, get_student ішінде student = Student() деп Student класының жаңа студентін жасадық. Төртіншіден, оның ішіндегі мәндерге нүкте арқылы (dot notation) жетеміз: student.name, student.house. Объектінің ішіндегі мұндай мәндерді атрибуттар (attributes) дейді.

    Класты, яғни сызбаны алып, сол арқылы нақты бірдеңе жасаған сайын, сіз объект (object) немесе дана (instance) жасайсыз. Біздің кодта student - объект. Сызба мен үйдің айырмашылығы сияқты: Student - сызба, ал student - сол сызбамен салынған нақты бір үй.

    __init__ және self

    Қазіргі класымыздың бір кемшілігі бар: студентте қандай атрибуттар болуы керек екені ешқайда жазылмаған. Біреу student.name орнына student.nmae деп қате жазса, Python үнсіз жаңа атрибут жасай салады. Класс ішінде атрибуттарды стандарттап, «әр студенттің аты мен үйі болады» деп алдын ала белгілеп қояйық:

    class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    student = Student(name, house)
    return student


if __name__ == "__main__":
    main()

    Класс ішінде __init__ деген функция пайда болды. Класқа тиесілі функцияларды әдістер (methods) деп атайды, олар осы кластың объектілері қалай әрекет ететінін анықтайды. Ал __init__ - ерекше әдіс: ол жаңа объект жасалған сәтте өздігінен шақырылып, оны «баптайды». Атауындағы екі жақты қос астын сызу (__) - Python-ның арнайы әдістерінің белгісі.

    student = Student(name, house) жолына қараңыз. Класс атын функция сияқты шақыру - конструктор (constructor): Python жаңа бос объект жасайды да, __init__-ті шақырып, оған біздің name мен house-ты береді. Ал __init__ ішінде оларды объектіге атрибут ретінде жазып қояды.

    Сонда self деген не? Ол дәл қазір жасалып жатқан объектінің өзін білдіреді. self.name = name дегенді «осы студенттің аты - маған берілген name» деп оқыңыз. Python self-ті бірінші аргумент ретінде өзі береді, сондықтан шақырғанда біз оны жазбаймыз: Student(name, house), екі-ақ аргумент.

    Кодты тағы ықшамдауға болады. Объектіні айнымалыға сақтап, келесі жолда қайтарудың орнына, бірден қайтарамыз:

    class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()

    return Student(name, house) алдыңғы нұсқадағы екі жолдың жұмысын бір жолда істейді. Толығырақ: Python құжаттамасындағы кластар бөлімі.

    raise

    Объектіге бағытталған бағдарламалау бір нәрсені ұсынады: кластың бар мүмкіндігін класс ішінде жинақтау, яғни инкапсуляция (encapsulation). Студент туралы бәрін Student класы білсін. Ал бірдеңе дұрыс болмаса ше? Біреу кездейсоқ бірдеңе жазса? Атсыз студент жасамақ болса? Мұны да класс өзі тексергені жөн:

    class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Missing name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.name = name
        self.house = house


def main():
    student = get_student()
    print(f"{student.name} from {student.house}")


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()

    Енді __init__ алдымен аттың бос емес екенін, сосын үйдің Хогвартстың төрт үйінің бірі екенін тексереді. Бірдеңе дұрыс болмаса, не істейміз? Осы уақытқа дейін біз Python шығарған ерекше жағдайларды (exceptions) try және except арқылы ұстап келдік. Ал енді рөлдер ауысты: ерекше жағдайды біз өзіміз көтереміз (raise). raise ValueError("Missing name") дегені - «бұл мән жарамсыз» деп дабыл қағу, қасына нақты түсіндірме жазып. Бұл қолданушы тудырған ықтимал қате туралы бағдарламашыға ескерту береді, ал ол бағдарламашы қаласа, оны try арқылы ұстай алады.

    Әдейі жарамсыз үй енгізіп көрейік:

    $ python student.py
Name: Harry
House: Number Four, Privet Drive
Traceback (most recent call last):
  ...
ValueError: Invalid house

    Класс өзін өзі қорғады: жарамсыз студент жасалмай қалды.

    __str__: объектіні шығару

    main-де әлі де f"{student.name} from {student.house}" деп жазып жүрміз. Ал студентті қалай шығару керегін де класс өзі білсе, ыңғайлы емес пе? Python бұған арнайы әдіс ұсынады: __str__. Оны көрсету үшін студентке тағы бір атрибут, патронусты қосайық:

    class Student:
    def __init__(self, name, house, patronus):
        if not name:
            raise ValueError("Missing name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.name = name
        self.house = house
        self.patronus = patronus

    def __str__(self):
        return f"{self.name} from {self.house}"


def main():
    student = get_student()
    print(student)


def get_student():
    name = input("Name: ")
    house = input("House: ")
    patronus = input("Patronus: ")
    return Student(name, house, patronus)


if __name__ == "__main__":
    main()

    main қаншалықты қысқарғанын байқадыңыз ба? Енді жай print(student) деп жазамыз. Объектіні шығару немесе жолға айналдыру керек болғанда, Python def __str__(self) әдісін өзі шақырады да, ол қайтарған жолды көрсетеді. Яғни бағдарламашы ретінде объектінің өзін, оның атрибуттарын, тіпті онымен байланысты кез келген нәрсені қалағаныңызша шығара аласыз.

    Ойланып көріңіз: __str__ әдісін алып тастасақ, print(student) не шығарады?

    Python объектіні қалай көрсетерін білмей, <__main__.Student object at 0x7f...> сияқты бір нәрсе шығарады: «бұл - Student объектісі, жадтың пәленбай мекенжайында тұр». Дұрыс, бірақ адамға пайдасы шамалы. __str__ дәл осы үшін керек.

    Өз әдістерімізді жазу

    __str__ - Python кластарымен бірге келетін дайын әдістердің бірі. Бірақ біз класқа өз әдістерімізді де қоса аламыз! Патронус шақыратын charm («сиқыр») әдісін жазайық:

    class Student:
    def __init__(self, name, house, patronus=None):
        if not name:
            raise ValueError("Missing name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        if patronus and patronus not in ["Stag", "Otter", "Jack Russell terrier"]:
            raise ValueError("Invalid patronus")
        self.name = name
        self.house = house
        self.patronus = patronus

    def __str__(self):
        return f"{self.name} from {self.house}"

    def charm(self):
        match self.patronus:
            case "Stag":
                return "🐴"
            case "Otter":
                return "🦦"
            case "Jack Russell terrier":
                return "🐶"
            case _:
                return "🪄"


def main():
    student = get_student()
    print("Expecto Patronum!")
    print(student.charm())


def get_student():
    name = input("Name: ")
    house = input("House: ")
    patronus = input("Patronus: ") or None
    return Student(name, house, patronus)


if __name__ == "__main__":
    main()

    Мұнда біраз жаңалық бар. Біріншіден, patronus=None: патронус енді міндетті емес, әдепкі мәні - None, яғни «ештеңе жоқ». Сол себепті тексеру де if patronus and ... деп басталады: патронус берілген болса ғана оның тізімде бар-жоғын тексереміз. get_student-тегі input("Patronus: ") or None да осыған қызмет етеді: қолданушы ештеңе жазбай Enter басса, бос жолдың орнына None алынады.

    Екіншіден, charm әдісі. Ол match арқылы патронусқа қарап, сәйкес эмодзиді қайтарады: бұғы (Stag) үшін 🐴, кәмшат (Otter) үшін 🦦, Джек-Рассел терьер үшін 🐶, ал басқа жағдайда (case _) жай сиқыр таяқшасы 🪄. Сөздіктерден айырмашылығы осы: класта тек деректер емес, сол деректермен жұмыс істейтін функциялар, яғни әдістер де болады. Сондай-ақ Python-ның эмодзилерді кодта тікелей қолдана алатынын байқаған боларсыз.

    Әрі қарай жүрмес бұрын, патронусқа қатысты кодты алып тастайық. Бірақ main-ге бір бұзақы жол қосамыз:

    class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Invalid name")
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"


def main():
    student = get_student()
    student.house = "Number Four, Privet Drive"
    print(student)


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()

    Класта енді тек екі әдіс қалды: __init__ және __str__. Ал main-дегі student.house = "Number Four, Privet Drive" жолына қараңыз.

    Ойланып көріңіз: «Harry» мен «Gryffindor» енгізсек, не шығады?

    Harry from Number Four, Privet Drive шығады! Біз __init__-те үйді мұқият тексердік, бірақ ол тек объект жасалған сәтте ғана жұмыс істейді. Кейін атрибутты кез келген адам нүкте арқылы еркін өзгерте алады, ал тексеріс айналып өтіліп кетеді. Мұны қалай жабамыз? Келесі бөлім осы туралы.

    Декораторлар және қасиеттер

    Кодымызды «қатайту» үшін қасиеттерді (properties) қолданамыз. Python-да қасиет функцияның үстіне жазылатын декоратор (decorator) арқылы анықталады. Декоратор @ белгісінен басталады және астындағы функцияға қосымша мағына береді:

    class Student:
    def __init__(self, name, house):
        if not name:
            raise ValueError("Invalid name")
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"

    # house үшін геттер
    @property
    def house(self):
        return self._house

    # house үшін сеттер
    @house.setter
    def house(self, house):
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self._house = house


def main():
    student = get_student()
    print(student)


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()

    Асықпай талдайық. house деген функцияның үстіне @property деп жаздық. Бұл house-ты кластың қасиеті етеді. Қасиет болғаннан кейін біз кластың бір атрибуты, _house, қалай оқылатынын және қалай жазылатынын өзіміз анықтай аламыз.

    Оқитын функция - геттер (getter): ол жай ғана _house-тың мәнін қайтарады. Қолданушы student.house деп жазғанда, ол шын мәнінде осы геттер арқылы _house-ты алады. Ал жазатын функция - сеттер (setter), ол @house.setter декораторымен белгіленген. Қасиетке мән меншіктелген сайын, мысалы, student.house = "Gryffindor" деп жазылғанда, Python осы сеттерді шақырады. Біздің сеттер мәнді тексереді: Хогвартс үйлерінің бірі болмаса, ValueError көтереді, әйтпесе мәнді _house-қа жазады.

    Тамаша жері: __init__ ішіндегі self.house = house жолы да енді тікелей атрибутқа емес, сеттер арқылы өтеді! Сондықтан үйді тексеруді __init__-тен алып тастадық, бұл жұмысты бір ғана жерде, сеттерде істейміз. Ал әлгі бұзақы student.house = "Number Four, Privet Drive" жолы енді ValueError береді.

    Неге house емес, _house?

    house - кластың қасиеті, яғни қолданушы атрибутқа мән жазуға тырысқанда іске қосылатын функциялар жұбы. Ал _house - мәннің өзі сақталатын атрибут. Сеттердің ішінде self.house = house деп жазсақ, сеттер өзін-өзі шексіз шақырар еді. Атаудың алдындағы астын сызу (_) басқа бағдарламашыларға: «бұған тікелей тиіспеңіз (және тимеген жөн!)» деген келісімді белгі. _house тек house сеттері арқылы жазылуы тиіс. Python оны күшпен тыйым салмайды, бұл - бағдарламашылар арасындағы сыйластық келісімі.

    Үйден бөлек, студенттің атын да дәл осылай қорғай аламыз:

    class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"

    # name үшін геттер
    @property
    def name(self):
        return self._name

    # name үшін сеттер
    @name.setter
    def name(self, name):
        if not name:
            raise ValueError("Invalid name")
        self._name = name

    @property
    def house(self):
        return self._house

    @house.setter
    def house(self, house):
        if house not in ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]:
            raise ValueError("Invalid house")
        self._house = house


def main():
    student = get_student()
    print(student)


def get_student():
    name = input("Name: ")
    house = input("House: ")
    return Student(name, house)


if __name__ == "__main__":
    main()

    Алдыңғы кодтағыдай, атқа да геттер мен сеттер жаздық. Енді __init__ мүлде таза: ешқандай тексеріс жоқ, бәрі сеттерлерде. Атты да, үйді де объект жасалғанда да, кейін де жарамсыз мәнге өзгерту мүмкін емес. Толығырақ: Python құжаттамасындағы әдістер туралы бөлім.

    Бұрынғы тақырыптармен байланыс

    Енді бір құпияны ашайын. Бұған дейін ашық айтпасақ та, сіз курстың басынан бері кластар мен объектілерді қолданып келдіңіз!

    int құжаттамасына үңілсеңіз, оның конструкторы бар класс екенін көресіз. Ол int типті объектілер жасауға арналған сызба. Жолдар да класс: str.lower() қолдансаңыз, str класымен бірге келген әдісті шақырдыңыз. list те класс, оның құжаттамасында list.append() сияқты әдістері тізілген. dict те Python ішіндегі класс.

    Өзіңіз көз жеткізу үшін терминалға code type.py деп жазып, мынаны іске қосыңыз:

    print(type(50))
    $ python type.py
<class 'int'>

    type функциясы мәннің класын айтады: 50-нің класы - int. Жолмен де солай:

    print(type("hello, world"))

    Бұл <class 'str'> шығарады. Бос тізімді тексерейік:

    print(type([]))

    Нәтиже - <class 'list'>. Тізімді төртбұрыш жақшамен емес, Python-ның дайын list класының атымен, конструктор арқылы да жасауға болады:

    print(type(list()))

    Бұл да <class 'list'>. Сөздікпен де дәл солай:

    print(type({}))

    Нәтиже - <class 'dict'>. Және Python-ның дайын dict класының атымен:

    print(type(dict()))

    Бұл да <class 'dict'> береді. Сонымен, Student() деп өз объектімізді жасағанымыз сияқты, list() мен dict() да кластың конструкторын шақырады. Python-дағы барлық дерлік нәрсе - объект.

    Класс әдістері

    Кейде функционалды кластың жеке даналарына емес, класстың өзіне қосқымыз келеді. Бұған @classmethod декораторы арналған, ол жасаған әдісті класс әдісі (class method) дейді. Алдымен класс әдісін қолданбаған мысалды көрейік. Терминалға code hat.py деп жазып, Хогвартстың Сұрыптаушы қалпағын жасаймыз:

    import random


class Hat:
    def __init__(self):
        self.houses = ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]

    def sort(self, name):
        print(name, "is in", random.choice(self.houses))


hat = Hat()
hat.sort("Harry")

    Қалпаққа студенттің атын берсек, ол оны кездейсоқ бір үйге жібереді, мысалы, Harry is in Hufflepuff. hat = Hat() жолы қалпақтың данасын жасайды, ал hat.sort("Harry") атты дәл осы hat данасының sort әдісіне береді. Яғни сұрыптауды әрдайым Hat класының нақты бір данасы орындайды.

    Бірақ ойланыңызшы: Сұрыптаушы қалпақ біреу ғана емес пе? Оның көшірмелерін жасаудың мәні жоқ. sort-ты ешқандай дана жасамай-ақ шақыра алсақ, жақсы болар еді:

    import random


class Hat:

    houses = ["Gryffindor", "Hufflepuff", "Ravenclaw", "Slytherin"]

    @classmethod
    def sort(cls, name):
        print(name, "is in", random.choice(cls.houses))


Hat.sort("Harry")

    Не өзгерді? __init__ әдісі жоғалды, себебі енді қалпақтың данасын ешқайда жасамаймыз. Үйлердің тізімі houses кластың ішіне, кез келген әдістің сыртына шықты, ол енді жеке данаға емес, бүкіл класқа тиесілі. Нақты дана болмағандықтан, self-тің де мағынасы жоқ, сондықтан sort-ты @classmethod деп белгілеп, self-тің орнына cls (класстың өзі) жаздық. Ең соңында Hat.sort("Harry") деп әдісті тікелей кластан шақырдық. Hat бас әріппен жазылғанына назар аударыңыз: бұл айнымалы емес, кластың аты.

    Енді student.py-ға оралайық. Онда да класс әдісін қолданатын жер жіберіліп қалған екен:

    class Student:
    def __init__(self, name, house):
        self.name = name
        self.house = house

    def __str__(self):
        return f"{self.name} from {self.house}"

    @classmethod
    def get(cls):
        name = input("Name: ")
        house = input("House: ")
        return cls(name, house)


def main():
    student = Student.get()
    print(student)


if __name__ == "__main__":
    main()

    get_student функциясы жоқ болды, оның орнына класс ішінде get деген класс әдісі пайда болды. Ойланып көрсеңіз, бұл қисынды: студентті қолданушыдан қалай сұрау керегін де Student класы білгені дұрыс, бәрі бір жерде. return cls(name, house) - Student(name, house) деумен бірдей, тек класс атын қайталамай, cls арқылы жаздық. Ең бастысы, бұл әдісті студент жасамай тұрып-ақ шақыра аламыз: Student.get(). Ол студентті өзі жасап қайтарады.

    Статикалық әдістер

    Сонымен, біз дана әдістері (self қабылдайтындар) мен класс әдістерінің (cls қабылдайтындар) айырмашылығын көрдік. Бұлардан басқа әдіс түрлері де бар. Солардың бірі - @staticmethod декораторы, яғни статикалық әдіс (static method). Ол не self, не cls қабылдамайды, жай ғана класс ішіне орналастырылған функция. Бұл курста біз оған арнайы тоқталмаймыз, бірақ қызығушылығыңыз болса, статикалық әдістер мен класс әдістерінің айырмашылығын өз бетіңізше зерттеп көруге шақырамыз.

    Мұрагерлік

    Енді, мүмкін, объектіге бағытталған бағдарламалаудың ең қуатты мүмкіндігіне келдік: мұрагерлік (inheritance). Бір класс басқа класстан оның әдістерін, айнымалылары мен атрибуттарын «мұраға» ала алады. Бала ата-анасынан көз түсін, мінезін алатыны сияқты. Терминалға code wizard.py деп жазыңыз:

    class Wizard:
    def __init__(self, name):
        if not name:
            raise ValueError("Missing name")
        self.name = name

    ...


class Student(Wizard):
    def __init__(self, name, house):
        super().__init__(name)
        self.house = house

    ...


class Professor(Wizard):
    def __init__(self, name, subject):
        super().__init__(name)
        self.subject = subject

    ...


wizard = Wizard("Albus")
student = Student("Harry", "Gryffindor")
professor = Professor("Severus", "Defense Against the Dark Arts")
...

    Мұнда үш класс бар: Wizard (сиқыршы), Student (студент) және Professor (профессор). Студенттің де, профессордың да аты бар. Және екеуі де сиқыршы. Сондықтан атпен жұмыс істейтін ортақ кодты екі жерге көшірмей, бір рет Wizard класына жаздық, ал Student пен Professor оны мұраға алады. Мұны class Student(Wizard): деген жақша айтады: «Student - Wizard-тың бір түрі».

    Бұл жағдайда Student - бала класс (child class, subclass), ал Wizard - ата-ана класс немесе суперкласс (parent class, superclass). Студенттің __init__-індегі super().__init__(name) жолы «ата-ана класымның __init__-ін шақыр» дегенді білдіреді. Сонда атты тексеріп, сақтау жұмысын Wizard атқарады, ал Student тек өзіне ғана тән нәрсені, үйді қосады. Professor да дәл солай, тек үйдің орнына пәнді (subject) сақтайды.

    Кодтың соңғы жолдары Альбус деген сиқыршыны, Гарри деген студентті және Северус деген профессорды жасайды. Ал атты тексеретін raise ValueError("Missing name") үшеуі үшін де бір жерде жазылған: оны өзгертсек, өзгеріс бірден барлық класқа тарайды.

    Ойланып көріңіз: Student("", "Gryffindor") деп жазсақ, не болады?

    ValueError: Missing name көтеріледі. Student-тің өз __init__-інде атты тексеретін ешқандай код жоқ, бірақ ол super().__init__(name) арқылы Wizard-тың тексерісін шақырады. Мұрагерліктің пайдасы осы: тексеріс бір жерде жазылып, барлық бала кластарға қызмет етеді.

    Мұрагерлік және ерекше жағдайлар

    Мұрагерлікті жаңа ғана таныстырдық, бірақ шын мәнінде сіз оны ерекше жағдайларды қолданған кезден бері пайдаланып келесіз. Ерекше жағдайлар иерархия, яғни шежіре сияқты құрылған: олардың балалары, ата-аналары, тіпті аталары бар. Міне, сол шежіренің бір бөлігі:

Сондықтан except ArithmeticError деп жазсаңыз, нөлге бөлу қатесі де ұсталады: бала класс ата-анасының бір түрі ғой. Біз raise етіп жүрген ValueError да осы шежіренің бір тармағы. Толығырақ: Python құжаттамасындағы ерекше жағдайлар.

    Операторларды қайта жүктеу

    Соңғы тақырып. + пен - сияқты кейбір операторларды қайта жүктеуге (operator overloading) болады, яғни оларға қарапайым арифметикадан тыс жаңа мүмкіндіктер беруге болады. Шын мәнінде, сіз мұны бұрын да көрдіңіз: сандар үшін + қосады, ал жолдар үшін біріктіреді. Енді өз класымыз үшін +-тің мағынасын өзіміз анықтайық.

    Гарри Поттер әлемінде ақша үш түрлі тиыннан тұрады: галлеон, сикль және кнат. Терминалға code vault.py деп жазып, Гринготтс банкіндегі сейфті (Vault) жасаймыз:

    class Vault:
    def __init__(self, galleons=0, sickles=0, knuts=0):
        self.galleons = galleons
        self.sickles = sickles
        self.knuts = knuts

    def __str__(self):
        return f"{self.galleons} Galleons, {self.sickles} Sickles, {self.knuts} Knuts"

    def __add__(self, other):
        galleons = self.galleons + other.galleons
        sickles = self.sickles + other.sickles
        knuts = self.knuts + other.knuts
        return Vault(galleons, sickles, knuts)


potter = Vault(100, 50, 25)
print(potter)

weasley = Vault(25, 50, 100)
print(weasley)

total = potter + weasley
print(total)
    $ python vault.py
100 Galleons, 50 Sickles, 25 Knuts
25 Galleons, 50 Sickles, 100 Knuts
125 Galleons, 100 Sickles, 125 Knuts

    __str__ әдісі бізге таныс: ол сейфтегі ақшаны әдемі пішімделген жол етіп қайтарады. Ал жаңасы - __add__. Python екі Vault арасында + көргенде, дәл осы әдісті шақырады. Ондағы self - +-тің сол жағындағы объект (potter), ал other - оң жағындағысы (weasley). Әдіс тиындарды түр-түрімен қосып, жаңа Vault қайтарады. Нәтижесінде potter + weasley деп, сандарды қосқандай-ақ, екі сейфті қоса аламыз. Поттерлер мен Уизлилер ақшаларын біріктірсе, осылай болар еді.

    Басқа операторлар да бар

    + үшін __add__ болса, - үшін __sub__, * үшін __mul__, == үшін __eq__ бар. Тізімі: Python құжаттамасындағы арнайы әдістер атаулары. Тапсырмалар жинағындағы Seasons of Love есебінде date класының __sub__-ын қолданасыз.

    Қорытынды

    Объектіге бағытталған бағдарламалау арқылы сіз мүлде жаңа деңгейдегі мүмкіндіктерге ие болдыңыз:

    • бағдарламалау парадигмалары: процедуралық тәсілден объектіге бағытталған бағдарламалауға;
    • кортеждер (өзгермейтін), тізімдер мен сөздіктер (өзгермелі);
    • кластар мен объектілер (даналар), атрибуттар, __init__, self және __str__;
    • raise арқылы өз ерекше жағдайларымызды көтеру;
    • декораторлар: @property, геттерлер мен сеттерлер;
    • класс әдістері (@classmethod, cls);
    • статикалық әдістер (@staticmethod);
    • мұрагерлік, super() және ерекше жағдайлар иерархиясы;
    • операторларды қайта жүктеу (__add__).

    Өзіңізді тексеріңіз

    1. student = ("Padma", "Gryffindor") болса, student[1] = "Ravenclaw" не істейді?

    Кортеж өзгермейтін (immutable), оның элементтеріне жаңа мән меншіктеуге болмайды. Өзгерту керек болса, тізім не сөздік қолданыңыз.

    2. Класс әдісінің ішіндегі self нені білдіреді?

    self - дәл осы объектінің өзі. self.name = name «осы объектінің аты» дегенді білдіреді, Python оны бірінші аргумент ретінде өзі береді.

    3. print(student) жазғанда Python объектіні қалай көрсетерін қай әдістен біледі?

    __str__ объектінің жолдық көрінісін қайтарады, print оны өзі шақырады.

    4. house қасиетінің сеттері бар класта student.house = "Number Four, Privet Drive" жазылса, не болады?

    Қасиетке мән меншіктелгенде @house.setter әдісі іске қосылады, ол жарамсыз үйді тексеріп, ValueError көтереді.

    5. @classmethod әдісінің бірінші параметрі әдетте қалай аталады және нені білдіреді?

    Класс әдісі данаға емес, класқа тиесілі. Сондықтан ол cls қабылдайды және Hat.sort("Harry") немесе Student.get() деп дана жасамай шақырылады.

    6. class Student(Wizard): ішіндегі super().__init__(name) не істейді?

    super() ата-ана класқа жетуге мүмкіндік береді. Атты тексеріп сақтау жұмысын Wizard атқарады.

    7. Vault класында potter + weasley жазғанда, __add__(self, other) ішінде other дегеніміз не?

    self - +-тің сол жағындағы объект, other - оң жағындағы.

    8. print(type(dict())) не шығарады?

    dict() - dict класының конструкторы, ол бос сөздік жасайды. type оның класын көрсетеді.

    Seasons of Love (Махаббат маусымдары)

    Five hundred twenty-five thousand, six hundred minutes
    Five hundred twenty-five thousand moments so dear
    Five hundred twenty-five thousand, six hundred minutes
    How do you measure, measure a year?

    - «Seasons of Love», Rent мюзиклі

    Бір жылда 365 күн бар десек, онда 365 × 24 × 60 = 525,600 минут бар (тәулікте 24 сағат, сағатта 60 минут). Ал екі не одан көп жылда қанша минут бар? Бұл олардың нешеуі 366 күндік кібісе жыл екеніне байланысты (Григориан күнтізбесі бойынша), өйткені кібісе жылда 1 × 24 × 60 = 1,440 минут артық. Сіз туғаннан бері қанша минут өтті? Бұл да арадағы кібісе жылдарға байланысты! Мұның алгоритмі бар, бірақ дөңгелекті қайта ойлап таппай-ақ, кітапхананы қолданайық. Python-да datetime модулі бар, оның date деген класы көмектеседі: docs.python.org/3/library/datetime.html#date-objects.

    seasons.py файлында қолданушыдан туған күнін YYYY-MM-DD пішімінде сұрап, оның неше минут жасағанын, ең жақын бүтінге дөңгелектеп, цифрмен емес, ағылшын сөздерімен (дәл Rent әніндегідей) шығаратын бағдарлама жазыңыз. Сөздердің арасында and болмауы керек. Қолданушы өзі туған уақытты білмеуі мүмкін, сондықтан ол сол күні түнгі сағат 00:00:00-де туған деп есептеңіз. Қазіргі уақыт та түн ортасы деп есептеңіз: бағдарлама түсте іске қосылса да, сол күннің түн ортасы деп алыңыз. Бүгінгі күнді алу үшін datetime.date.today қолданыңыз.

    Бағдарламаны төмендегідей құрылымдаңыз: main функциясынан бөлек, тағы бір не одан көп функция болсын:

    from datetime import date


def main():
    ...


...


if __name__ == "__main__":
    main()

    Басқа кірістірілген кітапханаларды немесе кеңестерде аталғандарын импорттауға болады. Қолданушы күнді YYYY-MM-DD пішімінде енгізбесе, sys.exit арқылы шығыңыз. Бағдарлама ешқандай ерекше жағдай көтермеуі керек.

    Сонымен қатар (seasons.py-тан бұрын не кейін) test_seasons.py файлында seasons.py-тағы main-нен басқа функцияларды мұқият тексеретін бір не одан көп функция жазыңыз. Олардың аты test_-тен басталсын, сонда тесттерді былай іске қосасыз:

    pytest test_seasons.py

    Мысал (демо 2000 жылғы 1 қаңтарда жазылған деп есептеңіз): бүгіннен бір жыл бұрынғы күнді енгізсеңіз, Five hundred twenty-five thousand, six hundred minutes шығуы керек (кібісе жыл болса, бір күн артық: Five hundred twenty-seven thousand forty minutes). Екі жыл бұрынғы күн үшін - One million, fifty-one thousand, two hundred minutes (кібісе жылда One million, fifty-two thousand, six hundred forty minutes). Жарамсыз пішімде енгізсеңіз, бағдарлама ерекше жағдайсыз, sys.exit арқылы шығуы керек.

    Кеңес

    date класының көп әдісі мен «қолдау көрсетілетін операциялары» бар. Атап айтқанда, класс __sub__-ты жүзеге асырады, яғни лекциядағы __add__ сияқты, - операторын қайта жүктейді: бір date объектісінен екіншісін алсаңыз, timedelta объектісі шығады, оның бірнеше (тек оқуға арналған) атрибуты бар. Күнді жолдан алу үшін date.fromisoformat қараңыз.

    Сандарды сөзбен жазу үшін inflect модулін қолданыңыз (оның number_to_words әдісі мен andword параметріне назар аударыңыз). Орнату:

    Cookie Jar (Печенье банкасы)

    Печенье сақтайтын банка жасағыңыз келеді делік. jar.py файлында келесі әдістері бар Jar класын жазыңыз:

    • __init__ банканы берілген capacity-мен (банкаға сыятын печеньенің ең көп саны) баптайды. capacity теріс емес int болмаса, __init__ ValueError көтеруі керек.

        ...

        ...

Бір әдісті (мысалы, withdraw) тексеру үшін алдымен басқасын (мысалы, deposit) шақыру керек болуы мүмкін. Бірақ бірінші шақырылған әдістің өзі қате болса ше! Сондықтан бағдарламашылар кейде күйді имитациялайды (mock), мысалы, Python-ның mock кітапханасымен. Бірақ қарапайымдылық үшін бұл жолы ештеңені имитацияламай-ақ, тесттерді әдеттегідей жазыңыз. main функциясын жазу міндетті емес.

    CS50 Shirtificate (CS50 футболка-сертификаты)

    CS50 «шертификатын» (shirtificate, shirt + certificate) жасағыңыз келеді делік: бұл «I took CS50» футболкасының суреті бар, қолданушының атымен безендірілген PDF.

    shirtificate.py файлында қолданушыдан атын сұрап, fpdf2 кітапханасы арқылы shirtificate.pdf деген файлға CS50 шертификатын шығаратын бағдарлама жазыңыз (Джон Гарвардқа арналған мына үлгідей). Талаптар:

    • PDF бағыты - тік (Portrait).
    • PDF пішімі - A4, яғни ені 210 мм, биіктігі 297 мм.
    • PDF-тің жоғарғы жағында көлденеңінен ортаға келтірілген «CS50 Shirtificate» мәтіні болсын.
    • Футболка суреті көлденеңінен ортада тұрсын.
    • Қолданушының аты футболканың үстінде, ақ түсті мәтінмен жазылсын.

    Қалған егжей-тегжейі өз еркіңізде. Жиектер, түстер, сызықтар қосуға да болады. Шертификатыңыз Джон Гарвардтікімен дәлме-дәл сәйкес келуі шарт емес, ал ұзын аттарды бірнеше жолға бөлудің қажеті жоқ.

    Код жазбас бұрын fpdf2-нің оқу құралын оқып шығыңыз, сосын оның API-ына (бағдарламалық интерфейсіне) көз жүгіртіп, функциялары мен параметрлерін қараңыз. PDF-терді кодпен бірге тапсырудың қажеті жоқ. Бірақ қаласаңыз, өз атыңыз жазылған шертификатпен CS50 қауымдастықтарында бөлісе аласыз!

    Жұмысты бастау үшін mkdir shirtificate және cd shirtificate орындап, суретті жүктеп алыңыз:

    wget https://cs50.harvard.edu/python/2022/psets/8/shirtificate/shirtificate.png
    Кеңес
    • fpdf2-де FPDF деген class бар, оның көп әдісі бар: py-pdf.github.io/fpdf2/fpdf/#fpdf.FPDF. Орнату: pip install fpdf2.
    • Әр бетке тақырып қосу үшін FPDF-ті кеңейтіп (лекциядағы мұрагерлік!), өз бала класыңыздың данасын жасауға болады: оқу құралының 2-бөлімі. Немесе мәтінді өзіңіз қосыңыз.
    • PDF екі бетке асып кетпеуі үшін автоматты бет бөлуді set_auto_page_break арқылы өшіруге болады: py-pdf.github.io/fpdf2/Margins.html.
    • Ұяшықтың (cell) биіктігі теріс болуы мүмкін, сонда ол жоғары жылжиды.
    • Шыққан shirtificate.pdf-ты VS Code-тың файлдар тізімінен басып ашуға болады.
    Компьютерде тексеріледі

    Бұл бағдарлама fpdf2 кітапханасы мен сурет файлын қажет етеді және PDF файл жасайды, сондықтан браузердегі автотексеруші жоқ. Оны компьютеріңізде немесе cs50.dev-те іске қосып, шыққан PDF-ті ашып қараңыз.

    Тексеру
    • python shirtificate.py атты сұрайды және shirtificate.pdf жасайды
    • A4, тік бағыт; жоғарыда ортаға келтірілген «CS50 Shirtificate»
    • Футболка суреті ортада, үстінде қолданушының аты ақ түспен жазылған
    • check50 cs50/problems/2022/python/shirtificate өтеді.
